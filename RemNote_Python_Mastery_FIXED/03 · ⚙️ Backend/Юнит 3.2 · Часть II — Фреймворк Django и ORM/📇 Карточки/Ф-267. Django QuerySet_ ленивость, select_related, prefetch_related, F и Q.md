1. Что означает утверждение «QuerySet в Django — ленивый (Lazy)»? >> Создание и цепочка методов `User.objects.filter(...).exclude(...).order_by(...)` не выполняют SQL-запрос к базе данных; запрос отправляется только в момент реального обращения к данным
2. В какие моменты происходит реальное выполнение (Evaluation) ленивого `QuerySet`? >> При итерации (`for x in qs`), взятии среза с шагом, преобразовании в `list(qs)` или `bool(qs)`, вызове `len(qs)`, `repr(qs)`
3. Почему для проверки наличия записей нужно использовать `qs.exists()`, а для подсчёта — `qs.count()`, а не `if qs:` и `len(qs)`? >> `if qs:` и `len(qs)` загружают в память Python все строки и создают ORM-объекты, тогда как `exists()` делает лёгкий `SELECT 1 ... LIMIT 1`, а `count()` — `SELECT COUNT(*)` на стороне СУБД
4. В чём суть проблемы N+1 запросов в ORM? >> При загрузке списка из $N$ родительских объектов (1 запрос) обращение в цикле к связанному полю каждого объекта (`book.author.name`) порождает ещё $N$ отдельных SQL-запросов вместо одного общего
5. Как работает `select_related()` в Django ORM и для каких типов связей он применяется? >> Выполняет один SQL-запрос с `JOIN`, сразу подтягивая связанные объекты в память; применяется для одиночных связей «вперёд»: `ForeignKey` и `OneToOneField`
6. Как работает `prefetch_related()` и чем он отличается от `select_related()`? >> Выполняет отдельный второй SQL-запрос с `WHERE id IN (...)` и склеивает связанные объекты уже в памяти Python; применяется для связей «многие» (`ManyToManyField` и обратный `ForeignKey` / `related_name`)
7. Для чего в Django ORM используется объект `Q()`? >> Для построения сложных условий фильтрации с логическими операторами `|` (ИЛИ), `&` (И) и `~` (НЕ), например `User.objects.filter(Q(role='admin') | Q(is_superuser=True))`
8. Для чего используется выражение `F()` в Django ORM и как оно защищает от Race Condition? >> `F('field')` ссылается на значение колонки прямо внутри SQL-запроса без выгрузки в Python: `Product.objects.filter(id=1).update(stock=F('stock') - 1)` выполняет атомарный `UPDATE ... SET stock = stock - 1` в БД
9. В чём разница между методами `aggregate()` и `annotate()` в QuerySet? >> `aggregate()` считает сводное значение по всему QuerySet и возвращает один словарь (`{'avg_price': 150.0}`); `annotate()` добавляет вычисленное поле к каждому отдельному объекту выборки (`GROUP BY`)
10. Чем отличаются методы `values()` и `values_list()` от обычного `QuerySet`? >> Вместо тяжёлых экземпляров моделей они возвращают словари (`values()`) или кортежи (`values_list()`, а с `flat=True` — плоский список значений одного поля), экономя память и CPU
11. Для чего используется метод `qs.iterator(chunk_size=2000)` при обходе миллиона записей? >> Обычный `QuerySet` кэширует все прочитанные объекты в памяти (вызывая Out of Memory на больших выборках); `iterator()` читает данные порциями без кэширования всего результата в ОЗУ
12. Как в Django массово вставить или обновить тысячи объектов за один SQL-запрос вместо цикла с `.save()`? >> Использовать `Model.objects.bulk_create(objs, batch_size=1000)` и `Model.objects.bulk_update(objs, fields=['status'])` (важно: они не вызывают метод `save()` модели и сигналы `pre_save`/`post_save`)
