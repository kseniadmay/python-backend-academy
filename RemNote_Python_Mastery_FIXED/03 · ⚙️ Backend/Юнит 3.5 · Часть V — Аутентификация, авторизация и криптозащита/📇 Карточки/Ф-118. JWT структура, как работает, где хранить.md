1. Где наиболее безопасно хранить Refresh токен на стороне клиента? >> В `HttpOnly` -куке; JavaScript не может прочитать – защита от XSS
2. Что содержит Payload в структуре JSON Web Token (JWT)? >> JSON-объект с claims: стандартные ( `sub` , `exp` , `iat` ) и кастомные ( `user_id` , `role` )
3. Где рекомендуется хранить короткоживущий Access Token в Single Page Application (SPA)? >> В памяти JS-приложения (переменная); исчезает при перезагрузке – не доступен XSS
4. По какой формуле вычисляется подпись (Signature) в токене JWT при алгоритме HS256? >> `HMAC-SHA256(base64url(header) + '.' + base64url(payload), secret_key)`
5. Что произойдёт при изменении любого символа в payload? >> Signature перестанет совпадать с вычисленной; токен будет отклонён
6. Что означает `exp` в payload? >> Expiration Time – время истечения токена в Unix timestamp
7. Как декодировать JWT в Python? >> `jwt.decode(token, secret, algorithms=["HS256"])` ; параметр `algorithms` обязателен для безопасности
8. Что такое `HttpOnly` Cookie? >> Кука недоступна для чтения через JavaScript; защищает от XSS
9. Типичный TTL access и refresh токенов? >> Access: ~15 минут; Refresh: 7–30 дней
10. Из чего состоит JWT? >> Три части через точку: `header.payload.signature` ; каждая часть – Base64url-encoded
11. Что обеспечивает JWT – конфиденциальность или целостность? >> Только целостность и аутентичность данных; не конфиденциальность
12. Какому RFC соответствует спецификация JWT? >> RFC 7519; формально определяет структуру JWT, кодировку и проверку подписи
13. Для чего нужен Refresh токен? >> Получение нового Access токена без повторного ввода пароля; позволяет использовать короткоживущие access tokens
14. Что произойдёт если `exp` истёк? >> Библиотека выбросит `ExpiredSignatureError` ; токен отклоняется
15. Является ли payload JWT зашифрованным? >> Нет; только Base64url-encoded; любой может декодировать и прочитать; нельзя хранить пароли и секреты
16. Что означает `iat` в payload? >> Issued At – время создания токена; полезен для логирования и отзыва старых сессий
17. Является ли HS256 симметричным или асимметричным? >> Симметричный; один ключ используется и для подписи, и для проверки
18. Что такое HMAC? >> Hash-based Message Authentication Code; криптографическая подпись с хэш-функцией и секретным ключом; гарантирует целостность и подлинность
19. Почему `localStorage` небезопасен для токенов? >> Доступен через JavaScript; XSS-атака может украсть токен; данные сохраняются между сессиями
20. Зачем явно указывать `algorithms=["HS256"]` при декодировании? >> Предотвращает атаку подмены алгоритма ( `alg: "none"` ); сервер принимает только разрешённые алгоритмы
21. От какой атаки защищает `SameSite=Strict` ? >> CSRF (Cross-Site Request Forgery); браузер не отправляет куки при кросс-доменных запросах
22. Что содержит Header JWT? >> Тип токена ( `typ: "JWT"` ) и алгоритм подписи ( `alg: "HS256"` )
