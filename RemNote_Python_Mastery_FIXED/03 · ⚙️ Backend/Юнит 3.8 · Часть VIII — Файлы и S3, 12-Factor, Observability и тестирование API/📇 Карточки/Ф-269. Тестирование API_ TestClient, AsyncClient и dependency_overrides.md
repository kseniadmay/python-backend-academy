1. Как работает `TestClient` в FastAPI и нужно ли для него запускать `uvicorn` на сетевом порту? >> Не нужно: `TestClient` (на базе `httpx` и `Starlette`) прогоняет HTTP-запросы напрямую через ASGI-интерфейс приложения в памяти процесса
2. Когда в тестах FastAPI вместо синхронного `TestClient` необходимо использовать `httpx.AsyncClient(transport=ASGITransport(app=app))`? >> Когда тесты и фикстуры (например, асинхронная сессия SQLAlchemy `AsyncSession`) сами являются асинхронными (`@pytest.mark.asyncio`) и должны работать в едином Event Loop
3. Как в тестах FastAPI подменить зависимость `Depends(get_db)` или `Depends(get_current_user)` без использования `unittest.mock.patch`? >> Через словарь `app.dependency_overrides[original_dep] = override_dep` с обязательной очисткой `app.dependency_overrides.clear()` в `finally` или teardown фикстуры
4. Почему `app.dependency_overrides` надёжнее `unittest.mock.patch('app.routers.users.get_db')`? >> `dependency_overrides` подменяет функцию в самом графе зависимостей FastAPI для всех роутеров сразу и не ломается при рефакторинге путей импорта
5. Как обеспечить полную изоляцию базы данных между интеграционными тестами без медленного пересоздания таблиц перед каждым тестом? >> Использовать паттерн Transactional Rollback: открывать транзакцию перед тестом, передавать эту сессию в приложение и делать `session.rollback()` после завершения теста
6. Что делает декоратор `@pytest.mark.django_db` из плагина `pytest-django`? >> Разрешает тесту доступ к тестовой БД Django и автоматически оборачивает каждый тест в транзакцию, откатывая все изменения после завершения теста
7. Чем метод `client.force_authenticate(user=user)` в `APIClient` (DRF) удобен при тестировании защищённых эндпоинтов? >> Он мгновенно авторизует тестовый запрос от имени переданного пользователя без затрат времени на хеширование пароля (`bcrypt`) и вызов эндпоинта логина `/api/token/`
8. Для чего в тестах бэкенда используют библиотеку `factory_boy` (или `polyfactory`) вместо жёстко зашитых JSON-фикстур? >> Фабрики генерируют валидные модели и связанные объекты с дефолтными полями на лету, позволяя в самом тесте указывать только те 1–2 поля, которые важны для конкретного сценария
9. Как протестировать код внутри `lifespan` (startup/shutdown) приложения с помощью `TestClient`? >> Открывать `TestClient` как контекстный менеджер: `with TestClient(app) as client:` — вход в блок `with` запускает события `startup`, а выход — `shutdown`
10. Как в тестах проверить, что сервис корректно обрабатывает ошибку `503` от внешнего платёжного API, не делая реальных сетевых запросов? >> Подменить клиент внешнего сервиса через `dependency_overrides` или перехватить HTTP-запрос на уровне транспорта `httpx` с помощью библиотеки `respx` (или `responses` для `requests`)
