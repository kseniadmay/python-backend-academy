3. Где хранить время начала запроса для измерения его длительности? >> В объекте `g`
4. Что представляет собой `current_app` ? >> Прокси на текущее запущенное Flask-приложение
5. Почему `request` и `g` выглядят как глобальные, но содержат разные данные для разных пользователей? >> Они являются `LocalProxy` -объектами, использующими `threading.local` для изоляции данных по потокам

10. Какой объект лучше всего подходит для хранения данных между `before_request` и view-функцией? >> `g`

14. Стандартный способ проверки наличия пользователя в сессии? >> `session.get('user_id')`

27. Какую проблему решает `g` ? >> Позволяет избежать избыточной передачи данных через параметры всех функций в цепочке вызовов
28. Два основных типа контекстов во Flask? >> Application context (контекст приложения) и Request context (контекст запроса)
29. К какому типу контекста относятся `current_app` и `g` ? >> Application context – данные приложения
30. Как получить IP-адрес клиента? >> `request.remote_addr`
31. С помощью какого декоратора создаются функции выполняющиеся перед каждым запросом? >> `@app.before_request`

33. Что произойдёт с данными `session` после завершения запроса? >> Сохранятся и будут доступны в следующих запросах того же пользователя (в отличие от `g` )
