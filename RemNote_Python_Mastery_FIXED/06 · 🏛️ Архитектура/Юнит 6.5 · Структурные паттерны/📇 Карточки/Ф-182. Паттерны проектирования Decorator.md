1. Как декоратор получает доступ к оборачиваемому объекту? >> Принимает его в конструкторе и сохраняет в `self._processor` ; при вызове `process()` делегирует работу обёрнутому объекту и добавляет своё поведение
2. Как работает оборачивание нескольких декораторов? >> `processor = LoggingDecorator(CompressionDecorator(EncryptionDecorator(BaseProcessor())))` ; каждый слой добавляет поведение; порядок важен
3. В чём разница между паттерном Decorator и синтаксисом `@decorator` в Python? >> Синтаксис `@` – синтаксический сахар для декорирования функций; GoF-паттерн Decorator работает с объектами через общий интерфейс; оба реализуют один концептуальный принцип, но в разных контекстах
4. Что делает декоратор `@retry` ? >> Повторяет вызов функции до `max_attempts` раз при исключении; после исчерпания попыток пробрасывает исключение дальше
5. Является ли `@` единственным способом реализации паттерна Decorator? >> Нет; паттерн реализуется через классы с общим интерфейсом и композицию; `@` – синтаксический сахар для функций
6. В каком порядке применяются несколько Python-декораторов? >> Снизу вверх при применении; сверху вниз при выполнении; `@A` над `@B` – B оборачивает функцию первым, A – вторым
7. Реальные применения паттерна Decorator? >> Кэширование ( `@cache` , `@lru_cache` ); авторизация ( `@login_required` ); логирование; измерение времени; retry-логика; валидация; middleware в Django/FastAPI
8. Что делает декоратор `@timer` ? >> Фиксирует время до и после вызова функции через `time.time()` ; выводит имя функции и затраченное время
9. Как создать Python-декоратор функции? >> Функция, принимающая `func` , возвращающая `wrapper` ; `wrapper` вызывает `func(*args, **kwargs)` и добавляет поведение до/после
10. К какому типу паттернов относится Decorator? >> Структурные (Structural); описывает способ организации классов и объектов
11. Какое ключевое требование к классам-декораторам в GoF-паттерне? >> Они должны реализовывать тот же интерфейс, что и декорируемый объект; клиент работает с декоратором как с обычным объектом
12. Что такое декоратор-фабрика (decorator factory)? >> Функция, принимающая параметры и возвращающая фактический декоратор; нужна когда декоратор должен принимать аргументы: `@retry(max_attempts=3)`
13. Чем Decorator гибче наследования? >> Комбинирование поведения происходит динамически в любом порядке; наследование создаёт жёсткую статическую иерархию; `N` поведений → `2^N` классов-наследников vs `N` декораторов
14. Что такое паттерн Decorator? >> Структурный паттерн; добавляет объекту новое поведение путём оборачивания в объект-декоратор, реализующий тот же интерфейс; динамическая альтернатива наследованию
15. Что произойдёт без `@wraps` при использовании декоратора? >> `func.__name__` вернёт `'wrapper'` вместо оригинального имени; это ломает логирование, документацию и интроспекцию
16. Для чего используется `@wraps(func)` из `functools` ? >> Сохраняет метаданные оригинальной функции ( `__name__` , `__doc__` ); без него декорированная функция теряет своё имя – распространённая ловушка
17. Может ли декоратор изменить возвращаемое значение функции? >> Да; `wrapper` контролирует вызов `func()` и может модифицировать или заменить результат
