1. Может ли один Observer подписаться на несколько событий? >> Да; объект можно добавить в списки разных ключей `_observers` для разных событий
2. Как устроено хранение подписчиков в EventEmitter? >> Словарь `dict[str, List[Observer]]` ; ключи – имена событий, значения – списки наблюдателей
3. Что произойдёт, если `notify()` вызван для события без подписчиков? >> Ничего; корректная реализация проверяет наличие ключа и не бросает исключение
4. Почему `notify()` вызывается после сохранения в БД? >> Чтобы уведомлять подписчиков только об успешном событии; уведомление до `commit` может привести к рассылке о несостоявшемся событии
5. Что такое `post_save` в Django? >> Сигнал, срабатывающий после успешного сохранения модели в БД
6. Обязательно ли использовать ABC для Observer в Python? >> Нет; duck typing достаточно – любой объект с методом `update()` подойдёт; ABC добавляет явный контракт и раннее обнаружение ошибок
7. Что делает метод `notify()` ? >> Перебирает всех подписчиков события и вызывает `observer.update(event, data)` у каждого
8. Что такое `pre_delete` в Django? >> Сигнал, срабатывающий перед удалением объекта из БД
9. Является ли стандартный Observer синхронным? >> Да; уведомления рассылаются последовательно в том же потоке; для асинхронных систем используют очереди или async
10. Какие роли участвуют в паттерне Observer? >> Subject (Издатель) – хранит список наблюдателей и уведомляет их; Observer (Наблюдатель) – реализует метод `update()` для получения уведомлений
11. Что такое паттерн Observer? >> Поведенческий паттерн; определяет зависимость «один-ко-многим»: при изменении состояния Subject все подписанные Observers уведомляются автоматически
12. Чем Observer отличается от Strategy? >> Strategy – взаимозаменяемые алгоритмы (один активный); Observer – множество подписчиков уведомляются об одном событии (все активны одновременно)
13. Как Observer реализован в Django? >> Через сигналы ( `Signals` ): `Signal.send()` – уведомление (notify); `@receiver` – подписка (subscribe); `post_save` , `pre_delete` – стандартные сигналы
14. Почему Observer обеспечивает слабую связанность? >> Subject знает только интерфейс Observer ( `update()` ), а не конкретные классы; можно добавлять новых подписчиков без изменения Subject
15. Реальные применения Observer? >> Системы уведомлений (email, SMS, push); Django-сигналы; реактивное программирование; синхронизация UI при изменении данных; логирование и аналитика событий
16. Что делает метод `subscribe()` ? >> Регистрирует наблюдателя для конкретного события; добавляет в список `_observers[event]`
