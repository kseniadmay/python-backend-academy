1. Где в FastAPI задаётся статус-код ответа? >> В декораторе маршрута: `@router.post("/users", status_code=201, response_model=UserResponse)`
2. Почему пароль есть в `UserCreateRequest` , но не в `UserResponse` ? >> Безопасность: пароль нужен при регистрации, но никогда не должен возвращаться клиенту
3. В каком направлении идут зависимости в слоистой архитектуре? >> Только сверху вниз: Presentation → Business → Data Access → Infrastructure; нижние слои не знают о верхних
4. Какую роль в FastAPI выполняет `schemas.py` ? >> Pydantic-схемы для валидации HTTP-запросов и формирования ответов; относится к Presentation Layer
5. Какую роль выполняет `Depends()` в FastAPI? >> Внедрение зависимостей (DI): автоматически создаёт и передаёт нужные объекты (сервисы, сессии БД) в функцию контроллера
6. Что происходит с бизнес-логикой при смене внешней почтовой службы? >> Ничего; изменения только в Infrastructure Layer; бизнес-логика работает через абстракцию `EmailSender`
7. Что делает `try/except` в контроллере? >> Перехватывает бизнес-исключения (например, `EmailAlreadyExists` ) и преобразует их в HTTP-ответы с соответствующими кодами (409, 404)
8. Чем `UserResponse` отличается от доменной модели `User` ? >> `UserResponse` – схема для API-ответа (например, без поля `password` ); `User` – внутренний доменный объект бизнес-логики
9. Может ли Controller обращаться напрямую к Repository? >> Нет; только через Service; правило: `Controller → Service → Repository`
10. В каком слое обрабатываются специфические ошибки БД? >> Data Access Layer (Repository); конвертирует их в доменные исключения; Presentation Layer не должен знать о деталях БД
11. Почему доменные модели в `models.py` не должны зависеть от других слоёв? >> Бизнес-сущности должны быть универсальными и независимыми от фреймворков, ORM и HTTP; это позволяет использовать их в любом контексте
12. Почему `Depends(get_user_service)` лучше прямого создания объекта в контроллере? >> Упрощает тестирование (можно подменить реализацию) и централизует управление зависимостями
13. Может ли Infrastructure зависеть от Presentation? >> Нет; зависимости строго однонаправленные вниз; нарушение этого правила ломает всю изоляцию слоёв
14. Что такое слоистая архитектура? >> Организация кода по горизонтальным слоям; зависимости строго однонаправленные – каждый слой знает только о слое непосредственно ниже
