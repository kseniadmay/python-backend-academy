1. Чему в MVC соответствует Django View? >> Controller; обрабатывает запрос и определяет, какие данные получить и какой шаблон использовать
2. Почему MVC удобен для командной разработки? >> Фронтенд-разработчики работают над View/Template, бэкенд-разработчики – над Model; слои независимы
3. Что делает Controller в MVC? >> Принимает запрос, получает данные из Model, передаёт их в View; «мозг» приложения – определяет, что получить и что отобразить
4. Что делает Model в MVC? >> Хранит данные и содержит бизнес-логику; работает с БД; не знает о View и Controller
5. Что делает View в MVC? >> Представляет данные пользователю (HTML, JSON, XML); не содержит бизнес-логики; получает данные от Controller
6. Что такое Router в MVC? >> Компонент, направляющий запрос к нужному методу Controller; в Django – `urls.py` с функцией `path()`
7. Чему в MVC соответствует Django Model? >> Model; описывает структуру данных и работает с БД
8. Если нужно сменить формат вывода с HTML на JSON, какой слой меняется? >> View; Model и Controller остаются нетронутыми
9. В чём ключевое отличие Django MTV от классического MVC? >> Терминология: то, что в MVC называется Controller, в Django называется View; то, что в MVC – View, в Django – Template; суть одна
10. Что такое MTV в Django? >> Model-Template-View – вариация MVC: `Model` = Model, `Template` = View (HTML), `View` = Controller (бизнес-логика запроса)
11. Если меняется алгоритм расчёта скидки (бизнес-логика), что нужно менять? >> Только Model; View только отображает результат
12. Можно ли использовать одну Model для разных View? >> Да; те же данные можно отображать по-разному: сайт, API, мобильное приложение
13. Чему в MVC соответствует Django Template? >> View; отвечает за отображение данных в HTML
14. Что такое паттерн MVC? >> Model-View-Controller: архитектурный паттерн, разделяющий приложение на три компонента с разными зонами ответственности
15. Как выглядит цикл запроса в MVC? >> Пользователь → Controller → Model → Controller → View → Пользователь
