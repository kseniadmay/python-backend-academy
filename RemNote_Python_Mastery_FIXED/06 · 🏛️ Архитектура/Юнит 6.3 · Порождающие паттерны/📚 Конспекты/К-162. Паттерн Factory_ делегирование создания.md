## 1. Зачем нужна Фабрика (Factory), если можно просто вызвать `ClassName()`?

> **Ментальная модель — «Единая служба заказа такси»**:
> Когда вы вызываете такси в приложении и выбираете тариф (`"econom"`, `"comfort"`, `"cargo"`), вы не звоните лично на завод Skoda или Mercedes и не ищете конкретного водителя. Диспетчерская (**Factory**) сама решает, какой именно автомобиль создать и подать к подъезду, но вы точно знаете одно: у любой поданной машины есть метод `.drive_to(address)` (**общий интерфейс продукта**).

Если бизнес-код сам создаёт объекты через цепочки `if channel == "email": notifier = SmtpEmailNotifier(host, port, tls)` в десяти разных файлах, возникает **жёсткая связность (Tight Coupling)**. Стоит поменять аргументы конструктора `SmtpEmailNotifier` или добавить канал `"telegram"`, как вам придётся переписывать весь проект.

```text
Без Фабрики (клиент привязан ко всем классам):     С Паттерном Factory (клиент знает только контракт):
+--------------+ ---> EmailNotifier                +--------------+      +-----------------+
| OrderService | ---> SmsNotifier                  | OrderService | ---> | NotifierFactory |
+--------------+ ---> TelegramNotifier             +--------------+      +-----------------+
                                                          |                       | Создаёт
                                                          v                       v
                                                   <<Notifier Protocol>> <--------+
                                                     ^       ^        ^
                                                     |       |        |
                                                   Email    SMS    Telegram
```

## 2. Три разновидности Фабрики: Simple Factory, Factory Method и Abstract Factory

На собеседованиях часто спрашивают разницу между **Фабричным методом (Factory Method)** и **Абстрактной фабрикой (Abstract Factory)**:

| Паттерн | Что создаёт | Как устроен в Python | Типичный пример на бэкенде |
| :--- | :--- | :--- | :--- |
| **Simple / Registry Factory** (Простая фабрика со словарём) | **Один продукт** по строковому ключу (`"csv"`, `"pdf"`) | Словарь `_registry: dict[str, type[Exporter]]` + метод `create(kind)` | Выбор парсера файлов (`JSON`, `CSV`, `XML`) или канала уведомлений |
| **Factory Method** (Фабричный метод) | **Один продукт**, но решение *какой класс инстанцировать* делегировано методу/подклассу | Базовый класс определяет алгоритм работы с продуктом, вызывая фабричный метод `create_transport()` | `Logistics.plan_delivery()` вызывает `create_transport()` (грузовик или корабль) |
| **Abstract Factory** (Абстрактная фабрика) | **Целое семейство связанных продуктов**, которые обязаны быть совместимы друг с другом | Интерфейс фабрики с несколькими методами: `create_connection()`, `create_query_builder()`, `create_migrator()` | Смена облачного провайдера: `AwsCloudFactory` (`S3 + SQS`) vs `GcpCloudFactory` (`GCS + PubSub`) |

## 3. Питоничная фабрика на словаре-реестре и декораторе регистрации

В Python классы являются **объектами первого класса (First-Class Citizens)**: их можно хранить в словарях как обычные значения и вызывать через `cls(*args, **kwargs)`.
Это позволяет полностью избавиться от `if/elif/else` и соблюсти **Open/Closed Principle (OCP)**: новый формат отчёта регистрируется одним декоратором `@ReportFactory.register("markdown")` без единой правки самой фабрики!

```python
from typing import Protocol, Callable

class ReportExporter(Protocol):
    def export(self, rows: list[dict[str, object]]) -> str: ...

class ReportFactory:
    _registry: dict[str, type[ReportExporter]] = {}

    @classmethod
    def register(cls, fmt: str) -> Callable[[type[ReportExporter]], type[ReportExporter]]:
        def decorator(exporter_cls: type[ReportExporter]) -> type[ReportExporter]:
            cls._registry[fmt.lower()] = exporter_cls
            return exporter_cls
        return decorator

    @classmethod
    def create(cls, fmt: str) -> ReportExporter:
        exporter_cls = cls._registry.get(fmt.lower())
        if exporter_cls is None:
            available = ", ".join(sorted(cls._registry))
            raise ValueError(f"Неизвестный формат '{fmt}'. Доступны: {available}")
        return exporter_cls()

@ReportFactory.register("csv")
class CsvExporter:
    def export(self, rows: list[dict[str, object]]) -> str:
        return "id,name\n" + "\n".join(f"{r['id']},{r['name']}" for r in rows)

@ReportFactory.register("json")
class JsonExporter:
    def export(self, rows: list[dict[str, object]]) -> str:
        import json
        return json.dumps(rows, ensure_ascii=False)

data = [{"id": 1, "name": "Алиса"}, {"id": 2, "name": "Боб"}]
for fmt_name in ("csv", "json"):
    exporter = ReportFactory.create(fmt_name)
    print(f"[{fmt_name.upper()}] -> {exporter.export(data)}")
```

## 4. Abstract Factory: гарантируем совместимость семейства объектов

Представьте, что ваш бэкенд должен работать либо с **PostgreSQL**, либо с **SQLite**, и для каждой СУБД нужны совместимые друг с другом `Connection` и `DialectCompiler`. Если случайно смешать `PostgresConnection` с `SqliteDialect`, запросы упадут. **Abstract Factory** исключает такое смешивание на уровне архитектуры.

> **Junior vs Senior**:
> - **Junior**: В каждом сервисе пишет `if settings.DB == 'postgres': ... else: ...`, рискуя в одном месте создать подключение к Postgres, а билдер запросов взять от SQLite.
> - **Senior**: Объединяет взаимосвязанные компоненты в `DatabaseToolkitFactory` (Abstract Factory) и передаёт выбранную фабрику на старте приложения.

```python
from typing import Protocol

class DialectCompiler(Protocol):
    def compile_limit(self, table: str, limit: int) -> str: ...

class DbConnection(Protocol):
    def execute_sql(self, sql: str) -> str: ...

class DatabaseFactory(Protocol):
    """Абстрактная фабрика создаёт семейство гарантированно совместимых объектов."""
    def create_compiler(self) -> DialectCompiler: ...
    def create_connection(self) -> DbConnection: ...

class PostgresFactory:
    def create_compiler(self) -> DialectCompiler:
        class PgCompiler:
            def compile_limit(self, table: str, limit: int) -> str:
                return f'SELECT * FROM "{table}" FETCH FIRST {limit} ROWS ONLY;'
        return PgCompiler()

    def create_connection(self) -> DbConnection:
        class PgConn:
            def execute_sql(self, sql: str) -> str:
                return f"[PostgreSQL Driver] Выполнено: {sql}"
        return PgConn()

def run_report(factory: DatabaseFactory) -> str:
    compiler = factory.create_compiler()
    conn = factory.create_connection()
    return conn.execute_sql(compiler.compile_limit("orders", 5))

print(run_report(PostgresFactory()))
```
