# 📊 К-121. Алгоритмы сортировки (Sorting Algorithms) и устройство Timsort в Python

> **Ментальная модель — «Разделяй и властвуй vs Попарные перестановки»**:
> - **Квадратичные сортировки ($O(n^2)$ — Пузырьком, Выбором, Вставками)** сравнивают и двигают соседей по одному шагу. На 10–30 элементах они очень просты и быстры, но на $100\,000$ элементов делают миллиарды операций.
> - **Эффективные сортировки ($O(n \log n)$ — Слиянием и Быстрая)** используют принцип **«Разделяй и властвуй» (Divide and Conquer)**: дробят задачу пополам на $\log_2 n$ ярусов и на каждом ярусе тратят $O(n)$ работы.
> - **Timsort (стандарт `list.sort()` и `sorted()` в Python)** берёт лучшее от обоих миров: находит в реальных данных уже упорядоченные куски (`runs`), досортировывает мелкие фрагменты **Вставками**, а крупные сливает как в **Merge Sort**!

## 1. Панорама алгоритмов сортировки

> **Стабильность (Stability)** сортировки означает, что элементы с **одинаковыми ключами сохраняют свой исходный взаимный порядок** после сортировки. Это критически важно при многоуровневой сортировке (например, сначала по имени, а затем по отделу).

| Алгоритм | Лучший случай (Best) | Средний (Average) | Худший (Worst) | Доп. память (Space) | Стабильная? | Ключевая идея |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Bubble Sort** (Пузырьком) | $O(n)$ (с флагом `swapped`) | $O(n^2)$ | $O(n^2)$ | $O(1)$ | Да | Соседи меняются местами; максимум «всплывает» в конец |
| **Selection Sort** (Выбором) | $O(n^2)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | Нет | Находим минимум в остатке и ставим на позицию `i` |
| **Insertion Sort** (Вставками) | **$O(n)$** (на почти отсорт.) | $O(n^2)$ | $O(n^2)$ | $O(1)$ | **Да** | Вставляем очередной элемент в уже отсортированную левую часть |
| **Merge Sort** (Слиянием) | $O(n \log n)$ | **$O(n \log n)$** | **$O(n \log n)$** | **$O(n)$** | **Да** | Делим пополам до 1 элемента и сливаем два отсортированных списка двумя указателями |
| **Quick Sort** (Быстрая, Хоара) | $O(n \log n)$ | **$O(n \log n)$** | $O(n^2)$ (плохой `pivot`) | $O(\log n)$ (стек) | Нет | Выбираем опорный `pivot`, делим на `< pivot` и `> pivot` (`partition`) |
| **Timsort** (`sorted` / `.sort`) | **$O(n)$** | **$O(n \log n)$** | **$O(n \log n)$** | $O(n)$ | **Да** | Гибрид **Insertion Sort** (для малых кусков) + **Merge Sort** (для слияния `runs`) |

## 2. Как работает Merge Sort (Сортировка слиянием)?

```text
Разделение (Divide — вниз) и Слияние двумя указателями (Merge — вверх):

              [ 38, 27, 43, 3 ]
               /             \
         [ 38, 27 ]       [ 43, 3 ]        <-- делим пополам (глубина log2(n))
          /      \         /     \
       [38]      [27]   [43]     [3]       <-- базовый случай (длина 1 уже отсортирована)
          \      /         \     /
         [ 27, 38 ]       [ 3, 43 ]        <-- сливаем за O(n) на каждом уровне
               \             /
              [ 3, 27, 38, 43 ]            <-- итог: O(n log n) всегда!
```

## 3. Почему в Python используют Timsort и параметр `key=`?

Встроенные функции `lst.sort()` (сортирует список на месте `in-place` и возвращает `None`) и `sorted(iterable)` (создаёт и возвращает новый список) реализованы на C с помощью алгоритма **Timsort** (автор — Тим Петерс, 2002 г.).
При передаче функции `key=func` Python применяет паттерн **Decorate-Sort-Undecorate (Schwartzian Transform)**: функция `key(x)` вызывается **ровно один раз для каждого элемента** ($O(n)$ вызовов) перед началом сравнений, а не при каждом из $O(n \log n)$ сравнений!

> **Junior vs Senior**:
> - **Junior**: Пишет `res = my_list.sort()`, получая `None` в переменной `res`, или использует `functools.cmp_to_key` для простой сортировки по двум полям, замедляя код в 5–10 раз.
> - **Senior**: Помнит, что `list.sort()` мутирует список `in-place` и возвращает `None`, а `sorted()` возвращает новую коллекцию. Для многокритериальной сортировки использует **кортеж в `key=`** (например, `key=lambda u: (-u["score"], u["name"])`) или стабильность Timsort.

```python
# 1. Классическая сортировка слиянием (Merge Sort) за гарантированное O(n log n)
def merge_sorted(left: list[int], right: list[int]) -> list[int]:
    """Сливает два отсортированных списка за O(len(left) + len(right)) двумя указателями."""
    merged: list[int] = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:  # <= сохраняет стабильность сортировки!
            merged.append(left[i])
            i += 1
        else:
            merged.append(right[j])
            j += 1
    merged.extend(left[i:])
    merged.extend(right[j:])
    return merged

def merge_sort(arr: list[int]) -> list[int]:
    if len(arr) <= 1:
        return arr
    mid = len(arr) // 2
    return merge_sorted(merge_sort(arr[:mid]), merge_sort(arr[mid:]))

# 2. Многоуровневая сортировка Timsort: по убыванию баллов (-score) и по возрастанию имени
candidates = [
    {"name": "Борис", "score": 90},
    {"name": "Анна", "score": 95},
    {"name": "Алексей", "score": 90},
]
ranked = sorted(candidates, key=lambda c: (-c["score"], c["name"]))

print("Merge Sort [38, 27, 43, 3, 9, 82, 10] ->", merge_sort([38, 27, 43, 3, 9, 82, 10]))
print("Рейтинг кандидатов (Timsort):", [f"{c['name']} ({c['score']})" for c in ranked])
```
