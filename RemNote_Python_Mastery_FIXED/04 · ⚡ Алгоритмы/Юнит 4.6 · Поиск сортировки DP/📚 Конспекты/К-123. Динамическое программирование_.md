# 🧠 К-123. Динамическое программирование (DP): мемоизация (`lru_cache`) и табуляция

> **Ментальная модель — «Шпаргалка-блокнот против амнезии»**:
> Спросите человека: *«Сколько будет $1 + 1 + 1 + 1 + 1$?»*. Он посчитает и ответит: *«Пять»*.
> Допишите слева ещё одну единицу: *«А теперь?»*. Он мгновенно скажет: *«Шесть!»*.
> Почему он не пересчитывал первые пять единиц заново? Потому что он **запомнил результат предыдущей подзадачи ($5$) и прибавил $1$**! Это и есть **Динамическое программирование (Dynamic Programming, DP)** — метод решения задач путём сохранения ответов на перекрывающиеся подзадачи, чтобы никогда не вычислять одно и то же дважды.

---

## 1. Два признака задачи на Динамическое программирование

1. **Перекрывающиеся подзадачи (Overlapping Subproblems)**: рекурсивное дерево вызовов многократно решает одни и те же мелкие подзадачи. Например, при наивном вычислении `fib(5)` функция `fib(3)` вызывается 2 раза, а `fib(2)` — 3 раза. При `fib(40)` число повторных вызовов превышает $10^8$ ($O(2^n)$)!
2. **Оптимальная подструктура (Optimal Substructure)**: оптимальное решение большой задачи однозначно собирается из оптимальных решений меньших подзадач (рекуррентное соотношение / **Transition Formula**).

```text
Дерево вызовов fib(5): почему наивная рекурсия тратит O(2^n), а DP с кэшем — всего O(n)?

                    fib(5)
                  /        \
             fib(4)         fib(3)  <-- С кэшем (DP) вся эта ветка берётся из словаря за O(1)!
            /      \
        fib(3)     fib(2)           <-- И эта ветка берётся из кэша за O(1)!
        /    \
    fib(2)  fib(1)
```

---

## 2. Два подхода DP: Сверху вниз (Top-Down) vs Снизу вверх (Bottom-Up)

| Характеристика | **Top-Down (Мемоизация / Memoization)** | **Bottom-Up (Табуляция / Tabulation)** | **Bottom-Up с оптимизацией памяти** |
| :--- | :--- | :--- | :--- |
| **Как работает?** | Обычная рекурсия от `n` вниз + кэширование ответов в словаре или `@functools.lru_cache` | Итеративный цикл `for` от базовых случаев `0, 1` вверх с заполнением массива `dp[i]` | Храним только 2 последние переменные (`prev2, prev1`) вместо всего массива `dp` |
| **Временная сложность** | **$O(n)$** (каждое состояние считается 1 раз) | **$O(n)$** | **$O(n)$** |
| **Пространственная сложность** | $O(n)$ (словарь кэша + стек рекурсии $O(n)$) | $O(n)$ (массив `dp` без риска `RecursionError`) | **$O(1)$** (только несколько переменных!) |
| **Плюсы** | Пишется за 1 минуту: достаточно добавить `@lru_cache(None)` к рекурсии | Нет накладных расходов рекурсии и лимита в 1000 вызовов | Идеален по памяти и скорости |

## 3. Классические паттерны DP на собеседованиях

### Задача 1: Лестница (`Climbing Stairs`)
На каждом шаге можно подняться на $1$ или на $2$ ступеньки. Сколькими способами можно подняться на $n$-ю ступеньку?
- На ступеньку $i$ можно попасть либо с $(i-1)$-й, либо с $(i-2)$-й $\implies \text{dp}[i] = \text{dp}[i-1] + \text{dp}[i-2]$.

### Задача 2: Размен монет (`Coin Change` — минимальное число монет для суммы $S$)
Даны номиналы монет `coins = [1, 3, 4]` и сумма `amount = 6`.
- **Ловушка жадного алгоритма (Greedy)**: жадный выбор возьмёт самую крупную монету `4`, а остаток доберёт единицами: `4 + 1 + 1` (**3 монеты**).
- **Правильное решение через DP**: перебираем каждую монету $c$ и берём минимум $\text{dp}[x] = \min(\text{dp}[x - c] + 1)$, находя оптимальный ответ `3 + 3` (**2 монеты**)!

> **Junior vs Senior**:
> - **Junior**: Пытается решить задачу о размене произвольных монет жадным алгоритмом (выбирая максимальный номинал на каждом шаге) или пишет рекурсивный перебор без `@lru_cache`, получая экспоненциальное зависание $O(k^n)$.
> - **Senior**: Сначала выписывает **состояние** `dp[x]` и **формулу перехода**, быстро прототипирует решение через `@functools.lru_cache(maxsize=None)`, а для продакшена переводит его в итеративную табуляцию (при необходимости сжимая память с $O(n)$ до $O(1)$).

```python
from functools import lru_cache

# 1. Top-Down DP (Мемоизация): Числа Фибоначчи за O(n) с декоратором @lru_cache
@lru_cache(maxsize=None)
def fib_memo(n: int) -> int:
    if n <= 1:
        return n
    return fib_memo(n - 1) + fib_memo(n - 2)

# 2. Bottom-Up DP с оптимизацией памяти до O(1): Задача о лестнице (Climbing Stairs)
def climb_stairs_o1(n: int) -> int:
    if n <= 2:
        return n
    prev2, prev1 = 1, 2
    for _ in range(3, n + 1):
        prev2, prev1 = prev1, prev2 + prev1
    return prev1

# 3. Bottom-Up DP (Табуляция): Размен монет (Coin Change) за O(amount * len(coins))
def coin_change_min(coins: list[int], amount: int) -> int:
    INF = amount + 1
    dp = [0] + [INF] * amount
    for x in range(1, amount + 1):
        for c in coins:
            if x >= c and dp[x - c] + 1 < dp[x]:
                dp[x] = dp[x - c] + 1
    return dp[amount] if dp[amount] != INF else -1

print("fib_memo(35) за O(n):", fib_memo(35))
print("Способов подняться на 5 ступенек (O(1) памяти):", climb_stairs_o1(5))
print("Мин. монет [1, 3, 4] для суммы 6 (DP побеждает жадный 4+1+1!):", coin_change_min([1, 3, 4], 6))
```
