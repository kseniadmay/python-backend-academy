# 📚 К-114. Стек (Stack), Очередь (Queue) и Дек (`collections.deque`)

> **Ментальная модель — «Стопка тарелок, Очередь в кассу и Вагон метро с дверями с двух сторон»**:
> - **Стек (Stack — LIFO: Last In, First Out)** — стопка чистых тарелок: какую тарелку положили сверху последней (`push`), ту первой и заберут (`pop`).
> - **Очередь (Queue — FIFO: First In, First Out)** — очередь людей в кассу: кто первым встал в очередь (`enqueue`), тот первым и обслуживается (`dequeue`).
> - **Дек (Deque — Double-Ended Queue)** — двусторонняя очередь (`collections.deque`), где вход и выход за $O(1)$ открыты **с обоих концов**.

---

## 1. Стек (Stack — LIFO) и его применения

В Python идеальная реализация стека — это обычный список **`list`**, используемый только с правого конца:
- `stack.append(x)` — положить на вершину (`push`) за амортизированное **$O(1)$**.
- `stack.pop()` — снять с вершины (`pop`) за **$O(1)$**.
- `stack[-1]` — посмотреть вершину без удаления (`peek` / `top`) за **$O(1)$**.

### Где стек незаменим?
1. **Системный стек вызовов (Call Stack)** — хранение локальных переменных и адресов возврата при вызове функций и рекурсии.
2. **Валидация скобочных последовательностей** (`()`, `[]`, `{}`) и вложенных тегов HTML/XML.
3. **Обратная польская нотация (Reverse Polish Notation, RPN)** и вычисление арифметических выражений.
4. **Монотонный стек (Monotonic Stack)** — поиск «следующего большего/меньшего элемента» (`Next Greater Element`, `Daily Temperatures`) за линейное время **$O(n)$** вместо $O(n^2)$.

```python
# 1. Валидация скобочной последовательности через стек за O(n)
def is_valid_brackets(s: str) -> bool:
    pairs = {")": "(", "]": "[", "}": "{"}
    stack: list[str] = []
    for ch in s:
        if ch in pairs:
            # Если встретили закрывающую скобку, вершина стека обязана совпасть с парой
            if not stack or stack.pop() != pairs[ch]:
                return False
        else:
            stack.append(ch)
    return len(stack) == 0

# 2. Монотонный стек: для каждого дня найти, через сколько дней станет теплее, за O(n)
def days_until_warmer(temps: list[int]) -> list[int]:
    result = [0] * len(temps)
    stack: list[int] = []  # храним ИНДЕКСЫ дней в порядке убывания температур
    for cur_day, cur_temp in enumerate(temps):
        while stack and temps[stack[-1]] < cur_temp:
            prev_day = stack.pop()
            result[prev_day] = cur_day - prev_day
        stack.append(cur_day)
    return result

print("Скобки '{[()]}' валидны:", is_valid_brackets("{[()]}"), "| '([)]' валидны:", is_valid_brackets("([)]"))
print("Дней до потепления [73, 74, 75, 71, 69, 72, 76, 73]:", days_until_warmer([73, 74, 75, 71, 69, 72, 76, 73]))
```

## 2. Очередь (Queue — FIFO) и устройство `collections.deque`

**Категорически нельзя** реализовывать очередь через `list.pop(0)`: удаление нулевого элемента в массиве сдвигает все $n-1$ элементов в памяти за **$O(n)$**!
В стандартной библиотеке Python для очередей используется **`collections.deque` (Double-Ended Queue)**.

### Как устроен `collections.deque` внутри CPython?
В отличие от `list` (один непрерывный массив), `deque` реализован как **двусвязный список блоков фиксированного размера** (по 64 указателя в каждом блоке `block`).
Благодаря этому вставка и удаление как слева (`appendleft`, `popleft`), так и справа (`append`, `pop`) работают за **строго константное время $O(1)$** без реаллокации и сдвига всего массива!

```text
Внутреннее устройство collections.deque в CPython (двусвязный список блоков по 64 ячейки):

         leftblock                                      rightblock
             v                                               v
None <-- [ . . x | x | x ] <===> [ x | x | x | x | x ] <===> [ x | x . . . ] --> None
               ^                                                   ^
            leftindex                                          rightindex
      appendleft / popleft O(1)                              append / pop O(1)
```

| Операция | `list` | `collections.deque` | Примечание |
| :--- | :--- | :--- | :--- |
| `append(x)` / `pop()` (справа) | **$O(1)$** | **$O(1)$** | Оба отлично подходят для стека (LIFO) |
| `appendleft(x)` / `popleft()` (слева) | **$O(n)$** (`insert(0)` / `pop(0)`) | **$O(1)$** | Для очереди (FIFO) — только `deque`! |
| Произвольный доступ `d[i]` в середине | **$O(1)$** | **$O(n)$** | В `deque` нужно пройти по цепочке блоков |
| Кольцевой буфер `deque(maxlen=K)` | Нет из коробки | **$O(1)$** | Автоматически вытесняет старые элементы с противоположного конца |

> **Junior vs Senior**:
> - **Junior**: В алгоритме обхода графа в ширину (BFS) или в Rate Limiter использует обычный список `queue = []` и вызывает `queue.pop(0)`, превращая линейный алгоритм $O(V + E)$ в квадратичный $O(V^2)$.
> - **Senior**: Импортирует `from collections import deque`, использует `q.append(x)` и `q.popleft()` за $O(1)$, а для хранения последних $N$ событий или скользящего окна логов задаёт `deque(maxlen=N)`.

```python
from collections import deque

# 1. Классическая очередь FIFO на базе deque + кольцевой буфер истории (maxlen=3)
task_queue: deque[str] = deque(["task_1", "task_2"])
task_queue.append("task_3")          # в конец очереди за O(1)
first_done = task_queue.popleft()    # из начала очереди за O(1)

recent_logs: deque[str] = deque(maxlen=3)
for i in range(1, 6):
    recent_logs.append(f"event_{i}")  # старые события вытесняются автоматически за O(1)

print(f"Выполнена задача: {first_done}, в очереди остались: {list(task_queue)}")
print(f"Последние 3 события в кольцевом буфере: {list(recent_logs)}")
```
