1. Сложность `arr.pop()` с конца? >> $O(1)$
2. Сложность `sorted(arr)` ? >> $O(n \log n)$ по времени (алгоритм Timsort — адаптивный гибрид Merge Sort и Insertion Sort); $O(n)$ памяти, так как создаёт и возвращает новый список
3. Сложность `s1 - s2` (разность множеств)? >> $O(\text{len}(s1))$ (или $O(n)$ по длине первого множества). В отличие от пересечения `s1 & s2` ($O(\min(n, m))$), при разности CPython обязан обойти именно элементы первого множества `s1`, проверяя их вхождение в `s2` за $O(1)$. Поэтому сложность зависит строго от размера `s1`, а не от минимума!
4. Каким типом структуры является `dict` в Python? >> Хэш-таблица; ключи хэшируются для определения индекса в памяти
5. Сложность `arr.copy()` ? >> $O(n)$ ; копирует все ссылки
6. Сложность `len(arr)` ? >> $O(1)$ ; длина хранится как атрибут объекта
7. К какому типу относится `list` в Python? >> Динамический массив; при нехватке места создаётся новый массив большего размера и элементы копируются
8. `x in list` vs `x in set` – в чём разница? >> `list` – $O(n)$ перебор; `set` – $O(1)$ хэш-поиск; для частых проверок наличия – всегда `set`
9. Сложность `list(d.keys())` ? >> $O(n)$ ; нужно создать новый список из всех ключей
10. Сложность `arr.append()` ? >> $O(1)$ амортизированная; редкое перевыделение памяти не влияет на среднюю сложность
11. Сложность `arr.remove(x)` ? >> $O(n)$ ; сначала линейный поиск, потом сдвиг элементов
12. Разница `s.remove(x)` и `s.discard(x)` ? >> `remove` бросает `KeyError` если элемента нет; `discard` молча игнорирует
13. Сложность `s1 & s2` (пересечение множеств)? >> $O(\min(n, m))$ ; итерируется по меньшему множеству
14. Сложность `s1 | s2` (объединение множеств)? >> $O(n + m)$
15. Для чего лучше использовать `set` , а не `list` ? >> Хранение уникальных элементов; частые проверки наличия ( `x in s` ); операции над множествами (объединение, пересечение)
16. Почему `arr.insert(0, x)` – $O(n)$ ? >> Все последующие элементы сдвигаются вправо, чтобы освободить место
17. Сложность `x in s` ? >> $O(1)$ ; хэш-поиск
18. Сложность `del d['key']` ? >> $O(1)$
19. Является ли `dict` в Python 3.7+ упорядоченным? >> Да; гарантирует порядок вставки с Python 3.7; но это не делает поиск по индексу возможным
20. Что делает хэш-функция? >> Вычисляет индекс (bucket) в памяти на основе ключа; обеспечивает $O(1)$ доступ
21. Что такое `set` в Python? >> Хэш-таблица без значений (только уникальные ключи); реализация аналогична `dict`
22. Сложность добавления/обновления ключа в `dict` ? >> $O(1)$ амортизированная
23. Сложность доступа по индексу `arr[i]` ? >> $O(1)$ ; список хранит непрерывный массив ссылок
24. Почему `key in dict` быстрее `key in list` ? >> `dict` использует хэш-функцию ( $O(1)$ ); `list` – линейный перебор ( $O(n)$ )
25. Какие структуры данных Python не поддерживают доступ по индексу? >> `dict` и `set` ; они неупорядочены по индексу (хотя `dict` с Python 3.7+ сохраняет порядок вставки)
26. Сложность `x in arr` ? >> $O(n)$ ; линейный перебор
27. Сложность `arr.pop(0)` ? >> $O(n)$ ; все элементы сдвигаются влево после удаления первого
28. Сложность `len(d)` ? >> $O(1)$ ; длина хранится как атрибут
29. Сложность `arr.index(x)` и `arr.count(x)` ? >> $O(n)$
30. Сложность `d['key']` и `d.get('key')` ? >> $O(1)$ амортизированная
31. Сложность `arr.reverse()` ? >> $O(n)$ ; in-place, $O(1)$ по памяти
32. Сложность `s.add(x)` ? >> $O(1)$ амортизированная
33. Когда операции со словарём деградируют до $O(n)$ ? >> При большом количестве коллизий (редко на практике при хорошей хэш-функции)
34. Поиск дубликатов через `set` vs вложенные циклы? >> `set` : $O(n)$ время, $O(n)$ память; вложенные циклы: $O(n²)$ время, $O(1)$ память
