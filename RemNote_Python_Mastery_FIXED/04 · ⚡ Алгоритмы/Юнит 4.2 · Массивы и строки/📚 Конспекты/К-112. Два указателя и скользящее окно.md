# 🎯 К-112. Паттерны массивов: Два указателя, Скользящее окно и Префиксные суммы

> **Ментальная модель — «Гусеница на ветке и кассовый счётчик»**:
> - **Два указателя (Two Pointers)** — два человека идут по списку навстречу друг другу с разных концов (или один бежит впереди другого), за один проход $O(n)$ находя нужную пару без вложенного цикла $O(n^2)$.
> - **Скользящее окно (Sliding Window)** — рамка (или гусеница), которая ползёт по массиву: когда рамка сдвигается на 1 шаг вправо, нам не нужно заново суммировать все элементы внутри неё — достаточно **прибавить один новый правый элемент и вычесть один ушедший левый** за $O(1)$!
> - **Префиксные суммы (Prefix Sums)** — показания электросчётчика по дням: чтобы узнать расход за неделю с 10-го по 17-е число, не нужно складывать 7 дней — достаточно из показаний 17-го дня вычесть показания 9-го дня за $O(1)$!

## 1. Паттерн «Два указателя» (Two Pointers)

Существует две классические схемы движения указателей `left` и `right`:

### Схема А: Встречные указатели (Opposite / Converging Pointers)
Применяется для **палиндромов**, разворота массива `in-place` и поиска пары с заданной суммой в **отсортированном** массиве (`Two Sum II`, `Container With Most Water`).

```text
Поиск пары с суммой target = 10 в отсортированном массиве:

  left = 0                              right = 4
    v                                       v
[   1,        3,        4,        7,        8   ]
1 + 8 = 9 < 10  ==> сумма мала, двигаем left += 1 (к большему числу: 3 + 7 = 10!)
```

### Схема Б: Попутные указатели (Fast & Slow / Read & Write Pointers)
Оба указателя стартуют с начала (`0`): `fast` («чтец») сканирует каждый элемент, а `slow` («писатель») записывает только подходящие элементы на место (`in-place` за $O(1)$ памяти) — например, удаление дубликатов из отсортированного массива или перемещение всех нулей в конец (`Move Zeroes`).

```python
# 1. Встречные указатели: Two Sum в отсортированном массиве за O(n) времени и O(1) памяти
def two_sum_sorted(nums: list[int], target: int) -> tuple[int, int] | None:
    left, right = 0, len(nums) - 1
    while left < right:
        cur_sum = nums[left] + nums[right]
        if cur_sum == target:
            return left, right
        if cur_sum < target:
            left += 1   # нужна большая сумма -> сдвигаем левый указатель вправо
        else:
            right -= 1  # сумма слишком велика -> сдвигаем правый указатель влево
    return None

# 2. Попутные указатели (Read/Write): удаление дубликатов in-place за O(n) и O(1) памяти
def deduplicate_sorted(nums: list[int]) -> list[int]:
    if not nums:
        return []
    write = 1
    for read in range(1, len(nums)):
        if nums[read] != nums[write - 1]:
            nums[write] = nums[read]
            write += 1
    return nums[:write]

print("Two Sum Sorted [1, 3, 4, 7, 8], target=10 -> индексы:", two_sum_sorted([1, 3, 4, 7, 8], 10))
print("In-place дедупликация [1, 1, 2, 2, 2, 3, 5, 5] ->", deduplicate_sorted([1, 1, 2, 2, 2, 3, 5, 5]))
```

## 2. Паттерн «Скользящее окно» (Sliding Window)

Используется для поиска оптимального **непрерывного подмассива (Subarray) или подстроки (Substring)** за $O(n)$ вместо $O(n \cdot k)$ или $O(n^2)$.

```text
Скользящее окно фиксированного размера k = 3:

Шаг 1: [ 2,  1,  5 ], 1,  3,  2   -> window_sum = 8
Шаг 2:   2, [1,  5,  1 ], 3,  2   -> window_sum = 8 - 2 (ушёл) + 1 (пришёл) = 7
Шаг 3:   2,  1, [5,  1,  3 ], 2   -> window_sum = 7 - 1 (ушёл) + 3 (пришёл) = 9 (MAX!)
```

### Динамическое окно (`left` догоняет `right`)
В задачах вроде *«Самая длинная подстрока без повторяющихся символов»*:
1. Указатель `right` на каждом шаге расширяет окно вправо.
2. Пока инвариант окна нарушен (например, появился дубликат символа), внутренний `while` сжимает окно слева (`left += 1`).
3. **Почему сложность остаётся $O(n)$, несмотря на `while` внутри `for`?** Потому что каждый из указателей `left` и `right` двигается **только вперёд** максимум $n$ раз за всю работу алгоритма ($n + n = 2n = O(n)$ — амортизированный анализ).

```python
# 1. Фиксированное окно размера k: максимальная сумма подмассива за O(n)
def max_subarray_sum_k(nums: list[int], k: int) -> int:
    window_sum = sum(nums[:k])
    best_sum = window_sum
    for right in range(k, len(nums)):
        window_sum += nums[right] - nums[right - k]
        if window_sum > best_sum:
            best_sum = window_sum
    return best_sum

# 2. Динамическое окно: длина самой длинной подстроки без повторов за O(n)
def longest_unique_substring(s: str) -> int:
    seen_chars: set[str] = set()
    left = 0
    max_len = 0
    for right, ch in enumerate(s):
        while ch in seen_chars:
            seen_chars.remove(s[left])
            left += 1
        seen_chars.add(ch)
        max_len = max(max_len, right - left + 1)
    return max_len

print("Макс. сумма окна k=3 в [2, 1, 5, 1, 3, 2]:", max_subarray_sum_k([2, 1, 5, 1, 3, 2], 3))
print("Длина уникальной подстроки в 'abcabcbb':", longest_unique_substring("abcabcbb"))
```

## 3. Паттерн «Префиксные суммы» (Prefix Sums)

Если нужно многократно отвечать на запрос **«Чему равна сумма элементов на отрезке $[L, R]$?»**, наивный `sum(nums[L:R+1])` тратит $O(n)$ на каждый запрос.
Построим массив `prefix` длины $n + 1$, где `prefix[i]` — сумма первых $i$ элементов (`prefix[0] = 0`). Тогда сумма любого отрезка $[L, R]$ вычисляется за **$O(1)$**:

$$\text{sum}(L, R) = \text{prefix}[R + 1] - \text{prefix}[L]$$

| Паттерн | Типичное условие задачи | Временная сложность | Пространственная сложность |
| :--- | :--- | :--- | :--- |
| **Два указателя (Two Pointers)** | Отсортированный массив, палиндром, in-place фильтрация | **$O(n)$** | **$O(1)$** |
| **Скользящее окно (Sliding Window)** | Непрерывный подмассив / подстрока (макс/мин длины или суммы) | **$O(n)$** | **$O(1)$** или **$O(k)$** (для `set`/`dict`) |
| **Префиксные суммы (Prefix Sums)** | Многократные суммы на отрезке $[L, R]$, подмассивы с суммой $K$ | **$O(n)$** предрасчёт, **$O(1)$** запрос | **$O(n)$** |

> **Junior vs Senior**:
> - **Junior**: Применяет скользящее окно к задаче «найти подмассив с суммой $K$» в массиве, где есть **отрицательные числа**. Но с отрицательными числами монотонность окна ломается (сжатие окна может как уменьшить, так и увеличить сумму!).
> - **Senior**: Проверяет инвариант: скользящее окно для суммы работает только при неотрицательных числах ($a_i \ge 0$). Если в массиве есть отрицательные числа, Senior использует **Префиксные суммы + Хэш-таблицу** (`prefix_sum - k in seen_prefixes`) за $O(n)$ времени и $O(n)$ памяти.

```python
# Префиксные суммы: мгновенный запрос суммы отрезка O(1) и поиск подмассивов с суммой K
class RangeSumQuery:
    def __init__(self, nums: list[int]) -> None:
        self.prefix = [0] * (len(nums) + 1)
        for i, x in enumerate(nums):
            self.prefix[i + 1] = self.prefix[i] + x

    def sum_range(self, left: int, right: int) -> int:
        return self.prefix[right + 1] - self.prefix[left]

rsq = RangeSumQuery([10, 20, 30, 40, 50])
print("Сумма на отрезке [1..3] (20+30+40):", rsq.sum_range(1, 3))
print("Сумма на отрезке [0..4] (все элементы):", rsq.sum_range(0, 4))
```
