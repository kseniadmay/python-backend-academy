# 🧱 К-111. Статический и динамический массив: устройство в памяти и амортизация

> **Ментальная модель — «Ряд кресел в кинотеатре vs Раздвижной стол»**:
> - **Статический массив (Static Array)** — это ряд из $N$ пронумерованных кресел, забетонированных в полу вплотную друг к другу. Зная адрес первого кресла, вы за $O(1)$ вычисляете положение любого кресла по формуле. Но если пришла компания из $N+1$ человек, добавить ещё одно кресло в этот ряд нельзя — если соседнее место в зале занято другим объектом.
> - **Динамический массив (Dynamic Array — `list` в Python)** — это ряд с запасом свободных кресел (`capacity > length`). Пока есть запас, новые зрители садятся мгновенно за $O(1)$. Когда запас исчерпан, администратор арендует новый зал в $\approx 1.125\text{–}2$ раза больше, пересаживает всех туда за $O(n)$, и снова появляется просторный запас!

## 1. Статический массив и формула адресной арифметики $O(1)$

**Массив (Array)** хранит элементы в **непрерывном блоке оперативной памяти (Contiguous Memory Block)**.
Благодаря непрерывности процессор не перебирает элементы по одному, чтобы добраться до `arr[i]`, а мгновенно вычисляет точный байтовый адрес:

$$\text{Address}(i) = \text{Base\_Address} + i \times \text{Element\_Size}$$

Именно поэтому чтение `arr[0]` и чтение `arr[999_999]` выполняются за **строго одинаковое время $O(1)$ (Random Access)**. Кроме того, соседние элементы попадают в одну **кэш-линию процессора (CPU Cache Line, обычно 64 байта)**, что обеспечивает отличную **пространственную локальность (Cache Locality)**.

```text
Непрерывный массив указателей PyObject* в CPython list (64-битная ОС, шаг = 8 байт):

Индекс i:       0          1          2          3          4
Адрес:       [0x1000]   [0x1008]   [0x1010]   [0x1018]   [0x1020]
             +----------+----------+----------+----------+----------+
Буфер:       |  ptr_0   |  ptr_1   |  ptr_2   |   свободный запас    |
             +----------+----------+----------+----------+----------+
             <-------- length (ob_size = 3) -->
             <---------------- capacity (allocated = 5) ------------>
```

## 2. Как устроен динамический массив `list` в CPython?

Внутри интерпретатора CPython объект `list` (структура `PyListObject` на языке C) содержит три ключевых поля:
1. `ob_item` (`PyObject **`) — указатель на непрерывный C-массив **ссылок (указателей по 8 байт)** на Python-объекты в куче.
2. `ob_size` (`length`) — текущее число реально хранящихся элементов (`len(lst)`).
3. `allocated` (`capacity`) — сколько всего ячеек под указатели выделено с запасом (сверхрезервирование / **Over-allocation**).

### Алгоритм `list.append(x)` и амортизированная сложность $O(1)$
- **Обычный шаг (`length < capacity`)**: запись ссылки в ячейку `ob_item[length]` и увеличение `length += 1`. Сложность: **$O(1)$**.
- **Реаллокация при переполнении (`length == capacity`)**:
  1. Выделяется новый буфер большего размера (в CPython коэффициент роста составляет $\approx 1.125$, т.е. `new_allocated = newsize + (newsize >> 3) + 6`).
  2. Все $n$ указателей копируются из старого буфера в новый за **$O(n)$**.
  3. Старый буфер освобождается.
- **Почему `append` в среднем стоит $O(1)$ (Amortized $O(1)$)?**
  Дорогое копирование $O(n)$ случается всё реже (по мере экспоненциального роста буфера). Если разделить суммарные затраты на серию из $n$ вызовов `append` ($\approx 2n$ элементарных операций), средняя (**амортизированная / Amortized**) стоимость одного `append` равна константе **$O(1)$**.

```python
import sys

# Отследим, как CPython выделяет память с запасом (over-allocation) при росте list
lst: list[int] = []
prev_bytes = sys.getsizeof(lst)
resizes: list[tuple[int, int]] = []

for i in range(1, 35):
    lst.append(i)
    cur_bytes = sys.getsizeof(lst)
    if cur_bytes != prev_bytes:
        # Каждая дополнительная ячейка в 64-битном CPython весит 8 байт
        delta_slots = (cur_bytes - prev_bytes) // 8
        resizes.append((len(lst), cur_bytes))
        prev_bytes = cur_bytes

print("Моменты реаллокации буфера list (len -> размер в байтах):")
for length, size_b in resizes:
    print(f"  при len={length:2d} -> выделено {size_b} байт")
```

## 3. Почему вставка и удаление в начале списка стоят $O(n)$?

Поскольку в массиве **не может быть «дырок»** между элементами:
- При `lst.insert(0, x)` приходится сдвинуть все $n$ существующих элементов на одну позицию вправо (`arr[i+1] = arr[i]`).
- При `lst.pop(0)` приходится сдвинуть все оставшиеся $n-1$ элементов на одну позицию влево (`arr[i-1] = arr[i]`).

| Операция в `list` | В конец (`i = n-1`) | В середину (`i = n // 2`) | В начало (`i = 0`) | Причина |
| :--- | :--- | :--- | :--- | :--- |
| Чтение / запись `lst[i]` | **$O(1)$** | **$O(1)$** | **$O(1)$** | Прямая адресная арифметика |
| Вставка (`append` / `insert`) | **$O(1)$ аморт.** | **$O(n)$** | **$O(n)$** | Сдвиг всех элементов правее `i` |
| Удаление (`pop()` / `pop(i)`) | **$O(1)$** | **$O(n)$** | **$O(n)$** | Сдвиг всех элементов правее `i` |
| Срез `lst[a:b]` | **$O(b - a)$** | **$O(b - a)$** | **$O(b - a)$** | Аллокация и поверхностное копирование $k = b - a$ ссылок |

## 4. Строки (`str`) и ловушка конкатенации в цикле

В Python строки (`str`) — это **неизменяемые (Immutable)** массивы символов.
Выражение `s = s + ch` внутри цикла из $n$ шагов на каждой итерации выделяет в памяти **новую строку** и копирует в неё все предыдущие символы: $1 + 2 + 3 + \dots + n = \frac{n(n+1)}{2} = O(n^2)$!

> **Junior vs Senior**:
> - **Junior**: Собирает строку в цикле через `result += chunk` или использует `list.pop(0)` для очереди задач, получая квадратичную деградацию $O(n^2)$ при больших объёмах данных.
> - **Senior**: Для сборки строки накапливает фрагменты в `parts: list[str]` за амортизированное $O(1)$ и в конце вызывает `"".join(parts)` (ровно одна аллокация памяти за $O(n)$). Для очереди FIFO использует `collections.deque.popleft()` за честное $O(1)$.

```python
# Эффективная сборка строки за O(n) и удаление элемента из середины массива за O(1)
def build_csv_row(items: list[int]) -> str:
    """Сборка строки через list + ''.join() за линейное время O(n)."""
    parts: list[str] = []
    for item in items:
        parts.append(str(item * 10))
    return ",".join(parts)

def fast_unordered_remove(arr: list[str], index: int) -> str:
    """
    Трюк Swap-and-Pop: если порядок элементов в массиве НЕ важен,
    удаление по индексу можно выполнить за O(1) вместо O(n)!
    """
    removed = arr[index]
    arr[index] = arr[-1]  # записываем последний элемент на место удаляемого за O(1)
    arr.pop()             # отрезаем хвост за O(1) без сдвига массива
    return removed

print("CSV строка:", build_csv_row([1, 2, 3, 4, 5]))
servers = ["srv-1", "srv-2", "srv-3", "srv-4"]
deleted = fast_unordered_remove(servers, 1)
print(f"Удалён за O(1): {deleted}, оставшиеся серверы: {servers}")
```
