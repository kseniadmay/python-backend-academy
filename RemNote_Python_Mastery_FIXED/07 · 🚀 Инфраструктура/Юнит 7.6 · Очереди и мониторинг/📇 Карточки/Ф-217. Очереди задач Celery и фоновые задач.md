1. Какая команда отправляет задачу в очередь? >> `.delay(*args)` – быстрый вариант; `.apply_async(args, kwargs, countdown=...)` – с дополнительными параметрами
2. Что делает `countdown=300` в `apply_async` ? >> Откладывает выполнение задачи на 300 секунд (5 минут) от момента отправки
3. Зачем в `celery.py` используется `namespace='CELERY'` ? >> Celery читает только настройки Django с префиксом `CELERY_` ; исключает конфликты с другими настройками
4. Что такое Celery? >> Распределённая система выполнения фоновых задач для Python; позволяет выносить длительные операции из HTTP-запроса в отдельные процессы
5. Как настроить автоматический повтор задачи при ошибке? >> `autoretry_for=(Exception,)` , `max_retries=3` , `default_retry_delay=60` в декораторе; или `self.retry(exc=e, countdown=60)` в блоке `except`
6. Что такое экспоненциальный backoff в Celery? >> Постепенное увеличение задержки между повторами: `countdown = 2 ** self.request.retries * 60` ; снижает нагрузку при массовых сбоях
7. Что такое `chain` в Celery? >> Последовательное выполнение задач; результат предыдущей передаётся в следующую через `.s()` (signature)
8. Какой декоратор используется для создания задачи Celery? >> `@shared_task` ; не привязан к конкретному экземпляру приложения – предпочтителен в Django-приложениях
9. Что такое `chord` в Celery? >> `group` + callback: параллельные задачи с финальной задачей, которая запускается после завершения всех
10. Чем Redis отличается от RabbitMQ как брокер? >> Redis: высокая производительность, простая настройка, но риск потери задач при перезапуске (данные в RAM); RabbitMQ: надёжнее (персистентность на диске), поддерживает AMQP, рекомендуется для критичных задач (платежи)
11. Что делает воркер (Worker)? >> Извлекает задачи из очереди брокера и выполняет их в фоновом режиме
12. Что такое AMQP? >> Advanced Message Queuing Protocol – стандартный протокол обмена сообщениями, используемый RabbitMQ
13. Почему нельзя использовать `--beat` при запуске нескольких воркеров? >> Beat будет работать в каждом воркере – задачи будут дублироваться; Beat должен быть один
14. Какие статусы может иметь задача Celery? >> `PENDING` , `STARTED` , `SUCCESS` , `FAILURE` , `RETRY` , `REVOKED`
15. Что даёт `bind=True` в `@shared_task` ? >> Передаёт экземпляр задачи первым аргументом ( `self` ); нужен для `self.retry()` , `self.request.retries` и доступа к метаданным
16. Что делает `expires` в `apply_async` ? >> Устанавливает срок годности задачи в секундах; если задача не начата до истечения – удаляется из очереди
17. Для чего используется Result Backend? >> Хранит статусы и результаты выполненных задач; позволяет приложению проверить статус через `task.status`
18. Чем `eta` отличается от `countdown` ? >> `eta` – точный момент запуска ( `datetime` -объект); `countdown` – задержка в секундах от текущего момента
19. Чем `.apply_async()` отличается от `.delay()` ? >> `apply_async` поддерживает дополнительные параметры: `countdown` , `eta` , `queue` , `expires` , `retry` ; `.delay()` – удобный shortcut без них
20. Что такое `group` в Celery? >> Параллельный запуск списка задач; все задачи выполняются одновременно
21. Команда для запуска воркера Celery? >> `celery -A project_name worker -l info` ; флаг `-Q high_priority` – только конкретная очередь; `--concurrency=4` – количество процессов
22. Что такое Flower? >> Веб-интерфейс для мониторинга задач, воркеров и очередей Celery в реальном времени
23. Базовая цепочка архитектуры Celery? >> Приложение → Брокер (очередь) → Воркер (выполнение) → Result Backend (хранение результатов)
24. Что делает `task.get()` ? >> Блокирует текущий поток и ждёт результата задачи; при `timeout` – бросает `TimeoutError` ; вызов в воркере приводит к дедлоку
25. Что такое Celery Beat? >> Планировщик периодических задач; запускается отдельным процессом: `celery -A project_name beat -l info`
26. Что такое брокер в архитектуре Celery? >> Промежуточное хранилище очередей задач; принимает задачи от приложения и раздаёт воркерам; типично Redis или RabbitMQ
