1. Как называется подзапрос в `FROM` ? >> Производная таблица (derived table)
2. Что означает условие `e2.department = e1.department` в коррелированном подзапросе? >> Привязка внутреннего подзапроса к отделу текущей строки внешнего запроса; `e1` – внешний, `e2` – внутренний
3. Что является связующим полем между `employees` и CTE `dept_avg` в примере? >> Поле `department`
4. Какой тип значения должен возвращать подзапрос в `WHERE salary > (...)` ? >> Скалярное значение – одно число
5. Какое ключевое преимущество CTE перед подзапросами в `FROM` ? >> Читаемость и разделение логики: каждый CTE – отдельный именованный блок; один CTE можно использовать несколько раз в одном запросе
6. Что находится внутри скобок в `WITH dept_avg AS (...)` ? >> Полноценный `SELECT` -запрос
7. Конструкция `WITH` – более читаемая альтернатива чему? >> Подзапросам в секции `FROM` (производным таблицам)
8. Чем `EXISTS` отличается от `IN` при использовании с подзапросом? >> `EXISTS` проверяет наличие хотя бы одной строки и останавливается при первом совпадении; работает эффективнее `IN` на больших таблицах, особенно при наличии `NULL`
9. Как называется `SELECT` на самом верхнем уровне вложенности? >> Внешний запрос
10. Как данные из CTE `dept_avg` объединяются с основной таблицей? >> Через `JOIN` по полю `department`
11. В каком случае подзапрос в `WHERE` возвращает набор строк? >> При использовании с операторами `IN` , `ANY` , `ALL` , `EXISTS`
12. Что такое подзапрос в SQL? >> Инструкция `SELECT` , вложенная внутрь другого SQL-выражения
13. Что такое коррелированный подзапрос? >> Подзапрос, который ссылается на значения из внешнего запроса и выполняется заново для каждой строки
14. В чём главная особенность выполнения коррелированного подзапроса? >> Он выполняется для каждой строки внешнего запроса отдельно, что делает его потенциально медленным
15. В каких четырёх секциях SQL-запроса могут встречаться подзапросы? >> `WHERE` , `FROM` , `SELECT` и `HAVING`
16. Можно ли использовать подзапрос внутри блока `SELECT` ? >> Да; такой подзапрос должен возвращать ровно одно скалярное значение (одну строку, один столбец)
17. Для чего использовалась группировка внутри производной таблицы в примере со статистикой отделов? >> Для предварительного вычисления средних зарплат по каждому отделу до фильтрации внешним запросом
18. Какое ключевое слово используется для объявления CTE? >> `WITH`
19. Какое требование обязательно для подзапроса в секции `FROM` ? >> Наличие псевдонима (alias): `(SELECT ...) AS dept_stats`
20. Где чаще всего используются подзапросы на практике? >> В секции `WHERE`
21. Когда в `WHERE` целесообразно использовать `IN` с подзапросом? >> Когда подзапрос возвращает список значений: `WHERE department_id IN (SELECT id FROM departments WHERE location = 'Moscow')`
22. В каком блоке подзапрос позволяет фильтровать группы по результатам агрегатных функций? >> В `HAVING`
23. Какая операция выполняется первой в запросе с некоррелированным подзапросом в `WHERE` ? >> Внутренний подзапрос выполняется один раз, затем его результат используется внешним запросом
24. Какую задачу выполняет подзапрос в `WHERE salary > (SELECT AVG(salary) FROM employees)` ? >> Вычисляет среднюю зарплату по всей таблице один раз; результат используется для сравнения с зарплатой каждой строки
25. Где объявляется имя производной таблицы? >> После закрывающей скобки подзапроса: `FROM (SELECT ...) AS dept_stats`
26. Подзапрос, который ссылается на внешний запрос, называется? >> Коррелированным
27. Как обратиться к `avg_sal` из подзапроса в `FROM` во внешнем `WHERE` ? >> Через псевдоним производной таблицы: `WHERE dept_stats.avg_sal > 80000`
28. Что произойдёт, если подзапрос в `FROM` не имеет псевдонима? >> Ошибка синтаксиса
29. Как корреляция с внешним запросом влияет на производительность? >> Замедляет выполнение: при N строках в внешнем запросе подзапрос выполняется N раз
30. Какую роль выполняет `AS` в конструкции `WITH name AS (...)` ? >> Связывает имя CTE с телом подзапроса, который его формирует
31. Когда коррелированный подзапрос необходим? >> Когда нужно сравнить значение строки с агрегатом её группы: например, зарплата сотрудника vs средняя по его отделу
32. Можно ли ссылаться на один CTE несколько раз в одном запросе? >> Да – в отличие от производной таблицы, CTE объявляется один раз и доступен во всём запросе
33. Почему CTE предпочтительнее при сложных многоуровневых запросах? >> Логика подготовки данных отделена от логики финальной выборки; код проще читать и отлаживать
34. Где располагается основной `SELECT` в запросе с CTE? >> Сразу после блока `WITH ... AS (...)`
35. Зачем в одном запросе к `employees` используются два псевдонима `e1` и `e2` ? >> Чтобы различать внешнюю и внутреннюю копии одной таблицы при самосравнении
36. Функционально CTE и производная таблица решают одни задачи? >> Да; но поведение различается: в PostgreSQL до версии 12 CTE материализовался (выполнялся один раз и кэшировался); с PostgreSQL 12 оптимизатор может встраивать (inline) CTE как обычный подзапрос
37. Где происходит фильтрация `avg_sal > 80000` в запросе с производной таблицей? >> Во внешнем запросе, после того как подзапрос сформировал временную таблицу
38. Что возвращает подзапрос `SELECT id FROM departments WHERE location = 'Moscow'` ? >> Список `id` отделов в Москве для фильтрации через `IN`
39. Как называется подзапрос, размещённый в секции `FROM` ? >> Производная таблица (derived table)
40. В чём риск использования большого числа коррелированных подзапросов? >> Значительное падение производительности при росте объёма данных
41. Что такое CTE (Common Table Expression)? >> Именованный временный результат запроса, объявляемый через `WITH` перед основным `SELECT`
