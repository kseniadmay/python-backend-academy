1. Когда следует использовать `UNION ALL` ? >> Когда дубликаты допустимы или гарантированно не возникнут – для оптимизации производительности
2. Как в `UNION ALL` различить источник данных для каждой строки? >> Добавить дополнительный столбец с константой: `SELECT name, 'customer' AS type FROM customers UNION ALL SELECT name, 'supplier' AS type FROM suppliers`
3. Для чего используются `UNION` и `UNION ALL` в SQL? >> Для объединения результирующих наборов нескольких `SELECT` -запросов в один
4. Какой оператор работает быстрее: `UNION` или `UNION ALL` ? >> `UNION ALL` – не тратит ресурсы на поиск и удаление дубликатов
5. Если одно и то же лицо есть и в таблице клиентов, и в таблице поставщиков, сколько раз оно появится в результате `UNION` ? >> Один раз – `UNION` удалит дубликат
6. Что такое `UNION` ? >> Оператор объединения наборов данных с автоматическим удалением дублирующихся строк
7. Что произойдёт, если типы данных в объединяемых `SELECT` несовместимы? >> Ошибка выполнения запроса
8. Что такое `UNION ALL` ? >> Оператор объединения наборов данных без дедупликации; быстрее `UNION` за счёт отсутствия сравнения строк
9. Как `UNION ALL` обрабатывает дублирующиеся строки? >> Сохраняет все строки включая дубликаты – дедупликация не выполняется
10. Почему `UNION` медленнее `UNION ALL` ? >> `UNION` выполняет дедупликацию: сравнивает все строки результата, что требует дополнительных ресурсов
11. Как `UNION` обрабатывает дублирующиеся строки? >> Удаляет все повторяющиеся строки, оставляя только уникальные
12. Каков результат `UNION` двух таблиц по 10 строк с 2 идентичными (при отсутствии дублей внутри таблиц)? >> 18 строк – 2 дубликата удаляются
13. Когда следует использовать `UNION` ? >> Когда дубликаты в итоговом результате недопустимы
14. Каков результат `UNION ALL` двух таблиц по 10 строк с 2 идентичными? >> 20 строк – все строки сохраняются
15. Какие два требования предъявляются к объединяемым `SELECT` -запросам? >> Одинаковое количество столбцов и совместимые типы данных в соответствующих столбцах
16. Если в объединяемых таблицах гарантированно нет дубликатов, какой оператор эффективнее? >> `UNION ALL` – даёт тот же результат без лишних затрат на дедупликацию
