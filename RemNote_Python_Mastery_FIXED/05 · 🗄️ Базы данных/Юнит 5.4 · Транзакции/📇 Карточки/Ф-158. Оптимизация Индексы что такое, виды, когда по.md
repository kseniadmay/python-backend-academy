1. Как создать Hash-индекс по `email` в таблице `users` ? >> `CREATE INDEX idx_users_email_hash ON users USING HASH(email);`
2. Почему не стоит индексировать столбец `gender` ? >> Низкая кардинальность (2–3 значения); оптимизатор выберет sequential scan, так как индекс не даст ускорения
3. В каких частях запроса индекс ускоряет работу помимо `WHERE` ? >> `JOIN ON` , `ORDER BY` , `GROUP BY`
4. Какую основную задачу выполняет индекс в БД? >> Ускорение поиска строк; без индекса СУБД выполняет sequential scan – перебор всех строк таблицы
5. Что такое уникальный индекс? >> Индекс, гарантирующий уникальность значений; создаётся автоматически для `PRIMARY KEY` и `UNIQUE`
6. Когда sequential scan быстрее индексного поиска? >> На маленьких таблицах (≈ до 1000 строк); накладные расходы на обход индекса превышают стоимость полного скана
7. Что такое составной индекс? >> Индекс по нескольким столбцам; порядок столбцов критически важен
8. Работает ли B-tree индекс для `LIKE '%suffix'` ? >> Нет; `%` в начале паттерна исключает использование B-tree индекса
9. Что происходит с неиспользуемым индексом? >> Занимает место на диске и замедляет `INSERT` / `UPDATE` / `DELETE` ; следует периодически проверять использование индексов через `pg_stat_user_indexes`
10. Какой тип индекса используется в PostgreSQL по умолчанию? >> B-tree (сбалансированное дерево)
11. Какие операции замедляются при наличии индексов? >> `INSERT` , `UPDATE` , `DELETE` ; при каждом изменении данных СУБД обновляет все индексы таблицы
12. Какую временную сложность даёт индекс по сравнению с sequential scan? >> B-tree: `O(log n)` ; Hash: `O(1)` для точного равенства; sequential scan: `O(n)`
13. Как создать частичный индекс только для активных заказов? >> `CREATE INDEX idx_active_orders ON orders(user_id) WHERE status = 'active';`
14. Как создать уникальный индекс по `email` ? >> `CREATE UNIQUE INDEX idx_users_email ON users(email);`
15. Какие типы индексов PostgreSQL используются для JSONB, массивов и полнотекстового поиска? >> `GIN` и `GiST` ; для JSONB чаще `GIN`
16. Когда Hash-индекс предпочтительнее B-tree? >> При поиске исключительно по точному равенству; Hash быстрее ( `O(1)` vs `O(log n)` ), но не поддерживает диапазоны и сортировку
17. Чем сбалансированность B-tree помогает производительности? >> Гарантирует одинаковую глубину дерева и одинаково быстрый доступ к любому значению вне зависимости от данных
18. Будет ли использован индекс `(user_id, created_at)` для `WHERE created_at > '2024-01-01'` ? >> Нет; ведущий столбец `user_id` не указан – правило левого префикса нарушено
19. Почему в составном индексе `(a, b, c)` важен порядок столбцов? >> Работает правило левого префикса: индекс используется для `(a)` , `(a, b)` , `(a, b, c)` , но не для `(b)` или `(b, c)` без `a`
20. Что такое кардинальность столбца? >> Количество уникальных значений; высокая кардинальность (id, email) – индекс эффективен; низкая (gender, status) – индекс бесполезен
21. Что такое частичный индекс? >> Индекс, охватывающий только строки, удовлетворяющие условию `WHERE` ; меньше по размеру и быстрее обновляется
22. Для какого единственного типа сравнения предназначен Hash-индекс? >> Точное равенство ( `=` ); диапазонный поиск ( `>` , `<` , `BETWEEN` ) не поддерживается
23. Как создать составной индекс для `orders` по `user_id` и `created_at` ? >> `CREATE INDEX idx_orders_user_date ON orders(user_id, created_at);`
24. Почему индекс по столбцу с низкой кардинальностью неэффективен? >> Индекс укажет на большую часть строк таблицы; СУБД всё равно прочитает почти все страницы – выгоднее sequential scan
25. Для каких операций эффективен B-tree индекс? >> `=` , `>` , `<` , `>=` , `<=` , `BETWEEN` , `ORDER BY` , `LIKE 'prefix%'` (только префикс)
