1. Что даёт `FORMAT JSON` в `EXPLAIN` ? >> Структурированный вывод плана для машинной обработки или визуализации в инструментах вроде `explain.depesz.com`
2. Для чего добавляется параметр `BUFFERS` в `EXPLAIN` ? >> Показывает информацию об использовании буферного кэша: сколько данных прочитано из памяти ( `shared hit` ) и с диска ( `shared read` )
3. Какую комбинацию параметров используют для полного анализа запроса? >> `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)`
4. О чём говорит значительное расхождение между `rows` и `actual rows` ? >> Устаревшая статистика таблицы; планировщик строит план на основе неактуальных данных
5. Чем `EXPLAIN ANALYZE` отличается от `EXPLAIN` ? >> `EXPLAIN` – только оценки планировщика без выполнения; `EXPLAIN ANALYZE` – реальное выполнение с фактическими данными; на `DELETE` / `UPDATE` данные изменяются
6. Что означает `Seq Scan` в выводе `EXPLAIN` ? >> Полное последовательное сканирование всей таблицы; на больших таблицах сигнализирует об отсутствии или неиспользовании индекса
7. Что показывает `actual time=0.05..0.08` ? >> Реальное время начала получения данных (0.05 мс) и завершения (0.08 мс); в миллисекундах
8. Что такое `Index Cond` в плане выполнения? >> Условие фильтрации внутри индекса; то, по чему СУБД ищет строки в индексной структуре
9. Что делает `EXPLAIN ANALYZE` ? >> Выполняет запрос и показывает как план, так и фактическую статистику: реальное время, реальное количество строк, количество итераций
10. Популярные инструменты для визуализации планов PostgreSQL? >> `explain.depesz.com` и `pgMustard` ; принимают вывод `EXPLAIN` и строят удобную визуализацию
11. Что означает `width=64` в плане выполнения? >> Средний ожидаемый размер одной строки в байтах
12. Что означает `Index Scan` в плане выполнения? >> СУБД использует индекс для поиска строк; предпочтительнее `Seq Scan` на больших таблицах с высокой кардинальностью
13. Какой параметр `EXPLAIN ANALYZE` первым указывает на узкое место? >> `actual time` ; ищи узел с наибольшим значением
14. Что делать при сильном расхождении `rows` и `actual rows` ? >> Выполнить `ANALYZE table_name` ; обновляет статистику о распределении данных в таблице
15. Что делает команда `EXPLAIN` ? >> Показывает план выполнения запроса (действия СУБД, порядок JOIN, методы сканирования) без реального выполнения запроса
16. Является ли `cost` реальным временем в секундах? >> Нет; это абстрактная оценка сложности в условных единицах; используется для сравнения планов между собой
17. Что означают два числа в `cost=0.43..8.45` ? >> Первое ( `0.43` ) – startup cost (стоимость до первой строки); второе ( `8.45` ) – total cost (полная стоимость узла); в условных единицах, не секундах
18. Когда `Seq Scan` не является проблемой? >> На маленьких таблицах; накладные расходы на обход индекса могут превысить стоимость полного скана
19. Что показывает `rows` в выводе `EXPLAIN` ? >> Оценочное количество строк, которое планировщик ожидает получить; может расходиться с реальностью
20. Если при наличии индекса в плане появился `Seq Scan` , что это означает? >> Планировщик посчитал индекс неэффективным (мало строк, устаревшая статистика, низкая кардинальность) или индекс не подходит для данного запроса
21. Что означает параметр `loops` ? >> Количество раз, которое выполнялся данный узел плана; `actual time` для одной итерации нужно умножать на `loops`
