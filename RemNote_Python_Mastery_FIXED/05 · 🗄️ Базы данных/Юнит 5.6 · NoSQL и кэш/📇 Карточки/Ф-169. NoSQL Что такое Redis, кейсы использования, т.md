1. Как убрать TTL и сделать ключ постоянным? >> `r.persist(key)`
2. Чем `Sorted Set` отличается от `Set` ? >> Каждый элемент имеет числовой вес ( `score` ); элементы автоматически упорядочены по score; используется для лидербордов
3. Какой тип данных Redis хранит строки, числа и сериализованные объекты? >> `String` ; базовый тип, поддерживает любые последовательности байтов
4. Что возвращает `r.ttl(key)` для вечного ключа? >> `-1` ; для несуществующего ключа – `-2`
5. Что делает `hgetall` ? >> Возвращает все поля и значения хеша
6. Как сериализовать Python-объект для хранения в Redis? >> `json.dumps(obj)` перед записью; `json.loads(cached)` при чтении; или `pickle` для сложных объектов
7. Как установить значение и TTL за одну операцию? >> `r.setex(key, seconds, value)` или `r.set(key, value, ex=seconds)`
8. Что такое `Hash` в Redis? >> Словарь пар «поле-значение» внутри одного ключа; удобен для хранения объектов с атрибутами
9. Что делает `sinter` ? >> Возвращает пересечение нескольких множеств (общие элементы)
10. Как устроен тип `List` в Redis? >> Двусвязный список; `O(1)` для добавления/извлечения с обоих концов; используется для очередей и стеков
11. Что такое TTL в Redis? >> Time To Live – время жизни ключа в секундах; по истечении ключ автоматически удаляется
12. Является ли `r.incr()` атомарной операцией? >> Да; выполняется как единое целое без прерывания другими командами; безопасна при конкурентном доступе
13. Как получить топ-3 лидеров из Sorted Set? >> `r.zrevrange("leaderboard", 0, 2, withscores=True)` ; `zrevrange` возвращает в порядке убывания score
14. Почему Redis так быстр? >> Все данные в оперативной памяти; операции выполняются без дискового I/O; сотни тысяч операций в секунду
15. Что делают `rpush` и `lpop` ? >> `rpush` – добавляет в конец (правый конец); `lpop` – извлекает из начала (левый конец); паттерн FIFO-очереди
16. Что произойдёт с данными Redis при выключении питания без настроенной персистентности? >> Все данные потеряются; RAM энергозависима
17. Что делает `r.incr(key)` ? >> Атомарно увеличивает числовое значение на 1; если ключ не существует – создаёт со значением 1
18. Что такое атомарная операция в Redis? >> Операция, выполняемая как единое целое; другие команды не могут прервать её выполнение; Redis однопоточный – все команды атомарны по умолчанию
19. В чём риск использования Redis только как кэша без персистентности? >> При перезапуске весь кэш сбрасывается; нужно прогревать кэш заново; приемлемо для кэша, критично для очередей
20. Чем `Set` отличается от `List` ? >> `Set` – неупорядоченное множество уникальных значений; `List` – упорядоченный список с дублями; `Set` поддерживает операции `sinter` , `sunion` , `sdiff`
21. Зачем в Rate Limiting `expire` устанавливается только при `count == 1` ? >> Чтобы окно ограничения отсчитывалось с первого запроса; повторная установка сбрасывала бы таймер
22. Какие механизмы персистентности поддерживает Redis? >> `RDB` – периодические снимки данных на диск; `AOF` (Append Only File) – журнал всех операций записи; можно комбинировать
23. Как Redis реализует кэш-паттерн (cache-aside)? >> `if cached: return cached` – возврат из Redis без обращения к БД; при промахе – запрос к БД, запись в Redis с TTL
24. Основные кейсы использования Redis? >> Кэширование (запросов, API, сессий); брокер сообщений для Celery; rate limiting; pub/sub; лидерборды (Sorted Set)
25. Что такое Redis? >> In-memory хранилище данных типа «ключ-значение»; Remote Dictionary Server; хранит данные в RAM для экстремальной скорости
