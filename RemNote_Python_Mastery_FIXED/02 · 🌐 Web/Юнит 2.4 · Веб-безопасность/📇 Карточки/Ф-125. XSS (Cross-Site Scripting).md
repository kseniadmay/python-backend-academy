1. Каковы основные методы защиты веб-приложения от XSS (Cross-Site Scripting)? >> Экранирование пользовательских данных перед вставкой в HTML; `<script>` → `&lt;script&gt;` ; браузер отображает как текст, не выполняет
2. Что такое Content Security Policy (CSP) и как этот HTTP-заголовок предотвращает атаки? >> HTTP-заголовок, ограничивающий источники загрузки ресурсов; запрещает inline-скрипты; блокирует внедрённый код даже при XSS
3. Защищает ли `HttpOnly` от всех последствий XSS? >> Только от кражи куки; XSS всё ещё может читать данные страницы, отправлять запросы, подменять UI
4. Что такое DOM-based XSS? >> Уязвимость в клиентском JavaScript; сервер не участвует; скрипт страницы берёт данные из `window.location` и вставляет в `innerHTML`
5. Что делает `script-src 'self'` в CSP? >> Разрешает выполнение скриптов только с того же домена; внешние и inline скрипты блокируются
6. Как `HttpOnly` защищает от XSS? >> Кука недоступна для `document.cookie` ; XSS-скрипт не может украсть сессионный токен
7. Чем `textContent` безопаснее `innerHTML` ? >> `textContent` вставляет как обычный текст; `innerHTML` интерпретирует как HTML – может выполнить внедрённые теги
8. Три типа XSS? >> Reflected (отражённая); Stored (хранимая); DOM-based
9. Что такое XSS? >> Атака, при которой злоумышленник внедряет вредоносный JavaScript в страницу; скрипт выполняется в браузере жертвы как доверенный код
10. Почему `{{ user_input | safe }}` опасен? >> Отключает автоэкранирование; браузер интерпретирует ввод как исполняемый HTML/JS
11. Когда нужно экранировать данные? >> Непосредственно перед вставкой в HTML; не при сохранении в БД
12. Чем Stored XSS опаснее Reflected? >> Атакует каждого посетителя без рассылки ссылок; достаточно один раз сохранить скрипт
13. Как Django шаблоны обрабатывают переменные по умолчанию? >> Автоматическое экранирование всех переменных; `{{ user_input }}` безопасен по умолчанию
14. Почему нельзя использовать `eval()` с пользовательскими данными? >> Выполняет строку как JavaScript-код; прямая XSS-уязвимость
15. Является ли автоэкранирование Django полной защитой от XSS? >> Нет; защищает от базовых XSS в HTML, но не заменяет CSP и `HttpOnly` ; DOM-based XSS требует отдельных мер
16. Что такое Stored XSS? >> Скрипт сохраняется в БД (комментарий, пост, имя профиля); выполняется у всех посетителей страницы автоматически; более массовая атака
17. Что может сделать XSS-скрипт? >> Украсть куки и токены; выполнить действия от имени пользователя; подменить контент; провести фишинг внутри доверенного сайта
18. Что такое Reflected XSS? >> Вредоносный скрипт передаётся в URL-параметре; сервер отражает его в ответе; активируется переходом жертвы по специальной ссылке
