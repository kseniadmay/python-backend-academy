## Зачем нужен DNS

Компьютеры в сети общаются через **IP-адреса** (`93.184.216.34`), но людям удобнее запоминать доменные имена (`example.com`). **DNS** (Domain Name System) – распределённая система, которая переводит (резолвит) человекочитаемые доменные имена в IP-адреса, по которым уже происходит фактическое сетевое соединение. Без DNS каждый раз пришлось бы вручную вводить числовой адрес сервера.

---

## Путь DNS-резолвинга

Когда браузер обращается к `example.com`, происходит цепочка запросов, обычно скрытая от пользователя за миллисекунды:

- 1. Браузер проверяет **локальный кэш** – если домен уже резолвился недавно, используется сохранённый результат.
- 2. Если в кэше нет – запрос уходит к **рекурсивному DNS-резолверу** (обычно предоставляется интернет-провайдером или публичным сервисом вроде `8.8.8.8` от Google).
- 3. Резолвер обращается к **корневому серверу** (root server), который знает, куда идти за доменами верхнего уровня (`.com`, `.org`, `.ru`).
- 4. Корневой сервер направляет к **TLD-серверу** (Top-Level Domain) – серверу, отвечающему за все домены `.com`.
- 5. TLD-сервер направляет к **авторитативному серверу (authoritative nameserver)** – именно он хранит настоящую запись для `example.com` и возвращает конкретный IP-адрес.
- 6. Резолвер кэширует результат на время, заданное **TTL** (Time To Live) записи, и возвращает IP-адрес браузеру.

Только после получения IP-адреса браузер устанавливает TCP-соединение с сервером – сам DNS-резолвинг происходит до любого HTTP-запроса.

## Основные типы записей

**A-запись** – сопоставляет доменное имя с IPv4-адресом (`example.com → 93.184.216.34`). **AAAA-запись** – то же самое для IPv6. **CNAME-запись** (Canonical Name) – псевдоним: направляет один домен на другой доменное имя вместо прямого IP (`www.example.com → example.com`), удобно, когда IP-адрес может меняться. **MX-запись** (Mail Exchange) – указывает, какой сервер отвечает за приём почты для домена. **TXT-запись** – произвольный текст, часто используется для верификации владения доменом и настройки защиты от спама (SPF, DKIM). **NS-запись** – указывает, какие серверы являются авторитативными для домена.

## DNS и модуль `socket` в Python

```python
import socket

ip = socket.gethostbyname('example.com')
print(ip)  # '93.184.216.34'
```

`socket.gethostbyname()` – простейший способ выполнить прямой DNS-резолвинг из Python: функция обращается к системному DNS-резолверу операционной системы и возвращает IPv4-адрес для переданного доменного имени. Для более гибкой работы (получение всех записей, IPv6, резолвинг сервисов по протоколу и порту) используется `socket.getaddrinfo()`.

## Почему TTL и кэширование важны

Каждая DNS-запись имеет **TTL** – время в секундах, в течение которого резолверы могут кэшировать результат, не обращаясь заново к авторитативному серверу. Низкий TTL означает быстрое распространение изменений (полезно перед миграцией сервера на новый IP), но увеличивает нагрузку на DNS-инфраструктуру и число запросов. Высокий TTL снижает нагрузку и ускоряет резолвинг для пользователей, но изменения адреса распространяются по интернету медленнее – часть пользователей ещё долго будет попадать на старый IP из закэшированной записи.

---

## Практическое значение

DNS – типичная точка отказа, которую нужно уметь диагностировать: если сайт недоступен, а сервер работает, стоит проверить `nslookup` или `dig` – возможно, проблема именно в резолвинге домена, а не в самом сервере. Понимание DNS также важно при настройке CDN (записи `CNAME`, направляющие на инфраструктуру CDN-провайдера) и при миграции инфраструктуры (важно заранее понижать TTL перед сменой IP-адреса, чтобы переключение прошло быстро).
