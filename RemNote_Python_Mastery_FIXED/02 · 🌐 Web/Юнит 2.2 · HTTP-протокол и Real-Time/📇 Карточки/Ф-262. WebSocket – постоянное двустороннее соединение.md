1. Какую фундаментальную проблему HTTP решает протокол WebSocket? >> В классическом HTTP сервер не может сам отправить сообщение клиенту без предварительного запроса; WebSocket устанавливает постоянное полнодуплексное соединение, где обе стороны могут слать данные в любой момент с минимальными накладными расходами
2. Как начинается установка соединения WebSocket (Handshake)? >> С обычного HTTP/1.1 GET-запроса с заголовками `Connection: Upgrade`, `Upgrade: websocket`, `Sec-WebSocket-Key` и `Sec-WebSocket-Version: 13`
3. Какой HTTP-статус возвращает сервер при успешном переключении на протокол WebSocket? >> `101 Switching Protocols` вместе с заголовком `Sec-WebSocket-Accept`
4. Чем отличаются схемы `ws://` и `wss://`? >> `ws://` — незашифрованный WebSocket поверх TCP (по умолчанию порт 80); `wss://` — зашифрованный WebSocket поверх TLS (по умолчанию порт 443, обязателен для HTTPS-сайтов)
5. Сравните WebSocket, Short Polling, Long Polling и SSE (Server-Sent Events). >> Short Polling — частые HTTP-запросы по таймеру; Long Polling — сервер держит запрос открытым до появления события; SSE — односторонний поток от сервера к клиенту поверх HTTP; WebSocket — полноценный двусторонний канал
6. Когда вместо WebSocket лучше выбрать SSE (Server-Sent Events)? >> Когда данные идут только от сервера к клиенту (лента котировок, уведомления, стриминг ответа LLM токенами): SSE работает поверх обычного HTTP, автоматически переподключается и проще проходит через корпоративные прокси
7. Зачем в WebSocket нужны управляющие фреймы `Ping` и `Pong` (Heartbeat)? >> Чтобы проверять, что клиент всё ещё на связи (не пропал интернет без пакета `FIN`), и не давать промежуточным балансировщикам (Nginx, NAT) закрыть «молчащее» соединение по таймауту
8. Какой серверный интерфейс Python необходим для работы с WebSocket в FastAPI и Django Channels? >> Интерфейс **ASGI** (`uvicorn`, `daphne`, `hypercorn`), так как классический синхронный WSGI (`gunicorn` с sync-воркером) не рассчитан на удержание тысяч долгоживущих асинхронных соединений
9. Как в FastAPI обрабатывается отключение клиента от WebSocket-эндпоинта? >> Оборачиванием цикла `await websocket.receive_text()` в блок `try ... except WebSocketDisconnect:` с удалением сокета из списка активных подключений
10. Почему при масштабировании WebSocket-сервера на несколько контейнеров/процессов нужен Redis Pub/Sub? >> Память процессов изолирована: если Пользователь А подключён к Воркеру 1, а Пользователь Б — к Воркеру 2, то для пересылки сообщения между ними воркеры должны общаться через общую шину (например, Redis Pub/Sub)
11. Как передавать токен аутентификации (JWT) при установке WebSocket-соединения из браузера? >> Браузерный API `new WebSocket(url)` не позволяет задать произвольный заголовок `Authorization`, поэтому токен передают через `HttpOnly`-куки, в первом сообщении после подключения, в `Sec-WebSocket-Protocol` или как одноразовый тикет в query-параметре
12. Какие типы полезных данных (Payload) поддерживает WebSocket на уровне фреймов? >> Текстовые фреймы (UTF-8 строки, обычно JSON — `send_text` / `send_json`) и бинарные фреймы (`bytes` — `send_bytes`, например аудио, видео или Protobuf)
