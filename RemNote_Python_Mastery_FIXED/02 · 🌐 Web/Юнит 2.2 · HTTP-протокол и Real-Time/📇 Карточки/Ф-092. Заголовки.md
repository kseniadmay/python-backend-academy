1. Что произойдет в браузере, если сервер не вернет заголовок Access-Control-Allow-Origin при кросс-доменном запросе? >> Браузер заблокирует доступ JavaScript к ответу
2. Для каких HTTP-запросов браузер отправляет предварительный CORS Preflight-запрос (OPTIONS)? >> Для непростых: `PUT` , `DELETE` , `PATCH` , кастомные заголовки, `Content-Type: application/json`
3. В чем фундаментальная суть механизма CORS (Cross-Origin Resource Sharing)? >> Ограничивает доступ JavaScript к ответам от другого домена если сервер явно не разрешил взаимодействие
4. В чем разница между «простым» (Simple) и «сложным» (Preflighted) CORS-запросом? >> Простые: `GET` / `HEAD` / `POST` с ограниченными заголовками без preflight; сложные требуют preflight-проверки
5. Как взаимодействуют HTTP-заголовки Origin и Access-Control-Allow-Origin при CORS-запросе? >> Браузер отправляет `Origin` ; сервер проверяет и возвращает разрешённый origin в `Access-Control-Allow-Origin`
6. В каких случаях нельзя использовать Access-Control-Allow-Origin: * в CORS? >> Разрешение для любых origin; не поддерживает credentials (cookies, Authorization)
7. Что возвращает сервер если `If-None-Match` совпадает с текущим `ETag` ? >> `304 Not Modified` ; клиент использует кэшированную версию
8. Зачем в `Content-Type` указывается `charset` ? >> Для уточнения кодировки текстовых данных
9. Какой заголовок браузер автоматически добавляет при кросс-доменном запросе? >> `Origin`
10. `Content-Type` при загрузке файлов? >> `multipart/form-data`
11. Для чего `X-Request-ID` ? >> Уникальный идентификатор запроса для трейсинга в распределённых системах
12. Для чего `Access-Control-Allow-Methods` ? >> Перечисляет разрешённые HTTP-методы для CORS
13. Что такое `ETag` ? >> Идентификатор конкретной версии ресурса; метка для механизма условных запросов
14. `Content-Type` для HTML-страницы? >> `text/html; charset=utf-8`
15. В чём разница `no-cache` и `no-store` ? >> `no-cache` – кэш хранится, но проверяется перед использованием; `no-store` – данные вообще не сохраняются
16. Что предписывает `Cache-Control: no-cache` ? >> Всегда проверять актуальность ресурса на сервере перед использованием кэша; кэш хранится, но не используется без валидации
17. `Content-Type` для JSON? >> `application/json`
18. Что означает `Cache-Control: max-age=3600` ? >> Ресурс считается актуальным в кэше в течение 3600 секунд (1 час)
19. `Accept` – заголовок запроса или ответа? >> Запроса
20. За что отвечает заголовок `Accept` ? >> Сообщает серверу в каком формате клиент ожидает ответ
21. Что такое preflight-запрос? >> Предварительный `OPTIONS` -запрос для проверки разрешений сервера перед основным CORS-запросом
22. Как формируется `Authorization` при JWT? >> `Bearer <токен>`
23. Назначение заголовка `Authorization` ? >> Передача учётных данных или токена для аутентификации клиента
24. `Content-Type` для HTML-формы без `enctype` ? >> `application/x-www-form-urlencoded` ; данные кодируются как `key=value&key2=value2`
25. Какую роль выполняют HTTP-заголовки? >> Передают метаданные о запросе или ответе: описывают свойства данных и правила обработки сообщения
26. Для чего используется `Content-Type` ? >> Указывает тип данных в теле сообщения
27. Как сервер и клиент договариваются о формате? >> Через `Content-Type` (сервер сообщает что отдаёт) и `Accept` (клиент сообщает что принимает)
28. Назначение `Cache-Control` ? >> Управление правилами кэширования ресурса
29. Расшифровка CORS? >> Cross-Origin Resource Sharing
30. Как клиент использует `If-None-Match` ? >> Отправляет ранее полученный `ETag` ; сервер возвращает `304` если ресурс не изменился
31. Можно ли передавать cookies если `Access-Control-Allow-Origin: *` ? >> Нет; при credentials сервер обязан указать конкретный origin и `Access-Control-Allow-Credentials: true`
32. Как указать предпочтение JSON, но допустимость HTML? >> `Accept: application/json, text/html;q=0.9`
33. Что означает параметр `q` в `Accept` ? >> Коэффициент приоритета от 0 до 1; чем выше – тем предпочтительнее формат
34. Что предписывает `Cache-Control: no-store` ? >> Полностью запрещает сохранение данных в кэше
35. Для чего заголовок `Content-Length` ? >> Указывает размер тела запроса или ответа в байтах; помогает серверу определить конец сообщения
36. Как передаются данные в `Authorization: Basic` ? >> Строка `user:password` кодируется в Base64: `Authorization: Basic <encoded>`
