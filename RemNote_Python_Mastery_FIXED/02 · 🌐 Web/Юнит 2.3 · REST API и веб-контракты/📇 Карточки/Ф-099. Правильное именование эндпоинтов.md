1. Стандартные параметры пагинации? >> `limit` и `offset` ; или `page` и `per_page`
2. `POST /users` – действие? >> Создание нового пользователя
3. К какой части речи должны относиться имена ресурсов в REST API? >> К существительным; действие задаётся HTTP-методом, а не глаголом в URL
4. Максимально рекомендуемый уровень вложенности URL? >> 2–3 уровня; глубже – сложнее читать и поддерживать
5. Какой метод использовать для действий вне стандартного CRUD? >> `POST` ; действие как sub-ресурс: `POST /users/42/activate` , `POST /orders/7/cancel`
6. Идемпотентны ли `GET` , `PUT` , `DELETE` ? >> Да; повторный одинаковый запрос даёт тот же результат; `POST` – не идемпотентен по умолчанию
7. Как обозначается сортировка по убыванию? >> Минус перед именем поля: `sort=-price`
8. `POST /users/42/orders` – действие? >> Создание нового заказа для пользователя 42
9. Путь для всех заказов пользователя 42? >> `/users/42/orders`
10. Как сократить `/users/42/orders/7/items/3/reviews` ? >> Вынести в отдельный корень: `/order-items/3/reviews`
11. `PATCH /users/42` – действие? >> Частичное обновление пользователя 42; передаются только изменяемые поля
12. Как версионировать REST API? >> Через URL ( `/api/v1/users` ) – наиболее распространено; через заголовок ( `Accept: application/vnd.api.v1+json` ); через query parameter ( `?version=1` )
13. Безопасен ли `GET` ? >> Да; не изменяет состояние сервера; `POST` , `PUT` , `PATCH` , `DELETE` – небезопасны
14. Почему `/getUsers` и `/createOrder` – ошибка в REST? >> Ресурсы должны быть существительными; глагол в URL нарушает принципы REST; корректно: `GET /users` , `POST /orders`
15. Почему `PATCH` предпочтительнее `PUT` для частичного обновления? >> `PATCH` передаёт только изменяемые поля; `PUT` требует полного объекта – риск перезаписать незаполненные поля нулями
16. `PUT /users/42` – действие? >> Полная замена данных пользователя 42; требует передачи всего объекта
17. Через что реализуется фильтрация, сортировка, пагинация? >> Через query parameters: `/users?role=admin&sort=-price&limit=20&offset=40`
18. Стандартный регистр и разделитель слов для URL? >> Нижний регистр; дефис (kebab-case): `/shipping-addresses` ; `camelCase` не рекомендуется
19. `GET /users` – действие? >> Получение списка пользователей
20. Стандартный путь для конкретного ресурса? >> `/users/42` ; идентификатор в пути URL
21. `DELETE /users/42` – действие? >> Удаление пользователя 42
22. Какое число использовать для коллекций в URL? >> Множественное: `/users` , `/orders` , `/products`
23. Что такое идемпотентный ключ для `POST` ? >> Клиент добавляет уникальный заголовок `Idempotency-Key` ; сервер кэширует результат первого запроса; повторный запрос с тем же ключом не создаёт дубликат
24. Почему `/users/delete/42` некорректно? >> Действие задаётся HTTP-методом; корректно: `DELETE /users/42`
25. Для чего вложенные ресурсы в URL? >> Для отображения иерархической связи между сущностями
