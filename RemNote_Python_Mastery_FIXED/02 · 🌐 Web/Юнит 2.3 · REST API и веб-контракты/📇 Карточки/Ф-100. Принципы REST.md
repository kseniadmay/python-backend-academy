1. Что такое HATEOAS в REST API и какова его цель? >> Hypermedia as the Engine of Application State; сервер возвращает не только данные, но и ссылки на доступные действия; клиент динамически обнаруживает возможности API
2. Требует ли архитектурный стиль REST обязательного использования протокола HTTP? >> Нет; REST – архитектурный стиль; HTTP – наиболее распространённая реализация, но не единственная
3. В чем суть архитектурного ограничения Layered System (Многоуровневая система) в REST? >> Клиент не знает, взаимодействует ли он с сервером напрямую или через промежуточные узлы (балансировщики, прокси, кэши, API Gateway)
4. Назовите 4 ключевых ограничения принципа Uniform Interface (Единый интерфейс) в REST. >> Идентификация ресурсов через URI; манипуляция через представления (JSON/XML); самоописывающие сообщения (Content-Type, статус-коды); HATEOAS
5. Опишите 4 уровня модели зрелости Ричардсона (Richardson Maturity Model) для REST API. >> Шкала из 4 уровней (0–3): 0 – один URI для всего; 1 – отдельные URI для ресурсов; 2 – HTTP-методы и статус-коды; 3 – HATEOAS
6. В чем заключается принцип Code on Demand в REST и почему он является опциональным? >> Сервер может передавать клиенту исполняемый код; классический пример – JavaScript в браузере; единственное необязательное ограничение REST
7. В чём разница между REST и RESTful? >> REST – архитектурный стиль; RESTful – API, реализующий принципы REST; большинство реальных API не реализуют HATEOAS и строго говоря не являются полностью RESTful
8. Какую проблему масштабируемости решает Stateless? >> Серверу не нужно хранить и синхронизировать состояния миллионов сессий; любой сервер кластера может обработать запрос
9. Суть Stateless? >> Каждый запрос содержит всю информацию для обработки; сервер не хранит состояние сессии между запросами; токен передаётся в каждом запросе
10. Является ли большинство реальных «REST API» строго RESTful? >> Нет; большинство реализует только уровни 0–2 по Ричардсону (URI + методы), но не HATEOAS; термин «REST» используется неточно
11. Какой принцип является фундаментом REST? >> Uniform Interface – единый интерфейс
12. Суть Cacheable? >> Ответы должны быть явно помечены как кэшируемые или некэшируемые; кэширование возможно на стороне клиента или на промежуточных серверах
13. Шесть ограничений (принципов) REST? >> Client-Server; Stateless; Cacheable; Uniform Interface; Layered System; Code on Demand (необязательное)
14. Что такое ресурс в REST? >> Любая сущность, доступная по уникальному URI; например, пользователь – `/users/42`
15. Что делает сообщения самоописывающими? >> Метаданные: `Content-Type` , статус-коды; клиент интерпретирует ответ без дополнительного контекста
16. Кем и когда описан REST? >> Роем Филдингом в 2000 году в докторской диссертации
17. Является ли REST протоколом или стандартом? >> Нет; REST – архитектурный стиль: набор принципов и ограничений проектирования
18. Суть ограничения Client-Server? >> Клиент и сервер независимы; клиент не знает как хранятся данные, сервер не знает детали UI; можно развивать независимо
