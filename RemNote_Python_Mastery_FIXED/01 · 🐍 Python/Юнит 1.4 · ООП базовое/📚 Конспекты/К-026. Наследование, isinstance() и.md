## Базовое наследование

Наследование выражает отношение "является" (is-a): дочерний класс получает все атрибуты и методы родителя и может их переопределять или дополнять.

```python
class Animal:
    def __init__(self, name):
        self.name = name

    def speak(self):
        return f'{self.name} издаёт звук'

class Dog(Animal):  # Dog является Animal
    def speak(self):  # переопределение метода родителя
        return f'{self.name} лает'

class Cat(Animal):
    pass  # ничего не переопределяет – использует Animal.speak как есть

print(Dog('Рекс').speak())  # 'Рекс лает'
print(Cat('Мурка').speak())  # 'Мурка издаёт звук' – унаследовано без изменений
```

## isinstance() – проверка типа с учётом иерархии

`isinstance(obj, Class)` проверяет, является ли `obj` экземпляром `Class` **или любого его подкласса** – в отличие от `type(obj) == Class`, который проверяет точное совпадение типа.

```python
d = Dog('Рекс')
print(isinstance(d, Dog))  # True
print(isinstance(d, Animal))  # True – Dog это подкласс Animal
print(type(d) == Animal)  # False – точный тип именно Dog, не Animal

print(isinstance(d, (Dog, Cat)))  # True – можно передать кортеж классов,
```

## issubclass() – проверка отношения между классами

`issubclass(ChildClass, ParentClass)` проверяет отношение на уровне **классов**, а не экземпляров.

```python
print(issubclass(Dog, Animal))  # True
print(issubclass(Animal, Dog))  # False – обратное неверно
print(issubclass(Dog, Dog))  # True – класс всегда является подклассом самого себя
```

---

## Почему isinstance() предпочтительнее сравнения type()

`isinstance()` уважает полиморфизm – код, написанный для `Animal`, корректно работает с любым подклассом `Animal`, что и является смыслом наследования. Проверка `type(obj) == Animal` сломается на любом подклассе, даже если он полностью совместим по интерфейсу – это противоречит самой идее ОО-иерархий и считается анти-паттерном за пределами редких случаев, когда точный тип действительно принципиален.

## Когда использовать

Наследование – когда есть настоящее отношение "является" и подклассы действительно должны переиспользовать и расширять поведение родителя (не просто ради переиспользования кода – для этого лучше подходит композиция). `isinstance()` – стандартный способ проверить тип с учётом иерархии перед разной обработкой объектов разных подклассов. `issubclass()` – реже, обычно в метапрограммировании: валидация, что переданный класс (а не экземпляр) соответствует ожидаемому интерфейсу.
