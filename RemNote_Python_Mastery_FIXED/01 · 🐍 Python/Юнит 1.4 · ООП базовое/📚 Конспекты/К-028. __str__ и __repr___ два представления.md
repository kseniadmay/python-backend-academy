## Зачем нужны два разных метода

Любой объект может понадобиться отобразить в двух разных контекстах. Первый – вывод для пользователя: здесь важна читаемость и лаконичность. Второй – отладка и логи: здесь важна однозначность и полнота информации. Python разделяет эти задачи между двумя методами.

---

## `__str__` – представление для человека

**`__str__`** вызывается, когда вы используете `print(obj)` или явно `str(obj)`. Его задача – вернуть строку, понятную без знания внутреннего устройства объекта.

```python
from datetime import date

d = date(2024, 1, 15)
print(str(d))  # '2024-01-15'
```

Это лаконичный формат ISO – понятный и удобный для отображения в интерфейсе или отчёте. Никаких технических подробностей.

---

## `__repr__` – представление для разработчика

**`__repr__`** вызывается в интерактивной консоли (REPL) и через явный `repr(obj)`. Это техническое представление объекта – именно его вы видите в стек-трейсах и логах при ошибках.

```python
print(repr(d))  # 'datetime.date(2024, 1, 15)'
```

Идеал для `__repr__` – строка, по которой можно воссоздать объект: `eval(repr(obj)) == obj`. Это не всегда достижимо на практике, но именно к этому нужно стремиться. Как минимум `__repr__` должен однозначно сообщать тип объекта и его ключевые атрибуты.

---

## Важная асимметрия

Если в классе определён только `__repr__`, Python использует его и вместо `__str__`. Это страховочный механизм: объект никогда не останется без описания. Обратное неверно: если определён только `__str__`, в консоли по-прежнему будет показан адрес объекта вида `<__main__.MyClass object at 0x...>`.

## Как реализовать в своём классе

```python
class Vector:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __repr__(self):
        return f'Vector({self.x}, {self.y})'

    def __str__(self):
        return f'({self.x}, {self.y})'

v = Vector(3, 5)
print(repr(v))  # Vector(3, 5)
print(v)  # (3, 5)
```

`__repr__` сообщает класс и аргументы – достаточно, чтобы понять, что это за объект и как он создан. `__str__` возвращает только координаты – удобно для отображения.

---

## Практические правила

`__repr__` нужно определять всегда – это базовый стандарт для любого класса. Без него объект становится непрозрачным при отладке, и найти проблему в логах будет значительно сложнее. `__str__` определяют только тогда, когда объект реально предназначен для отображения пользователю. Для внутренних служебных объектов отдельный `__str__` избыточен.

На собеседовании важно чётко разграничить: `__repr__` – для разработчика и отладки, `__str__` – для пользователя и вывода. И помнить, что `__repr__` работает как фолбэк для `__str__`, но не наоборот.
