## Создание объекта – это не один шаг

Когда вы пишете `Dog('Rex')`, Python не выполняет это как единое действие. Под капотом происходит два последовательных этапа: сначала объект создаётся в памяти, затем заполняется данными. За каждый этап отвечает свой метод.

---

## `__new__` – создание объекта в памяти

`_`**`_new__`** – это настоящий конструктор. Именно он выделяет память и возвращает новый экземпляр класса. Большинство разработчиков никогда не переопределяют этот метод, потому что стандартная реализация из базового класса `object` справляется автоматически.

```python
class MyObject:
    def __new__(cls, *args, **kwargs):
        instance = super().__new__(cls)
        return instance
```

Первый аргумент `__new__` – это **`cls`**, то есть сам класс, а не экземпляр. Это логично: объекта ещё не существует, поэтому передавать `self` некуда. Метод обязан вернуть созданный экземпляр – если `__new__` не вернёт объект нужного класса, `__init__` вызван не будет.

`__new__` переопределяют в двух основных сценариях: при реализации паттерна **Singleton** (когда нужно гарантировать существование только одного экземпляра класса) и при наследовании от неизменяемых встроенных типов – `int`, `str`, `tuple`. У них нельзя изменить состояние в `__init__`, потому что объект уже создан и зафиксирован, поэтому логику инициализации приходится переносить в `__new__`.

---

## `__init__` – инициализация состояния

`_`**`_init__`** часто называют конструктором, но технически это **инициализатор**. К моменту его вызова объект уже существует в памяти. Задача `__init__` – заполнить этот объект данными: записать атрибуты, установить начальное состояние.

```python
class Dog:
    def __init__(self, name):
        self.name = name
```

Первый аргумент `__init__` – `self` – это уже готовый экземпляр, созданный `__new__`. Метод ничего не возвращает (точнее, возвращает `None`). Попытка вернуть что-то отличное от `None` приведёт к `TypeError`.

В 99% случаев работа с объектами в Python – это работа только с `__init__`.

---

## Порядок вызовов и критическое правило

При вызове `MyClass()` Python выполняет строгую последовательность. Сначала вызывается `__new__(cls)` – создаётся объект и возвращается его экземпляр. Затем Python берёт этот экземпляр и передаёт его в `__init__` как `self`. После этого `__init__` заполняет объект атрибутами.

Критическое правило: если `__new__` вернёт не экземпляр данного класса – `__init__` не будет вызван вообще. Это важно помнить при переопределении `__new__`.

---

## Разница между `__new__` и `__init__`

`__new__` первый по порядку вызова, принимает `cls`, создаёт объект в памяти и обязан его вернуть. `__init__` второй, принимает `self` – уже готовый объект, – заполняет его данными и ничего не возвращает. `__new__` переопределяют редко и по конкретным причинам. `__init__` – стандартное место для любой инициализации.

---

## Практическое значение

Для большинства задач достаточно понимать `__init__`. Знание `__new__` нужно, когда вы встречаете Singleton, метаклассы или работаете с наследованием от встроенных неизменяемых типов. На собеседовании важно чётко разграничить: `__new__` создаёт объект, `__init__` его инициализирует – это не синонимы.
