## Что такое dunder-методы

**Dunder** – сокращение от  *double underscore* , двойное подчёркивание. Это методы вида `__init__`, `__add__`, `__str__`, которые всегда обрамлены двумя символами подчёркивания с обеих сторон. Такое оформление – соглашение языка: оно сигнализирует интерпретатору, что перед ним системный механизм, и исключает случайные коллизии имён с пользовательским кодом.

Их также называют **магическими методами** (magic methods), потому что разработчик почти никогда не вызывает их напрямую – они срабатывают автоматически в ответ на стандартные операции.

---

## Как это работает

Когда вы пишете `v1 + v2`, Python не выполняет сложение напрямую. Он транслирует это выражение во внутренний вызов `v1.__add__(v2)`. Аналогично `str(obj)` превращается в `obj.__str__()`, `len(obj)` – в `obj.__len__()`, `a == b` – в `a.__eq__(b)`.

Этот механизм называется **перегрузкой операторов** (operator overloading): вы определяете, что именно должен делать стандартный оператор применительно к вашему классу.

## Пример: класс `Vector`

```python
class Vector:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __str__(self):
        return f'Vector({self.x}, {self.y})'

    def __len__(self):
        return 2

    def __eq__(self, other):
        return self.x == other.x and self.y == other.y
```

`__init__` вызывается при создании объекта и записывает начальное состояние.

`__str__` определяет, что вернёт `print(v)` и `str(v)` – без него вы увидите адрес объекта в памяти вида `<__main__.Vector object at 0x...>`.

`__len__` позволяет использовать стандартную функцию `len()` на вашем объекте.

`__eq__` переопределяет поведение оператора `==`. Если метод `__eq__` не определён, Python по умолчанию считает равными только ссылки на один и тот же объект в памяти – фактически поведение будет близко к `is`, а не к сравнению содержимого объектов.

## `__str__` vs `__repr__`

Это различие часто встречается на собеседованиях. **`__str__`** – читаемое представление для пользователя, вызывается через `print()` и `str()`. **`__repr__`** – однозначное техническое представление для разработчика, вызывается в интерактивной консоли и через `repr()`. Если определён только `__repr__`, Python использует его и вместо `__str__`. Если определён только `__str__` – в консоли по-прежнему будет показан адрес объекта.

Хорошая практика: `__repr__` должен возвращать строку, по которой можно воссоздать объект, например `Vector(3, 5)`.

## Зачем это нужно на практике

Dunder-методы – основа **протоколов** Python. Протокол – это неформальный интерфейс: если объект реализует нужные методы, он автоматически совместим со встроенными функциями и конструкциями языка. Например, реализовав `__iter__` и `__next__`, вы делаете объект итерируемым – его можно использовать в `for`-цикле. Реализовав `__len__` и `__getitem__`, объект становится совместимым со срезами и функциями, ожидающими последовательность.

Это то, что делает Python гибким: язык не требует наследования от специальных базовых классов – достаточно реализовать нужные методы. Именно так работают все встроенные типы, и именно так ваши классы могут вести себя так же естественно, как `list` или `dict`.
