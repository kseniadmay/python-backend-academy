1. Что проверяет isinstance(obj, Class)? >> Является ли obj экземпляром Class ИЛИ любого его подкласса.
2. Чем isinstance() отличается от type(obj) == Class? >> isinstance учитывает иерархию наследования (подклассы тоже подходят), type() требует точного совпадения типа.
3. Что проверяет issubclass(A, B)? >> Отношение на уровне классов — является ли A подклассом B.
4. Является ли класс подклассом самого себя по issubclass()? >> Да, issubclass(A, A) всегда True.
5. Почему isinstance() предпочтительнее сравнения type()? >> Уважает полиморфизм — работает корректно с любым подклассом, что и есть смысл наследования.
6. Что вернёт isinstance(True, int)? >> True — bool является подклассом int в Python.
7. Можно ли передать кортеж классов в issubclass()? >> Да: issubclass(Dog, (Animal, Mammal)) — проверит "является ли подклассом хотя бы одного из них".
8. Что произойдёт при super().__init__() в классе без явного родителя, кроме object? >> Вызовет object.__init__() — безопасная операция, ничего не делает по умолчанию.
9. Обязательно ли переопределять все методы родителя в дочернем классе? >> Нет, можно переопределить только нужные — остальные наследуются без изменений.
10. Чем плох anti-pattern сравнения type(obj) == ExpectedClass вместо isinstance? >> Ломается на любом легитимном подклассе, даже полностью совместимом по интерфейсу — нарушает принцип полиморфизма.
11. Что произойдёт при issubclass(int, object)? >> True — все классы в Python неявно наследуются от object.
12. Может ли класс наследоваться от нескольких классов одновременно? >> Да, Python поддерживает множественное наследование (см. тему про миксины и MRO).
13. Что вернёт isinstance(5, (int, float))? >> True — 5 является экземпляром int, один из перечисленных в кортеже типов подошёл.
14. Как переопределение __init__ в дочернем классе влияет на наследование методов? >> Не влияет на другие методы — переопределяется только __init__, остальные методы родителя остаются доступны как есть.
