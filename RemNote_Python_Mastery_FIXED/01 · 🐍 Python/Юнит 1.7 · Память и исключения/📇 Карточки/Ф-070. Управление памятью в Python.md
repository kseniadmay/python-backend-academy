1. В чём заключается ловушка интернирования строк при использовании оператора `is` ? >> `a is b` может вернуть `True` для одинаковых строк из-за интернирования, но это деталь реализации CPython, а не гарантия языка; для сравнения строк всегда использовать `==`
2. Какие строки автоматически интернируются в CPython и как принудительно интернировать строку? >> Строки похожие на идентификаторы (без пробелов и спецсимволов); поведение зависит от реализации и не гарантировано
3. Как устроен поколенческий сборщик мусора (Generational GC) в CPython и почему он эффективен? >> Большинство объектов живут недолго; молодые объекты проверяются чаще, старые – реже
4. Поверх какого системного вызова работает менеджер памяти Python? >> `malloc`
5. Как называется механизм переиспользования уже существующих объектов? >> Интернирование
6. Как называется встроенный модуль сборщика мусора? >> `gc`
7. Требуется ли вручную выделять и освобождать память? >> Нет
8. Что использует `pymalloc` для организации памяти? >> Пулы памяти фиксированного размера
9. Пороговый размер объекта для `pymalloc` ? >> 512 байт; крупные объекты передаются напрямую в `malloc`
10. Какой механизм является основным для отслеживания живых объектов? >> Подсчёт ссылок (reference counting)
11. При каком условии reference counting освобождает память? >> Когда счётчик ссылок на объект падает до нуля
12. Для каких целых чисел Python применяет интернирование? >> От `-5` до `256` ; числа вне этого диапазона создаются как новые объекты
13. Что отвечает за обработку циклических ссылок? >> Garbage collector ( `gc` )
14. Какую проблему не может обнаружить reference counting? >> Циклические ссылки: когда объекты ссылаются друг на друга, счётчик никогда не падает до нуля
15. Как осуществляется управление памятью в Python? >> Автоматически через менеджер памяти, reference counting и garbage collector
16. Как называется специальный аллокатор Python для небольших объектов? >> `pymalloc`
17. Главная цель интернирования? >> Экономия памяти и ускорение сравнения идентичных объектов через `is`
18. С какой скоростью освобождается память при reference counting? >> Немедленно; в отличие от GC не требует отдельного прохода
19. Как проверить количество ссылок на объект? >> `sys.getrefcount(obj)` ; возвращает на 1 больше ожидаемого – сама функция создаёт временную ссылку
20. По какому принципу работает GC в Python? >> По поколениям: объекты делятся на 3 поколения (0, 1, 2); чаще всего проверяется поколение 0 (новые объекты)
21. Преимущество пулов памяти перед системными вызовами? >> Ускоряет работу, избегая частых дорогостоящих обращений к ОС
