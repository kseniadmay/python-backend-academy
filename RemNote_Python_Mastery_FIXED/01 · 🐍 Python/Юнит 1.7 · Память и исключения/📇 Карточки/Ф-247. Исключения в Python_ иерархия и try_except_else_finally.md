1. От какого класса наследуются почти все встроенные исключения, которые стоит ловить? >> От Exception (а не BaseException напрямую).
2. Почему не стоит ловить BaseException или использовать голый except? >> Это ловит и SystemExit, и KeyboardInterrupt — сигналы намеренного завершения программы, которые не должны молча глотаться.
3. Когда выполняется блок else в try/except/else? >> Только если блок try завершился без исключений.
4. Когда выполняется блок finally? >> Всегда — было исключение или нет, даже при return внутри try/except.
5. Зачем нужен отдельный else, если код можно оставить внутри try? >> Чтобы явно отделить код, который может упасть, от кода, который должен выполниться только при успехе — исключения в else не перехватываются теми же except выше.
6. Что делает `raise ... from e`? >> Связывает новое исключение с исходным в трейсбеке, сохраняя причину (re-raise с контекстом).
7. От какого класса стоит наследовать собственные исключения? >> От Exception, с суффиксом Error в имени.
8. Какое исключение — родитель для IndexError и KeyError? >> LookupError.
9. Что произойдёт, если исключение возникнет и в except, и есть finally? >> finally выполнится в любом случае, но новое исключение из except заменит контекст обработки — оригинальное отобразится как __context__.
10. Можно ли перехватить несколько типов исключений в одном except? >> Да: except (ValueError, TypeError) as e.
11. Что делает голый raise без аргументов внутри except? >> Повторно бросает то же самое пойманное исключение, сохраняя весь исходный трейсбек.
12. В каком порядке нужно располагать несколько except для связанных по иерархии исключений? >> От более специфичных к более общим — иначе общий класс перехватит раньше, чем код дойдёт до специфичного.
13. Что произойдёт, если return есть и в try, и в finally? >> Возврат из finally "побеждает" — перекрывает return/исключение из try, это частый источник багов.
14. Чем KeyError отличается от IndexError по происхождению? >> KeyError — отсутствие ключа в dict/сопоставлении, IndexError — выход за границы последовательности по индексу.
15. Как можно узнать тип пойманного исключения внутри except Exception as e? >> type(e) или e.__class__.
16. Что делает except* (exception groups), появившийся в Python 3.11? >> Позволяет обрабатывать сразу несколько независимых исключений, возникших параллельно (например, в asyncio.TaskGroup).
17. Что делает `except Exception as e: e.add_note("...")` (Python 3.11+)? >> Добавляет дополнительный контекст к исключению, который отобразится в трейсбеке вместе с основным сообщением.
18. Может ли finally "проглотить" исключение, если внутри него есть return? >> Да — return в finally подавляет любое незавершённое исключение из try/except, это считается анти-паттерном.
19. Что делает traceback.format_exc()? >> Возвращает текст трейсбека текущего исключения в виде строки, для логирования.
20. В чём разница между raise ValueError("x") и raise ValueError? >> Функционально почти идентично — второе создаёт экземпляр без аргументов, message будет пустым.
21. Что произойдёт, если исключение не поймано ни одним except во всей программе? >> Программа завершится, интерпретатор выведет трейсбек в stderr.
22. Как поймать исключение, но проигнорировать его осознанно, не помечая код как "забыли обработать"? >> except SomeError: pass — с комментарием, зачем именно оно игнорируется.
