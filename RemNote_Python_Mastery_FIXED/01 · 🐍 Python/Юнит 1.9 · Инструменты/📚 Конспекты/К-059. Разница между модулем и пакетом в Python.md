## Модуль – один файл .py

**Модуль** – любой файл `.py`, который можно импортировать. Каждый файл с кодом Python, который вы пишете, – уже модуль.

```python
def greet(name):
    return f'Привет, {name}!'
```

```python
import utils
print(utils.greet('Alex'))  # 'Привет, Alex!'
```

---

## Пакет – папка с модулями и файлом __init__.py

**Пакет** – директория, содержащая несколько модулей (и, возможно, вложенные пакеты), помеченная файлом `__init__.py` – он может быть пустым, но его наличие (в классических пакетах) сигнализирует Python, что эту папку нужно трактовать как импортируемый пакет, а не просто директорию с файлами.

```text
myapp/
├── __init__.py
├── models.py
├── views.py
└── services/
    ├── __init__.py
    ├── payment.py
    └── notification.py
```

```python
from myapp import models
from myapp.services import payment
from myapp.services.payment import process_payment
```

---

## __init__.py – не просто формальность

`__init__.py` выполняется при первом импорте пакета – в нём можно определить, что именно доступно при `from package import *`, импортировать и "поднять" наверх часто используемые объекты из вложенных модулей, чтобы сократить путь импорта для пользователей пакета:

```python
from .payment import process_payment
from .notification import send_notification
```

---

## Namespace-пакеты – пакет без __init__.py

Начиная с Python 3.3, директория может выступать пакетом и без `__init__.py` (namespace package, PEP 420) – Python сам определяет её как пакет по наличию импортируемых модулей внутри. На практике `__init__.py` всё равно принято добавлять явно в большинстве проектов – ради предсказуемости и возможности управлять тем, что публично доступно из пакета.

---

## Когда использовать

Модуль – минимальная единица кода, которую есть смысл переиспользовать; если проект маленький, одного-двух модулей может быть достаточно. Пакет – когда модулей становится много и их нужно логически сгруппировать (по слоям приложения, по доменным областям) – стандартная структура для любого нетривиального Python-проекта, включая Django-приложения (каждое Django app – это пакет) и любую библиотеку, публикуемую через pip.
