## Что такое сериализация

**Сериализация** – превращение объекта в памяти (список, словарь, экземпляр класса) в последовательность байт или строку, которую можно сохранить в файл, передать по сети или положить в кэш. **Десериализация** – обратный процесс: восстановление объекта из этого представления. Без сериализации структуры данных Python существуют только в оперативной памяти одного процесса.

---

## json – текстовый, межъязыковой формат

```python
import json

data = {'name': 'Alex', 'age': 30, 'is_admin': False, 'tags': ['python', 'backend']}

json_string = json.dumps(data)
print(json_string)  # '{'name': 'Alex', 'age': 30, 'is_admin': false, 'tags': ['python', 'backend']}'

restored = json.loads(json_string)
print(restored['name'])  # 'Alex'

with open('data.json', 'w') as f:
    json.dump(data, f)  # dump – пишет сразу в файл

with open('data.json') as f:
    loaded = json.load(f)  # load – читает сразу из файла
```

`json.dumps`/`json.loads` работают со **строкой**, `json.dump`/`json.load` – сразу с файловым объектом. JSON поддерживает только ограниченный набор типов: строки, числа, `bool`, `None`, списки, словари (с ключами-строками) – Python `True`/`False`/`None` превращаются в `true`/`false`/`null` по стандарту JSON.

## pickle – бинарный, Python-специфичный формат

```python
import pickle

class User:
    def __init__(self, name, age):
        self.name = name
        self.age = age

user = User('Alex', 30)

binary_data = pickle.dumps(user)

restored_user = pickle.loads(binary_data)
print(restored_user.name, type(restored_user))  # Alex <class '__main__.User'>
```

`pickle` умеет сериализовать практически любой объект Python – включая экземпляры пользовательских классов, множества, кортежи, даже функции – то, что `json` в принципе не умеет без ручного преобразования в словарь.

## Главное различие: переносимость vs полнота

**`json`** – текстовый, человекочитаемый, языконезависимый формат: JSON, полученный из Python, без проблем прочитает JavaScript, Java, Go – универсальный стандарт обмена данными между разными системами. Но он ограничен простыми типами и не может напрямую сериализовать произвольный объект Python. **`pickle`** – бинарный, Python-специфичный: сериализует почти любой объект Python "как есть", но результат бессмысленно передавать в систему, написанную не на Python – она не сможет его разобрать.

## Критическая опасность pickle: небезопасная десериализация

```python

import pickle

class Exploit:
    def __reduce__(self):
        import os
        return (os.system, ('echo "код выполнен из pickle!"',))

malicious = pickle.dumps(Exploit())
```

`pickle.loads()` на данных, полученных из сети, от пользователя, из внешнего API – это уязвимость выполнения произвольного кода (arbitrary code execution), не гипотетическая, а хорошо известная и часто используемая на практике. `json.loads()` этой проблемы лишён – JSON не может закодировать исполняемое поведение, только данные.

## Сериализация объектов через json – нужен кастомный encoder

```python
from datetime import datetime
import json

def custom_encoder(obj):
    if isinstance(obj, datetime):
        return obj.isoformat()
    raise TypeError(f'Object of type {type(obj)} is not JSON serializable')

data = {'created_at': datetime.now()}
print(json.dumps(data, default=custom_encoder))  # {"created_at": "2026-09-23T18:15:00.123456"}
```

`json` из коробки не знает, как сериализовать `datetime`, `Decimal`, кастомные классы – параметр `default` даёт функцию-подсказку, что делать с "непонятными" типами (в веб-фреймворках вроде Django/FastAPI/DRF эта логика обычно уже встроена в сериализаторы).

---

## Когда использовать

`json` – для API, конфигурационных файлов, любого обмена данными между разными системами или языками, для данных из недоверенных источников. `pickle` – только для внутреннего использования внутри своей же Python-системы, когда источник данных полностью доверенный (например, кэширование сложных Python-объектов в Redis внутри одного приложения) – и никогда для данных, пришедших от пользователя или из внешней сети.
