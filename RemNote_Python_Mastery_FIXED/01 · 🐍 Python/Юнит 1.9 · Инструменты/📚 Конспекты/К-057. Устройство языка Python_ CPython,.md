## Python – спецификация, CPython – реализация

**Python** как язык программирования – это строгая **спецификация** синтаксиса и семантики (описанная в официальной документации и Python Enhancement Proposals, PEP).

**CPython** – эталонная, общепринятая реализация этой спецификации, написанная на языке C. Именно она запускается по команде `python` в терминале.

Существуют и альтернативные реализации спецификации Python:
- **PyPy** — реализация с JIT-компилятором (Just-In-Time), ускоряющая вычисления в 2–7 раз.
- **Jython** — компиляция в байткод Java Virtual Machine (JVM).
- **IronPython** — интеграция со средой выполнения .NET CLR.

В продакшен backend-разработке 99% сервисов выполняются именно на **CPython**.

## Путь от .py файла до выполнения: AST, байткод и PVM

Python сочетает черты компилируемых и интерпретируемых языков: он **не компилируется напрямую в машинный код** процессора (как C, Rust или Go), но и **не является чисто построчным скриптом**.

Схема конвейера выполнения:

```text
1. Исходный код (.py)
      ↓ парсинг в AST
2. Синтаксическое дерево
      ↓ компиляция
3. Байткод (.pyc)
      ↓ исполнение
4. Виртуальная машина (PVM)
```

1. **Парсер** преобразует текст `.py` в абстрактное синтаксическое дерево (**AST**).
2. **Компилятор** превращает AST в платформонезависимый **байткод** (набор инструкций для виртуальной машины).
3. Байткод сохраняется в кэш — папку `__pycache__` в виде файлов `.pyc`, чтобы не тратить время на повторный парсинг при неизменном исходнике.
4. **Python Virtual Machine (PVM)** построчно исполняет байткод в цикле `eval loop`.

## Интроспекция байткода: модуль dis

Стандартный модуль **`dis`** (disassembler) позволяет заглянуть под капот любой функции и увидеть инструкции байткода CPython:

```python
import dis


def add(a, b):
    return a + b


dis.dis(add)
```

Вывод дизассемблера раскрывает стек виртуальной машины:

```python
# Инструкции байткода функции add:
# 1 LOAD_FAST   0 (a) — положить a в стек
# 2 LOAD_FAST   1 (b) — положить b в стек
# 3 BINARY_OP   0 (+) — вызвать nb_add
# 4 RETURN_VALUE      — вернуть со стека
```

### Constant Folding (сворачивание констант)

На этапе компиляции AST в байткод CPython выполняет оптимизацию константных выражений:

```python
# Замер сворачивания констант:
dis.dis("seconds = 24 * 60 * 60")
# Инструкция в байткоде всего одна:
# LOAD_CONST 86400 (вычислено сразу!)
```

Вычисление констант происходит один раз при импорте или компиляции, а не на каждом цикле исполнения.

## Почему Python называют медленным: CPU-bound vs I/O-bound

Выполнение байткода виртуальной машиной поверх стека требует дополнительных накладных расходов: каждая инструкция проверяет типы операндов во время работы (динамическая типизация). Поэтому чистые вычисления на Python уступают в скорости компилируемым в машинный код C или Rust.

Однако в реальной backend-разработке это редко является узким местом:

```python
# Backend — это I/O bound операции:
# 90% времени уходит на сеть и БД:
# HTTP -> PostgreSQL -> Redis -> JSON
```

Там, где критична скорость вычислений (CPU-bound), узкие места делегируют C/Rust библиотекам:
- `pydantic-core` (написан на Rust);
- `numpy`, `uvloop` (написаны на C);
- Python выступает в роли надёжного и чистого клея (glue language).

## Модель вычислений PVM: Stack-based Virtual Machine

Виртуальная машина CPython построена по принципу **стекового автомата** (Stack-based VM), в отличие от регистровых виртуальных машин (таких как LuaJIT):

```python
# Стек вычислений:
# 1. Аргументы пушатся в стек
# 2. Оператор берет N верхних операндов
# 3. Результат возвращается на стек
```

Каждый вызов функции в Python создает объект **кадра выполнения (`frame`)** в стеке вызовов. Кадр хранит локальные переменные, ссылки на глобальное пространство имен и указатель на текущую инструкцию байткода.

## Архитектура на собеседовании: GIL и реализация

На технических интервью различие между Python и CPython является базовым маркером уровня кандидата:

1. **GIL (Global Interpreter Lock)** — это особенность конкретной реализации **CPython**, созданная для защиты счетчика ссылок (`PyObject.ob_refcnt`) от гонок данных в многопоточности.
2. В спецификации языка Python нет требования о наличии GIL.
3. В альтернативных реализациях (Jython, IronPython) GIL отсутствует, а в CPython 3.13+ активно развивается экспериментальный режим **free-threaded CPython** (PEP 703 без GIL).
4. Наличие папки `__pycache__` объясняется сохранением байткода модулей для мгновенного старта приложения.
