## Почему pathlib заменил os.path в современном Python

В старом коде пути к файлам хранили в обычных строках (`str`) и склеивали через `os.path.join(os.path.dirname(__file__), "config", "settings.yaml")`. Вложенные вызовы `os.path` трудно читать, а строки не знают ничего о файловой системе.

Модуль **`pathlib`** (PEP 428) представляет пути как полноценные **объекты** класса `Path`, у которых есть удобные свойства (`.name`, `.stem`, `.suffix`, `.parent`), методы чтения/записи и перегруженный оператор деления **`/`** для кроссплатформенной склейки путей (автоматически выбирает `/` на Linux/macOS и `\` на Windows):

```python
from pathlib import Path

# Корень проекта относительно текущего файла (2 уровня вверх)
BASE_DIR = Path(__file__).resolve().parent.parent

# Склейка путей через оператор /
config_path = BASE_DIR / "configs" / "production.env.yaml"
```

## Анатомия объекта Path: разбор пути без регулярок и split()

Объект `Path` мгновенно разбирает путь на составляющие без строковых срезов и `os.path.splitext`:

```python
from pathlib import Path

p = Path("/var/log/nginx/access.tar.gz")

print(p.name)      # 'access.tar.gz' — полное имя файла с расширением
print(p.stem)      # 'access.tar' — имя файла без ПОСЛЕДНЕГО расширения
print(p.suffix)    # '.gz' — последнее расширение (с точкой!)
print(p.suffixes)  # ['.tar', '.gz'] — список всех расширений
print(p.parent)    # Path('/var/log/nginx') — родительская директория
print(p.parents[1]) # Path('/var/log') — дедушка (на 2 уровня выше)

# Замена имени или расширения (возвращает НОВЫЙ объект Path, т.к. Path иммутабелен):
backup = p.with_suffix(".bak")         # /var/log/nginx/access.tar.bak
renamed = p.with_name("error.log")     # /var/log/nginx/error.log
```

## Чтение, запись и управление директориями

Для небольших файлов `Path` позволяет прочитать или записать содержимое в одну строчку, автоматически открывая и закрывая файл:

```python
from pathlib import Path

report = Path("output/reports/summary.txt")

# Создаём все недостающие родительские папки:
# parents=True (как mkdir -p), exist_ok=True (не падать, если папка уже есть)
report.parent.mkdir(parents=True, exist_ok=True)

# Быстрая запись и чтение текста / байтов (без явного with open)
report.write_text("Отчёт готов\n", encoding="utf-8")
content = report.read_text(encoding="utf-8")

# Для больших файлов или построчного чтения используется p.open():
with report.open("a", encoding="utf-8") as f:
    f.write("Дополнительная строка\n")
```

Проверить существование и тип объекта позволяют методы `.exists()`, `.is_file()`, `.is_dir()`, `.is_symlink()`, а получить метаданные (размер в байтах `st_size`, время модификации `st_mtime`) — метод `.stat()`.

## Поиск файлов и обход дерева: iterdir, glob, rglob

Вместо устаревших `os.listdir()` и модуля `glob` объект `Path` предоставляет ленивые генераторы, возвращающие сразу объекты `Path`:

```python
from pathlib import Path

src_dir = Path("src")

# 1. Прямые потомки папки (нерекурсивно)
for item in src_dir.iterdir():
    if item.is_dir():
        print("Подпапка:", item.name)

# 2. Поиск по маске в текущей папке (нерекурсивно)
py_files = list(src_dir.glob("*.py"))

# 3. Рекурсивный поиск по всем вложенным подпапкам (rglob = glob("**/*"))
all_tests = list(src_dir.rglob("test_*.py"))
```

## resolve() vs absolute() и архитектура PurePath vs Path

В `pathlib` иерархия классов разделена на два уровня:

1. **`PurePath`** (`PurePosixPath`, `PureWindowsPath`) — «чистые» вычислительные пути в памяти. Они **не обращаются к ОС и диску**: позволяют разбирать, склеивать и форматировать например Windows-пути, находясь на Linux-сервере.

2. **`Path`** (`PosixPath`, `WindowsPath`) — «конкретные» пути, наследующие `PurePath` и добавляющие системные вызовы ввода-вывода (`exists()`, `mkdir()`, `read_text()`, `unlink()`).

Важное отличие на собеседовании: метод **`p.resolve()`** не только делает относительный путь абсолютным, но и **раскрывает все символические ссылки (symlinks)** и убирает сегменты `..` на уровне файловой системы.
