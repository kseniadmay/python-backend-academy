1. Как в `unittest` проверить, что функция генерирует ожидаемое исключение? >> `assertRaises(ExceptionType, func, *args)` или через контекстный менеджер: `with self.assertRaises(ValueError): func()`
2. Для чего используются `setUp` и `tearDown` ? >> `setUp` – подготовка перед каждым тестом; `tearDown` – очистка после каждого теста; вызываются автоматически
3. Что делает `unittest.main()` ? >> Запускает поиск и выполнение всех методов с префиксом `test_` в модуле
4. Основная цель тестов? >> Убедиться что код работает ожидаемо и не ломается после изменений
5. Самый популярный фреймворк тестирования в Python? >> `pytest`
6. От какого класса наследуются тестовые классы? >> `unittest.TestCase`
7. Назначение `assertFalse` ? >> Проверка что выражение ложно
8. Прообразом `unittest` стал какой фреймворк? >> `JUnit` из Java
9. С какого префикса должны начинаться тестовые методы? >> `test_` ; методы без этого префикса не будут запущены как тесты
10. Назначение `assertEqual` ? >> Проверка равенства двух значений; тест упадёт если значения не равны
11. Как называется тестирование сохранения работоспособности после правок? >> Регрессионное тестирование
12. Что такое `unittest` ? >> Стандартный фреймворк Python для написания и запуска тестов; входит в стандартную библиотеку
13. Как проверить наличие элемента в контейнере? >> `assertIn(elem, container)`
14. Назначение `assertIsNone` ? >> Проверка что объект равен `None`
15. Когда предпочитают `unittest` вместо сторонних решений? >> Когда нельзя устанавливать внешние библиотеки
16. В чём ключевые преимущества `pytest` перед `unittest` ? >> Не требует классов; использует обычный `assert` ; мощные фикстуры; богатая экосистема плагинов; более читаемые сообщения об ошибках
17. Назначение `assertTrue` ? >> Проверка, что выражение истинно
18. Назначение `assertNotEqual` ? >> Проверка что два значения не равны
