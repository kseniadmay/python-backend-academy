1. Назовите 5 стандартных уровней логирования в модуле logging по возрастанию их критичности (и их числовые значения). >> DEBUG (10), INFO (20), WARNING (30), ERROR (40), CRITICAL (50).
2. Какой уровень логирования установлен в корневом логгере (root) по умолчанию без вызова basicConfig()? >> WARNING (30) — поэтому сообщения уровней DEBUG и INFO по умолчанию в консоль не выводятся.
3. Почему в каждом модуле принято создавать логгер через logging.getLogger(__name__), а не использовать корневой logging.info()? >> Это автоматически выстраивает иерархию логгеров по именам пакетов и модулей (через точку), позволяя видеть источник каждого сообщения и гибко настраивать уровни для отдельных подсистем.
4. За что отвечают 4 основных компонента модуля logging: Logger, Handler, Formatter и Filter? >> Logger принимает записи из кода по уровню; Handler отправляет их в место назначения (консоль, файл, сеть); Formatter задаёт шаблон текста/JSON; Filter отсеивает или обогащает записи по кастомному условию.
5. Чем вызов logger.exception('Ошибка') внутри блока except отличается от обычного logger.error(f'Ошибка: {e}')? >> logger.exception() записывает сообщение на уровне ERROR и автоматически прикрепляет полный стектрейс (traceback) перехваченного исключения (эквивалент logger.error(..., exc_info=True)).
6. Почему сообщения в логах иногда начинают дублироваться (выводиться в консоль по два раза)? >> Потому что у дочернего логгера добавлен собственный StreamHandler, и при включённом по умолчанию флаге propagate=True он дополнительно передаёт запись родительскому (root) логгеру, у которого тоже есть свой хендлер.
7. Как отключить передачу логов от дочернего логгера вверх к родительским логгерам? >> Установить атрибут logger.propagate = False.
8. Что произойдёт с сообщением уровня DEBUG, если на самом Logger установлен уровень INFO, а на привязанном к нему Handler — уровень DEBUG? >> Сообщение будет отброшено ещё на входе в Logger и до Handler даже не дойдёт (запись должна пройти порог уровня и на логгере, и на хендлере).
9. Почему в вызовах логгера часто рекомендуют ленивую подстановку logger.debug('User: %s', user) вместо f-строки? >> При использовании шаблона '%s' форматирование строки и вызов __str__() выполняются только тогда, когда уровень DEBUG реально активен, экономя ресурсы в продакшене.
10. Чем отличаются обработчики RotatingFileHandler и TimedRotatingFileHandler? >> RotatingFileHandler ротирует (пересоздаёт) файлы логов при достижении лимита размера в байтах (maxBytes), а TimedRotatingFileHandler — по расписанию времени (каждый час, полночь, день недели).
11. В какой момент срабатывает logging.basicConfig(), если вызвать его повторно после того, как у root-логгера уже появились хендлеры? >> По умолчанию повторный вызов basicConfig() ничего не делает (игнорируется), если не передать явно параметр force=True (Python 3.8+).
12. Какой стандартный способ конфигурации сложной системы логирования со множеством логгеров, хендлеров и форматтеров используется в Django и FastAPI? >> Декларативная настройка через словарь с помощью функции logging.config.dictConfig(config_dict).
13. Как добавить стек вызовов (traceback) к логу уровня WARNING, не используя метод logger.exception()? >> Передать именованный аргумент exc_info=True: logger.warning('Сбой сети', exc_info=True).
14. Зачем в микросервисной архитектуре и Docker-контейнерах логи форматируют в однострочный JSON вместо обычного текста? >> Чтобы системы сбора логов (ELK, Grafana Loki, Datadog) могли автоматически парсить и индексировать поля (level, service, trace_id, user_id) без сложных регулярных выражений и не разбивали многострочные traceback на десятки отдельных записей.
15. Какой встроенный хендлер ставят в библиотечном коде по умолчанию, чтобы библиотека не спамила в stderr, если приложение не настроило логирование? >> logging.NullHandler() — хендлер-заглушка, который ничего никуда не выводит.
16. Как временно приглушить слишком шумные INFO-логи сторонней библиотеки (например, httpx или urllib3) в своём приложении? >> Получить её логгер по имени и поднять ему порог уровня: logging.getLogger('httpx').setLevel(logging.WARNING).
