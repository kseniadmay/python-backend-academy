1. Что такое дескриптор? >> Объект-атрибут класса, реализующий хотя бы один из методов __get__, __set__, __delete__, перехватывающий доступ к себе.
2. Чем data descriptor отличается от non-data descriptor? >> Data descriptor реализует и __get__, и __set__ — имеет приоритет выше instance.__dict__; non-data — только __get__, приоритет ниже.
3. Что вызывается автоматически при создании класса и сообщает дескриптору его имя? >> __set_name__(self, owner, name).
4. Зачем в __get__ нужна проверка `if instance is None`? >> Дескриптор вызывается и при обращении через класс (Class.attr) — тогда instance будет None, нужно вернуть сам дескриптор.
5. Чем является @property технически? >> Встроенным дата-дескриптором, реализующим __get__/__set__ на основе переданных функций.
6. Где на практике используются дескрипторы? >> property, classmethod, staticmethod, поля моделей Django ORM/SQLAlchemy, functools.cached_property.
7. Что произойдёт, если хранить значение прямо в self.value внутри самого дескриптора (не в instance)? >> Все экземпляры класса будут делить одно и то же значение — дескриптор является атрибутом класса, а не экземпляра.
8. Какая функция __set_name__ решает историческую проблему явной передачи имени в дескриптор? >> До появления __set_name__ (Python 3.6) имя приходилось передавать вручную: field = Descriptor('field_name').
9. Что произойдёт при обращении к дескриптору через класс, а не через экземпляр — Class.attr? >> instance в __get__ будет None; типичная реализация возвращает в этом случае сам дескриптор.
10. Может ли non-data descriptor быть переопределён значением в instance.__dict__? >> Да — если атрибут уже есть в __dict__ экземпляра, non-data descriptor при чтении больше не вызывается.
11. На чём именно построен functools.cached_property? >> На non-data дескрипторе — вычисленное значение кладётся прямо в __dict__ экземпляра, и повторные обращения идут в обход __get__.
12. Может ли один и тот же класс дескриптора использоваться для нескольких разных атрибутов одного класса? >> Да, это одно из главных преимуществ — например, Typed(int) можно применить и к age, и к quantity без дублирования логики.
13. Что произойдёт, если дескриптор не реализует __set__, а только __get__, и попытаться присвоить значение атрибуту? >> Присваивание пройдёт как обычно — значение попадёт прямо в __dict__ экземпляра, дескриптор больше не будет использоваться при последующем чтении (не data descriptor).
14. Как дескриптор узнаёт, к какому классу он был подключён? >> Через параметр owner в методах __get__/__set_name__.
15. Могут ли дескрипторы использоваться вне классов, на обычных переменных модуля? >> Нет, протокол дескрипторов работает только для атрибутов класса, не для обычных переменных.
