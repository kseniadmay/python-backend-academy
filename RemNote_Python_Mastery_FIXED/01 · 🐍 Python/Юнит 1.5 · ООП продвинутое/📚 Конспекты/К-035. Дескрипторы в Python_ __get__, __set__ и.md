## Что такое дескриптор

Дескриптор – это обычный объект, который управляет доступом к атрибуту другого класса, реализуя хотя бы один из методов протокола: `__get__`, `__set__` или `__delete__`. Как только такой объект становится атрибутом класса (не экземпляра!), Python начинает вызывать эти методы вместо обычного поиска в `__dict__`.

Это не экзотика ради экзотики – именно на дескрипторах построены `@property`, `@classmethod`, `@staticmethod`, а также поля моделей в Django ORM и SQLAlchemy. Когда вы пишете `user.name = "Alex"` в Django-модели, срабатывает не просто присваивание – срабатывает `__set__` дескриптора поля.

## Data-дескрипторы vs non-data-дескрипторы

**Non-data descriptor** – реализует только `__get__`. Пример: обычная функция-метод класса – она дескриптор, поэтому `instance.method` превращается в bound method.

**Data descriptor** – реализует `__get__` и `__set__` (и опционально `__delete__`). Это меняет приоритет поиска атрибута.

Порядок поиска атрибута в Python (MRO поиска, не путать с MRO классов):

- 1. Data-дескриптор в классе – **всегда побеждает**, даже если в `instance.__dict__` есть значение с тем же именем.
- 2. Значение из `instance.__dict__`.
- 3. Non-data-дескриптор или обычный атрибут класса.

Отсюда важное следствие для собеседования: `@property` – это data-дескриптор, поэтому `self.x = 5` никогда не «перезапишет» property напрямую в `__dict__`, минуя геттер/сеттер – вызовется `__set__`.

## Минимальный дескриптор своими руками

```python
class PositiveNumber:
    def __get__(self, obj, owner):
        if obj is None:
            return self
        return obj.__dict__.get(self.name, 0)

    def __set__(self, obj, value):
        if value < 0:
            raise ValueError('Значение не может быть отрицательным')
        obj.__dict__[self.name] = value

    def __set_name__(self, owner, name):
        self.name = name

class Product:
    price = PositiveNumber()

p = Product()
p.price = 10  # -> PositiveNumber.__set__(p, 10)
print(p.price)  # -> PositiveNumber.__get__(p, Product)
p.price = -5  # ValueError
```

`__set_name__` появился в Python 3.6 и решает старую боль: раньше имя атрибута приходилось передавать в дескриптор вручную (`price = PositiveNumber('price')`), что легко забыть и рассинхронизировать.

## Где хранить значение – частый вопрос на собеседовании

Хранить значение в **самом дескрипторе** (`self.value = value`) – плохая идея, если дескриптор один на класс: все экземпляры класса будут делить одно и то же значение, потому что дескриптор – атрибут класса, а не экземпляра.

Правильно – хранить в `obj.__dict__[self.name]`, как в примере выше, либо в отдельном `WeakKeyDictionary`, если экземпляры класса должны оставаться легко собираемыми сборщиком мусора.

## property как частный случай дескриптора

`@property` – это готовый data-дескриптор из стандартной библиотеки. Синтаксис `@property` / `@x.setter` – просто удобный способ создать экземпляр класса `property`, который сам реализует `__get__`/`__set__`, вызывая переданные вами функции.

```python
class Circle:
    def __init__(self, radius):
        self._radius = radius

    @property
    def radius(self):
        return self._radius

    @radius.setter
    def radius(self, value):
        if value <= 0:
            raise ValueError('Радиус должен быть положительным')
        self._radius = value

    @property
    def area(self):
        return 3.14159 * self._radius ** 2
```

Если нужен именно дескриптор, а не `property` – обычно потому, что логика переиспользуется на нескольких полях/классах (как в примере с `PositiveNumber` выше – один класс дескриптора можно повесить на любое количество полей).
