## Всё является объектом – включая классы

В Python не только данные являются объектами, но и сами классы. Число `5`, строка `'hello'`, список – всё это объекты. Но и `int`, и `str`, и любой ваш класс – тоже объекты. Это можно проверить:

```python
print(type(5))  # <class 'int'>
print(type(int))  # <class 'type'>
print(type(str))  # <class 'type'>

class MyClass: pass
print(type(MyClass))  # <class 'type'>
```

Если класс является объектом, значит что-то должно его создавать. Это **`type`** – базовый метакласс, встроенный в Python. Именно он является классом для всех классов.

---

## Что такое метакласс

**Метакласс** – это класс, экземплярами которого являются другие классы. Обычный класс описывает, как создаются и ведут себя объекты. Метакласс описывает, как создаются и ведут себя классы.

По умолчанию все классы в Python создаются через `type`. Вы можете переопределить этот процесс, написав собственный метакласс.

---

## Как создать собственный метакласс

Метаклассы – одна из самых абстрактных тем в Python, потому что здесь класс сам становится объектом, который кто-то создаёт. Ключевая идея: обычный класс создаёт объекты, метакласс создаёт сами классы.

Например `class User: pass`, новичку кажется, что `User` просто появился. Но в реальности Python тоже создаёт этот класс как объект. По умолчанию этим занимается встроенный метакласс `type`. То есть под капотом Python делает примерно что-то такое `User = type('User', (), {})`. Здесь `'User'` – имя класса, `()` – родительские классы, `{}` – словарь методов и атрибутов.

```python
class Meta(type): 
    def __new__(mcs, name, bases, namespace): 
        print(f'Creating class {name}') 
        return super().__new__(mcs, name, bases, namespace) 

class MyClass(metaclass=Meta): 
    pass 
```

Здесь мы создаём собственный метакласс `Meta`, наследуясь от `type`. То есть `Meta` – это "кастомизированный завод по созданию классов".

Теперь `class MyClass(metaclass=Meta): pass` означает "Создай класс `MyClass` не через обычный `type`, а через мой метакласс `Meta`".

Важный момент: метакласс срабатывает **в момент определения класса** – когда интерпретатор читает строку `class MyClass(metaclass=Meta)`. Не при создании экземпляра, а раньше. Именно поэтому сообщение появляется до любого `MyClass()`.

Теперь про аргументы `def __new__(mcs, name, bases, namespace):`

`mcs` – сам метакласс (`Meta`);

`name` – имя создаваемого класса (`'MyClass'`);

`bases` – родительские классы;

`namespace` – словарь всего содержимого класса.

Например:

```python
class MyClass:
    x = 10

    def hello(self):
        pass
```

даст примерно такой `namespace`:

```text
{
    'x': 10,
    'hello': <function ...>
}
```

Метакласс может изменить этот словарь до создания класса. Например, автоматически добавить атрибут:

```python
class Meta(type):
    def __new__(mcs, name, bases, namespace):
        namespace['version'] = 1
        return super().__new__(mcs, name, bases, namespace)
```

Теперь:

```python
class MyClass(metaclass=Meta):
    pass

print(MyClass.version)  # 1
```

Хотя `version` внутри класса вообще не писали.

Именно поэтому метаклассы используют в ORM, Django, Pydantic, dataclass, Enum – когда нужно автоматически модифицировать классы во время их создания.

---

## Где метаклассы используются на практике

Самый известный пример – **Django ORM**. Когда вы пишете:

```python
class User(models.Model):
    name = models.CharField(max_length=100)
```

Метакласс перехватывает создание этого класса, анализирует атрибуты и связывает их с колонками таблицы в базе данных. Вы пишете обычный Python-класс, а метакласс за кулисами превращает его в полноценную ORM-модель.

Другие сценарии: автоматическая регистрация подклассов для паттернов «Плагин» или «Фабрика», валидация структуры класса – принудительная проверка, что все подклассы реализуют обязательные методы.

## Когда метаклассы не нужны

Метаклассы усложняют код и отладку. В большинстве случаев задачу можно решить проще.

**Декораторы классов** подходят, если нужно модифицировать уже готовый класс – добавить методы, проверить структуру, зарегистрировать в реестре. **`__init_subclass__`** – современный способ управлять подклассами без написания метакласса: он вызывается автоматически при создании любого подкласса и значительно проще в реализации и понимании.

```python
class Base:
    def __init_subclass__(cls, **kwargs):
        super().__init_subclass__(**kwargs)
        print(f'Registered subclass: {cls.__name__}')

class Child(Base):  # Автоматически: Registered subclass: Child
    pass
```

Метакласс оправдан только тогда, когда нужен контроль именно над процессом **создания** класса и ни один из более простых инструментов не справляется с задачей.
