## Итерируемый объект (Iterable) vs итератор (Iterator)

Это разные, хотя и связанные понятия, и их часто путают. **Iterable** – любой объект, который умеет отдать итератор через встроенную функцию `iter()`, то есть реализует `__iter__`. Список, строка, словарь, множество – всё это iterable, но не итераторы сами по себе. **Iterator** – объект, который умеет отдавать элементы по одному через `next()`, реализуя протокол `__iter__` и `__next__`, и который помнит своё текущее положение между вызовами.

```python
lst = [1, 2, 3]
it = iter(lst)  # получили итератор из iterable

print(next(it))  # 1
print(next(it))  # 2
print(next(it))  # 3
print(next(it))  # StopIteration
```

Список сам по себе не хранит позицию – сколько раз ни вызови `iter(lst)`, каждый раз получится новый независимый итератор с начала. А вот у самого итератора `it` состояние есть: он «помнит», сколько элементов уже отдал.

## Протокол итератора вручную

```python
class CountUp:
    def __init__(self, limit):
        self.limit = limit
        self.current = 0

    def __iter__(self):
        return self

    def __next__(self):
        if self.current >= self.limit:
            raise StopIteration
        self.current += 1
        return self.current

for num in CountUp(3):
    print(num)  # 1, 2, 3
```

`for` не знает ничего о внутреннем устройстве объекта – он просто вызывает `iter()`, затем `next()` в цикле, пока не поймает `StopIteration`. Ручная реализация протокола требует явного хранения состояния (`self.current`) и явного `raise StopIteration` – это и есть основная причина, по которой генераторы удобнее.

## Генератор – итератор, который пишется как функция

**Генератор** – это частный случай итератора: он автоматически реализует `__iter__`/`__next__` и сам управляет состоянием, без ручных атрибутов и без ручного `raise StopIteration`.

```python
def count_up(limit):
    current = 0
    while current < limit:
        current += 1
        yield current

gen = count_up(3)
print(next(gen))  # 1
print(next(gen))  # 2
for num in gen:  # продолжает с того места, где остановились
    print(num)  # 3
```

Эквивалентный класс `CountUp` выше занял 12 строк ручной работы с состоянием, генератор – 5. Каждый вызов `next()` (или каждая итерация `for`) продолжает выполнение функции с той точки, где она была приостановлена на `yield`, а не начинает заново.

## Ключевое различие: память и время вычисления

Список хранит все элементы в памяти сразу – построение `[x**2 for x in range(10_000_000)]` требует памяти под все десять миллионов чисел одновременно. Генератор `(x**2 for x in range(10_000_000))` хранит только текущую позицию и вычисляет следующее значение **лениво**, по требованию – в памяти в любой момент времени находится только один элемент.

Это ключевой trade-off: списки можно индексировать (`lst[5]`), проходить несколько раз, знать их длину через `len()`. Генератор можно пройти **только один раз** – после исчерпания он не перезапускается, и `next()` снова и снова будет бросать `StopIteration`.

---

## Итог: три уровня абстракции

**Iterable** – умеет отдать итератор (`list`, `str`, `dict`, `set`, генераторная функция и результат её вызова). **Iterator** – умеет отдавать элементы по одному и помнить позицию (`__iter__` + `__next__`). **Generator** – способ создать итератор коротким синтаксисом (`yield` в функции или генераторное выражение), не реализуя протокол вручную. Каждый генератор – итератор, но не каждый итератор – генератор.
