## Что это и когда появилось

**`match-case`** (PEP 634) – конструкция структурного сопоставления с образцом, добавленная в Python 3.10. Это не просто "switch из других языков" – `match-case` умеет не только сравнивать значение, но и **разбирать структуру** объекта (распаковывать кортежи, словари, атрибуты класса) прямо в условии.

---

## Базовое сравнение по значению

```python
def http_status(code):
    match code:
        case 200:
            return 'OK'
        case 404:
            return 'Not Found'
        case 500 | 502 | 503:  # '|' – несколько значений в одном case
            return 'Server Error'
        case _:  # '_' – случай по умолчанию, как else
            return 'Unknown'

print(http_status(404))  # 'Not Found'
print(http_status(503))  # 'Server Error'
```

## Структурное сопоставление – главное отличие от switch

```python
def describe_point(point):
    match point:
        case (0, 0):
            return 'начало координат'
        case (0, y):
            return f'на оси Y, y={y}'
        case (x, 0):
            return f'на оси X, x={x}'
        case (x, y):
            return f'точка ({x}, {y})'
        case _:
            return 'не точка'

print(describe_point((0, 5)))  # 'на оси Y, y=5'
print(describe_point((3, 4)))  # 'точка (3, 4)'
```

`case (0, y):` не просто сравнивает – он одновременно **проверяет форму** (кортеж из двух элементов, первый из которых 0) и **извлекает** второй элемент в переменную `y`, доступную внутри блока case. Обычный `switch` в других языках так не умеет – это сравнение и распаковка одновременно.

## Сопоставление по структуре словаря

```python
def handle_event(event):
    match event:
        case {'type': 'click', 'x': x, 'y': y}:
            return f'клик по ({x}, {y})'
        case {'type': 'keypress', 'key': key}:
            return f'нажата клавиша {key}'
        case {'type': str(event_type)}:
            return f'неизвестное событие типа {event_type}'

print(handle_event({'type': 'click', 'x': 10, 'y': 20}))  # 'клик по (10, 20)'
```

Словарный паттерн проверяет **наличие** нужных ключей (лишние ключи в реальном словаре не мешают совпадению) и одновременно извлекает их значения – удобно для обработки JSON-подобных структур: событий, сообщений из очереди, ответов API.

## Сопоставление по классу и атрибутам

```python
class Circle:
    def __init__(self, radius):
        self.radius = radius

class Rectangle:
    def __init__(self, width, height):
        self.width = width
        self.height = height

def area(shape):
    match shape:
        case Circle(radius=r):
            return 3.14159 * r ** 2
        case Rectangle(width=w, height=h):
            return w * h
        case _:
            raise TypeError('Неизвестная фигура')

print(area(Circle(5)))  # 78.53975
print(area(Rectangle(3, 4)))  # 12
```

`case Circle(radius=r):` проверяет одновременно и **тип** (это должен быть именно `Circle`), и **извлекает** атрибут `radius` в переменную `r` – замена длинной цепочки `isinstance()` + ручного обращения к атрибутам.

## Guard-условие – дополнительная проверка через if

```python
def classify(n):
    match n:
        case int(x) if x < 0:
            return 'отрицательное число'
        case int(x) if x == 0:
            return 'ноль'
        case int(x):
            return 'положительное число'
        case _:
            return 'не число'

print(classify(-5))  # 'отрицательное число'
```

`if` после паттерна – дополнительное условие, которое проверяется только если структурное совпадение уже произошло; если guard возвращает `False`, поиск продолжается со следующего `case`.

---

## Когда использовать

`match-case` уместен, когда логика ветвления завязана не просто на равенство значения, а на **структуру** данных – разбор ответов внешних API, обработка разнотипных событий/сообщений, парсинг команд, где нужно и проверить форму, и сразу распаковать нужные части. Для простого сравнения одного значения с несколькими вариантами `if/elif` работает так же хорошо и не требует Python 3.10+ – выбор в пользу `match-case` оправдан именно структурными паттернами, а не как повсеместная замена `if/elif`.
