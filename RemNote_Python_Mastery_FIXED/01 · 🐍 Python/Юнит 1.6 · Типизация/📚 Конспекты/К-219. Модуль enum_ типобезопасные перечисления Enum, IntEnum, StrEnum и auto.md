## Зачем нужны перечисления (Enum) вместо «магических» строк и чисел

В сыром коде статусы заказов, роли пользователей или типы платежей часто передают просто строками (`"pending"`, `"paid"`) или числами (`1`, `2`). Это приводит к опечаткам (`"pendig"`), которые не ловятся до рантайма, и размывает область допустимых значений.

Модуль **`enum`** создаёт закрытое, типобезопасное множество именованных констант, которое понимают IDE и статические анализаторы (`mypy`, `pyright`), а также валидаторы в `Pydantic`, `FastAPI` и `SQLAlchemy`.

```python
from enum import Enum

class OrderStatus(Enum):
    NEW = "new"
    PAID = "paid"
    SHIPPED = "shipped"

status = OrderStatus.PAID
print(status.name)   # 'PAID' — имя члена перечисления
print(status.value)  # 'paid' — хранимое значение
```

## Идентичность (синглтоны), сравнение и обратный поиск

Каждый член `Enum` является **синглтоном** — поэтому члены одного перечисления принято сравнивать как через `==`, так и через `is` (`status is OrderStatus.PAID`).

Важное свойство базового **`Enum`**: его элементы **не равны** своим сырым значениям! `OrderStatus.PAID == "paid"` вернёт **`False`**. Это защищает от случайного смешивания разных сущностей.

Получить элемент перечисления динамически (например, при чтении из БД или HTTP-запроса) можно двумя способами:

```python
# 1. По ЗНАЧЕНИЮ (value) — круглые скобки вызова класса:
s1 = OrderStatus("paid")       # OrderStatus.PAID (или ValueError, если значения нет)

# 2. По ИМЕНИ (name) — квадратные скобки (как ключ словаря):
s2 = OrderStatus["PAID"]       # OrderStatus.PAID (или KeyError, если имени нет)
```

## IntEnum и StrEnum — когда нужна совместимость с int и str

Базовый `Enum` не сериализуется в `json.dumps()` из коробки и не сравнивается со строками или числами напрямую. Когда перечисление должно вести себя одновременно и как `Enum`, и как строка или число (например, для JSON API, HTTP-кодов, запросов в БД), используют **`StrEnum`** (появился в Python 3.11; ранее писали `class MyEnum(str, Enum)`) и **`IntEnum`**:

```python
import json
from enum import StrEnum, IntEnum

class Role(StrEnum):
    ADMIN = "admin"
    USER = "user"

class HttpCode(IntEnum):
    OK = 200
    NOT_FOUND = 404

print(Role.ADMIN == "admin")          # True! Наследует поведение str
print(json.dumps({"role": Role.ADMIN, "code": HttpCode.OK}))
# '{"role": "admin", "code": 200}' — сериализуется в JSON без кастомного encoder!
```

## auto() и декоратор @unique

Функция **`auto()`** автоматически генерирует значения для членов перечисления: в обычном `Enum` и `IntEnum` это последовательные целые числа начиная с `1` (`1, 2, 3...`), а в **`StrEnum`** — имя самого атрибута в **нижнем регистре** (`ADMIN = auto()` получит значение `'admin'`).

По умолчанию, если два поля `Enum` имеют одинаковое значение, второе поле становится **алиасом (псевдонимом)** первого, а не отдельным элементом при итерации. Чтобы запретить дублирующиеся значения и превратить их в `ValueError` при импорте модуля, используют декоратор **`@unique`**:

```python
from enum import StrEnum, auto, unique

@unique
class Environment(StrEnum):
    DEV = auto()      # 'dev'
    STAGING = auto()  # 'staging'
    PROD = auto()     # 'prod'
    # PRODUCTION = "prod"  # с @unique вызовет ValueError: duplicate values found!
```

## Flag и IntFlag — битовые маски прав доступа

Когда нужно комбинировать несколько флагов одновременно через побитовые операторы `|` (ИЛИ), `&` (И), `~` (НЕ), используют **`Flag`** (или `IntFlag`). `auto()` внутри `Flag` автоматически назначает степени двойки (`1, 2, 4, 8...`):

```python
from enum import Flag, auto

class Permission(Flag):
    READ = auto()     # 1
    WRITE = auto()    # 2
    EXECUTE = auto()  # 4
    ADMIN = READ | WRITE | EXECUTE

user_perm = Permission.READ | Permission.WRITE
print(Permission.WRITE in user_perm)    # True — проверка вхождения флага!
print(Permission.EXECUTE in user_perm)  # False
```

## Методы в Enum и исчерпывающая проверка в match-case

Так как `Enum` — это полноценный класс, в него можно добавлять собственные методы и `@property` (например, метод `can_transition_to(self, next_status)` для конечного автомата статусов заказа). При этом создать новый экземпляр перечисления в рантайме нельзя — набор членов фиксируется при объявлении класса.

В связке с `match-case` и `typing.assert_never` перечисления позволяют статическому анализатору (`mypy`) проверять, что вы обработали **абсолютно все** возможные варианты `Enum` и не забыли ни один статус при расширении системы.
