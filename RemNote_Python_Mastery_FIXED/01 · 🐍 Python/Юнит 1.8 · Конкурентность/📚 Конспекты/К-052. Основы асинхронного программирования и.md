## `async def`: функция, которая возвращает объект

Обычная функция при вызове немедленно начинает выполнение и возвращает результат. Функция с `async def` ведёт себя иначе: при вызове она **не выполняется**. Вместо этого создаётся объект-корутина – «замороженная» задача, содержащая инструкции, но не запущенная.

```python
async def greet():
    return 'hello'

result = greet()  # возвращает объект корутины, а не 'hello'
print(result)  # <coroutine object greet at 0x...>
```

Чтобы корутина реально выполнилась, её нужно передать в event loop – через `await` или `asyncio.run()`.

## `await`: точка добровольной передачи управления

**`await`**** **- это не просто «подожди». Это инструкция корутине: «в этом месте я завишу от внешней операции, и мне нет смысла удерживать управление». При встрече с `await` происходит три вещи: текущая корутина приостанавливается (состояние всех локальных переменных сохраняется), управление возвращается в event loop, и event loop может запустить другие задачи, пока ожидается результат.

```python
async def fetch():
    await asyncio.sleep(1)  # приостановиться, отдать управление
    return 'done'
```

`await` можно использовать только внутри `async def`. Попытка использовать его в обычной функции – `SyntaxError`.

## Event Loop: диспетчер корутин

**Event loop** (цикл событий) – центральный механизм `asyncio`. Он работает в одном потоке и управляет всеми корутинами: решает, какую запустить, какую приостановить, какую возобновить.

Алгоритм прост. Event loop выбирает готовую к выполнению корутину и запускает её. Когда корутина достигает `await`, она приостанавливается и помещается в список ожидающих. Event loop немедленно переключается на следующую готовую корутину. Когда ожидаемая операция завершается (пришёл ответ от сервера, истёк таймер), корутина возвращается в очередь и возобновляется ровно с той точки, где была приостановлена.

## Критическая ошибка: блокирующий вызов в async-коде

Если внутри async-функции вызвать обычную блокирующую операцию – `time.sleep()`, синхронный HTTP-запрос, тяжёлые вычисления без `await` – весь event loop заморозится до её завершения. Никакие другие корутины не выполнятся.

```python
async def bad():
    time.sleep(1)  # весь event loop стоит 1 секунду

async def good():
    await asyncio.sleep(1)  # event loop свободен, другие задачи работают
```

Это самая распространённая ошибка при переходе к `asyncio`. Правило: в async-коде используйте только async-совместимые библиотеки.

## `asyncio.gather`: параллельный запуск корутин

**`asyncio.gather`** принимает несколько корутин и запускает их конкурентно, возвращая результаты в исходном порядке.

```python
import asyncio

async def task(name, delay):
    await asyncio.sleep(delay)
    return name

async def main():
    results = await asyncio.gather(
        task('A', 2),
        task('B', 1),
        task('C', 3),
    )
    print(results)  # ['A', 'B', 'C']

asyncio.run(main())
```

Event loop запускает все три задачи, каждая уходит в `await asyncio.sleep`. Задача B завершается первой (через 1 сек), затем A (через 2 сек), затем C (через 3 сек). Общее время – время самой долгой задачи, а не сумма всех.

Результаты `gather` возвращаются в том же порядке, в котором переданы корутины – независимо от порядка завершения.

## `asyncio.run`: точка входа

**`asyncio.run(main())`** – стандартный способ запустить асинхронный код из синхронного контекста. Он создаёт новый event loop, запускает переданную корутину, ждёт её завершения и закрывает loop. Вызывать его следует один раз – это точка входа в асинхронную часть программы.

```python
if __name__ == '__main__':
    asyncio.run(main())
```

До Python 3.7 для этого нужно было вручную создавать event loop через `asyncio.get_event_loop().run_until_complete(main())`. Сейчас `asyncio.run` – стандарт.
