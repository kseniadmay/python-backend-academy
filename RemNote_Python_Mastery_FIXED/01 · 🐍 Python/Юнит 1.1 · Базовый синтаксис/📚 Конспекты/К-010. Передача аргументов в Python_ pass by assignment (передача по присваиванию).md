## Почему функция иногда меняет данные, а иногда нет

Это один из самых частых источников путаницы у начинающих. Список внутри функции изменился – а число нет, хотя код выглядит похоже. Чтобы понять почему, нужно разобраться, как Python вообще хранит данные.

---

## Переменные в Python – это ссылки, а не коробки

В Python переменная не хранит значение напрямую. Она хранит **ссылку** – указатель на объект в памяти. Когда вы пишете `a = 5`, переменная `a` не содержит пятёрку, она указывает на объект `5`, который живёт где-то в памяти.

При вызове функции происходит следующее: локальная переменная внутри функции получает ту же самую ссылку, что и переменная снаружи. Никакого копирования данных не происходит – функция просто получает доступ к тому же объекту.

Этот механизм называется **pass by assignment** (передача по присваиванию) или **pass by object reference**.

---

## Что происходит дальше – зависит от типа объекта

Все объекты в Python делятся на **изменяемые** (mutable) и **неизменяемые** (immutable). Это разделение и определяет поведение.

К неизменяемым относятся `int`, `float`, `str`, `tuple`. К изменяемым – `list`, `dict`, `set` и большинство пользовательских классов.

---

## Неизменяемые объекты: функция не трогает оригинал

```python
def change(x):
    x = 100  # перепривязка локальной переменной

a = 5
change(a)
print(a)  # 5 – оригинал не изменился
```

Разберём пошагово. `a` указывает на объект `5`. При вызове `change(a)` локальная переменная `x` получает ту же ссылку – тоже указывает на `5`. Затем внутри функции выполняется `x = 100`. Поскольку объект `5` изменить невозможно, Python не меняет его – он создаёт новый объект `100` и перепривязывает `x` к нему. Переменная `a` по-прежнему указывает на `5`. Связь разорвана только для `x`.

Это называется **rebinding** – перепривязка имени к другому объекту.

## Изменяемые объекты: функция работает с тем же объектом

```python
def append_item(lst):
    lst.append(99)

my_list = [1, 2, 3]
append_item(my_list)
print(my_list)  # [1, 2, 3, 99]
```

Здесь `lst` внутри функции указывает на тот же самый объект-список, что и `my_list` снаружи. Метод `.append(99)` модифицирует объект **на месте**, не создавая новый. Поэтому изменение видно снаружи – оба имени указывают на один и тот же список.

---

## Ключевое различие: мутация vs перепривязка

Важно понимать, что дело не в типе объекта как таковом, а в том, **что именно делает код внутри функции**.

Если внутри функции написать `lst = [99]` вместо `lst.append(99)` – произойдёт перепривязка: `lst` начнёт указывать на новый список, а оригинал `my_list` останется нетронутым. Это тот же механизм, что и с числами.

Изменения видны снаружи только тогда, когда вы **мутируете объект** – то есть изменяете его содержимое через методы или прямое присваивание по индексу (`lst[0] = 99`). Если вы **переприсваиваете** локальную переменную – оригинал не затрагивается никогда, независимо от типа объекта.

---

## Практические последствия

Передача изменяемых объектов в функцию – частый источник неожиданных побочных эффектов. Функция, которая молча меняет переданный список, усложняет отладку и делает код менее предсказуемым.

Если нужно защитить оригинал – передавайте копию: `append_item(my_list[:])` или `append_item(my_list.copy())`. Для глубоко вложенных структур используют `copy.deepcopy()`.

Понимание этого механизма особенно важно при работе со словарями как аргументами функций, при написании декораторов и при передаче данных между слоями приложения.
