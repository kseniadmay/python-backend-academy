## Почему выбор структуры данных важен

Программа идеально работает с десятью элементами – и зависает на десяти тысячах. Причина почти всегда не в железе, а в неправильном выборе структуры данных. Разные структуры дают разную сложность для одних и тех же операций – и это и есть главный рычаг управления скоростью.

---

## List: когда важен порядок

Список – динамический массив. Идеален, когда нужно сохранить порядок элементов и обращаться к ним по индексу.

- **Быстрые операции – $O(1)$:** `arr.append(x)`, `arr.pop()`, `arr[2]`, `len(arr)`. Они не требуют прохода по всему массиву.
- **Медленные операции – $O(n)$:** `arr.insert(0, x)`, `arr.pop(0)`, `arr.remove(x)`, `x in arr`. Все они требуют либо полного прохода, либо сдвига элементов.

Почему `insert(0, x)` медленный? Python не может просто «втиснуть» элемент в начало. Он физически сдвигает каждый существующий элемент на одну позицию вправо. Чем длиннее список – тем больше работы.

`[1, 2, 3, 4, 5] → insert(0, 0) → [0, 1, 2, 3, 4, 5]`

Сортировка `sorted(arr)` стоит особняком – это $O(n \log n)$.

## Dict: мгновенный поиск по ключу

Словарь – структура «ключ – значение» на основе хэш-таблицы. Хэш-функция мгновенно превращает ключ в адрес в памяти – поэтому доступ, добавление и проверка наличия выполняются за $O(1)$.

```python
d = {'key': 42}
d['key']       # O(1) – мгновенный доступ по ключу
d['new'] = 10  # O(1) – добавление новой пары
'key' in d     # O(1) – проверка наличия без перебора
print(d['key'], 'key' in d)
```

Это называется **амортизированным $O(1)$**: иногда Python нужно расширить таблицу в памяти или разрешить коллизию (когда два разных ключа претендуют на один адрес). В эти редкие моменты скорость падает, но в подавляющем большинстве случаев операция мгновенная.

---

## Set: уникальность и мгновенная проверка

Множество – это словарь без значений, только ключи. Главная суперсила – мгновенная проверка наличия и уникальность элементов.

```python
s = {1, 2}
x = 3
s.add(x)     # O(1) – мгновенное добавление
s.remove(x)  # O(1) – в разы быстрее, чем удаление из списка
x in s       # O(1) – проверка вхождения через хэш-таблицу
print(s, x in s)
```

Операции над двумя множествами – пересечение `&` (общие элементы), объединение `|` (все уникальные из обоих), разность `-` (есть в первом, но нет во втором) и симметрическая разность `^` – выполняются за $O(\min(n, m))$ или $O(n + m)$, что позволяет молниеносно сравнивать большие наборы данных.

---

## Сравнение операций

Проверка вхождения (`x in ...`): список – $O(n)$, словарь и множество – $O(1)$. Удаление элемента: список – $O(n)$, словарь и множество – $O(1)$. Доступ по индексу: только список – $O(1)$. Доступ по ключу: только словарь – $O(1)$. Длина структуры: все три – $O(1)$.

## Практический кейс: наивный поиск дубликатов O(n²)

Разбор пошагово — операция за операцией:
1. **Шаг 1 (Внешний указатель):** фиксируем индекс `i` от первого до предпоследнего элемента.
2. **Шаг 2 (Внутренний обход):** вторым указателем `j` обходим строго оставшиеся элементы справа (`i + 1` до конца).
3. **Шаг 3 (Сравнение пар):** проверяем равенство `arr[i] == arr[j]`. При первом же совпадении сразу выходим `return True`.
4. **Шаг 4 (Результат):** если все $n(n-1)/2$ пар проверены и дубликатов нет — возвращаем `False`.

```python
def has_duplicate(arr):
    # Шаг 1: перебираем опорный элемент
    for i in range(len(arr)):
        # Шаг 2: сравниваем его только со следующими элементами
        for j in range(i + 1, len(arr)):
            # Шаг 3: проверка пары за O(1)
            if arr[i] == arr[j]:
                return True
    # Шаг 4: обход завершён, совпадений нет
    return False

sample = [4, 8, 15, 16, 23, 42, 15]
print("has_duplicate:", has_duplicate(sample))
```

- **Сложность по времени — $O(n^2)$:** два вложенных цикла сравнивают каждый элемент с каждым последующим. На массиве из $10\,000$ элементов это до $\approx 50\,000\,000$ сравнений.
- **Сложность по памяти — $O(1)$:** алгоритм не требует дополнительной оперативной памяти под вспомогательные структуры.

## Быстрый поиск через set: O(n) и Time-Space Tradeoff

Разбор пошагово — операция за операцией:
1. **Шаг 1 (Буфер виденных):** инициализируем хеш-таблицу `seen = set()` для хранения уже встреченных значений.
2. **Шаг 2 (Один проход):** последовательно берём каждый элемент `x` из массива `arr` за один цикл $O(n)$.
3. **Шаг 3 (Проверка за O(1)):** операция `x in seen` вычисляет хеш ключа за $O(1)$. Если элемент уже в множестве — дубликат найден, сразу `return True`.
4. **Шаг 4 (Запоминание за O(1)):** если элемента ещё не было, добавляем его через `seen.add(x)` за $O(1)$.
5. **Шаг 5 (Итог):** если список обойдён без повторов — возвращаем `False`.

```python
def has_duplicate_fast(arr):
    seen = set()  # Шаг 1: инициализируем хеш-таблицу памяти
    for x in arr:
        # Шаг 2 & 3: мгновенная проверка O(1)
        if x in seen:
            return True
        # Шаг 4: сохраняем просмотренное значение за O(1)
        seen.add(x)
    # Шаг 5: завершение без дубликатов
    return False

sample = [4, 8, 15, 16, 23, 42, 15]
print("has_duplicate_fast:", has_duplicate_fast(sample))
```

- **Сложность по времени — $O(n)$:** список обходится ровно один раз. Поскольку проверка `x in seen` и добавление `seen.add(x)` в хэш-таблице работают за $O(1)$, для $10\,000$ элементов требуется всего $10\,000$ операций (в $5\,000$ раз быстрее!).
- **Сложность по памяти — $O(n)$:** создаётся вспомогательное множество `seen = set()`.
- **Компромисс времени и памяти (Time-Space Tradeoff):** мы осознанно расходуем память $O(n)$, чтобы радикально ускорить вычисления с квадратичных до линейных.

## Как выбирать

Нужен порядок и доступ по индексу – **list**. Нужно хранить пары «ключ – значение» для быстрого поиска – **dict**. Нужно мгновенно проверять наличие элемента и важна уникальность – **set**.
