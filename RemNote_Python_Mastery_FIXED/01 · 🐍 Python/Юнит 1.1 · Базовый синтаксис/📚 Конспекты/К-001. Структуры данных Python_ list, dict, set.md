## Почему выбор структуры данных важен

Программа идеально работает с десятью элементами – и зависает на десяти тысячах. Причина почти всегда не в железе, а в неправильном выборе структуры данных. Разные структуры дают разную сложность для одних и тех же операций – и это и есть главный рычаг управления скоростью для бэкенд-разработчика.

Главное инженерное правило: перед написанием логики всегда определи, какие операции будут выполняться чаще всего — поиск по значению, вставка в начало или конец, удаление или сортировка? Ответ на этот вопрос однозначно диктует выбор структуры.

---

## List: динамический массив и порядок элементов

Список (`list`) – динамический массив указателей. Идеален, когда нужно сохранить строгий порядок элементов и обращаться к ним по целочисленному индексу за $O(1)$.

- **Быстрые операции — $O(1)$:** `arr.append(x)` (вставка в конец), `arr.pop()` (удаление с конца), `arr[2]` (доступ по индексу), `len(arr)` (размер массива хранится как атрибут).
- **Медленные операции — $O(n)$:** `arr.insert(0, x)`, `arr.pop(0)`, `arr.remove(x)`, `x in arr`. Все они требуют либо полного прохода, либо физического сдвига элементов в оперативной памяти.

Почему `insert(0, x)` медленный? Python не может просто «втиснуть» элемент в начало. Он физически сдвигает каждый существующий элемент на одну позицию вправо в памяти:

```python
items = [1, 2, 3, 4, 5]
items.insert(0, 0)
# Результат: [0, 1, 2, 3, 4, 5] — все 5 элементов сдвинулись вправо!
```

Сортировка `sorted(arr)` стоит особняком – это адаптивный Timsort со сложностью $O(n \log n)$.

## Dict: мгновенный поиск по ключу

Словарь – структура «ключ – значение» на основе хэш-таблицы. Хэш-функция мгновенно превращает ключ в адрес в памяти – поэтому доступ, добавление и проверка наличия выполняются за $O(1)$.

```python
d = {'key': 42}

# O(1) — мгновенный доступ по ключу
value = d['key']

# O(1) — добавление новой пары
d['new'] = 10

# O(1) — проверка наличия без перебора
is_present = 'key' in d

print(value, is_present)
```

Это называется **амортизированным $O(1)$**: иногда Python нужно расширить таблицу в памяти или разрешить коллизию (когда два разных ключа претендуют на один адрес). В эти редкие моменты скорость падает, но в подавляющем большинстве случаев операция мгновенная.

## Set: уникальность и мгновенная проверка

Множество – это словарь без значений, только ключи. Главная суперсила – мгновенная проверка наличия и уникальность элементов.

```python
s = {1, 2}
x = 3

# O(1) — мгновенное добавление
s.add(x)

# O(1) — быстрое удаление
s.remove(x)

# O(1) — проверка вхождения через хэш-таблицу
is_member = x in s

print(s, is_member)
```

Операции над двумя множествами – пересечение `&` (общие элементы), объединение `|` (все уникальные из обоих), разность `-` (есть в первом, но нет во втором) и симметрическая разность `^` – выполняются за $O(\min(n, m))$ или $O(n + m)$, что позволяет молниеносно сравнивать большие наборы данных.

---

## Сравнение операций

Проверка вхождения (`x in ...`): список – $O(n)$, словарь и множество – $O(1)$. Удаление элемента: список – $O(n)$, словарь и множество – $O(1)$. Доступ по индексу: только список – $O(1)$. Доступ по ключу: только словарь – $O(1)$. Длина структуры: все три – $O(1)$.

## Практический кейс: наивный поиск дубликатов O(n²)

Построчный разбор работы алгоритма:

```python
def has_duplicate(arr):
    # Строка 1: фиксируем опорный элемент от первого до конца
    for i in range(len(arr)):
        # Строка 2: сравниваем его ТОЛЬКО со следующими справа (i + 1)
        for j in range(i + 1, len(arr)):
            # Строка 3: если пара элементов совпала — найден дубликат
            if arr[i] == arr[j]:
                return True
    # Строка 4: все пары проверены, дубликатов нет
    return False

sample = [4, 8, 15, 16, 23, 42, 15]
print("has_duplicate:", has_duplicate(sample))
```

- **Строка 2 (`for i in range(len(arr)):`):** Внешний указатель выбирает базовый элемент.
- **Строка 4 (`for j in range(i + 1, len(arr)):`):** Внутренний указатель обходит строго оставшиеся элементы справа (`i + 1`). Сравнивать элемент с самим собой или элементами слева не требуется.
- **Строка 6 (`if arr[i] == arr[j]:`):** Одиночная проверка равенства за $O(1)$. При первом совпадении немедленно выходим через `return True` (ранний выход).
- **Строка 8 (`return False`):** Срабатывает только после полного исчерпания всех возможных пар.

- **Сложность по времени — $O(n^2)$:** два вложенных цикла сравнивают каждый элемент с каждым последующим ($n(n-1)/2$ сравнений). На массиве из $10\,000$ элементов это до $\approx 50\,000\,000$ операций.
- **Сложность по памяти — $O(1)$:** не требует вспомогательной оперативной памяти.

## Быстрый поиск через set: O(n) и Time-Space Tradeoff

Построчный разбор работы быстрого алгоритма:

```python
def has_duplicate_fast(arr):
    # Строка 1: создаём хеш-таблицу для мгновенного поиска O(1)
    seen = set()

    # Строка 2: один линейный проход по массиву O(n)
    for x in arr:
        # Строка 3: проверка наличия в хеш-таблице за O(1)
        if x in seen:
            return True
        # Строка 4: сохраняем встреченное значение в память за O(1)
        seen.add(x)

    # Строка 5: весь список обойдён без повторов
    return False

sample = [4, 8, 15, 16, 23, 42, 15]
print("has_duplicate_fast:", has_duplicate_fast(sample))
```

- **Строка 2 (`seen = set()`):** Инициализируем пустое множество памяти.
- **Строка 4 (`for x in arr:`):** Единственный цикл обходит список за один проход ($O(n)$).
- **Строка 5 (`if x in seen:`):** Операция `in` вычисляет хеш ключа и находит его за $O(1)$. Если элемент уже был встречен — дубликат обнаружен мгновенно.
- **Строка 7 (`seen.add(x)`):** Если элемента в множестве нет, добавляем его в хеш-таблицу за $O(1)$.
- **Строка 9 (`return False`):** Список завершён, повторений не найдено.

- **Сложность по времени — $O(n)$:** список обходится ровно один раз. Для $10\,000$ элементов требуется всего $10\,000$ операций (в $5\,000$ раз быстрее наивного поиска!).
- **Сложность по памяти — $O(n)$:** вспомогательное множество `seen = set()` хранит уникальные элементы.
- **Компромисс времени и памяти (Time-Space Tradeoff):** мы осознанно расходуем память $O(n)$, чтобы радикально ускорить работу программы с квадратичной до линейной.

## Как выбирать

Нужен порядок и доступ по индексу – **list**. Нужно хранить пары «ключ – значение» для быстрого поиска – **dict**. Нужно мгновенно проверять наличие элемента и важна уникальность – **set**.
