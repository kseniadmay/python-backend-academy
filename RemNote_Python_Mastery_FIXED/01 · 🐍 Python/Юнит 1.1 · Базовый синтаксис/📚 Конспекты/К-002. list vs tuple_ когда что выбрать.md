## Главное отличие – изменяемость

**`list`** – изменяемая (mutable) последовательность: можно добавлять, удалять, менять элементы после создания. **`tuple`** – неизменяемая (immutable): после создания состав и порядок элементов зафиксированы навсегда.

```python
lst = [1, 2, 3]
lst.append(4)  # OK – список можно менять
lst[0] = 100
print(lst)  # [100, 2, 3, 4]

tup = (1, 2, 3)
tup[0] = 100  # TypeError: 'tuple' object does not support item assignment
```

---

## Следствие неизменяемости: tuple можно хэшировать

Поскольку `tuple` не может измениться после создания, у него есть стабильный хэш – а значит, кортеж можно использовать как **ключ словаря** или элемент `set`. Список – нельзя, именно потому что список изменяемый, а хэш ключа обязан оставаться постоянным на всё время его жизни в словаре.

```python
cache = {}
cache[(1, 2)] = 'результат для точки (1,2)'  # tuple как ключ – OK
print(cache[(1, 2)])  # 'результат для точки (1,2)'

cache[[1, 2]] = 'x'  # TypeError: unhashable type: 'list'
```

Это одна из самых частых практических причин выбрать `tuple` вместо `list` – например, координаты `(x, y)` как ключ словаря кэша.

## Семантика: гетерогенная структура vs однородная коллекция

Помимо технических различий, в инженерном сообществе принята чёткая семантическая договорённость:

- **`tuple` (разнородная запись):** используется для фиксированной по смыслу, разнородной (гетерогенной) структуры данных, где позиция определяет назначение поля:
  - `point = (x, y)` — геопозиция / координаты;
  - `record = (user_id, username, created_at)` — облегчённая строка базы данных (сродни `namedtuple`).

- **`list` (однородная коллекция):** используется для однородной (гомогенной) коллекции равноправных элементов, размер которой может динамически расти или сокращаться:
  - `active_users = ["alice", "bob", "carol"]` — список пользователей;
  - `pending_orders = [101, 102, 103]` — очередь заказов на обработку.

---

## Производительность

Создание `tuple` немного быстрее создания `list` с тем же содержимым, и `tuple` занимает чуть меньше памяти – оба следствия того, что интерпретатору не нужно резервировать место под потенциальный рост структуры. На практике разница ощутима только в узких, горячих участках кода с огромным числом создаваемых объектов – не повод выбирать `tuple` вместо `list` по умолчанию "ради скорости", если структура данных по смыслу изменяемая.

---

## Общее: и то, и другое – последовательности

И `list`, и `tuple` поддерживают индексацию, срезы, `len()`, перебор в `for`, вложенность. Разница исключительно в изменяемости и, как следствие, в хэшируемости – не в наборе операций чтения.

---

## Когда использовать

`tuple` – для неизменяемых по смыслу данных: координат, RGB-цвета, возвращаемых из функции нескольких значений (`return x, y`), ключей словаря, записей фиксированной структуры. `list` – когда коллекция по смыслу может расти, сжиматься или меняться со временем: результаты запроса, накопление элементов в цикле, любая изменяемая последовательность.
