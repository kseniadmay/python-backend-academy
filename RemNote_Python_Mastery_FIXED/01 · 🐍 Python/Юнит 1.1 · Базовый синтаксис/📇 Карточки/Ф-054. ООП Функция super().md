1. Какой аргумент передаётся в родительский конструктор через `super().__init__()` в примере с Dog(Animal): `class Animal:; def __init__(self, name: str):; self.name = name; class Dog(Animal):; def __init__(self, name: str, breed: str):; super().__init__(name); self.breed = breed` ? >> `name`
2. Как выглядит современный синтаксис `super()` в Python 3 при вызове родительского конструктора? >> `super().__init__(args)`
3. Почему синтаксис `super(Dog, self).__init__()` в Python 3 считается устаревшим и избыточным? >> Пишут `super(Dog, self).__init__()` вместо `super().__init__()` ; избыточно, но работает
4. Почему прямой вызов `Parent.__init__(self)` хуже использования `super().__init__()` при множественном наследовании? >> Жёстко привязан к конкретному классу; при множественном наследовании может пропустить классы в цепочке MRO
5. В чём разница в синтаксисе `super()` между Python 2 и Python 3? >> `super(Dog, self).__init__(args)` ; в Python 3 аргументы не нужны
6. Как `super()` ведёт себя при множественном ромбовидном наследовании `class D(B, C)` ? >> Следует MRO: `D → B → C → A → object` ; `super()` в `B` вызовет `C` , а не `A` напрямую
7. Нужно ли передавать `self` при `super().__init__()` ? >> Нет; Python передаёт `self` автоматически
8. Что произойдёт если не вызвать `super().__init__()` в дочернем классе? >> Атрибуты родительского класса не будут инициализированы; обращение к ним выбросит `AttributeError`
9. Почему `super()` предпочтительнее прямого `Animal.__init__(self, name)` ? >> `super()` следует MRO; при множественном наследовании гарантирует корректный проход по всей цепочке родителей
10. Каково назначение `super()` в `__init__` подкласса? >> Вызов метода родительского класса по цепочке MRO; чаще всего – инициализация атрибутов родителя
11. Применяется ли `super()` только в `__init__` ? >> Нет; можно использовать в любом методе: `super().speak()` , `super().save()` и др.
