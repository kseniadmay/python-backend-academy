1. Почему оператор `is` нельзя использовать для сравнения строк и чисел вместо `==` ? >> CPython кэширует малые целые числа (обычно от -5 до 256) и некоторые строки (интернирование); `is` может вернуть `True` для таких значений, но это деталь реализации, а не гарантия языка
2. При `a = [1, 2, 3]; b = [1, 2, 3]`: Какой результат вернёт `a is b` ? >> `False`
3. При `a = [1, 2, 3]; b = [1, 2, 3]`: Какой результат вернёт `a == b` ? >> `True`
4. Для каких значений использование `is` считается корректным? >> `None` , `True` , `False` – они существуют в памяти в единственном экземпляре
5. Какой оператор рекомендуется использовать для проверки того, что переменная равна `None` ? >> `is` ; корректная форма: `if x is None` ; использование `==` для сравнения с `None` – нарушение PEP 8
6. Какой оператор следует использовать для сравнения значений переменных? >> `==`
7. Что проверяет оператор `==` ? >> Равенство значений объектов
8. Почему `a is b` возвращает `False` , если оба списка содержат одинаковые значения? >> Потому что это два разных объекта в разных участках памяти; `is` сравнивает `id()` объектов, а не их содержимое
9. Что проверяет оператор `is` ? >> Идентичность объектов: ссылаются ли переменные на один и тот же объект в памяти
