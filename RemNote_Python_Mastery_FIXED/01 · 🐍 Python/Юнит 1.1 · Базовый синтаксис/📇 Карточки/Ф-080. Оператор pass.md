1. Каким комментарием в коде часто сопровождается оператор `pass` ? >> Комментарием о том, что блок будет реализован позже
2. Зачем нужен оператор `pass` с точки зрения синтаксиса? >> Python требует наличия хотя бы одной инструкции в теле блока; `pass` позволяет оставить блок пустым, не нарушая синтаксис
3. Влияет ли наличие `pass` на логику выполнения программы? >> Нет, он не изменяет состояние программы и не выполняет вычислений
4. В каких случаях использование `pass` становится синтаксически необходимым? >> Когда структура кода требует наличия тела блока, но логика в нём отсутствует
5. Что произойдёт при выполнении оператора `pass` интерпретатором? >> Ничего не произойдёт – интерпретатор просто перейдёт к следующей инструкции
6. Почему нельзя оставить тело функции или класса абсолютно пустым? >> Это нарушит правила синтаксиса, требующие наличия хотя бы одной инструкции в блоке
7. Какую роль играет `pass` при проектировании структуры программы? >> Временное заполнение блоков кода, которые будут реализованы позже
8. Как объявить функцию-заглушку с именем `todo` ? >> def todo(): pass
9. Что представляет собой оператор `pass` ? >> Оператор-заглушка, который не выполняет никаких действий (null-operation)
