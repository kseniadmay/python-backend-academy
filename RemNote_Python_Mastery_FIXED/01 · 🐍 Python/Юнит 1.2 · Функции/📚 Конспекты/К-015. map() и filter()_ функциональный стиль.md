## map() – применить функцию к каждому элементу

**`map(func, iterable)`** применяет `func` к каждому элементу `iterable` и возвращает **ленивый итератор** (не список!) с результатами.

```python
numbers = [1, 2, 3, 4, 5]

squared = map(lambda x: x ** 2, numbers)
print(squared)  # <map object at 0x...> – это итератор, не список
print(list(squared))  # [1, 4, 9, 16, 25] – материализуем явно через list()

a = [1, 2, 3]
b = [10, 20, 30]
sums = list(map(lambda x, y: x + y, a, b))
print(sums)  # [11, 22, 33]
```

## filter() – оставить только подходящие элементы

**`filter(func, iterable)`** оставляет только те элементы, для которых `func` вернула истинное значение – тоже возвращает ленивый итератор.

```python
numbers = [1, 2, 3, 4, 5, 6, 7, 8]

evens = filter(lambda x: x % 2 == 0, numbers)
print(list(evens))  # [2, 4, 6, 8]

values = [0, 1, '', 'text', None, [], [1, 2]]
truthy = filter(None, values)
print(list(truthy))  # [1, 'text', [1, 2]]
```

---

## map/filter vs list comprehension – идентичный результат, разный стиль

```python
numbers = [1, 2, 3, 4, 5]

result_functional = list(map(lambda x: x ** 2, filter(lambda x: x % 2 == 0, numbers)))

result_comprehension = [x ** 2 for x in numbers if x % 2 == 0]

print(result_functional)  # [4, 16]
print(result_comprehension)  # [4, 16]
```

Оба варианта дают одинаковый результат. В сообществе Python списковые включения обычно считаются более читаемыми, особенно когда `map`/`filter` комбинируются друг с другом (как в примере выше – вложенный вызов читается тяжелее, чем `[x**2 for x in numbers if x % 2 == 0]`). `map`/`filter` чаще оправданы, когда функция уже существует отдельно (не lambda), – тогда `map(str.upper, words)` компактнее, чем `[str.upper(w) for w in words]`.

## Ленивость – общее с генераторами

`map` и `filter` не вычисляют результат сразу – как и генераторы, они вычисляют следующий элемент только когда его запрашивают (`next()`, `for`, оборачивание в `list()`). Это значит, что `map`/`filter` можно применять к бесконечным или очень большим последовательностям, не тратя память на промежуточный список:

```python
import itertools

infinite = itertools.count(1)
first_five_squares = list(itertools.islice(map(lambda x: x ** 2, infinite), 5))
print(first_five_squares)  # [1, 4, 9, 16, 25]
```

---

## Когда использовать

`map`/`filter` уместны, когда применяется уже существующая именованная функция (`map(int, string_list)`, `map(str.strip, lines)`) – тогда они компактнее списковых включений. Для логики, которую проще выразить lambda-выражением с условием, особенно при комбинировании нескольких трансформаций подряд, списковые включения или генераторные выражения обычно читаются понятнее и считаются более идиоматичным Python.
