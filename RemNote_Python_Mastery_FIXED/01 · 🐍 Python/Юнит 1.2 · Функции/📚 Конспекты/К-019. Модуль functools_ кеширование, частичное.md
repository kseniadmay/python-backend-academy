## `@lru_cache` – кеширование результатов функции

Рекурсивное вычисление чисел Фибоначчи без оптимизации работает крайне медленно: `fibonacci(100)` порождает экспоненциальное количество повторных вызовов, пересчитывая одни и те же промежуточные значения снова и снова.

**`@lru_cache`** решает это добавлением кеша: при первом вызове с определёнными аргументами результат сохраняется, при повторном вызове с теми же аргументами возвращается из памяти без пересчёта.

```python
from functools import lru_cache

@lru_cache(maxsize=128)
def fibonacci(n):
    if n < 2:
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)
```

**LRU** расшифровывается как Least Recently Used – наименее востребованные за последнее время. Когда кеш заполняется до `maxsize`, алгоритм вытесняет записи, к которым дольше всего не обращались, освобождая место для новых. `maxsize=128` – значение по умолчанию, подобранное как баланс между скоростью и потреблением памяти. Если передать `maxsize=None` – кеш будет расти неограниченно.

Важное ограничение: `@lru_cache` работает только с **чистыми функциями**, аргументы которых хешируемы. Передать список как аргумент не получится – он не может быть ключом в словаре кеша. Если функция имеет побочные эффекты или зависит от внешнего состояния – кеширование даст непредсказуемые результаты.

В Python 3.9+ появился `@cache` из того же модуля – упрощённый вариант без `maxsize`, эквивалентный `@lru_cache(maxsize=None)`.

## `partial` – фиксация аргументов функции

Бывает ситуация: есть универсальная функция, но в большинстве случаев она вызывается с одними и теми же параметрами. Дублировать вызов с одинаковыми аргументами каждый раз – лишний шум в коде.

`partial` позволяет зафиксировать часть аргументов и получить новую функцию с меньшим числом параметров:

```python
from functools import partial

def power(base, exp):
    return base ** exp

square = partial(power, exp=2)
cube = partial(power, exp=3)

print(square(5))  # 25
print(cube(3))  # 27
```

`partial` возвращает новый объект-обёртку, который при вызове подставляет зафиксированные аргументы и передаёт остальные в оригинальную функцию. Это удобно при работе с колбэками, конфигурировании обработчиков событий и везде, где одна и та же функция должна использоваться в разных контекстах с разными предустановками.

## `@wraps` – сохранение метаданных при написании декораторов

Когда пишешь декоратор, оригинальная функция оборачивается внутренней функцией `wrapper`. Это приводит к побочному эффекту: атрибуты `__name__`, `__doc__` и другие метаданные оригинала перезаписываются данными `wrapper`. Для отладки, логирования и документации это проблема.

```python
from functools import wraps

def my_decorator(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        print('Логирование перед вызовом')
        return func(*args, **kwargs)

    return wrapper

@my_decorator
def greet():
    """Greets the user"""
    print('Hello!')

print(greet.__name__)  # greet, а не wrapper
print(greet.__doc__)  # Greets the user, а не None
```

`@wraps(func)` копирует все важные атрибуты из оригинальной функции в `wrapper`. Без него `greet.__name__` вернул бы `'wrapper'`, что ломает любое средство отладки или интроспекции, которое полагается на имя функции.

Это не опциональная деталь – `@wraps` нужно использовать в каждом декораторе. Его отсутствие считается ошибкой при код-ревью.

## Когда что применять

`@lru_cache` используют для дорогостоящих чистых функций с повторяющимися аргументами: рекурсивные вычисления, парсинг, обращения к конфигурации. `partial` – когда нужно создать специализированную версию универсальной функции или передать функцию как колбэк с предзаполненными аргументами. `@wraps` – обязательно при написании любого декоратора.
