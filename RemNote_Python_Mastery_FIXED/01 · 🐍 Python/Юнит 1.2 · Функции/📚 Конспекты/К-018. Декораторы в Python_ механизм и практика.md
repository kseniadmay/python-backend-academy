**Декоратор** – это функция, которая принимает другую функцию как аргумент, добавляет ей дополнительное поведение и возвращает новую функцию. Вызывающий код продолжает обращаться к той же функции по тому же имени – и не знает, что внутри она теперь обёрнута в дополнительную логику.

---

## Синтаксис `@` – это просто сокращение

```python
@decorator
def func():
    pass

def func():
    pass

func = decorator(func)
```

Символ `@` – инструкция интерпретатору: передай следующую функцию в декоратор и переприсвой имя результату. Никакой магии – просто более читаемая запись переприсваивания.

---

## Анатомия декоратора

```python
from functools import wraps
import time

def timer(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        end = time.time()
        print(f'{func.__name__} выполнялась {end - start:.4f} сек')
        return result

    return wrapper

@timer
def slow_function():
    time.sleep(1)
    return 'done'

slow_function()  # slow_function выполнялась 1.0012 сек
```

Разберём по частям. `timer` – внешняя функция, принимающая `func`. `wrapper` – внутренняя функция, которая и будет вызываться вместо оригинала. `*args, **kwargs` делают декоратор универсальным: `wrapper` принимает любые аргументы и прозрачно передаёт их в `func`. Без `return result` декоратор сломает любую функцию, которая что-то возвращает – она начнёт возвращать `None`.

`@wraps(func)` копирует метаданные оригинальной функции (`__name__`, `__doc__`) в `wrapper`. Без него `slow_function.__name__` вернёт `'wrapper'`, что ломает отладку и интроспекцию. Подробнее это разобрано в теме про `functools`.

## Декоратор с аргументами – три уровня вложенности

Если декоратору нужны настройки, добавляется ещё один уровень:

```python
from functools import wraps

def repeat(n):
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            for _ in range(n):
                result = func(*args, **kwargs)
            return result

        return wrapper

    return decorator

@repeat(3)
def greet():
    print('Hello!')

greet()  # выведет Hello! три раза
```

`repeat(3)` вызывается первым и возвращает `decorator`. Затем `decorator` получает `greet` и возвращает `wrapper`. При вызове `greet()` выполняется `wrapper`, который запускает оригинальную функцию `n` раз.

`@repeat(3)` – это не просто декоратор, это **вызов функции, возвращающей декоратор**. Именно поэтому здесь три уровня вложенности, а не два.

## Где декораторы используются в реальном коде

В backend-разработке декораторы встречаются повсеместно. **Логирование** – автоматически записывать, кто и с какими аргументами вызвал функцию. **Проверка прав доступа** – в Django и Flask декораторы вроде `@login_required` проверяют аутентификацию до выполнения view. **Кеширование** – `@lru_cache` из `functools`. **Retry-логика** – повторный запуск при сетевых ошибках. **Измерение производительности** – профилирование без изменения бизнес-логики.

Главный архитектурный смысл декораторов – **разделение ответственности**. Функция содержит только бизнес-логику, декоратор берёт на себя инфраструктурные задачи. Это соответствует принципу DRY: вместо дублирования логирования в десяти местах – один декоратор, применённый к десяти функциям.
