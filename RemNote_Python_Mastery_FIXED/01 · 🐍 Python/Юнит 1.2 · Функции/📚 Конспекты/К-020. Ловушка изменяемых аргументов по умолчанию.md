## Суть ловушки

Значение по умолчанию для аргумента функции вычисляется **один раз**, в момент определения функции – а не при каждом вызове. Если это значение – изменяемый объект (`list`, `dict`, `set`), все вызовы без явного аргумента будут делить **один и тот же** объект.

```python
def add_item(item, cart=[]):
    cart.append(item)
    return cart

cart1 = add_item('apple')
print(cart1)  # ['apple']

cart2 = add_item('banana')
print(cart2)  # ['apple', 'banana'] – а не ['banana']!
print(cart1 is cart2)  # True – это буквально один и тот же список
```

---

## Правильный способ

```python
def add_item(item, cart=None):
    if cart is None:
        cart = []  # новый список создаётся заново при КАЖДОМ вызове
    cart.append(item)
    return cart

cart1 = add_item('apple')
cart2 = add_item('banana')
print(cart1)  # ['apple']
print(cart2)  # ['banana']
```

`None` – неизменяемый синглтон, поэтому в качестве значения по умолчанию он безопасен: сравнение `is None` не создаёт разделяемого состояния, а реальный изменяемый объект создаётся заново внутри тела функции при каждом вызове.

---

## Почему так сделан Python – не баг, а следствие модели

Функция в Python – обычный объект, а `def` выполняется один раз при импорте/определении модуля. Значения по умолчанию – часть этого объекта функции, вычисляются в момент `def` и живут вместе с функцией, а не пересоздаются при каждом вызове. Это касается любых изменяемых объектов по умолчанию, не только `list` – тот же эффект с `dict`, `set`, экземплярами собственных классов.

---

## Когда использовать

Правило без исключений: если значение по умолчанию – изменяемый объект, используйте `None` и создавайте реальное значение внутри функции. Для неизменяемых значений по умолчанию (`0`, `""`, `None`, `tuple()`) эта проблема не возникает – их нельзя случайно мутировать, поэтому разделяемое состояние безопасно.
