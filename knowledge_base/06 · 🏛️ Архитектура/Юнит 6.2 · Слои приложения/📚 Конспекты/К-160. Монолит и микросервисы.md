## 1. Монолит, Модульный монолит и Микросервисы: эволюция архитектуры

> **Ментальная модель — «Квартира-студия, Дом с комнатами и Коттеджный посёлок»**:
> - **Спагетти-монолит** — огромная квартира-студия без перегородок: кухня, спальня и мастерская стоят вперемешку. Дешево построить в первый день, но невозможно жить втроём.
> - **Модульный монолит (Modular Monolith)** — просторный дом с чёткими комнатами и дверьми под одной крышей и с общими коммуникациями (один деплой, одна БД, но строгие границы модулей). Идеальный выбор для 90% проектов!
> - **Микросервисы (Microservices)** — коттеджный посёлок, где спальня, кухня и гараж стоят в отдельных зданиях со своими генераторами, охраной и курьерами между ними. Если сгорит гараж — спальня уцелеет, но чтобы просто принести бутерброд из кухни в спальню, нужно одеваться и идти по улице (сетевые вызовы, сериализация, таймауты).

```text
1. МОДУЛЬНЫЙ МОНОЛИТ (Один процесс, вызовы в памяти за ~100 нс, общая ACID-транзакция):
+-----------------------------------------------------------------------+
|  [ API Router ] ---> [ Модуль Users ] | [ Модуль Orders ] | [ Billing ]|
|                              \                 |               /      |
|                               v                v              v       |
|                         [( Единая СУБД PostgreSQL )]                  |
+-----------------------------------------------------------------------+

2. МИКРОСЕРВИСЫ (Разные процессы/серверы, общение по сети HTTP/gRPC/Kafka за ~5-50 мс):
+--------------+      +-------------------+      +-------------------+
| API Gateway  | ---> | Orders Service    | ===> | Брокер Kafka/RMQ  |
+--------------+      | (Своя БД Orders)  |      +-------------------+
       |              +-------------------+                |
       v                                                   v
+-------------------+                            +-------------------+
| Users Service     |                            | Billing Service   |
| (Своя БД Users)   |                            | (Своя БД Billing) |
+-------------------+                            +-------------------+
```

## 2. Сравнительная матрица: Монолит vs Модульный монолит vs Микросервисы

Любое архитектурное решение — это **инженерный компромисс (Trade-off)**: выигрывая в независимости масштабирования, мы платим огромную цену за распределённые данные и сетевую инфраструктуру.

| Критерий | Классический Монолит | Модульный Монолит | Микросервисы |
| :--- | :--- | :--- | :--- |
| **Скорость вызовов между модулями** | Мгновенно в памяти (`~0.0001 мс`) | Мгновенно в памяти (`~0.0001 мс`) | По сети HTTP/gRPC (`2..50 мс` + риск обрыва) |
| **Транзакции и консистентность** | Простая `ACID`-транзакция (`COMMIT`/`ROLLBACK`) | Простая `ACID`-транзакция | **Eventual Consistency** + паттерн **Saga** и **Outbox** |
| **Сложность деплоя и отладки** | Низкая (1 контейнер, 1 лог) | Низкая (1 контейнер, чёткие пакеты) | Высокая (Kubernetes, Service Mesh, Jaeger Tracing) |
| **Масштабирование (Scaling)** | Только целиком весь процесс | Целиком (но легко вынести 1 горячий модуль) | Точечное (10 копий `Billing`, 1 копия `Profile`) |
| **Изоляция сбоев (Fault Isolation)** | Утечка памяти роняет весь сайт | Утечка памяти роняет весь сайт | Падение `Notifications` не мешает оформлять заказы |
| **Оптимальный размер команды** | 1–10 разработчиков | 3–30 разработчиков | 30–500+ разработчиков (несколько независимых команд) |

## 3. Проблема распределённых транзакций в микросервисах: паттерн Saga

В монолите списание денег и резерв товара на складе оборачиваются в один `BEGIN ... COMMIT`. В микросервисах у `OrderService`, `PaymentService` и `InventoryService` **разные базы данных**! Если деньги списались, а товара на складе не оказалось, обычный `ROLLBACK` уже не сработает.

Решение — паттерн **Saga**: последовательность локальных транзакций в разных сервисах, где для каждого шага заранее написана **компенсирующая транзакция (Compensating Action)** — явная операция возврата средств (`refund_payment`), если следующий шаг цепочки упал.

> **Junior vs Senior**:
> - **Junior**: С первого дня стартапа на 3 человека пилит 12 микросервисов с Kafka и Kubernetes, а затем связывает их общей базой данных (получая худшее из обоих миров — **распределённый монолит / Distributed Monolith**!).
> - **Senior**: Начинает проект с **Модульного монолита** с чёткими контрактами между пакетами. Когда конкретный модуль (например, генерация видео или биллинг) реально упирается в CPU или требует отдельной релизной политики — вырезает его в отдельный микросервис по уже готовому интерфейсу.

## 4. Практикум: координатор распределённой транзакции (Saga Orchestrator) в Python

Посмотрим, как оркестратор Саги автоматически выполняет компенсирующие действия (отмену резерва и возврат денег) при сбое на последнем шаге доставки:

```python
from typing import Callable
from dataclasses import dataclass

@dataclass
class SagaStep:
    name: str
    action: Callable[[], str]
    compensate: Callable[[], str]

class SagaOrchestrator:
    def __init__(self, steps: list[SagaStep]) -> None:
        self._steps = steps

    def execute(self) -> tuple[bool, list[str]]:
        log: list[str] = []
        completed: list[SagaStep] = []
        for step in self._steps:
            try:
                res = step.action()
                log.append(f"✅ {step.name}: {res}")
                completed.append(step)
            except RuntimeError as err:
                log.append(f"❌ Сбой на шаге «{step.name}»: {err}")
                for done_step in reversed(completed):
                    comp_res = done_step.compensate()
                    log.append(f"↩️ Компенсация «{done_step.name}»: {comp_res}")
                return False, log
        return True, log

saga = SagaOrchestrator([
    SagaStep("Резерв склада", lambda: "Товар #7 зарезервирован", lambda: "Резерв товара #7 снят"),
    SagaStep("Списание оплаты", lambda: "Списано 1500 руб.", lambda: "Возврат 1500 руб. на карту"),
    SagaStep("Вызов курьера", lambda: (_ for _ in ()).throw(RuntimeError("Нет свободных курьеров")), lambda: "Отмена курьера"),
])

ok, events = saga.execute()
print(f"Статус Саги: {'УСПЕХ' if ok else 'ОТКАТ (COMPENSATED)'}")
for line in events:
    print(" ", line)
```
