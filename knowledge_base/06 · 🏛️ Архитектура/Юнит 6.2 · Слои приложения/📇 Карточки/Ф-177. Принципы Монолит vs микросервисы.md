1. Каков практический совет по эволюции архитектуры? >> Начинать с модульного монолита; выделять сервисы по мере появления реальной необходимости (нагрузка, независимые команды, разные требования к масштабированию)
2. Что такое «Modular Monolith»? >> Хорошо структурированный монолит, разделённый на чёткие модули внутри одного кода; хороший первый шаг перед микросервисами
3. Когда предпочтительнее монолит? >> Стартапы и MVP; команда до 10–20 человек («правило двух пицц»); домен системы ещё не изучен; нет чётких границ между сервисами
4. Почему модульный монолит – хороший первый шаг? >> Приучает к чётким границам между модулями без сетевой сложности; при необходимости модуль легче выделить в сервис
5. Что происходит с количеством БД при переходе от монолита к микросервисам? >> Увеличивается; каждый сервис имеет свою БД (или несколько); это усложняет обеспечение согласованности данных
6. Сравнение монолита и микросервисов по ключевым параметрам? >> Сложность: монолит низкая, микросервисы высокая; масштабирование: монолит вертикальное, микросервисы горизонтальное; отказоустойчивость: монолит – падает всё, микросервисы – падает один; транзакции: монолит ACID, микросервисы Saga/eventual consistency; latency: монолит быстрее (in-process), микросервисы медленнее (сеть)
7. Когда предпочтительнее микросервисы? >> Разные части системы с сильно различающимися требованиями к нагрузке; большие команды с независимыми зонами ответственности; требуется независимый деплой компонентов
8. Почему монолит лучше на ранних этапах при неизученном домене? >> Сложно правильно провести границы между сервисами; преждевременная декомпозиция создаёт неправильные границы, которые дорого переделывать
9. Почему in-process вызовы в монолите быстрее сетевых? >> Нет накладных расходов на сетевую передачу, сериализацию/десериализацию данных и сетевые задержки
10. Что такое eventual consistency? >> Данные в конечном счёте станут согласованными на всех узлах, но не обязательно немедленно; типично для микросервисов с разными БД
11. Что такое паттерн Saga? >> Паттерн управления транзакциями в распределённых системах; заменяет ACID-транзакции последовательностью локальных транзакций с компенсирующими действиями
12. Что такое монолитная архитектура? >> Все модули системы развёртываются как единый процесс с одной общей БД; просто на старте, но сложно масштабировать и изменять независимо
13. Что такое микросервисная архитектура? >> Каждый функциональный домен – отдельный сервис со своей БД, деплоем и API; сервисы взаимодействуют через API Gateway или Message Bus
14. Что такое API Gateway? >> Единая точка входа для внешних клиентов в микросервисную систему; маршрутизирует запросы к нужным сервисам
15. Что такое «преждевременная микросервисная архитектура»? >> Антипаттерн: разбиение на микросервисы до того, как появилась реальная необходимость; высокие затраты на инфраструктуру перекрывают выгоды для маленьких команд
