## 1. Три фильтра инженерного здравомыслия: DRY, KISS, YAGNI

> **Ментальная модель — «Сборы в поход на выходные»**:
> - **YAGNI (You Aren't Gonna Need It)** — не берите в двухдневный поход в лес акваланг, смокинг и дизель-генератор «на всякий случай». Каждый лишний предмет утяжеляет рюкзак (кодовую базу) прямо сейчас.
> - **KISS (Keep It Simple, Stupid)** — чтобы разжечь костёр, возьмите обычные спички, а не стройте лазерный воспламенитель с Bluetooth-управлением.
> - **DRY (Don't Repeat Yourself)** — храните список маршрутных точек в одной карте у штурмана, а не переписывайте его от руки на 10 клочков бумаги: если маршрут изменится, кто-то обязательно пойдёт по старой записке.

```text
Как работают 3 фильтра перед написанием кода:

  [Идея новой фичи или класса]
               |
               v
  1. YAGNI: "Нужно ли это бизнесу ПРЯМО СЕЙЧАС?"
       |-- Нет --> 🗑️ Не пишем вообще (самый быстрый и надёжный код — ненаписанный)
       |-- Да  --> v
  2. KISS:  "Какое решение самое простое и читаемое?"
       |---------> Выбираем функцию из 5 строк вместо абстрактной мета-фабрики
                   |
                   v
  3. DRY:   "Не дублируем ли мы уже существующее бизнес-правило?"
       |---------> Выносим единый источник истины (Single Source of Truth)
```

## 2. DRY vs Rule of Three: когда дублирование опаснее абстракции, а когда — наоборот

**DRY (Don't Repeat Yourself)** (Энди Хант, Дейв Томас, *The Pragmatic Programmer*): *«Каждая частица знания должна иметь единственное, непротиворечивое и авторитетное представление в рамках системы»*.

Обратите внимание на слово **«знания» (бизнес-правила)**, а не просто «похожих строчек текста»!
- Если формула НДС `price * 0.20` скопирована в модуль корзины, модуль чеков и генератор PDF-отчётов — это **нарушение DRY** (единое знание размазано по 3 местам).
- Но если валидация длины `len(title) <= 100` для товара и `len(bio) <= 100` для профиля пользователя случайно совпали по числу `100` — это **разные бизнес-знания**! Сливать их в одну функцию `validate_100_chars()` вредно: завтра лимит `bio` вырастет до `500`, и общая функция сломает товары.
- Поэтому в инженерии действует **Правило трёх (Rule of Three)**: не стройте сложную обобщённую абстракцию при первом же совпадении двух кусков кода — дождитесь третьего реального случая, когда паттерн станет очевидным.

| Ситуация в коде | Нарушенный принцип | Чем грозит в продакшене | Как исправить |
| :--- | :--- | :--- | :--- |
| Формула расчёта комиссии скопирована в 4 эндпоинтах | **DRY** | При смене тарифа исправят в 3 местах, а 4-е начнёт списывать старую сумму | Вынести в единую чистую функцию или доменный метод |
| Для проверки двух статусов написали иерархию из 6 классов и метакласса | **KISS** | Коллеги тратят 30 минут на чтение кода, который помещается в 3 строки `if/ return` | Заменить на простую чистую функцию или словарь |
| На старте MVP написали движок плагинов и поддержку 12 СУБД | **YAGNI** | Потратили 2 недели на мёртвый код, который нужно поддерживать и тестировать | Удалить неиспользуемый код; решать задачу текущего спринта |

## 3. Практический рефакторинг: убираем нарушения DRY, KISS и YAGNI

> **Junior vs Senior**:
> - **Junior**: Либо копипастит один и тот же блок расчёта скидки в 5 функций (нарушая **DRY**), либо впадает в другую крайность — строит универсальный `AbstractEnterpriseDiscountEngineFactory` с заделом «на 2030 год» (нарушая **KISS** и **YAGNI**).
> - **Senior**: Отсекает непрошенные фичи по **YAGNI**, пишет прямолинейный и прозрачный код по **KISS**, а бизнес-константы и формулы собирает в едином источнике истины по **DRY**.

```python
from dataclasses import dataclass

# ✅ Единый источник истины для бизнес-правил (DRY) + предельная простота (KISS & YAGNI)
VAT_RATE = 0.20
FREE_SHIPPING_THRESHOLD = 3000

@dataclass(frozen=True)
class OrderSummary:
    subtotal: float
    vat: float
    shipping: float
    total: float

def calculate_order_summary(prices: list[float]) -> OrderSummary:
    if not prices:
        return OrderSummary(subtotal=0.0, vat=0.0, shipping=0.0, total=0.0)
    subtotal = round(sum(prices), 2)
    vat = round(subtotal * VAT_RATE, 2)
    shipping = 0.0 if subtotal >= FREE_SHIPPING_THRESHOLD else 299.0
    return OrderSummary(
        subtotal=subtotal,
        vat=vat,
        shipping=shipping,
        total=round(subtotal + vat + shipping, 2),
    )

print("Малый заказ:", calculate_order_summary([500.0, 700.0]))
print("Крупный заказ (бесплатная доставка):", calculate_order_summary([2000.0, 1500.0]))
```

## 4. Чек-лист перед отправкой Pull Request

Перед тем как отправить код на ревью, задайте себе три коротких вопроса:
1. **Проверка на YAGNI**: Есть ли в моём PR методы, аргументы или таблицы, которые *прямо сейчас* никем не вызываются? (Если да — удаляем без жалости, Git всё помнит).
2. **Проверка на KISS**: Поймёт ли этот код другой разработчик за 30 секунд в пятницу вечером без отладчика?
3. **Проверка на DRY**: Если завтра аналитик изменит пороговое значение или формулу, в скольких файлах мне придётся сделать правку? (Идеальный ответ — **в одном**).

```python
def audit_code_smells(code_metrics: dict[str, int]) -> list[str]:
    warnings: list[str] = []
    if code_metrics.get("duplicated_formulas", 0) > 1:
        warnings.append("Нарушен DRY: формула продублирована в нескольких местах")
    if code_metrics.get("unused_future_methods", 0) > 0:
        warnings.append("Нарушен YAGNI: присутствуют неиспользуемые методы 'на будущее'")
    if code_metrics.get("nesting_depth", 0) > 3:
        warnings.append("Нарушен KISS: глубина вложенности условий превышает 3 уровня")
    return warnings or ["Код чист: DRY, KISS и YAGNI соблюдены!"]

print(audit_code_smells({"duplicated_formulas": 3, "unused_future_methods": 2, "nesting_depth": 4}))
print(audit_code_smells({"duplicated_formulas": 1, "unused_future_methods": 0, "nesting_depth": 2}))
```
