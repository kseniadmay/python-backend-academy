1. Кто сформулировал принципы SOLID? >> Роберт Мартин (Uncle Bob)
2. Как связаны DIP и Dependency Injection? >> DIP – принцип (зависеть от абстракций); Dependency Injection – механизм реализации (подставлять зависимости снаружи); DI – один из способов соблюдать DIP
3. Что такое SRP? >> Single Responsibility Principle: класс должен иметь только одну причину для изменения; «один класс – одна задача»
4. Как реализовать DIP? >> Передавать абстракцию (интерфейс) через конструктор: `def __init__(self, db: Database)` ; конкретная реализация подставляется снаружи (Dependency Injection)
5. Что такое DIP? >> Dependency Inversion Principle: модули высокого уровня не должны зависеть от низкоуровневых; оба должны зависеть от абстракций; детали зависят от абстракций, а не наоборот
6. Признак нарушения OCP? >> Длинная цепочка `if/elif` в методе при добавлении нового типа; необходимость изменять уже протестированный код
7. Как DIP помогает в тестировании? >> В тестах передаётся `InMemoryDatabase` или мок вместо реальной БД; бизнес-логика тестируется изолированно
8. Как связаны OCP и паттерн Strategy? >> Strategy реализует OCP: новое поведение добавляется через новый класс-стратегию без изменения контекста
9. Признак нарушения DIP? >> `self.db = PostgreSQLDatabase()` в конструкторе сервиса; жёсткая зависимость от конкретной реализации
10. Как исправить нарушение ISP (пример с животными)? >> Разделить `Animal` на `Walkable` , `Flyable` , `Swimmable` ; `Eagle(Walkable, Flyable)` , `Penguin(Walkable, Swimmable)` – каждый реализует только нужные интерфейсы
11. Что такое OCP? >> Open/Closed Principle: программные сущности открыты для расширения, но закрыты для изменения; новое поведение добавляется через новые классы, а не правку существующих
12. Что такое ISP? >> Interface Segregation Principle: клиент не должен зависеть от методов, которые он не использует; много маленьких специализированных интерфейсов лучше одного большого
13. Признак нарушения SRP? >> Класс меняется по нескольким независимым причинам; например, изменение схемы БД ломает логику отправки email в одном классе
14. Расшифруйте SOLID? >> S – SRP (Single Responsibility), O – OCP (Open/Closed), L – LSP (Liskov Substitution), I – ISP (Interface Segregation), D – DIP (Dependency Inversion)
15. Что такое LSP? >> Liskov Substitution Principle: объекты подкласса должны заменять объекты базового класса без нарушения корректности программы
16. Как связаны ISP и duck typing в Python? >> Python не требует явного объявления интерфейсов; `Protocol` из `typing` позволяет определять структурные интерфейсы без наследования – питоничный способ реализации ISP
17. Другие признаки нарушения LSP? >> Подкласс бросает исключения, не предусмотренные базовым классом; игнорирует аргументы метода; возвращает другой тип; требует `isinstance()` для корректной обработки
18. Классический пример нарушения LSP? >> `Square` наследует `Rectangle` ; изменение ширины квадрата меняет высоту – нарушает инварианты прямоугольника; клиентский код, работающий с `Rectangle` , ведёт себя непредсказуемо
19. Признак нарушения ISP? >> Класс реализует метод интерфейса через `raise NotImplementedError` или пустой `pass` – явный сигнал, что интерфейс слишком широк
