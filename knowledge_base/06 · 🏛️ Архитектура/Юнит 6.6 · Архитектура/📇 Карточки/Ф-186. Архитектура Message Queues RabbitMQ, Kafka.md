1. Что делает `ch.basic_ack()` ? >> Подтверждает брокеру успешную обработку сообщения; без `ack` сообщение вернётся в очередь при падении воркера
2. В каких архитектурных сценариях брокер сообщений RabbitMQ предпочтительнее Apache Kafka? >> Task Queue: отправка email, SMS, обработка платежей; когда важна гарантия доставки и сложная маршрутизация; в связке с Celery
3. Что представляет собой Apache Kafka и каковы её ключевые архитектурные особенности? >> Распределённая горизонтально масштабируемая платформа потоковой передачи событий (Event Streaming Platform), использующая персистентный append-only лог на диске, партиционирование топиков и архитектуру Consumer Groups.
4. Что такое синхронное взаимодействие сервисов? >> Сервис A вызывает Сервис B и блокируется в ожидании ответа; если B недоступен или медленный – A не может продолжать работу
5. Что такое `group.id` в Kafka? >> Идентификатор группы потребителей; разные группы читают топик независимо с разными offset; внутри группы партиции распределяются между потребителями
6. Что делает `durable=True` при объявлении очереди в RabbitMQ? >> Очередь сохраняется при перезапуске брокера; для полной гарантии также нужны персистентные сообщения ( `delivery_mode=2` )
7. Какие три типа Exchange есть в RabbitMQ? >> Direct (по точному `routing_key` ); Fanout (broadcast во все очереди); Topic (по шаблону, например `order.*` )
8. Что позволяет `auto.offset.reset: earliest` ? >> Начать чтение с самого начала лога; по умолчанию ( `latest` ) – только новые сообщения
9. Чем масштабирование в Kafka отличается от RabbitMQ? >> RabbitMQ: распределяет сообщения между свободными воркерами; Kafka: распределяет партиции между потребителями в группе; количество потребителей ≤ количеству партиций
10. Какие три проблемы решает Message Queue? >> Decoupling (слабая связанность); сглаживание пиковых нагрузок (буферизация); надёжность (сообщения сохраняются при падении потребителя)
11. Что такое сетевой протокол AMQP (Advanced Message Queuing Protocol) и где он применяется? >> Открытый бинарный протокол прикладного уровня для передачи сообщений между компонентами распределённых систем; лежит в основе брокера сообщений RabbitMQ и определяет понятия Exchange, Queue и Binding.
12. Ключевое отличие Kafka от RabbitMQ по хранению сообщений? >> RabbitMQ: сообщение удаляется после `ack` ; Kafka: сообщение хранится в логе установленное время (по умолчанию 7 дней) и может быть перечитано
13. Что такое асинхронное взаимодействие через Message Queue? >> Сервис A кладёт сообщение в очередь и не ждёт; Сервис B забирает его в своём темпе; сервисы не знают о деталях реализации друг друга (Decoupling)
14. Что такое offset в Kafka? >> Позиция (смещение) потребителя в логе топика; каждый потребитель хранит свой offset независимо
15. Что гарантирует надёжность RabbitMQ при сбое питания? >> Комбинация `durable=True` (очередь) + `delivery_mode=2` (персистентные сообщения); оба условия необходимы
16. В каких сценариях потоковой обработки и масштабирования распределённый журнал Apache Kafka предпочтительнее RabbitMQ? >> Event Streaming: аналитика кликов, аудит действий, real-time дашборды; когда нужна высокая пропускная способность или возможность перечитать историю событий
17. Что произойдёт с сообщением в RabbitMQ, если воркер упал без `ack` ? >> Сообщение вернётся в очередь и будет обработано другим воркером
18. Что такое RabbitMQ? >> Классический брокер сообщений; работает по протоколу AMQP; гарантирует доставку; сообщение удаляется после `ack`
19. Что такое паттерн Competing Consumers? >> Несколько воркеров читают одну очередь; каждое сообщение обрабатывается только одним воркером; масштабирование добавлением воркеров
