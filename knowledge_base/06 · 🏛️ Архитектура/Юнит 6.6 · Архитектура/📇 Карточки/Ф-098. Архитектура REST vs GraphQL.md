1. Сколько отдельных REST-запросов обычно требуется для последовательной загрузки пользователя, его заказов и товаров внутри заказов? >> его заказов → товаров в заказах? → Три; в GraphQL – один
2. Что такое BFF (Backend for Frontend)? >> Паттерн: отдельный backend-слой для каждого типа клиента (мобильное приложение, веб); GraphQL часто используется как BFF
3. Сколько эндпоинтов у GraphQL API? >> Один ( `/graphql` ); в REST – по эндпоинту на каждый ресурс
4. Каковы основные практические способы версионирования эндпоинтов в REST API? >> Через URL: `/api/v1/users` → `/api/v2/users`
5. В каких сценариях архитектурный стиль REST предпочтительнее GraphQL? >> Простой CRUD API; важно HTTP-кэширование; передача файлов и бинарных данных; публичные API для неограниченного круга потребителей; команда хорошо знает HTTP-стандарты
6. Какие Python-библиотеки используются для REST? >> FastAPI (производительность + автодокументация), DRF (Django REST Framework)
7. Как GraphQL решает Over-fetching и Under-fetching? >> Клиент указывает в запросе только нужные поля; все связанные данные получаются за один запрос
8. Как GraphQL обновляет API без версионирования? >> Добавляются новые поля; устаревшие помечаются `@deprecated` ; клиенты продолжают работать со старыми полями
9. Что представляет собой GraphQL и в чём его ключевое концептуальное отличие от REST API? >> Декларативный язык запросов и среда выполнения API, позволяющий клиенту запросить ровно те поля данных, которые ему необходимы, через единственный HTTP-эндпоинт (обычно POST /graphql), исключая проблемы over-fetching и under-fetching.
10. Что представляет собой архитектурный стиль REST (Representational State Transfer)? >> Архитектурный стиль построения распределённых веб-систем, описанный Роем Филдингом, основанный на манипуляции ресурсами через стандартные URI и явные HTTP-методы с соблюдением 6 ключевых ограничений.
11. Какие Python-библиотеки используются для GraphQL? >> Strawberry (современный, поддерживает type hints), Graphene
12. Почему REST лучше для HTTP-кэширования? >> GET-запросы в REST кэшируются стандартными механизмами HTTP (CDN, браузер); GraphQL обычно использует POST – кэширование сложнее
13. Что такое Over-fetching в REST? >> Сервер возвращает все поля объекта, даже если клиенту нужно только одно; например, запрос имени возвращает весь профиль пользователя
14. Что такое Under-fetching в REST? >> Одного запроса недостаточно для получения всех нужных связанных данных; требуются дополнительные запросы
15. В каких сценариях клиент-серверного взаимодействия GraphQL предпочтительнее REST API? >> Мобильные приложения (экономия трафика); разные клиенты с разными потребностями (iOS, Android, Web); часто меняющиеся требования фронтенда; сложные графы связей между сущностями; BFF-паттерн
