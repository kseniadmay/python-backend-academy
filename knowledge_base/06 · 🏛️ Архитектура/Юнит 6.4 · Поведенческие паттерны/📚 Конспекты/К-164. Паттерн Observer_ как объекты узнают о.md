## Паттерн Observer (Наблюдатель / Pub-Sub): разрываем жёсткую связность

> **Подписка на YouTube-канал против обзвона по телефону**: с паттерном **Observer** издатель (`OrderService`) просто нажимает **«Опубликовать» (`emit`)**, а все подписчики реагируют на событие независимо.

Без Observer автору видео приходилось бы лично обзванивать каждого зрителя (`EmailService`, `BonusService`, `AnalyticsService`) и менять код сервиса при добавлении нового получателя. С `emit("order.paid", event)` издатель вообще не знает, кто на него подписан (`subscribe`).

```text
Архитектура паттерна Observer / Event Bus:

  +------------------+                        +-----------------------+
  |   OrderService   |                        |     <<Subscriber>>    |
  |   (Publisher)    |                        +-----------------------+
  +------------------+                                    ^
           |                                              |
           | 1. emit(OrderPaidEvent)        +-------------+-------------+
           v                                |             |             |
  +------------------+   2. Уведомляет   +-------+   +---------+   +-----------+
  |    EventBus      | ================> | Email |   | Loyalty |   | Analytics |
  |  _subscribers[]  |                   |Handler|   | Handler |   |  Handler  |
  +------------------+                   +-------+   +---------+   +-----------+
```

## Изоляция сбоев: почему падение одного подписчика не должно ломать остальных

Представьте, что при оплате заказа срабатывают три подписчика:
1. `FiscalReceiptSubscriber` (отправка онлайн-чека в налоговую);
2. `LoyaltyPointsSubscriber` (начисление кэшбэка);
3. `AnalyticsSubscriber` (отправка метрики во внешний трекер).

Что произойдёт в наивном цикле `for sub in subscribers: sub(event)`, если внешний сервер аналитики временно недоступен и выбросит `TimeoutError`?
Если `AnalyticsSubscriber` стоял первым в списке, то цикл оборвётся: **клиент не получит чек, кэшбэк не начислится, а оплаченный заказ вернёт HTTP 500**!

| Аспект реализации | Наивный Observer (Уязвимый) | Промышленный EventBus / Domain Events |
| :--- | :--- | :--- |
| **Обработка исключений в `emit()`** | Нет `try/except` — ошибка одного подписчика обрывает всю цепочку | Каждый вызов обёрнут в `try/except`, ошибка логируется, остальные подписчики отрабатывают штатно |
| **Мутация данных события** | Передаётся обычный `dict`, который первый подписчик может случайно испортить (`data.clear()`) | Событие передаётся как неизменяемый `@dataclass(frozen=True)` |
| **Тяжёлые сетевые операции** | Выполняются синхронно в том же HTTP-потоке (тормозят ответ клиенту) | Перекладываются в фоновую очередь (`BackgroundTasks` / `Celery` / `Transactional Outbox`) |

## Где Observer живёт в реальных фреймворках (Django Signals vs FastAPI EventBus)

- В **Django** паттерн Observer встроен из коробки в виде **Сигналов (`django.dispatch.Signal`, `post_save`, `pre_delete`)** и декоратора `@receiver(post_save, sender=Order)`. Однако с сигналами Django нужно быть осторожным: они выполняются **синхронно в том же потоке** и при злоупотреблении превращают логику сохранения в неявный лабиринт.
- В **Чистой архитектуре и DDD** вместо магических сигналов ORM используют **явные доменные события (`Domain Events`)** и **шину событий (`EventBus`)**: сервис явно публикует типизированный объект `UserRegisteredEvent(user_id=42, email='...')`.

> **Junior vs Senior**:
> - **Junior**: Вешает на сигнал Django `post_save` модели `User` синхронный HTTP-запрос к внешнему CRM. В результате каждый `user.save()` в тестах и админке начинает зависать на 3 секунды или падать при сбое сети.
> - **Senior**: Использует явную шину доменных событий (`EventBus`) с неизменяемыми `@dataclass(frozen=True)`-событиями, защищает диспетчер изоляцией ошибок (`try/except` на каждого слушателя), а внешние сетевые вызовы делегирует фоновому воркеру.

## Шина доменных событий (`EventBus`) и типизация событий

События оформляются как неизменяемые `@dataclass(frozen=True)`, а диспетчер `EventBus` изолирует ошибки каждого подписчика:

```python
from collections import defaultdict
from dataclasses import dataclass
from typing import Callable, TypeVar

TEvent = TypeVar("TEvent")

@dataclass(frozen=True)
class OrderPaidEvent:
    order_id: int
    user_email: str
    amount: float

class EventBus:
    def __init__(self) -> None:
        self._listeners: dict[
            type,
            list[Callable[[object], None]],
        ] = defaultdict(list)
        self.error_log: list[str] = []

    def subscribe(
        self, event_type: type[TEvent],
        handler: Callable[[TEvent], None]
    ) -> None:
        (
            self._listeners[event_type]
            .append(handler)
        )

    def publish(self, event: object) -> None:
        for handler in (
            self._listeners.get(
                type(event),
                [],
            )
        ):
            try:
                handler(event)
            except Exception as exc:
                self.error_log.append(
                    f"{handler.__name__}: "
                    f"{exc}"
                )

bus = EventBus()
```

## Подписка и изоляция сбоев подписчиков

Если один обработчик упал (например, сбой внешней аналитики), остальные подписчики обязаны успешно выполниться:

```python
from collections import defaultdict
from dataclasses import dataclass

@dataclass(frozen=True)
class OrderPaidEvent:
    order_id: int
    user_email: str
    amount: float

class EventBus:
    def __init__(self) -> None:
        self._listeners: dict = (
            defaultdict(list)
        )
        self.error_log: list[str] = []

    def subscribe(
        self,
        event_type,
        handler,
    ) -> None:
        (
            self._listeners[event_type]
            .append(handler)
        )

    def publish(self, event: object) -> None:
        for h in (
            self._listeners.get(
                type(event),
                [],
            )
        ):
            try:
                h(event)
            except Exception as exc:
                self.error_log.append(
                    f'{h.__name__}: {exc}'
                )

bus = EventBus()
audit_trail: list[str] = []

def broken_analytics_handler(
    ev: OrderPaidEvent,
) -> None:
    raise RuntimeError(
        'Сервер аналитики недоступен'
    )

def send_receipt_handler(
    ev: OrderPaidEvent,
) -> None:
    msg = (
        f'Чек на {ev.amount} руб. -> '
        f'{ev.user_email}'
    )
    audit_trail.append(msg)

def add_bonus_handler(
    ev: OrderPaidEvent,
) -> None:
    bonus = int(ev.amount * 0.05)
    audit_trail.append(
        f'Бонусы +{bonus} за #{ev.order_id}'
    )

bus.subscribe(
    OrderPaidEvent,
    broken_analytics_handler,
)
bus.subscribe(
    OrderPaidEvent,
    send_receipt_handler,
)
bus.subscribe(
    OrderPaidEvent,
    add_bonus_handler,
)

bus.publish(
    OrderPaidEvent(
        77,
        'bob@example.com',
        2000.0,
    )
)
print('Успешные подписчики:', audit_trail)
# >>> Успешные подписчики: ['Чек на 2000.0 руб. -> bob@example.com', 'Бонусы +100 за #77']
print('Перехваченные сбои:', bus.error_log)
# >>> Перехваченные сбои: ['broken_analytics_handler: Сервер аналитики недоступен']
```
