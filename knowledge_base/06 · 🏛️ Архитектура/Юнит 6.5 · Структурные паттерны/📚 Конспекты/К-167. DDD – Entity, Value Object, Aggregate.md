## Зачем нужен тактический DDD: богатая модель против анемичной (Anemic Model)

> **Паспорт гражданина против купюры в 1000 рублей**: сущность (`Entity`) определяется своим уникальным `id`, а объект-значение (`Value Object`) — набором неизменяемых атрибутов.

- **Человек (`Entity` / Сущность)** имеет уникальный идентификатор (номер паспорта). Даже после смены фамилии или адреса это остаётся тот же человек (равенство по `id`).
- **Купюра 1000 ₽ (`Value Object`)** не имеет личной биографии: две купюры `Money(1000, "RUB")` полностью взаимозаменяемы и неизменяемы (равенство по значениям всех полей).

Без **Domain-Driven Design (DDD)** проекты часто скатываются в антипаттерн **Анемичная доменная модель (Anemic Domain Model)**: классы превращаются в «тупые мешки с геттерами и сеттерами» без проверок, где любой внешний код может написать `order.status = "paid"; order.total = -500`.

В **богатой доменной модели (Rich Domain Model)** данные и бизнес-инварианты защищены внутри самих объектов!

```text
Три базовых строительных блока тактического DDD:

  +-------------------------------------------------------------------+
  |                   AGGREGATE (Граница транзакции)                  |
  |                                                                   |
  |   +-----------------------------------------------------------+   |
  |   | 👑 Order (Aggregate Root / Корневая Entity, id=101)       |   |
  |   |   Инвариант: "Нельзя добавить позицию в оплаченный заказ" |   |
  |   +-----------------------------------------------------------+   |
  |              |                                    |               |
  |              v (Внутренние Entity)                v (Value Object)|
  |   +-----------------------+            +----------------------+   |
  |   | OrderLine (product=5) | ---------> | Money(1500, "RUB")   |   |
  |   +-----------------------+            | (frozen=True, без id)|   |
  |                                        +----------------------+   |
  +-------------------------------------------------------------------+
  ⬆️ Внешний мир общается ТОЛЬКО через методы корня Order.add_item()!
```

## Сравнительная таблица: Entity vs Value Object vs Aggregate

| Строительный блок DDD | Как сравнивается (`==`)? | Изменяемость (Mutability) | Примеры из реального бэкенда |
| :--- | :--- | :--- | :--- |
| **Entity (Сущность)** | Только **по уникальному `id`** (`self.id == other.id`) | **Изменяема**: проходит жизненный цикл статусов во времени | `User`, `Order`, `BankAccount`, `SupportTicket` |
| **Value Object (Объект-значение)** | **По совпадению всех атрибутов** (`amount == amount and currency == currency`) | **Строго неизменяем (`@dataclass(frozen=True)`)**: любая операция возвращает *новый* экземпляр | `Money(100, 'RUB')`, `EmailAddress`, `GeoCoordinates(lat, lon)`, `DateRange` |
| **Aggregate (Агрегат)** | По `id` своего корня (**Aggregate Root**) | Изменяется только целиком через методы **Aggregate Root** в одной транзакции | Кластер `Order` (корень) + список `OrderLine` + `ShippingAddress` |

## Золотые правила проектирования Aggregate Root

**Aggregate Root (Корень агрегата)** — это главный страж бизнес-инвариантов:
1. **Единый вход**: внешний код не имеет права напрямую делать `order.items.append(line)` в обход корня. Все изменения идут только через методы корня (`order.add_item(...)`, `order.pay()`), которые проверяют бизнес-правила!
2. **Защита внутренней коллекции**: чтобы внешний код случайно не мутировал внутренний список `_items`, наружу отдаётся только неизменяемая копия (`tuple(self._items)`).
3. **Один репозиторий на один Aggregate Root**: мы создаём `OrderRepository`, но **не создаём** отдельный `OrderItemRepository` — позиции заказа сохраняются и загружаются вместе со своим заказом.

> **Junior vs Senior**:
> - **Junior**: Хранит деньги в `float` (`0.1 + 0.2 == 0.30000000000000004`), email — в непроверенной строке `str`, а статус заказа меняет напрямую `order.status = 'shipped'` без проверки, был ли заказ вообще оплачен.
> - **Senior**: Выделяет `Money` (с проверкой совпадения валют в `__add__`) и `Email` в неизменяемые **Value Objects** (`@dataclass(frozen=True)`), а переходы статусов и инварианты заказа закрывает внутри методов **Aggregate Root** `Order`.

## Практикум: Value Object `Money` в Python 3.13

Объекты-значения создаются через `@dataclass(frozen=True)`: они неизменяемы, валидируют себя при создании и сравниваются строго по значениям полей, а не по `id`.

```python
from dataclasses import dataclass

# Неизменяемый Value Object для денег
@dataclass(frozen=True)
class Money:
    amount: int
    currency: str = "RUB"

    def __post_init__(self) -> None:
        if self.amount < 0:
            raise ValueError(
                "Сумма Money не может быть "
                "отрицательной"
            )
        if (
            len(self.currency) != 3
            or not self.currency.isupper()
        ):
            raise ValueError(
                f"Некорректный код валюты: "
                f"{self.currency}"
            )

    # Сложение с проверкой совпадения валют
    def __add__(
        self,
        other: "Money",
    ) -> "Money":
        if self.currency != other.currency:
            raise ValueError(
                f"Нельзя складывать валюты "
                f"{self.currency} и "
                f"{other.currency}"
            )
        return Money(
            self.amount + other.amount,
            self.currency,
        )

    def multiply(self, qty: int) -> "Money":
        return Money(
            self.amount * qty,
            self.currency,
        )

m1 = Money(1200, "RUB")
m2 = Money(450, "RUB")
print("Сумма Money:", m1 + m2)
# >>> Сумма Money: Money(amount=1650, currency='RUB')
print(
    "Проверка равенства Value Object:",
    m1 == Money(1200, "RUB"),
)
# >>> Проверка равенства Value Object: True
```

## Практикум: Aggregate Root `Order` и бизнес-инварианты

Корень агрегата инкапсулирует работу с позициями заказа и запрещает модификации в обход своих методов:

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Money:
    amount: int
    currency: str = 'RUB'

    def __add__(
        self,
        other: 'Money',
    ) -> 'Money':
        return Money(
            self.amount + other.amount,
            self.currency,
        )

    def multiply(self, qty: int) -> 'Money':
        return Money(
            self.amount * qty,
            self.currency,
        )

@dataclass(frozen=True)
class OrderLine:
    sku: str
    qty: int
    unit_price: Money

    @property
    def subtotal(self) -> Money:
        return self.unit_price.multiply(
            self.qty
        )

# Агрегат защищает свои инварианты
class Order:
    def __init__(
        self,
        order_id: int,
        currency: str = 'RUB',
    ) -> None:
        self.id = order_id
        self.currency = currency
        self.status = 'draft'
        self._lines: list[OrderLine] = []

    def __eq__(self, other: object) -> bool:
        return (
            isinstance(other, Order)
            and self.id == other.id
        )

    def add_item(
        self,
        sku: str,
        qty: int,
        unit_price: Money,
    ) -> None:
        # Запрет правки подтверждённого заказа
        if self.status != 'draft':
            raise ValueError(
                'Нельзя менять '
                'подтверждённый заказ!'
            )
        if qty <= 0:
            raise ValueError(
                'Количество товара должно '
                'быть > 0'
            )
        self._lines.append(
            OrderLine(
                sku=sku,
                qty=qty,
                unit_price=unit_price,
            )
        )

    @property
    def total(self) -> Money:
        result = Money(0, self.currency)
        for line in self._lines:
            result = result + line.subtotal
        return result

    def confirm(self) -> None:
        if not self._lines:
            raise ValueError(
                'Нельзя подтвердить пустой '
                'заказ!'
            )
        self.status = 'confirmed'

order = Order(order_id=501)
order.add_item(
    'BOOK-DDD',
    qty=2,
    unit_price=Money(1200, 'RUB'),
)
order.add_item(
    'COFFEE',
    qty=1,
    unit_price=Money(450, 'RUB'),
)
order.confirm()
tot = order.total
print(
    f'Заказ #{order.id} [{order.status}] | '
    f'Итого: {tot.amount} {tot.currency}'
)
# >>> Заказ #501 [confirmed] | Итого: 2850 RUB
```
