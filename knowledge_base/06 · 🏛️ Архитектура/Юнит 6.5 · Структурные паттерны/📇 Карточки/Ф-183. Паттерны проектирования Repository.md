1. Какой принцип SOLID реализует Repository? >> SRP (Single Responsibility Principle): логика работы с данными вынесена из бизнес-сервисов в отдельные классы; также DIP (зависимость от абстракции, а не реализации)
2. Зачем нужен Repository, если есть ORM? >> ORM – инструмент; Repository – архитектурный паттерн; без Repository бизнес-логика напрямую зависит от ORM и конкретной БД; с Repository – нет
3. Как Repository связан с Dependency Injection? >> Конкретная реализация репозитория передаётся в сервис через конструктор ( `__init__` ); в продакшене – `SQLAlchemyRepository` , в тестах – `InMemoryRepository`
4. Как Repository помогает в тестировании? >> Вместо реальной БД подставляется `InMemoryRepository` – тесты быстрые, изолированные, не требуют инфраструктуры
5. Что даёт разделение интерфейса и реализации в Repository? >> Можно сменить хранилище (PostgreSQL → MongoDB → Redis) без изменения бизнес-логики; достаточно создать новую реализацию интерфейса
6. Что такое `InMemoryRepository` ? >> Реализация репозитория, хранящая данные в словаре в RAM; используется для unit-тестов; не требует реальной БД
7. Как Repository помогает при масштабировании команды? >> Разработчики бизнес-логики и разработчики БД работают независимо, ориентируясь на общий интерфейс
8. Что скрывает Repository: «что» или «как»? >> «Как» – технические детали получения и сохранения данных; «что» определяет бизнес-логика через интерфейс
9. Чем Repository отличается от DAO (Data Access Object)? >> DAO – низкоуровневый доступ к данным, часто один метод = один SQL; Repository – объектно-ориентированная коллекция доменных объектов с более богатым API
10. Почему `get_by_id` возвращает `Optional[User]` , а не `User` ? >> Пользователь с данным ID может не существовать; `None` – явный способ обозначить отсутствие объекта
11. Что произойдёт при попытке создать экземпляр `SQLAlchemyUserRepository` , если метод `get_by_id` не реализован? >> Python бросит `TypeError` ; нельзя создать экземпляр класса с нереализованными `@abstractmethod`
12. Обязательно ли использовать SQLAlchemy в Repository? >> Нет; реализация может быть на любом инструменте: Raw SQL, `asyncpg` , Motor (MongoDB), Redis; интерфейс остаётся неизменным
13. Что такое паттерн Repository? >> Паттерн слоя доступа к данным; абстрагирует логику работы с хранилищем (БД, API, файлы) за интерфейсом; бизнес-логика взаимодействует только с интерфейсом
