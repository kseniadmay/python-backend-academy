1. Какой тип сети Docker использует сетевой стек хоста напрямую? >> `host`
2. В чём разница между дефолтной сетью `bridge` и пользовательской (user-defined) bridge-сетью? >> В дефолтной `bridge` DNS-разрешение по имени контейнера не работает – только по IP; в user-defined bridge DNS работает автоматически, контейнеры общаются по имени
3. Как подключить уже запущенный контейнер к сети? >> `docker network connect my-network my-container`
4. Как сервисы в `docker-compose` обращаются друг к другу? >> По имени сервиса из `docker-compose.yml` ; DNS работает автоматически так как создаётся user-defined bridge-сеть
5. Как контейнеры в user-defined bridge-сети могут обращаться друг к другу? >> По имени контейнера через встроенный DNS Docker; в дефолтной сети `bridge` это не работает
6. Как создаются сети при использовании `docker-compose` ? >> Автоматически; по умолчанию создаётся одна общая user-defined bridge-сеть для всех сервисов файла
7. В команде `psql -h db` , запущенной в user-defined bridge-сети, чем является `db` ? >> Именем контейнера базы данных; Docker резолвит его через встроенный DNS
8. Где по умолчанию находятся все сервисы одного `docker-compose` файла? >> В одной общей автоматически созданной user-defined bridge-сети
9. При использовании `docker-compose` , к сервису `api` можно обратиться по адресу? >> `api` – по имени сервиса как hostname
10. Как называется режим Docker, обеспечивающий полную сетевую изоляцию? >> `none` ; контейнер не имеет сетевых интерфейсов кроме loopback
11. Тип сети `none` – для чего используется? >> Полная сетевая изоляция; например, для batch-задач, которым сеть не нужна
12. Команда для просмотра всех сетей Docker? >> `docker network ls`
13. К какому типу сети относится сеть, создаваемая `docker-compose` по умолчанию? >> User-defined bridge; именно поэтому сервисы сразу общаются по именам без дополнительной настройки
14. Почему рекомендуется создавать пользовательские bridge-сети вместо использования дефолтной? >> В user-defined bridge работает DNS по именам контейнеров, лучше изоляция и контроль над тем, какие контейнеры видят друг друга
15. Что происходит с сетевой изоляцией при режиме `host` ? >> Изоляция отсутствует; контейнер разделяет сетевой стек с хостом; работает только на Linux (на macOS/Windows с Docker Desktop не поддерживается)
16. Тип сети `bridge` – для чего используется? >> Связь контейнеров на одном хосте; стандартный выбор для большинства задач
17. Какая команда создаёт новую пользовательскую сеть? >> `docker network create my-network`
18. Какое основное преимущество даёт тип сети `host` ? >> Максимальная производительность: нет трансляции портов и сетевого overhead; контейнер использует порты хоста напрямую
19. Как настроено сетевое взаимодействие контейнеров Docker по умолчанию? >> Контейнеры изолированы друг от друга; для связи необходимо явно подключить их к одной сети
20. Команда для просмотра детальной информации о сети? >> `docker network inspect my-network`
21. Как называется тип сети Docker, используемый по умолчанию? >> `bridge` (конкретнее – дефолтная сеть с именем `bridge` , создаваемая автоматически)
22. С помощью какого флага в `docker run` контейнер подключается к определённой сети? >> `--network` : `docker run --network my-network myapp`
23. Что позволяет контейнерам в user-defined bridge-сети общаться по имени, а не по IP? >> Встроенный DNS-сервер Docker, автоматически доступный во всех пользовательских сетях
24. Тип сети `host` – для чего используется? >> Когда нужна максимальная сетевая производительность и изоляция не требуется; только Linux
25. Команда для удаления сети? >> `docker network rm my-network`
26. Какой механизм в Docker позволяет контейнерам устанавливать связь друг с другом? >> Сети (Networks)
27. Что представляет собой сеть типа `bridge` в Docker? >> Виртуальный коммутатор на хосте (интерфейс `docker0` на Linux); контейнеры подключаются к нему через виртуальные сетевые пары (veth)
