1. Какой формат адреса у реестра AWS ECR? >> `123456789.dkr.ecr.eu-west-1.amazonaws.com`
2. Какой хост используется в тегах для GHCR? >> `ghcr.io`
3. Для чего используется `docker tag` перед отправкой образа в реестр? >> Для присвоения образу имени с путём к целевому реестру или именем пользователя
4. Команда для отправки образа `myusername/myapp:1.0` в Docker Hub? >> `docker push myusername/myapp:1.0`
5. Является ли Nexus реестром только для Docker-образов? >> Нет, Nexus – универсальный менеджер артефактов: поддерживает Maven, npm, Docker и другие форматы
6. Команда для скачивания `python:3.11-slim` ? >> `docker pull python:3.11-slim`
7. Почему `latest` считается плохой практикой в production? >> Содержимое образа под этим тегом может смениться; Docker кэширует образ и может не подтянуть обновление без явного `docker pull`
8. Как называется реестр контейнеров GitHub? >> GitHub Container Registry (GHCR)
9. Команда для тегирования `myapp` для организации `myorg` в GHCR с версией `1.0` ? >> `docker tag myapp ghcr.io/myorg/myapp:1.0`
10. Какая команда создаёт ссылку на образ для другого реестра? >> `docker tag`
11. Что на самом деле означает тег `latest` ? >> Это тег по умолчанию, не обязательно самая свежая версия; автор образа сам решает, что тегировать как `latest`
12. Что обозначает тег `myapp:1.2` ? >> Минорную версию; обычно обновляется при выходе патча ( `1.2.1` ), указывая на последний патч внутри минора
13. Какая команда выполняет авторизацию в реестре? >> `docker login` – без адреса авторизует на Docker Hub; с адресом – на указанном реестре
14. Какая команда авторизует в приватном реестре `registry.example.com` ? >> `docker login registry.example.com`
15. Что такое image digest и чем он точнее тега? >> `sha256` -хэш содержимого образа: `myapp@sha256:abc...` ; в отличие от тега, digest неизменяем и однозначно идентифицирует конкретный образ
16. Какую платформу для хранения кода приводят как аналог реестра Docker-образов? >> GitHub
17. Что означает слово `slim` в теге образа? >> Версию с уменьшенным размером за счёт исключения лишних пакетов
18. Для чего в production используются приватные реестры? >> Для хранения внутренних образов без публичного доступа; часть корпоративной инфраструктуры
19. Какую утилиту используют для получения пароля авторизации в AWS ECR? >> `aws ecr get-login-password`
20. Что означает `docker pull myusername/myapp:1.0` ? >> Скачать образ `myapp` версии `1.0` пользователя `myusername` с Docker Hub
21. Что рекомендуется использовать в production вместо тега `latest` ? >> Конкретный тег версии ( `1.2.3` ) или хэш коммита ( `git-abc1234` )
22. Команда для отправки образа в GHCR? >> `docker push ghcr.io/myorg/myapp:1.0`
23. Что обозначает тег `myapp:stable` ? >> Стабильную версию образа
24. Верно ли, что `docker pull` работает только с публичными образами? >> Нет; после `docker login` можно скачивать и приватные образы
25. Команда для скачивания образа `nginx:latest` ? >> `docker pull nginx:latest`
26. Если в `docker pull` не указан тег (например, `docker pull nginx` ), какой тег будет использован? >> `latest`
27. Какой регион указан в адресе `123456789.dkr.ecr.eu-west-1.amazonaws.com` ? >> `eu-west-1`
28. Можно ли использовать `docker login` без указания адреса сервера? >> Да, в этом случае авторизация произойдёт на Docker Hub
29. Какое соглашение об именовании тегов лучше всего подходит для автоматизации в CI/CD? >> Хэш коммита ( `git-abc1234` ): образ однозначно привязан к конкретному коммиту в репозитории
30. Какой реестр образов используется в Docker по умолчанию? >> Docker Hub
31. Для чего используется тег `myapp:1.2.3` ? >> Для точной фиксации версии; рекомендуемый подход в production
32. Как Docker понимает, что образ нужно искать в `ghcr.io` , а не в Docker Hub? >> По префиксу адреса реестра в имени образа
33. Откуда будет скачан образ при `docker pull python:3.11` ? >> Из Docker Hub – публичного реестра по умолчанию
34. Как выглядит формат именования образа для Docker Hub? >> `myusername/myapp:1.0`
35. Что произойдёт, если запустить `docker push` для образа без имени пользователя или адреса реестра? >> Docker попытается отправить его в официальную библиотеку Docker Hub, что без прав невозможно
36. Как пароль от AWS ECR передаётся в `docker login` ? >> Через пайп с флагом `--password-stdin` : `aws ecr get-login-password | docker login --username AWS --password-stdin <адрес>`
37. Что передаётся через пайп в `docker login --username AWS --password-stdin` ? >> Пароль, сгенерированный AWS CLI командой `aws ecr get-login-password`
38. Для чего используется именование тегов по хэшу коммита ( `myapp:git-abc1234` )? >> В CI/CD для точного соответствия образа исходному коду и воспроизводимости сборок
39. Как называется хранилище для Docker-образов? >> Реестр (Registry)
40. Назовите три реестра помимо Docker Hub, GHCR и AWS ECR? >> GitLab Registry, Yandex Container Registry, Nexus
