1. В чём главное отличие Bind Mounts от Named Volumes? >> Bind Mounts зависят от конкретного пути на хосте; Named Volumes управляются Docker и переносимы между окружениями
2. К какому типу относится монтирование `- postgres_data:/var/lib/postgresql/data` ? >> Named Volume
3. Куда монтируются данные при tmpfs? >> В оперативную память хоста (RAM); на диск данные не записываются
4. Для каких данных целесообразно использовать tmpfs? >> Временные данные, чувствительные к скорости: сессии, кэш, секреты, которые не должны попасть на диск
5. В какой директории хоста по умолчанию хранятся Named Volumes на Linux? >> `/var/lib/docker/volumes/` ; на macOS и Windows с Docker Desktop – внутри скрытой Linux VM
6. Команда для создания нового тома `my-data` ? >> `docker volume create my-data`
7. Какая команда удаляет все неиспользуемые тома? >> `docker volume prune`
8. Какая подкоманда `docker volume` позволяет убедиться в существовании тома? >> `docker volume ls` – если том есть, он появится в списке
9. Что представляет собой Bind Mount? >> Монтирование конкретной директории или файла с хост-машины в контейнер
10. Как в `docker-compose.yml` подключить named volume `postgres_data` к сервису `db` ? >> В секции `volumes` сервиса: `- postgres_data:/var/lib/postgresql/data` ; сам том объявляется в корневом разделе `volumes:`
11. Что такое `--mount` синтаксис и чем он отличается от `-v` ? >> Более явный и читаемый способ задать монтирование: `--mount type=volume,source=my-data,target=/app/data` ; рекомендуется в production-скриптах за счёт отсутствия неоднозначности
12. К какому типу относится монтирование `- .:/app` ? >> Bind Mount
13. Что происходит с данными в write-слое контейнера при его удалении? >> Данные в write-слое теряются; данные в подключённых томах (volumes) сохраняются
14. Как использовать named volume `my-data` при запуске контейнера? >> `docker run -v my-data:/app/data myapp`
15. В команде `docker run -v /home/user/code:/app myapp` , что является путём на хосте? >> `/home/user/code` (левая часть от двоеточия)
16. Как добавить том только для чтения при `docker run` ? >> Добавить `:ro` в конец пути: `docker run -v my-data:/app/data:ro myapp`
17. Команда для запуска контейнера с монтированием `/tmp` в память? >> `docker run --tmpfs /tmp myapp`
18. Команда для просмотра всех существующих томов Docker? >> `docker volume ls`
19. Что происходит с данными в tmpfs при остановке контейнера? >> Данные теряются – tmpfs существует только в RAM
20. Где в `docker-compose.yml` объявляются именованные тома? >> В корневом блоке `volumes:` – на одном уровне с `services:`
21. Как называется механизм в Docker для сохранения данных между перезапусками? >> Volumes (тома)
22. Как предотвратить перезапись `node_modules` внутри контейнера при bind mount всего проекта? >> Добавить анонимный том для `/app/node_modules` – Docker сохранит содержимое этой директории из образа, не затрагивая bind mount
23. Почему Bind Mounts идеальны для разработки? >> Изменения файлов на хосте мгновенно отражаются в контейнере без пересборки образа
24. Если в `docker-compose` под `volumes` указано только `/app/node_modules` , какой это тип тома? >> Анонимный том (anonymous volume) – Docker генерирует ему случайный ID
25. Обязательно ли указывать абсолютный путь в Bind Mount при `docker run` ? >> Да; относительные пути не поддерживаются в `docker run` , используют `$(pwd):/app` ; в `docker-compose` относительные пути ( `.:/app` ) допустимы
26. Какой тип монтирования НЕ сохраняет данные на диске? >> tmpfs
27. Какая сущность управляет Named Volumes? >> Docker; пользователь не управляет путём хранения напрямую
28. Какой тип монтирования рекомендуется для данных в production? >> Named Volumes: Docker управляет расположением, данные не зависят от файловой структуры хоста
29. Для чего используется запись `- /app/node_modules` без источника в `docker-compose` ? >> Создаёт анонимный том для `node_modules` внутри контейнера, предотвращая перезапись содержимого контейнера локальной папкой при bind mount всего проекта
30. В команде `docker run -v /home/user/code:/app myapp` , что является путём внутри контейнера? >> `/app` (правая часть от двоеточия)
31. Назовите три основных типа монтирования в Docker? >> Named Volumes, Bind Mounts и tmpfs
32. Что означает запись `- .:/app` в `docker-compose.yml` ? >> Bind Mount текущей директории в `/app` контейнера; `.` – относительный путь к директории с `docker-compose.yml`
33. Команда для удаления конкретного тома `my-data` ? >> `docker volume rm my-data` ; том должен быть не используемым ни одним контейнером
34. Как получить подробную информацию о томе `my-data` ? >> `docker volume inspect my-data` – выводит JSON с путём на хосте, датой создания и опциями
35. Что произойдёт с данными в Named Volume при удалении контейнера? >> Данные сохранятся в томе; том продолжает существовать независимо от контейнера
36. Какую переменную можно использовать в флаге `-v` для монтирования текущей директории? >> `$(pwd)` : `docker run -v $(pwd):/app myapp`
