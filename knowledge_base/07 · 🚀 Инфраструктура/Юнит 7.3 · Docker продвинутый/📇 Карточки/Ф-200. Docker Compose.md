1. Какая утилита PostgreSQL используется в `healthcheck` для проверки доступности БД? >> `pg_isready`
2. Что определяет параметр `retries` в блоке `healthcheck` ? >> Количество неудачных попыток подряд, после которых контейнер признаётся `unhealthy`
3. Какая команда останавливает и удаляет контейнеры? >> `docker-compose down`
4. Как запустить с пересборкой образов? >> `docker-compose up -d --build`
5. Какая инструкция в сервисе переопределяет стандартную команду запуска контейнера? >> `command`
6. Какой флаг `docker-compose down` удаляет и тома вместе с контейнерами? >> `-v` ( `--volumes` )
7. Какая запись в `volumes` создаёт bind mount текущей директории в `/app` ? >> `.:/app`
8. В каком разделе сервиса указывается принадлежность к виртуальной сети? >> `networks`
9. Как перезапустить конкретный сервис без остановки всего проекта? >> `docker-compose restart <service_name>`
10. Для чего используется переменная `POSTGRES_DB` ? >> Для задания имени базы данных, создаваемой при первом запуске контейнера
11. В чём ограничение `depends_on` без `condition: service_healthy` ? >> Он только ждёт запуска контейнера (статус started), но не гарантирует готовность приложения внутри; БД может ещё не принимать соединения
12. Какая команда принудительно пересобирает образы? >> `docker-compose build`
13. Какой параметр определяет порядок запуска сервисов? >> `depends_on`
14. В чём разница между `docker-compose` и `docker compose` ? >> `docker-compose` – отдельный бинарник v1 (Python); `docker compose` – встроенный плагин v2 (Go), рекомендуемый в современных версиях Docker
15. В каком глобальном разделе YAML описываются общие настройки сетей? >> `networks` на верхнем уровне, вне `services`
16. Какой раздел в конфигурации сервиса описывает проверку готовности? >> `healthcheck`
17. Какая инструкция в блоке сервиса указывает собрать образ из текущей директории? >> `build: .`
18. Какая команда healthcheck используется для проверки PostgreSQL в примере? >> `["CMD-SHELL", "pg_isready -U user -d mydb"]`
19. Как запустить в фоне только один сервис `web` ? >> `docker-compose up -d web`
20. Какой ключ позволяет загружать переменные окружения из внешнего файла? >> `env_file`
21. Что произойдёт при `docker-compose down` без флага `-v` ? >> Контейнеры удалятся, именованные тома сохранятся
22. Для чего в YAML используется `-` перед элементами портов или сетей? >> Для обозначения элемента списка (array item)
23. Что определяет параметр `timeout` в блоке `healthcheck` ? >> Максимальное время ожидания ответа на одну проверку
24. Как увидеть текущий статус и порты запущенных сервисов? >> `docker-compose ps`
25. Что определяет параметр `interval` в блоке `healthcheck` ? >> Интервал между повторными проверками (например, `interval: 10s` )
26. Что означает статус `healthy` в контексте Docker Compose? >> Контейнер успешно прошёл все проверки, описанные в `healthcheck`
27. Какая переменная окружения передаёт URL подключения к БД сервису `web` ? >> `DATABASE_URL`
28. Какое условие в `depends_on` заставляет сервис ждать прохождения healthcheck? >> `condition: service_healthy`
29. Как называется стандартный драйвер для пользовательских сетей в Compose? >> `bridge`
30. Как войти в bash работающего сервиса `web` ? >> `docker-compose exec web bash`
31. В каком глобальном разделе YAML объявляются именованные тома? >> `volumes` на верхнем уровне, вне `services`
32. Как называется тип тома, когда вместо пути на хосте указывается имя (например, `static_files` )? >> Именованный том (named volume)
33. Как в Compose называется механизм автоматического перезапуска упавшего контейнера? >> `restart` policy; значения: `no` , `always` , `on-failure` , `unless-stopped`
34. Какая команда выводит логи сервиса `web` в реальном времени? >> `docker-compose logs -f web`
35. Какой формат файла используется для конфигурации Docker Compose? >> YAML
36. Какое условие в `depends_on` используется по умолчанию? >> `condition: service_started` – контейнер запущен, но приложение может быть ещё не готово
37. Какая команда запускает все сервисы в фоновом режиме? >> `docker-compose up -d` (или `docker compose up -d` в v2)
38. В каком разделе YAML-файла описываются контейнеры приложения? >> `services`
39. Какая сетевая конфигурация позволяет сервисам `web` и `db` общаться по именам? >> Общая user-defined bridge-сеть в разделе `networks`
40. Какая политика перезапуска поднимает контейнер автоматически, если он не был остановлен вручную? >> `unless-stopped`
41. Как в Docker Compose описывается проброс порта 8000 хоста на порт 8000 контейнера? >> `"8000:8000"` в разделе `ports`
42. В каком разделе сервиса перечисляются переменные окружения в формате `КЛЮЧ=ЗНАЧЕНИЕ` ? >> `environment`
43. Какой ключ верхнего уровня указывает версию формата Compose? >> `version` ; в современном Compose v2 ( `docker compose` ) этот ключ устарел и игнорируется – его можно не указывать
44. Как называется инструмент для запуска многоконтейнерных приложений через YAML-файл? >> Docker Compose
45. Для чего используется переменная `POSTGRES_PASSWORD` ? >> Для установки пароля суперпользователя базы данных
46. Зачем в сервисе `celery` указана зависимость от `db` и `redis` ? >> Чтобы гарантировать запуск базы данных и брокера до старта воркера
47. Каким образом в Docker Compose реализуется изоляция групп контейнеров? >> Разделением на разные виртуальные сети ( `networks` ): сервисы видят только те, что в одной с ними сети
48. Какая инструкция используется для указания готового образа вместо сборки? >> `image` : например, `image: redis:7-alpine`
49. Какой путь используется для хранения данных PostgreSQL внутри контейнера? >> `/var/lib/postgresql/data`
