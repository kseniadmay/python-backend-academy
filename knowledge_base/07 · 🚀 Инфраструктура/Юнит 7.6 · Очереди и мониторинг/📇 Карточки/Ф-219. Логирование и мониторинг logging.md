1. Для чего используется уровень `DEBUG` ? >> Детальная отладочная информация; в production обычно отключён
2. Перечислите уровни логирования Python в порядке возрастания важности >> `DEBUG` → `INFO` → `WARNING` → `ERROR` → `CRITICAL`
3. Что делает `log.bind()` в `structlog` ? >> Привязывает данные к логгеру; все последующие вызовы автоматически включают эти поля – удобно для request_id или user_id
4. Какой метод рекомендуется для сложной конфигурации логирования? >> `logging.config.dictConfig(config_dict)`
5. Для чего используется уровень `WARNING` ? >> Произошло что-то неожиданное, но приложение продолжает работать: «Кэш недоступен»
6. Какая библиотека популярна для структурированного логирования в Python? >> `structlog`
7. Какое преимущество даёт `logging` перед `print()` ? >> Поддержка уровней важности, гибкое форматирование, несколько обработчиков и конфигурирование без изменения кода приложения
8. Где располагается настройка логирования в Django-проекте? >> В `settings.py` в переменной `LOGGING` (словарь в формате `dictConfig` )
9. Как называется стандартная библиотека Python для ведения логов? >> `logging`
10. В чём преимущество использования `__name__` при инициализации логгера? >> Имя логгера отражает полный путь модуля (например, `myapp.users.service` ), что позволяет точно определить источник сообщения
11. Как правильно передавать переменные в логгер? >> `logger.info("Создан заказ order_id=%s", order_id)`
12. Как динамически задать уровень логирования из переменной окружения? >> `level = os.getenv("LOG_LEVEL", "INFO")` ; затем `logging.basicConfig(level=level)` или передать в `dictConfig`
13. Что такое контекст в сообщении лога? >> Дополнительные данные (user_id, request_id, order_id), передаваемые в каждом сообщении для облегчения трассировки и поиска
14. Для чего в `dictConfig` используется `'disable_existing_loggers': False` ? >> Предотвращает отключение логгеров, созданных до применения конфигурации; без этого сторонние библиотеки могут перестать логировать
15. Для чего используется уровень `ERROR` ? >> Серьёзная проблема, из-за которой конкретная операция не может быть выполнена
16. Для чего используется уровень `INFO` ? >> Подтверждение штатной работы: «Пользователь создан», «Сервер запущен»
17. Почему структурированное логирование важно для production? >> Логи в JSON легко парсятся системами сбора (ELK, Loki, Datadog); по ним удобно строить запросы и алерты
18. Как рекомендуется получать экземпляр логгера внутри модуля? >> `logger = logging.getLogger(__name__)` ; `__name__` автоматически задаёт имя модуля и встраивает логгер в иерархию
19. За что отвечает секция `handlers` в конфигурации логирования Django? >> Определяет обработчики – способы вывода логов: в консоль ( `StreamHandler` ), файл ( `FileHandler` ), внешний сервис
20. Для чего используется уровень `CRITICAL` ? >> Фатальная ошибка, при которой работа всего приложения может быть невозможна
21. Чем `logger.exception()` отличается от `logger.error(exc_info=True)` ? >> Ничем по результату; `exception()` – удобная обёртка, которая всегда добавляет traceback; должна вызываться только внутри блока `except`
22. Почему при логировании рекомендуется передавать аргументы через запятую, а не через f-строки? >> Строка не форматируется, если уровень сообщения ниже текущего порога; `logger.info("id=%s", user_id)` эффективнее `logger.info(f"id={user_id}")`
23. В чём суть контекстного логгера? >> Общие данные (например, `request_id` ) привязываются к логгеру один раз через `bind()` ; не нужно передавать их в каждом вызове
24. Что произойдёт, если вызвать `logger.debug()` , а минимальный уровень установлен в `INFO` ? >> Сообщение будет проигнорировано и не попадёт в вывод; форматирование строки при этом тоже не произойдёт
25. Как включить traceback в запись лога при обработке исключения? >> `logger.error("Ошибка", exc_info=True)` или `logger.exception("Ошибка")` – второй вариант автоматически добавляет `exc_info=True`
26. Если для логгера `myapp` установлен уровень `DEBUG` , а в `root` – `WARNING` , какой уровень будет у `myapp` ? >> `DEBUG` ; настройки конкретного логгера имеют приоритет над корневыми
27. Для чего используется `'propagate': False` в настройках логгера Django? >> Предотвращает передачу сообщений вверх по иерархии к родительским обработчикам; без этого сообщения могут дублироваться
