1. Что такое контейнер с точки зрения операционной системы? >> Изолированный процесс, использующий ядро хостовой ОС
2. Как называется компонент, стоящий между физическим железом и Guest OS в стеке VM? >> Гипервизор
3. Какая технология позволяет достичь большей плотности приложений на одном сервере? >> Контейнеризация
4. Опишите стек слоёв Docker-контейнера? >> Физический сервер → Host OS (Linux kernel) → Docker Engine (containerd / runc) → Контейнер (приложение + библиотеки)
5. Что представляет собой виртуальная машина с точки зрения работы с ресурсами? >> Среду с аппаратной виртуализацией: гипервизор предоставляет каждой VM изолированное виртуальное железо через механизмы Intel VT-x / AMD-V; «полная программная эмуляция» – это отдельный, значительно более медленный режим
6. Эмулирует ли контейнер аппаратное обеспечение? >> Нет, контейнер не эмулирует железо и не запускает собственное ядро ОС
7. Как соотносится время старта VM и контейнеров? >> VM стартуют минуты (загрузка Guest OS); контейнеры – секунды (запуск процесса в уже работающем ядре)
8. Может ли контейнер на Linux-хосте нативно запустить приложение для Windows? >> Нет: контейнер использует системные вызовы ядра хоста, а Windows-приложения требуют Windows kernel
9. В чём разница между гипервизором Type 1 и Type 2? >> Type 1 (bare-metal) работает напрямую на железе без Host OS: VMware ESXi, KVM, Hyper-V; Type 2 (hosted) работает поверх Host OS: VirtualBox, VMware Workstation
10. Какое ПО управляет несколькими VM на одном физическом сервере? >> Гипервизор
11. За какое время обычно стартует контейнер? >> За секунды, иногда миллисекунды
12. Для каких задач лучше всего подходят контейнеры? >> Микросервисы, CI/CD-пайплайны, высокая плотность размещения приложений на одном хосте
13. Что управляет распределением ресурсов между несколькими VM на одном физическом хосте? >> Гипервизор
14. Через какой Linux-механизм реализуется изоляция ресурсов контейнера? >> `namespaces` (пространства имён): `pid` , `net` , `mnt` , `uts` , `ipc` , `user`
15. Каков типичный объём оперативной памяти, требуемый для одной VM? >> 2–4 ГБ RAM
16. Правда ли, что контейнер содержит собственное ядро ОС? >> Нет, он разделяет ядро хостовой ОС со всеми остальными контейнерами
17. Является ли Docker технологией эмуляции железа? >> Нет, Docker – технология контейнеризации процессов на базе `namespaces` и `cgroups` ядра Linux
18. Каков типичный размер контейнера (приложение + библиотеки)? >> 50–200 МБ
19. Что подразумевается под `shared kernel` в контексте контейнеров? >> Все контейнеры выполняют системные вызовы через одно общее ядро Linux хостовой ОС
20. Верно ли утверждение: «VM изолирует приложения на уровне процессов»? >> Нет, VM изолирует на уровне аппаратного обеспечения: каждая имеет собственное ядро и виртуальное железо
21. Какой тип изоляции обеспечивает VM? >> Полную: каждая VM имеет собственное ядро ОС и виртуальное железо
22. Какая технология требует больше дискового пространства? >> VM: 20+ ГБ против 50–200 МБ у контейнера
23. Почему контейнер стартует за секунды, а VM – за минуты? >> Контейнеру не нужно загружать собственную ОС: он запускает процесс в уже работающем ядре хоста
24. В чём преимущество контейнеров для CI/CD? >> Быстрый старт (секунды), малый размер образов и воспроизводимость окружения между средами
25. Почему у контейнеров минимальный overhead? >> Они не эмулируют железо и не запускают дополнительные копии ядра ОС – только изолированный процесс поверх существующего ядра
26. Для чего нужна изоляция сети через Network Namespace? >> Чтобы каждый контейнер имел собственный сетевой стек: интерфейсы, таблицы маршрутизации, порты
27. Опишите стек слоёв виртуальной машины? >> Физический сервер → Гипервизор → Guest OS (ядро + библиотеки) → Приложение
28. Какая технология лучше подходит для микросервисной архитектуры? >> Контейнеризация
29. Верно ли: `namespaces` обеспечивают изоляцию, `cgroups` – ограничение ресурсов? >> Да, это два ключевых Linux-механизма, на которых строится контейнеризация
30. У какой технологии выше накладные расходы (overhead)? >> У виртуальных машин: каждая несёт полную копию ядра ОС и виртуальное железо
31. Как соотносится потребление дискового пространства у VM и контейнеров? >> VM занимают десятки ГБ, контейнеры – десятки–сотни МБ
32. Какой тип изоляции обеспечивают контейнеры? >> Процессную: изолированный процесс в рамках общего ( `shared` ) ядра хостовой ОС
33. Какая технология изоляции считается более надёжной? >> Виртуальные машины: у каждой своё ядро, уязвимость в одной VM не компрометирует другие
34. Перечислите три примера гипервизоров? >> VMware ESXi, VirtualBox, KVM
35. Для чего в контейнеризации используются `cgroups` ? >> Для ограничения и учёта потребления ресурсов: CPU, RAM, дисковый I/O
36. Какие ОС можно запускать внутри VM? >> Любые, совместимые с архитектурой хоста: Linux, Windows, BSD и т.д.
37. Какая технология обеспечивает минимальный overhead? >> Контейнеризация: не требует отдельного ядра ОС и виртуального железа
38. На каком ядре нативно работают контейнеры? >> На ядре Linux; на macOS и Windows Docker Desktop запускает скрытую Linux VM, чтобы предоставить это ядро
39. Если на одном сервере нужно запустить одновременно Linux и Windows, что следует выбрать? >> Виртуальные машины
40. Как называется тип ОС, установленной внутри виртуальной машины? >> Guest OS (гостевая ОС)
41. Что включает в себя полный стек внутри VM? >> Ядро Guest OS, системные библиотеки и само приложение
42. Когда предпочтительнее VM вместо контейнеров? >> Когда нужна полная изоляция на уровне ядра, запуск разных ОС на одном хосте или работа с Windows-окружением
43. Содержит ли каждая виртуальная машина собственное ядро ОС? >> Да, каждая VM запускает полноценную Guest OS со своим ядром
44. Какое ПО выступает посредником между Host OS и контейнерами в стеке Docker? >> Docker Engine; под капотом – `containerd` как container runtime и `runc` как низкоуровневый исполнитель
45. Какую основную задачу решают и виртуальные машины, и контейнеры? >> Изоляцию приложений и их зависимостей от среды выполнения
46. Каков типичный объём дискового пространства, занимаемого одной VM? >> 20+ ГБ
