1. Как размер build context влияет на скорость сборки Docker-образа? >> Весь контекст передаётся daemon до начала сборки; большой контекст замедляет даже локальную сборку и особенно заметен в CI
2. Какие директории настроек IDE не нужны в Docker-образе? >> `.idea/` (JetBrains) и `.vscode/` (VS Code)
3. Какие расширения скомпилированных файлов Python должны быть в `.dockerignore` ? >> `*.pyc` , `*.pyo` , `*.pyd`
4. Какие типы файлов с секретами обязательно исключать через `.dockerignore` ? >> `.env` , `*.key` , директория `secrets/`
5. Почему файлы виртуального окружения (например, `venv/` ) не нужны в контексте сборки? >> Зависимости должны устанавливаться внутри контейнера через `pip install` ; локальный `venv` несовместим с окружением контейнера
6. Назовите директорию с кэшем байт-кода Python, которую следует исключить из сборки? >> `__pycache__/`
7. Нужно ли включать файл `.gitignore` в итоговый Docker-образ? >> Нет, он не требуется для работы приложения
8. С какой целью из продакшен-образа исключаются директории `tests/` и `docs/` ? >> Они не нужны для функционирования приложения и только увеличивают размер образа
9. Перечислите стандартные названия директорий виртуального окружения Python, которые стоит добавить в `.dockerignore` ? >> `venv/` , `.venv/` , `env/`
10. Почему важно исключать секреты из build context с помощью `.dockerignore` ? >> Файлы, попавшие в контекст, могут быть скопированы в слой образа инструкцией `COPY . .` , после чего останутся в истории слоёв даже при последующем удалении
11. Что такое build context в процессе сборки Docker-образа? >> Набор файлов, которые Docker CLI отправляет daemon перед выполнением инструкций Dockerfile; чем он меньше, тем быстрее передача и сборка
12. Почему файлы `*.log` рекомендуется добавлять в `.dockerignore` ? >> Локальные логи не нужны в образе и могут содержать чувствительные данные
13. Аналогом какого файла в Git является `.dockerignore` ? >> `.gitignore`
14. По какой причине директорию `.git/` следует исключать из build context? >> История Git не нужна для работы приложения и может значительно увеличить размер контекста
15. Как `.dockerignore` снижает риск утечки секретов? >> Предотвращает попадание файлов вроде `.env` в build context, откуда они могут быть скопированы в слои образа через `COPY . .`
16. Какую основную функцию выполняет файл `.dockerignore` ? >> Исключает файлы и директории из build context при сборке образа
17. В каком порядке Docker применяет правила `.dockerignore` ? >> Последовательно сверху вниз; более позднее правило имеет приоритет – можно исключить директорию, а затем явно включить отдельный файл из неё через `!`
18. Что происходит, если `.dockerignore` отсутствует в проекте? >> В build context попадают все файлы из директории сборки, включая `venv/` , `.git/` , `.env` и прочее лишнее
