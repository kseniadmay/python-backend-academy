1. Для чего используется команда `docker ps -a` ? >> Для просмотра всех контейнеров, включая остановленные
2. Каким основным свойством обладают слои Docker Image? >> Они неизменяемы (read-only)
3. Что такое Copy-on-Write (CoW) в контексте контейнеров? >> Механизм, при котором изменение файла из read-only слоя Image копирует его в write-слой контейнера, оставляя оригинал нетронутым
4. Как соотносится состояние разных контейнеров, запущенных из одного образа? >> У каждого контейнера своё независимое состояние (свой write-слой)
5. Какое свойство слоёв Docker обеспечивает их стабильность и безопасность? >> Неизменяемость (read-only статус): ни контейнер, ни пользователь не могут изменить слой образа напрямую
6. Что происходит со слоями образа при остановке контейнера? >> Они остаются неизменными – они всегда read-only
7. В чём основное отличие `docker ps` от `docker ps -a` ? >> `docker ps` показывает только запущенные контейнеры; `docker ps -a` – все, включая остановленные
8. Какой флаг в команде `docker ps` позволяет увидеть не только активные контейнеры? >> `-a` (all)
9. Что представляет собой Docker Image? >> Неизменяемый (read-only) шаблон, содержащий файловую систему, зависимости, конфигурацию и метаданные запуска: `CMD` , `ENTRYPOINT` , `ENV` и т.д.
10. Зависит ли вывод `docker images` от того, запущены ли сейчас контейнеры? >> Нет, команда показывает образы на диске независимо от состояния контейнеров
11. С какой целью Docker кэширует и переиспользует слои? >> Для ускорения сборки образов и экономии дискового пространства при хранении нескольких версий
12. Что такое Docker Layer? >> Часть структуры образа, созданная инструкцией `RUN` , `COPY` или `ADD` ; может кэшироваться и переиспользоваться между образами
13. Сколько контейнеров можно запустить из одного образа? >> Неограниченное количество; каждый получает собственный независимый write-слой
14. Где хранятся изменения, сделанные во время работы контейнера? >> В верхнем write-слое контейнера (container layer); при удалении контейнера они теряются
15. Откуда разные контейнеры одного образа читают основные данные? >> Из одних и тех же общих read-only слоёв Image
16. Какая структура позволяет Docker эффективно переиспользовать части образов? >> Слоистая (layered) структура с кэшированием read-only слоёв
17. Почему Docker-образы занимают меньше места при хранении нескольких версий приложения? >> Благодаря переиспользованию общих кэшированных read-only слоёв
18. Из каких двух компонентов состоит структура контейнера? >> Read-only слои Image + тонкий записываемый (write) слой поверх
19. С каким понятием из ООП сравнивается Docker Image? >> С классом
20. С каким понятием из ООП сравнивается Docker Container? >> С экземпляром класса (instance)
21. Для чего используется команда `docker ps` ? >> Для просмотра только запущенных в данный момент контейнеров
22. Является ли состояние контейнера общим для всех экземпляров одного образа? >> Нет, у каждого контейнера свой независимый write-слой
23. Для чего используется команда `docker images` ? >> Для вывода списка всех образов, доступных на диске локально
24. Можно ли изменить Image, работая внутри контейнера? >> Нет, изменения записываются только в write-слой контейнера через CoW; Image остаётся неизменным
25. Что такое Docker Container? >> Запущенный экземпляр Docker Image
26. Какая команда позволяет убедиться, что контейнер был создан, но завершил работу? >> `docker ps -a`
27. Как называется механизм, при котором Docker не пересобирает слой повторно, если он уже существует? >> Кэширование слоёв (layer caching)
28. В формуле `Container = Image + X` , что такое X? >> Container layer – тонкий read-write слой поверх read-only слоёв образа
29. Что происходит с данными в write-слое контейнера при его удалении? >> Данные теряются; read-only слои Image остаются нетронутыми
30. Какие инструкции Dockerfile создают новый слой в образе? >> Только `RUN` , `COPY` и `ADD` ; остальные – `ENV` , `EXPOSE` , `CMD` , `WORKDIR` и др. – добавляют метаданные без создания отдельного слоя
31. Если в Dockerfile 10 инструкций, из которых 3 это `RUN` / `COPY` / `ADD` , сколько слоёв будет в образе? >> 3 – слои создают только `RUN` , `COPY` и `ADD`
