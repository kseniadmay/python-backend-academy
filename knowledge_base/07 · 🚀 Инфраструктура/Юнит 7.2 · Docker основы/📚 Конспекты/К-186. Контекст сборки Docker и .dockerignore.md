## Чемодан, который вы отправляете на фабрику
Когда вы пишете команду `docker build -t myapp .`, точка `.` в конце — это **НЕ** «найди Dockerfile в текущей папке»!
Точка `.` — это **Контекст сборки (Build Context)**. Первым же шагом клиент Docker упаковывает **абсолютно все файлы и папки** внутри `.` в архив и пересылает их демону Docker (`dockerd`).

Если в вашей папке лежат локальное окружение `.venv` (500 МБ), история `.git` (300 МБ) и дампы базы данных, Docker будет копировать этот гигабайтный «чемодан» перед каждой сборкой!
Файл **`.dockerignore`** работает как фильтр перед упаковкой чемодана: всё, что в нём перечислено, даже не отправляется демону сборки.

```text
Без .dockerignore (контекст 850 МБ — сборка тормозит и сбрасывает кэш!):
[Папка проекта: src/ + .venv/ + .git/ + .env] ──850 MB──► [Docker Daemon]

С .dockerignore (контекст 120 КБ — мгновенный старт и защита секретов!):
[Папка проекта] ──► [Фильтр .dockerignore] ──только src/ (120 KB)──► [Docker Daemon]
```

## Опасности сборки без .dockerignore

Без файла `.dockerignore` инструкция `COPY . /app` переносит в образ весь локальный мусор:
- Файл `.env` с секретами и паролями становится доступен любому пользователю образа.
- Каталоги `.git` и `.pytest_cache` сбрасывают слой кэша сборки при каждом коммите или запуске тестов на хосте.
- Каталог `.venv` операционной системы хоста повреждает окружение Linux-контейнера.

| Риск сборки | Причина | Роль .dockerignore |
| :--- | :--- | :--- |
| **`Sending context: 1.2 GB`** | В архив попадают `.venv`, `.git` | Сжимает контекст сборки до килобайт |
| **Утечка секретов** | `COPY . .` переносит локальный `.env` | Исключает `.env*` из контекста |
| **Сброс кэша сборки** | Изменение `.pytest_cache` | Игнорирует кэши IDE и тестов |

## Правило гигиены контекста сборки

> **Junior vs Senior**:
> - **Junior**: Запускает `docker build .` без `.dockerignore` или случайно запускает сборку из домашней директории `~`, удивляясь, почему Docker 5 минут пишет ` transferring context: 14.5GB`.
> - **Senior**: Создаёт `.dockerignore` одновременно с `Dockerfile`, а в самом `Dockerfile` вместо слепого `COPY . .` копирует только нужные директории явно (`COPY ./src ./src`).

## Анализ экономии Build Context и защиты от утечек
Посчитаем на Python, насколько `.dockerignore` сжимает размер контекста сборки и какие угрозы безопасности предотвращает:

```python
def analyze_build_context(
    project_files: dict[str, int],
    dockerignore: set[str],
) -> dict:
    raw_kb = sum(project_files.values())
    sent_files = {
        f: sz
        for f, sz in project_files.items()

        # Исключаем тяжёлые локальные папки
        if f.split("/")[0] not in dockerignore
    }
    sent_kb = sum(sent_files.values())
    leaked_secrets = [
        f
        for f in sent_files

        # Контролируем утечку секретов в образ
        if f.startswith(".env")
    ]
    return {
        "raw_mb": round(raw_kb / 1024, 2),
        "filtered_kb": sent_kb,
        "saved_percent": (
            round(
                (1 - sent_kb / raw_kb) * 100,
                2,
            )
        ),
        "leaked_secrets": leaked_secrets,
    }

workspace = {
    ".git/pack": 320_000,
    ".venv/lib": 540_000,
    "__pycache__/app.pyc": 1_200,
    ".env": 4,
    "src/main.py": 45,
    "requirements.txt": 2,
}
ignore_set = {
    ".git",
    ".venv",
    "__pycache__",
    ".env",
}
print(
    'Без .dockerignore:',
    analyze_build_context(workspace, set()),
)
# >>> Без .dockerignore: {'raw_mb': 841.07, 'filtered_kb': 861251, 'saved_percent': 0.0, 'leaked_secrets': ['.env']}

print(
    'С   .dockerignore:',
    analyze_build_context(
        workspace,
        ignore_set,
    ),
)
# >>> С   .dockerignore: {'raw_mb': 841.07, 'filtered_kb': 47, 'saved_percent': 99.99, 'leaked_secrets': []}
```
