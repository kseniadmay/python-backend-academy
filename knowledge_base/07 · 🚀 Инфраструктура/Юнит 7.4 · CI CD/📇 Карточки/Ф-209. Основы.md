1. В чём основная цель CI? >> Быстро обнаруживать проблемы интеграции, пока они ещё небольшие и дешёвы в исправлении
2. Какие популярные инструменты используются для CI/CD? >> GitHub Actions, GitLab CI, Jenkins, CircleCI; выбор зависит от платформы и инфраструктуры
3. Какие проверки типично запускаются в CI-пайплайне? >> Линтер (проверка стиля и потенциальных ошибок), автотесты и сборка (build)
4. Что означает аббревиатура CD? >> Continuous Delivery (непрерывная доставка) или Continuous Deployment (непрерывное развёртывание); это разные практики
5. Чем Continuous Delivery отличается от Continuous Deployment? >> В Continuous Delivery код всегда готов к деплою, но деплой в продакшен инициируется вручную; в Continuous Deployment деплой происходит автоматически после прохождения всех проверок
6. Как происходит деплой в Continuous Deployment? >> Автоматически после успешного прохождения всех автоматических проверок; участие человека не требуется
7. В чём разница между CI и CD на уровне ответственности? >> CI отвечает за автоматическую проверку кода; CD – за автоматическую доставку проверенного кода в целевое окружение
8. Почему CI/CD повышает уверенность в коде? >> Нельзя смержить PR с «красными» (failed) тестами; каждое изменение проходит одинаковый набор проверок
9. Что такое «красные тесты» в контексте PR? >> Автоматические тесты, завершившиеся с ошибкой; блокируют merge до исправления
10. Какова типичная последовательность этапов с CI/CD? >> Push → автотесты → автосборка → автодеплой; цикл занимает минуты
11. Какова типичная последовательность этапов без CI/CD? >> Разработка → ручные тесты → ручная сборка → ручной деплой; цикл занимает дни или недели
12. Как частые небольшие релизы влияют на риски? >> Каждый релиз содержит мало изменений, поэтому проще найти причину ошибки и риск катастрофического сбоя минимален
13. Как часто разработчики интегрируют код при CI? >> Несколько раз в день; долгоживущие ветки – антипаттерн для CI
14. Что такое сборка (build) в контексте CI/CD? >> Процесс превращения исходного кода в готовый артефакт: Docker-образ, бинарник, пакет и т.д.
15. Что такое линтер в контексте CI? >> Инструмент автоматической проверки кода на соответствие стандартам оформления и наличие потенциальных ошибок (например, `flake8` , `ruff` для Python)
16. Какие два главных недостатка разработки без CI/CD? >> Много ручного труда и высокий риск человеческих ошибок на каждом этапе
17. Что такое CI (Continuous Integration)? >> Практика частой автоматической интеграции кода всех разработчиков в общую ветку; при каждом push запускаются автоматические проверки
18. Какое событие запускает автоматические проверки в CI? >> Push кода в репозиторий (или открытие/обновление PR)
19. Какую проблему устраняет стандартизация деплоев в CI/CD? >> Проблему «работает на моей машине»: деплой всегда выполняется одинаково в контролируемом окружении
