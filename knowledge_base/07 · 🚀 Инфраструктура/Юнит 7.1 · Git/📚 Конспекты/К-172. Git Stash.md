## Временный карман (stash): сохранение незакоммиченных правок
Представьте: вы разобрали на столе половину часов (код не дописан, тесты падают), и тут вбегает тимлид: «Срочно почини баг на проде в ветке `main`!». Делать сырой коммит `wip: broken` — плохая практика, а переключать ветку с конфликтующими изменениями Git не даст.
Команда **`git stash`** одним движением сгребает все незакоммиченные правки в выдвижной ящик (стек) и оставляет рабочий стол кристально чистым (как после последнего коммита).

```text
Работа с git stash:

Рабочая папка (wip)
  │
  ▼ git stash push -u -m "wip: cart"
Стек Stash [stash@{0}] (чистая папка)
  │
  ▼ чиним хотфикс в main
  │
  ▼ git stash pop
Правки снова в рабочей папке!
```

---
### Главные команды и скрытая ловушка новых файлов (`-u`)
По умолчанию `git stash` прячет только те файлы, о которых Git уже знает (tracked). Если вы создали новый файл `utils.py` и не сделали `git add`, обычный `git stash` оставит его на столе! Используйте флаг **`-u` (`--include-untracked`)**.

```bash
# Спрятать правки и untracked файлы:
git stash push -u \
  -m "feat: wip-валидация"

# Список всех ящиков в стеке:
git stash list

# Вернуть ящик и УДАЛИТЬ из стека:
git stash pop

# Применить ящик, ОСТАВИВ копию:
git stash apply stash@{1}
```

| Команда | Что делает с рабочей директорией | Удаляет ли запись из стека? | Что с новыми (`untracked`) файлами? |
| :--- | :--- | :--- | :--- |
| `git stash` | Прячет изменения tracked-файлов | Создаёт `stash@{0}` | Игнорирует (остаются в папке!) |
| `git stash push -u -m '...'` | Прячет всё, включая новые файлы | Создаёт `stash@{0}` с именем | Безопасно прячет в стек |
| `git stash pop` | Возвращает правки из `stash@{0}` | **Да** (если не было конфликта) | Восстанавливает |
| `git stash apply` | Возвращает правки из стека | **Нет** (хранит копию в стеке) | Восстанавливает |
| `git stash drop stash@{0}` | Не меняет рабочую папку | Удаляет выбранную запись | — |

## Практика использования stash при срочном переключении

Скрытие изменений (`git stash`) позволяет моментально очистить рабочее дерево для срочного хотфикса:

1. **Именованные карманы**: Всегда добавляйте осмысленное сообщение: `git stash push -m "wip: auth token caching"`.
2. **Контроль содержимого**: Просматривайте сохранённые изменения перед извлечением: `git stash show -p stash@{0}`.
3. **Безопасное применение**: Используйте `git stash apply` вместо `pop`, пока не убедитесь, что код успешно восстановился.

### LIFO-стек `git stash` с поддержкой неотслеживаемых файлов (`-u`)
Механика сохранения и восстановления рабочего дерева через стек:

```python
stash_stack: list[dict[str, str]] = []
working_tree = {"app.py": "v2 (modified)", "new.py": "untracked"}

# git stash push -u: сохраняем изменения и очищаем дерево
stash_stack.append(working_tree.copy())
working_tree = {"app.py": "v1 (clean)", "new.py": ""}

# git stash pop: восстанавливаем изменения из стека
restored = stash_stack.pop()
working_tree.update(restored)
print("Восстановленное рабочее дерево:", working_tree["app.py"])
```
