## Временный карман (`stash`) для незакоммиченных правок

Если код в рабочей папке ещё не готов к коммиту, а нужно срочно переключиться на хотфикс в `main`, делать сырой коммит `wip: broken` — плохая практика.

Команда **`git stash`** одним движением убирает незакоммиченные правки в отдельный стек и оставляет рабочее дерево чистым:

```text
Работа с git stash:

Рабочая папка (wip)
  │
  ▼ git stash push -u -m "wip: cart"
Стек Stash [stash@{0}] (чистая папка)
  │
  ▼ чиним хотфикс в main
  │
  ▼ git stash pop
Правки снова в рабочей папке!
```

## Скрытая ловушка новых файлов и флаг `-u`

По умолчанию `git stash` прячет только те файлы, которые Git уже отслеживает (*tracked*). Новые созданные файлы без `git add` останутся лежать в папке и не попадут в карман.

Чтобы сохранить вообще все правки вместе с новыми файлами, добавляйте флаг **`-u`** (`--include-untracked`):

```bash
# Спрятать правки и новые файлы
git stash push -u -m "feat: wip"

# Посмотреть список всех записей стека
git stash list

# Вернуть и удалить верхнюю запись
git stash pop

# Применить запись, оставив копию
git stash apply stash@{1}
```

## Справочник команд и режимов `git stash`

Поведение ключевых команд управления стеком карманов:

| Команда | Что делает с рабочей папкой | Удаляет из стека? | Новые (`untracked`) файлы |
| :--- | :--- | :--- | :--- |
| `git stash` | Прячет изменения tracked-файлов | Создаёт `stash@{0}` | Игнорирует (остаются в папке) |
| `git stash push -u -m '...'` | Прячет всё, включая новые файлы | Создаёт `stash@{0}` с именем | Безопасно прячет в стек |
| `git stash pop` | Возвращает правки из `stash@{0}` | **Да** (если без конфликтов) | Восстанавливает |
| `git stash apply` | Возвращает правки из стека | **Нет** (копия остаётся в стеке) | Восстанавливает |
| `git stash drop stash@{0}` | Не меняет рабочую папку | Удаляет выбранную запись | — |

## Безопасная практика работы со `stash` при хотфиксе

При срочном переключении между задачами помогают три привычки:

1. **Именованные карманы**: всегда добавляйте описание через `git stash push -m "wip: auth cache"`, чтобы не путаться в списке `stash@{N}`.
2. **Инспекция перед возвратом**: посмотрите содержимое кармана перед применением командой `git stash show -p stash@{0}`.
3. **Страховка через `apply`**: используйте `git stash apply` вместо `pop`, если не уверены, что правки лягут без конфликтов, и удаляйте запись только после проверки.

## Модель LIFO-стека `git stash` на Python

Смоделируем сохранение и восстановление рабочего дерева (включая новые файлы) по принципу стека LIFO:

```python
stash_stack: list[dict[str, str]] = []
working_tree = {
    'app.py': 'v2 (modified)',
    'new.py': 'untracked',
}

# git stash push -u сохраняет состояние
stash_stack.append(working_tree.copy())
working_tree = {
    'app.py': 'v1 (clean)',
    'new.py': '',
}

# git stash pop возвращает изменения
restored = stash_stack.pop()
working_tree.update(restored)

print('После pop:', working_tree['app.py'])
# >>> После pop: v2 (modified)
```

> **Junior vs Senior**:
> - **Junior**: складирует десятки безымянных стэшей, забывает флаг `-u` (теряя новые untracked-файлы в каталоге) и падает в конфликтах при `git stash pop`.
> - **Senior**: включает новые файлы через `git stash -u`, использует осмысленные сообщения `push -m` или временные WIP-ветки, а для параллельной работы над срочным фиксом предпочитает `git worktree`.
