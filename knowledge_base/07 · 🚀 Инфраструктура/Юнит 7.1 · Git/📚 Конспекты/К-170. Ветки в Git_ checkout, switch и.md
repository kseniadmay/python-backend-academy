## Указатель ветки в Git: легковесный файл-ссылка и `HEAD`

В Git **ветка (branch)** — это легковесный текстовый файл (41 байт), содержащий хеш одного конкретного коммита, а указатель **`HEAD`** ссылается на текущую активную ветку.

```text
История коммитов (граф DAG):

[c1: init] ◄── [c2: auth] ◄── [c3: main]
                   ▲
                   └── [c4: feat/login]
                            ▲
                           HEAD
```

Когда вы делаете новый коммит, Git создаёт снимок со ссылкой на родителя и передвигает указатель текущей ветки на 1 шаг вперёд.

---

## Разделение ответственности: `switch` и `restore`

До Git 2.23 команда `git checkout` была перегружена: она и переключала ветки, и отменяла правки в файлах, из-за чего разработчики случайно теряли код при совпадении имён ветки и файла.

В современном Git её разделили на две безопасные команды:

```bash
# Переключиться на существующую ветку
git switch main

# Создать ветку feat/oauth и перейти
git switch -c feat/oauth

# Вернуться на прошлую ветку
git switch -

# Отменить изменения в файле
git restore app/auth.py

# Убрать файл из индекса (git add)
git restore --staged app/db.py
```

## Сравнение команд `switch`, `restore` и устаревшей `checkout`

Сводная матрица перехода со старого синтаксиса на безопасные команды Git 2.23+:

| Задача | Старая команда (`checkout`) | Современная команда (`2.23+`) | Безопасность |
| :--- | :--- | :--- | :--- |
| Переключить ветку | `git checkout dev` | `git switch dev` | Не затрёт одноимённый файл |
| Создать ветку и перейти | `git checkout -b feat` | `git switch -c feat` | Чёткое намерение |
| Сбросить правки файла | `git checkout -- a.py` | `git restore a.py` | Явная работа с файлами |
| Оторвать HEAD на коммит | `git checkout a1b2c3d` | `git switch --detach a1b2c3d` | Требует явного `--detach` |

## Состояние `Detached HEAD` и защита правок

При навигации по веткам важно учитывать два механизма безопасности рабочей директории:

1. **Защита незакоммиченных данных**: если локальные правки конфликтуют с целевой веткой, `git switch <branch>` заблокирует переход и предложит сначала убрать их в `git stash`.
2. **Режим `Detached HEAD`**: при переходе на конкретный коммит (`git switch --detach <sha>`) указатель `HEAD` отрывается от веток; чтобы новые коммиты не потерялись сборщиком мусора, создайте ветку командой `git switch -c <new-branch>`.

## Симуляция графа коммитов, веток и `HEAD`

Смоделируем на Python устройство веток как словаря ссылок на коммиты:

```python
branches: dict[str, str] = {'main': 'c1'}
head: str = 'main'

# Создаём ветку feat/jwt от HEAD за O(1)
branches['feat/jwt'] = branches[head]
head = 'feat/jwt'

# Новый коммит c2 двигает только feat/jwt
branches[head] = 'c2'

print(f'HEAD -> {head} -> {branches[head]}')
# >>> HEAD -> feat/jwt -> c2

print('main осталась на:', branches['main'])
# >>> main осталась на: c1
```

> **Junior vs Senior**:
> - **Junior**: пользуется одним `git checkout` для всего подряд и при попадании в `Detached HEAD` вслепую переключается обратно, оставляя новые коммиты висячими.
> - **Senior**: разделяет `git switch` для переключения веток и `git restore` для отката файлов, понимает модель указателей `HEAD` и уверенно спасает коммиты из `Detached HEAD` новой веткой или через `reflog`.
