## Указатель ветки в Git: легковесный файл-ссылка, а не копия папки
Новички часто думают, что создание ветки в Git копирует все файлы проекта в новую папку. На самом деле **ветка (branch)** — это крошечный текстовый файл (41 байт), в котором записан хеш одного конкретного коммита (как стикер-закладка в книге). А указатель **`HEAD`** — это ваш «взгляд» сейчас: он показывает, на какой закладке вы находитесь.

```text
История коммитов (граф DAG):

[c1: init] ◄── [c2: auth] ◄── [c3: main]
                   ▲
                   └── [c4: feat/login]
                            ▲
                           HEAD
```

Когда вы делаете новый коммит, Git создаёт снимок с ссылкой на родителя и просто передвигает стикер текущей ветки на 1 шаг вперёд. Создание ветки занимает 0.001 секунды и почти 0 байт на диске!

### Почему `git checkout` разделили на `switch` и `restore`?
До Git 2.23 команда `git checkout` была перегружена: она и переключала ветки, и отменяла изменения в файлах (из-за чего разработчики случайно стирали свой код, если имя ветки совпадало с именем файла). Поэтому её разделили на две безопасные команды:

```bash
# Современный способ (Git 2.23+):
# Переключиться на существующую ветку main
git switch main
# Создать ветку feat/oauth и перейти:


# Вернуться на прошлую ветку:
git switch -

# Отмена изменений в файле:
# Вернуть файл к состоянию последнего коммита
git restore app/auth.py
# Убрать файл из индекса (git add):
git restore --staged app/db.py
```

| Задача | Старая команда (`checkout`) | Современная команда (`2.23+`) | Безопасность |
| :--- | :--- | :--- | :--- |
| Переключить ветку | `git checkout dev` | `git switch dev` | Не затрёт одноимённый файл |
| Создать ветку и перейти | `git checkout -b feat` | `git switch -c feat` | Чёткое намерение |
| Сбросить изменения файла | `git checkout -- a.py` | `git restore a.py` | Явная работа с файлами |
| Оторвать HEAD на коммит | `git checkout a1b2c3d` | `git switch --detach a1b2c3d` | Требует явного флага `--detach` |

## Переключение веток и безопасность рабочей директории

Команда `git switch` разработана для безопасной навигации по веткам без риска затереть локальные файлы:

1. **Изоляция ответственности**: `git switch` только переключает ветки (`git switch <branch>`) или создаёт новые (`git switch -c <new-branch>`), в отличие от перегруженной устаревшей команды `git checkout`.
2. **Защита незакоммиченных данных**: При наличии конфликтующих незафиксированных правок Git заблокирует переключение и предложит сохранить их в `git stash`.

### Живая проверка: симуляция графа коммитов, веток и `HEAD`
Запустим модель хранилища Git на Python и увидим, как `switch -c` и `commit` двигают указатели за $O(1)$:

```python
class MiniGitRepo:
    def __init__(self) -> None:
        c1 = {"msg": "init", "parent": None}
        self.commits = {"c1": c1}
        self.branches: dict[str, str] = {
            "main": "c1"
        }
        # Имя ветки или хеш коммита (detached)
        self.head: str = "main"

    def commit(
        self, cid: str, msg: str
    ) -> None:
        p = self.branches.get(self.head)
        parent = p or self.head
        self.commits[cid] = {
            "msg": msg, "parent": parent
        }
        if self.head in self.branches:
            self.branches[self.head] = cid

    def switch(
        self, branch: str,
        create: bool = False
    ) -> None:
        if create:
            cur = self.branches.get(self.head)
            current_commit = cur or self.head
            self.branches[branch] = (
                current_commit
            )
        self.head = branch

repo = MiniGitRepo()
repo.commit("c2", "feat: add user model")
repo.switch("feat/jwt", create=True)
repo.commit("c3", "feat: add jwt token")

print(f"HEAD указывает на ветку: {repo.head}")
m_c = repo.branches['main']
c_msg = repo.commits[m_c]['msg']
print(f"main -> {m_c} ({c_msg})")
f_c = repo.branches['feat/jwt']
j_msg = repo.commits[f_c]['msg']
print(f"feat -> {f_c} ({j_msg})")
```
