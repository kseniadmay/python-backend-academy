## Стандарт `src-layout` и анатомия Python-проекта

Если бизнес-логика, скрипты отладки и тестовые дампы лежат вперемешку в корне репозитория, проект становится хрупким и плохо поддерживается.

В промышленной разработке исходный код изолируют в каталоге **`src/`**, тесты выносят в **`tests/`**, конфигурацию собирают в **`pyproject.toml`**, а быстрый старт описывают в **`README.md`**:

```text
my-service/
├── pyproject.toml  # Зависимости и линтеры
├── README.md       # Запуск за 3 команды
├── .env.example    # Шаблон переменных
├── .gitignore      # Защита от мусора Git
├── Dockerfile      # Сборка контейнера
├── src/            # (src-layout) Пакет
│   └── billing/
│       ├── __init__.py
│       ├── api.py
│       └── services.py
└── tests/          # Зеркальные тесты
```

## Стандартизация конфигурации через `pyproject.toml`

В современном Python (PEP 518 и PEP 621) файл **`pyproject.toml`** заменяет старый зоопарк конфигов (`setup.py`, `.flake8`, `pytest.ini`) единым описанием пакета и инструментов:

```toml
[project]
name = 'billing-service'
version = '0.2.0'
requires-python = '>=3.12'
dependencies = [
  'fastapi>=0.115.0',
  'pydantic>=2.9.0',
  'sqlalchemy>=2.0.35',
]

[tool.ruff]
line-length = 100
target-version = 'py312'

[tool.pytest.ini_options]
pythonpath = ['src']
testpaths = ['tests']
```

## Назначение директорий и ключевых файлов

Чёткое разделение обязанностей каждого элемента корня упрощает онбординг и настройку CI/CD:

| Элемент репозитория | Назначение | Частый антипаттерн |
| :--- | :--- | :--- |
| **`pyproject.toml`** | Зависимости, сборка и настройки `ruff`/`pytest` | Разрозненные `setup.py`, `pytest.ini`, `.flake8` |
| **`src/<pkg>/`** | Изолированный пакет с исходным кодом | Свалка `.py`-файлов в корне репозитория |
| **`tests/`** | Зеркальная структура юнит- и API-тестов | Тестовые скрипты внутри бизнес-пакетов |
| **`.env.example`** | Шаблон обязательных переменных окружения | Коммит реального `.env` с секретами |
| **`README.md`** | Инструкция запуска за пару минут | Устаревший или пустой файл |

## Зачем нужен `src-layout` вместо плоской структуры

Вынесение кода в подпапку `src/<package_name>/` решает две практические проблемы сборки и тестирования:

1. **Защита от случайного импорта в `pytest`**: в плоском проекте при запуске из корня Python подмешивает текущую папку в `sys.path[0]`, поэтому тесты могут молча импортировать локальный каталог вместо реально установленного в окружении пакета.
2. **Чистая упаковка пакета**: сборщик гарантированно включает только код внутри `src/`, а корневые утилиты, миграции, конфиги и тестовые фикстуры не утекают в дистрибутив.

## Автоматический аудитор структуры репозитория

Напишем на Python простую проверку наличия обязательных компонентов стандартного бэкенд-репозитория:

```python
REQUIRED = {
    'README.md',
    '.gitignore',
    'pyproject.toml',
    'src',
    'tests',
}
repo_files = {
    'README.md',
    '.gitignore',
    'pyproject.toml',
    'src',
    'tests',
    'docs',
}

# Ищем недостающие элементы стандарта
missing = REQUIRED - repo_files
status = (
    'Соответствует стандарту'
    if not missing
    else f'Отсутствуют: {missing}'
)

print('Результат:', status)
# >>> Результат: Соответствует стандарту
```

## Переменные окружения (`.env`), `Makefile` и окружение

В продакшен-репозитории конфигурация строго отделена от кода (12-Factor App):

- **`.env` (в `.gitignore`) и `.env.example` (в Git):** секреты и параметры среды (`DATABASE_URL`, `DEBUG`, `ALLOWED_HOSTS`) никогда не хардкодят в `.py` и не коммитят в репозиторий.
- **Виртуальное окружение (`.venv`):** изолирует зависимости проекта (активация: `source .venv/bin/activate` на Linux/macOS или `.venv\Scripts\activate` на Windows).
- **`Makefile`:** фиксирует единые короткие команды для всей команды и CI (`make test`, `make lint`, `make run`), чтобы не запоминать длинные флаги `pytest` и `ruff`.

```makefile
lint:
	ruff check src tests

test:
	pytest -q
```

> **Junior vs Senior**:
> - **Junior**: Коммитит `.env` с паролем от БД и папку `.venv` в Git, а все модули и скрипты складывает в корень репозитория.
> - **Senior**: Использует `src-layout`, единый `pyproject.toml`, `.env.example` с `.gitignore`, стандартизирует запуск через `Makefile` и держит тесты зеркально в `tests/`.
