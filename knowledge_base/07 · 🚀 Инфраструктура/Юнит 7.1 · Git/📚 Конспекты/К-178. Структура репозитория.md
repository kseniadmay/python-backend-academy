## Архитектурный стандарт: src-layout, изоляция модулей и тесты
Когда технический лид открывает репозиторий кандидата на собеседовании, архитектурная зрелость считывается за первые 30 секунд. Если бизнес-логика, утилиты отладки и временные дампы (`script1.py`, `test_final2.py`, `db_copy.py`) свалены в корень без изоляции контекста, проект не пройдёт технический скрининг.
Промышленный Python-репозиторий следует единому стандарту: конфигурация сборки лежит в **`pyproject.toml`**, исходный код изолирован в пакете **`src/`** (или `app/`), тесты — в **`tests/`**, а инструкция по запуску за 60 секунд — в **`README.md`**.

```text
my-service/
├── pyproject.toml  # Зависимости и линтеры
├── README.md       # Запуск за 3 команды
├── .env.example    # Шаблон переменных
├── .gitignore      # Защита от мусора Git
├── Dockerfile      # Сборка контейнера
├── src/            # (src-layout) Пакет
│   └── billing/
│       ├── __init__.py
│       ├── api.py
│       └── services.py
└── tests/          # Зеркальные тесты
```

## Стандартизация конфигурации через pyproject.toml

В современном Python (PEP 518 и PEP 621) единым стандартом декларации зависимостей, метаданных и конфигурации инструментов (`ruff`, `pytest`, `mypy`) является файл **`pyproject.toml`**:

```toml
# Пример современного pyproject.toml:
[project]
name = "billing-service"
version = "0.2.0"
requires-python = ">=3.12"
dependencies = ["fastapi>=0.115.0", "pydantic>=2.9.0", "sqlalchemy>=2.0.35"]
[tool.ruff]
line-length = 100
target-version = "py312"
[tool.pytest.ini_options]
pythonpath = ["src"]
testpaths = ["tests"]
```

## Архитектура структуры репозитория: изоляция src/

| Элемент репозитория | Назначение | Антипаттерн |
| :--- | :--- | :--- |
| **`pyproject.toml`** | Единая конфигурация зависимостей и линтеров | Разрозненные `setup.py`, `pytest.ini`, `.flake8` |
| **`src/<pkg>/`** | Защита от случайного импорта из текущей директории | Свалка `.py`-файлов в корне репозитория |
| **`.env.example`** | Шаблон необходимых переменных окружения | Коммит реального `.env` с паролями |
| **`README.md`** | Быстрый старт проекта за 2 минуты | Отсутствие инструкции по запуску |

## Архитектурные стандарты репозитория бэкенда

Критерии качественного промышленного репозитория:

1. **Чистая компоновка `src-layout`**: Исходный код изолирован в `src/<package_name>/`, тесты вынесены в `tests/`, сборка описывается в `pyproject.toml`.
2. **Автоматизация и документация**: Наличие `Makefile` или `docker compose`, шаблона переменных окружения `.env.example`, тестов в CI и понятного `README.md` со схемой запуска.

### Автоматический аудитор структуры репозитория
Напишем на Python линтер структуры проекта, проверяющий соблюдение стандартов индустрии:

```python
REQUIRED_FILES = {
    "README.md",
    ".gitignore",
    "pyproject.toml",
    "src",
    "tests",
}
repo_files = {
    "README.md",
    ".gitignore",
    "pyproject.toml",
    "src",
    "tests",
    "docs",
}

# Разность множеств: ищем забытые файлы
missing = REQUIRED_FILES - repo_files
status = (
    "Соответствует стандарту"
    if not missing
    else f"Отсутствуют: {missing}"
)

print('Результат аудита:', status)
# >>> Результат аудита: Соответствует стандарту
print(
    'Все обязательные компоненты на месте:',
    len(missing) == 0,
)
# >>> Все обязательные компоненты на месте: True
```
