## Жизненный цикл изменений: четыре зоны Git

Процесс создания коммита в Git удобно представлять как последовательное перемещение кода между четырьмя зонами:

1. **Working Directory (Рабочая папка)** — файлы на диске, где вы пишете и редактируете код.
2. **Staging Area / Index (Индекс)** — черновик будущего коммита; команда `git add` переносит туда только выбранные правки.
3. **Local Repository (`.git`)** — локальная история коммитов; `git commit` навсегда фиксирует всё, что попало в индекс.
4. **Remote Repository (`origin`)** — удалённый сервер (GitHub/GitLab), куда история уходит через `git push`.

```text
Жизненный цикл изменений в Git:
[1. Working Dir]
  │
  ▼ git add <файл>
[2. Staging Area]
  │
  ▼ git commit -m "..."
[3. Local Repo (HEAD)]
  │
  ▼ git push origin <ветка>
[4. Remote Repo (GitHub/GitLab)]
```

## Частичная индексация (`git add -p`) и режимы `git reset`

Перед коммитом полезно отбирать только нужные фрагменты кода через `git add -p`, а при ошибке откатывать указатель ветки командой `git reset`:

```bash
# Отобрать нужные куски кода интерактивно
git add -p app/services.py

# Снять коммит, оставив правки в Staging
git reset --soft HEAD~1

# Снять коммит и индекс, оставив код на диске
git reset --mixed HEAD~1

# ОПАСНО: удалить коммит и все правки в папке
git reset --hard HEAD~1
```

---

## Три режима `git reset` и безопасный `git revert`

Судьба локальных файлов и индекса целиком зависит от выбранного флага отката:

| Команда | Local Repo (`HEAD`) | Staging Index | Working Directory | Безопасность |
| :--- | :--- | :--- | :--- | :--- |
| `git reset --soft HEAD~1` | Откатывается на 1 шаг | Сохраняет правки (`staged`) | Не трогает код | 100% безопасно |
| `git reset --mixed HEAD~1` | Откатывается на 1 шаг | Очищает индекс | Оставляет код на диске | 100% безопасно |
| `git reset --hard HEAD~1` | Откатывается на 1 шаг | Очищает индекс | **Стирает незакоммиченный код** | Потеря правок |
| `git revert HEAD` | Создаёт **новый** анти-коммит | Не трогает | Отменяет правки чисто | Идеально для `main` |

---

## Отмена изменений в публичной ветке: `revert` против `reset`

При откате уже сделанных коммитов критически важно, видели ли их другие разработчики:

1. **Публичная ветка (`main`)**: используйте строго **`git revert <sha>`** — он добавляет новый отменяющий коммит поверх истории, не ломая её у коллег.
2. **Локальная черновая ветка**: до `git push` допустим `git reset --soft HEAD~1` для пересборки коммитов, а `git reset --hard` применяйте только при осознанном удалении лишних правок.

## Машина состояний 4 зон Git на Python

Проследим на Python, как файл поэтапно переходит из рабочей директории в удалённый репозиторий:

```python
zones = {
    'working': 'draft',
    'staging': '',
    'local': '',
    'remote': '',
}

# Этап 1: git add app.py -> в индекс
zones['staging'] = zones['working']

# Этап 2: git commit -> в локальный архив
zones['local'] = zones['staging']

# Этап 3: git push -> на удалённый сервер
zones['remote'] = zones['local']

print('Staging:', zones['staging'])
# >>> Staging: draft

print('Remote :', zones['remote'])
# >>> Remote : draft
```
