## Исключения `.gitignore`: кэши, окружения и секреты

При работе Python-проекта на диске постоянно появляются служебные файлы: байткод `__pycache__/*.pyc`, виртуальное окружение `.venv/`, кэш `.pytest_cache/` и локальный `.env` с паролями.

Файл **`.gitignore`** задаёт правила для `git add`: всё, что попадает под его маски, остаётся в папке проекта, но никогда не попадёт в историю коммитов:

```text
Фильтрация через .gitignore:
Рабочая папка проекта:
├── src/app.py
│     │
│     ▼
│   [Охранник .gitignore] ──► ✅ В Git!
│
├── .env (секреты БД!)
│     │
│     ▼
│   [Правило: .env]       ──► 🛑 СТОП!
│
```

---

## Спасение закоммиченного файла: команда `git rm --cached`

Файл `.gitignore` действует только на неотслеживаемые (`untracked`) файлы. Если секрет или кэш уже был закоммичен в репозиторий, добавление строки в `.gitignore` не остановит его версионирование.

Чтобы удалить файл из индекса Git, сохранив его на локальном диске, применяется флаг `--cached`:

```bash
# Удалить .env из Git, оставив на диске
git rm --cached .env
git commit -m "chore: stop tracking .env"

# Проверить, какое правило скрывает файл
git check-ignore -v logs/keep.log
```

## Синтаксис шаблонов Globbing в `.gitignore`

Маски в `.gitignore` поддерживают каталоги, символы подстановки, привязку к корню и исключения через восклицательный знак `!`:

| Шаблон в `.gitignore` | Область действия | Пример совпадения |
| :--- | :--- | :--- |
| `__pycache__/` | Папка `__pycache__` на любом уровне | `src/api/__pycache__/` |
| `*.py[cod]` | Файлы `.pyc`, `.pyo`, `.pyd` | `models.cpython-313.pyc` |
| `/build/` | Папка `build` строго в корне репозитория | `/build/` (но не `src/build/`) |
| `.env*` + `!.env.example` | Все файлы `.env*`, кроме шаблона `.env.example` | Пропускает `.env.example` |

## Безопасность секретов и удаление скомпрометированных данных

Если конфиденциальные данные случайно попали в удалённый репозиторий, простого удаления файла недостаточно:

1. **Мгновенная ротация**: любой токен, пароль или API-ключ, утекший в Git, считается скомпрометированным — его нужно немедленно отозвать и перевыпустить у провайдера.
2. **Очистка истории**: удаление файла новым коммитом оставляет секрет в истории предыдущих коммитов, поэтому для вычищения всех следов используют инструмент `git-filter-repo`.

## Движок правил `.gitignore` с поддержкой отрицания `!`

Реализуем на Python простой обработчик масок с исключением через префикс `!` (как для `!.env.example`):

```python
import fnmatch

def is_ignored(
    path: str,
    rules: list[str],
) -> bool:
    ignored = False
    for r in rules:
        if (
            r.startswith('!')
            and fnmatch.fnmatch(path, r[1:])
        ):
            ignored = False
        elif fnmatch.fnmatch(path, r):
            ignored = True
    return ignored

rules = [
    '*.pyc',
    '__pycache__/*',
    '!important.pyc',
]

# Скрыт по маске *.pyc
print(
    'app.pyc:',
    is_ignored('app.pyc', rules),
)
# >>> app.pyc: True

# Разрешён правилом отрицания !
print(
    'imp.pyc:',
    is_ignored('important.pyc', rules),
)
# >>> imp.pyc: False
```
