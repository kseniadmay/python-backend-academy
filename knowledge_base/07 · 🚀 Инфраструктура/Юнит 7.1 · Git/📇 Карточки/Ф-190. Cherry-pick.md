1. Как именно `cherry-pick` переносит изменения? >> Вычисляет diff исходного коммита относительно его родителя и применяет этот патч к текущей ветке
2. Когда `cherry-pick` предпочтительнее `merge` ? >> Когда нужно перенести только выборочные изменения из ветки, не вливая всю её историю
3. Как применить диапазон коммитов от `abc1234` до `def5678` ? >> `git cherry-pick abc1234..def5678` ; нотация `..` исключает левый коммит; чтобы включить его, используют `abc1234^..def5678`
4. Что Git извлекает из коммита при `cherry-pick` ? >> Только diff (патч) – разницу между коммитом и его родителем; метаданные автора сохраняются, дата создания – новая
5. Каково основное назначение `git cherry-pick` ? >> Применить изменения конкретного коммита из любой ветки на текущую ветку, создав новый коммит
6. Куда попадают изменения после `git cherry-pick abc1234 --no-commit` ? >> В рабочую директорию и индекс (staged); новый коммит в истории не создаётся
7. Типичные сценарии использования `cherry-pick` ? >> Перенос hotfix из `main` в `release` -ветку; исправление ситуации «закоммитил не в ту ветку»; выборочный перенос одного фикса из feature-ветки
8. Как применить один коммит с хэшем `abc1234` ? >> `git cherry-pick abc1234` ; достаточно уникального префикса хэша, не обязательно полного
9. Остаётся ли исходный коммит в своей ветке после `cherry-pick` ? >> Да; `cherry-pick` копирует изменения, не перемещает коммит
10. Что делает флаг `--no-commit` в `git cherry-pick` ? >> Применяет изменения коммита в рабочую директорию и индекс (staging area), но не создаёт коммит автоматически – можно доработать перед фиксацией
11. На какую ветку `cherry-pick` добавляет изменения? >> На текущую активную ветку ( `HEAD` )
12. Что происходит с SHA коммита при `cherry-pick` ? >> Git создаёт новый объект коммита с новым SHA; исходный коммит остаётся нетронутым в своей ветке
13. Как применить два несвязанных коммита одной командой? >> `git cherry-pick abc1234 def5678` ; коммиты применяются последовательно в указанном порядке
14. Может ли `cherry-pick` вызвать конфликт? >> Да; если изменения конфликтуют с текущей веткой, Git останавливается и просит разрешить конфликт вручную, после чего продолжают через `git cherry-pick --continue`
15. Что делать, если в процессе `cherry-pick` возник конфликт и нужно отменить операцию? >> `git cherry-pick --abort` – откатывает состояние к моменту до начала `cherry-pick`
