1. Какие файлы и папки тестирования и покрытия кода обычно игнорируются? >> `.coverage` , `htmlcov/` , `.pytest_cache/`
2. Что означает флаг `--cached` в команде `git rm` ? >> Удалить файл из индекса (прекратить отслеживание), оставив его нетронутым на диске
3. Что означает `!` перед именем файла в `.gitignore` ? >> Исключение из правила игнорирования: Git будет отслеживать этот файл, даже если он подпадает под более ранний шаблон
4. Какой системный файл Windows для кэша эскизов стоит игнорировать? >> `Thumbs.db`
5. Как в `.gitignore` обозначается игнорирование папки `__pycache__` ? >> `__pycache__/`
6. Почему `.env` и `.env.local` должны быть в `.gitignore` ? >> Они содержат секреты (ключи API, пароли, DSN баз данных), которые нельзя публиковать в репозитории
7. В чём разница между `logs/` и `/logs/` в `.gitignore` ? >> `logs/` игнорирует папку с таким именем в любом месте репозитория; `/logs/` – только в корневом каталоге
8. Что игнорирует шаблон `*.py[cod]` ? >> Файлы байт-кода Python с расширениями `.pyc` , `.pyo` и `.pyd`
9. Можно ли разигнорировать конкретный файл внутри игнорируемой папки? >> Нет; если родительская директория игнорируется, правила `!` для файлов внутри неё не работают – это распространённая ловушка
10. Как игнорировать все `.log` -файлы во всём проекте? >> `*.log`
11. Как удалить файл `.env` из отслеживания Git, не удаляя его с диска? >> `git rm --cached .env` , затем закоммитить изменение и добавить `.env` в `.gitignore`
12. Что означает шаблон `logs/**/*.log` ? >> Игнорировать все `.log` -файлы внутри `logs/` и любых её поддиректорий на любой глубине
13. Какие папки настроек IDE стоит добавлять в `.gitignore` ? >> `.idea/` (JetBrains) и `.vscode/` (VS Code); они содержат локальные настройки, не актуальные для других участников
14. Какие имена папок виртуального окружения Python стоит добавлять в `.gitignore` ? >> `venv/` , `.venv/` , `env/`
15. Какие папки артефактов сборки Python обычно игнорируются? >> `dist/` и `build/`
16. Попадают ли файлы из `.gitignore` в индекс при `git add .` ? >> Нет; Git пропускает их при индексировании – они не становятся ни staged, ни tracked
17. Для чего используется запись `*.egg-info/` в `.gitignore` ? >> Для игнорирования метаданных пакета Python, генерируемых при установке через `pip` или `setup.py`
18. Какие инструменты помогают генерировать `.gitignore` для конкретного стека? >> `gitignore.io` (toptal) и готовые шаблоны в репозитории `github/gitignore`
19. Уберёт ли добавление файла в `.gitignore` его из отслеживания, если он уже закоммичен? >> Нет; `.gitignore` влияет только на untracked-файлы; уже отслеживаемый файл нужно удалить из индекса вручную
20. Как игнорировать папку `build` строго в корне репозитория? >> `/build/`
21. Что такое `*.swp` в контексте `.gitignore` ? >> Временные swap-файлы текстовых редакторов (например, Vim)
22. Какой системный файл macOS часто встречается в `.gitignore` ? >> `.DS_Store`
23. Каково основное назначение файла `.gitignore` ? >> Описывать файлы и директории, которые Git не должен отслеживать; подходящие файлы не попадают в индекс при `git add` и не появляются в `git status` как untracked
24. Как игнорировать все `.log` -файлы, кроме `important.log` ? >> Две строки: `*.log` , затем `!important.log` ; порядок важен – `!` должен стоять после общего правила
25. Как в `.gitignore` игнорировать все файлы с расширением `.key` ? >> `*.key`
26. Как рекурсивно удалить директорию `venv/` из индекса, не удаляя её физически? >> `git rm --cached -r venv/`
