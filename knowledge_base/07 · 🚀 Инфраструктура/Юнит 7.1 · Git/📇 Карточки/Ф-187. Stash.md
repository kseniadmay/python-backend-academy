1. Когда полезна команда `git stash branch` ? >> Когда применение stash привело к конфликтам или изменения выросли в отдельную задачу – удобно выделить их в новую ветку
2. К какому состоянию возвращается рабочая директория после `git stash` ? >> К состоянию последнего коммита ( `HEAD` )
3. Какой флаг позволяет включить неотслеживаемые (untracked) файлы в `git stash` ? >> `-u` или `--include-untracked` ; по умолчанию `git stash` игнорирует untracked-файлы
4. Какая команда применяет последние изменения из stash и удаляет запись из стека? >> `git stash pop`
5. Что делает `git stash -u` ? >> Сохраняет изменения в stash, включая неотслеживаемые (untracked) файлы
6. Как применить конкретную запись stash без удаления из стека? >> `git stash apply stash@{1}`
7. В какой ситуации наиболее полезен `git stash` ? >> Когда нужно срочно переключиться на другую ветку, не завершив текущую работу и не создавая сырой коммит
8. Какая команда полностью очищает стек stash? >> `git stash clear`
9. Что обозначает запись `stash@{0}` в выводе `git stash list` ? >> Идентификатор записи в стеке; `{0}` – вершина (последний сохранённый), `{1}` – следующий и т.д.
10. Правда ли, что `git stash` удаляет незафиксированные изменения навсегда? >> Нет; изменения сохраняются в стек и могут быть восстановлены командами `pop` или `apply`
11. Что произойдёт с untracked-файлом при обычном `git stash` без флага `-u` ? >> Он останется в рабочей директории нетронутым и не попадёт в stash
12. Как удалить одну конкретную запись из стека stash? >> `git stash drop stash@{0}`
13. В какую структуру данных Git помещает сохранённые stash-записи? >> В стек (LIFO); последний сохранённый элемент извлекается первым
14. Что происходит с индексированными (staged) изменениями при `git stash` ? >> По умолчанию они тоже попадают в stash и убираются из индекса; флаг `--keep-index` позволяет оставить их в staging area
15. Какая команда показывает список всех сохранённых stash-записей? >> `git stash list`
16. Как сохранить изменения в stash с пользовательским описанием? >> `git stash save "описание"` или предпочтительный современный вариант: `git stash push -m "описание"`
17. В чём отличие `git stash apply` от `git stash pop` ? >> `apply` применяет изменения, но оставляет запись в стеке; `pop` применяет и удаляет запись
18. Что делает `git stash branch <name> stash@{0}` ? >> Создаёт новую ветку от коммита, на котором был сделан stash, применяет к ней изменения из `stash@{0}` и удаляет запись из стека
19. Как сохранить изменения в stash с автоматически сгенерированным именем? >> `git stash` (или `git stash push` )
20. Каково основное назначение `git stash` ? >> Временно сохранить незафиксированные изменения в стек, очистить рабочую директорию и вернуться к состоянию последнего коммита – без создания коммита
