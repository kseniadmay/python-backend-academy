1. Для чего используется `SIGHUP` (1)? >> Исторически – завершение при закрытии терминала; в современных демонах (nginx, gunicorn) – сигнал перечитать конфигурацию без остановки
2. Что такое PID? >> Уникальный идентификатор процесса (Process ID); назначается ядром при запуске и уникален в рамках системы
3. Что такое зомби-процесс ( `Z` в колонке `STAT` )? >> Процесс завершился, но его запись не убрана из таблицы процессов, потому что родитель не вызвал `wait()` ; потребляет PID, но не память
4. Для чего используется `kill -9 <PID>` ? >> Принудительно завершает процесс сигналом `SIGKILL` ; процесс не может его перехватить или проигнорировать
5. Как найти процессы по имени через `ps` ? >> `ps aux | grep python` ; учти, что в выводе появится и сам процесс `grep` – это распространённая ловушка
6. Чем `htop` отличается от `top` ? >> Поддерживает управление мышью, прокрутку, цветной интерфейс, дерево процессов ( `F5` ) и удобное меню kill ( `F9` )
7. Чем отличаются колонки `VSZ` и `RSS` в `ps aux` ? >> `VSZ` – виртуальная память процесса (включая незагруженные страницы); `RSS` – физическая память, реально занятая в RAM (Resident Set Size)
8. Как запустить скрипт сразу в фоновом режиме? >> `./script.sh &` ; символ `&` отправляет процесс в фон, возвращая управление терминалу
9. Какой сигнал отправляет `kill <PID>` по умолчанию? >> `SIGTERM` (15) – запрос на корректное завершение
10. Чем `nohup` отличается от запуска с `&` ? >> `&` только отправляет в фон, но процесс всё равно получит `SIGHUP` при закрытии сессии; `nohup` защищает от этого сигнала
11. Для чего используется `pkill -f "gunicorn"` ? >> Завершает процессы, у которых строка запуска содержит `gunicorn` ; `-f` ищет по полной командной строке, а не только по имени
12. Что делает `Ctrl+Z` ? >> Приостанавливает (suspend) текущий процесс и возвращает управление оболочке; процесс не завершается
13. Как возобновить приостановленную задачу в фоне? >> `bg %1` ; предварительно задача должна быть приостановлена через `Ctrl+Z`
14. Что показывают колонки `%CPU` и `%MEM` в `ps aux` ? >> Процент использования процессора и физической оперативной памяти соответственно
15. В чём главное отличие `SIGTERM` от `SIGKILL` ? >> `SIGTERM` позволяет процессу завершиться корректно (закрыть файлы, сохранить состояние); `SIGKILL` убивает немедленно без возможности обработки
16. Как завершить все процессы с именем `python` одной командой? >> `killall python`
17. Как просмотреть информацию о процессе с конкретным PID? >> `ps -p <PID>`
18. Какая команда показывает список фоновых задач текущей сессии? >> `jobs`
19. Как вернуть фоновую задачу №1 на передний план? >> `fg %1`
20. Почему не стоит сразу использовать `kill -9` ? >> Процесс не успевает освободить ресурсы (файлы, соединения, временные данные); `SIGTERM` предпочтителен как первый шаг
21. Какие горячие клавиши `top` нужно знать? >> `q` – выход; `k` – kill процесса; `M` – сортировка по памяти; `P` – по CPU; `1` – нагрузка по каждому ядру
22. Какая утилита предназначена для интерактивного мониторинга процессов в реальном времени? >> `top`
23. Что означает колонка `USER` в выводе `ps aux` ? >> Имя пользователя, от имени которого запущен процесс
24. Какая команда используется для просмотра текущих процессов в Linux? >> `ps` ; без аргументов показывает только процессы текущего терминала
25. Что делает `ps aux` ? >> Показывает все процессы всех пользователей в системе с подробной информацией (CPU, память, PID, команда)
26. Для чего используется `nohup` ? >> Запускает процесс так, что он игнорирует `SIGHUP` ; процесс продолжает работу после закрытия терминала; вывод по умолчанию пишется в `nohup.out`
27. Что отображает колонка `STAT` в выводе `ps` ? >> Текущий статус процесса: `S` – sleeping, `R` – running, `Z` – zombie, `D` – uninterruptible sleep
28. Какой сигнал невозможно перехватить или проигнорировать процессу? >> `SIGKILL` (9); исключение – `init` / `systemd` с PID 1, ядро игнорирует `SIGKILL` для него
