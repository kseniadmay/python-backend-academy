1. Что выполняет `ls -la | grep ".py"` ? >> Выводит строки из списка файлов, содержащие `.py`
2. Как найти команды с `git commit` в истории терминала? >> `history | grep "git commit"`
3. Что делает оператор ` >> ` ? >> Добавляет `stdout` в конец файла, не перезаписывая существующее содержимое
4. Как посчитать количество строк с `ERROR` в `access.log` ? >> `grep "ERROR" access.log | wc -l` ; `cat access.log | grep ... | wc -l` тоже работает, но лишний `cat` – антипаттерн (useless use of cat)
5. Как просматривать новые строки лога и фильтровать ошибки в реальном времени? >> `tail -f app.log | grep --line-buffered "ERROR"` ; флаг `--line-buffered` отключает буферизацию `grep` и выдаёт результат сразу
6. Что означает оператор `||` ? >> Вторая команда выполняется только если первая завершилась с ненулевым кодом (ошибкой)
7. Что означает оператор `;` ? >> Последовательное выполнение команд независимо от кода возврата предыдущей
8. Для чего используется `tee` в конвейере? >> Одновременно выводит данные в терминал и записывает в файл; `tee -a` дописывает в конец файла
9. Для чего используется `grep -v grep` в цепочке `ps aux | grep python | grep -v grep` ? >> Исключает из вывода сам процесс `grep python` , который тоже содержит слово `python` в командной строке
10. Что делает `2>&1` ? >> Перенаправляет `stderr` (дескриптор 2) туда же, куда указывает `stdout` (дескриптор 1) в момент выполнения
11. Для чего используется `/dev/null` ? >> Специальный файл-«мусорка»: всё записанное туда безвозвратно уничтожается; используется для подавления нежелательного вывода
12. Зачем `grep` в конвейере с `tail -f` нужен флаг `--line-buffered` ? >> По умолчанию `grep` буферизует вывод блоками; `--line-buffered` заставляет выдавать каждую строку сразу, что критично для мониторинга логов в реальном времени
13. Что произойдёт при `./script.sh || echo "Failed"` , если скрипт завершился успешно? >> `echo "Failed"` не выполнится; `||` срабатывает только при ненулевом коде возврата
14. Как запустить скрипт, скрыв только сообщения об ошибках? >> `./script.sh 2>/dev/null`
15. Как перенаправить одновременно `stdout` и `stderr` в один файл? >> `./script.sh &> all.log` или `./script.sh > all.log 2>&1` ; важен порядок: `2>&1` должен стоять после `>`
16. Что такое heredoc? >> Механизм многострочного ввода в shell; позволяет передать блок текста в команду до маркера завершения ( `EOF` )
17. Какой оператор перенаправляет только `stderr` в файл? >> `2>` ; например `./script.sh 2> errors.log`
18. Что означает оператор `&&` ? >> Вторая команда выполняется только если первая завершилась с кодом `0` (успешно)
19. Как направить `stdout` скрипта в файл, оставив `stderr` в терминале? >> `./script.sh > log.txt` ; `stderr` (дескриптор 2) при этом не перенаправляется и остаётся в терминале
20. Какой оператор передаёт содержимое файла в `stdin` команды? >> `<` ; например `python script.py < input.txt`
21. Что хранит переменная `$?` ? >> Код возврата последней выполненной команды; `0` – успех, ненулевое – ошибка
22. Как добавить строку `New line` в конец `output.txt` ? >> `echo "New line" >> output.txt`
23. Чем `&&` отличается от `;` ? >> `&&` выполняет следующую команду только при успехе предыдущей; `;` выполняет всегда – независимо от результата
24. Что делает конвейер `cat app.log | sort | uniq -c | sort -rn | head -10` ? >> Выводит топ-10 наиболее часто встречающихся уникальных строк в лог-файле
25. Что делает оператор `>` ? >> Перенаправляет `stdout` в файл, полностью перезаписывая его; если файл не существует – создаёт
26. Какова основная концепция Unix, связанная с pipe ( `|` )? >> Вывод ( `stdout` ) одной команды передаётся как ввод ( `stdin` ) следующей; позволяет строить сложные конвейеры из простых утилит
27. Как дописывать вывод скрипта в `app.log` , видя его в терминале? >> `./script.sh | tee -a app.log`
28. Как запустить команду, полностью подавив любой вывод? >> `command > /dev/null 2>&1`
