## Что такое Origin и правило Same-Origin Policy

**Origin** — это комбинация трёх параметров адреса: схемы (`http` или `https`), домена и порта.

По умолчанию в браузере действует правило **Same-Origin Policy (SOP)**: скрипт на странице одного Origin не может читать ответы на запросы к другому Origin.

Изоляция защищает пользователя: сторонняя вкладка не прочитает ваши письма или данные банка.

По той же причине фронтенд на `https://app.io` не получит ответ API с `https://api.app.io` без явного разрешения.

Сравним несколько адресов относительно базового `https://app.io`:

| Адрес | Совпадает с `https://app.io`? | Причина |
| --- | --- | --- |
| `https://app.io/api` | Да | Путь не входит в Origin |
| `http://app.io` | Нет | Отличается схема (`http`) |
| `https://api.app.io` | Нет | Другой поддомен (`api.`) |
| `https://app.io:8080` | Нет | Отличается порт (`8080`) |

## Как работает CORS

**CORS (Cross-Origin Resource Sharing)** — это механизм HTTP-заголовков, позволяющий серверу явно разрешить браузеру читать ответы с другого Origin.

Когда скрипт отправляет запрос на другой домен, браузер автоматически добавляет заголовок `Origin` с адресом текущей страницы.

Сервер проверяет `Origin` по белому списку и при совпадении возвращает заголовок `Access-Control-Allow-Origin`.

Если заголовок подходит, браузер передаёт ответ JavaScript-коду, а иначе скрывает данные и пишет ошибку CORS в консоль.

## Простые и сложные запросы: preflight OPTIONS

Обычные `GET`- и `POST`-запросы со стандартными заголовками и типом тела `text/plain` или `application/x-www-form-urlencoded` браузер отправляет сразу.

Запросы с методами `PUT` и `DELETE`, заголовком `Authorization` или телом `application/json` считаются сложными.

Перед ними браузер автоматически шлёт предварительный запрос `OPTIONS` (preflight), чтобы спросить разрешение у сервера.

Пример preflight-запроса браузера и ответа сервера:

```http
OPTIONS /api/orders HTTP/1.1
Origin: https://app.io
Access-Control-Request-Method: DELETE
Access-Control-Request-Headers: Authorization

HTTP/1.1 204 No Content
Access-Control-Allow-Origin: https://app.io
Access-Control-Allow-Methods: GET, DELETE
Access-Control-Allow-Headers: Authorization
Access-Control-Max-Age: 86400
```

Заголовок `Access-Control-Max-Age: 86400` кэширует ответ на preflight-проверку на 24 часа, чтобы браузер не повторял лишний `OPTIONS` перед каждым запросом.

## Настройка CORS в Django (django-cors-headers)

Для настройки CORS в Django обычно используют пакет `django-cors-headers`:

```bash
pip install django-cors-headers
```

Подключите приложение в `settings.py`, поставьте `CorsMiddleware` выше `CommonMiddleware` и задайте белый список доменов:

```python
# settings.py
INSTALLED_APPS = [
    # Подключаем библиотеку в приложениях
    'corsheaders',
]

MIDDLEWARE = [
    # CorsMiddleware строго на самом верху
    'corsheaders.middleware.CorsMiddleware',
    (
        'django.middleware.common.'
        'CommonMiddleware'
    ),
]

CORS_ALLOWED_ORIGINS = [
    'https://app.io',
    'http://localhost:3000',
]

# Разрешаем передачу Cookie с других доменов
CORS_ALLOW_CREDENTIALS = True
```

Если фронтенд отправляет куки (`credentials: 'include'`), добавьте `CORS_ALLOW_CREDENTIALS = True`.

В этом режиме браузер запрещает подстановочный символ `*`: разрешённые домены должны быть указаны явно.

В production не оставляйте `CORS_ALLOW_ALL_ORIGINS = True` для приватных маршрутов: в списке `CORS_ALLOWED_ORIGINS` должны быть только ваши фронтенд-домены.

## Главное заблуждение о CORS

CORS не является защитой бэкенда от посторонних запросов и не заменяет аутентификацию. Заголовки CORS проверяет только браузер на машине пользователя.

Злоумышленник может спокойно отправить запрос на ваш сервер через `curl`, Postman или Python-скрипт, где вообще нет механизма CORS.

Кроме того, простой cross-origin `POST`-запрос браузер всё равно отправляет на сервер, а CORS лишь скрывает ответ от JavaScript.

Поэтому каждая защищённая ручка обязана проверять токены авторизации и права доступа прямо на бэкенде.

> **Junior vs Senior**:
> - **Junior**: думает, что настройка CORS защищает бэкенд от посторонних клиентов, или вслепую разрешает `Origin: *` вместе с передачей `Credentials`.
> - **Senior**: знает, что SOP/CORS исполняется только браузером (и легко обходится через `curl`), проверяет авторизацию на сервере, задаёт строгий список доверенных `Origin` и кеширует preflight `OPTIONS`.
