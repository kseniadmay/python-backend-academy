## Что такое CSRF и почему это опасно

**CSRF (Cross-Site Request Forgery)** — атака, при которой сторонний сайт заставляет браузер жертвы отправить запрос на сервис, где она уже авторизована.

В результате от имени жертвы без её ведома срабатывает целевое действие: перевод денег, смена пароля или добавление администратора.

---

## Как выглядит атака изнутри

Атака опирается на **Ambient Authority**: браузер автоматически прикрепляет сессионные куки `bank.com` к запросу на этот домен, даже если он ушёл с чужого сайта.

Допустим, пользователь залогинен в `bank.com` и в соседней вкладке открывает страницу `evil.com` со скрытой HTML-формой:

```html
<!-- Скрытая форма на сайте злоумышленника -->
<form
  action="https://bank.com/transfer"
  method="POST"
>
  <input
    type="hidden"
    name="to"
    value="hacker_account"
  >
  <input
    type="hidden"
    name="amount"
    value="10000"
  >
</form>
<script>document.forms[0].submit();</script>
```

Браузер сам подставит куку `session_id` от `bank.com` и отправит POST-запрос.

Если сервер опирается только на куку, он сочтёт перевод легитимным действием пользователя. Браузер скроет ответ по CORS, но списание средств на сервере к этому моменту уже выполнится.

## Защита №1: CSRF-токены

Основная защита форм и сессий — **Synchronizer Token Pattern**: сервер генерирует случайный секрет и встраивает его прямо в страницу.

Чужой сайт не может прочитать HTML вашей страницы из-за Same-Origin Policy, поэтому не узнает значение токена.

В шаблонах Django тег добавляет в форму скрытое поле с этим секретом:

```html
<form action="/transfer" method="POST">
  <!-- Скрытое поле с CSRF-токеном -->
  {% csrf_token %}
  <input type="text" name="amount">
  <button type="submit">Перевести</button>
</form>
```

При получении POST-запроса сервер сравнивает присланный токен с эталоном из сессии за константное время через `hmac.compare_digest`, чтобы защититься от атак по времени:

```python
import hmac

def verify_csrf(sent_token, session_token):
    if not sent_token or not session_token:
        return False

    return hmac.compare_digest(
        sent_token,
        session_token,
    )
```

## Защита №2: атрибут SameSite и проверка заголовков

Дополнительный барьер на уровне браузера — атрибут `SameSite` у сессионной куки, который управляет её отправкой со сторонних сайтов.

Также сервер может сверять заголовки `Origin` и `Referer` с разрешённым доменом для всех изменяющих запросов.

| Механизм | Как защищает | Особенность |
| --- | --- | --- |
| `SameSite=Strict` | Кука не шлётся со сторонних сайтов вообще | Сбрасывает сессию даже при клике из письма |
| `SameSite=Lax` | Шлётся только при переходе по обычной ссылке (`GET`) | Стандарт в современных браузерах и `Django` |
| `Origin` / `Referer` | Блокирует запрос с чужого домена на сервере | Работает как второй эшелон проверки |

## Когда CSRF исчезает (SPA и JWT) и чек-лист защиты

Если SPA-приложение хранит токен доступа не в `Cookie`, а в памяти JavaScript и передаёт его в заголовке `Authorization: Bearer <token>`, классический CSRF исчезает.

Браузер никогда не добавляет `Authorization` автоматически, а чужой скрипт не пропустит проверка CORS. Если же JWT всё-таки хранится в куках, защита через CSRF-токен и `SameSite` снова становится обязательной.

Базовые правила безопасности:

- **Никогда не меняйте данные по `GET`**: создание, удаление и переводы должны работать только через `POST`, `PUT`, `PATCH` или `DELETE`.
- **Токен для сессионных кук**: используйте встроенный `CsrfViewMiddleware` в Django или передавайте `X-CSRFToken` в AJAX-запросах.
- **Комбинируйте слои защиты**: `SameSite=Lax`, проверка `Origin` и перенос авторизации в заголовок `Authorization` перекрывают атаку даже при сбое одного из уровней.

> **Junior vs Senior**:
> - **Junior**: изменяет данные по `GET`-ссылкам и полагается на автоматические cookie-сессии без `SameSite` и проверки CSRF-токена.
> - **Senior**: разделяет безопасные и мутирующие методы, защищает cookie-формы синхронным CSRF-токеном и `SameSite=Lax`, а для SPA использует передачу токена в заголовке `Authorization`.
