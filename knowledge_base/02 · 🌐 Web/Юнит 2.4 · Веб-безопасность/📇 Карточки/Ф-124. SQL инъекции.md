1. Почему нельзя показывать пользователю детали ошибок БД? >> Раскрывают структуру таблиц, имена столбцов, версию БД – упрощают подготовку атаки
2. Освобождает ли ORM от понимания SQL-инъекций? >> Нет; raw-запросы внутри ORM или неправильное использование могут вернуть уязвимость
3. Почему f-строки в SQL-запросах опасны? >> Пользовательский ввод попадает в запрос необработанным; БД интерпретирует его как SQL-команды, а не данные
4. Что такое принцип минимальных прав для пользователя БД? >> Предоставление только необходимых прав (SELECT, INSERT, UPDATE, DELETE); запрет DROP, ALTER, системных таблиц
5. Что такое SQL-инъекция? >> Атака, при которой вредоносный SQL-код вставляется в пользовательский ввод и выполняется базой данных
6. Как Django ORM защищает от SQL-инъекций? >> Автоматически параметризует все запросы через `.get()` , `.filter()` и другие методы API
7. Что произойдёт если передать `'; DROP TABLE users; --` в параметризованный запрос? >> БД ищет пользователя с таким именем; `DROP TABLE` не выполняется – это просто строковые данные
8. Основная причина SQL-инъекций? >> Формирование SQL-запроса через конкатенацию строк с пользовательским вводом вместо параметризации
9. Является ли ручная фильтрация спецсимволов надёжной защитой? >> Нет; параметризованные запросы – золотой стандарт; ручная фильтрация легко обходится нестандартными кодировками
10. Что такое WAF? >> Web Application Firewall; анализирует HTTP-трафик и блокирует запросы с признаками вредоносных нагрузок; дополнительная мера, не замена параметризации
11. Что делает `admin' --` в поле логина? >> `'` закрывает строку в SQL; `--` комментирует остаток запроса включая проверку пароля; вход без пароля
12. Что такое payload в контексте SQL-инъекций? >> Специально сформированные данные, эксплуатирующие уязвимость: `'; DROP TABLE users; --`
13. Что делает `;` в SQL-инъекции? >> Разделяет несколько независимых команд: `'; DROP TABLE users; --` удаляет таблицу
14. Достаточно ли ограничения прав БД для защиты от SQL-инъекций? >> Нет; это дополнительная мера снижения ущерба, но не устраняет саму уязвимость
15. Основной метод защиты от SQL-инъекций? >> Параметризованные запросы (prepared statements): структура запроса и данные передаются раздельно
16. Плейсхолдер psycopg2 для PostgreSQL? >> `%s` ; данные передаются отдельным аргументом: `cursor.execute("SELECT * FROM users WHERE id = %s", (user_id,))`
