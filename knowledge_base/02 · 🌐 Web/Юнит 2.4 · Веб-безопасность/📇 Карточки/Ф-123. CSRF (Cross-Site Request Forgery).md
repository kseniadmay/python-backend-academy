1. В чем ключевая разница между режимами SameSite=Lax и SameSite=Strict для Cookies? >> Кука отправляется при безопасной навигации (GET-переходы по ссылкам); не отправляется при POST-запросах с других сайтов
2. Что такое CSRF-токен и как работает механизм защиты от подделки межсайтовых запросов? >> Случайный токен, вставляемый в форму как скрытое поле; сервер проверяет его наличие при POST; злоумышленник не может знать его значение
3. Почему CSRF работает через куки? >> Браузер автоматически отправляет куки при любом запросе к домену; вредоносный сайт не знает их содержимое, но браузер прикрепляет их сам
4. Как Django реализует CSRF-защиту? >> Автоматически включена; тег `{% csrf_token %}` вставляет скрытое поле `csrfmiddlewaretoken` ; проверяется при POST-запросах
5. Для каких HTTP-методов Django проверяет CSRF-токен? >> POST, PUT, PATCH, DELETE; GET считается безопасным и не проверяется
6. Комбинация каких мер даёт надёжную защиту от CSRF? >> CSRF-токен + `SameSite=Strict/Lax` + проверка `Origin` ; `HttpOnly` защищает от XSS, но не от CSRF
7. Чем CSRF отличается от XSS? >> XSS – внедрение кода на доверенный сайт; CSRF – использование браузера жертвы для отправки запросов от её имени; разные векторы атаки
8. Какие заголовки сервер может проверять для верификации источника? >> `Origin` и `Referer` ; но это вспомогательная мера, не самостоятельная защита
9. Почему CSRF-токен должен быть случайным? >> Чтобы его невозможно было предугадать или вычислить; предсказуемый токен не даёт защиты
10. Что такое CSRF-атака? >> Вредоносный сайт заставляет браузер жертвы отправить запрос на сайт, где она аутентифицирована; браузер автоматически прикрепляет куки – сервер считает запрос легитимным
11. Как `SameSite=Strict` защищает от CSRF? >> Браузер не отправляет куку при любых кросс-сайтовых запросах; вредоносный сайт не может инициировать запрос с кукой
12. Почему JWT в API снижает актуальность CSRF? >> JWT обычно хранится в памяти JS или `localStorage` , а не в куках; браузер не прикрепляет его автоматически к запросам; но тогда актуален XSS
13. Является ли проверка `Origin` / `Referer` достаточной защитой от CSRF? >> Нет; вспомогательная мера; основные методы – CSRF-токен и `SameSite` куки
14. Чем отличается поведение куки с `SameSite=Lax` от `SameSite=Strict`? >> `SameSite=Strict` блокирует отправку куки при любых кросс-сайтовых переходах; `SameSite=Lax` разрешает отправку куки при безопасной навигации верхнего уровня (GET-переход по внешней ссылке), но блокирует при кросс-сайтовых POST-запросах и скрытых формах
15. К какому типу атак становится уязвимо приложение, если хранить JWT-токен в `localStorage` браузера? >> К XSS-атакам: любой внедрённый JavaScript-код может прочитать `localStorage.getItem('token')` и украсть токен
