1. Являются ли https://example.com:3000 и https://example.com одним и тем же Origin по правилу Same-Origin Policy? >> Нет; разные порты → разные origin
2. Являются ли http://example.com и https://example.com одним Origin? >> Нет; разные протоколы → разные origin
3. Какой заголовок браузер добавляет к кросс-доменному запросу? >> `Origin: https://frontend.com`
4. Какие заголовки сервер должен вернуть на preflight? >> `Access-Control-Allow-Origin` ; `Access-Control-Allow-Methods` ; `Access-Control-Allow-Headers` ; опционально `Access-Control-Max-Age`
5. Что такое простой (simple) запрос в контексте CORS? >> GET или POST со стандартными заголовками без `Authorization` , без `application/json` Content-Type; не требует preflight
6. Какие элементы определяют Origin? >> Протокол + домен + порт; путь (path) не входит
7. Чем `CORS_ALLOWED_ORIGINS` безопаснее `*` ? >> Ограничивает доступ только доверенным доменам; позволяет безопасно использовать `CORS_ALLOW_CREDENTIALS = True`
8. Почему нельзя использовать `*` при передаче credentials (куки)? >> При `credentials: true` нельзя использовать `*` в `Access-Control-Allow-Origin` ; нужен конкретный домен
9. Являются ли `https://frontend.com` и `https://sub.frontend.com` одним origin? >> Нет; разные поддомены → разные origin
10. Что такое CORS? >> Cross-Origin Resource Sharing; механизм браузера, позволяющий серверу явно разрешить запросы с конкретных сторонних доменов
11. Что такое preflight-запрос? >> Предварительный `OPTIONS` -запрос перед сложным запросом; браузер спрашивает сервер разрешение перед отправкой основного запроса
12. Что такое Same-Origin Policy? >> Политика безопасности браузера: JavaScript не может читать ответы от доменов, отличных от источника загрузки страницы
13. Что делает `Access-Control-Max-Age: 86400` ? >> Кэширует результат preflight на 24 часа; браузер не повторяет OPTIONS-запрос в течение этого времени
14. Какой заголовок сервер должен вернуть для разрешения доступа? >> `Access-Control-Allow-Origin: https://frontend.com` или `*`
15. Когда браузер отправляет preflight? >> Перед запросами с `PUT` , `DELETE` , `PATCH` ; с кастомными заголовками ( `Authorization` , `X-API-Key` ); с `Content-Type: application/json`
16. Кто является субъектом защиты CORS – сервер или браузер? >> Браузер; CORS защищает пользователя от вредоносных сайтов, читающих его данные; сервер получает запрос в любом случае
17. Какая библиотека настраивает CORS в Django? >> `django-cors-headers` ; `CorsMiddleware` добавляется как можно выше в `MIDDLEWARE` , перед `CommonMiddleware`
18. Когда опасно использовать `CORS_ALLOW_ALL_ORIGINS = True` ? >> В production с важными данными; любой сайт сможет читать API-ответы используя сессию авторизованного пользователя
19. Что произойдёт если сервер не вернёт `Access-Control-Allow-Origin` ? >> Запрос выполнится, но браузер заблокирует JavaScript-доступ к ответу
20. Почему `curl` и Postman всегда получают ответ несмотря на CORS? >> Они игнорируют CORS; это механизм только браузеров; не защищает API от прямых запросов
