## Необходимость версионирования: закон эволюции API

Любой продакшен-API непрерывно развивается. Изменения делятся на две категории:

- **Обратно совместимые (Non-breaking):** добавление нового опционального поля в ответ, добавление нового query-параметра, появление нового эндпоинта. Не требуют повышения мажорной версии.
- **Ломающие (Breaking Changes):** удаление или переименование поля, изменение типа данных (`int` ➔ `string`), изменение обязательности параметров, изменение статус-кода ошибки. **Требуют обязательного версионирования**.

## Стратегии версионирования: 3 подхода индустрии

1. **Версионирование в URI (URI Versioning):**
   `https://api.example.com/v1/users`
   * ✅ Самый наглядный, кэшируемый и распространенный стандарт (FastAPI, Stripe, GitHub).
2. **Версионирование через кастомный заголовок (Header Versioning):**
   `X-API-Version: 2026-10-01`
   * Сохраняет URI чистым, но усложняет тестирование через обычную строку браузера.
3. **Согласование содержимого (Accept / Media Type Versioning):**
   `Accept: application/vnd.company.v2+json`
   * Академически верный подход REST, но избыточно сложен для интеграции сторонними клиентами.

## Уведомление об устаревании: стандарты Deprecation и Sunset

Нельзя внезапно отключать старые версии API — это сломает мобильные приложения пользователей. RFC 8594 стандартизирует уведомление клиентов через HTTP-заголовки:

```http
HTTP/1.1 200 OK
Deprecation: @1793404800
Sunset: Wed, 11 Nov 2026 00:00:00 GMT
Link: <https://api.example.com/v2>;
  rel="successor-version"
```

- **`Deprecation`:** дата или факт объявления эндпоинта устаревшим (клиентам рекомендуется запланировать миграцию).
- **`Sunset`:** точная дата окончательного вывода эндпоинта из эксплуатации (после нее сервер вернет `410 Gone` или `404`).

## Архитектура версионирования в FastAPI

В FastAPI версионирование организуется модульным подключением роутеров (`APIRouter`):

```python
from fastapi import APIRouter, FastAPI

app = FastAPI()

v1 = APIRouter(prefix="/api/v1")
v2 = APIRouter(prefix="/api/v2")

@v1.get("/users")
def get_users_v1():
    return [{"name": "Alice"}]

@v2.get("/users")
def get_users_v2():
    return [{
        "first_name": "Alice",
        "last_name": "Smith"
    }]

app.include_router(v1)
app.include_router(v2)
```

Каждая версия изолирует свои Pydantic-схемы, предотвращая регрессии в старых контрактах.
