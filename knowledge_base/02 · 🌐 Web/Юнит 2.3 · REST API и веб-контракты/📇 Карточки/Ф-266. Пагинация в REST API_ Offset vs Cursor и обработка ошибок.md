1. Назовите два основных способа пагинации в REST API. >> 1) **Offset-пагинация** (`limit` / `offset` или `page` / `page_size`); 2) **Cursor-пагинация** (Keyset / Seek пагинация через указатель `cursor` на последний элемент)
2. Почему `LIMIT 20 OFFSET 1000000` работает медленно в реляционных базах данных? >> СУБД не может перепрыгнуть смещение по индексу: ей приходится прочитать и отсортировать все `1 000 020` записей, отбросить первые `1 000 000` и вернуть только последние 20 — сложность растёт линейно $O(\text{OFFSET})$
3. Что такое проблема «дрейфа строк» (Row Drift) при Offset-пагинации? >> Если во время чтения 1-й страницы в начало таблицы вставляется новая запись, все строки сдвигаются вниз, и при запросе 2-й страницы (`offset=20`) клиент снова получает последние элементы с 1-й страницы (дубликаты)
4. Как работает Cursor (Keyset) пагинация на уровне SQL-запроса? >> Вместо `OFFSET` используется индексное условие `WHERE`: например, `WHERE (created_at, id) < (:last_ts, :last_id) ORDER BY created_at DESC, id DESC LIMIT 20`
5. Какова алгоритмическая сложность Cursor-пагинации при наличии B-Tree индекса на поле сортировки? >> $O(\log N)$ на поиск начальной точки по индексу + $O(\text{LIMIT})$ на чтение страницы: 1-я и 100 000-я страницы открываются с одинаковой скоростью
6. Зачем в Cursor-пагинации при сортировке по дате `created_at` в курсор и `ORDER BY` добавляют второе уникальное поле `id`? >> Чтобы разрешить коллизии (Tie-breaker): если у нескольких записей совпала секунда `created_at`, без уникального `id` часть записей с тем же временем будет пропущена условием `<`
7. Какое главное функциональное ограничение есть у Cursor-пагинации по сравнению с Offset? >> Нельзя перепрыгнуть сразу на произвольный номер страницы (например, «Страница 42») и сложно показать общее число страниц; подходит для лент, чатов и бесконечного скролла
8. Как определить флаг `has_more` (есть ли следующая страница) без выполнения тяжёлого запроса `SELECT COUNT(*)`? >> Запросить из базы на одну запись больше: `LIMIT (page_size + 1)`. Если вернулось `page_size + 1` строк — значит `has_more = True`, а клиенту возвращаются первые `page_size` элементов
9. Почему значение `cursor` обычно кодируют в `base64` перед отправкой клиенту? >> Чтобы сделать курсор непрозрачным (Opaque) для клиента: фронтенд не должен завязываться на внутренние имена колонок сортировки, и бэкенд сможет изменить формат курсора без поломки клиентов
10. Что описывает стандарт RFC 7807 (RFC 9457) Problem Details for HTTP APIs? >> Единый стандартный JSON-формат ответа для ошибок API (`application/problem+json`) с полями `type`, `title`, `status`, `detail` и `instance`
11. Почему в продакшене категорически нельзя возвращать клиенту сырой `Traceback` при ошибке `500 Internal Server Error`? >> Стектрейс раскрывает злоумышленнику пути к файлам, версии библитьотек, SQL-запросы и внутреннюю структуру приложения; детали пишутся в серверные логи с `request_id`, а клиенту отдаётся безопасный Problem Details
12. Какой HTTP-статус код возвращает FastAPI при ошибке валидации входной схемы Pydantic, а какой — DRF Serializer по умолчанию? >> FastAPI возвращает `422 Unprocessable Entity`; Django REST Framework по умолчанию возвращает `400 Bad Request`
