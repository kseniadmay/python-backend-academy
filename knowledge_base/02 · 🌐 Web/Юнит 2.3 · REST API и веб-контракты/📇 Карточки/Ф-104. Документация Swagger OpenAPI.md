1. Для чего используется инструмент Swagger Codegen (или OpenAPI Generator)? >> Автоматическая генерация клиентских SDK, серверных шаблонов и моделей данных из спецификации
2. Какой класс View отвечает за генерацию схемы OpenAPI в библиотеке drf-spectacular? >> `SpectacularAPIView`
3. В чем ключевые различия между спецификациями OpenAPI 2.0 (Swagger) и OpenAPI 3.0? >> OpenAPI 2.0 – это Swagger Specification; OpenAPI 3.0 – современный стандарт с улучшенной структурой: `components` , `requestBody` , поддержка нескольких серверов
4. Как описать массив объектов в схеме OpenAPI 3.0? >> `type: array` + блок `items` с описанием элемента или `$ref`
5. Как FastAPI обеспечивает автоматическую синхронизацию OpenAPI документации при изменении Pydantic-моделей? >> Обновится автоматически при следующем запуске; документация всегда актуальна
6. Что определяет поле `openapi` в спецификации? >> Версию стандарта OpenAPI: `openapi: "3.0.0"`
7. Как сослаться на переиспользуемую схему? >> `$ref: '#/components/schemas/User'`
8. Для каких задач используется визуальный инструмент Swagger Editor при разработке API? >> Написание и визуальное редактирование спецификаций OpenAPI с валидацией в реальном времени
9. Каковы главные преимущества автоматической генерации OpenAPI-документации на основе кода и Pydantic-схем? >> Документация всегда актуальна и соответствует реальному поведению кода; нет рассинхронизации между кодом и документацией
10. Что такое спецификация OpenAPI и какую роль она играет при проектировании REST API? >> Языконезависимый машиночитаемый стандарт описания REST API (в формате YAML или JSON), специфицирующий эндпоинты, параметры, структуры тел запросов и ответов, схемы валидации и механизмы аутентификации.
11. Какую функцию выполняет интерактивный веб-интерфейс Swagger UI в веб-приложениях? >> Визуализация интерактивной документации в браузере; позволяет тестировать запросы без Postman
12. Где хранятся переиспользуемые модели в OpenAPI 3.0? >> `components/schemas`
13. Что представляет собой экосистема Swagger и какие ключевые инструменты в неё входят? >> Набор инструментов вокруг спецификации OpenAPI: Swagger UI (интерактивная документация в браузере), Swagger Editor (редактор спецификаций) и Swagger Codegen (генератор клиентских библиотек и серверных заглушек).
14. С помощью какого поля в спецификации OpenAPI (Swagger) задаётся местоположение параметра (in: query, path, header, cookie)? >> Поле `in` : `query` , `header` , `path` , `cookie`
15. Как описать тело запроса в OpenAPI 3.0? >> Блок `requestBody` с `required: true` и `content: application/json: schema: ...`
16. Откуда FastAPI берёт описание эндпоинта для документации? >> Из docstring функции-обработчика
17. Библиотека для OpenAPI в Django REST Framework? >> `drf-spectacular`
18. Что такое `operationId` ? >> Уникальный идентификатор операции; используется Codegen для именования методов SDK и в тестах
19. Какой View отображает Swagger UI в `drf-spectacular` ? >> `SpectacularSwaggerView`
20. Настройка `DEFAULT_SCHEMA_CLASS` для `drf-spectacular` ? >> `drf_spectacular.openapi.AutoSchema` в `REST_FRAMEWORK` в `settings.py`
21. Как называется метод Pydantic-модели для преобразования в словарь? >> `dict()` в Pydantic v1; `model_dump()` в Pydantic v2
