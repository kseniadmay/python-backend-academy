## Зачем нужна модель OSI

**Модель OSI** (*Open Systems Interconnection*) — это семиуровневая схема, описывающая путь данных от приложения на одном компьютере до приложения на другом через сеть.

Она не является протоколом сама по себе, но служит единой системой координат, чтобы инженеры говорили на одном языке об уровнях абстракции сети.

Backend-разработчику в первую очередь важны уровни `3–7`, однако знание всей модели помогает быстро локализовать место сбоя.

---

## Семь уровней модели OSI и мнемоника

Каждый уровень решает свою изолированную задачу и оборачивает данные нижележащего слоя:

| № | Уровень | Ключевая задача | Примеры протоколов и данных |
| :-: | :--- | :--- | :--- |
| **7** | **Прикладной** (*Application*) | Сетевой интерфейс приложений | `HTTP`, `DNS`, `FTP`, `SMTP` |
| **6** | **Представления** (*Presentation*) | Кодировки, сжатие, шифрование | `TLS` (частично), UTF-8, gzip |
| **5** | **Сеансовый** (*Session*) | Установка и завершение сеанса | Сессии связи между процессами |
| **4** | **Транспортный** (*Transport*) | Доставка по портам, контроль потерь | `TCP`, `UDP` |
| **3** | **Сетевой** (*Network*) | Маршрутизация между сетями | `IP`-адреса, маршрутизаторы |
| **2** | **Канальный** (*Data Link*) | Передача в локальной сети | `Ethernet`, `MAC`-адреса |
| **1** | **Физический** (*Physical*) | Биты в виде сигнала среды | Кабель, оптика, Wi-Fi-сигнал |

Для запоминания снизу вверх используют фразу: «**Ф**изик **К**ушает **С**ладкий **Т**орт, **С**прашивает **П**орцию **П**обольше».

## Путь HTTP-запроса через уровни

При отправке `GET /users` данные проходят инкапсуляцию сверху вниз на клиенте и обратную распаковку на сервере:

```text
Инкапсуляция при отправке запроса:
L7 (App)      -> HTTP 'GET /users'
L4 (Transp.)  -> TCP-сегмент (порт 443)
L3 (Network)  -> IP-пакет (адрес сервера)
L2 (Link)     -> Ethernet-кадр (MAC)
L1 (Physical) -> Сигнал в кабеле/радиоэфире
```

На уровне L7 полезная нагрузка представляет собой структурированный поток байтов HTTP:

```python
http_payload = (
    b'GET /users HTTP/1.1\r\n'
    b'Host: localhost\r\n'
    b'Connection: close\r\n\r\n'
)

print('Размер L7:', len(http_payload), 'байт')
# >>> Размер L7: 59 байт
```

## Диагностика ошибок и балансировка L4 / L7

Понимание уровней OSI сразу подсказывает источник проблемы при сетевом сбое:

- `No route to host` — уровень 3 (маршрутизация пакетов в сети).
- `Connection refused` — уровень 4 (порт закрыт или серверный процесс не запущен).
- `DNS resolution failed` — уровень 7 (доменное имя не переводится в IP-адрес).

На том же разделении строят балансировщики нагрузки: **L4-балансировщик** направляет трафик на уровне TCP-портов, а **L7-балансировщик** (`nginx`) читает HTTP-заголовки и маршрутизирует по URL.
