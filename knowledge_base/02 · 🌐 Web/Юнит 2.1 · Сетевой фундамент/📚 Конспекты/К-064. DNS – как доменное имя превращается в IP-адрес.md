## Зачем нужен DNS

Машины в сети общаются по **IP-адресам** (`93.184.216.34`), но людям удобнее запоминать доменные имена (`example.com`).

**DNS** (*Domain Name System*) — распределённый справочник, который переводит (резолвит) доменное имя в IP-адрес перед установкой сетевого соединения.

---

## Путь DNS-резолвинга

При переходе к `example.com` браузер и сеть за миллисекунды проходят цепочку из шести шагов:

1. Браузер проверяет **локальный кэш** ОС и самого браузера.
2. Если записи нет, запрос идёт к **рекурсивному резолверу** (провайдера или публичному вроде `8.8.8.8`).
3. Резолвер спрашивает **корневой сервер** (root server), кто отвечает за зону верхнего уровня (`.com`, `.ru`).
4. Корневой сервер направляет к **TLD-серверу** доменной зоны (например, `.com`).
5. TLD-сервер указывает на **авторитативный сервер** (*authoritative nameserver*), хранящий реальные записи `example.com`.
6. Резолвер кэширует полученный IP на время **TTL** и возвращает его браузеру для TCP-соединения.

## Основные типы DNS-записей

Зона домена хранит несколько типов ресурсных записей для маршрутизации трафика и почты:

| Запись | Назначение | Пример значения |
| :--- | :--- | :--- |
| **`A`** | Связывает домен с **IPv4**-адресом | `example.com` $\to$ `93.184.216.34` |
| **`AAAA`** | Связывает домен с **IPv6**-адресом | `example.com` $\to$ `2606:2800::1` |
| **`CNAME`** | Псевдоним: ссылает домен на другой домен | `www.site.com` $\to$ `site.com` |
| **`MX`** | Указывает почтовые серверы домена | `10 mail.example.com` |
| **`TXT`** | Произвольный текст (валидация, SPF/DKIM) | `"v=spf1 include:_spf..."` |
| **`NS`** | Задаёт авторитативные DNS-серверы | `ns1.provider.com` |

## DNS и модуль `socket` в Python

Модуль `socket` позволяет обратиться к системному резолверу ОС напрямую из Python и узнать IPv4-адрес домена:

```python
import socket

ip = socket.gethostbyname('example.com')
print(ip)
# >>> 93.184.216.34
```

Для гибкой работы — получения IPv6-адресов и фильтрации по порту/протоколу — используют `socket.getaddrinfo()`.

## TTL, кэширование и диагностика отказов

Каждая DNS-запись имеет **TTL** (*Time To Live*) — время кэширования в секундах: высокий TTL снижает нагрузку и ускоряет открытие сайта, но замедляет обновление адреса при переезде сервера.

Поэтому перед миграцией инфраструктуры TTL заранее понижают, а при сбоях доступности домена проверяют резолвинг утилитами **`dig`** или **`nslookup`**.
