## Что такое сокет

**Сокет** (socket) – это программный интерфейс операционной системы, представляющий собой конечную точку сетевого соединения: комбинацию IP-адреса и порта, через которую приложение отправляет и принимает данные по сети. Всё сетевое взаимодействие – HTTP-запрос, соединение с базой данных, WebSocket – в итоге сводится к работе с сокетами на более низком уровне; библиотеки вроде `requests` или `httpx` просто скрывают эту работу за удобным интерфейсом.

Модуль **`socket`** в стандартной библиотеке Python даёт прямой доступ к этому механизму.

---

## TCP-сервер: пошаговый протокол

Создание TCP-сервера всегда проходит через одну и ту же последовательность вызовов:

```python
import socket

server = socket.socket(socket.AF_INET, socket.SOCK_STREAM)

server.bind(('localhost', 8080))  # привязываем сокет к адресу и порту
server.listen(5)  # переходим в режим ожидания подключений,

print('Сервер слушает на порту 8080...')

conn, addr = server.accept()  # блокируется, пока не подключится клиент
print(f'Подключился клиент: {addr}')  # напечатает: Подключился клиент: ('127.0.0.1', 54321)

data = conn.recv(1024)  # получаем до 1024 байт от клиента
print(f'Получено: {data.decode()}')  # напечатает: Получено: Hello from client!

conn.send(b'Hello from server!')  # отправляем ответ клиенту

conn.close()
server.close()
```

`bind()` – привязка сокета к конкретному сетевому адресу и порту. `listen()` – перевод сокета в пассивный режим, готовый принимать входящие подключения. `accept()` – блокирующий вызов, который ждёт подключения клиента и возвращает новый сокет `conn` для общения именно с этим клиентом (исходный `server`-сокет продолжает слушать новые подключения).

## TCP-клиент

```python
import socket

client = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
client.connect(('localhost', 8080))  # устанавливаем соединение с сервером

client.send(b'Hello from client!')
response = client.recv(1024)
print(f'Ответ сервера: {response.decode()}')  # напечатает: Ответ сервера: Hello from server!

client.close()
```

`connect()` инициирует TCP-рукопожатие с сервером по указанному адресу и порту. После установки соединения клиент и сервер обмениваются данными через `send()`/`recv()` – именно на этом уровне TCP-соединение (см. тему про TCP vs UDP) превращается в реальный обмен байтами между двумя процессами.

---

## Данные передаются как байты

Обратите внимание: `send()` принимает объект `bytes` (`b'...'`), а не строку – сокеты работают на уровне сырых байтов, а не текста. Строку нужно явно закодировать перед отправкой (`'text'.encode()`) и декодировать после получения (`data.decode()`). Это отличает низкоуровневую работу с сокетами от привычной работы со строками в Python.

## UDP-сокет: без `listen()`/`accept()`/`connect()`

```python
import socket

server = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)  # SOCK_DGRAM – UDP
server.bind(('localhost', 9090))

data, addr = server.recvfrom(1024)  # получить датаграмму и адрес отправителя
print(f'От {addr}: {data.decode()}')  # напечатает: От ('127.0.0.1', 54321): Hello from client!
server.sendto(b'ACK', addr)  # отправить ответ конкретному отправителю
```

У UDP-сокета нет соединения – нет `listen()`, `accept()`, `connect()`. Каждая датаграмма самодостаточна, и `recvfrom()`/`sendto()` всегда явно работают с адресом отправителя/получателя, потому что соединение как таковое не устанавливается (см. тему про TCP vs UDP).

## Неблокирующий режим

По умолчанию вызовы вроде `accept()` и `recv()` блокируют выполнение программы, пока не произойдёт событие. Для обработки нескольких соединений без создания отдельного потока на каждое используют неблокирующий режим:

```python
server.setblocking(False)
```

После этого вызовы, которые не могут выполниться немедленно, бросают исключение `BlockingIOError` вместо ожидания – программа сама решает, что делать дальше (повторить попытку позже, переключиться на другое соединение). На этом принципе строятся модули `selectors` и `asyncio` – вместо блокировки на одном соединении событийный цикл переключается между множеством сокетов.

## Практическое значение

Понимание сокетов на низком уровне объясняет, что происходит «под капотом» у `requests`, драйверов баз данных, WebSocket-библиотек. На собеседовании часто спрашивают про разницу `bind`/`listen`/`accept`/`connect`, про блокирующий и неблокирующий режимы, и про то, почему `asyncio` эффективен именно для сетевого I/O – ответ связан напрямую с тем, что сокеты умеют работать в неблокирующем режиме.
