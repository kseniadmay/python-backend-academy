## Что такое сокет

**Сокет** (*socket*) — это программный интерфейс ОС, представляющий конечную точку сетевого соединения (пару IP-адреса и порта), через которую приложение отправляет и получает данные.

Любое сетевое взаимодействие (`requests`, `httpx`, драйверы БД, WebSocket) под капотом работает через сокеты.

Модуль **`socket`** в стандартной библиотеке Python даёт прямой доступ к этому уровню.

---

## TCP-сервер: пошаговый протокол

Создание классического блокирующего TCP-сервера всегда проходит через одну цепочку вызовов:

```python
import socket

server = socket.socket(
    socket.AF_INET,
    socket.SOCK_STREAM,
)
server.bind(('localhost', 8080))
server.listen(5)

conn, addr = server.accept()
data = conn.recv(1024)
print(f'Получено: {data.decode()}')
# >>> Получено: Hello from client!

conn.send(b'Hello from server!')
conn.close()
server.close()
```

Вызов `bind()` закрепляет порт, `listen()` включает приём подключений, а `accept()` ждёт клиента и выдаёт отдельный сокет `conn` для общения именно с ним.

## TCP-клиент и передача сырых байтов

Сокеты работают строго на уровне байтов `bytes` (`b'...'`), поэтому строки перед отправкой кодируют через `.encode()`, а после получения декодируют через `.decode()`:

```python
import socket

client = socket.socket(
    socket.AF_INET,
    socket.SOCK_STREAM,
)
client.connect(('localhost', 8080))

# Отправляем сырые байты и ждём ответ
client.send(b'Hello from client!')
response = client.recv(1024)
print(f'Ответ: {response.decode()}')
# >>> Ответ: Hello from server!

client.close()
```

Вызов `connect()` инициирует TCP-рукопожатие, после чего процессы обмениваются потоком байтов через `send()` и `recv()`.

## UDP-сокет: без `listen()`, `accept()` и `connect()`

У UDP нет постоянного соединения, поэтому каждая датаграмма самодостаточна и передаётся методами `recvfrom()` и `sendto()` с явным адресом:

```python
import socket

server = socket.socket(
    socket.AF_INET,
    socket.SOCK_DGRAM,
)
server.bind(('localhost', 9090))

data, addr = server.recvfrom(1024)
print(f'От {addr}: {data.decode()}')
# >>> От ('127.0.0.1', 54321): Hello UDP!

server.sendto(b'ACK', addr)
```

## Неблокирующий режим и практическое значение

По умолчанию `accept()` и `recv()` блокируют поток, пока по сети не придут данные.

Чтобы обслуживать тысячи соединений без отдельного потока на каждого клиента, сокет переводят в неблокирующий режим:

```python
server.setblocking(False)
```

Если данных ещё нет, такой сокет вместо ожидания сразу бросает `BlockingIOError` — именно на этом механизме работают `selectors` и цикл событий `asyncio` в асинхронном бэкенде.

## `SO_REUSEADDR`, таймауты, `sendall()` и подход Junior vs Senior

При работе с сокетами в Python на собеседованиях и на практике проверяют три критичных детали:

1. **`send()` vs `sendall()`:** низкоуровневый `sock.send(data)` может записать в сетевой буфер ОС лишь **часть байтов** и вернуть их количество. Чтобы гарантированно отправить весь массив байтов, используют **`sock.sendall(data)`**.
2. **`SO_REUSEADDR`:** при перезапуске сервера предыдущий сокет остаётся в состоянии `TIME_WAIT`, и повторный `bind()` падает с `OSError: Address already in use`. Флаг `SO_REUSEADDR` разрешает немедленно переиспользовать порт.
3. **Таймауты и `with`:** без `settimeout()` метод `recv()` может зависнуть навсегда при обрыве кабеля у клиента, а менеджер `with socket.socket(...) as s:` гарантированно освободит файловый дескриптор.

```python
import socket

with socket.socket(
    socket.AF_INET,
    socket.SOCK_STREAM,
) as s:
    # Быстрый рестарт на том же порту
    s.setsockopt(
        socket.SOL_SOCKET,
        socket.SO_REUSEADDR,
        1,
    )
    # Защита от вечного зависания
    s.settimeout(5.0)
    print(s.gettimeout())
    # >>> 5.0
```

> **Junior vs Senior**:
> - **Junior**: Вызывает `sock.send()` для крупных ответов (теряя хвост данных), оставляет `recv()` без таймаута и забывает `with`, провоцируя утечку файловых дескрипторов ОС.
> - **Senior**: Оборачивает сокеты в `with`, ставит `settimeout()`, отправляет буфер через `sendall()`, включает `SO_REUSEADDR` на серверном сокете и использует неблокирующие сокеты/асинхронность под высокой нагрузкой.
