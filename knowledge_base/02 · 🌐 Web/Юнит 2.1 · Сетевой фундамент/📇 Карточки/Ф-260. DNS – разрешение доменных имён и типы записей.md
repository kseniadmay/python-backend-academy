1. Какую задачу решает система DNS (Domain Name System)? >> Переводит человекочитаемые доменные имена (`example.com`) в IP-адреса (`93.184.216.34`), которые нужны сетевому уровню для маршрутизации пакетов
2. В каком порядке клиент ищет IP-адрес домена перед отправкой запроса в интернет? >> 1) Кэш браузера → 2) Системный кэш ОС и файл `/etc/hosts` → 3) Рекурсивный DNS-резолвер провайдера (или `8.8.8.8` / `1.1.1.1`)
3. Опишите иерархию DNS-серверов при полном рекурсивном поиске `api.example.com`. >> Рекурсивный резолвер по очереди опрашивает: 1) Корневой сервер (Root `.`) → 2) Сервер зоны верхнего уровня (TLD `.com`) → 3) Авторитетный сервер домена (`example.com`)
4. Чем отличается рекурсивный DNS-запрос от итеративного? >> При рекурсивном запросе клиент ждёт от резолвера готовый IP-адрес; при итеративном — сервер возвращает ссылку («спроси у следующего сервера NS»), и поиск продолжает сам резолвер
5. За что отвечают DNS-записи типов `A` и `AAAA`? >> Запись `A` связывает доменное имя с IPv4-адресом (32 бита); запись `AAAA` — с IPv6-адресом (128 бит)
6. Что такое DNS-запись `CNAME` (Canonical Name) и какое у неё важное ограничение? >> Это алиас (псевдоним), перенаправляющий одно доменное имя на другое (`www.example.com` → `example.com`); `CNAME` нельзя ставить на корневой домен зоны (Zone Apex, `@`) вместе с `MX`/`SOA`
7. Для чего используются DNS-записи `MX`, `TXT` и `NS`? >> `MX` указывает почтовые серверы домена; `TXT` хранит произвольный текст (подтверждение владения доменом, SPF/DKIM для защиты почты); `NS` указывает авторитетные DNS-серверы зоны
8. Что такое `TTL` (Time To Live) в DNS-записи и зачем его снижают перед миграцией сервера? >> Время в секундах, в течение которого резолверы и клиенты кэшируют ответ. Перед сменой IP сервера `TTL` заранее снижают (например, до 60–300 с), чтобы новый IP распространился почти мгновенно
9. По какому транспортному протоколу и порту по умолчанию работает DNS и когда он переключается на TCP? >> По умолчанию UDP порт 53 (быстрый запрос-ответ в 1 пакет); переключается на TCP порт 53, если ответ превышает 512 байт (без EDNS0) или при передаче зон между серверами (AXFR)
10. Что такое DNS Round Robin и почему он не заменяет полноценный Load Balancer? >> Возврат нескольких `A`-записей для одного домена по кругу; минус в том, что DNS не проверяет живость серверов (Health Check), и клиенты будут продолжать стучаться на упавший IP, пока не истечёт `TTL`
11. Какие уязвимости есть у классического DNS и как их решают DoH и DoT? >> Классический DNS передаётся в открытом виде (уязвим к перехвату и DNS Spoofing); DNS over HTTPS (DoH, порт 443) и DNS over TLS (DoT, порт 853) шифруют DNS-трафик
12. Какая функция стандартной библиотеки Python используется для разрешения доменного имени в IP-адреса? >> `socket.getaddrinfo(host, port)` (поддерживает и IPv4, и IPv6) или `socket.gethostbyname(host)` (только IPv4)
