1. Что такое сетевой сокет (Socket) с точки зрения операционной системы? >> Программная конечная точка (абстракция файлового дескриптора ОС) для отправки и чтения данных по сети, однозначно определяемая парой `(IP-адрес, порт)` и протоколом
2. Что означают константы `socket.AF_INET` и `socket.AF_INET6` при создании сокета в Python? >> Семейство сетевых адресов (Address Family): `AF_INET` — IPv4, `AF_INET6` — IPv6
3. Чем отличается сокет `socket.SOCK_STREAM` от `socket.SOCK_DGRAM`? >> `SOCK_STREAM` создаёт потоковый TCP-сокет с установкой соединения; `SOCK_DGRAM` создаёт дейтаграммный UDP-сокет без соединения
4. Назовите последовательность методов жизненного цикла серверного TCP-сокета в Python. >> `socket()` → `bind((host, port))` → `listen(backlog)` → `accept()` → `recv()` / `send()` (`sendall()`) → `close()`
5. Почему метод `accept()` серверного TCP-сокета возвращает кортеж `(conn, addr)` с новым сокетом `conn`? >> Исходный сокет остаётся только слушающим (принимает новые подключения на порту), а для общения с каждым конкретным клиентом ОС выделяет отдельный клиентский сокет `conn`
6. В чём разница между привязкой сервера к `127.0.0.1` (`localhost`) и `0.0.0.0`? >> `127.0.0.1` принимает подключения только с этой же машины (loopback); `0.0.0.0` слушает все сетевые интерфейсы машины (обязательно внутри Docker-контейнера, чтобы порт был доступен снаружи)
7. Почему в TCP-сокете один вызов `sock.recv(4096)` не гарантирует получение всего сообщения целиком? >> TCP — это поток байтов без границ сообщений: `recv(4096)` возвращает столько байт, сколько сейчас успело прийти в буфер ОС (от 1 до 4096 байт)
8. Что означает ситуация, когда `sock.recv(1024)` возвращает пустую байтовую строку `b''`? >> Противоположная сторона корректно закрыла TCP-соединение (пришёл пакет `FIN`); если не выйти из цикла чтения, возникнет бесконечный цикл
9. Чем `sock.sendall(data)` безопаснее `sock.send(data)` в Python? >> `send()` может отправить только часть буфера и возвращает число отправленных байт; `sendall()` в цикле досылает данные до тех пор, пока не отправит весь буфер или не возникнет ошибка
10. Зачем серверному сокету включают опцию `SO_REUSEADDR` перед `bind()`? >> Чтобы при перезапуске сервера сразу занять тот же порт, не дожидаясь окончания состояния `TIME_WAIT` от старых соединений (`Address already in use`)
11. Чем неблокирующий сокет (`sock.setblocking(False)`) отличается от блокирующего? >> Вызовы `recv()` / `send()` не усыпляют поток в ожидании сети, а мгновенно выбрасывают `BlockingIOError`, если данных нет; это основа работы `asyncio` и мультиплексирования (`epoll` / `kqueue`)
12. Какие диапазоны номеров портов существуют в ОС? >> `0–1023` — системные (привилегированные: 80 HTTP, 443 HTTPS, 22 SSH, 5432 PostgreSQL); `1024–49151` — пользовательские/зарегистрированные; `49152–65535` — динамические (эфемерные порты клиента)
