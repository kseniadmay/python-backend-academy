1. Какая технология обеспечивает безопасность HTTP и на каком уровне сетевой модели она работает? >> TLS-шифрование; HTTP + TLS = HTTPS
2. Первое сообщение клиента при TLS Handshake? >> `ClientHello` ; содержит поддерживаемые версии TLS и алгоритмы шифрования
3. Как соотносятся TLS и SSL? >> TLS – современный преемник SSL; SSL считается небезопасным
4. Кем выдаются доверенные SSL-сертификаты? >> Доверенными центрами сертификации (CA): Comodo, DigiCert, Let's Encrypt
5. В каком виде передаются данные по HTTP? >> В открытом виде; любой посредник может их прочитать
6. Что видит злоумышленник при перехвате HTTPS-трафика? >> Только зашифрованные данные
7. Что сервер отвечает на `ClientHello` ? >> `ServerHello` + SSL-сертификат с публичным ключом
8. Почему сессионный ключ симметричный, а не асимметричный? >> Симметричное шифрование значительно быстрее; асимметричное используется только для безопасной передачи сессионного ключа
9. Происходит ли TLS Handshake при каждой отправке данных? >> Нет; только при установке соединения
10. Для чего используется публичный ключ в сертификате? >> Клиент шифрует данные публичным ключом; расшифровать может только сервер с соответствующим приватным ключом
11. Что такое MITM-атака? >> Man-in-the-Middle – злоумышленник перехватывает трафик между клиентом и сервером; HTTPS защищает от неё через шифрование и проверку сертификата
12. Что подтверждает SSL-сертификат? >> Что сервер является тем за кого себя выдаёт
13. Как называется процесс установки защищённого соединения? >> TLS Handshake
14. Три гарантии HTTPS? >> Шифрование (данные нельзя прочитать), целостность (данные не изменены), аутентификация (сервер не поддельный)
15. В чём разница асимметричного и симметричного шифрования в TLS? >> Асимметричное (публичный/приватный ключ) используется только при Handshake для безопасного обмена; симметричное (сессионный ключ) – для всей последующей передачи данных как более быстрое
16. Почему передача токенов по HTTP опасна? >> Токены передаются в открытом виде и могут быть перехвачены
17. Три примера данных уязвимых при HTTP? >> Пароли, токены, личные данные
18. Что содержит SSL-сертификат? >> Публичный ключ сервера и данные подтверждающие его идентичность
19. Для чего устанавливается сессионный ключ? >> Для симметричного шифрования всех данных после Handshake
20. Кто может прочитать HTTP-трафик? >> Любой субъект между клиентом и сервером: провайдер, прокси, злоумышленник
21. Расшифровка SSL? >> Secure Sockets Layer
22. Роль Let's Encrypt? >> Бесплатная автоматическая выдача SSL-сертификатов
23. Как клиент проверяет подлинность сертификата? >> Через цепочку доверия: проверяет подпись CA до корневого сертификата которому браузер уже доверяет
24. Расшифровка TLS? >> Transport Layer Security
