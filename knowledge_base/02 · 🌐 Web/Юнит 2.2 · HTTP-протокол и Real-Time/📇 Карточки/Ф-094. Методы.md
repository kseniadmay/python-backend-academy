1. Где и в каком формате передаются параметры в HTTP GET-запросе? >> В URL: `GET /users?page=1&limit=10`
2. Какой метод предназначен для получения ресурса? >> `GET`
3. Почему `POST` не идемпотентен? >> Два одинаковых запроса создадут две разные записи
4. Что произойдёт если отправить `PUT` с неполным объектом? >> Ресурс будет заменён неполным объектом; недостающие поля могут быть стёрты
5. Единственный метод из `GET` , `POST` , `PUT` , `DELETE` , `PATCH` не являющийся ни безопасным, ни идемпотентным? >> `POST`
6. Почему результаты `GET` кэшируются браузером? >> Метод безопасный и идемпотентный; одинаковый запрос всегда даёт одинаковый результат
7. Является ли `PATCH` строго идемпотентным? >> Нет; зависит от реализации; повторный запрос может изменить состояние повторно
8. Является ли `PUT` идемпотентным? >> Да; повторный запрос с теми же данными даёт тот же результат
9. Для чего используется `PATCH` ? >> Частичное обновление ресурса; передаются только изменяемые поля
10. Основная задача `PUT` ? >> Полная замена существующего ресурса; нужно передать весь объект целиком
11. Какой заголовок в ответе `HEAD` позволяет узнать тип контента? >> `Content-Type`
12. Какой метод экономнее при частичном обновлении большой записи? >> `PATCH`
13. Почему `404` при повторном `DELETE` не нарушает идемпотентность? >> Состояние системы не изменилось по сравнению с первым успешным удалением
14. Какие методы одновременно безопасны и идемпотентны? >> `GET` , `HEAD` , `OPTIONS` , `TRACE`
15. Почему `POST` не кэшируется? >> Изменяет состояние сервера; ответы зависят от контекста
16. Почему `DELETE` считается идемпотентным? >> Конечное состояние системы (отсутствие ресурса) не меняется при повторных вызовах
17. Какой метод используется для создания нового ресурса? >> `POST`
18. Верно ли что все безопасные методы идемпотентны? >> Да
19. Что описывают HTTP-методы? >> Намерение запроса – что клиент хочет сделать с ресурсом
20. В чём разница между безопасным и идемпотентным методом? >> Безопасный – не изменяет состояние сервера; идемпотентный – повторные вызовы дают тот же результат; безопасный всегда идемпотентен, но не наоборот ( `DELETE` – идемпотентен, но не безопасен)
21. Что такое `OPTIONS` ? >> Метод для получения информации о поддерживаемых методах для данного URL
22. Когда использовать `HEAD` ? >> Для проверки существования ресурса, получения метаданных или проверки URL без загрузки контента
23. Где передаются данные в `POST` -запросе? >> В теле запроса (Body)
24. Какой риск несёт повторная отправка `POST` при сбое сети? >> Создание дублирующих записей на сервере
25. Может ли `PUT` изменить только одно поле? >> Нет; `PUT` заменяет объект целиком; для частичного обновления – `PATCH`
26. Что делает `DELETE` ? >> Удаляет указанный ресурс
27. Может ли `POST` быть безопасным? >> Нет; он изменяет данные на сервере
28. В чём отличие `HEAD` от `GET` ? >> `HEAD` возвращает только заголовки без тела ответа
29. Какое свойство `GET` гарантирует что он не изменяет данные? >> Безопасность
30. Какие небезопасные методы идемпотентны? >> `PUT` и `DELETE`
31. Что такое preflight-запрос? >> Автоматический `OPTIONS` -запрос браузера перед CORS-запросом для проверки разрешений сервера
