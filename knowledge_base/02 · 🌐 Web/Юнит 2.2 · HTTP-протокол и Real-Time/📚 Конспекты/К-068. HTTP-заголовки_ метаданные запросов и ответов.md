## Что такое заголовки и зачем они нужны

**HTTP-заголовки** – это метаданные, которые сопровождают каждый запрос и ответ. Они описывают формат данных, идентификацию клиента, правила кеширования, права доступа и многое другое. Без заголовков сервер не знал бы, как интерпретировать входящий поток байтов: это JSON, изображение или HTML?

---

## Согласование формата: `Content-Type` и `Accept`

**`Content-Type`** указывает формат данных в теле сообщения.

**`Accept`** сообщает серверу, какие форматы клиент готов принять.

`application/json` – стандарт современных API.

`multipart/form-data` – загрузка файлов: необходим для передачи бинарных данных.

`application/x-www-form-urlencoded` – стандартный формат HTML-форм, данные передаются как `key=value`.

`text/html; charset=utf-8` – HTML-страница с указанием кодировки.

`Accept` может содержать приоритеты: `Accept: text/html, application/json;q=0.9` означает «предпочитаю HTML, но JSON тоже подойдёт с весом 0.9». Это позволяет клиенту гибко согласовывать формат с сервером.

Если сервер не может вернуть ни один из запрошенных форматов, он должен ответить `406 Not Acceptable`.

## Аутентификация: заголовок `Authorization`

**`Authorization`** – это удостоверение личности, которое клиент предъявляет серверу при каждом запросе.

**Bearer-токен** – самый распространённый метод в современных API. Используется для передачи JWT:

`Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...`

**Basic-аутентификация** – логин и пароль, закодированные в Base64:

`Authorization: Basic dXNlcjpwYXNz`

Base64 – это кодирование, а не шифрование. Basic безопасен только внутри HTTPS-соединения: по HTTP логин и пароль тривиально расшифровываются.

**API-токен** – простой способ аутентификации сервисов:

`Authorization: Token abc123def456`

## Кеширование: `Cache-Control` и `ETag`

**`Cache-Control`** управляет тем, как и как долго браузер и промежуточные прокси кешируют ответ.

`no-cache` означает «проверяй актуальность перед каждым использованием».

`max-age=3600` устанавливает срок жизни кеша в секундах.

`no-store` запрещает сохранять данные где-либо – используется для чувствительных данных: банковские транзакции, личные данные.

**`ETag`** – уникальный идентификатор версии ресурса, работающий как штрихкод файла. Механизм: сервер отправляет ресурс с заголовком `ETag: "abc123"`. При следующем запросе браузер добавляет `If-None-Match: "abc123"`. Если ресурс не изменился, сервер возвращает `304 Not Modified` без тела ответа. Клиент использует кешированную копию. Аналогично работает пара `Last-Modified` / `If-Modified-Since`, но ETag точнее – он основан на содержимом, а не на времени.

## CORS: безопасность кросс-доменных запросов

**CORS** (Cross-Origin Resource Sharing) – механизм браузера, который запрещает JavaScript с одного домена без явного разрешения обращаться к ресурсам другого.

Браузер автоматически добавляет заголовок `Origin` к запросам на другой домен. Сервер решает, доверять ли этому источнику, и возвращает заголовки разрешений.

`Access-Control-Allow-Origin` указывает, каким доменам разрешён доступ – конкретный домен или `*` для всех.

`Access-Control-Allow-Methods` перечисляет разрешённые HTTP-методы.

`Access-Control-Allow-Headers` – разрешённые заголовки запроса.

`Access-Control-Allow-Credentials: true` разрешает передачу куки.

Для «небезопасных» запросов (с телом, нестандартными методами или заголовками) браузер предварительно отправляет **preflight-запрос** методом `OPTIONS`. Только получив разрешение, он выполняет основной запрос. Ошибка CORS в консоли браузера почти всегда означает, что сервер неправильно обрабатывает `OPTIONS` или не возвращает нужные заголовки `Access-Control-Allow-*`.

## Технические заголовки: отладка и трейсинг

**`User-Agent`** содержит информацию о браузере, операционной системе и устройстве клиента. Используется для аналитики, адаптации контента и иногда – для защиты от ботов.

**`X-Request-ID`** – уникальный идентификатор запроса, который проставляется при входе в систему и передаётся через все сервисы по цепочке. В распределённых системах с несколькими микросервисами это позволяет по одному ID восстановить полную картину прохождения запроса через все слои в логах. Без него найти причину ошибки в цепочке вызовов значительно сложнее.
