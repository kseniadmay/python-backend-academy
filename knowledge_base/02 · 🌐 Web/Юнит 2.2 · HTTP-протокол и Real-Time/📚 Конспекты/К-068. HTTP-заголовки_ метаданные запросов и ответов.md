## Роль заголовков: метаданные протокола HTTP

**HTTP-заголовки (Headers)** — пары `Ключ: Значение`, определяющие контекст сетевого взаимодействия: форматы данных, авторизацию, кэширование и правила безопасности.

- Имена заголовков **нечувствительны к регистру** (`Content-Type` эквивалентно `content-type` по RFC 7230, в HTTP/2 передаются строго в нижнем регистре).
- Заголовки отделяются от тела ответа пустой строкой `\r\n\r\n`.

```http
GET /api/v1/profile HTTP/1.1
Host: api.example.com
User-Agent: MyApp/2.4
Accept: application/json
Authorization: Bearer eyJhbGciOi...
```

## Согласование содержимого: Content-Type и Accept

Механизм **Content Negotiation** позволяет клиенту и серверу договариваться о представлении ресурса:

- **`Content-Type`:** сообщает тип данных в **теле текущего сообщения** (MIME-тип).
  * `application/json` — тело в формате JSON;
  * `application/x-www-form-urlencoded` — веб-формы `key1=val1&key2=val2`;
  * `multipart/form-data; boundary=...` — загрузка бинарных файлов и смешанных данных.
- **`Accept`:** сообщает серверу, какой формат ответа ожидает клиент (`Accept: application/json, text/plain; q=0.9`). Если сервер не может отдать указанный формат, он возвращает `406 Not Acceptable`.

## Аутентификация и сессии: Authorization и Cookie

- **`Authorization`:** передает учетные данные клиента:
  * `Authorization: Bearer <JWT_TOKEN>` — бессрочный или access-токен (OAuth 2.0 / JWT);
  * `Authorization: Basic <base64(login:pass)>` — базовый парольный доступ.
- **`Cookie` и `Set-Cookie`:** механизм сохранения состояния:
  * Сервер отправляет `Set-Cookie: session_id=abc42; HttpOnly; Secure; SameSite=Strict`.
  * Браузер автоматически прикрепляет заголовок `Cookie: session_id=abc42` к каждому следующему запросу к данному домену.

## Управление кэшированием: Cache-Control, ETag, Last-Modified

- **`Cache-Control`:** ключевой заголовок политик кэширования:
  * `max-age=3600` — кэшировать ответ на 1 час;
  * `no-cache` — обязательно перепроверять актуальность на сервере перед отдачей из кэша;
  * `no-store` — категорический запрет сохранять ответ в кэше (для банковских и секретных данных).
- **Валидация кэша (`ETag` и `If-None-Match`):** сервер отправляет хэш ресурса `ETag: "v3a1"`. При следующем запросе клиент отправляет `If-None-Match: "v3a1"`. Если ресурс не менялся, сервер отвечает легковесным `304 Not Modified` без передачи тела.

## Безопасность и маршрутизация: CORS, HSTS и прокси

- **`Origin`:** отправляется браузером при кросс-доменных запросах (схема, хост и порт источника).
- **`Strict-Transport-Security` (HSTS):** заставляет браузер обращаться к сайту исключительно по HTTPS (`max-age=31536000; includeSubDomains`).
- **Служебные заголовки за обратным прокси:** при работе за Nginx реальный IP клиента скрывается за IP прокси. Nginx пробрасывает заголовки:
  * `X-Forwarded-For: <client_ip>, <proxy_ip>` — цепочка адресов;
  * `X-Real-IP: <client_ip>` — прямой IP клиента;
  * `X-Forwarded-Proto: https` — исходный протокол шифрования.
