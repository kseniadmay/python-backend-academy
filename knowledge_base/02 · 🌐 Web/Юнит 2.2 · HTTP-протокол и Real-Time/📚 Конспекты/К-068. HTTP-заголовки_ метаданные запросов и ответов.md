## Роль заголовков: метаданные протокола HTTP

**HTTP-заголовки (Headers)** — пары `Ключ: Значение`, задающие контекст запроса и ответа: формат тела, авторизацию, кэширование и безопасность.

Имена заголовков нечувствительны к регистру (`Content-Type` эквивалентно `content-type`), а сам блок заголовков отделяется от тела пустой строкой `\r\n\r\n`:

```http
GET /api/v1/profile HTTP/1.1
Host: api.example.com
User-Agent: MyApp/2.4
Accept: application/json
Authorization: Bearer eyJhbGciOi...
```

В стандартной библиотеке Python объект `HTTPMessage` хранит заголовки с поиском без учёта регистра:

```python
from http.client import HTTPMessage

headers = HTTPMessage()
headers['Content-Type'] = 'application/json'
headers['Authorization'] = 'Bearer token42'

# Поиск не зависит от регистра букв
print(headers.get('content-type'))
# >>> application/json

print(headers.get('AUTHORIZATION'))
# >>> Bearer token42
```

## Согласование содержимого: `Content-Type` и `Accept`

Механизм **Content Negotiation** позволяет клиенту и серверу договориться о формате передаваемых данных.

Заголовок **`Content-Type`** описывает MIME-тип в теле **текущего сообщения**:

- `application/json` — структурированные данные JSON;
- `application/x-www-form-urlencoded` — веб-формы `key1=val1&key2=val2`;
- `multipart/form-data; boundary=...` — загрузка файлов и бинарных полей.

Заголовок **`Accept`** сообщает серверу, какой формат ответа ожидает клиент (`Accept: application/json`); если сервер не умеет его отдать, возвращается `406 Not Acceptable`.

## Аутентификация и сессии: `Authorization` и `Cookie`

Заголовок **`Authorization`** передаёт учётные данные клиента на каждый запрос:

- `Authorization: Bearer <JWT_TOKEN>` — предъявительский токен (JWT / OAuth 2.0);
- `Authorization: Basic <base64(login:pass)>` — базовая аутентификация по логину и паролю.

Механизм **`Set-Cookie`** и **`Cookie`** сохраняет сессию между запросами:

- Сервер задаёт куку: `Set-Cookie: session_id=abc42; HttpOnly; Secure; SameSite=Strict`.
- Браузер сохраняет её и автоматически прикрепляет `Cookie: session_id=abc42` к следующим запросам этого домена.

## Управление кэшированием: `Cache-Control` и `ETag`

Заголовок **`Cache-Control`** задаёт политику сохранения ответа в кэше браузера и CDN:

- `max-age=3600` — кэшировать ответ на 1 час без перепроверки;
- `no-cache` — проверять актуальность на сервере перед отдачей из кэша;
- `no-store` — полностью запретить сохранение (для банковских и секретных данных).

Для быстрой валидации применяют хэш **`ETag`** (`If-None-Match`) или время **`Last-Modified`** (`If-Modified-Since`): если ресурс не менялся, сервер отвечает пустым `304 Not Modified`.

## Безопасность и заголовки за обратным прокси

Заголовок **`Origin`** браузер добавляет при кросс-доменных запросах, а **`Strict-Transport-Security` (HSTS)** принуждает клиент общаться только по HTTPS (`max-age=31536000`).

При работе приложения за обратным прокси (Nginx) реальный адрес клиента скрывается за IP прокси, поэтому балансировщик добавляет служебные заголовки:

- `X-Forwarded-For: <client_ip>, <proxy_ip>` — цепочка адресов от клиента через прокси;
- `X-Real-IP: <client_ip>` — исходный IP клиента;
- `X-Forwarded-Proto: https` — схема (`http` или `https`), по которой подключился клиент.
