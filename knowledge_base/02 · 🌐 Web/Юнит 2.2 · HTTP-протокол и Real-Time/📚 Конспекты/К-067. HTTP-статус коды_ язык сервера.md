## Архитектура статус-кодов: 5 классов ответов

Статус-код ответа HTTP состоит из 3 цифр. Первая цифра строго определяет семантический класс взаимодействия между клиентом и сервером:

- **`1xx` (Информационные):** запрос получен, процесс продолжается (`101 Switching Protocols` для WebSocket).
- **`2xx` (Успех):** действие клиента успешно принято, понято и обработано.
- **`3xx` (Перенаправление):** для завершения запроса клиент обязан совершить дополнительное действие (редирект или взятие из кэша).
- **`4xx` (Ошибка клиента):** синтаксическая ошибка в запросе, отсутствие прав или неверный ресурс.
- **`5xx` (Ошибка сервера):** сбой выполнения на стороне сервера или вышестоящего сервиса (upstream).

---

## Класс 2xx (Успех): 200, 201, 204

- **`200 OK`:** стандартный успешный ответ на чтение (`GET`), изменение (`PUT`, `PATCH`) или вычисление (`POST`). Возвращает тело с результатом.
- **`201 Created`:** запрос привел к созданию нового ресурса на сервере. Обязан сопровождаться заголовком `Location` с постоянным URL созданного объекта:

```http
HTTP/1.1 201 Created
Location: /api/v1/orders/8941
Content-Type: application/json

{"id": 8941, "status": "pending"}
```

- **`204 No Content`:** действие успешно выполнено, но тело ответа отсутствует. Стандарт для методов `DELETE` и обновлений, которым не требуется передавать пейлоад клиенту.

---

## Класс 3xx (Редиректы и кэш): 301, 302, 304, 307, 308

- **`301 Moved Permanently`:** ресурс навсегда перенесен на новый URL (заголовок `Location`). Поисковые системы переносят ссылочный вес, а браузеры намертво кэшируют редирект в локальном дисковом кэше.
- **`302 Found`:** временный редирект. Исторически браузеры ошибочно меняли метод `POST` на `GET` при переходе по ссылке.
- **`307 Temporary Redirect` vs `308 Permanent Redirect`:** современные строгие аналоги `302` и `301`, которые **гарантируют сохранение исходного HTTP-метода и тела** при повторном запросе по новому адресу.
- **`304 Not Modified`:** тело не передается. Ответ на условный запрос клиента (`If-None-Match: "etag_hash"`), сообщающий, что кэш браузера актуален.

---

## Класс 4xx (Ошибки клиента): 400, 401, 403, 404, 409, 422

- **`400 Bad Request`:** синтаксически невалидный запрос (битый JSON, некорректные символы заголовка).
- **`401 Unauthorized`:** **отсутствует или невалидна аутентификация** (пользователь не представился). Сервер обязан вернуть заголовок `WWW-Authenticate`.
- **`403 Forbidden`:** **авторизация отклонена** (пользователь распознан, но у него нет прав на данный ресурс). Повтор запроса с теми же данными бесполезен.
- **`404 Not Found`:** ресурс по указанному URI не существует.
- **`409 Conflict`:** конфликт бизнес-состояния (например, попытка создать пользователя с уже занятым email или оптимистическая блокировка версии документа).
- **`422 Unprocessable Entity`:** синтаксис верен, но нарушена семантика данных (стандартный ответ FastAPI при непрохождении валидации Pydantic).

---

## Класс 5xx (Ошибки сервера): 500, 502, 503, 504

- **`500 Internal Server Error`:** необработанное исключение внутри Python-кода (uncaught exception, разрыв соединения с СУБД).
- **`502 Bad Gateway`:** обратный прокси (Nginx/Traefik) получил недопустимый ответ или отказ соединения (Connection Refused) от приложения (Gunicorn/Uvicorn завершился аварийно или перегружен).
- **`503 Service Unavailable`:** сервер временно не готов обрабатывать трафик (плановые регламентные работы или исчерпание пула воркеров).
- **`504 Gateway Timeout`:** обратный прокси не дождался ответа от бэкенда за отведенный таймаут (`proxy_read_timeout` превышен из-за медленного SQL-запроса).

## Скрининг Junior+: ключевые пары сравнения

```text
401 vs 403:
- 401: "Кто ты? Предъяви токен!"
- 403: "Я знаю тебя, но прав нет!"

502 vs 504:
- 502: Nginx -> Uvicorn
  (сокет закрыт / авария воркера)
- 504: Nginx -> Uvicorn
  (таймаут ответа > 60 сек)
```

- **Безопасность продакшена:** никогда не возвращайте клиенту стектрейсы Python (`Traceback`) в теле `500` ошибок — это раскрывает пути, имена файлов и уязвимости системы злоумышленникам.
