## Защита транспортного уровня: HTTP поверх TLS

**HTTPS** — это обычный протокол HTTP, работающий внутри криптографического туннеля **TLS** по порту `443`.

Устаревший SSL (3.0) отключён, но термин «SSL-сертификат» остался по привычке; актуальные стандарты — **TLS 1.2** и **TLS 1.3**.

Туннель TLS даёт соединению три ключевые гарантии безопасности:

1. **Конфиденциальность (Encryption):** трафик зашифрован от прослушивания.
2. **Целостность (Integrity):** данные нельзя незаметно подменить по дороге.
3. **Аутентификация (Authentication):** клиент уверен, что общается с владельцем домена, а не со злоумышленником (MITM).

## Рукопожатие TLS Handshake: от асимметрии к симметрии

Шифрование строится на гибридной схеме: медленная асимметричная криптография работает только на старте для обмена общим ключом.

Затем весь поток данных шифруется быстрым симметричным шифром (`AES-GCM`, `ChaCha20`):

```text
Клиент                      Сервер
  │ ── ClientHello (TLS 1.3) ──> │
  │    (ciphers, KeyShare)       │
  │                              │
  │ <─ ServerHello + Cert ────── │
  │    (KeyShare, Handshake)     │
  │                              │
  │ === Общий сессионный ключ ===│
  │ <── Симметричный трафик ───> │
```

На шагах `ClientHello` и `ServerHello` стороны согласуют шифр и вычисляют общий ключ; в **TLS 1.3** весь handshake занимает ровно **1-RTT** вместо 2-RTT в TLS 1.2.

## Сертификаты X.509 и цепочка доверия

Сертификат — это цифровой паспорт домена, подписанный удостоверяющим центром (**Certificate Authority, CA**):

```text
[Root CA (в ОС / браузере)]
       └── [Intermediate CA]
                 └── [api.example.com]
```

- ОС и браузер хранят список доверенных корневых сертификатов (**Trust Store**) и проверяют подпись каждого звена до корня.
- **Let's Encrypt** автоматически выдаёт бесплатные сертификаты через протокол ACME (`certbot`) с обновлением каждые 90 дней.

## Практика в Python: модуль `ssl` и проверка сертификатов

В продакшен-интеграциях со сторонними API критично сохранять строгую проверку подлинности сертификата и имени хоста:

```python
import ssl
import urllib.request

ctx = ssl.create_default_context()
ctx.check_hostname = True
ctx.verify_mode = ssl.CERT_REQUIRED

req = urllib.request.Request(
    'https://example.com'
)
with urllib.request.urlopen(
    req, context=ctx
) as r:
    payload = r.read()
    print('HTTPS status:', r.status)
    # >>> HTTPS status: 200
```

> ⚠️ Отключение проверки (`verify=False` в `requests`/`httpx`) открывает сервис для перехвата токенов любой машиной в сети.

## Вопросы скрининга: SNI и мифы об HTTPS

На собеседованиях часто проверяют две тонкости работы TLS в реальном вебе:

- **SNI (Server Name Indication):** расширение TLS, которое передаёт имя домена в открытом виде в `ClientHello`, чтобы один сервер и IP-адрес могли отдавать разные сертификаты для сотен сайтов.
- **Миф об абсолютной безопасности:** зелёный замок HTTPS защищает лишь *канал передачи*; владелец фишингового домена тоже может спокойно выпустить валидный сертификат Let's Encrypt.

## TLS Termination, HSTS, mTLS и подход Junior vs Senior

В продакшен-архитектуре Python-сервер (`uvicorn` / `gunicorn`) почти никогда не расшифровывает TLS сам:

- **TLS Termination (терминация TLS):** криптографию и сертификаты берёт на себя входной Reverse Proxy или балансировщик (Nginx, Envoy, Cloudflare) на порту `443`, а внутрь защищённой приватной сети запрос проксируется по HTTP с заголовком `X-Forwarded-Proto: https`.
- **HSTS (`Strict-Transport-Security`):** ответный HTTP-заголовок, приказывающий браузеру обращаться к домену **только по HTTPS** в течение заданного срока (защита от понижения протокола — *SSL-stripping*):

```http
Strict-Transport-Security:
  max-age=31536000; includeSubDomains
```

- **mTLS (*Mutual TLS*):** двусторонняя аутентификация, при которой сертификат предъявляет не только сервер, но и клиент — стандарт защиты межсервисного взаимодействия в банках и платёжных шлюзах.

> **Junior vs Senior**:
> - **Junior**: Отключает проверку сертификата (`verify=False`) в `httpx`/`requests` при ошибке SSL в продакшене или пытается настраивать сертификаты напрямую внутри воркеров Gunicorn.
> - **Senior**: Терминирует TLS на уровне Nginx/Ingress с автообновлением Let's Encrypt, включает заголовок `HSTS`, передаёт кастомный `ssl.SSLContext` для внутренних CA и использует mTLS для критичных контуров.
