## Защита транспортного уровня: HTTP поверх TLS

**HTTPS (HyperText Transfer Protocol Secure)** — это стандартный протокол HTTP, работающий через защищенный криптографический туннель **TLS (Transport Layer Security)** по TCP-порту 443.

- **SSL vs TLS:** SSL (Secure Sockets Layer) — устаревший предшественник (уязвимости POODLE, Heartbleed). Современные сервисы используют исключительно **TLS 1.2** и **TLS 1.3**. Термин «SSL» остался лишь как привычное торговое название сертификатов.
- **Три гарантии безопасности:**
  1. **Конфиденциальность (Encryption):** защита от прослушивания трафика (Eavesdropping).
  2. **Целостность (Integrity):** защита от незаметной модификации данных в пути (Tampering).
  3. **Аутентификация (Authentication):** гарантия того, что клиент общается с настоящим владельцем домена, а не с атакующим (MITM-атака).

## Рукопожатие TLS Handshake: от асимметрии к симметрии

Шифрование строится на гибридной модели: ресурсоемкая асимметричная криптография используется только для обмена общим секретом, а основной поток данных шифруется быстрым симметричным шифром (AES-GCM, ChaCha20).

```text
Клиент                      Сервер
  │ ── ClientHello (TLS 1.3) ──> │
  │    (ciphers, KeyShare)       │
  │                              │
  │ <─ ServerHello + Cert ────── │
  │    (KeyShare, Handshake)     │
  │                              │
  │ === Общий сессионный ключ ===│
  │ <── Симметричный трафик ───> │
```

1. **ClientHello:** клиент отправляет поддерживаемые версии TLS, наборы шифров (Cipher Suites) и свою часть открытого ключа (ECDHE).
2. **ServerHello:** сервер выбирает параметры, присылает сертификат открытого ключа и свою часть открытого ключа.
3. Обе стороны независимо вычисляют **симметричный сессионный ключ**. В TLS 1.3 рукопожатие занимает ровно **1-RTT** (1 сетевой оборот) против 2-RTT в старом TLS 1.2.

## Сертификаты X.509 и цепочка доверия (Chain of Trust)

Сертификат — это цифровой паспорт домена, подписанный доверенным удостоверяющим центром (Certificate Authority, CA):

```text
[Root CA (в ОС / браузере)]
       └── [Intermediate CA]
                 └── [api.example.com]
```

- Браузер и операционная система содержат встроенное хранилище доверенных корневых сертификатов (**Trust Store**).
- Клиент валидирует цифровую подпись каждого звена цепочки до доверенного корня.
- **Let's Encrypt:** некоммерческий CA, выдающий бесплатные доверенные сертификаты через автоматизированный протокол ACME (certbot), обновляемые каждые 90 дней.

## Практика в Python: модуль ssl и проверка сертификатов

В backend-приложениях при интеграции со сторонними API критично проверять валидность удаленных сертификатов:

```python
import ssl
import urllib.request

# Канонический безопасный контекст
ctx = ssl.create_default_context()
ctx.check_hostname = True
ctx.verify_mode = ssl.CERT_REQUIRED

req = urllib.request.Request(
    'https://api.example.com/data'
)
with urllib.request.urlopen(
    req, context=ctx
) as r:
    payload = r.read()
    print("HTTPS status:", r.status)
```

> ⚠️ Отключение проверки (`verify=False` в `requests`/`httpx`) открывает приложение для перехвата учетных данных любой машиной в локальной сети.

## Вопросы скрининга: SNI и мифы об HTTPS

- **SNI (Server Name Indication):** расширение TLS, передающее доменное имя запрашиваемого хоста в открытом виде на этапе ClientHello. Это позволяет одному серверу и IP-адресу хостить сотни сайтов с разными сертификатами.
- **Миф об абсолютной защите:** «Замочек HTTPS» гарантирует только шифрование канала между браузером и сервером. Он **не гарантирует**, что сам сайт не является фишинговым. Владелец фишингового домена может легко получить валидный сертификат Let's Encrypt.
