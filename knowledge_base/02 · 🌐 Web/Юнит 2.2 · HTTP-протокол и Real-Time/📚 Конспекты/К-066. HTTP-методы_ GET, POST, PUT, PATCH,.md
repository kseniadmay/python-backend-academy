## Семантика методов: Безопасность (Safety) и Идемпотентность (Idempotency)

HTTP-метод определяет действие над ресурсом. Архитектура HTTP базируется на двух фундаментальных свойствах:

- **Безопасность (Safety):** метод не изменяет состояние сервера и данных в БД (операция чтения). Безопасные методы (`GET`, `HEAD`, `OPTIONS`) можно вызывать без риска сайд-эффектов.
- **Идемпотентность (Idempotency):** повторный вызов запроса с теми же параметрами оставляет систему в том же конечном состоянии: $f(f(x)) = f(x)$.

| Метод | Назначение | Safe | Idempotent |
| :--- | :--- | :---: | :---: |
| `GET` | Чтение ресурса | ✅ Да | ✅ Да |
| `HEAD` | Только заголовки | ✅ Да | ✅ Да |
| `POST` | Создание сущности | ❌ Нет | ❌ Нет |
| `PUT` | Полная замена | ❌ Нет | ✅ Да |
| `PATCH` | Частичная дельта | ❌ Нет | ⚠️ Зависит |
| `DELETE` | Удаление ресурса | ❌ Нет | ✅ Да |
| `OPTIONS` | Доступные методы | ✅ Да | ✅ Да |

## Чтение ресурсов: методы GET и HEAD

Метод `GET` предназначен строго для выборки данных. Параметры запроса передаются в строке запроса (Query String).

```http
GET /api/v1/users?page=1&limit=20
Host: api.example.com
Accept: application/json
```

- **Кэшируемость:** `GET`-ответы нативно кэшируются браузерами, CDN и прокси-серверами через заголовки `Cache-Control` и `ETag`.
- **Метод `HEAD`:** возвращает идентичные `GET` заголовки ответа, но без тела (`Body`). Применяется для быстрой проверки существования ресурса, замера размера файла (`Content-Length`) или валидации кэша перед тяжелой загрузкой.

## Создание и замена: POST vs PUT

- **`POST` (не идемпотентен):** передает тело на сервер для создания подчиненного ресурса или запуска вычислений. Сервер сам генерирует идентификатор (URI) новой сущности. Повторный вызов создает вторую запись.

```http
POST /api/v1/orders
Content-Type: application/json

{"user_id": 42, "item_id": 105}
```

- **`PUT` (идемпотентен):** выполняет полную замену ресурса по явно указанному адресу. Клиент передает полное представление объекта.

```http
PUT /api/v1/users/42
Content-Type: application/json

{
  "name": "Alice Smith",
  "email": "alice@example.com",
  "role": "admin"
}
```

> **Важно:** если при `PUT` опустить поле `role`, в ресурсе оно будет стерто или сброшено в дефолт, так как это замена всей сущности целиком.

## Частичное обновление и удаление: PATCH vs DELETE

- **`PATCH` (дельта изменений):** передает только изменившиеся атрибуты сущности (стандарт JSON Merge Patch RFC 7396).

```http
PATCH /api/v1/users/42
Content-Type: application/json

{"email": "new_alice@example.com"}
```

- **Идемпотентность PATCH:** при передаче фиксированных значений (`{"status": "active"}`) PATCH идемпотентен. Но если тело содержит операцию инкремента (`{"balance": "+100"}`), повторный вызов изменит состояние снова — поэтому в RFC PATCH не гарантирует идемпотентность.
- **`DELETE` (идемпотентен):** удаляет ресурс по URI. Первый запрос вернет `204 No Content` или `200 OK`, повторный может вернуть `404 Not Found`, однако конечное состояние сервера идентично — ресурса нет.

## Служебные методы: OPTIONS и CORS Preflight

Метод `OPTIONS` опрашивает сервер о поддерживаемых методах и возможностях для указанного URI без выполнения полезного действия.

```http
OPTIONS /api/v1/orders
Host: api.example.com
```

Сервер возвращает допустимый список в заголовке `Allow`:
```http
HTTP/1.1 204 No Content
Allow: GET, POST, HEAD, OPTIONS
```

- **CORS Preflight:** браузер автоматически отправляет предварительный `OPTIONS`-запрос при кросс-доменных вызовах со сложными заголовками (`Authorization`) или небезопасными методами (`PUT`, `DELETE`, `PATCH`), чтобы подтвердить права перед реальной отправкой данных.

## Инженерные ловушки на собеседовании

- ❌ **Мутация через `GET` (`GET /users/delete?id=1`):** грубейшая ошибка архитектуры. Поисковые краулеры, префетч браузера или прокси-кэш сотрут базу данных простым сканированием ссылок.
- ❌ **Дубли транзакций при `POST`:** при сетевом сбое клиент повторяет `POST /payments`. Для защиты от двойного списания используется заголовок `Idempotency-Key` с сохранением статуса первой операции в Redis.
- ❌ **Путаница `PUT` и `PATCH`:** `PUT` требует полный пейлоад и перезаписывает документ целиком; `PATCH` принимает дельту.
