## Роль интерфейса шлюза: мост между Nginx и Python

Веб-серверы общего назначения (`Nginx`, `Caddy`) написаны на C/Go для быстрой отдачи статики и SSL-терминации, но не умеют напрямую вызывать функции Python.

**Server Gateway Interface** — это стандартный контракт передачи HTTP-запроса от сервера приложений (Uvicorn, Gunicorn) в ваш код:

```text
[Клиент]
  │ (HTTP)
  ▼
[Nginx]
  │ (UNIX socket)
  ▼
[Uvicorn / Gunicorn]
  │ (callable)
  ▼
[FastAPI / Django]
```

Шлюз разбирает сырые байты сокета в структуры Python и отправляет назад сгенерированный ответ.

## Синхронный стандарт WSGI (PEP 3333)

**WSGI** (*Web Server Gateway Interface*) работает как синхронная функция с двумя параметрами `environ` и `start_response`:

```python
def application(environ, start_response):
    status = '200 OK'
    headers = [
        ('Content-Type', 'text/plain')
    ]
    start_response(status, headers)
    return [b'Hello, WSGI World!']
```

Его главное ограничение — модель «один запрос на поток/процесс»: пока запрос ждёт SQL или внешний API, воркер заблокирован (Flask, синхронный Django).

## Асинхронный стандарт ASGI

**ASGI** (*Asynchronous Server Gateway Interface*) создан для `asyncio`, фоновых задач, SSE и долгоживущих WebSocket-соединений:

```python
async def application(scope, receive, send):
    if scope['type'] == 'http':
        await send({
            'type': 'http.response.start',
            'status': 200,
            'headers': [(
                b'content-type',
                b'text/plain',
            )],
        })
        await send({
            'type': 'http.response.body',
            'body': b'Hello, ASGI World!'
        })
```

- `scope` — словарь метаданных соединения (метод, путь, заголовки);
- `receive` — асинхронный канал чтения входящих чанков тела;
- `send` — асинхронный канал отправки статуса, заголовков и тела.

На ASGI строятся **FastAPI**, **Starlette**, **Litestar** и **Django Channels**.

## Продакшен-стек: Nginx + Gunicorn + Uvicorn

В продакшене мастер-процесс Gunicorn контролирует пул асинхронных воркеров Uvicorn с быстрым event loop `uvloop`:

```bash
gunicorn main:app \
  --workers 4 \
  -k uvicorn.workers.UvicornWorker \
  --bind 127.0.0.1:8000
```

1. **Nginx** терминирует TLS, отдаёт статику и буферизирует медленных клиентов.
2. **Gunicorn Master** перезапускает упавшие воркеры и обновляет приложение без простоя.
3. **Uvicorn Worker** обслуживает тысячи параллельных I/O-соединений внутри процесса.

## Типичные ошибки при работе с ASGI

Главная угроза асинхронного сервера — блокировка единого потока Event Loop:

- ❌ **Синхронный код внутри `async def`:** вызов `time.sleep(5)` или блокирующего драйвера БД замораживает весь воркер, ставя остальных клиентов в очередь.
- ✅ **Правильное решение:** использовать неблокирующие драйверы (`asyncpg`, `httpx.AsyncClient`) или выносить синхронные вызовы в пул потоков через `await asyncio.to_thread(sync_func)`.

## Сравнительная таблица WSGI vs ASGI и подход Junior vs Senior

Сводка ключевых архитектурных различий двух серверных интерфейсов Python:

| Критерий | WSGI (PEP 3333) | ASGI |
| :--- | :--- | :--- |
| **Модель вызова** | Синхронная: `app(environ, start_response)` | Асинхронная: `await app(scope, receive, send)` |
| **Протоколы** | Только классический HTTP/1.1 | HTTP/1.1, HTTP/2, **WebSocket**, **SSE** |
| **Конкурентность** | 1 запрос = 1 поток ОС / процесс | Тысячи корутин в одном Event Loop |
| **Серверы и фреймворки** | Gunicorn, uWSGI · Flask, Django | Uvicorn, Hypercorn · FastAPI, Starlette |

В ASGI также встроен протокол **`lifespan`** (`startup` / `shutdown`), позволяющий инициализировать пул соединений к БД и Redis один раз при старте воркера и корректно закрывать его при остановке.

> **Junior vs Senior**:
> - **Junior**: Вызывает синхронный `requests.get()` или `time.sleep()` внутри `async def` эндпоинта FastAPI, блокируя Event Loop для всех параллельных пользователей воркера.
> - **Senior**: В `async def` использует только неблокирующий I/O (`httpx.AsyncClient`, `AsyncSession`), тяжёлые CPU-задачи выносит в `ProcessPoolExecutor` / Celery, а в продакшене запускает связку Nginx + Gunicorn (`UvicornWorker`).
