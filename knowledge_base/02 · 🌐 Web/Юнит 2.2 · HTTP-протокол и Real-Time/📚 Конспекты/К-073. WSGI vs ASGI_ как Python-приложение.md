## Роль интерфейса шлюза: мост между веб-сервером и Python

Веб-серверы общего назначения (Nginx, Caddy, Apache) написаны на C/Go и оптимизированы для отдачи статики и SSL-терминации. Они не умеют напрямую вызывать функции языка Python.

Интерфейс шлюза (**Web Gateway Interface**) — стандартизированный контракт вызова Python-кода из сервера приложений.

```text
[Клиент]
  │ (HTTP)
  ▼
[Nginx]
  │ (UNIX socket)
  ▼
[Uvicorn / Gunicorn]
  │ (callable)
  ▼
[FastAPI / Django]
```

Шлюз берет на себя парсинг сырых HTTP-байтов в словари Python и возвращает сгенерированный поток байтов ответа.

## Синхронный стандарт WSGI (PEP 3333)

**WSGI (Web Server Gateway Interface)** принят в 2003 г. как синхронный callable-объект:

```python
def application(environ, start_response):
    status = '200 OK'
    headers = [
        ('Content-Type', 'text/plain')
    ]
    start_response(status, headers)
    return [b'Hello, WSGI World!']
```

- **Архитектурное ограничение:** модель «один запрос — один поток/процесс».
- Если во время запроса приложение ждет ответа от СУБД или делает внешний HTTP-вызов, рабочий поток блокируется целиком. Масштабирование упирается в память ОС при создании сотен процессов (Django до v3.0, Flask).

## Асинхронный стандарт ASGI: конкурентность нового поколения

**ASGI (Asynchronous Server Gateway Interface)** — современный стандарт, поддерживающий асинхронность (`asyncio`), фоновые задачи, Server-Sent Events и длительные WebSocket-соединения:

```python
async def application(scope, receive, send):
    if scope['type'] == 'http':
        await send({
            'type': 'http.response.start',
            'status': 200,
            'headers': [
                (b'content-type',
                 b'text/plain')
            ]
        })
        await send({
            'type': 'http.response.body',
            'body': b'Hello, ASGI World!'
        })
```

- `scope`: метаданные соединения (метод, путь, заголовки, тип);
- `receive`: асинхронная корутина для чтения входящих чанков тела запроса;
- `send`: асинхронная корутина для отправки частей ответа.
- Основа современных фреймворков: **FastAPI**, **Starlette**, **Litestar**, **Django Channels**.

## Продакшен-стек: Nginx + Gunicorn с воркерами Uvicorn

В боевом окружении применяется эталонная связка: мастер-процесс Gunicorn управляет жизненным циклом асинхронных воркеров Uvicorn:

```bash
gunicorn main:app \
  --workers 4 \
  -k uvicorn.workers.UvicornWorker \
  --bind 127.0.0.1:8000
```

1. **Nginx:** принимает публичный HTTPS-трафик, отдает статику, защищает от DDOS и балансирует запросы.
2. **Gunicorn Master:** следит за процессами, перезапускает упавшие воркеры, обновляет код без даунтайма (Zero-Downtime Reload).
3. **Uvicorn Worker:** крутит Event Loop `uvloop` на базе `libuv` и выполняет тысячи параллельных I/O запросов в одном процессе.

## Скрининг: типичные ошибки при работе с ASGI

- ❌ **Вызов блокирующего кода внутри `async def`:** если вызвать `time.sleep(5)` или тяжелый синхронный драйвер базы данных внутри роута FastAPI, Event Loop воркера заблокируется — все параллельные клиенты встанут в очередь.
- ✅ **Решение:** использовать асинхронные драйверы (`asyncpg`, `motor`, `httpx.AsyncClient`) либо выносить блокирующие задачи в отдельный пул потоков: `await asyncio.to_thread(sync_func)`.
