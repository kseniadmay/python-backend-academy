## Модуль – базовая единица кода

**Модуль** — любой файл `.py`, группирующий связанные функции, классы и константы для повторного использования в проекте.

Создадим файл модуля `math_utils.py` с двумя функциями:

```python
# math_utils.py
def add(a, b):
    return a + b

def multiply(a, b):
    return a * b
```

Подключим созданный модуль из другого файла целиком или импортировав конкретное имя:

```python
import math_utils
from math_utils import add
```

Форма `import math_utils` оставляет пространство имён модуля (`math_utils.add(2, 3)`), а `from math_utils import add` вносит имя напрямую в текущий файл.

## Пакет – директория с модулями

Когда модулей становится много, их группируют в **пакет** — директорию с подмодулями и подпакетами:

```text
my_package/
    __init__.py
    utils.py
    models.py
    helpers/
        __init__.py
        string_helper.py
```

Обращение к вложенным модулям через точку повторяет путь по папкам:

```python
from my_package import utils
from my_package.helpers import string_helper
```

## `__init__.py` – что делает папку пакетом

Наличие **`__init__.py`** (даже пустого) отмечает директорию как явный пакет, а его код выполняется ровно один раз при первом импорте пакета.

Обычно внутри `__init__.py` поднимают наверх публичный API пакета, чтобы сократить путь импорта:

```python
# Позволяет писать from my_package import add
from .utils import add
```

Не усложняйте иерархию заранее: начинайте с отдельных модулей `.py` и создавайте пакеты по мере роста числа файлов.

## Как Python ищет модули при импорте

При `import something` интерпретатор сперва проверяет **`sys.modules`** (кэш уже загруженных модулей текущего процесса), чтобы не выполнять файл повторно.

Если в кэше пусто, Python по очереди ищет файл по каталогам списка **`sys.path`**: папка запущенного скрипта, стандартная библиотека и установленные пакеты.

## Относительные vs абсолютные импорты

Внутри пакета доступны два вида импортов:

- **Абсолютный:** полный путь от корня проекта (`from my_package.utils import add`).
- **Относительный:** путь относительно текущего файла (`from .utils import add` или `from ..core import db`), работающий только внутри пакетов.

Стандарт PEP 8 и продакшен-проектов — предпочитать **абсолютные импорты**: они проще читаются и устойчивы при перемещении файлов.

## Кэширование в `sys.modules`, затенение stdlib и подход Junior vs Senior

Модуль в Python загружается и исполняется **ровно один раз за время жизни процесса**. Все последующие инструкции `import math_utils` в других файлах мгновенно возвращают уже готовый объект модуля из словаря **`sys.modules`**:

```python
import sys
import json

# Модуль уже лежит в глобальном кэше
print('json' in sys.modules)
# >>> True
```

**Опасная ловушка — затенение стандартной библиотеки (*module shadowing*):** так как текущая папка скрипта стоит первой в `sys.path[0]`, файл с именем `json.py`, `random.py` или `email.py` в вашем проекте перекроет одноимённый модуль стандартной библиотеки и сломает `import json` во всех сторонних пакетах.

> **Junior vs Senior**:
> - **Junior**: Называет тестовый скрипт `requests.py` или `logging.py` (получая `AttributeError` из-за самоимпорта) либо модифицирует `sys.path.append('../..')` прямо внутри бизнес-модулей.
> - **Senior**: Даёт модулям уникальные доменные имена, опирается на кэш `sys.modules` для модульных синглтонов и настраивает корень пакетов декларативно через `pyproject.toml`.
