## Преимущества объектного API pathlib перед os.path

В старом коде пути держали строками и склеивали через вложенный `os.path.join(os.path.dirname(__file__), 'config')`, что плохо читалось. Модуль **`pathlib`** (PEP 428) представляет пути объектами класса `Path`.

Объект `Path` кроссплатформенно склеивает пути оператором `/`, разбирает компоненты без срезов и умеет читать файлы напрямую:

```python
from pathlib import Path

# Корень проекта (2 уровня вверх)
BASE_DIR = (
    Path(__file__).resolve().parent.parent
)

# Кроссплатформенная склейка через /
config_path = (
    BASE_DIR
    / 'configs'
    / 'production.env.yaml'
)
```

## Анатомия `Path` и иммутабельная модификация путей

Объект `Path` разбирает имя файла, расширения и родительские каталоги без строковых срезов и `os.path.splitext`:

```python
from pathlib import Path

p = Path('/var/log/nginx/access.tar.gz')
print(p.name)
# >>> access.tar.gz

print(p.stem)
# >>> access.tar

print(p.suffix)
# >>> .gz

print(p.suffixes)
# >>> ['.tar', '.gz']

print(p.parent.as_posix())
# >>> /var/log/nginx

print(p.parents[1].as_posix())
# >>> /var/log
```

Все объекты `Path` **иммутабельны**: методы вроде `with_suffix()` и `with_name()` всегда возвращают новый объект, оставляя исходный `p` неизменным:

```python
from pathlib import Path

p = Path('/var/log/nginx/access.tar.gz')

# Замена только последнего расширения
backup = p.with_suffix('.bak')
print(backup.name)
# >>> access.tar.bak

# Полная замена имени файла в той же папке
renamed = p.with_name('error.log')
print(renamed.name)
# >>> error.log
```

## Чтение, запись, статус и метаданные пути

Для небольших файлов `Path` умеет создавать вложенные папки и читать/записывать текст в одну строку:

```python
from pathlib import Path

# Описываем путь (файл ещё не создан)
report = Path('output/reports/summary.txt')

# Создаём вложенные папки, если их нет
report.parent.mkdir(
    parents=True,
    exist_ok=True,
)

# Создаём summary.txt и записываем текст
report.write_text(
    'Отчёт готов\nСтрок: 42\n',
    encoding='utf-8',
)

# Читаем всё содержимое файла в строку
content = report.read_text(encoding='utf-8')
print(content)
# >>> Отчёт готов
# >>> Строк: 42
```

### Проверка статуса и метаданные пути

Основные методы проверки существования и получения свойств файла в системе:

| Метод `Path` | Что проверяет / возвращает |
| :--- | :--- |
| **`.exists()`** | Существует ли файл или папка на диске |
| **`.is_file()` / `.is_dir()`** | Обычный ли это файл или директория |
| **`.is_symlink()`** | Является ли путь символической ссылкой |
| **`.stat()`** | Метаданные ОС: размер `st_size`, время `st_mtime` |

## Поиск файлов и обход дерева: iterdir, glob, rglob

Вместо `os.listdir()` и отдельного модуля `glob` класс `Path` даёт три ленивых генератора:

- **`iterdir()`** — перебирает прямых потомков директории (без рекурсии).
- **`glob(pattern)`** — ищет файлы по маске в текущей папке.
- **`rglob(pattern)`** — рекурсивный поиск по всему дереву (`rglob('*')` равен `glob('**/*')`).

Пример обхода подпапок и фильтрации `.py`-файлов во временной директории:

```python
from pathlib import Path
from tempfile import TemporaryDirectory

# Временная папка удалится сама
with TemporaryDirectory() as tmp:
    src = Path(tmp)
    (src / 'models').mkdir()
    (src / 'services').mkdir()
    (src / 'main.py').touch()

    dirs = sorted(
        p.name
        for p in src.iterdir()
        if p.is_dir()
    )
    print('Подпапки:', dirs)
    # >>> Подпапки: ['models', 'services']

    py_files = [
        p.name
        for p in src.glob('*.py')
    ]
    print('Python-файлы:', py_files)
    # >>> Python-файлы: ['main.py']
```

## `resolve()` и архитектура PurePath vs Path

Иерархия `pathlib` делится на два уровня — «чистые» вычисления и системный ввод-вывод:

- **`PurePath`** (`PurePosixPath`, `PureWindowsPath`) — работа со структурой пути только в RAM без обращений к ОС (удобно парсить чужие пути, например Windows-путь на Linux).
- **`Path`** (`PosixPath`, `WindowsPath`) — наследует `PurePath` и добавляет реальный I/O (`exists()`, `mkdir()`, `unlink()`).

Метод **`p.resolve()`** не только строит абсолютный путь, но и раскрывает символические ссылки на диске:

```python
from pathlib import Path, PurePosixPath

# PurePath: работа в памяти без I/O
pure = PurePosixPath('/etc/hosts')
print(pure.name)
# >>> hosts

# Path.resolve() нормализует '..' и symlinks
target = Path('symlink.lnk').resolve()
```
