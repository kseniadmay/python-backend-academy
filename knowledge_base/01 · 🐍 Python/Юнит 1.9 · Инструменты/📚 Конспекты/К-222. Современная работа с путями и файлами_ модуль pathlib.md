## Преимущества объектного API pathlib перед функциями os.path

В легаси-коде пути к файлам хранили в обычных строках (`str`) и склеивали через громоздкий `os.path.join(os.path.dirname(__file__), "config", "settings.yaml")`. Вложенные вызовы функций `os.path` трудно читать, а обычные строки ничего не знают о файловой системе.

Модуль **`pathlib`** (PEP 428) представляет пути как полноценные **объекты** класса `Path`. У них есть удобные свойства (`.name`, `.stem`, `.suffix`, `.parent`), встроенные методы ввода-вывода и перегруженный оператор деления **`/`** для кроссплатформенной склейки путей (автоматически ставит `/` на Linux/macOS и `\` на Windows):

```python
from pathlib import Path
# Корень проекта (2 уровня вверх):
BASE_DIR = (
    Path(__file__).resolve().parent.parent
)
# Кроссплатформенная склейка через /:
config_path = (
    BASE_DIR
    / 'configs'
    / 'production.env.yaml'
)
```

## Анатомия объекта Path: разбор пути без split()

Объект `Path` мгновенно разбирает путь на составляющие без строковых срезов и устаревшего `os.path.splitext`:

```python
from pathlib import Path
p = Path('/var/log/nginx/access.tar.gz')
print(p.name)
print(p.stem)
print(p.suffix)
print(p.suffixes)
print(p.parent)
print(p.parents[1])
```

## Иммутабельная модификация путей: with_suffix() и with_name()

Объекты `Path` **иммутабельны** (неизменяемы). Любая операция модификации пути возвращает **новый экземпляр** `Path`, не изменяя исходный объект:

```python
# Замена расширения (с точкой):
# Исходный p остается неизменным
backup = p.with_suffix('.bak')
# /var/log/nginx/access.tar.bak

# Полная замена имени в той же папке:
renamed = p.with_name('error.log')
# /var/log/nginx/error.log
```

## Чтение, запись и управление директориями

Для небольших файлов `Path` позволяет прочитать или записать содержимое в одну строчку, автоматически открывая и закрывая файл:

```python
from pathlib import Path
report = Path(
    'output/reports/summary.txt'
)
report.parent.mkdir(
    parents=True, exist_ok=True
)
report.write_text(
    'Отчёт готов\n', encoding='utf-8'
)
content = report.read_text(
    encoding='utf-8'
```

### Проверка статуса и метаданные пути
- **`.exists()`** — проверяет существование файла или папки на диске.
- **`.is_file()` / `.is_dir()`** — определяет, является ли объект обычным файлом или директорией.
- **`.is_symlink()`** — определяет, является ли путь символической ссылкой.
- **`.stat()`** — возвращает метаданные: размер `st_size` в байтах, метку времени изменения (`st_mtime`).

## Поиск файлов и обход дерева: iterdir, glob, rglob

Вместо устаревших `os.listdir()` и отдельного модуля `glob` объект `Path` предоставляет три ленивых генератора:

1. **`iterdir()`** — итерация по прямым потомкам директории (без рекурсии).
2. **`glob(pattern)`** — поиск файлов по маске в текущей директории.
3. **`rglob(pattern)`** — рекурсивный поиск по всему дереву подпапок (аналог `glob("**/*")`).

```python
from pathlib import Path
src_dir = Path('src')
# 1. Прямые потомки папки (нерекурсивно):
for item in src_dir.iterdir():
    if item.is_dir():
        print('Подпапка:', item.name)
# 2. Поиск по маске в текущей папке:
py_files = list(src_dir.glob('*.py'))
all_tests = list(
    src_dir.rglob('test_*.py')
)
```

## resolve() vs absolute() и архитектура PurePath vs Path

В `pathlib` иерархия классов строго разделена на два уровня:

1. **`PurePath`** (`PurePosixPath`, `PureWindowsPath`) — «чистые» вычислительные пути в оперативной памяти. Они **не обращаются к операционной системе и диску**: позволяют конструировать и парсить пути других ОС (например Windows-пути на Linux-сервере).

2. **`Path`** (`PosixPath`, `WindowsPath`) — «конкретные» пути, которые наследуют `PurePath` и подключают системные вызовы ввода-вывода (`exists()`, `mkdir()`, `read_text()`, `unlink()`).

Различие на собеседовании: метод **`p.resolve()`** не просто превращает относительный путь в абсолютный, но и **раскрывает все символические ссылки (symlinks)** и нормализует переходы `..` на физическом уровне файловой системы:

```python
from pathlib import Path, PurePosixPath

# PurePath: работа в памяти без I/O:
pure = PurePosixPath('/etc/hosts')
print(pure.name)  # hosts

# Path.resolve(): раскрывает symlinks:
target = Path('symlink.lnk').resolve()
```
