## Преимущества logging перед print() и 5 уровней важности

Вызов `print()` пишет неструктурированный текст только в `stdout` без времени, имени модуля и фильтрации для файлов или систем мониторинга (Sentry, ELK, Loki).

Модуль **`logging`** управляет потоками вывода через 5 стандартных уровней важности:

| Уровень | Вес | Когда используется в сервисе |
| :--- | :--- | :--- |
| **`DEBUG`** | `10` | Подробная отладка шагов и параметров запроса |
| **`INFO`** | `20` | Штатные события: старт воркера, успешный заказ |
| **`WARNING`** | `30` | Порог по умолчанию: ретрай, диск заполнен на 85% |
| **`ERROR`** | `40` | Ошибка конкретной операции (сервис продолжает работу) |
| **`CRITICAL`** | `50` | Фатальный отказ всей системы (нет БД на старте) |

Сравним вывод обычного `print()` и структурированного логгера через `basicConfig`:

```python
import logging

print('Сервер запущен')
# >>> Сервер запущен

logging.basicConfig(
    format=(
        '%(asctime)s [%(levelname)s] '
        '%(name)s: %(message)s'
    ),
    datefmt='%H:%M:%S',
    level=logging.INFO,
)
web_log = logging.getLogger('web')
web_log.info('Сервер слушает порт 8000')
```

## Четыре столпа архитектуры logging: Logger, Handler, Formatter, Filter

Модуль `logging` разделяет настройку записи и маршрутизацию логов между четырьмя компонентами:

- **`Logger` (Логгер):** точка входа (`logging.getLogger(__name__)`), отсекает сообщения ниже своего уровня.
- **`Handler` (Обработчик):** выбирает канал вывода (`StreamHandler`, `FileHandler`, `RotatingFileHandler`) со своим порогом.
- **`Formatter` (Форматтер):** задаёт строковый или JSON-шаблон записи.
- **`Filter` (Фильтр):** отбирает или обогащает запись (`LogRecord`, например, добавляя `request_id`).

Настроим отдельный логгер с записью форматированных событий в поток:

```python
import io
import logging

logger = logging.getLogger('shop.order')
logger.setLevel(logging.INFO)

stream = io.StringIO()
handler = logging.StreamHandler(stream)
fmt = logging.Formatter(
    '[%(levelname)s] %(name)s: %(message)s'
)
handler.setFormatter(fmt)
logger.addHandler(handler)

logger.info('Заказ #101 успешно оформлен')
print(stream.getvalue().strip())
# >>> [INFO] shop.order: Заказ #101 успешно оформлен
```

## Иерархия по точкам и флаг propagate

Имена логгеров образуют дерево по точкам (`app.services.payment` ➔ `app.services` ➔ `app` ➔ корневой `root`). По умолчанию включён флаг **`propagate = True`**, передающий каждое событие вверх по цепочке до `root`.

Если одновременно повесить `StreamHandler` на дочерний логгер и на `root` (через `basicConfig`), каждое сообщение напечатается дважды. Изолируют дочерний логгер через `propagate = False`:

```python
import logging

child = logging.getLogger('app.service')
print('По умолчанию:', child.propagate)
# >>> По умолчанию: True

# Отключаем проброс записей в root
child.propagate = False
print('После настройки:', child.propagate)
# >>> После настройки: False
```

## Логирование исключений: `logger.exception()` и ленивый `%s`

Частая ошибка в `except` — писать `logger.error(f'Ошибка: {e}')`, из-за чего теряется стек вызовов.

Метод **`logger.exception()`** внутри `except` сам записывает уровень `ERROR` вместе с полным трейсбеком:

```python
import io
import logging

logger = logging.getLogger('billing')
logger.propagate = False
stream = io.StringIO()
handler = logging.StreamHandler(stream)
handler.setFormatter(
    logging.Formatter(
        '%(levelname)s:%(name)s:%(message)s'
    )
)
logger.addHandler(handler)

user_id = 42
try:
    result = 100 / 0
except ZeroDivisionError:
    logger.exception(
        'Сбой расчёта для id=%s',
        user_id,
    )

lines = stream.getvalue().strip().splitlines()
print(lines[0])
# >>> ERROR:billing:Сбой расчёта для id=42

print(lines[-1])
# >>> ZeroDivisionError: division by zero
```

Передавайте аргументы в логгер через `%s` (`logger.debug('Payload: %s', obj)`), а не через f-строку: преобразование в строку сработает лениво, только если уровень логирования действительно включён.

## Конфигурация `dictConfig` и структурированные JSON-логи

В сервисах (FastAPI, Django, Celery) всю схему форматтеров, хендлеров и сторонних логгеров задают декларативно на старте через **`dictConfig`**:

```python
import io
import logging
from logging.config import dictConfig

stream = io.StringIO()
LOGGING_CONFIG = {
    'version': 1,
    'disable_existing_loggers': False,
    'formatters': {
        'std': {
            'format': (
                '[%(levelname)s] '
                '%(name)s: %(message)s'
            ),
        },
    },
    'handlers': {
        'memory': {
            'class': 'logging.StreamHandler',
            'formatter': 'std',
            'stream': stream,
        }
    },
    'root': {
        'level': 'INFO',
        'handlers': ['memory'],
    },
}

dictConfig(LOGGING_CONFIG)
log = logging.getLogger('api')
log.info('Сервис запущен на порту 8000')
print(stream.getvalue().strip())
# >>> [INFO] api: Сервис запущен на порту 8000
```

В продакшен-кластерах (Docker, Kubernetes) вместо текстовых строк подключают JSON-логгирование (например, `structlog`) с полями `timestamp`, `level` и `trace_id` для индексации в Kibana и Grafana Loki.
