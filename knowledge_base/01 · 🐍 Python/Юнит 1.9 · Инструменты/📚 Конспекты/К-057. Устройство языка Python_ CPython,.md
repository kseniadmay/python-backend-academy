## Python – спецификация, CPython – реализация

**Python** как язык — это строгая спецификация синтаксиса и семантики (документация и PEP), а **CPython** — её эталонная реализация на языке C, запускаемая командой `python` (на ней работают 99% бэкенд-сервисов).

Помимо CPython, существуют и альтернативные реализации языка:

- **PyPy** — реализация с JIT-компилятором, ускоряющая вычисления в 2–7 раз.
- **Jython** — компиляция в байткод Java Virtual Machine (JVM).
- **IronPython** — интеграция со средой выполнения .NET CLR.

## Путь от `.py` до выполнения: AST, байткод и PVM

Python не компилируется сразу в машинный код CPU (как C, Rust или Go), но и не исполняет сырой текст построчно.

Схема конвейера выполнения исходного файла:

```text
1. Исходный код (.py)
      ↓ парсинг в AST
2. Синтаксическое дерево
      ↓ компиляция
3. Байткод (.pyc)
      ↓ исполнение
4. Виртуальная машина (PVM)
```

Этапы прохождения программы:

1. **Парсер** превращает текст `.py` в абстрактное синтаксическое дерево (**AST**).
2. **Компилятор** преобразует AST в платформонезависимый байткод и кэширует его в `__pycache__/*.pyc` ради быстрого повторного запуска.
3. **Виртуальная машина PVM** построчно исполняет инструкции байткода в цикле `eval loop`.

## Байткод (`dis`), стековая PVM и Constant Folding

Модуль **`dis`** дизассемблирует функцию и показывает инструкции стековой виртуальной машины CPython (PVM):

```python
import dis

def add(a, b):
    return a + b

# Вывод инструкций: LOAD_FAST, BINARY_OP
dis.dis(add)
```

В отличие от регистровых ВМ (вроде LuaJIT), PVM устроена как **стековый автомат**: аргументы кладутся на стек кадра (`frame`), а инструкция забирает верхние операнды.

Каждый вызов функции создаёт новый кадр с локальными переменными и указателем байткода.

Также на этапе компиляции AST CPython выполняет оптимизацию **Constant Folding**, заранее сворачивая константные выражения:

```python
import dis

# Выражение сворачивается в константу 86400
dis.dis('seconds = 24 * 60 * 60')
```

## Производительность CPython: когда делегировать C и Rust

Виртуальная машина проверяет типы операндов в рантайме на каждой инструкции, поэтому чистые вычисления в Python уступают C и Rust.

В бэкенде это редко мешает (90% времени уходит на сетевой I/O). Критичные к CPU расчёты делегируют библиотекам на C и Rust (`pydantic-core`, `numpy`, `uvloop`).

## Архитектура на собеседовании: GIL и спецификация

На технических интервью обязательно разделяют язык **Python** и реализацию **CPython**:

1. **GIL (Global Interpreter Lock)** — особенность именно **CPython**, защищающая счётчик ссылок (`PyObject.ob_refcnt`) от гонок данных.
2. В самой спецификации языка Python требования о GIL нет (в `Jython` и `IronPython` его нет).
3. С версии **CPython 3.13+** развивается экспериментальный режим **free-threaded Python** без GIL (PEP 703).
