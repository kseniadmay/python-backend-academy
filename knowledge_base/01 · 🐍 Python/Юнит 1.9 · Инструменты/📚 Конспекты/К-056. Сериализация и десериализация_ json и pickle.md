## Что такое сериализация: сохранение состояния между процессами

**Сериализация (serialization)** — процесс преобразования объекта из оперативной памяти (структуры Python: словари, списки, экземпляры классов) в последовательность байт или строку для сохранения на диск, отправки по сети или записи в кэш.

**Десериализация (deserialization)** — обратный процесс: восстановление живого объекта в памяти из потока байт или текста.

Без сериализации данные живут только в оперативной памяти текущего процесса и исчезают при его завершении. На бэкенде сериализация используется постоянно: при отправке JSON-ответов из FastAPI/Django в браузер, кэшировании сессий в Redis и передаче задач воркерам Celery.

```python
import json

# Объект в оперативной памяти (RAM):
user = {'name': 'Alex', 'role': 'admin'}

# Сериализация: превращение в строку
serialized = json.dumps(user)
print('Тип:', type(serialized).__name__)
print('Строка:', serialized)
```

## json.dumps() и json.loads(): строковая сериализация для API

Модуль **`json`** из стандартной библиотеки Python работает с форматом JSON (JavaScript Object Notation) — универсальным текстовым стандартом обмена данными в веб-разработке.

**Соответствие типов Python и JSON:**
- `dict` ➔ JSON Object `{...}`
- `list`, `tuple` ➔ JSON Array `[...]`
- `str` ➔ String `"..."`
- `int`, `float` ➔ Number `42`, `3.14`
- `True` / `False` ➔ `true` / `false`
- `None` ➔ `null`

Функции с суффиксом **`s`** (`dumps`, `loads`) работают со строками в памяти:

```python
import json
data = {
    'name': 'Alex',
    'age': 30,
    'is_admin': False,
    'tags': ['python', 'api']
}
json_str = json.dumps(data)
print('JSON:', json_str)
restored = json.loads(json_str)
print('Имя:', restored['name'])
```

## json.dump() vs json.load(): потоковая работа с файлами

Когда данные нужно сохранить в файл на диске или передать через сетевой сокет, функции без суффикса `s` работают напрямую с файловыми объектами (потоками ввода-вывода):

- **`json.dump(obj, fp)`** — сериализует объект и **записывает его сразу в файл** `fp` (stream).
- **`json.load(fp)`** — читает файл `fp` и **десериализует объект напрямую из потока**.

Это эффективнее по памяти, чем промежуточное создание большой строки через `dumps()` и ручной `f.write()`.

```python
import io
import json
payload = {'status': 'ok', 'code': 200}
# Имитация файлового потока в памяти:
stream = io.StringIO()
# dump() пишет напрямую в файловый поток:
json.dump(payload, stream)
# load() читает напрямую из потока:
stream.seek(0)
loaded = json.load(stream)
print('Из потока:', loaded['code'])
```

## Модуль pickle: бинарная сериализация объектов Python

Модуль **`pickle`** — это встроенный инструмент бинарной сериализации, созданный специально для Python.

В отличие от `json`, `pickle` умеет сериализовать почти любой объект Python «как есть»: экземпляры пользовательских классов, множества `set`, функции, генераторы и циклические ссылки.

Результатом работы `pickle.dumps()` является бинарная последовательность **`bytes`**, а не текст.

```python
import pickle
class User:
    def __init__(
        self, name: str, age: int
    ):
        self.name = name
        self.age = age
user = User('Alex', 30)
binary = pickle.dumps(user)
print('Тип:', type(binary).__name__)
restored = pickle.loads(binary)
print('Имя:', restored.name)
```

## Сравнение json vs pickle: переносимость против полноты

На техническом собеседовании обязательно проверяют понимание различий между текстовой и бинарной сериализацией:

- **Переносимость (Cross-language)**: JSON понимают практически все языки (JavaScript, Go, Rust, Java). Бинарный `pickle` понятен только интерпретатору Python.
- **Поддерживаемые типы**: JSON ограничен базовыми типами (числа, строки, списки, словари). `pickle` сохраняет сложные структуры данных и состояние классов.
- **Читаемость**: JSON легко читать глазами и редактировать в текстовом редакторе. `pickle` — непрозрачный бинарный поток.
- **Безопасность**: JSON безопасен при чтении из сети. `pickle` критически опасен при десериализации недоверенных данных.

```python
# Чек-лист выбора формата:
# json: API, конфиги, микросервисы
# pickle: доверенный кэш Python

print('json: открытый API | pickle: кэш')
```

## Критическая опасность pickle: RCE через метод __reduce__

Главное правило безопасности бэкенд-разработчика: **никогда не вызывайте `pickle.loads()` на данных, полученных из внешней сети или от пользователя!**

Модуль `pickle` позволяет объекту определить специальный метод **`__reduce__()`**, который указывает интерпретатору, какую функцию вызвать при восстановлении объекта. Злоумышленник может упаковать в `pickle` вызов системной команды операционной системы (`os.system` / `subprocess`), что приводит к **Remote Code Execution (RCE)** — полному захвату сервера!

В `json` эта уязвимость невозможна в принципе, потому что JSON описывает только чистые данные и не содержит инструкций исполнения кода.

```python
import pickle

# Уязвимость через метод __reduce__:
class Exploit:
    def __reduce__(self):
        # Возврат функции и аргументов
        return (print, ('⚠️ Взлом!',))

payload = pickle.dumps(Exploit())

# ВНИМАНИЕ: pickle.loads() выполнит код!
restored = pickle.loads(payload)
```

## Кастомный энкодер json: сериализация datetime и UUID

По умолчанию `json.dumps()` выбрасывает `TypeError: Object of type datetime is not JSON serializable` при попытке упаковать дату, время или UUID.

Для решения этой проблемы в `json.dumps()` передают параметр **`default=callable`** — функцию-трансформер, которая подсказывает сериализатору, как представить нестандартный тип в виде строки или числа.

В современных веб-фреймворках (FastAPI / Pydantic v2) эта задача решается автоматически через метод `model.model_dump_json()`.

```python
from datetime import datetime
import json
def custom_encoder(obj):
    if isinstance(obj, datetime):
        return obj.isoformat()
    msg = f'{type(obj)} не сериализуем'
    raise TypeError(msg)
now = datetime(2026, 10, 20, 12, 0)
data = {'event': 'login', 'date': now}
encoded = json.dumps(
    data, default=custom_encoder
)
```
