## Преимущества pytest и паттерн Arrange-Act-Assert (AAA)

В отличие от `unittest` с наследованием от `TestCase` и методами `self.assertEqual`, **`pytest`** использует обычные функции и нативный `assert`.

При падении теста `pytest` переписывает AST до компиляции, чтобы показать значения всех подвыражений.

Любой тест организуют по схеме **AAA (Arrange — Act — Assert)**:

1. **Arrange (Подготовка):** входные данные, фикстуры и моки.
2. **Act (Действие):** ровно один вызов тестируемой функции или метода.
3. **Assert (Проверка):** сверка результата и побочных эффектов.

## Проверка исключений: pytest.raises

Чтобы проверить, что код выбрасывает ожидаемое исключение с нужным текстом ошибки, используют менеджер `pytest.raises`:

```python
import pytest

def withdraw(
    balance: float, amount: float
) -> float:
    if amount <= 0:
        raise ValueError('Сумма > 0!')
    if amount > balance:
        raise ValueError('Мало средств')
    return balance - amount

def test_withdraw_insufficient_funds():
    # Ждём ValueError с точным текстом
    with pytest.raises(
        ValueError, match='Мало средств'
    ):
        withdraw(100.0, 250.0)
```

Внутри блока `with pytest.raises(...)` держите ровно одну строку вызова (шаг **Act**), иначе тест может ложно сработать на ошибку подготовки данных.

## Фикстуры (`@pytest.fixture`) и teardown через `yield`

**Фикстуры** — механизм внедрения зависимостей (DI) в `pytest`: достаточно указать имя фикстуры в параметрах тестовой функции.

Если вместо `return` использовать **`yield`**, код до него готовит ресурс (setup), а после — гарантированно очищает (teardown) даже при падении теста:

```python
import pytest

@pytest.fixture(scope='function')
def db_conn(engine):
    conn = engine.connect()
    transaction = conn.begin()

    # Передаём подключение в тест
    yield conn

    # Teardown: откат транзакции БД
    transaction.rollback()
    conn.close()
```

## Области видимости `scope`, `conftest.py` и встроенные фикстуры

Время жизни и частоту пересоздания ресурса задаёт параметр `scope`:

| Значение `scope` | Когда фикстура создаётся заново |
| :--- | :--- |
| **`function`** (дефолт) | Перед каждым тестом |
| **`class`** | Один раз на тестовый класс |
| **`module`** | Один раз на `.py`-файл |
| **`package`** | Один раз на пакет тестов |
| **`session`** | Ровно один раз на весь запуск `pytest` |

Общие фикстуры кладут в **`conftest.py`** (импортировать его не нужно, `pytest` найдёт файл сам).

Полезные встроенные фикстуры: **`tmp_path`** (временная папка), **`monkeypatch`** (`setenv` и подмена атрибутов) и **`caplog`** (перехват логов).

## Параметризация: `@pytest.mark.parametrize`

Чтобы не дублировать одинаковые тесты и получать отчёт по каждому кейсу отдельно, применяют **`@pytest.mark.parametrize`**:

```python
import pytest

@pytest.mark.parametrize(
    'price, discount, expected',
    [
        pytest.param(
            100.0, 10, 90.0, id='std_10'
        ),
        pytest.param(
            100.0, 0, 100.0, id='zero'
        ),
        pytest.param(
            100.0, 100, 0.0, id='free'
        ),
    ],
)
def test_calculate_discount(
    price, discount, expected
):
    calc = price * (1 - discount / 100)
    assert calc == expected
```

В отличие от цикла `for` внутри теста, параметризация при падении одного кейса всё равно прогонит и проверит остальные наборы.

## Изоляция сервисов: `unittest.mock` и `AsyncMock`

Юнит-тесты не должны ходить в реальный платёжный шлюз или внешний HTTP API. Для их замены используют модуль **`unittest.mock`**.

Объекты **`Mock`** и **`MagicMock`** имитируют зависимости (`MagicMock` добавляет `__len__`, `__iter__`, `with`), а для корутин обязателен **`AsyncMock`**.

Два главных атрибута настройки поведения любого мока:

- **`return_value`** — фиксированный результат вызова.
- **`side_effect`** — выброс исключения (`mock.side_effect = TimeoutError('API down')`), последовательность ответов (`[500, 200]` для тестов retry) либо функция-обработчик.

Факт вызова проверяют через `assert_called_once()`, `assert_called_once_with(*args, **kwargs)`, `assert_not_called()` и `call_count`.

## Главное правило `patch()`: мокай там, где используется

Когда `app/service.py` импортирует функцию строкой `from app.payment_client import charge_card`, в нём создаётся собственная локальная ссылка.

Поэтому `@patch('app.payment_client.charge_card')` не сработает — мокать нужно точку использования в `app.service`:

```python
from unittest.mock import patch

# Мокаем точку вызова внутри app.service
@patch('app.service.charge_card')
def test_checkout_calls_gateway(mock_charge):
    mock_charge.return_value = {
        'status': 'ok',
        'tx_id': 'tx_99',
    }
    result = process_checkout(
        user_id=1, amount=500
    )
    assert result['tx_id'] == 'tx_99'
    mock_charge.assert_called_once_with(
        user_id=1, amount=500
    )
```

Всегда добавляйте `autospec=True` (или `create_autospec`): он привязывает мок к сигнатуре оригинала и сразу поймает устаревший тест с лишними аргументами.
