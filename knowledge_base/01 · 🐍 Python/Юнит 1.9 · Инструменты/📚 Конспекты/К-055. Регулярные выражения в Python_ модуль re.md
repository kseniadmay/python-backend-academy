## Регулярные выражения в сравнении со строковыми методами

**Регулярное выражение (RegEx)** — декларативный язык шаблонов для поиска, валидации форматов и извлечения данных в тексте; в Python за него отвечает модуль **`re`**.

Не используйте регулярки там, где хватает методов `str` (`in`, `startswith`), — они намного быстрее, так как не запускают конечный автомат:

```python
import re

text = 'admin@example.com'

# Быстрые строковые методы:
print('@' in text, text.endswith('.com'))
# >>> True True

# Модуль re для проверки формата:
email_rx = r'^[\w.-]+@[\w.-]+\.\w+$'
print(bool(re.search(email_rx, text)))
# >>> True
```

## `re.search()` — первое совпадение и объект Match

Функция **`re.search(pattern, string)`** сканирует строку и возвращает объект **`Match`** для первого найденного совпадения (или `None`):

```python
import re

log_line = (
    '2026-10-19 ERROR [user_id=42]: '
    'timeout connecting to db'
)

# Скобки () захватывают группу цифр
pattern = r'user_id=(\d+)'
match = re.search(pattern, log_line)
if match:
    print('Совпадение:', match.group(0))
    # >>> Совпадение: user_id=42

    print('Значение:', match.group(1))
    # >>> Значение: 42

    print('Индексы:', match.span())
    # >>> Индексы: (18, 28)
```

Методы объекта `Match` для извлечения результата:

- **`match.group(0)`** (`match.group()`) — весь совпавший фрагмент текста.
- **`match.start()` / `match.end()`** — начальный и конечный индексы среза.
- **`match.span()`** — кортеж `(start, end)` для прямого среза `log_line[start:end]`.

## `re.match()` vs `re.fullmatch()`: префикс и полная строка

Классическая ловушка собеседований — различие трёх базовых функций поиска:

- **`re.search()`** — ищет совпадение в любом месте строки.
- **`re.match()`** — ищет строго от начала строки (неявно добавляет `^`).
- **`re.fullmatch()`** — требует совпадения всей строки от начала до конца.

Сравним поведение этих проверок на примерах:

```python
import re

text = 'order_12345_complete'

print(bool(re.match(r'order_\d+', text)))
# >>> True

print(bool(re.match(r'12345', text)))
# >>> False

# fullmatch отклонит лишний хвост _complete
print(bool(re.fullmatch(r'order_\d+', text)))
# >>> False

slug = 'valid-slug-2026'
rx = r'[a-z0-9-]+'
print(bool(re.fullmatch(rx, slug)))
# >>> True
```

Для валидации пользовательского ввода (slug, телефон, номер карты) всегда берите **`re.fullmatch()`**, чтобы исключить лишний хвост строки.

## `re.findall()` vs `re.finditer()`: память и потоки логов

Выбор функции для извлечения всех совпадений влияет на расход RAM:

- **`re.findall(pattern, text)`** — возвращает готовый **`list`** строк (удобно для коротких текстов, но дорого на больших файлах).
- **`re.finditer(pattern, text)`** — возвращает **ленивый итератор** `Match` для потоковой обработки без аллокации списка.

Пример использования обеих функций на одной строке:

```python
import re

text = 'Цены: 1500 руб, 3200 руб, 450 руб'

prices = re.findall(r'\d+', text)
print('Все цены списком:', prices)
# >>> Все цены списком: ['1500', '3200', '450']

matches = [
    (m.group(), f'{m.start()}..{m.end()}')
    for m in re.finditer(r'\d+', text)
]
print(matches)
# >>> [('1500', '6..10'), ('3200', '16..20'), ('450', '26..29')]
```

## `re.sub()` и `re.split()`: замена и гибкое разделение

### Функция `re.sub()`: замена по динамическому шаблону

В `re.sub(pattern, repl, string, count=0)` вторым аргументом можно передать не только строку, но и функцию `callable(Match) -> str`:

```python
import re

# 1) Маскирование: оставляем только цифры
phone = '+7 (999) 123-45-67'
clean_digits = re.sub(r'\D', '', phone)
print('Только цифры:', clean_digits)
# >>> Только цифры: 79991234567

# 2) Динамическая замена через функцию
doubled = re.sub(
    r'\d+',
    lambda m: str(int(m.group()) * 2),
    'x=3 y=7',
)
print(doubled)
# >>> x=6 y=14
```

### Разделение текста: `re.split()` vs `str.split()`

Когда разделителями одновременно выступают разные символы (запятые, точки с запятой, пробелы), вместо простого `str.split()` используют `re.split()`:

```python
import re

raw_csv = 'apple , banana; orange, grape'
items = re.split(r'\s*[,;]\s*', raw_csv)
print('Элементы списка:', items)
# >>> Элементы списка: ['apple', 'banana', 'orange', 'grape']
```

## Классы символов и их отрицания

Заглавная буква управляющей последовательности в регулярных выражениях всегда означает логическое отрицание:

| Шаблон | Значение | Пример совпадения |
| :--- | :--- | :--- |
| `.` | Любой символ, кроме `\n` | `a`, `5`, `@` |
| `\d` / `\D` | Цифра `[0-9]` / НЕ цифра | `7` / `a` |
| `\w` / `\W` | Буква, цифра, `_` (Unicode) / остальное | `User_1` / `!` |
| `\s` / `\S` | Пробельный (` `, `\t`, `\n`) / НЕ пробел | `\t` / `x` |
| `[abc]` / `[^abc]` | Один из `abc` / любой КРОМЕ `abc` | `b` / `z` |

Применим эти классы символов для разбора строки лога:

```python
import re

sample = 'User_007: login OK! (code #42)'

digits = re.findall(r'\d+', sample)
print('Цифры:', digits)
# >>> Цифры: ['007', '42']

words = re.findall(r'\w+', sample)[:3]
print('Слова:', words)
# >>> Слова: ['User_007', 'login', 'OK']

non_space = len(re.findall(r'\S+', sample))
print('Не пробелы:', non_space)
# >>> Не пробелы: 5
```

## Квантификаторы и жадный (`*`) vs ленивый (`*?`) поиск

Квантификатор задаёт число повторений предшествующего символа или группы:

| Квантификатор | Число повторений | Пример шаблона |
| :--- | :--- | :--- |
| `*` | 0 или более раз | `a*` |
| `+` | 1 или более раз | `\d+` |
| `?` | 0 или 1 раз (необязательный) | `https?` |
| `{n}` | Ровно `n` раз | `\d{4}` |
| `{n,m}` / `{n,}` | От `n` до `m` / от `n` и выше | `\d{4,6}` |

По умолчанию `*`, `+` и `{n,m}` работают **жадно (greedy)** — захватывают самую длинную подходящую подстроку.

Суффикс `?` делает квантификатор **ленивым (lazy)**, останавливаясь на первом совпадении:

```python
import re

html = '<div>Первый</div> <span>Второй</span>'

# Жадный <.+> идёт до самого последнего '>'
greedy = re.findall(r'<.+>', html)
print('Жадный:', len(greedy))
# >>> Жадный: 1

# Ленивый <.+?> берёт каждый тег отдельно
lazy = re.findall(r'<.+?>', html)
print('Ленивый:', lazy)
# >>> Ленивый: ['<div>', '</div>', '<span>', '</span>']
```

## Якоря и границы строк (`^`, `$`, `\b`)

Якоря фиксируют позицию в строке, не потребляя сами символы:

- **`^`** — начало строки (или каждой строки при `re.MULTILINE`).
- **`$`** — конец строки.
- **`\b`** (*word boundary*) — граница между словесным `\w` и не-словесным `\W` символом.

Использование `\b` предотвращает ложные срабатывания внутри других слов:

```python
import re

text = 'cat category concatenate cat'

# Без границы \b найдёт все 4 вхождения
all_cat = len(re.findall(r'cat', text))
print('Всего cat:', all_cat)
# >>> Всего cat: 4

words = re.findall(r'\bcat\b', text)
print('Изолированные:', words)
# >>> Изолированные: ['cat', 'cat']
```

## Группы захвата `(...)`, `(?:...)` и именованные `(?P<name>...)`

Круглые скобки `(...)` группируют части шаблона и сохраняют найденные подстроки в `match.groups()`, а **`(?:...)`** группирует без сохранения в результат.

Чтобы не ломать код при изменении нумерации скобок, группам дают имена через **`(?P<name>...)`** и читают готовый словарь `match.groupdict()`:

```python
import re

# Незахватывающая группа (?:...)
url_rx = r'(?:https?://)?(github\.com/\w+)'
url = 'https://github.com/py'
m_url = re.search(url_rx, url)
print(m_url.groups() if m_url else ())
# >>> ('github.com/py',)

# Именованные группы -> .groupdict()
log = 'IP: 192.168.1.10 | STATUS: 200'
pattern = (
    r'IP: (?P<ip>[\d.]+) \| '
    r'STATUS: (?P<status>\d+)'
)
match = re.search(pattern, log)
if match:
    data = match.groupdict()
    print(data['ip'], data['status'])
    # >>> 192.168.1.10 200
```

## `re.compile()`, ReDoS и чек-лист выбора инструмента

Функция **`re.compile(pattern, flags)`** заранее компилирует регулярку для циклов и принимает флаги `re.IGNORECASE` (`re.I`), `re.MULTILINE` (`re.M`), `re.DOTALL` (`re.S` — точка матчит `\n`) и `re.VERBOSE` (`re.X`).

Пример компиляции регистронезависимого шаблона проверки email:

```python
import re

email_rx = re.compile(
    r'^[a-z0-9_.+-]+@[a-z0-9-]+\.[a-z]+$',
    re.IGNORECASE,
)
valid = email_rx.match('Admin@Host.ORG')
print(bool(valid))
# >>> True
```

Избегайте вложенных квантификаторов вроде `(a+)+$` и `([a-zA-Z]+)*`: на неподходящем входе они вызывают **ReDoS** (*катастрофический бэктрекинг* $O(2^n)$), надолго удерживая GIL.

Краткий чек-лист выбора инструмента:

- **Подстрока или префикс/суффикс:** `in`, `.startswith()`, `.endswith()` — быстрее любого regex.
- **Фиксированный разделитель или замена:** `str.split()`, `str.partition()`, `str.replace()`.
- **Валидация формата или парсинг логов:** `re.fullmatch()` и `re.finditer()`.
- **Вложенный HTML/XML:** специализированные парсеры вроде `BeautifulSoup` или `lxml`.
