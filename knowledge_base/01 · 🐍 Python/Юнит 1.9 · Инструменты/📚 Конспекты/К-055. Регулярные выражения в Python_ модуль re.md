## Зачем нужны регулярные выражения: re vs строковые методы

**Регулярное выражение (RegEx)** — это декларативный мини-язык описания шаблонов в тексте: валидация формата email, поиск IP-адресов в access-логах, извлечение параметров из неструктурированных данных. В стандартной библиотеке Python за это отвечает модуль **`re`**.

Главное правило на техническом скрининге: **не используйте регулярки там, где достаточно обычных методов `str`**. Строковые методы работают в разы быстрее и не требуют компиляции автомата:

```python
import re

text = 'admin@example.com'

# 1. Быстрые строковые методы:
print('@' in text)  # True
print(text.endswith('.com'))  # True

# 2. Модуль re для сложных шаблонов:
email_rx = r'^[\w.-]+@[\w.-]+\.\w+$'
print(bool(re.search(email_rx, text)))
```

## re.search() — первое совпадение и объект Match

Функция **`re.search(pattern, string)`** сканирует всю строку и возвращает объект **`Match`** для **первого** найденного совпадения (или `None`, если совпадений нет).

```python
import re

log_line = (
    '2026-10-19 ERROR [user_id=42]: '
    'timeout connecting to db'
)

# re.search() ищет первое совпадение:
pattern = r'user_id=(\d+)'
match = re.search(pattern, log_line)
if match:
    # Весь совпавший фрагмент:
    print('Совпадение:', match.group(0))
    # Извлечённое значение:
    print('Значение:', match.group(1))
    # Индексы среза в строке:
    print('Индексы:', match.span())
```

- **`match.group(0)`** (или `match.group()`) — весь совпавший фрагмент строки.
- **`match.start()` / `match.end()`** — начальный и конечный индексы среза в исходной строке.
- **`match.span()`** — кортеж `(start, end)` для прямого взятия среза `log_line[start:end]`.

## re.match() vs re.fullmatch(): валидация префикса и полной строки

Классическая ловушка первого скрининга — разница между `search`, `match` и `fullmatch`:

- **`re.search()`** — ищет совпадение **в любой части строки**.
- **`re.match()`** — ищет совпадение **строго от начала строки** (неявно добавляет `^`).
- **`re.fullmatch()`** — требует, чтобы **вся строка от начала до конца** соответствовала шаблону.

```python
import re

text = 'order_12345_complete'

# re.match() проверяет только начало:
print(bool(re.match(r'order_\d+', text)))
# True (префикс совпадает)

print(bool(re.match(r'12345', text)))
# False (число не в начале)

# re.fullmatch() проверяет всю строку:
is_full = re.fullmatch(r'order_\d+', text)
print(bool(is_full))
# False (хвост _complete лишний)

slug = 'valid-slug-2026'
rx = r'[a-z0-9-]+'
print(bool(re.fullmatch(rx, slug)))
# True — 100% валидный slug
```

Для валидации пользовательского ввода (URL slug, телефон, номер карты) всегда используйте **`re.fullmatch()`** вместо `re.match()`, чтобы исключить инъекции в конце строки.

## re.findall() vs re.finditer(): память и ленивая обработка логов

Когда нужно извлечь все совпадения из текста, используются две функции:

1. **`re.findall(pattern, text)`** — возвращает обычный **`list`** со всеми найденными строками. Удобно для коротких строк, но неэффективно по памяти на файлах в сотни мегабайт.
2. **`re.finditer(pattern, text)`** — возвращает **ленивый итератор** объектов `Match`. Позволяет обрабатывать строки по одной в генераторном пайплайне, не аллоцируя массив в RAM.

```python
import re

text = 'Цены: 1500 руб, 3200 руб, 450 руб'

# 1. re.findall() возвращает список строк:
prices = re.findall(r'\d+', text)
print('Все цены списком:', prices)

# 2. re.finditer() — ленивый итератор:
for m in re.finditer(r'\d+', text):
    val = m.group()
    pos = f'{m.start()}..{m.end()}'
    print(f'Число {val} на позиции {pos}')
```

## re.sub() и re.split(): замена и гибкое разделение текста

### re.sub() — замена по динамическому шаблону
Метод `re.sub(pattern, repl, string, count=0)` заменяет совпадения шаблона. В параметр `repl` можно передать не только строку, но и вызываемую функцию-трансформер `callable(Match) -> str`:

```python
import re

# Маскирование (оставляем только цифры):
phone = '+7 (999) 123-45-67'
clean_digits = re.sub(r'\D', '', phone)
print('Только цифры:', clean_digits)

# Разделение по запятым и пробелам:
raw_csv = 'apple , banana; orange, grape'
items = re.split(r'[,;]\s*', raw_csv)
print('Элементы списка:', items)
```

### re.split() vs str.split()
`str.split()` умеет делить только по одному фиксированному символу. Если в файле разделителями выступают и запятые, и табы, и пробелы переменной длины — `re.split(r"[,\t ]+", line)` незаменим.

## Классы символов: \d, \w, \s и их отрицания \D, \W, \S

Специальные управляющие последовательности определяют категории символов. Заглавная буква всегда означает **логическое отрицание**:

- **`.`** — любой одиночный символ, кроме перевода строки `\n`.
- **`\d`** (digit) — любая цифра `[0-9]`.
- **`\D`** — любой символ, **кроме** цифры (буквы, знаки, пробелы).
- **`\w`** (word) — буква, цифра или знак подчёркивания `_` (в Python 3 поддерживает Unicode).
- **`\W`** — любой не-словесный символ (пробелы, знаки препинания, скобки).
- **`\s`** (space) — пробельный символ (пробел, `\t`, `\n`, `\r`).
- **`\S`** — любой непробельный символ.
- **`[abc]`** — символьный класс: любой один символ из перечисленных.
- **`[^abc]`** — отрицающий класс: любой символ, **кроме** перечисленных.

```python
import re

sample = 'User_007: login OK! (code #42)'

# \d — цифры:
digits = re.findall(r'\d+', sample)
print('Цифры:', digits)

# \w — буквы, цифры и _:
words = re.findall(r'\w+', sample)[:3]
print('Слова:', words)

# \S — непробельные символы:
non_space = len(
    re.findall(r'\S+', sample)
)
print('Не пробелы:', non_space)
```

## Квантификаторы повторений: *, +, ? и точные диапазоны {n,m}

Квантификатор указывает, сколько раз предшествующий символ или группа могут повторяться:

- **`*`** — **0 или более** раз (символ может отсутствовать вовсе).
- **`+`** — **1 или более** раз (символ обязан встретиться хотя бы единожды).
- **`?`** — **0 или 1** раз (необязательный символ).
- **`{n}`** — **ровно `n`** раз (например, `\d{4}` для года).
- **`{n,m}`** — от **`n` до `m`** раз включительно.
- **`{n,}`** — не менее **`n`** раз (верхняя граница не ограничена).

```python
import re

codes = ['HTTP', 'HTTPS', 'HTTPSS', 'HTP']

# 'S' опционален (0 или 1 раз):
pattern = r'^HTTPS?$'
valid = [
    c for c in codes
    if re.match(pattern, c)
]
print('HTTP протоколы:', valid)

# Точный диапазон {4,6} цифр для PIN:
pin_pattern = r'^\d{4,6}$'
valid_5 = re.match(pin_pattern, '12345')
print(bool(valid_5))
print(bool(re.match(pin_pattern, '12')))
```

## Границы и якоря: ^, \$, \b

Якоря не сопоставляются с физическими символами, они фиксируют **позицию** в строке:

- **`^`** — начало строки (или начало каждой строки при флаге `re.MULTILINE`).
- **`$`** — конец строки.
- **`\b`** (word boundary) — **граница слова**: граница между символом `\w` и `\W` (или началом/концом строки).

```python
import re

text = 'cat category concatenate cat'

# Без границы \b: найдет все 4 вхождения
all_cat = len(re.findall(r'cat', text))
print("Все 'cat':", all_cat)

# С границей слова \b: отдельное слово
words = re.findall(r'\bcat\b', text)
print('Изолированные:', words)

# Якоря ^ (начало) и $ (конец строки):
print(bool(re.search(r'^cat', text)))
print(bool(re.search(r'cat$', text)))
```

Использование `\b` критично при полнотекстовом поиске тегов или ключевых слов, чтобы не получать ложные срабатывания внутри более длинных слов.

## Группы захвата () и не захватывающие группы (?:...)

Круглые скобки **`(...)`** выполняют две роли: группируют квантификаторы и **захватывают** извлечённые подстроки в объект `Match`.

- **`match.group(1)`** — первая захваченная группа.
- **`match.groups()`** — кортеж всех захваченных групп.
- **`match.group(0)`** — полное совпадение всей регулярки.
- **`(?:...)`** — **не захватывающая группа** (non-capturing group). Группирует логику для квантификатора, но не тратит память на сохранение и не попадает в `match.groups()`.

```python
import re

email = 'alex.dev@corp.example.com'
pattern = r'([\w.]+)@([\w.]+)'

match = re.search(pattern, email)
if match:
    print('Имя:', match.group(1))
    print('Домен:', match.group(2))
    print('Все группы:', match.groups())

# (?:...) группирует, но не захватывает:
url_rx = (
    r'(?:https?://)?'
    r'(github\.com/[\w-]+)'
)
urls = re.findall(
    url_rx,
    'https://github.com/torvalds'
)
print('GitHub URL:', urls)
```

## Именованные группы (?P<name>...) и словарь .groupdict()

В продакшен-коде обращение к группам по номерам `group(1)`, `group(2)` приводит к трудноуловимым ошибкам при изменении шаблона.

Синтаксис **`(?P<name>...)`** присваивает группе имя, а метод **`match.groupdict()`** возвращает готовый `dict`, идеально подходящий для парсинга конфигураций и логов:

```python
import re

log = 'IP: 192.168.1.10 | STATUS: 200'

# Именованные группы (?P<name>...):
pattern = (
    r'IP: (?P<ip>[\d.]+) \| '
    r'STATUS: (?P<status>\d+)'
)

match = re.search(pattern, log)
if match:
    data = match.groupdict()
    print('IP клиента:', data['ip'])
    print('HTTP статус:', data['status'])
    print('Словарь:', data)
```

## Жадные (*) vs ленивые (*?) квантификаторы

По умолчанию квантификаторы `*`, `+`, `{n,m}` являются **жадными (greedy)**: они захватывают максимально длинную цепочку символов, удовлетворяющую условию.

Добавление суффикса **`?`** превращает квантификатор в **ленивый (non-greedy / lazy)**: он захватывает минимально возможное количество символов.

```python
import re

html_snippet = (
    '<div>Первый блок</div> '
    '<span>Второй блок</span>'
)

# Жадный <.+> идет до ПОСЛЕДНЕГО '>':
greedy = re.findall(r'<.+>', html_snippet)
print('Жадный поиск:', len(greedy))

# Ленивый <.+?>: стоп на первом '>':
lazy = re.findall(r'<.+?>', html_snippet)
print('Ленивый поиск:', lazy)
```

На техническом собеседовании этот вопрос задают регулярно: парсинг кавычек `"[^"]*"` или `".*?"` против жадного `".*"`.

## re.compile() и флаги компиляции: IGNORECASE, MULTILINE, DOTALL

Функция **`re.compile(pattern, flags)`** компилирует строку шаблона в байткод регулярного выражения (`Pattern`). CPython кэширует последние скомпилированные регулярки, но явный `re.compile()` на уровне модуля ускоряет циклы и улучшает читаемость.

### Популярные флаги модуля `re`:
- **`re.IGNORECASE` (`re.I`)** — регистронезависимый поиск.
- **`re.MULTILINE` (`re.M`)** — якоря `^` и `$` срабатывают для каждой строки файла (после `\n`), а не только для начала и конца всего текста.
- **`re.DOTALL` (`re.S`)** — символ `.` начинает соответствовать **абсолютно любому символу, включая перевод строки `\n`**.
- **`re.VERBOSE` (`re.X`)** — разрешает форматировать регулярку в несколько строк и добавлять комментарии через `#`.

```python
import re

# 1. Предкомпиляция шаблона:
email_rx = re.compile(
    r'^[a-z0-9_.+-]+@[a-z0-9-]+\.[a-z]+$',
    re.IGNORECASE
)
valid_email = email_rx.match(
    'Admin@Host.ORG'
)
print(bool(valid_email))

# 2. Флаг re.DOTALL: '.' матчит и '\n'
multi = 'start\nhello world\nend'
matched = bool(
    re.search(
        r'start.*end', multi, re.DOTALL
    )
)
print('DOTALL совпадение:', matched)
```

## Безопасность на скрининге: катастрофический бэктрекинг (ReDoS)

**ReDoS (Regular Expression Denial of Service)** — уязвимость отказа в обслуживании из-за катастрофического бэктрекинга движка регулярных выражений (NFA).

Если шаблон содержит вложенные квантификаторы с неоднозначностью (например, `(a+)+$` или `([a-zA-Z]+)*`), при подаче несовпадающей строки вроде `"aaaaaaaaaaaaaaaaaaaaaaaaaaaa!"` движок начинает перебирать все $O(2^n)$ вариантов разбиения, намертво блокируя поток выполнения в GIL на минуты или часы!

```python
import re

# Шаблон без вложенных повторений:
safe_pattern = r'^\w+@\w+\.\w+$'
is_valid = bool(
    re.match(
        safe_pattern, 'user@test.com'
    )
)
print('Безопасный regex:', is_valid)

# Защита от ReDoS на бэкенде:
# 1. Избегать (a+)+ и (.*)*
# 2. Ограничивать длину: len(s) <= 255
# 3. Валидировать через Pydantic v2
```

## Архитектурный выбор: когда использовать regex на практике

Чек-лист Senior-интервьюера для первого технического скрининга:

1. **Точное вхождение подстроки?** ➔ Используйте оператор **`in`** (`if "error" in line:`) или **`str.startswith()` / `str.endswith()`**. Это в 5–10 раз быстрее любого regex.
2. **Фиксированный разделитель?** ➔ Используйте **`str.split(',')`** или **`str.partition(':')`**.
3. **Простая замена подстроки?** ➔ Используйте **`str.replace('old', 'new')`**.
4. **Вариативный шаблон или валидация формата?** ➔ Используйте **`re.fullmatch()`** или **`re.finditer()`** с предкомпиляцией через **`re.compile()`**.
5. **Парсинг HTML / XML?** ➔ **Никогда не парсите вложенный HTML регулярными выражениями!** Используйте специализированные парсеры (`BeautifulSoup`, `lxml`), так как HTML не является регулярным языком (грамматика Хомского).

```python
# Чек-лист выбора инструментов:
# 1. Подстрока: 'sub' in s
# 2. Префикс/суффикс: startswith/endswith
# 3. Разделитель: split()
# 4. Вариативный шаблон: модуль re
# 5. DTO в API: Pydantic v2 BaseModel

print('Регулярные выражения освоены!')
```
