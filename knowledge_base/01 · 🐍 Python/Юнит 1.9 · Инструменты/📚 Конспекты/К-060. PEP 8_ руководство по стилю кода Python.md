## Что такое PEP 8

**PEP 8** (*Python Enhancement Proposal 8*) — официальное руководство по стилю кода Python. Это не требование интерпретатора, а соглашение сообщества ради единообразия и читаемости в команде.

---

## Ключевые правила оформления кода

Основные нормы PEP 8, применяемые в каждом Python-проекте:

| Аспект стиля | Стандарт PEP 8 | Пример / Пояснение |
| :--- | :--- | :--- |
| **Отступы** | Строго 4 пробела | Табуляция запрещена |
| **Длина строки** | 79 символов (72 для комм.) | В командах с `black`/`ruff` — 88–100 |
| **Именование** | `snake_case` / `PascalCase` / `UPPER` | `user_name`, `UserAccount`, `MAX_RETRIES` |
| **Пустые строки** | 2 перед классом/ф-ей, 1 внутри | Между методами класса — 1 строка |
| **Импорты** | По 1 на строке, 3 группы | Stdlib ➔ сторонние ➔ локальные модуля |

Пример типичного нарушения стандарта стиля:

```python
# ПЛОХО: нарушение норм PEP 8
import os,sys

def calculateTotal(price,qty):
  return price*qty

class userAccount:
    def __init__(self,Name):
        self.Name=Name
```

Тот же код, оформленный чисто по требованиям PEP 8:

```python
# Каждый импорт на отдельной строке
import os
import sys

# snake_case, отступ 4 пробела
def calculate_total(price, qty):
    return price * qty

# PascalCase для имени класса
class UserAccount:
    def __init__(self, name):
        self.name = name
```

## Инструменты автоматизации и практика в команде

Проверять PEP 8 глазами ненадёжно, поэтому стиль автоматизируют: сверхбыстрый линтер и форматтер **`ruff`** (написан на Rust, заменяет `flake8`, `isort` и `black`), а также классические `flake8`, `pylint` и `black`.

В продакшене их подключают через хуки `pre-commit` и шаги CI/CD до слияния веток. На собеседованиях номера правил не спрашивают, но ожидают интуитивно чистого кода и понимания роли форматтеров в ревью.
