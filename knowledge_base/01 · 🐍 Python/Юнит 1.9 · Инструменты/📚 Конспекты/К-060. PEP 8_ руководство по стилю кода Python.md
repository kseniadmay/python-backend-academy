## Что такое PEP 8

**PEP 8** (Python Enhancement Proposal 8) – официальное руководство по стилю написания кода на Python, написанное создателем языка Гвидо ван Россумом с соавторами. Это не требование интерпретатора (код без PEP 8 всё равно выполнится), а соглашение сообщества ради единообразия и читаемости кода между разными разработчиками и проектами.

---

## Ключевые правила

- **Отступы** — строго 4 пробела на уровень вложенности, без табуляции.
- **Длина строки** — до 79 символов для кода и до 72 для докстрингов и комментариев (во многих командах используют лимит 88–100 под форматтер `black`).
- **Именование**: `snake_case` для функций и переменных (`user_name`), `PascalCase` для классов (`UserAccount`), `UPPER_SNAKE_CASE` для констант (`MAX_RETRIES`), `_prefix` — соглашение приватности.
- **Пустые строки** — две пустые строки перед классом или функцией верхнего уровня, одна — между методами класса.
- **Импорты** — каждый на отдельной строке и в 3 группах с пустым разделителем: стандартная библиотека, сторонние пакеты, локальные модули проекта.

Пример нарушения PEP 8:

```python
# ПЛОХО: нарушение норм PEP 8
import os,sys
def calculateTotal(price,qty):
  return price*qty
class userAccount:
    def __init__(self,Name):
        self.Name=Name
```

Тот же код по стандарту PEP 8:

```python
import os
# Каждый импорт на отдельной строке
import sys


# snake_case, отступ 4 пробела
def calculate_total(price, qty):
    return price * qty


# PascalCase для имени класса
class UserAccount:
    def __init__(self, name):
        self.name = name
```

## Инструменты автоматической проверки и форматирования

Соблюдение PEP 8 вручную ненадёжно на большом проекте – поэтому используют инструменты: **`flake8`**/**`pylint`** – линтеры, находят нарушения и сообщают о них (не изменяя код), **`black`**/**`autopep8`** – форматтеры, автоматически переписывают код под стиль.

В CI/CD пайплайне линтер обычно запускают как обязательную проверку перед мержем – код, не проходящий проверку стиля, не попадает в основную ветку.

---

## Когда использовать

PEP 8 – базовая гигиена читаемости кода на любом Python-проекте, особенно в команде: единый стиль упрощает чтение чужого кода и уменьшает бессмысленные споры о форматировании в код-ревью.

На собеседовании PEP 8 редко спрашивают дословно (номера правил, точные цифры), но ожидают, что кандидат пишет код, интуитивно ему соответствующий, и знает, зачем нужны линтеры/форматтеры в CI.
