## Что такое PEP 8

**PEP 8** (*Python Enhancement Proposal 8*) — официальное руководство по стилю кода Python. Это не требование интерпретатора, а соглашение сообщества: код читают в разы чаще, чем пишут, поэтому единый стиль экономит время всей команды на code review.

---

## Ключевые правила оформления кода

Основные нормы PEP 8, применяемые в каждом Python-проекте:

| Аспект стиля | Стандарт PEP 8 | Пример / Пояснение |
| :--- | :--- | :--- |
| **Отступы** | Строго 4 пробела | Табуляция запрещена |
| **Длина строки** | 79 символов (72 для комм.) | В командах с `black`/`ruff` — 88–100 |
| **Именование** | `snake_case` / `PascalCase` / `UPPER` | `user_name`, `UserAccount`, `MAX_RETRIES` |
| **Пустые строки** | 2 перед классом/ф-ей, 1 внутри | Между методами класса — 1 строка |
| **Импорты** | По 1 на строке, 3 группы | Stdlib ➔ сторонние ➔ локальные модули |

Пример типичного нарушения стандарта стиля:

```python
# ПЛОХО: нарушение норм PEP 8
import os,sys

def calculateTotal(price,qty):
  return price*qty

class userAccount:
    def __init__(self,Name):
        self.Name=Name
```

Тот же код, оформленный чисто по требованиям PEP 8:

```python
# Каждый импорт на отдельной строке
import os
import sys


# snake_case, отступ 4 пробела
def calculate_total(price, qty):
    return price * qty


# PascalCase для имени класса
class UserAccount:
    def __init__(self, name):
        self.name = name
```

## Идиомы PEP 8 в повседневном коде

Помимо пробелов и имён, PEP 8 закрепляет важные семантические привычки:

- **Сравнение с `None`:** всегда через `is None` / `is not None`, а не `== None` (оператор `==` может быть переопределён классом).
- **Проверка пустоты коллекций:** пишите `if not items:` вместо `if len(items) == 0:`.
- **Булевы значения:** пишите `if is_active:` вместо `if is_active == True:`.
- **Пробелы вокруг `=`:** в присваивании `x = 1` пробелы нужны, а в аргументах по умолчанию `def f(x=1):` — нет (если нет аннотации типа; с аннотацией `x: int = 1` пробелы ставятся).
- **Явные исключения:** избегайте голого `except:` — перехватывайте конкретный тип (`except ValueError:`), иначе скроете `KeyboardInterrupt` и баги.

```python
def find_first(items, default=None):
    # Проверка пустоты без len(items) == 0
    if not items:
        return default

    first = items[0]
    # Проверка None строго через is
    if first is None:
        return default
    return first
```

## Автоматизация: `ruff`, `pre-commit` и CI/CD

Проверять стиль глазами на ревью неэффективно, поэтому в индустрии его полностью автоматизируют.

- **`ruff`** — сверхбыстрый линтер и форматтер на Rust, заменяющий сразу `flake8`, `isort` и `black`.
- Настройки хранят централизованно в `pyproject.toml`, чтобы у всей команды правила были едины:

```toml
[tool.ruff]
line-length = 88
target-version = 'py312'

[tool.ruff.lint]
select = ['E', 'F', 'I', 'UP']
```

Запуск в терминале сводится к двум командам: `ruff check .` (поиск ошибок и нарушений) и `ruff format .` (автоформатирование). В продакшене их вешают на `pre-commit` хуки и пайплайн CI, чтобы неконсистентный код не попадал в `main`.

> **Junior vs Senior**:
> - **Junior**: Спорит на code review о кавычках и пробелах вручную, использует `== None` и оставляет неиспользуемые импорты.
> - **Senior**: Настраивает `ruff` в `pyproject.toml` и `pre-commit`, полностью снимая вопросы стиля с ревью и фокусируясь на архитектуре и логике.
