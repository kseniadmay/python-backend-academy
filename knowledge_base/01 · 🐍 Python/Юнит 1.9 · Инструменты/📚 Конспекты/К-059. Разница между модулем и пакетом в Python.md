## Модуль, пакет и namespace-пакет: суть различий

В Python единицы организации кода выстраиваются в три уровня иерархии:

| Понятие | Физический вид | Особенности и назначение |
| :--- | :--- | :--- |
| **Модуль** | Один файл `.py` | Минимальная единица переиспользования кода |
| **Пакет** | Папка с файлом `__init__.py` | Группировка модулей по слоям или доменам |
| **Namespace-пакет** | Папка без `__init__.py` | Разделение одного пространства имён (PEP 420) |

Простейший модуль `utils.py` достаточно импортировать по имени файла в другом скрипте:

```python
# Модуль — отдельный файл (например, utils.py)
def greet(name: str) -> str:
    return f'Привет, {name}!'

print(greet('Alex'))
# >>> Привет, Alex!
```

## Пакет — директория с подмодулями и вложенностью

Классический пакет представляет собой дерево директорий с файлами `__init__.py`, где каждый файл может выступать подмодулем:

```text
myapp/
├── __init__.py
├── models.py
├── views.py
└── services/
    ├── __init__.py
    ├── payment.py
    └── notification.py
```

Импорт из пакета строится от его корня через точку вместо слешей пути:

```python
# Импорт модуля целиком
from myapp import models
from myapp.services import payment

# Точечный импорт конкретной функции
from myapp.services.payment import (
    process_payment,
)
```

## `__init__.py` — фасад публичного API пакета

Файл `__init__.py` исполняется интерпретатором один раз при первом импорте пакета. В нём часто собирают публичный API из внутренних модулей, чтобы сократить путь импорта для внешнего кода.

Например, подняв функции на уровень корня `myapp/__init__.py`, вы разрешаете писать `from myapp import process_payment`:

```python
# myapp/__init__.py — фасад публичного API
from .payment import process_payment
from .notification import send_notification
```

## Namespace-пакеты (PEP 420) и архитектурные критерии

Начиная с Python 3.3, папка в `sys.path` может импортироваться и без `__init__.py` (**namespace package**, PEP 420) — удобно для распределённых плагинов.

Однако в обычных приложениях `__init__.py` добавляют явно ради предсказуемости.

Выбирайте один модуль для небольших утилит и переходите к пакетам при росте логики по доменам и слоям (каждое приложение Django и любая `pip`-библиотека — это пакет).
