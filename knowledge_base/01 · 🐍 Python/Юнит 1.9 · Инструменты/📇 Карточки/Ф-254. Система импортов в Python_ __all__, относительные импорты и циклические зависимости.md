1. Где Python в первую очередь проверяет наличие модуля при выполнении инструкции import? >> В словаре-кэше sys.modules; если модуль уже загружен туда ранее, его код повторно не исполняется, а сразу возвращается ссылка из кэша.
2. В какой момент объект импортируемого модуля добавляется в словарь sys.modules: до или после выполнения кода самого файла? >> До выполнения кода файла: сначала в sys.modules кладётся пустой объект модуля, и только затем в его пространстве имён сверху вниз исполняется код файла.
3. Почему при циклическом импорте from a import func_a возникает ошибка 'cannot import name func_a from partially initialized module a'? >> Потому что модуль a уже зарегистрирован в sys.modules, но его выполнение приостановилось на верхней строчке импорта модуля b ещё до того, как интерпретатор дошёл до строки def func_a.
4. Какой способ устранения циклических импортов считается самым правильным с точки зрения архитектуры? >> Вынести общие сущности, интерфейсы или схемы в отдельный независимый модуль нижнего уровня, чтобы зависимости шли строго в одну сторону (сверху вниз).
5. Как разорвать циклический импорт, если класс из второго модуля нужен ТОЛЬКО для аннотации типов (type hints)? >> Использовать from __future__ import annotations и поместить импорт внутрь блока if typing.TYPE_CHECKING:, который равен False в рантайме, но читается статическим анализатором mypy.
6. Чему равна константа typing.TYPE_CHECKING во время обычного выполнения программы (в рантайме)? >> Всегда False (она условно считается True только для статических анализаторов типов вроде mypy и pyright).
7. За что отвечает переменная __all__ = [...] внутри модуля или файла __init__.py? >> Явно задаёт список публичных имён модуля, которые будут экспортированы при from module import *, и фиксирует публичный контракт пакета для IDE и линтеров.
8. Какие имена экспортируются при вызове from module import *, если переменная __all__ в модуле НЕ объявлена? >> Все глобальные имена модуля (включая импортированные в него чужие модули и функции), которые не начинаются с символа нижнего подчёркивания _.
9. Почему при запуске файла внутри пакета командой python app/services/auth.py падает ошибка 'ImportError: attempted relative import with no known parent package'? >> При прямом запуске файла как скрипта его __name__ становится '__main__', а __package__ равен None, поэтому Python не видит родительский пакет app для разрешения относительных точек.
10. Как правильно запускать вложенный модуль пакета из терминала, чтобы внутри него работали относительные импорты? >> Запускать из корневой директории проекта как модуль с флагом -m (без расширения .py): python -m app.services.auth.
11. Что означают одна точка и две точки в относительном импорте (from .utils import x и from ..core import y)? >> Одна точка (.) означает текущий пакет, в котором лежит файл; две точки (..) — подъём на один уровень вверх в родительский пакет.
12. Почему в модуле, где нужен циклический вызов, инструкция import a часто работает без ошибок, тогда как from a import func_a падает с ImportError? >> Инструкция import a лишь связывает имя со ссылкой на объект модуля из sys.modules (пусть и не до конца заполненный), а обращение a.func_a() происходит позже внутри функции, когда оба модуля уже полностью загружены.
13. Зачем в конце исполняемых файлов пишут условие if __name__ == '__main__':? >> Чтобы код запуска (тесты, CLI, старт сервера) выполнялся только при прямом запуске этого файла, но не срабатывал автоматически при его импорте в другие модули.
14. Как программно перезагрузить уже импортированный модуль в текущей сессии Python, если он уже закэширован в sys.modules? >> С помощью функции importlib.reload(module_obj) из стандартного модуля importlib.
15. Как динамически импортировать модуль по его строковому имени (например, из конфигурационного файла) во время работы программы? >> Вызвать importlib.import_module('package.module_name') (вместо устаревшего прямого вызова __import__).
16. Почему не стоит называть свои рабочие файлы именами стандартных модулей (например, logging.py, json.py, random.py, email.py)? >> Директория текущего скрипта стоит в начале sys.path, поэтому ваш файл затенит (shadowing) одноимённый модуль стандартной библиотеки, и даже сторонние пакеты упадут при попытке импортировать стандартный модуль.
