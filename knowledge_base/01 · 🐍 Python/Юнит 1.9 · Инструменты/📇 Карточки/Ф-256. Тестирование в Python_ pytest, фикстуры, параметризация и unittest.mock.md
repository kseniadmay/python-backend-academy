1. Что означает главное правило патчинга в unittest.mock: «patch where it is looked up, not where it is defined»? >> Если модуль app.service импортировал функцию через from app.api import fetch, патчить нужно 'app.service.fetch' (там, где имя ищется при вызове), а не 'app.api.fetch'.
2. Как в фикстуре @pytest.fixture разделить код подготовки ресурса (setup) и гарантированной очистки после теста (teardown)? >> Заменить return на yield: код до yield выполняется перед тестом, а код после yield — гарантированно после завершения теста (даже если тест упал).
3. Назовите области видимости (scope) фикстур в pytest от самой узкой к самой широкой. >> function (по умолчанию, на каждый тест) → class → module → package → session (один раз на весь запуск pytest).
4. Зачем нужен файл conftest.py в pytest и нужно ли его импортировать в файлы с тестами? >> Он хранит общие фикстуры и хуки для всей директории и вложенных пакетов; pytest подгружает его автоматически, импортировать его через import нельзя.
5. Чем проверка граничных значений через @pytest.mark.parametrize лучше цикла for внутри одной тестовой функции? >> Каждый набор параметров в parametrize запускается как отдельный изолированный тест: падение одного кейса не прерывает проверку остальных и сразу видно в отчёте.
6. Как в pytest проверить, что функция выбрасывает конкретное исключение и что текст ошибки соответствует шаблону? >> Через контекстный менеджер with pytest.raises(ValueError, match='шаблон регулярки'): вокруг вызова тестируемой функции.
7. В чём разница между атрибутами return_value и side_effect у объектов Mock / MagicMock? >> return_value возвращает одно фиксированное значение, а side_effect позволяет выбросить исключение, вернуть последовательность разных значений по очереди (из списка) или вызвать функцию.
8. Как настроить мок для тестирования retry-механизма, чтобы первые два вызова выбрасывали ConnectionError, а третий возвращал {'ok': True}? >> Присвоить списком: mock_fn.side_effect = [ConnectionError(), ConnectionError(), {'ok': True}].
9. Чем MagicMock отличается от обычного класса Mock в модуле unittest.mock? >> MagicMock уже имеет преднастроенные реализации большинства магических дандер-методов Python (__len__, __iter__, __getitem__, __enter__/__exit__), а обычный Mock — нет.
10. Какой класс из unittest.mock нужно использовать для мокирования асинхронных функций (async def), вызываемых через await? >> AsyncMock (появился в стандартной библиотеке с Python 3.8).
11. Зачем при использовании patch() или создании мока рекомендуется указывать параметр autospec=True (или spec=RealClass)? >> Он проверяет сигнатуру и атрибуты реального объекта: если в тесте вызвать несуществующий метод или передать лишний аргумент, мок сразу выбросит AttributeError или TypeError, а не проглотит ошибку молча.
12. Какими методами у объекта Mock проверяют, что функция была вызвана ровно один раз с конкретными аргументами? >> mock.assert_called_once_with(arg1, key=val) (или просто mock.assert_called_once() без проверки аргументов).
13. Для чего предназначена встроенная фикстура monkeypatch в pytest? >> Для безопасной временной подмены переменных окружения (monkeypatch.setenv), атрибутов объектов (setattr) или элементов словарей с автоматическим откатом после окончания теста.
14. Какую встроенную фикстуру pytest используют для создания изолированных временных файлов и папок в тестах? >> Фикстуру tmp_path, которая возвращает уникальный для каждого теста объект pathlib.Path во временной директории.
15. Как расшифровывается паттерн структуры хорошего юнит-теста AAA? >> Arrange (подготовка данных и окружения), Act (выполнение тестируемого действия), Assert (проверка результата и побочных эффектов).
16. Какая встроенная фикстура pytest позволяет перехватывать сообщения модуля logging и проверять их уровень и текст в тестах? >> Фикстура caplog (например, через caplog.records или caplog.at_level(logging.INFO)).
