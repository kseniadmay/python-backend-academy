1. Как в `pytest` / `unittest.mock` проверить, что mock-метод был вызван ровно один раз с определенными аргументами? >> `mock.assert_called_once_with(arg1, arg2)`
2. Что определяет параметр `scope` в фикстурах `pytest.fixture` ? Перечислите доступные значения. >> Частоту создания фикстуры и время её жизни
3. Перечислите 5 уровней области видимости (scope) фикстур `pytest` в порядке от наименьшего к наибольшему. >> `function` → `class` → `module` → `session`
4. Для чего декоратор `@pytest.mark.parametrize` ? >> Запуск одного теста с несколькими наборами входных данных; устраняет дублирование тестов
5. Самый популярный фреймворк тестирования в Python? >> `pytest`
6. Для чего функция `patch` ? >> Подмена реального объекта моком на время выполнения теста
7. Можно ли использовать несколько фикстур в одном тесте? >> Да; передаются как несколько именованных аргументов
8. Что `pytest` использует для проверки условий? >> Обычный `assert` ; `pytest` перехватывает его и формирует подробное сообщение об ошибке
9. Главное структурное отличие `pytest` от `unittest` ? >> В `pytest` тесты – обычные функции; классы не обязательны
10. Какой `scope` создаёт фикстуру один раз для всего запуска? >> `session`
11. Что такое `conftest.py` ? >> Специальный файл `pytest` ; фикстуры объявленные в нём автоматически доступны всем тестам в директории без импорта
12. Когда выполняется тело теста в жизненном цикле фикстуры? >> В момент `yield`
13. Декоратор для создания фикстуры? >> `@pytest.fixture`
14. Атрибут `Mock` для задания возвращаемого значения? >> `return_value`
15. Как называется механизм подготовки и очистки окружения в `pytest` ? >> Фикстуры ( `fixtures` )
16. В чём разница между `Mock` и `MagicMock` ? >> `MagicMock` автоматически реализует магические методы ( `__len__` , `__str__` , `__iter__` и др.); `Mock` – нет
17. Что означает изоляция кода в тестировании? >> Проверка функции без реального взаимодействия с внешними системами
18. В каких формах применяется `patch` ? >> Контекстный менеджер `with patch(...)` или декоратор `@patch(...)`
19. Когда нужны моки? >> Когда код зависит от внешних систем: БД, API, файловой системы
20. Как фикстура передаётся в тест? >> Как именованный аргумент функции; `pytest` сопоставляет по имени автоматически
21. Что такое моки? >> Объекты-заглушки имитирующие поведение реальных компонентов
22. Из какого модуля импортируются инструменты мокирования? >> `unittest.mock`
23. Что происходит с объектом после выхода из `with patch` ? >> Восстанавливается исходное поведение
24. Как часто создаётся фикстура со `scope='function'` ? >> Для каждого теста отдельно
25. Какое слово разделяет setup и teardown в фикстуре? >> `yield` ; код до – setup, код после – teardown
