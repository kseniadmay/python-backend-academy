1. Как в `pytest` / `unittest.mock` проверить, что mock-метод был вызван ровно один раз с определенными аргументами? >> `mock.assert_called_once_with(arg1, arg2)`.
2. Что определяет параметр `scope` в фикстурах `pytest.fixture` и какие 5 уровней он может принимать? >> Частоту создания фикстуры и время её жизни; принимает 5 значений от узкого к широкому: `'function'` (по умолчанию), `'class'`, `'module'`, `'package'` и `'session'`.
3. Для чего декоратор `@pytest.mark.parametrize`? >> Запуск одного теста с несколькими наборами входных данных; устраняет дублирование тестов.
4. Самый популярный фреймворк тестирования в Python? >> `pytest`.
5. Для чего функция `patch`? >> Подмена реального объекта моком на время выполнения теста.
6. Можно ли использовать несколько фикстур в одном тесте? >> Да; передаются как несколько именованных аргументов.
7. Что `pytest` использует для проверки условий? >> Обычный `assert`; `pytest` перехватывает его и формирует подробное сообщение об ошибке.
8. Главное структурное отличие `pytest` от `unittest`? >> В `pytest` тесты — обычные функции; классы не обязательны.
9. Какой `scope` создаёт фикстуру один раз для всего запуска? >> `session`.
10. Что такое `conftest.py`? >> Специальный файл `pytest`; фикстуры, объявленные в нём, автоматически доступны всем тестам в директории без импорта.
11. Когда выполняется тело теста в жизненном цикле фикстуры? >> В момент `yield`.
12. Декоратор для создания фикстуры? >> `@pytest.fixture`.
13. Атрибут `Mock` для задания возвращаемого значения? >> `return_value`.
14. Как называется механизм подготовки и очистки окружения в `pytest`? >> Фикстуры (`fixtures`).
15. В чём разница между `Mock` и `MagicMock`? >> `MagicMock` автоматически реализует магические методы (`__len__`, `__str__`, `__iter__` и др.); `Mock` — нет.
16. Что означает изоляция кода в тестировании? >> Проверка функции без реального взаимодействия с внешними системами.
17. В каких формах применяется `patch`? >> Контекстный менеджер `with patch(...)` или декоратор `@patch(...)`.
18. В каких случаях при написании тестов в `pytest` необходимо использовать моки (mocking)? >> Когда код зависит от внешних систем: БД, API, файловой системы.
19. Как фикстура передаётся в тест? >> Как именованный аргумент функции; `pytest` сопоставляет по имени автоматически.
20. Каково назначение мок-объектов (`Mock`) при модульном тестировании изолированных компонентов бэкенда? >> Имитация поведения реальных зависимостей (заглушки) для изолированной проверки тестируемого компонента.
21. Из какого модуля импортируются инструменты мокирования? >> `unittest.mock`.
22. Что происходит с объектом после выхода из `with patch`? >> Восстанавливается исходное поведение.
23. Как часто создаётся фикстура со `scope='function'`? >> Для каждого теста отдельно.
24. Какое слово разделяет setup и teardown в фикстуре? >> `yield`; код до — setup, код после — teardown.
25. В чём разница между метриками Line Coverage (покрытие по строкам) и Branch Coverage (покрытие по ветвлениям) при тестировании кода? >> Line Coverage проверяет лишь факт выполнения каждой строки кода, а Branch Coverage требует прохождения обеих веток (`True` и `False`) каждого условия `if/else`.
26. Почему согласно закону Гудхарта 100% покрытие кода тестами (Test Coverage) не гарантирует отсутствие багов в продакшене? >> Coverage показывает только то, какие строки исполнялись во время тестов, но не проверяет качество проверок `assert` и не защищает от пропущенных граничных сценариев.
27. Какой системный хук в модуле `sys` стандартной библиотеки Python используется инструментами вроде `coverage.py` для отслеживания исполняемых строк? >> Функция `sys.settrace()` (или низкоуровневый `sys.monitoring` в Python 3.12+), перехватывающая события вызова функций и перехода между строками байткода.
28. С помощью какого плагина и флага командной строки в `pytest` включают замер покрытия ветвлений (Branch Coverage)? >> Плагин `pytest-cov` с флагами `pytest --cov=app --cov-branch`.
