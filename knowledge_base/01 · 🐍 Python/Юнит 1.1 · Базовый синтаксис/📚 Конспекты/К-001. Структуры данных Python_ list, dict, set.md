## Почему выбор структуры данных важен

Программа стабильно работает на 10 элементах, но зависает на 10 000 при неверном выборе структуры данных. Разные коллекции обеспечивают разную асимптотическую сложность операций.

Выбор структуры диктуется преобладающими операциями: поиск по значению, вставка в начало или конец, удаление либо сортировка.

---

## List: динамический массив и порядок элементов

Список (`list`) — динамический массив указателей, который сохраняет строгий порядок элементов и даёт доступ по индексу за $O(1)$:

```text
items (PyListObject)
┌────────┬────────┬────────┬────────┬────────┐
│ ptr[0] │ ptr[1] │ ptr[2] │ ptr[3] │ ptr[4] │
└───┬────┴────────┴────────┴────────┴────────┘
    ▼
┌──────────────────┐
│ PyLongObject (1) │  (в куче памяти CPython)
└──────────────────┘
```

Основные характеристики операций над списком:

- **Быстрые ($O(1)$):** `arr.append(x)` (в конец), `arr.pop()` (с конца), `arr[2]` (по индексу) и `len(arr)`.
- **Медленные ($O(n)$):** `arr.insert(0, x)`, `arr.pop(0)`, `arr.remove(x)`, `x in arr` — требуют полного обхода или сдвига элементов в памяти.
- **Сортировка ($O(n \log n)$):** `sorted(arr)` и `arr.sort()` используют адаптивный алгоритм Timsort.

Сложность `insert(0, x)` обусловлена физическим сдвигом элементов массива в памяти вправо:

```python
items = [1, 2, 3, 4, 5]
items.insert(0, 0)
print(items)
# >>> [0, 1, 2, 3, 4, 5]
```

## Мутабельность списка: in-place сложение += против создания копии +

Список — изменяемый тип (`mutable`). Оператор `+=` вызывает `__iadd__` и дополняет список на месте, а `+` создаёт новый объект:

```python
a = [1, 2]
b = a
b += [3]

# a и b ссылаются на один список
print(len(a))
# >>> 3

c = [1, 2]
d = c
d = d + [3]

# d стал новым объектом, а c не изменился
print(len(c))
# >>> 2
```

## Хэшируемость и неизменяемость: мост между коллекциями

Ключи `dict` и элементы `set` обязаны быть **хэшируемыми** (`hashable`): иметь неизменный хэш-код (`__hash__`) на всё время жизни и поддерживать равенство (`__eq__`).

Поскольку `list` мутабелен, его содержимое может измениться в любой момент — это сломало бы поиск по хэш-таблице.

Попытка положить список в `set` или ключом `dict` выбрасывает `TypeError`:

```python
# {[1, 2]} вызовет TypeError: unhashable

# Неизменяемый кортеж tuple подходит:
valid_set = {(1, 2), (3, 4)}
print(len(valid_set))
# >>> 2
```

## Dict: мгновенный поиск по ключу

Словарь хранит пары «ключ – значение» в хэш-таблице, поэтому доступ, добавление и проверка ключа выполняются за $O(1)$:

```python
d = {'key': 42}

# O(1) — мгновенный доступ по ключу
value = d['key']

# O(1) — добавление новой пары
d['new'] = 10

# O(1) — проверка наличия без перебора
is_present = 'key' in d

print(value, is_present)
# >>> 42 True
```

Это **амортизированный $O(1)$**: изредка Python расширяет таблицу или разрешает коллизию, но в среднем операция выполняется мгновенно.

## Set: уникальность и мгновенная проверка

Множество (`set`) устроено как хэш-таблица без значений: оно хранит только уникальные элементы и мгновенно проверяет вхождение за $O(1)$:

```python
s = {1, 2}
x = 3

# O(1) — мгновенное добавление и удаление
s.add(x)
s.remove(x)

# O(1) — проверка вхождения через хэш
is_member = x in s
print(s, is_member)
# >>> {1, 2} False
```

Теоретико-множественные операции над двумя `set` тоже опираются на хэш-таблицу:

| Операция | Оператор | Сложность |
| :--- | :--- | :--- |
| Пересечение (общие) | `a & b` | $O(\min(n, m))$ |
| Разность (только в `a`) | `a - b` | $O(n)$ |
| Объединение (все уникальные) | `a | b` | $O(n + m)$ |
| Симметрическая разность | `a ^ b` | $O(n + m)$ |

## Поиск дубликатов: от O(n²) к O(n) через set

Наивный поиск дубликатов проверяет пары вложенным циклом за $O(n^2)$ времени и $O(1)$ памяти:

```python
def has_duplicate(arr):
    # Внешний индекс опорного элемента
    for i in range(len(arr)):
        # Сравниваем только с правым остатком
        for j in range(i + 1, len(arr)):
            if arr[i] == arr[j]:
                return True
    return False

sample = [4, 8, 15, 16, 23, 42, 15]
print('has_duplicate:', has_duplicate(sample))
# >>> has_duplicate: True
```

Для $10\,000$ элементов двойной цикл делает до $\approx 50\,000\,000$ сравнений. Проходя массив за один раз с множеством `seen`, мы ускоряем поиск до линейного $O(n)$:

```python
def has_duplicate_fast(arr):
    # Храним уже встреченные числа
    seen = set()
    for x in arr:
        # Проверка x in seen за O(1)
        if x in seen:
            return True
        seen.add(x)
    return False

sample = [4, 8, 15, 16, 23, 42, 15]
res = has_duplicate_fast(sample)
print('Fast duplicate:', res)
# >>> Fast duplicate: True
```

Это **компромисс времени и памяти (Time-Space Tradeoff)**: мы тратим $O(n)$ RAM на `seen`, чтобы сократить время с $O(n^2)$ до $O(n)$.

## Сравнение асимптотики и правила выбора

Сравнение ключевых операций в трёх базовых структурах Python:

| Операция | `list` | `dict` | `set` |
| :--- | :--- | :--- | :--- |
| Проверка вхождения (`x in ...`) | $O(n)$ | **$O(1)$** (по ключу) | **$O(1)$** |
| Доступ по индексу `arr[i]` | **$O(1)$** | — | — |
| Доступ по ключу `d[k]` | — | **$O(1)$** | — |
| Удаление произвольного элемента | $O(n)$ | **$O(1)$** | **$O(1)$** |
| Получение длины `len()` | **$O(1)$** | **$O(1)$** | **$O(1)$** |

Правило выбора: нужен порядок и доступ по индексу — берите `list`; пары «ключ – значение» — `dict`; уникальность и частые проверки `x in ...` — `set`.

> **Junior vs Senior**:
> - **Junior**: Использует список `list` для частых проверок принадлежности `if x in items`, получая скрытую деградацию производительности $O(n)$ на каждом запросе.
> - **Senior**: Выбирает `set` или `dict` для мгновенных проверок наличия за $O(1)$, а список сохраняет строго для упорядоченных последовательностей элементов.
