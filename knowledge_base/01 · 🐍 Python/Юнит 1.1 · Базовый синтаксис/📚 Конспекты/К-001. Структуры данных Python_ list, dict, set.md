## Почему выбор структуры данных важен

Программа стабильно работает на 10 элементах, но зависает на 10 000 при неверном выборе структуры данных. Разные структуры обеспечивают различную асимптотическую сложность операций — это ключевой рычаг оптимизации backend-производительности.

Выбор структуры диктуется преобладающими операциями: поиск по значению, вставка в начало или конец, удаление либо сортировка.

---

## List: динамический массив и порядок элементов

Список (`list`) – динамический массив указателей. Идеален, когда нужно сохранить строгий порядок элементов и обращаться к ним по целочисленному индексу за $O(1)$.

```text
items (PyListObject)
┌────────┬────────┬────────┬────────┬────────┐
│ ptr[0] │ ptr[1] │ ptr[2] │ ptr[3] │ ptr[4] │
└───┬────┴────────┴────────┴────────┴────────┘
    ▼
┌──────────────────┐
│ PyLongObject (1) │  (в куче памяти CPython)
└──────────────────┘
```

- **Быстрые операции — $O(1)$:** `arr.append(x)` (вставка в конец), `arr.pop()` (удаление с конца), `arr[2]` (доступ по индексу), `len(arr)` (размер массива хранится как атрибут).
- **Медленные операции — $O(n)$:** `arr.insert(0, x)`, `arr.pop(0)`, `arr.remove(x)`, `x in arr`. Все они требуют либо полного прохода, либо физического сдвига элементов в оперативной памяти.

Сложность `insert(0, x)` обусловлена физическим сдвигом элементов массива в памяти вправо:

```python
items = [1, 2, 3, 4, 5]
items.insert(0, 0)
print(items)
# >>> [0, 1, 2, 3, 4, 5]
```

- **Сортировка:** `sorted(arr)` использует адаптивный алгоритм Timsort со сложностью $O(n \log n)$.

## Мутабельность списка: in-place сложение += против создания копии +

Список — изменяемый тип (`mutable`). Оператор `+=` вызывает метод `__iadd__`, который дополняет список **на месте** (in-place), не создавая нового объекта:

```python
a = [1, 2]
b = a
b += [3]

# ссылаются на один список
print(len(a))
# >>> 3

# В отличие от создания нового списка через +:
c = [1, 2]
d = c
d = d + [3]

# d стал новым объектом, а c не изменился
print(len(c))
# >>> 2
```

## Хэшируемость и неизменяемость: мост между коллекциями

Списки `list` не могут быть элементами множества `set` или ключами словаря `dict`. Ключи и элементы хэш-таблиц обязаны быть **хэшируемыми** (`hashable`): иметь неизменный на протяжении всей жизни объекта хэш-код (метод `__hash__`) и поддерживать строгое сравнение на равенство (метод `__eq__`).

Поскольку `list` мутабелен, его содержимое может измениться в любой момент — это сломало бы поиск по хэш-таблице. Попытка использовать изменяемую коллекцию там, где требуется хэш, немедленно выбрасывает `TypeError: unhashable type: 'list'`:

```python
# Ошибка при попытке положить список в множество:
# set_of_lists = {[1, 2], [3, 4]}  # >>> TypeError: unhashable type: 'list'

# Корректное решение — использовать неизменяемый кортеж tuple:
valid_set = {(1, 2), (3, 4)}
print(len(valid_set))
# >>> 2
```

## Dict: мгновенный поиск по ключу

Словарь – структура «ключ – значение» на основе хэш-таблицы. Хэш-функция мгновенно превращает ключ в адрес в памяти – поэтому доступ, добавление и проверка наличия выполняются за $O(1)$.

```python
d = {'key': 42}

# O(1) — мгновенный доступ по ключу
value = d['key']

# O(1) — добавление новой пары
d['new'] = 10

# O(1) — проверка наличия без перебора
is_present = 'key' in d

print(value, is_present)
# >>> 42 True
```

Это называется **амортизированным $O(1)$**: иногда Python нужно расширить таблицу в памяти или разрешить коллизию (когда два разных ключа претендуют на один адрес). В эти редкие моменты скорость падает, но в подавляющем большинстве случаев операция мгновенная.

## Set: уникальность и мгновенная проверка

Множество – это словарь без значений, только ключи. Главная суперсила – мгновенная проверка наличия и уникальность элементов.

```python
s = {1, 2}
x = 3

# O(1) — мгновенное добавление
s.add(x)

# O(1) — быстрое удаление
s.remove(x)

# O(1) — проверка вхождения через хэш-таблицу
is_member = x in s
print(s, is_member)
# >>> {1, 2} False
```

Операции над двумя множествами – пересечение `&` (общие элементы), объединение `|` (все уникальные из обоих), разность `-` (есть в первом, но нет во втором) и симметрическая разность `^` – работают быстро за счёт хэш-таблицы: `&` за $O(\min(n, m))$, `-` за $O(n)$, а `|` и `^` за $O(n + m)$.

---

## Сравнение операций

Проверка вхождения (`x in ...`): список – $O(n)$, словарь и множество – $O(1)$. Удаление элемента: список – $O(n)$, словарь и множество – $O(1)$. Доступ по индексу: только список – $O(1)$. Доступ по ключу: только словарь – $O(1)$. Длина структуры: все три – $O(1)$.

## Практический кейс: наивный поиск дубликатов O(n²)

Построчный разбор работы алгоритма:

```python
def has_duplicate(arr):
    # Шаг 1: перебираем опорный элемент
    for i in range(len(arr)):
        # Шаг 2: сравниваем его только со
        # следующими элементами
        for j in range(i + 1, len(arr)):
            # Шаг 3: проверка пары за O(1)
            if arr[i] == arr[j]:
                return True

    # Шаг 4: обход завершён, совпадений нет
    return False

sample = [4, 8, 15, 16, 23, 42, 15]
print("has_duplicate:", has_duplicate(sample))
# >>> has_duplicate: True
```

- **Строка 3 (`for i in range(len(arr)):`):** Внешний указатель выбирает базовый элемент.
- **Строка 6 (`for j in range(i + 1, len(arr)):`):** Внутренний указатель обходит строго оставшиеся элементы справа (`i + 1`). Сравнивать элемент с самим собой или элементами слева не требуется.
- **Строка 8 (`if arr[i] == arr[j]:`):** Одиночная проверка равенства за $O(1)$. При первом совпадении немедленно выходим через `return True` (ранний выход).
- **Строка 11 (`return False`):** Срабатывает только после полного исчерпания всех возможных пар.

- **Сложность по времени — $O(n^2)$:** два вложенных цикла сравнивают каждый элемент с каждым последующим ($n(n-1)/2$ сравнений). На массиве из $10\,000$ элементов это до $\approx 50\,000\,000$ операций.
- **Сложность по памяти — $O(1)$:** не требует вспомогательной оперативной памяти.

## Быстрый поиск через set: O(n) и Time-Space Tradeoff

Построчный разбор работы быстрого алгоритма:

```python
def has_duplicate_fast(arr):
    # Множество уже встреченных чисел
    seen = set()
    for x in arr:
        # Поиск в set за O(1) через хэш
        if x in seen:
            return True

        # Запоминаем элемент за O(1)
        seen.add(x)
    return False

sample = [4, 8, 15, 16, 23, 42, 15]
print(
    "Fast duplicate:",
    has_duplicate_fast(sample),
)
# >>> Fast duplicate: True
```

- **Строка 3 (`seen = set()`):** Инициализируем пустое множество в памяти.
- **Строка 4 (`for x in arr:`):** Единственный цикл обходит список за один проход ($O(n)$).
- **Строка 6 (`if x in seen:`):** Операция `in` вычисляет хэш ключа и находит его за $O(1)$. Если элемент уже был встречен — дубликат обнаружен мгновенно.
- **Строка 9 (`seen.add(x)`):** Если элемента в множестве нет, добавляем его в хэш-таблицу за $O(1)$.
- **Строка 10 (`return False`):** Список завершён, повторений не найдено.

- **Сложность по времени — $O(n)$:** список обходится ровно один раз. Для $10\,000$ элементов требуется всего $10\,000$ операций (в $5\,000$ раз быстрее наивного поиска!).
- **Сложность по памяти — $O(n)$:** вспомогательное множество `seen = set()` хранит уникальные элементы.
- **Компромисс времени и памяти (Time-Space Tradeoff):** мы осознанно расходуем память $O(n)$, чтобы радикально ускорить работу программы с квадратичной до линейной.

## Как выбирать

Нужен порядок и доступ по индексу – **list**. Нужно хранить пары «ключ – значение» для быстрого поиска – **dict**. Нужно мгновенно проверять наличие элемента и важна уникальность – **set**.

## Инженерные ориентиры выбора структур данных

> **Junior vs Senior**:
> - **Junior**: Использует список `list` для частых проверок принадлежности `if x in items`, получая скрытую деградацию производительности $O(n)$ на каждом запросе.
> - **Senior**: Выбирает `set` или `dict` для мгновенных проверок наличия за $O(1)$, а список сохраняет строго для упорядоченных последовательностей элементов.
