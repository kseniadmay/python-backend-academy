## open() и обязательное закрытие файла

Функция **`open(path, mode)`** открывает файл и возвращает файловый объект.

После работы его нужно обязательно закрыть, иначе буфер может не сброситься на диск, а файловый дескриптор утечёт:

```python
f = open('data.txt', 'r')
content = f.read()

# Файл нужно закрывать: close() легко забыть
f.close()
```

---

## with open() – правильный идиоматичный способ

Контекстный менеджер `with` гарантированно вызывает `__exit__()` и закрывает файл при выходе из блока, даже если возникло исключение:

```python
with open('data.txt', 'r') as f:
    content = f.read()
```

Схема жизненного цикла файлового дескриптора внутри блока `with`:

```text
          with open('data.txt', 'w') as f
                        │
            1. __enter__() вызывается
                        │
       ┌────────────────▼────────────────┐
       │       Тело блока with           │
       │   f.write('payload')            │
       │   (или возникает исключение)    │
       └────────────────┬────────────────┘
                        │
            2. __exit__() вызывается
                        │
       ┌────────────────▼────────────────┐
       │      Файл закрыт в ОС!          │
       │  Дескриптор освобождён          │
       └─────────────────────────────────┘
```

Открывать файлы вручную без `with` или `try...finally` считается ошибкой из-за риска исчерпания лимита открытых файлов ОС при сбое.

## Режимы открытия файла

Второй аргумент `open()` определяет права доступа и способ работы с содержимым:

```python
# Только чтение (ошибка, если файла нет)
open('file.txt', 'r')

# Перезапись с нуля (создаст новый)
open('file.txt', 'w')

# Дозапись в конец без затирания
open('file.txt', 'a')

# Создать новый (ошибка, если уже есть)
open('file.txt', 'x')

# Чтение и запись без обнуления файла
open('file.txt', 'r+')

# Бинарное чтение (картинки, PDF)
open('image.png', 'rb')

# Бинарная запись с перезаписью
open('image.png', 'wb')
```

Самая частая ошибка — спутать `'w'` и `'a'`: режим `'w'` мгновенно обнуляет существующий файл прямо в момент вызова `open()`.

## Способы чтения

Выбор метода чтения определяет нагрузку на оперативную память:

```python
with open('data.txt') as f:
    # Весь файл целиком одной строкой
    content = f.read()

with open('data.txt') as f:
    # Список строк с '\n' на конце
    lines = f.readlines()

with open('data.txt') as f:
    # Построчно, лениво: O(1) по памяти
    for line in f:
        process(line.strip())
```

Для больших логов и файлов в несколько гигабайт используйте итерацию `for line in f`: она не загружает файл целиком в RAM, в отличие от `f.read()`.

## Кодировка – источник частых багов

Чтобы поведение не зависело от локали конкретной операционной системы, всегда явно указывайте кодировку `UTF-8`:

```python
with open('data.txt', encoding='utf-8') as f:
    content = f.read()
```

Без явного `encoding='utf-8'` на Windows по умолчанию может выбраться `cp1251`, что сломает чтение файлов с юникодом.

## pathlib и правила работы с файлами в продакшене

Объектный API **`pathlib.Path`** заменяет строковые пути и `os.path`, объединяя сегменты кроссплатформенно через `/`:

```python
from pathlib import Path

# Кроссплатформенное построение пути
path = Path('data') / 'reports' / '2026.txt'

# Запись и чтение без open()/close()
path.write_text('данные', encoding='utf-8')
content = path.read_text(encoding='utf-8')

print(path.exists())
# >>> True

print(path.suffix)
# >>> .txt

print(path.stem)
# >>> 2026
```

Всегда оборачивайте файловый ввод-вывод в `with`, явно задавайте `encoding='utf-8'`, читайте гигабайты построчно и работайте с путями через `pathlib`.

> **Junior vs Senior**:
> - **Junior**: Открывает файл через `f = open('data.txt')` без `with` или открывает файлы в цикле, получая ошибку операционной системы `EMFILE: Too many open files` при сбоях и забывая указать `encoding='utf-8'`.
> - **Senior**: Всегда использует `with open(...)` с явным `encoding='utf-8'`, для больших файлов читает построчно через `for line in f` (сохраняя $O(1)$ потребление памяти), а для манипуляций с файловой системой использует `pathlib.Path`.
