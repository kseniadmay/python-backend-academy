## open() и обязательное закрытие файла

**`open(path, mode)`** – базовый способ получить доступ к файлу. Возвращает файловый объект, через который можно читать или писать, но который необходимо явно закрыть после использования – иначе данные могут не записаться до конца (буферизация) и дескриптор файла останется занят операционной системой.

```python
f = open('data.txt', 'r')
content = f.read()
f.close()  # обязательно закрыть – легко забыть, особенно если между open() и close()
```

---

## with open() – правильный идиоматичный способ

```python
with open('data.txt', 'r') as f:
    content = f.read()
```

`open()` реализует протокол контекстного менеджера (`__enter__`/`__exit__`, см. тему про `with`) – файл гарантированно закрывается при выходе из блока `with`, в том числе при исключении внутри блока. Открывать файлы без `with`/`try-finally` считается плохой практикой именно из-за риска утечки открытых дескрипторов при необработанном исключении.

## Режимы открытия файла

```python
open('file.txt', 'r')  # read – чтение, файл должен существовать (иначе FileNotFoundError)
open('file.txt', 'w')  # write – запись, СОЗДАЁТ файл заново, стирая существующее содержимое
open('file.txt', 'a')  # append – запись в конец файла, существующее содержимое сохраняется
open('file.txt', 'x')  # exclusive creation – создать, упадёт с ошибкой если файл уже существует
open('file.txt', 'r+')  # чтение И запись, файл должен существовать
open('image.png', 'rb')  # binary – бинарный режим, вернёт bytes, а не str
open('image.png', 'wb')  # запись в бинарном режиме
```

Самая частая ошибка новичка – перепутать `"w"` и `"a"`: открытие в режиме `"w"` **мгновенно обнуляет** существующий файл, даже если потом ничего не записать – это происходит уже в момент вызова `open()`, не в момент записи.

## Способы чтения

```python
with open('data.txt') as f:
    content = f.read()  # весь файл целиком одной строкой

with open('data.txt') as f:
    lines = f.readlines()  # список строк, каждая с '\n' на конце

with open('data.txt') as f:
    for line in f:  # построчно, лениво – не загружает весь файл в память
        process(line.strip())  # правильный способ для больших файлов
```

Перебор файла в цикле `for line in f` – предпочтительный способ для больших файлов: файл читается построчно, а не загружается целиком в память, как это происходит при `f.read()`. Для файла на несколько гигабайт разница критична.

## Кодировка – источник частых багов

```python
with open('data.txt', encoding='utf-8') as f:
    content = f.read()
```

Явное указание `encoding="utf-8"` – хорошая практика для любого текстового файла, если нет специальной причины использовать другую кодировку: устраняет зависимость поведения кода от настроек конкретной машины, на которой он выполняется.

## pathlib как современная альтернатива работе со строками путей

```python
from pathlib import Path

path = Path('data') / 'reports' / '2026.txt'  # кроссплатформенное построение пути через /
content = path.read_text(encoding='utf-8')  # чтение без явного open()/close()
path.write_text('новое содержимое', encoding='utf-8')

print(path.exists())  # True – проверка существования файла
print(path.suffix)  # '.txt'
print(path.stem)  # '2026'
```

`pathlib.Path` – объектно-ориентированный способ работы с путями и файлами, пришедший на смену старому модулю `os.path` со строковыми путями – избавляет от ручной конкатенации `/` или `\` и различий между операционными системами.

---

## Когда использовать

Всегда открывать файлы через `with` – без исключений, независимо от того, насколько простой скрипт. Использовать построчное чтение (`for line in f`) для больших файлов вместо `f.read()`, чтобы не загружать всё в память разом. Явно указывать `encoding="utf-8"` для текстовых файлов. `pathlib` предпочтительнее ручной работы со строками путей в новом коде – читается яснее и не зависит от разделителя пути конкретной ОС.
