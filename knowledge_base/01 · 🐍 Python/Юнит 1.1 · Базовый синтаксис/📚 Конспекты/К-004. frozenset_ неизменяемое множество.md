## frozenset – неизменяемая версия set

**`frozenset`** – то же множество (уникальные элементы, быстрая проверка на вхождение через хэш-таблицу), но неизменяемое после создания: нет `add()`, `remove()`, `update()`.

```python
s = {1, 2, 3}
# OK – обычный set изменяемый
s.add(4)
print(s)  # {1, 2, 3, 4}

fs = frozenset([1, 2, 3])
# AttributeError: у frozenset нет метода add
fs.add(4)
```

---

## Главная практическая причина существования – хэшируемость

Как и `tuple` в сравнении с `list`, `frozenset` в сравнении с `set` неизменяем – а значит, хэшируем, а значит, его можно использовать как **элемент другого множества** или **ключ словаря**. Обычный `set` – нельзя, ровно по той же причине, по которой нельзя `list`.

```python
regular_set = {1, 2, 3}

frozen = frozenset([1, 2, 3])
# OK – frozenset хэшируем
set_of_sets = {frozen, frozenset([4, 5])}
# {frozenset({1, 2, 3}), frozenset({4, 5})}
print(set_of_sets)

cache = {}
# frozenset как ключ
key = frozenset(['read', 'write'])
cache[key] = 'права администратора'
```

## Операции – те же, что у set, кроме мутирующих

Все теоретико-множественные операции (`|`, `&`, `-`, `^`, `issubset`, `issuperset`) работают одинаково для `set` и `frozenset` – разница только в методах, которые изменяют содержимое на месте.

```python
# Инициализация неизменяемых множеств
a = frozenset([1, 2, 3])
b = frozenset([2, 3, 4])
# O(len(a) + len(b)) — объединение
# Результат: frozenset({1, 2, 3, 4})
print(a | b)
# O(min(len(a), len(b))) — пересечение
# Результат: frozenset({2, 3})
print(a & b)
# O(len(a)) — разность множеств
# Результат: frozenset({1})
print(a - b)  # frozenset({1})
```

## Сценарии применения frozenset

`frozenset` незаменим в двух ключевых ситуациях:

- **Ключ словаря или элемент множества**: когда коллекция уникальных признаков сама должна стать ключом хэш-таблицы (например, кэширование прав доступа: `cache[frozenset(['read', 'write'])] = ...`). Обычный `set` вызовет `TypeError: unhashable type: 'set'`.
- **Неизменяемый контракт функции**: передача множества в функцию с гарантией, что вызываемый код не сможет случайно мутировать коллекцию.

---

## Когда предпочесть обычный set

- **Динамическое наполнение**: когда требуется добавлять или удалять элементы в процессе работы программы (`.add()`, `.discard()`, `.pop()`).
- **Стандартный выбор**: если неизменяемость и хэшируемость не требуются, обычный `set` проще, инициализируется через компактный литерал `{1, 2, 3}` и привычнее в повседневном коде.
