## Главное отличие – изменяемость

`list` — изменяемая (`mutable`) последовательность, а `tuple` — неизменяемая (`immutable`), где состав и порядок элементов фиксируются при создании:

```python
lst = [1, 2, 3]

# OK — список можно менять
lst.append(4)
lst[0] = 100
print(lst)
# >>> [100, 2, 3, 4]

tup = (1, 2, 3)

# Попытка мутации tuple вызовет TypeError
try:
    tup[0] = 100
except TypeError as err:
    print(type(err).__name__)
# >>> TypeError
```

---

## Следствие неизменяемости: tuple можно хэшировать

Поскольку `tuple` неизменяем, при хэшируемых элементах у него стабильный хэш (а кортеж вроде `([1, 2], 3)` со списком внутри всё равно даст `TypeError`).

Благодаря стабильному хэшу `tuple` можно использовать как **ключ словаря** (например, координаты `(x, y)` в кэше) или элемент `set`:

```python
cache = {}

# tuple как ключ — OK
cache[(1, 2)] = 'результат для точки (1,2)'
print(cache[(1, 2)])
# >>> результат для точки (1,2)

# Список не хэшируется: TypeError
try:
    cache[[1, 2]] = 'x'
except TypeError as err:
    print(type(err).__name__)
# >>> TypeError
```

## Семантика: гетерогенная структура vs однородная коллекция

Помимо технических различий, в Python принято разделять типы по смыслу данных:

- **`tuple` (разнородная запись):** фиксированная структура, где позиция определяет смысл поля — например, `point = (x, y)` или `record = (user_id, username, created_at)`.
- **`list` (однородная коллекция):** равноправные элементы одного типа, размер которой меняется — например, `active_users = ['alice', 'bob']` или `pending_orders = [101, 102]`.

## Расход памяти и оверхед структур

Устройство буфера в памяти для обоих типов различается наличием запаса слотов:

```text
tuple (фиксированный массив):
┌────────┬────────┬────────┐
│ ptr[0] │ ptr[1] │ ptr[2] │
└────────┴────────┴────────┘

list (over-allocation под рост):
┌────────┬────────┬────────┬────────┬────────┐
│ ptr[0] │ ptr[1] │ ptr[2] │ unused │ unused │
└────────┴────────┴────────┴────────┴────────┘
```

Кортеж занимает меньше памяти, так как интерпретатору не требуется резервировать запасные слоты под динамический рост:

```python
import sys

# Размер кортежа в байтах
t_size = sys.getsizeof((1, 2, 3))

# Список выделяет память с запасом
l_size = sys.getsizeof([1, 2, 3])
print(t_size < l_size)
# >>> True
```

## Общие свойства последовательностей и выбор в продакшене

Оба типа поддерживают индексацию, срезы, `len()`, перебор в `for` и вложенность: разница только в изменяемости, хэшируемости и памяти, а не в операциях чтения.

Выбирайте `tuple` для неизменяемых контрактов (возврат `return x, y` из функции, ключи кэша, константы), а `list` — для накопления и фильтрации динамических списков.

> **Junior vs Senior**:
> - **Junior**: Использует изменяемый `list` для ключей кэша или параметров конфигурации, сталкиваясь с невозможностью хэширования или случайной мутацией данных.
> - **Senior**: Защищает неизменяемые структуры через `tuple`, экономя память за счёт отсутствия over-allocation и гарантируя потокобезопасность чтения.
