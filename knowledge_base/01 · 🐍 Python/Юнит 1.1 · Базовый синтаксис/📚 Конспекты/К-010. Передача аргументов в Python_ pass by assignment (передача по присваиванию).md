## Механика передачи по присваиванию (Pass by Assignment)

Переменная в Python — это имя в таблице символов, которое хранит указатель на объект `PyObject` в куче памяти.

При вызове функции аргумент без копирования связывается с тем же объектом (**pass by assignment**):

```text
locals()                  Куча CPython
┌─────────────┐       ┌────────────────────┐
│ name='data' │ ────► │ PyListObject [1,2] │
└─────────────┘       └────────────────────┘
                                 ▲
┌─────────────┐                  │
│ arg='items' │ ─────────────────┘
└─────────────┘
```

Последствия зависят от мутабельности объекта (`int`, `str`, `tuple` неизменяемы; `list`, `dict`, `set` изменяемы): мутация внутри функции видна снаружи, а переприсваивание — нет.

---

## Неизменяемые объекты: функция не трогает оригинал

Для неизменяемых типов (`int`, `float`, `str`, `tuple`) любое присваивание внутри функции создаёт новый объект, не меняя исходную переменную:

```python
def change(x):
    # Перепривязка локального имени x
    x = 100

a = 5
change(a)

# Оригинал a по-прежнему указывает на 5
print(a)
# >>> 5
```

При вызове `change(a)` имя `x` получает ссылку на `5`, а строка `x = 100` привязывает локальное имя `x` к новому объекту `100`. Такое разрывание старой связи локального имени называют **rebinding** (перепривязкой).

---

## Изменяемые объекты: функция работает с тем же объектом

При передаче изменяемого объекта (`list`, `dict`, `set`) модифицирующие методы меняют исходный объект в куче напрямую:

```python
def append_item(lst):
    # Мутация меняет исходный объект
    lst.append(99)

my_list = [1, 2, 3]
append_item(my_list)
print(my_list)
# >>> [1, 2, 3, 99]
```

Имена `lst` и `my_list` ссылаются на один список в памяти. Вызов `.append(99)` изменяет его на месте, поэтому результат виден вне функции.

---

## Ключевое различие: мутация vs перепривязка

Поведение внутри функции определяет не сам тип данных, а выбранная операция над именем.

- **Перепривязка (`lst = [99]`):** локальное имя `lst` начинает указывать на новый список, а внешний `my_list` остаётся нетронутым — независимо от мутабельности типа.
- **Мутация (`lst.append(99)` или `lst[0] = 99`):** меняет содержимое общего объекта в куче, поэтому изменения проявляются во внешнем коде.

---

## Практические последствия и дефолтные аргументы

Функции, скрытно изменяющие переданные списки или словари, усложняют отладку. Чтобы защитить исходные данные, передавайте копию (`my_list.copy()` или `copy.deepcopy()`).

> **Junior vs Senior**:
> - **Junior**: Объявляет изменяемые значения по умолчанию `def add(item, target=[])`, сталкиваясь с накоплением мусора между вызовами функции.
> - **Senior**: Использует маркер `target: list | None = None` с явной инициализацией `target = [] if target is None else target` внутри тела функции.
