## zip() – параллельный перебор нескольких последовательностей

**`zip()`** объединяет несколько итерируемых объектов поэлементно, возвращая ленивый итератор кортежей – по одному элементу из каждой последовательности за раз.

```python
names = ['Alice', 'Bob', 'Charlie']
scores = [90, 85, 70]

for name, score in zip(names, scores):
    print(name, score)

pairs = list(zip(names, scores))
print(pairs)  # [('Alice', 90), ('Bob', 85), ('Charlie', 70)]
```

---

## zip() останавливается на самой короткой последовательности

Если длины входных последовательностей не совпадают, `zip()` **молча** останавливается там, где заканчивается самая короткая – не бросает исключение и не дополняет отсутствующие значения:

```python
names = ['Alice', 'Bob']  # 2 элемента
scores = [90, 85, 70]  # 3 элемента

result = list(zip(names, scores))
print(result)  # [('Alice', 90), ('Bob', 85)] – третий элемент scores (70) молча отброшен
```

Это частая причина трудноуловимых багов, когда предполагалось, что списки одной длины, а по факту – нет; при необходимости явно проверить совпадение длин или использовать `itertools.zip_longest`, который заполняет недостающие места указанным значением вместо молчаливого обрезания.

## Разворачивание zip через ту же функцию

```python
pairs = [('Alice', 90), ('Bob', 85), ('Charlie', 70)]
names, scores = zip(*pairs)  # распаковка списка кортежей обратно в отдельные последовательности
print(names)  # ('Alice', 'Bob', 'Charlie')
print(scores)  # (90, 85, 70)
```

`zip(*pairs)` – идиоматичный способ "транспонировать" список пар обратно в пару списков, используя тот же принцип распаковки аргументов (`*args`, см. соответствующую тему).

## id() – идентификатор объекта в памяти

**`id(obj)`** возвращает уникальное целое число, идентифицирующее объект на всё время его жизни – в CPython это фактически адрес объекта в памяти (хотя формально спецификация языка гарантирует только уникальность, а не конкретный физический смысл числа).

```python
a = [1, 2, 3]
b = a
c = [1, 2, 3]

print(id(a))  # например, 140234...
print(id(a) == id(b))  # True – b ссылается на тот же объект
print(id(a) == id(c))  # False – c это другой объект с таким же содержимым
```

Именно на сравнении `id()` двух объектов работает оператор `is` (см. тему «== и is») – `a is b` фактически эквивалентно `id(a) == id(b)`.

---

## Практическое применение id()

```python
def process(items, seen_ids=None):
    if seen_ids is None:
        seen_ids = set()
    for item in items:
        if id(item) in seen_ids:
            continue  # пропускаем объект, который уже физически обрабатывали
        seen_ids.add(id(item))
```

`id()` иногда используют вместо `==` для отслеживания уже обработанных объектов, когда важна именно физическая идентичность, а не совпадение значений (например, объекты, которые не поддерживают хэширование через `__hash__`, но нужна дедупликация по ссылке). На практике `id()` чаще встречается при отладке (напечатать `id()`, чтобы убедиться, один это объект или разные копии) – как самостоятельный практический инструмент в бизнес-логике используется довольно редко.

---

## Когда использовать

`zip()` – стандартный инструмент для параллельного перебора нескольких связанных последовательностей одинаковой длины (имена и оценки, ключи и значения, координаты x и y) – всегда явно контролируйте длины входных данных, если совпадение критично для корректности. `id()` – почти исключительно для отладки и явных случаев, когда нужна физическая идентичность объекта, а не сравнение значений; в обычной бизнес-логике вместо `id()` почти всегда правильнее `==` или `is` напрямую.
