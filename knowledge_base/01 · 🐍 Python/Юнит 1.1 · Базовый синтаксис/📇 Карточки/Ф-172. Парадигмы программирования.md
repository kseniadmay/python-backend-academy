1. Какие основные принципы ООП поддерживает Python и чем декларативный стиль отличается от императивного? >> Python полностью поддерживает инкапсуляцию, наследование и полиморфизм; императивный стиль описывает **как** выполнить задачу (пошагово), а декларативный — **что** нужно получить (например, `sum(x for x in data if x > 0)`).
2. Какие встроенные инструменты Python поддерживают функциональную парадигму программирования? >> Функции высшего порядка (`map()`, `filter()`), списковые включения (list/dict/set comprehensions), генераторы (`yield`), лямбда-функции (`lambda`) и модуль `functools` (`reduce`, `partial`, `lru_cache`).
3. Что такое duck typing (утиная типизация) в Python и к какой парадигме она относится? >> Подход динамического полиморфизма: тип объекта определяется его поведением (наличием нужных методов/атрибутов), а не явным наследованием («если крякает как утка — значит утка»).
4. В чём разница между чистой функцией (pure function) и функцией с побочными эффектами (side effects)? >> Чистая функция всегда возвращает одинаковый результат для одинаковых аргументов и не изменяет внешнее состояние; функция с побочными эффектами меняет глобальные переменные, мутирует переданные изменяемые объекты или выполняет I/O.
5. Почему в Python рекомендуется предпочитать списковые включения функциям map() и filter()? >> List comprehensions более читаемы (Pythonic), работают быстрее в CPython за счёт оптимизированного байткода `LIST_APPEND` и не требуют обёртывания в `lambda`.
6. Как в Python реализуется инкапсуляция и сокрытие данных при отсутствии ключевых слов private и protected? >> Через соглашение об именовании: одиночное подчёркивание `_var` (protected по соглашению) и двойное `__var` (name mangling, превращающее имя в `_ClassName__var`).
7. Какая парадигма является первичной для языка Python? >> Мультипарадигменная: Python гармонично сочетает объектно-ориентированное, функциональное и процедурное программирование, позволяя выбирать оптимальный инструмент под задачу.
8. Что такое процедурная парадигма и когда её уместно использовать в Python? >> Организация программы как последовательности вызовов процедур (функций), оперирующих глобальными или переданными данными; идеальна для простых скриптов автоматизации и утилит миграции.
9. Что такое первоклассные функции (first-class functions) в функциональной парадигме Python? >> Функции являются объектами первого класса: их можно присваивать переменным, передавать в качестве аргументов и возвращать из других функций.
10. Что такое каррирование (currying) и как его аналог реализуется в Python? >> Преобразование функции от нескольких аргументов в цепочку функций от одного аргумента; в Python реализуется через замыкания или `functools.partial`.
11. В чём преимущество иммутабельности данных в функциональном стиле? >> Исключает гонки данных (race conditions) при многопоточности, упрощает отладку и гарантирует предсказуемость состояния программы.
12. Как паттерн Strategy (Стратегия) из ООП упрощается в Python благодаря функциональной парадигме? >> Вместо создания иерархии классов со стратегиями достаточно передать обычную функцию или лямбду в качестве аргумента.
13. Что такое полиморфизм подтипов (Subtype Polymorphism) в ООП Python? >> Возможность вызывать один и тот же метод у объектов разных классов, унаследованных от общего предка, с разным специфичным поведением.
14. Что такое композиция и почему принцип ООП «композиция вместо наследования» предпочтителен? >> Включение одного объекта в другой в качестве поля; композиция обеспечивает слабую связанность (loose coupling) и позволяет динамически менять поведение в рантайме.
15. Как статический анализатор MyPy проверяет утиную типизацию (duck typing)? >> Через протоколы `typing.Protocol` (структурная подтипизация / PEP 544): класс считается совместимым, если реализует сигнатуры методов протокола.
