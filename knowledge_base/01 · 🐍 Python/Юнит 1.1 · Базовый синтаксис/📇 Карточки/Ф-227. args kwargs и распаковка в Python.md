1. Что делает `*args` в сигнатуре функции? >> Собирает все лишние позиционные аргументы в кортеж (tuple).
2. Что делает `**kwargs` в сигнатуре функции? >> Собирает все лишние именованные аргументы в словарь (dict).
3. Какой порядок параметров является правильным в сигнатуре функции с `*args` и `**kwargs`? >> `def f(a, b, *args, c, **kwargs):` — сначала позиционные, затем `*args`, затем keyword-only, затем `**kwargs`.
4. Что делает `*` при вызове функции: `f(*my_list)`? >> Распаковывает список в отдельные позиционные аргументы вызова.
5. Что делает `**` при вызове функции: `f(**my_dict)`? >> Распаковывает словарь в отдельные именованные аргументы вызова.
6. Зачем используются `*args` и `**kwargs` в декораторах? >> Чтобы декоратор мог прозрачно прокидывать любые позиционные и именованные аргументы в обёрнутую функцию, не зная её сигнатуру заранее.
7. Что означает `first, *middle, last = [1,2,3,4,5]`? >> first=1, middle=[2,3,4], last=5 — распаковка с сбором "остатка" через звёздочку.
8. Что произойдёт при `{**defaults, **overrides}`, если ключи совпадают? >> Значение из overrides (последнего распакованного словаря) перезапишет значение из defaults.
9. Можно ли поменять местами значения двух переменных без временной переменной? >> Да: a, b = b, a — работает через распаковку кортежа.
10. Обязательно ли называть параметры именно args и kwargs? >> Нет, это общепринятое соглашение; синтаксически важны символы `*` и `**`, а не имена переменных.
11. Что произойдёт при вызове `f(1, 2, x=3)` для функции с сигнатурой `def f(a, b, *, x)` в Python? >> x — keyword-only параметр (после *), обязан передаваться по имени; вызов сработает корректно, x=3.
12. Можно ли распаковать генератор через оператор `*` при вызове функции? >> Да, оператор `*` распаковывает любой итерируемый объект, включая генераторы, списки, множества и кортежи.
13. Что произойдёт при вызове функции `f(*[1, 2], *[3, 4])` в Python? >> Оба списка распакуются в единый набор позиционных аргументов: `f(1, 2, 3, 4)`.
14. Как объявить сигнатуру функции, принимающей исключительно именованные аргументы (keyword-only)? >> `def f(*, a, b):` — одиночная звёздочка без имени запрещает позиционную передачу всех аргументов после неё.
15. Что означает косая черта `/` в сигнатуре функции `def f(a, b, /, c)` в Python 3.8+? >> a и b — позиционно-только параметры (нельзя передать по имени), начиная с Python 3.8.
16. В каком порядке Python заполняет `*args` при смешанном вызове `f(1, 2, 3, key=4)`? >> Сначала заполняются обычные позиционные параметры по порядку определения, остаток уходит в `*args`, а именованные аргументы вне сигнатуры — в `**kwargs`.
17. Что вернёт вызов конструктора `dict(**{'a': 1}, **{'b': 2})` в Python? >> `{'a': 1, 'b': 2}` — распаковка двух словарей в конструктор `dict`.
18. Одинакова ли семантика `*args` при определении функции и при её вызове? >> Нет, семантика противоположна: при определении функции `*` упаковывает аргументы в кортеж, а при вызове — распаковывает коллекцию.
19. Какую ошибку вызовет попытка передать позиционное и именованное значение для одного параметра `f(1, a=1)` в Python? >> `TypeError`: got multiple values for argument 'a' — позиционное и именованное значение конфликтуют.
20. Может ли словарь `**kwargs` содержать ключи, не являющиеся строками? >> Нет, ключи словаря `kwargs` всегда строки — это строгое ограничение синтаксиса именованных вызовов в Python.
21. Почему вызов `f(1, 2, 3)` для сигнатуры `def f(a, *args, b)` завершится ошибкой `TypeError`? >> `TypeError`: f() missing 1 required keyword-only argument: 'b' — b обязан передаваться по имени, позиционные не заполнят его.
22. Как объединить два кортежа через распаковку звёздочкой в один новый кортеж? >> `(*t1, *t2)` — например, распаковка `(*[1, 2], *[3, 4])` сформирует кортеж `(1, 2, 3, 4)`.
23. Эквивалентны ли вызов `dict(a=1, b=2)` и литерал `{'a': 1, 'b': 2}`? >> Да, конструктор `dict()` с именованными аргументами создаёт точно такой же словарь, как и литерал.
