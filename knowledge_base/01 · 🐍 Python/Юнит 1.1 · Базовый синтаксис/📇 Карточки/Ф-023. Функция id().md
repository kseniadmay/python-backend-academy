1. Вернёт ли выражение `x is y` значение `True` для `x = 1000; y = 1000` в общем случае? Почему? >> Нет; создаются два разных объекта
2. Что вернёт `id(a) == id(c)` если `c = [1, 2, 3]` создан отдельно от `a = [1, 2, 3]` ? >> `False` ; разные объекты с одинаковым значением
3. Как называется механизм переиспользования объектов для оптимизации? >> Интернирование
4. Какая функция возвращает уникальный идентификатор объекта? >> `id()`
5. Для чего используется сравнение `id()` двух имён? >> Чтобы проверить ссылаются ли они на один и тот же объект в памяти
6. Какой тип возвращает `id()` ? >> `int`
7. Какие типы данных подвержены интернированию? >> Малые целые числа (от `-5` до `256` ) и некоторые строки
8. Что сравнивает оператор `is` ? >> `id()` двух объектов; возвращает `True` только если это один и тот же объект в памяти
9. Если `id(a) == id(b)` возвращает `True` , сколько объектов в памяти? >> Один
10. Почему для чисел больше `256` Python создаёт разные объекты? >> Они находятся за пределами диапазона интернирования ( `-5` до `256` )
11. Что вернёт `id(a) == id(b)` если `b = a` ? >> `True` ; оба имени указывают на один объект
12. Что представляет `id(obj)` в CPython? >> Адрес объекта в памяти
13. Может ли `id()` совпасть у двух разных объектов? >> Да; если первый объект удалён из памяти, новый объект может занять тот же адрес; поэтому сравнивать `id()` временных объектов опасно
14. Что вернёт `id(x) == id(y)` для `x = y = 1000` ? >> `False` ; `1000` за пределами кэша интернирования
15. Что вернёт `id(x) == id(y)` для `x = y = 256` ? >> `True` ; Python переиспользует один объект
16. Если два объекта имеют одинаковое значение, гарантирует ли это равенство `id()` ? >> Нет; `==` проверяет значение, `is` проверяет идентичность
17. Какой оператор выполняет ту же проверку что и сравнение `id()` ? >> `is`
