1. Каковы 5 стандартных уровней логирования в модуле `logging` Python в порядке возрастания их критичности? >> `DEBUG` → `INFO` → `WARNING` → `ERROR` → `CRITICAL`.
2. Каково назначение модуля `timeit` в стандартной библиотеке Python и почему он точнее ручного замера через `time.time()`? >> Точное измерение времени выполнения небольшого участка кода; точнее `time.time()`, так как использует высокоточный таймер (`time.perf_counter`), выполняет многократные прогоны и временно отключает сборщик мусора.
3. В каком порядке (сверху вниз или снизу вверх) следует анализировать трассировку стека (`traceback`) при отладке исключений в Python? >> Снизу вверх; последняя строка — непосредственное место ошибки.
4. Что значит воспроизвести баг минимальным примером? >> Создать самый короткий код, гарантированно вызывающий ту же ошибку.
5. Какое действие выполняет команда `n` (next) при пошаговой отладке строк кода в `pdb`? >> Следующая строка (без захода в функцию).
6. Какое действие выполняет команда `q` (quit) для завершения сеанса отладки в `pdb`? >> Выйти из дебаггера.
7. Какое действие выполняет команда `l` (list) при инспекции исходного кода в отладчике `pdb`? >> Показать фрагмент кода вокруг текущей позиции.
8. Что дают IDE-дебаггеры по сравнению с `pdb`? >> Установка точек останова кликом, удобный просмотр переменных, стека и выражений без команд.
9. Какая встроенная функция в Python 3.7+ используется для установки интерактивной точки останова в коде? >> `breakpoint()`.
10. Чем команда `s` (step) отличается от команды `n` (next) при пошаговой отладке в отладчике `pdb`? >> `s` (`step`) заходит внутрь вызываемой функции, а `n` (`next`) выполняет вызов целиком и переходит к следующей строке текущей функции.
11. Что использовать для проверки предположений перед дебаггером? >> `assert` или `print`.
12. Первый шаг алгоритма отладки? >> Воспроизведение бага на минимальном примере.
13. Уровень для максимально подробной информации? >> `logging.DEBUG`.
14. Что следует за воспроизведением бага? >> Изоляция проблемного участка.
15. С какой версии Python появился `breakpoint()`? >> Python 3.7.
16. Самый быстрый способ отладки для простых случаев? >> `print()` и `logging`.
17. Какими преимуществами (подсветка синтаксиса, автодополнение) отладчик `ipdb` на базе IPython обладает по сравнению с `pdb`? >> Улучшенная версия `pdb` с подсветкой синтаксиса и автодополнением.
18. Почему `print` неприемлем в production-коде? >> Нет контроля уровня важности, нет фильтрации, нет записи в файл; засоряет вывод.
19. Какое действие выполняет команда `p expr` при исследовании значений выражений в отладчике `pdb`? >> Вычисляет и печатает значение выражения `expr`.
20. В каких случаях разработчику необходимо запускать профилирование производительности кода (profiling) в Python? >> Когда код работает корректно, но слишком медленно.
21. Что представляет собой стандартный модуль `pdb` в Python и как установить точку останова в коде? >> Встроенный интерактивный дебаггер для пошагового исследования состояния программы; точка останова ставится вызовом `breakpoint()` (Python 3.7+) или `pdb.set_trace()`.
22. Модуль для полного профилирования? >> `cProfile`; показывает время выполнения каждой функции.
23. Преимущество `breakpoint()` перед `pdb.set_trace()`? >> Короче и не требует явного импорта `pdb`.
24. Почему `logging` предпочтительнее `print`? >> Настраиваемые уровни важности, фильтрация, запись в файл; не нужно удалять код после отладки.
25. Что нужно импортировать для логирования? >> `import logging`.
26. Какое действие выполняет команда `c` (continue) при управлении выполнением в отладчике `pdb`? >> Продолжить выполнение до следующей точки останова.
27. В чём ограничение `cProfile`? >> Показывает статистику по функциям, но не по строкам; для построчного профилирования нужен `line_profiler`.
28. Как настроить базовый уровень вывода логов? >> `logging.basicConfig(level=logging.DEBUG)`.
