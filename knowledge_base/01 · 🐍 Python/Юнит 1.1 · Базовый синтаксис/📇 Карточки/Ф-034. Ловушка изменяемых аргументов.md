1. Как программно проверить текущее значение изменяемого аргумента по умолчанию у функции? >> Через атрибут `__defaults__` : `add_item.__defaults__` покажет текущее состояние объекта по умолчанию
2. В какой момент создаются и вычисляются значения аргументов функции по умолчанию? >> Один раз при определении функции; не при каждом вызове
3. Что произойдёт при многократных вызовах функции с изменяемым дефолтным аргументом `add_item(1)`: `def add_item(val, lst=[]):; lst.append(val); return lst` ? >> Список накапливает элементы: `add_item(1)` → `[1]` , `add_item(2)` → `[1, 2]`
4. Распространяется ли ловушка изменяемых аргументов по умолчанию на словари ( `d={}` )? Как её избежать? >> Да; `def f(d={})` – та же проблема; рекомендуется `def f(d=None)` с `if d is None: d = {}`
5. Почему использование `lst=None` в качестве дефолтного аргумента решает проблему изменяемых параметров? >> `None` – неизменяемый объект; при каждом вызове создаётся новый локальный список
6. Создаёт ли Python новый список при каждом вызове функции `add_item(1)` с дефолтным аргументом `lst=[]` ? >> Нет; используется один объект, созданный при парсинге определения функции
7. Что такое ловушка изменяемого дефолтного аргумента? >> Дефолтный `list` или `dict` сохраняет состояние между вызовами функции, накапливая данные
8. `def add_item(item, lst=[])` – к какому типу относится `lst` ? >> Изменяемый ( `mutable` ) объект
9. Как правильно инициализировать список внутри функции при `lst=None` ? >> `if lst is None: lst = []` ; при каждом вызове создаётся новый объект
10. Какое значение рекомендуется использовать вместо изменяемого дефолтного аргумента? >> `None`
11. Почему изменяемые объекты как дефолтные аргументы считаются ловушкой? >> Все вызовы без явной передачи аргумента делят один и тот же объект в памяти
