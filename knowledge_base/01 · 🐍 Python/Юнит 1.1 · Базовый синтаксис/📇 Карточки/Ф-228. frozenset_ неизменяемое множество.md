1. Чем frozenset отличается от set? >> frozenset неизменяем после создания — нет add(), remove(), update().
2. Почему frozenset можно положить в другое множество, а set нельзя? >> frozenset хэшируем благодаря неизменяемости, обычный set — нет.
3. Можно ли использовать frozenset как ключ словаря? >> Да, именно из-за хэшируемости.
4. Какие операции доступны у frozenset? >> Все теоретико-множественные: объединение (|), пересечение (&), разность (-), кроме мутирующих методов.
5. Как создать frozenset? >> frozenset([1, 2, 3]) — из любого итерируемого объекта.
6. Что произойдёт при попытке frozenset.add(x)? >> AttributeError — метод add не существует у frozenset.
7. Можно ли создать frozenset из другого frozenset? >> Да, frozenset(other_frozenset) — создаст копию (или тот же объект, если он уже frozenset и неизменяем).
8. Поддерживает ли frozenset оператор in для проверки вхождения? >> Да, с той же O(1) средней сложностью, что и обычный set, благодаря хэш-таблице.
9. Чем frozenset({1,2,3}) отличается от {1,2,3}? >> Вторая запись создаёт обычный изменяемый set, а не frozenset — фигурные скобки без frozenset() всегда дают set.
10. Можно ли сравнивать frozenset и set через ==? >> Да, сравнение идёт по содержимому — frozenset({1,2}) == {1,2} вернёт True, несмотря на разные типы.
11. Что вернёт frozenset() без аргументов? >> Пустой frozenset() — аналог пустого множества, но неизменяемый.
12. Можно ли выполнить объединение frozenset и обычного set через |? >> Да, результат — новый frozenset, если левый операнд frozenset.
13. Хранит ли frozenset элементы в порядке добавления? >> Нет, как и обычный set — порядок не гарантирован, элементы упорядочены по внутреннему хэшу.
14. Могут ли элементы frozenset быть нехэшируемыми (например, list)? >> Нет, все элементы множества (или frozenset) обязаны быть хэшируемыми.
15. Что вернёт len(frozenset([1,1,2,2,3]))? >> 3 — как и обычное множество, frozenset автоматически убирает дубликаты.
