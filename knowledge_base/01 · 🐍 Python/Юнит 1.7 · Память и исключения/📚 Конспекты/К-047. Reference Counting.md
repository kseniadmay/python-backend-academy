## Как работает подсчёт ссылок

**Reference counting** – основной механизм управления памятью в Python. Каждый объект хранит внутри себя счётчик: сколько переменных, списков, словарей и других структур данных на него ссылаются прямо сейчас. Счётчик растёт, когда появляется новая ссылка, и падает, когда ссылка удаляется. Как только счётчик достигает нуля – объект уничтожается немедленно, память освобождается без каких-либо задержек.

```python
import sys

a = [1, 2, 3]
sys.getrefcount(a)  # 2: одна ссылка – переменная a,

b = a  # новая ссылка на тот же объект
sys.getrefcount(a)  # 3

del b  # одна ссылка убрана
sys.getrefcount(a)  # 2
```

`sys.getrefcount()` всегда возвращает значение на единицу больше, чем можно ожидать – сам вызов функции создаёт временную ссылку на объект в момент передачи аргумента.

## Циклические ссылки – слепое пятно reference counting

Reference counting не справляется с одним случаем: когда объекты ссылаются друг на друга по кругу.

```python
a = []
b = []
a.append(b)  # a содержит ссылку на b
b.append(a)  # b содержит ссылку на a
del a, b  # внешние ссылки удалены, но счётчики не нулевые
```

После `del a, b` оба списка по-прежнему держат друг друга в живых через внутренние ссылки. Их счётчики не упадут до нуля никогда – это утечка памяти, которую reference counting обнаружить не может.

Именно для таких случаев существует **garbage collector** – модуль `gc`. Он периодически обходит объекты и ищет изолированные группы с циклическими ссылками, после чего удаляет их все разом.

GC работает по трём **поколениям** (0, 1, 2). Логика простая: большинство объектов живут недолго – создались, использовались, удалились. Поэтому молодые объекты (поколение 0) проверяются часто, а те, что пережили несколько проверок и перешли в поколения 1 и 2, проверяются значительно реже. Это снижает накладные расходы на сборку мусора.
