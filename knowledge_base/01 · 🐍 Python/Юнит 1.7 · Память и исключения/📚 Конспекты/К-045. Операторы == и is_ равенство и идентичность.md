## Разные вопросы

**`==`** спрашивает "равны ли значения?" – вызывает метод `__eq__` объекта и сравнивает **содержимое**. **`is`** спрашивает "это один и тот же объект в памяти?" – сравнивает результат `id()`, то есть физический адрес объекта, без вызова какой-либо пользовательской логики.

```python
a = [1, 2, 3]
b = [1, 2, 3]
c = a

print(a == b)  # True – одинаковое содержимое
print(a is b)  # False – это два разных объекта в памяти
print(a is c)  # True – c ссылается на тот же объект, что и a
print(id(a), id(b), id(c))  # id(a) == id(c) != id(b) (у a и c один адрес памяти)
```

## Почему None сравнивают через is

`None` в Python – **синглтон**: во всей программе существует ровно один объект `None`. Поэтому `is None` не просто стиль, а технически корректный и более быстрый способ проверки – не нужно вызывать `__eq__`, физическое тождество гарантированно означает совпадение. PEP 8 явно рекомендует `if x is None`, а не `if x == None`.

```python
x = None
print(x is None)  # True – идиоматично, рекомендовано PEP 8
print(x == None)  # True – технически тоже сработает, но не рекомендуется
```

## Ловушка с кэшированием мелких чисел и строк

CPython кэширует маленькие целые числа (обычно от -5 до 256) и некоторые строковые литералы – из-за этого `is` может неожиданно вернуть `True` там, где интуитивно ожидали новый объект:

```python
a = 256
b = 256
print(a is b)  # True – маленькие int закэшированы CPython

x = 257
y = 257
print(x is y)  # False (в большинстве случаев) – вне диапазона кэша,
```

Вывод для собеседования: поведение `is` для чисел/строк – **деталь реализации CPython**, а не гарантия языка. Полагаться на `is` для сравнения чисел или строк нельзя – для этого всегда `==`.

---

## Практическое правило

Использовать `==` для сравнения **значений** – то, что нужно в 99% случаев (сравнение чисел, строк, списков, объектов). Использовать `is` только для сравнения с синглтонами (`None`, `True`, `False`) и когда осознанно нужно проверить, что это буквально один и тот же объект (например, проверка на self-reference в рекурсивных структурах, или намеренная проверка идентичности объекта в кэше).

---

## Когда использовать

`is` – только для `None`/`True`/`False` и явных проверок идентичности объекта. Во всех остальных случаях, где сравнивается смысл/содержимое данных – `==`. Перепутать их – частая причина трудноуловимых багов, особенно когда код неожиданно "работает" из-за кэширования мелких чисел в разработке, а потом ломается в продакшене на больших значениях.
