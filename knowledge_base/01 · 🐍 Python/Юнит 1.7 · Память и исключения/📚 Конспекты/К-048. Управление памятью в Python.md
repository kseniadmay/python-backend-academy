## Как Python работает с памятью

В отличие от C и C++, где разработчик вручную вызывает `malloc` и `free`, Python управляет памятью автоматически. Но автоматически не означает магически – под капотом работает несколько конкретных механизмов, которые полезно понимать.

Python не обращается к системе напрямую при каждом выделении памяти. Вместо этого у него есть собственный менеджер памяти, который работает поверх системного `malloc`. Для небольших объектов размером до 512 байт используется специальный аллокатор – **pymalloc**. Он заранее запрашивает у системы крупные блоки памяти и нарезает их на пулы фиксированного размера, из которых быстро выдаёт куски под мелкие объекты. Это существенно быстрее, чем идти к системе за каждым маленьким объектом отдельно.

## Reference counting – основной механизм сборки мусора

Каждый объект в Python хранит внутри себя счётчик ссылок – сколько имён, контейнеров или аргументов функций на него указывают прямо сейчас. Когда счётчик падает до нуля, память освобождается немедленно, без задержек.

```python
import sys

a = []  # счётчик = 1
b = a  # счётчик = 2
del a  # счётчик = 1
del b  # счётчик = 0 → объект уничтожается сразу
```

Проверить текущее значение счётчика можно через `sys.getrefcount()`. Результат всегда будет на единицу больше ожидаемого – потому что сам вызов функции создаёт временную ссылку на объект.

## Cyclic GC – для того, что reference counting не видит

Reference counting не справляется с одним случаем – циклическими ссылками, когда объекты ссылаются друг на друга.

```python
a = {}
b = {}
a['b'] = b
b['a'] = a
```

После `del a` и `del b` оба словаря по-прежнему держат друг друга в живых – их счётчики не нулевые. Reference counting такое не обнаружит.

Для этого в Python есть **garbage collector** – модуль `gc`. Он периодически обходит объекты и ищет циклы. Включён по умолчанию, но его можно настраивать через `gc.collect()`, `gc.disable()` и пороговые значения поколений. Большинству разработчиков трогать его настройки не нужно, но знать о его существовании важно.

## Интернирование – переиспользование объектов

Python не создаёт новый объект каждый раз, когда это не нужно. Для небольших целых чисел от **-5 до 256** и для многих строк Python держит заранее созданные объекты в кеше и возвращает один и тот же объект при каждом обращении. Это называется **интернированием**.

```python
a = 100
b = 100
print(a is b)  # True – один и тот же объект в памяти

a = 1000
b = 1000
print(a is b)  # False – уже два разных объекта
```

Именно поэтому сравнение через `is` даёт неожиданные результаты с числами и строками – и именно поэтому `is` нельзя использовать для проверки равенства значений. `is` проверяет идентичность объекта в памяти, `==` – равенство значений. Это классическая ловушка на собеседованиях.
