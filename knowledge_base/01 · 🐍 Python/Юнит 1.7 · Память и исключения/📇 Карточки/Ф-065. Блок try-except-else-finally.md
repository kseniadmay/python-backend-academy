1. Зачем в конструкции `try-except-else-finally` использовать блок `else` ? >> Чтобы исключения из кода успешного пути не перехватывались текущим `except`
2. Каков порядок выполнения конструкции `try-except-else-finally` , если в `try` НЕ возникло ошибок? >> `try` → `else` → `finally`
3. Каков строгий порядок выполнения блоков `try-except-else-finally` , если внутри `try` возникло исключение? >> `try` → `except` → `finally`
4. Что выведет следующий код с блоками `try-except-else-finally`: `try:; result = 10 / 2; except ZeroDivisionError:; print('Ошибка'); else:; print(f'Успешно: {result}'); finally:; print('Выполняется всегда')` ? >> `Успешно: 5.0` , затем `Выполняется всегда`
5. Что произойдёт если исключение возникнет внутри `else` ? >> Не будет поймано блоком `except` того же уровня; распространится выше
6. В какой момент выполняется `finally` ? >> Всегда: и при исключении, и при успешном выполнении
7. Для чего используется `else` в блоке `try/except` ? >> Для кода, который должен выполняться только при отсутствии исключений; отделяет опасную операцию от логики успешного выполнения
8. Что позволяет избежать раздувания блока `try` ? >> Использование `else` для кода, который не должен перехватываться
9. Для чего нужен `finally` ? >> Для кода обязательного к выполнению вне зависимости от результата: закрытие файлов, освобождение ресурсов
10. Если возникнет `ZeroDivisionError` , выполнится ли `else` ? >> Нет
11. Верно ли что `else` выполняется перед `finally` ? >> Да: `else` – после `try` , до `finally`
12. Будет ли выполнен `else` если управление перешло в `except` ? >> Нет; `except` и `else` взаимоисключающие
13. Ключевое отличие кода в `try` от кода в `else` ? >> Исключения в `try` ловятся текущим `except` ; исключения в `else` – нет
14. Что произойдёт если исключение возникнет внутри `finally` ? >> Оно подавит исходное исключение из `try` ; оригинальная ошибка будет потеряна – опасная ловушка
15. Выполнится ли `finally` если внутри `try` есть `return` ? >> Да; `finally` выполняется даже при `return` ; если `finally` тоже содержит `return` – он перекрывает `return` из `try`
