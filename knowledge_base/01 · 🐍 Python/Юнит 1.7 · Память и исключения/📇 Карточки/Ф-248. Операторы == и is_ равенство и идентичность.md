1. В чём разница между == и is в Python? >> == сравнивает значения (вызывает __eq__), is сравнивает идентичность объектов (одинаковый id()).
2. Почему None сравнивают через is, а не ==? >> None — синглтон, единственный объект в программе; is None быстрее и корректнее, не зависит от переопределённого __eq__.
3. Что выведет `a = 256; b = 256; print(a is b)`? >> True — CPython кэширует маленькие целые числа (обычно от -5 до 256).
4. Можно ли полагаться на is при сравнении чисел или строк? >> Нет, это деталь реализации CPython, а не гарантия языка; для значений всегда используйте ==.
5. Что вернёт `[1,2] == [1,2]`? >> True — списки сравниваются поэлементно по значению через __eq__.
6. Что вернёт `[1,2] is [1,2]`? >> False — это два разных объекта в памяти, несмотря на одинаковое содержимое.
7. Что рекомендует PEP 8 для сравнения с None? >> Использовать is None / is not None, а не == None.
8. Какой метод вызывается под капотом при использовании ==? >> __eq__.
9. Что вернёт "" == False? >> False — разные типы не считаются равными автоматически, даже если оба "falsy".
10. Может ли пользовательский класс переопределить поведение ==? >> Да, через метод __eq__.
11. Можно ли переопределить поведение is? >> Нет, is всегда сравнивает физическую идентичность объектов, это встроенная неизменяемая семантика оператора.
12. Что вернёт a = "hello"; b = "hello"; a is b в CPython? >> Чаще всего True — CPython интернирует короткие строковые литералы, похожие на идентификаторы, но это деталь реализации, не гарантия.
13. Как безопаснее всего проверить, что два объекта — буквально один и тот же экземпляр? >> Через is, а не ==, и понимая, что это про идентичность, а не значение.
14. Что произойдёт с sorted() при сравнении объектов без __lt__? >> TypeError — sorted() полагается на операторы сравнения, не на равенство.
15. Чем отличается __eq__ от __hash__ с точки зрения контракта? >> Равные по __eq__ объекты обязаны иметь одинаковый __hash__, иначе поведение в set/dict будет некорректным.
16. Что вернёт (1,2) == (1,2)? >> True — кортежи сравниваются поэлементно по значению, как и списки.
17. Может ли a == a вернуть False для какого-то объекта? >> Да, теоретически, если класс переопределит __eq__ нестандартным образом (например, для NaN: float('nan') == float('nan') возвращает False).
18. Что произойдёт при сравнении объектов разных несовместимых типов через ==, если __eq__ не определён явно? >> Сработает сравнение по умолчанию от object — вернёт False, если это не один и тот же объект (эквивалентно is).
19. Что вернёт 1 == 1.0? >> True — Python сравнивает числовые значения между int и float по значению, несмотря на разные типы.
20. Что вернёт 1 is 1.0? >> False — разные типы означают разные объекты, идентичность не может совпадать.
