## Что такое MRO и зачем он нужен

При множественном наследовании один и тот же метод может быть определён в нескольких родительских классах. Python должен однозначно решить, какой из них вызвать. Для этого существует **MRO** (Method Resolution Order) – строго определённый порядок, в котором Python обходит классы иерархии в поиске метода или атрибута.

MRO строится по алгоритму **C3-линеаризации**. Он гарантирует, что каждый класс встречается в цепочке ровно один раз, порядок соблюдает отношения наследования и остаётся предсказуемым при любой сложности иерархии.

---

## Как посмотреть MRO

Python предоставляет два способа. `ClassName.__mro__` – атрибут класса, возвращает кортеж. `ClassName.mro()` – метод, возвращает список. На практике чаще используют `__mro__` – он быстрее, потому что Python обращается к нему напрямую при поиске имён.

## Классический пример: ромбовидное наследование

Ромбовидная схема возникает, когда два класса наследуются от одного общего предка, а затем объединяются в четвёртом:

```python
class A:
    def hello(self):
        return 'A'

class B(A):
    def hello(self):
        return 'B'

class C(A):
    def hello(self):
        return 'C'

class D(B, C):
    pass

print(D.__mro__)  # (D, B, C, A, object)
print(D().hello())  # 'B'
```

MRO для класса `D` выглядит так: `D → B → C → A → object`. При вызове `D().hello()` Python идёт по этому списку и останавливается на первом классе, где метод определён. Первым после `D` оказывается `B` – он и выигрывает. Классы `C` и `A` тоже имеют этот метод, но до них поиск не доходит.

## `super()` – это не вызов родителя

Распространённое заблуждение: `super()` вызывает метод прямого родителя. На самом деле **`super()`**** вызывает следующий класс в цепочке MRO для текущего объекта**.

```python
class A:
    def hello(self):
        return 'A'

class B(A):
    def hello(self):
        result = super().hello()
        return f'B + {result}'

class C(A):
    def hello(self):
        return 'C'

class D(B, C):
    pass

print(D().hello())  # 'B + C'
```

Разберём пошагово. Вызывается `D().hello()`. `D` метода не имеет – переходим к `B`. Внутри `B.hello()` вызывается `super().hello()`. MRO объекта `D` – это `D → B → C → A → object`. Следующий после `B` – класс `C`. Значит, `super().hello()` вызывает `C.hello()`, который возвращает `'C'`. Итог: `B` получает `'C'` и возвращает `'B + C'`.

Ключевой момент: `super()` смотрит на MRO **конкретного объекта**, а не на иерархию класса, в котором написан. Для объекта `D` следующий после `B` – это `C`, а не `A`, хотя `A` и является родителем `B`. Это позволяет всей цепочке классов кооперативно участвовать в вызове.

---

## Почему это важно на практике

Без понимания MRO поведение `super()` при множественном наследовании кажется непредсказуемым. С пониманием – всё становится детерминированным: посмотрел на `__mro__`, понял порядок, предсказал результат.

Это стандартный вопрос на собеседованиях уровня middle. Важно уметь не только назвать термин, но и объяснить на примере ромба, что `super()` следует MRO, а не идёт напрямую к родителю. Также стоит помнить, что в конце любой MRO-цепочки всегда стоит `object` – базовый класс всех классов в Python.
