## Как атрибуты хранятся по умолчанию

Каждый экземпляр класса по умолчанию хранит свои атрибуты в специальном словаре **`__dict__`**. Это обычная хеш-таблица, которая даёт $O(1)$ доступ к атрибутам и позволяет добавлять новые атрибуты в любой момент:

```python
class Dog:
    def __init__(self, name):
        self.name = name

d = Dog('Rex')
print(d.__dict__)  # {'name': 'Rex'}
d.age = 5  # можно добавить атрибут прямо сейчас
print(d.__dict__)  # {'name': 'Rex', 'age': 5}
```

Хеш-таблица требует избыточной памяти: Python выделяет её с запасом, чтобы минимизировать коллизии. Для одного объекта это незаметно. Но если создать миллион объектов – накладные расходы становятся существенными.

---

## `__slots__` – фиксированный набор атрибутов

**`__slots__`** – механизм, который говорит Python: не создавай словарь для этого объекта, используй компактный массив с фиксированными ячейками.

```python
class Point:
    __slots__ = ['x', 'y']

    def __init__(self, x, y):
        self.x = x
        self.y = y

p = Point(1, 2)
p.x = 10  # OK
p.z = 5  # AttributeError – атрибут не объявлен в __slots__
p.__dict__  # AttributeError – словаря не существует
```

Когда объявлен `__slots__`, словарь `__dict__` не создаётся вообще. Вместо него Python использует более компактную структуру: он знает точное смещение каждого атрибута в памяти, поэтому доступ к ним немного быстрее, а сам объект занимает значительно меньше памяти.

Обратная сторона: вы полностью теряете гибкость. Добавить атрибут, не объявленный в `__slots__`, невозможно – `AttributeError`.

---

## Насколько велика экономия памяти

Разница заметна при большом количестве объектов. Один экземпляр с `__dict__` может занимать 200-400 байт и более в зависимости от количества атрибутов и версии Python. Аналогичный объект с `__slots__` – 50-100 байт. При миллионе объектов разница составляет сотни мегабайт.

---

## Нюансы при наследовании

`__slots__` и наследование требуют внимания. Если родительский класс не использует `__slots__`, дочерний класс всё равно получит `__dict__` – от родителя. Чтобы `__slots__` работал полноценно по всей иерархии, он должен быть объявлен в каждом классе цепочки.

```python
class Base:
    __slots__ = ['x']

class Child(Base):
    __slots__ = ['y']  # нужно объявить явно, даже если добавляется одно поле
```

---

## Когда использовать `__slots__`

`__slots__` оправдан в трёх сценариях. Первый – когда создаётся очень большое количество однотипных объектов: точки, координаты, записи, события. Второй – когда память критична и каждый мегабайт имеет значение. Третий – когда структура объекта должна быть жёстко зафиксирована и любое добавление атрибутов должно вызывать ошибку.

В обычном коде `__slots__` не нужен. Гибкость `__dict__` – это преимущество Python, и убирать её без явной причины не стоит. Преждевременная оптимизация памяти усложняет код и лишает его динамичности.
