## Как атрибуты хранятся по умолчанию

Каждый экземпляр класса в Python по умолчанию хранит свои поля в личном словаре **`__dict__`**. Это хэш-таблица со средним временем доступа $O(1)$, позволяющая добавлять новые атрибуты прямо во время работы программы.

В современном CPython работают оптимизации **PEP 412** (*key-sharing dict*) и **inline values** (Python 3.11+): таблица ключей общая на класс, а сам экземпляр хранит массив значений и обвязку словаря. Полноценная персональная хэш-таблица с бакетами выделяется при нарушении схемы ключей или материализации `obj.__dict__`, поэтому на сотнях тысяч и миллионах объектов перерасход памяти всё равно остаётся высоким.

```python
class Dog:
    def __init__(self, name):
        self.name = name

d = Dog('Rex')
print(d.__dict__)
# >>> {'name': 'Rex'}

# Новое поле добавляется динамически
d.age = 5
print(d.__dict__)
# >>> {'name': 'Rex', 'age': 5}
```

## `__slots__`, `mappingproxy` класса и `member_descriptor`

Важно отличать `__dict__` экземпляра от **`__dict__` самого класса**: у класса словарь остаётся всегда (обёрнут в защитный `mappingproxy` и хранит методы с атрибутами класса), а **`__slots__`** отключает создание `__dict__` именно у каждого экземпляра.

Принято задавать `__slots__` кортежем (`('x', 'y')`), а не списком: кортеж неизменяем и занимает меньше памяти. Внутри `Point.__dict__` для каждого слота CPython создаёт дескриптор данных **`member_descriptor`**, который обращается напрямую к фиксированному смещению в памяти экземпляра без вычисления хэша и поиска по таблице (поэтому доступ к полям обычно немного быстрее); запись необъявленного поля или чтение `p.__dict__` вызовет `AttributeError`.

```python
class Point:
    __slots__ = ('x', 'y')

    def __init__(self, x, y):
        self.x = x
        self.y = y

p = Point(1, 2)
print(hasattr(p, '__dict__'))
# >>> False

print(type(Point.__dict__).__name__)
# >>> mappingproxy

print(type(Point.x).__name__)
# >>> member_descriptor

try:
    p.z = 5
except AttributeError as err:
    print(type(err).__name__)
# >>> AttributeError
```

## Замер памяти и слепая зона `sys.getsizeof()`

Обычный вызов `sys.getsizeof(obj)` возвращает размер **только самого контейнера объекта** и не учитывает размер вложенного словаря `obj.__dict__` и других ссылочных объектов. Из-за этой слепой зоны поверхностный замер обычного объекта вроде `Reg` кажется искусственно маленьким.

Чтобы честно оценить память обычного экземпляра с простыми полями, нужно сложить размер объекта и его словаря: `sys.getsizeof(obj) + sys.getsizeof(obj.__dict__)`. Точное число байтов зависит от разрядности ОС и версии CPython (с учётом PEP 412 и inline values в Python 3.11+), но при массовом создании объектов `__slots__` даёт кратную экономию.

```python
import sys

class Reg:
    def __init__(self, x, y):
        self.x = x
        self.y = y

class Slot:
    __slots__ = ('x', 'y')

    def __init__(self, x, y):
        self.x = x
        self.y = y

r = Reg(1, 2)
s = Slot(1, 2)
r_mem = (
    sys.getsizeof(r)
    + sys.getsizeof(r.__dict__)
)
s_mem = sys.getsizeof(s)
print(r_mem > s_mem)
# >>> True
```

## Наследование: `__slots__ = ()`, расширение и конфликт раскладки

При наследовании действуют четыре правила: 1) если родитель без `__slots__`, наследник всё равно получит `__dict__`; 2) если родитель со слотами, а наследник не задал `__slots__`, у наследника снова появится свой `__dict__` — при отсутствии новых полей обязательно пишут **`__slots__ = ()`**; 3) если наследник добавляет поля, в его `__slots__` перечисляют **только новые имена** (не дублируя слоты родителя), а одноэлементный кортеж пишут с запятой: `('record_id',)` — без запятой получится строка `str` (сам CPython распознает её как один слот, но `cls.__slots__` будет типа `str` и разобьётся по буквам при ручной итерации);

4) при множественном наследовании запрещено смешивать два класса с **непустыми** `__slots__`: их смещения несовместимы, и Python выбросит `TypeError: multiple bases have instance lay-out conflict`.

```python
class Base:
    __slots__ = ('x',)

class ChildSame(Base):
    __slots__ = ()

class ChildExtra(Base):
    __slots__ = ('y',)

class Other:
    __slots__ = ('z',)

ce = ChildExtra()
ce.x, ce.y = 1, 2
print(hasattr(ce, '__dict__'))
# >>> False

try:
    class Bad(Base, Other):
        pass
except TypeError as err:
    print('conflict' in str(err))
# >>> True
```

## Специальные слоты: `__weakref__` и `__dict__`

По умолчанию классы со `__slots__` не поддерживают слабые ссылки (`weakref.ref(obj)` выбросит `TypeError`). Чтобы разрешить слабые ссылки для кэшей и графов объектов без создания полного словаря, в слоты добавляют имя **`'__weakref__'`**.

Иногда нужен гибрид: быстрые фиксированные поля и редкая возможность добавлять произвольные атрибуты на лету. Тогда в `__slots__` включают **`'__dict__'`**, однако при первой записи динамического поля создастся словарь и часть экономии памяти будет потеряна.

```python
import weakref

class CacheNode:
    __slots__ = ('val', '__weakref__')

    def __init__(self, val):
        self.val = val

node = CacheNode(42)
ref = weakref.ref(node)
print(ref().val, hasattr(node, '__dict__'))
# >>> 42 False

class Hybrid:
    __slots__ = ('id', '__dict__')

h = Hybrid()
h.extra = 'ok'
print(h.__dict__)
# >>> {'extra': 'ok'}
```

## Когда применять `__slots__`

`__slots__` оправдан в трёх сценариях: при создании **сотен тысяч и миллионов** однотипных объектов (точки, события телеметрии, узлы деревьев), при жёстком лимите оперативной памяти или когда нужно строго защитить структуру модели от случайных опечаток в именах атрибутов.

В обычной бизнес-логике с небольшим числом объектов `__slots__` не нужен: гибкость `__dict__` упрощает отладку, мокирование в тестах и расширение кода без лишней сложности при наследовании.

> **Junior vs Senior**:
> - **Junior**: прописывает `__slots__` на каждом классе ради призрачного ускорения, замеряет память только через `sys.getsizeof(obj)` без `__dict__` и забывает `__slots__ = ()` или запятую в кортеже из одного поля.
> - **Senior**: оставляет `__dict__` по умолчанию, применяет `__slots__` точечно после замеров на сотнях тысяч однотипных экземпляров, расширяет слоты без дублирования полей родителя и добавляет `'__weakref__'` только там, где нужны слабые ссылки.
