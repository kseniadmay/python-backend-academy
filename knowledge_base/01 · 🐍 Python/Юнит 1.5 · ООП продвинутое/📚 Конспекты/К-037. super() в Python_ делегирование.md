## Зачем нужен `super()`

При наследовании дочерний класс часто переопределяет `__init__`, чтобы добавить свои атрибуты. При этом атрибуты родителя тоже нужно инициализировать. Можно скопировать логику родителя вручную, но это дублирование. **`super()`** решает задачу чище: он передаёт управление следующему классу в цепочке MRO, чтобы тот выполнил свою часть инициализации.

---

## Базовый пример

```python
class Animal:
    def __init__(self, name):
        self.name = name

class Dog(Animal):
    def __init__(self, name, breed):
        super().__init__(name)  # делегируем инициализацию имени родителю
        self.breed = breed
```

`Dog.__init__` принимает и `name`, и `breed`. Атрибут `breed` специфичен для `Dog`, поэтому устанавливается здесь. Атрибут `name` – общий для всех животных, его инициализация делегируется `Animal.__init__` через `super().__init__(name)`.

При вызове `super().__init__(name)` Python автоматически подставляет `self` – передавать его вручную не нужно.

---

## Почему не стоит вызывать родителя напрямую

Вместо `super().__init__(name)` можно написать `Animal.__init__(self, name)`. Это сработает в простом случае, но создаёт проблемы.

Первая проблема – жёсткая привязка к имени класса. Если вы переименуете `Animal` или реорганизуете иерархию, придётся вручную обновлять все прямые вызовы по всей кодовой базе. `super()` подстраивается автоматически.

Вторая проблема – множественное наследование. При ромбовидной иерархии прямые вызовы могут привести к тому, что общий предок будет инициализирован дважды. `super()` следует MRO и гарантирует, что каждый класс в цепочке будет вызван ровно один раз и в правильном порядке. Это называется **кооперативным множественным наследованием**.

---

## Python 2 vs Python 3

В Python 2 `super()` требовал явной передачи имени класса и `self`:

```python
class Dog(Animal):
    def __init__(self, name):
        # Python 2: super(Dog, self).__init__(name)
        # Python 3:
        super().__init__(name)
```

В Python 3 аргументы не нужны – интерпретатор определяет их автоматически через магические переменные `__class__` и `__self__`. В современном коде всегда используется короткая форма.

---

## Порядок вызовов имеет значение

При инициализации важно сначала вызвать `super().__init__()`, а уже потом устанавливать собственные атрибуты – особенно если логика дочернего класса зависит от атрибутов родителя. В примере выше порядок не критичен, но в реальных проектах это часто играет роль.

Если в классе несколько уровней наследования и каждый вызывает `super().__init__()`, Python последовательно проходит по цепочке MRO и вызывает конструкторы родительских классов.

```python
class A:
    def __init__(self):
        print('A')

class B(A):
    def __init__(self):
        print('B start')
        super().__init__()
        print('B end')

class C(B):
    def __init__(self):
        print('C start')
        super().__init__()
        print('C end')

C()
# Вывод: C start -> B start -> A -> B end -> C end
```

При создании объекта `C()` Python построит цепочку MRO `C -> B  -> A -> object` и вызовы пойдут по этой цепочке через `super()`:

- 1. Запускается `C.__init__`
- 2. `super()` внутри `C` вызывает `B.__init__`
- 3. `super()` внутри `B` вызывает `A.__init__`

В результате каждый класс добавляет свою часть в создание объекта. Это особенно важно при множественном наследовании, где `super()` позволяет Python корректно пройти по всей MRO-цепочке без ручного вызова каждого родителя.
