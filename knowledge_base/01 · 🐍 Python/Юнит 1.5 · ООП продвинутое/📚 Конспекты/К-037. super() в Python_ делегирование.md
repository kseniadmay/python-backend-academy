## Зачем нужен `super()`

При наследовании дочерний класс часто переопределяет `__init__`, чтобы добавить свои атрибуты. При этом атрибуты родителя тоже нужно инициализировать. Можно скопировать логику родителя вручную, но это дублирование. **`super()`** решает задачу чище: он передаёт управление следующему классу в цепочке MRO, чтобы тот выполнил свою часть инициализации.

---

## Базовый пример

```python
class Animal:
    def __init__(self, name):
        self.name = name

class Dog(Animal):
    def __init__(self, name, breed):
        # делегируем инициализацию имени
        # родителю
        super().__init__(name)
        self.breed = breed
```

`Dog.__init__` принимает и `name`, и `breed`. Атрибут `breed` специфичен для `Dog`, поэтому устанавливается здесь. Атрибут `name` – общий для всех животных, его инициализация делегируется `Animal.__init__` через `super().__init__(name)`.

При вызове `super().__init__(name)` Python автоматически подставляет `self` – передавать его вручную не нужно.

---

## Почему не стоит вызывать родителя напрямую

Вместо `super().__init__(name)` можно написать `Animal.__init__(self, name)`. Это сработает в простом случае, но создаёт проблемы.

Первая проблема – жёсткая привязка к имени класса. Если вы переименуете `Animal` или реорганизуете иерархию, придётся вручную обновлять все прямые вызовы по всей кодовой базе. `super()` подстраивается автоматически.

Вторая проблема – множественное наследование. При ромбовидной иерархии прямые вызовы могут привести к тому, что общий предок будет инициализирован дважды. `super()` следует MRO и гарантирует, что каждый класс в цепочке будет вызван ровно один раз и в правильном порядке. Это называется **кооперативным множественным наследованием**.

---

## Python 2 vs Python 3

В Python 2 `super()` требовал явной передачи имени класса и `self`:

```python
class Dog(Animal):
    def __init__(self, name):
        # Python 2: super(Dog,
        # self).__init__(name)
        # Python 3:
        super().__init__(name)
```

В Python 3 аргументы не нужны – интерпретатор определяет их автоматически через магические переменные `__class__` и `__self__`. В современном коде всегда используется короткая форма.

---

## Порядок инициализации в цепочке MRO

При наследовании вызов `super().__init__()` передает управление вверх по цепочке MRO, гарантируя полную подготовку базовых классов перед расширением функционала:

```python
class A:
    def __init__(self, log):
        log.append('A')

class B(A):
    def __init__(self, log):
        # Цепочка конструкторов от A к B к C
        super().__init__(log)
        log.append('B')

class C(B):
    def __init__(self, log):
        super().__init__(log)
        log.append('C')

order = []
C(order)
print(' -> '.join(order))
# >>> A -> B -> C
```

Вызов `super().__init__()` в начале метода гарантирует, что состояние родительского объекта уже сконструировано и доступно для использования в дочернем классе.

## Кооперативные `**kwargs` в MRO и подход Junior vs Senior

При множественном наследовании классы часто принимают разные параметры в `__init__`. Если просто вызвать `super().__init__(arg)`, следующий класс в цепочке MRO может не знать про этот аргумент и упасть с `TypeError`.

Промышленное решение — **кооперативные `**kwargs`**: каждый класс забирает из `**kwargs` только свои именованные параметры (с помощью `kwargs.pop(...)` или явных keyword-only аргументов) и пробрасывает оставшиеся через `super().__init__(**kwargs)` дальше по MRO вплоть до пустого `object.__init__()`.

```python
class Base:
    def __init__(self, **kwargs):
        super().__init__(**kwargs)

class LogMixin(Base):
    def __init__(self, level='INFO', **kw):
        self.level = level
        super().__init__(**kw)

class Service(LogMixin):
    def __init__(self, name, **kw):
        self.name = name
        # Передаём оставшиеся kwargs дальше
        super().__init__(**kw)

svc = Service(name='billing', level='WARN')
print(svc.name, svc.level)
# >>> billing WARN
```

> **Junior vs Senior**:
> - **Junior**: Вызывает родителя жёстко по имени `Parent.__init__(self)` (дважды инициализируя общего предка в ромбе) или ломает цепочку MRO, забывая прокинуть `**kwargs` в `super().__init__()`.
> - **Senior**: Использует `super()` без аргументов, пробрасывает `**kwargs` по кооперативной цепочке MRO и предпочитает композицию множественному наследованию там, где классы не разделяют общий контракт.
