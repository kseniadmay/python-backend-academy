## `@classmethod` – метод, привязанный к классу

Обычный метод получает `self` – ссылку на экземпляр. **`@classmethod`** получает вместо него **`cls`** – ссылку на сам класс. Это означает, что метод можно вызвать без создания объекта, и он будет знать, с каким классом работает.

```python
class User:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    @classmethod
    def from_string(cls, user_str):
        name, age = user_str.split(',')
        return cls(name, int(age))

user = User.from_string('Alice,30')
```

Главный сценарий использования `@classmethod` – **альтернативные конструкторы**. Обычный `__init__` принимает готовые данные напрямую, а методы вроде `from_string` сначала преобразуют входные данные, а затем создают объект через `cls(...)`. Использование `cls` вместо жёстко прописанного `User(...)` особенно важно при наследовании. Если создать подкласс `AdminUser`, то вызов `AdminUser.from_string(...)` вернёт экземпляр `AdminUser`, а не обычный `User`, потому что `cls` автоматически ссылается на тот класс, через который был вызван метод. Благодаря этому один и тот же `@classmethod` начинает корректно работать для всей иерархии наследования без дублирования кода.

Этот паттерн называется **фабричным методом** (factory method). Именно так устроены, например, `dict.fromkeys()` и `datetime.fromisoformat()` в стандартной библиотеке.

Упрощённо `datetime.fromisoformat()` внутри работает примерно так:

```python
class MyDateTime:
    def __init__(self, year, month, day):
        self.year = year
        self.month = month
        self.day = day

    @classmethod
    def from_isoformat(cls, date_string):
        parts = date_string.split('-')

        year = int(parts[0])
        month = int(parts[1])
        day = int(parts[2])

        return cls(year, month, day)

dt = MyDateTime.from_isoformat('2025-05-26')

print(dt.year)  # 2025
print(dt.month)  # 5
print(dt.day)  # 26
```

То есть:

- 1. Метод получает строку
- 2. Разбирает её
- 3. Преобразует данные
- 4. Создаёт объект класса

В этом и заключается идея альтернативного конструктора: объект создаётся не напрямую через обычный `__init__`, а через дополнительный метод подготовки данных.

Главный плюс `cls(...)` проявляется при наследовании:

```python
class AdminDateTime(MyDateTime):
    pass

dt = AdminDateTime.from_isoformat('2025-05-26')

print(type(dt))
```

Хотя метод написан один раз в родительском классе, `cls` автоматически становится `AdminDateTime`. Если бы внутри было жёстко прописано `return MyDateTime(year, month, day)`, то наследование бы сломалось – метод всегда создавал бы только `MyDateTime`.

## `@staticmethod` – независимая утилита внутри класса

**`@staticmethod`** не получает ни `self`, ни `cls`. По сути это обычная функция, которая живёт в пространстве имён класса. Она не имеет доступа ни к состоянию экземпляра, ни к атрибутам класса.

```python
class MathUtils:
    @staticmethod
    def add(a, b):
        return a + b

result = MathUtils.add(10, 5)
```

Статические методы используют, когда функция логически связана с классом, но не нуждается в его данных. Это делает код организованным – связанные утилиты собраны в одном месте – и упрощает тестирование: статический метод можно проверить изолированно, без создания объекта.

Если вы поймали себя на мысли «этот метод не использует `self` и не использует `cls`» – скорее всего, это кандидат на `@staticmethod`. Если он не использует `self`, но должен знать о классе (например, для наследования) – это `@classmethod`.

## `@property` – атрибут с логикой внутри

`@`**`property`** позволяет вызывать метод как обычный атрибут – без скобок. Снаружи это выглядит как доступ к полю, внутри может быть любая логика.

```python
import math

class Circle:
    def __init__(self, radius):
        self._radius = radius

    @property
    def area(self):
        return math.pi * (self._radius ** 2)

c = Circle(5)
print(c.area)  # 78.539...
```

`_radius` с нижним подчёркиванием – соглашение, означающее «внутренний атрибут, не трогай напрямую». `area` – публичный интерфейс: пользователь просто читает значение, не зная, что за ним скрывается вычисление. Если определён только геттер, метод, который управляет чтением значения атрибута – свойство автоматически становится read-only: попытка записать `c.area = 10` вызовет `AttributeError`.

Главная идея `property` в том, что объект может выглядеть как набор обычных полей, но при чтении или изменении Python будет автоматически запускать дополнительную логику. Например, у круга есть внутренний радиус `self._radius`. Но пользователю объекта может быть удобнее работать не с радиусом, а с площадью круга. Для этого создают `property`:

```python
@property
def area(self):
    return math.pi * self._radius ** 2
```

Теперь можно писать `print(circle.area)` как будто `area` – обычный атрибут, хотя на самом деле Python вызывает метод-геттер и вычисляет площадь динамически.

Но возникает проблема. Что должно происходить, если пользователь захочет изменить площадь? `circle.area = 50`. Без сеттера, метода, который управляет изменением значения атрибута,  Python выдаст ошибку, потому что `property` доступно только для чтения. Чтобы разрешить изменение, добавляют сеттер:

```python
@area.setter
def area(self, value):
    self._radius = math.sqrt(value / math.pi)
```

Теперь при выполнении `circle.area = 50` Python автоматически вызывает метод-сеттер и передаёт `50` в параметр `value`. Сеттер пересчитывает радиус так, чтобы площадь действительно стала равна `50`. То есть пользователь работает с объектом через удобный интерфейс `circle.area`, а сам объект внутри поддерживает корректное состояние автоматически.

В этом и главный смысл геттеров и сеттеров они позволяют контролировать доступ к данным и скрывать внутреннюю логику объекта за простым интерфейсом.

`@property` часто применяют для валидации при установке значения, ленивых вычислений и кеширования результата, а также чтобы скрыть рефакторинг – если раньше `area` был просто атрибутом, его можно превратить в `@property` без изменения внешнего интерфейса.

## Когда что использовать

`@classmethod` нужен, когда метод должен создавать объекты или работать с атрибутами класса, особенно с учётом наследования. `@staticmethod` – когда функция логически принадлежит классу, но не использует ни `self`, ни `cls`. `@property` – когда нужно скрыть вычисление за простым доступом к атрибуту или защитить данные от прямой записи.
