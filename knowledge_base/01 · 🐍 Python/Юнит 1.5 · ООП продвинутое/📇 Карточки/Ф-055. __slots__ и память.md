1. Что нужно добавить в `__slots__` , чтобы объекты класса поддерживали создание слабых ссылок ( `weakref` )? >> `'__weakref__'`
2. Почему атрибуты в `__slots__` занимают фиксированное место? >> Реализуются как дескрипторы без накладных расходов хеш-таблицы; адрес атрибута вычисляется напрямую
3. Примерный размер словаря атрибутов для небольшого объекта? >> Около 232 байт
4. Какая функция проверяет размер объекта в байтах? >> `sys.getsizeof()` ; важно: не учитывает размер вложенных объектов, только сам контейнер
5. Как `__slots__` изменяет способ хранения атрибутов? >> Заменяет динамический словарь фиксированным набором дескрипторов на уровне класса
6. Пример структуры данных для которой выгодны `__slots__` ? >> Узлы дерева, точки в пространстве, записи в высоконагруженных системах
7. Что вернёт `hasattr(obj, '__dict__')` для класса со `__slots__` ? >> `False`
8. Когда использование `__slots__` наиболее оправдано? >> При создании миллионов экземпляров когда экономия памяти критична
9. Основной недостаток `__dict__` для хранения атрибутов? >> Значительное потребление памяти: хранит хеш-таблицу даже для простых объектов
10. На каком уровне реализуются атрибуты при `__slots__` ? >> На уровне класса в виде дескрипторов; каждый экземпляр хранит только значения
11. Почему `__dict__` считается гибкой структурой? >> Позволяет добавлять любые новые атрибуты динамически в процессе выполнения
12. Как `__slots__` влияет на динамическое добавление атрибутов? >> Запрещает добавление атрибутов не указанных в слотах; выбросит `AttributeError`
13. Преимущество `__slots__` помимо экономии памяти? >> Немного более быстрый доступ к атрибутам за счёт прямой адресации вместо хеш-поиска
14. Что усложняет применение `__slots__` ? >> Множественное наследование: если хотя бы один родитель без `__slots__` , дочерний класс всё равно получит `__dict__`
15. Примерный размер объекта с `__slots__` ? >> Около 56 байт
