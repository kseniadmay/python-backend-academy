1. В чём главное преимущество функций из модуля itertools перед обычными операциями со списками? >> Они работают лениво (вычисляют элементы по одному на лету) за O(1) памяти и реализованы на C, не создавая промежуточных списков.
2. Почему перед использованием itertools.groupby(data, key=...) данные почти всегда нужно предварительно отсортировать по этому же ключу? >> Потому что groupby группирует только соседние (подряд идущие) элементы с одинаковым ключом, как утилита uniq в Linux.
3. Что произойдёт, если в цикле по itertools.groupby сохранить в список сами итераторы групп без вызова list(group) на каждом шаге? >> Все сохранённые итераторы кроме последнего окажутся пустыми, так как они разделяют один базовый итератор, который продвигается вперёд на каждом шаге внешнего цикла.
4. Чем itertools.chain(a, b) лучше конкатенации списков a + b? >> chain не копирует элементы в новый список в памяти, а лениво перебирает сначала a, затем b за O(1) дополнительной памяти.
5. Чем отличается itertools.chain.from_iterable(iterables) от itertools.chain(*iterables)? >> chain.from_iterable принимает один итерируемый объект (даже ленивый или бесконечный генератор списков), не распаковывая все вложенные последовательности в память разом, как оператор *.
6. Зачем нужен itertools.islice(iterable, start, stop, step), если в Python есть обычный срез [start:stop:step]? >> Обычный срез не работает с генераторами и итераторами (вызовет TypeError), а islice позволяет взять срез из любого потока данных лениво.
7. Какие три бесконечных итератора есть в модуле itertools? >> count(start, step) — бесконечный счётчик, cycle(iterable) — зацикливание последовательности по кругу, repeat(elem[, n]) — повторение одного элемента.
8. В чём разница между itertools.permutations и itertools.combinations? >> В permutations порядок элементов важен ((1, 2) и (2, 1) — разные кортежи), а в combinations порядок не важен (выдаётся только уникальная пара (1, 2)).
9. Какую конструкцию заменяет itertools.product(A, B, repeat=1)? >> Вложенные циклы for x in A: for y in B:, вычисляя декартово произведение последовательностей.
10. Чем отличаются itertools.takewhile(pred, it) и встроенный filter(pred, it)? >> takewhile останавливается навсегда при первом же элементе, для которого предикат вернул False, тогда как filter проверяет все элементы до конца.
11. Что делает itertools.dropwhile(pred, it)? >> Пропускает первые элементы, пока условие истинно, но как только предикат впервые вернёт False — выдаёт этот и все последующие элементы без дальнейших проверок.
12. Что делает функция itertools.batched(iterable, n) (Python 3.12+)? >> Разбивает входной итерируемый объект на кортежи (батчи) длиной до n элементов (последний кортеж может быть короче).
13. Что возвращает itertools.accumulate([1, 2, 3, 4]) по умолчанию? >> Итератор префиксных (накопленных) сумм: 1, 3, 6, 10 (также можно передать свою функцию, например max или operator.mul).
14. Какой скрытый расход памяти есть у itertools.tee(iterable, n)? >> Если один из созданных итераторов продвинулся далеко вперёд, а другой ещё не прочитан, tee хранит все промежуточные элементы во внутреннем буфере памяти.
15. Чем itertools.zip_longest(*iterables, fillvalue=None) отличается от встроенного zip()? >> Встроенный zip() останавливается по самому короткому итератору, а zip_longest продолжает работу до конца самого длинного, заполняя недостающие значения через fillvalue.
16. Что делает itertools.compress(data, selectors)? >> Отфильтровывает элементы из data, оставляя только те, на соответствующих позициях которых в последовательности selectors стоит истинное (truthy) значение.
