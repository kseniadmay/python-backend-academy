1. Чем Iterable отличается от Iterator? >> Iterable умеет отдать итератор через iter() (реализует __iter__); Iterator умеет отдавать элементы по одному через next() и помнит позицию.
2. Какие два метода нужны для ручной реализации протокола итератора? >> __iter__ (возвращает self) и __next__ (возвращает следующий элемент или бросает StopIteration).
3. Чем генератор проще, чем ручная реализация класса-итератора? >> Автоматически реализует __iter__/__next__ и сам управляет состоянием, без ручных атрибутов и явного raise StopIteration.
4. Можно ли пройти генератор дважды? >> Нет, только один раз — после исчерпания next() продолжает бросать StopIteration.
5. Что эффективнее по памяти: список или генератор для больших данных? >> Генератор — хранит только текущую позицию, вычисляет значения лениво, по одному за раз.
6. Что произойдёт при повторном вызове iter() на одном и том же списке? >> Каждый раз возвращается новый независимый итератор, начинающий с начала — список сам не хранит позицию.
7. Реализует ли генератор протокол __iter__ автоматически? >> Да, генератор — сам себе итератор, возвращает self из __iter__.
8. Что произойдёт при вызове next() на исчерпанном генераторе повторно? >> Продолжит бросать StopIteration.
9. Обязательно ли писать raise StopIteration явно в ручной реализации __next__? >> Да, без явного raise итератор никогда не завершит цикл for.
10. Что эффективнее по времени создания — список или генератор для 10 миллионов элементов? >> Генератор создаётся почти мгновенно (ленивое вычисление), список требует построить и разместить в памяти все элементы сразу.
11. Что произойдёт при вызове list() на объекте-итераторе дважды подряд? >> Первый вызов вернёт все элементы и исчерпает итератор; второй вызов вернёт пустой список [].
12. Является ли range() итератором? >> Нет, range — это iterable (ленивый, но допускает многократный обход и индексацию) — свой итератор он создаёт заново при каждом iter(range_obj).
13. Какая функция проверяет, что объект — итератор, а не просто iterable? >> hasattr(obj, '__next__') — итератор обязан иметь __next__, обычный iterable может не иметь.
14. Что произойдёт, если вызвать next() на объекте, у которого нет __next__? >> TypeError: 'X' object is not an iterator.
15. Можно ли построить бесконечный итератор? >> Да — если __next__ никогда не бросает StopIteration, итератор бесконечен (пример: itertools.count()).
