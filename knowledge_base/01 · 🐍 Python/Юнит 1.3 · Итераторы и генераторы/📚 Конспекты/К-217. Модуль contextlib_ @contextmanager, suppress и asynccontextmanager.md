## Модуль contextlib и ловушка `try/finally` в `@contextmanager`

Стандартный модуль **`contextlib`** избавляет от шаблонного кода классов с `__enter__`/`__exit__`. Декоратор `@contextmanager` превращает генератор с одним `yield` в контекстный менеджер:

```text
  with transactional_session(db):
                │
        1. generator.__next__()
                │
     ┌──────────▼──────────┐
     │ session = connect() │
     │ yield session       │ ──► в блок with
     └──────────┬──────────┘
                │ (тело with)
       [ Исключение в with ]
                │
        2. generator.throw(exc)
                │
     ┌──────────▼──────────┐
     │ except Exception:   │
     │     rollback()      │
     │ finally:            │
     │     close()         │
     └─────────────────────┘
```

Если в блоке `with` возникнет ошибка, Python пробросит её в точку `yield` через `.throw()`. Без `try...finally` генератор оборвётся прямо на `yield` и не закроет ресурс:

```python
from contextlib import contextmanager

class FakeSession:
    def __init__(self):
        self.state = 'connected'

    def commit(self):
        self.state = 'committed'

    def rollback(self):
        self.state = 'rolled_back'

    def close(self):
        self.state = 'closed'

@contextmanager
def safe_session():
    session = FakeSession()
    try:
        yield session
        session.commit()
    except Exception:
        session.rollback()
        raise
    finally:
        session.close()

with safe_session() as s:
    pass
print('Штатный выход:', s.state)
# >>> Штатный выход: closed

try:
    with safe_session() as s:
        raise RuntimeError('Сбой сети')
except RuntimeError:
    pass
print('После сбоя:', s.state)
# >>> После сбоя: closed
```

## contextlib.suppress — декларативное подавление ожидаемых ошибок

Вместо шаблонного `try ... except FileNotFoundError: pass` для игнорирования ожидаемых ошибок используют **`suppress(*exceptions)`**:

```python
import os
from contextlib import suppress

# Игнорируем отсутствие или запрет на файл
with suppress(
    FileNotFoundError, PermissionError
):
    os.remove('temp_cache.tmp')
print('Файл безопасно удалён или пропущен')
# >>> Файл безопасно удалён или пропущен
```

`suppress` перехватывает только перечисленные исключения и их наследников (возвращая `True` из `__exit__`); все остальные ошибки вроде `TypeError` пробрасываются наружу.

## closing, nullcontext и redirect_stdout

**`closing(thing)`** оборачивает объект с методом `.close()`, у которого нет собственного `__enter__`/`__exit__`, гарантируя его закрытие после `with`.

**`nullcontext(enter_result=None)`** — контекстный менеджер-заглушка, который ничего не делает при входе и выходе.

Он избавляет от дублирования кода, когда блокировка или менеджер передаются опционально по условию:

```python
from contextlib import nullcontext

def process_data(data: list[int], lock=None):
    cm = (
        lock
        if lock is not None
        else nullcontext()
    )
    with cm:
        return [x * 2 for x in data]

res = process_data([1, 2, 3])
print('Обработка без блокировки:', res)
# >>> Обработка без блокировки: [2, 4, 6]
```

**`redirect_stdout(new_target)`** и **`redirect_stderr`** временно перенаправляют вывод (например, в `io.StringIO()`), что удобно для перехвата вывода функций в тестах.

## ExitStack — динамический стек контекстных менеджеров

Когда заранее неизвестно, сколько файлов или соединений понадобится открыть (например, список путей приходит параметром), вложить `with` в цикле не получится.

В таких случаях используют **`ExitStack`** — он закрывает все зарегистрированные ресурсы и колбэки строго в обратном порядке (LIFO):

```python
from contextlib import ExitStack

def process_batch(
    items: list[str],
) -> list[str]:
    audit = []
    with ExitStack() as stack:
        # Колбэки выполняются в порядке LIFO
        stack.callback(
            audit.append,
            'cleanup: finish',
        )
        stack.callback(
            audit.append,
            'cleanup: flush',
        )
        for item in items:
            audit.append(f'process:{item}')
    return audit

res = process_batch(['order_1', 'order_2'])
print('Журнал ExitStack:', res)
# >>> Журнал ExitStack:
# >>> ['process:order_1', 'process:order_2',
# >>> 'cleanup: flush', 'cleanup: finish']
```

Даже если ошибка произойдёт в середине инициализации третьего ресурса, `ExitStack` гарантированно закроет первые два в порядке LIFO.

## @asynccontextmanager и AsyncExitStack

Для асинхронного протокола `async with` (подключения к БД, `aiohttp`/`httpx`, локи в Redis) применяют **`@asynccontextmanager`** над `async def` + `yield`, а для динамического набора ресурсов — **`AsyncExitStack`**.

Обёртка освобождает асинхронный ресурс при выходе или отмене корутины:

```python
import asyncio
from contextlib import asynccontextmanager

class FakeLockStorage:
    def __init__(self):
        self.locked = False

@asynccontextmanager
async def async_lock(
    storage: FakeLockStorage,
):
    storage.locked = True
    try:
        yield storage
    finally:
        storage.locked = False

async def main():
    store = FakeLockStorage()
    async with async_lock(store):
        print(
            'Внутри async with, locked =',
            store.locked,
        )
        # >>> Внутри async with, locked = True

    print(
        'После async with, locked =',
        store.locked,
    )
    # >>> После async with, locked = False

asyncio.run(main())
```

Как и в синхронном `@contextmanager`, блок `try...finally` вокруг `yield` здесь обязателен даже при `asyncio.CancelledError`.

> **Junior vs Senior**:
> - **Junior**: пишет генератор под `@contextmanager` без `try...finally` вокруг `yield`, из-за чего любая ошибка внутри блока `with` пропускает освобождение ресурса.
> - **Senior**: гарантирует cleanup через `try...finally`, заменяет пустые `except: pass` на `contextlib.suppress`, управляет динамическим набором ресурсов в `ExitStack`/`AsyncExitStack` и применяет `@asynccontextmanager`.
