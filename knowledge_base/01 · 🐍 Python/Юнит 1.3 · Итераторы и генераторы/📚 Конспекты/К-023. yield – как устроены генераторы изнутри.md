## `yield` приостанавливает функцию, а не завершает её

Если в теле функции есть **`yield`**, при вызове она не исполняется сразу, а возвращает объект-генератор.

Каждый вызов `next()` выполняет код до ближайшего `yield`, возвращает значение и замораживает локальные переменные до следующего шага:

```python
def simple_gen():
    # Выполняется до первого yield
    yield 1

    # Возобновляется отсюда
    yield 2

g = simple_gen()
print(next(g))
# >>> 1

print(next(g))
# >>> 2

# Следующий next(g) вызовет StopIteration
```

Следующий `next()` продолжает выполнение сразу после того `yield`, на котором функция остановилась в прошлый раз.

## Генераторные выражения – компактный синтаксис

Как списковое включение сокращает создание списка, так **генераторное выражение** кратко описывает генератор:

```python
# Список — вся память сразу
squares_list = [
    x**2 for x in range(1_000_000)
]

# Генератор — по одному значению
squares_gen = (
    x**2 for x in range(1_000_000)
)
```

Синтаксис отличается только круглыми скобками `()` вместо `[]`. Значения вычисляются не сразу, а по мере запроса `next()` или циклом `for`.

## `yield from` – делегирование другому итерируемому объекту

Чтобы отдать все значения из вложенного итерируемого объекта без ручного `for x in sub: yield x`, используют **`yield from`**:

```python
def inner():
    yield 1
    yield 2

def outer():
    yield 'start'

    # Эквивалент: for x in inner(): yield x
    yield from inner()
    yield 'end'

print(list(outer()))
# >>> ['start', 1, 2, 'end']
```

`yield from` особенно удобен при рекурсивном обходе вложенных структур и деревьев, пробрасывая значения вложенного генератора наружу.

## Конвейеры генераторов (generator pipeline)

Генераторы объединяют в цепочку, где каждый шаг лениво обрабатывает поток от предыдущего без промежуточных списков:

```python
def read_numbers(n):
    for i in range(n):
        yield i

def filter_even(numbers):
    for n in numbers:
        if n % 2 == 0:
            yield n

def square(numbers):
    for n in numbers:
        yield n ** 2

# Ленивый конвейер без лишних списков
evens = filter_even(read_numbers(10))
pipeline = square(evens)
print(list(pipeline))
# >>> [0, 4, 16, 36, 64]
```

Данные текут по цепочке поэлементно без промежуточных массивов в RAM — так строят потоковый парсинг логов, файлов и ETL-пайплайны.

## `send()` – двусторонний канал

`yield` может не только отдавать значение наружу, но и принимать его обратно через метод **`send()`**:

```python
def echo():
    while True:
        received = yield
        print(f'Получено: {received}')

gen = echo()

# Запуск генератора до первого yield
next(gen)
gen.send('hello')
# >>> Получено: hello

gen.send('world')
# >>> Получено: world
```

На практике `send()` встречается редко — современный асинхронный код строится поверх `async`/`await`, выросших из этого механизма.

## Когда использовать генераторы

Генераторы оптимальны в трёх основных сценариях работы с потоками данных:

- **Большие и бесконечные последовательности:** построчное чтение гигабайтных файлов, потоки событий и счётчики без переполнения памяти.
- **Конвейеры трансформаций:** поэтапная фильтрация и преобразование без аллокации промежуточных списков.
- **Ленивые вычисления по требованию:** когда дорогой элемент не нужно считать, пока его не запросят (и цикл может оборваться раньше конца).
