## `yield` приостанавливает функцию, а не завершает её

Как только в теле функции встречается ключевое слово **`yield`**, эта функция при вызове перестаёт быть обычной функцией – она становится **генераторной функцией**. Вызов такой функции не выполняет её тело сразу, а возвращает объект-генератор:

```python
def simple_gen():
    print('старт')
    yield 1
    print('между yield')
    yield 2
    print('конец')

# тело ещё не выполнилось, ничего не напечаталось
g = simple_gen()
# 'старт', затем 1
print(next(g))
# 'между yield', затем 2
print(next(g))
# 'конец', затем StopIteration
print(next(g))
```

Каждый вызов `next()` выполняет код до ближайшего `yield`, возвращает значение после `yield` и **замораживает** состояние функции – все локальные переменные сохраняются. Следующий `next()` продолжает выполнение сразу после того `yield`, на котором остановились, а не с начала функции.

## Генераторные выражения – компактный синтаксис

Так же, как списковые включения – компактная форма цикла, создающего список, **генераторное выражение** – компактная форма функции с `yield`:

```python
# список – вся память сразу
squares_list = [x**2 for x in range(1_000_000)]
# генератор – по одному значению
squares_gen  = (x**2 for x in range(1_000_000))
```

Синтаксис отличается от спискового включения только скобками: `()` вместо `[]`. Значения не вычисляются заранее – только по мере того, как их запрашивает `next()` или `for`.

## `yield from` – делегирование другому итерируемому объекту

Когда генератор должен отдать все значения из другого итерируемого объекта (в том числе другого генератора), вместо ручного цикла `for x in sub: yield x` используют **`yield from`**:

```python
def inner():
    yield 1
    yield 2

def outer():
    yield 'start'
    # эквивалент: for x in inner(): yield x
    yield from inner()
    yield 'end'

# ['start', 1, 2, 'end']
print(list(outer()))
```

`yield from` особенно полезен при обходе вложенных структур – например, рекурсивного обхода дерева, где на каждом уровне нужно «прокинуть» значения вложенного генератора наружу без явного цикла.

## Конвейеры генераторов (generator pipeline)

Генераторы можно соединять в цепочку, где каждый следующий обрабатывает поток данных от предыдущего лениво, не материализуя промежуточные списки:

```python
def read_numbers(n):
    for i in range(n):
        yield i

def filter_even(numbers):
    for n in numbers:
        if n % 2 == 0:
            yield n

def square(numbers):
    for n in numbers:
        yield n ** 2

pipeline = square(filter_even(read_numbers(10)))
# [0, 4, 16, 36, 64]
print(list(pipeline))
```

Ни один список целиком не строится в памяти между шагами – данные текут по конвейеру поэлементно. Это тот же принцип, на котором строится обработка больших файлов, потоковый парсинг логов, ETL-пайплайны.

## `send()` – двусторонний канал

`yield` может не только отдавать значение наружу, но и принимать его обратно через метод **`send()`**:

```python
def echo():
    while True:
        received = yield
        print(f'Получено: {received}')

gen = echo()
# обязательный первый next() – доходим до первого yield
next(gen)
# 'Получено: hello'
gen.send('hello')
# 'Получено: world'
gen.send('world')
```

На практике `send()` встречается редко – асинхронный код сейчас строится через `async`/`await`, которые исторически как раз выросли из этого механизма.

---

## Когда использовать генераторы

Генераторы уместны для обработки больших или бесконечных последовательностей данных (потоковое чтение файлов, бесконечный счётчик, поток событий), для построения конвейеров трансформации данных без лишних промежуточных списков и везде, где важна ленивость – значение не нужно вычислять, пока оно реально не потребовалось.
