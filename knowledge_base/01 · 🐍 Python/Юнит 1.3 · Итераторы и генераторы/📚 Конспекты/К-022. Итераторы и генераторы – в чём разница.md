## Iterable vs Iterator: ключевые различия

Это разные, хотя и связанные понятия, и их часто путают:

- **Iterable (итерируемый объект)** — любой объект, который умеет отдать итератор через встроенную функцию `iter()` (реализует метод `__iter__`). Списки, строки, словари, множества — всё это `iterable`, но не итераторы сами по себе.
- **Iterator (итератор)** — объект потока данных, отдающий элементы по одному через `next()`. Он реализует методы `__iter__` и `__next__`, и сохраняет своё текущее состояние между вызовами.

---

## Получение итератора через iter() и обход next()

Список сам по себе не хранит позицию обхода. Каждый вызов `iter(lst)` создаёт новый независимый итератор с начала:

```python
lst = [1, 2, 3]
# получили итератор из iterable
it = iter(lst)

print(next(it))  # 1
print(next(it))  # 2
print(next(it))  # 3
print(next(it))  # StopIteration
```

У самого итератора `it` есть внутреннее состояние: он «помнит», сколько элементов уже отдал, и не может быть сброшен в начало.

## Протокол итератора вручную

Любой класс становится итератором, если реализует два dunder-метода:

```python
class CountUp:
    def __init__(self, limit):
        self.limit = limit
        self.current = 0

    def __iter__(self):
        return self

    def __next__(self):
        if self.current >= self.limit:
            raise StopIteration
        self.current += 1
        return self.current

for num in CountUp(3):
    print(num)  # 1, 2, 3
```

Цикл `for` не знает деталей класса — он просто вызывает `iter()`, а затем `next()` на каждом шаге, пока не перехватит `StopIteration`. Ручная реализация требует явного хранения состояния (`self.current`) и ручного `raise StopIteration`.

## Генератор – итератор, который пишется как функция

**Генератор** — это частный случай итератора: он автоматически реализует протокол `__iter__` и `__next__` и сам сохраняет стек вызова:

```python
def count_up(limit):
    current = 0
    while current < limit:
        current += 1
        yield current

gen = count_up(3)
print(next(gen))  # 1
print(next(gen))  # 2
# продолжает с того места, где остановились
for num in gen:
    print(num)  # 3
```

Класс `CountUp` занял 12 строк кода с ручным состоянием, а генератор — всего 5 строк. Инструкция `yield` «замораживает» функцию и возвращает значение, а следующий `next()` возобновляет исполнение с той же точки.

## Память и ленивые вычисления: List vs Generator

Список аллоцирует память сразу под все элементы, а генератор вычисляет элементы **лениво**, строго по требованию:

- `[x**2 for x in range(10_000_000)]` — требует сотни мегабайт оперативной памяти ($O(n)$) под 10 миллионов чисел одновременно.
- `(x**2 for x in range(10_000_000))` — занимает в памяти всего несколько байт ($O(1)$), так как хранит лишь формулу и текущее число.

---

## Однократность обхода и компромиссы генераторов

Ленивость даёт экономию памяти, но накладывает важные ограничения:

1. **Однократный обход**: генератор можно пройти **только один раз**. После исчерпания он остаётся пустым и повторный вызов `next()` будет выбрасывать `StopIteration`.
2. **Нет индексов и длины**: у генератора нельзя запросить `gen[5]` или `len(gen)`.
3. Для повторного обхода генераторную функцию нужно вызывать заново.

---

## Итог: три уровня абстракции

Запомните чёткую ментальную иерархию для собеседований:

- **Iterable**: контейнер с `__iter__` (`list`, `str`, `dict`, `set`).
- **Iterator**: поток данных с `__iter__` и `__next__`. Помнит текущую позицию.
- **Generator**: краткий способ создания итератора через `yield` или генераторное выражение без написания громоздких классов.
- *Правило*: каждый генератор — итератор, но не каждый итератор — генератор!
