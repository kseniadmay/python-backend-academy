## Iterable vs Iterator: ключевые различия

Это разные, хотя и связанные понятия, которые часто путают:

- **Iterable (итерируемый объект)** — любой объект, который умеет отдать итератор через `iter()` (реализует метод `__iter__`). Списки, строки, словари и множества — это `iterable`, но не итераторы сами по себе.
- **Iterator (итератор)** — объект потока данных, отдающий элементы по одному через `next()`. Он реализует `__iter__` и `__next__` и хранит текущую позицию между вызовами.

---

## Получение итератора через iter() и обход next()

Список сам не хранит позицию обхода, а каждый вызов `iter(lst)` создаёт новый независимый итератор с начала:

```python
lst = [1, 2, 3]

# Получили итератор из iterable
it = iter(lst)

print(next(it))
# >>> 1

print(next(it))
# >>> 2

print(next(it))
# >>> 3

# Четвёртый вызов вызывает StopIteration
try:
    print(next(it))
except StopIteration:
    print('StopIteration')
# >>> StopIteration
```

У самого итератора `it` есть внутреннее состояние: он помнит, сколько элементов уже отдал, и не может быть сброшен обратно в начало.

## Протокол итератора вручную

Любой класс становится итератором, если реализует два dunder-метода:

```python
class CountUp:
    def __init__(self, limit):
        self.limit = limit
        self.current = 0

    # Возвращает сам объект-итератор
    def __iter__(self):
        return self

    # Выдаёт следующий элемент или стоп
    def __next__(self):
        if self.current >= self.limit:
            raise StopIteration
        self.current += 1
        return self.current

for num in CountUp(3):
    print(num)
# >>> 1
# >>> 2
# >>> 3
```

Цикл `for` просто вызывает `iter()`, а затем `next()` до перехвата `StopIteration`. Ручная реализация требует явного хранения счётчика и ручного выброса исключения.

## Генератор – итератор, который пишется как функция

**Генератор** — частный случай итератора: он сам реализует `__iter__` и `__next__` и автоматически сохраняет стек вызова:

```python
def count_up(limit):
    current = 0
    while current < limit:
        current += 1
        yield current

gen = count_up(3)
print(next(gen))
# >>> 1

print(next(gen))
# >>> 2

# Продолжает с места остановки
for num in gen:
    print(num)
# >>> 3
```

Вместо 11 строк класса генератор занимает 5 строк: `yield` замораживает функцию, а следующий `next()` возобновляет её с той же строки.

## Память и ленивые вычисления: List vs Generator

Список аллоцирует память сразу под все элементы, а генератор вычисляет их **лениво**, строго по требованию:

- `[x**2 for x in range(10_000_000)]` — занимает сотни мегабайт RAM ($O(n)$) под 10 миллионов чисел одновременно.
- `(x**2 for x in range(10_000_000))` — занимает лишь десятки байт ($O(1)$), храня только формулу и текущее состояние.

---

## Однократность обхода и компромиссы генераторов

Ленивость даёт огромную экономию памяти, но накладывает два ограничения:

1. **Однократный обход:** генератор можно пройти только один раз — после исчерпания он остаётся пустым, и для повтора генераторную функцию нужно вызвать заново.
2. **Нет индексов и длины:** у генератора нельзя запросить `gen[5]` или `len(gen)`.

## Итог: три уровня абстракции

Сводка иерархии абстракций для собеседований:

| Уровень | Протокол | Примеры и назначение |
| :--- | :--- | :--- |
| **Iterable** | `__iter__` | Контейнеры (`list`, `str`, `dict`, `set`) |
| **Iterator** | `__iter__` + `__next__` | Поток данных с текущей позицией обхода |
| **Generator** | Итератор через `yield` / `(...)` | Лаконичный ленивый поток без классов |

Правило: каждый генератор является итератором, но не каждый итератор — генератор.
