1. Каково золотое правило `__str__` и `__repr__` ? >> Всегда определяй `__repr__` ; `__str__` – только когда нужно отдельное красивое отображение для пользователя
2. Почему важно всегда определять `__repr__` ? >> Чтобы у объекта всегда было хотя бы одно строковое представление; без него вывод будет `<ClassName object at 0x...>`
3. Что общего у `__str__` и `__repr__` ? >> Оба возвращают строковое представление объекта
4. Какая функция используется для воссоздания объекта из `repr` ? >> `eval()` ; применять с осторожностью – выполняет произвольный Python-код
5. Какое основное требование к выводу `__repr__` ? >> Должен быть однозначным; в идеале позволять воссоздать объект через `eval()`
6. Какое равенство должно в идеале соблюдаться для `repr` ? >> `eval(repr(obj)) == obj` ; это идеал, не всегда достижимый – например, для объектов с внешними ресурсами или ссылками
7. Через какие функции вызывается `__str__` ? >> `str()` , `print()` ; также в f-строках: `f'{obj}'` вызывает `__str__`
8. Как называется механизм когда Python использует `__repr__` при отсутствии `__str__` ? >> Механизм отката (fallback)
9. В какой среде `repr(obj)` выполняется автоматически? >> В интерактивной консоли (REPL)
10. Для какой аудитории предназначен `__str__` ? >> Для конечного пользователя: читаемое, человекопонятное представление
11. В чём разница между `__str__` и `__repr__` ? >> `__str__` – читаемый вывод для пользователя; `__repr__` – однозначный технический вывод для разработчика
12. Для какой аудитории предназначен `__repr__` ? >> Для разработчика: техническое, однозначное представление объекта
13. Что вернёт `str(date(2024, 1, 15))` ? >> `'2024-01-15'`
14. Когда вызывается `__repr__` ? >> В интерактивной консоли (REPL), через `repr()` , при логировании через `logging` , в f-строках с `!r` : `f'{obj!r}'`
15. Что произойдёт если для объекта не определён `__str__` ? >> Python использует `__repr__` как fallback
16. Что вернёт `repr(date(2024, 1, 15))` ? >> `'datetime.date(2024, 1, 15)'`
