## Что такое dunder-методы

**Dunder** (*double underscore*) — системные методы вида `__init__`, `__add__`, `__str__` с двойным подчёркиванием с обеих сторон. Такое оформление исключает случайные конфликты с обычными методами разработчика.

Их также называют **магическими методами**: разработчик почти никогда не вызывает их напрямую — Python запускает их сам в ответ на операторы (`+`, `==`, `in`, `[]`) и встроенные функции (`len()`, `str()`, `iter()`).

---

## Как работает перегрузка операторов

Когда вы пишете `v1 + v2`, интерпретатор транслирует выражение в вызов `v1.__add__(v2)`. Аналогично `len(obj)` вызывает `obj.__len__()`, унарный минус `-v1` вызывает `v1.__neg__()`, а `a == b` — `a.__eq__(b)`.

Этот механизм называется **перегрузкой операторов** (*operator overloading*): класс сам задаёт поведение стандартных операторов языка для своих объектов.

## Пример перегрузки в классе `Vector`

Реализуем двумерный вектор с поддержкой строкового вывода, длины, унарного минуса `-v`, сложения `+` и сравнения `==`:

```python
class Vector:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __repr__(self):
        return f'Vector({self.x}, {self.y})'

    def __len__(self):
        return 2

    def __neg__(self):
        return Vector(-self.x, -self.y)

    # Оператор сложения v1 + v2
    def __add__(self, other):
        if not isinstance(other, Vector):
            return NotImplemented
        return Vector(
            self.x + other.x,
            self.y + other.y,
        )

    # Оператор равенства ==
    def __eq__(self, other):
        if not isinstance(other, Vector):
            return NotImplemented
        return (
            self.x == other.x
            and self.y == other.y
        )


v1 = Vector(1, 2)
v2 = Vector(3, 4)
print(v1 + v2)
# >>> Vector(4, 6)

print(-v1)
# >>> Vector(-1, -2)

print(v1 == Vector(1, 2))
# >>> True
```

Без `__repr__`/`__str__` вывод покажет адрес вида `<__main__.Vector object at 0x...>`, а без `__eq__` оператор `==` по умолчанию сравнивает только ссылки в памяти как `is`.

## Протоколы коллекций и вызова (`[]`, `in`, `()`)

Dunder-методы позволяют сделать собственный объект полноценной коллекцией или вызываемым объектом без наследования от `list`/`dict`:

- **`__getitem__(self, key)` и `__setitem__(self, key, val)`** — чтение `obj[k]` и запись `obj[k] = v`;
- **`__contains__(self, item)`** — проверка вхождения `item in obj`;
- **`__call__(self, *args)`** — позволяет вызывать экземпляр как функцию: `obj(x)`.

```python
class Box:
    def __init__(self):
        self._items = {}

    def __setitem__(self, key, value):
        self._items[key] = value

    def __getitem__(self, key):
        return self._items[key]

    def __contains__(self, key):
        return key in self._items


box = Box()
box['cpu'] = 8
print('cpu' in box, box['cpu'])
# >>> True 8
```

## Перехват атрибутов: `__getattr__` vs `__getattribute__`

На собеседованиях часто спрашивают про перехват доступа к полям объекта:

- **`__getattribute__(self, name)`** — вызывается при **каждом** обращении к любому атрибуту (`obj.x`), даже существующему. Внутри нужно обращаться через `super().__getattribute__(name)`, иначе возникнет бесконечная рекурсия.
- **`__getattr__(self, name)`** — срабатывает **только** если атрибут не найден обычным поиском (удобно для ленивых прокси и fallback-значений).
- **`__delattr__(self, name)`** — перехватывает удаление атрибута (`del obj.x`).

```python
class SafeConfig:
    def __init__(self, data):
        self._data = data

    def __getattr__(self, name):
        # Сработает только для новых полей
        return self._data.get(name, 'default')


cfg = SafeConfig({'port': 8080})
print(cfg.port, cfg.host)
# >>> 8080 default
```

## `NotImplemented`, `__hash__` и подход Junior vs Senior

- **Возврат `NotImplemented`:** в бинарных методах (`__add__`, `__eq__`) при несовместимом типе `other` возвращают именно `NotImplemented`, а не выбрасывают `TypeError` — тогда Python попробует вызвать зеркальный метод `other.__radd__(self)`.
- **Ловушка `__eq__` и `__hash__`:** как только вы переопределяете `__eq__`, Python автоматически сбрасывает `__hash__ = None`, и объект перестаёт помещаться в `set` и ключи `dict`. Чтобы вернуть хешируемость, для неизменяемого объекта нужно явно реализовать `__hash__`.
- **Протоколы и утиная типизация:** класс с `__iter__`/`__next__` работает в цикле `for`, а с `__len__`/`__getitem__` ведёт себя как последовательность без жёсткого наследования от `ABC`.

> **Junior vs Senior**:
> - **Junior**: В `__add__` выбрасывает `TypeError` при другом типе (ломая обратные операторы `__radd__`) или переопределяет `__getattribute__` с прямым `self.x`, получая `RecursionError`.
> - **Senior**: Возвращает `NotImplemented` в бинарных dunder-методах, разделяет `__getattr__` (fallback) и `__getattribute__`, а при переопределении `__eq__` осознанно решает, должен ли объект быть хешируемым (`__hash__`).
