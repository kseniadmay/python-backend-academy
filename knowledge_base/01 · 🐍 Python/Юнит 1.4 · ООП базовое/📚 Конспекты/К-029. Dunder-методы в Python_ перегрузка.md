## Что такое dunder-методы

**Dunder** (*double underscore*) — системные методы вида `__init__`, `__add__`, `__str__` с двойным подчёркиванием. Такое оформление исключает случайные коллизии с обычными именами.

Их также называют **магическими методами**: разработчик не вызывает их напрямую — Python запускает их сам в ответ на операторы и встроенные функции.

---

## Как работает перегрузка операторов

Когда вы пишете `v1 + v2`, интерпретатор транслирует выражение в вызов `v1.__add__(v2)`. Аналогично `len(obj)` вызывает `obj.__len__()`, а `a == b` — `a.__eq__(b)`.

Этот механизм называется **перегрузкой операторов** (*operator overloading*): класс сам задаёт поведение стандартных знаков языка.

## Пример перегрузки в классе `Vector`

Реализуем двумерный вектор с поддержкой строкового вывода, длины, сложения `+` и сравнения `==`:

```python
class Vector:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __repr__(self):
        return f'Vector({self.x}, {self.y})'

    def __len__(self):
        return 2

    # Оператор сложения v1 + v2
    def __add__(self, other):
        if not isinstance(other, Vector):
            return NotImplemented
        return Vector(
            self.x + other.x,
            self.y + other.y,
        )

    # Оператор равенства ==
    def __eq__(self, other):
        if not isinstance(other, Vector):
            return NotImplemented
        return (
            self.x == other.x
            and self.y == other.y
        )

v1 = Vector(1, 2)
v2 = Vector(3, 4)
print(v1 + v2)
# >>> Vector(4, 6)

print(v1 == Vector(1, 2))
# >>> True
```

Без `__repr__`/`__str__` вывод объекта покажет адрес вида `<__main__.Vector object at 0x...>`, а без `__eq__` оператор `==` по умолчанию сравнивает только ссылки как `is`.

## Протоколы, `NotImplemented` и утиная типизация

В бинарных методах (`__add__`, `__eq__`) при несовместимом типе `other` возвращают `NotImplemented` вместо выброса `TypeError` — тогда Python попробует вызвать зеркальный `other.__radd__(self)`.

Dunder-методы формируют **протоколы** (неформальные интерфейсы языка): класс с `__iter__`/`__next__` работает в цикле `for`, а с `__len__`/`__getitem__` ведёт себя как последовательность без жёсткого наследования.
