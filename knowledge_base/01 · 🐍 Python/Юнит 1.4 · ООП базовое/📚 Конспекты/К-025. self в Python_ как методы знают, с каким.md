## Зачем нужен `self`

Когда в памяти существует сотня экземпляров одного класса (например, сто объектов `Dog`), метод `bark` у всех один. Нужен способ точно указать методу, к чьим именно данным обращаться.

**`self`** — это ссылка на конкретный экземпляр, с которым метод работает прямо сейчас. Через `self` метод обращается к атрибутам и другим методам именно этого объекта, не затрагивая остальные.

---

## Как это работает под капотом

При создании объекта Python выделяет память и передаёт ссылку на новый экземпляр в `__init__` через `self`:

```python
class Dog:
    def __init__(self, name):
        self.name = name

    def bark(self):
        return f'{self.name} says woof!'

d = Dog('Rex')
print(d.bark())
# >>> Rex says woof!
```

Внутри `d = Dog('Rex')` инструкция `self.name = name` записывает `'Rex'` в словарь атрибутов именно экземпляра `d`.

При вызове `d.bark()` метод снова получает ссылку на `d` и читает `'Rex'`, а не имя другого объекта.

---

## Механизм автоматической передачи аргумента

Разработчик не передаёт `self` вручную: выражение `d.bark()` под капотом преобразуется в вызов метода класса `Dog.bark(d)`.

Убедимся в эквивалентности обеих форм вызова напрямую:

```python
class Dog:
    def __init__(self, name):
        self.name = name

    def bark(self):
        return f'{self.name} says woof!'

d = Dog('Rex')
print(d.bark())
# >>> Rex says woof!

# Эквивалентный явный вызов через класс
print(Dog.bark(d))
# >>> Rex says woof!
```

Объект слева от точки автоматически становится первым аргументом внутри скобок.

---

## `self` — соглашение PEP 8 и ошибки на практике

Технически `self` не является ключевым словом: первый аргумент можно назвать `this` или `obj`. Однако в Python-сообществе отказ от имени `self` считается грубым нарушением PEP 8, на которое ругаются линтеры.

Если забыть указать `self` в объявлении метода, вызов через экземпляр `d.bark()` передаст скрытый первый аргумент и упадёт с `TypeError: ... takes 0 positional arguments but 1 was given`.
