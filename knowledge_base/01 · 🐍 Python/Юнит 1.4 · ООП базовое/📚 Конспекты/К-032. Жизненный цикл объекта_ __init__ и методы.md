## Класс и экземпляр — в чём разница

**Класс** — это описание структуры: какие атрибуты будут у объекта и какие методы он умеет вызывать.

**Экземпляр** — живой объект в памяти со своим состоянием, созданный по чертежу класса выражением вроде `Car('BMW')`. Каждый экземпляр хранит свои поля в собственном словаре `obj.__dict__`.

---

## `__init__` — инициализация состояния

После того как `__new__` выделил память, Python автоматически вызывает метод `__init__`, чтобы задать начальные атрибуты экземпляра:

```python
class Car:
    def __init__(self, brand):
        # Уникальный атрибут экземпляра
        self.brand = brand

        # Общее начальное состояние
        self.speed = 0

    def accelerate(self, value):
        self.speed += value


car = Car('BMW')
car.accelerate(50)
print(car.brand, car.speed)
# >>> BMW 50
```

Через `self.brand = brand` значение записывается именно в конкретный объект. Без явной инициализации поля в `__init__` обращение к нему вызовет `AttributeError`.

## Атрибуты класса vs атрибуты экземпляра

Атрибуты, объявленные прямо в теле класса, **общие для всех экземпляров**; атрибуты в `self.*` — индивидуальны для каждого объекта.

Частая ловушка — положить изменяемый список `tags = []` на уровень класса:

```python
class User:
    # Опасно: общий список для всех User!
    shared_roles = []

    def __init__(self, name):
        self.name = name
        # Безопасно: отдельный список объекта
        self.roles = []


u1 = User('Аня')
u2 = User('Игорь')
u1.roles.append('admin')
print(u1.roles, u2.roles)
# >>> ['admin'] []
```

Атрибуты уровня класса подходят только для неизменяемых констант (`MAX_SPEED = 240`, `DEFAULT_ROLE = 'guest'`).

## Три вида методов: обычные, `@classmethod` и `@staticmethod`

В Python-классе методы делятся по тому, к чему они имеют доступ:

| Тип метода | Первый аргумент | Когда использовать |
| :--- | :--- | :--- |
| **Обычный метод** | `self` (экземпляр) | Читает и меняет состояние конкретного объекта |
| **`@classmethod`** | `cls` (сам класс) | Альтернативные конструкторы и фабрики |
| **`@staticmethod`** | нет | Вспомогательная утилита, логически связанная с классом |

```python
class Order:
    def __init__(self, amount):
        self.amount = amount

    @classmethod
    def from_cents(cls, cents):
        # Фабричный конструктор через cls
        return cls(cents / 100)

    @staticmethod
    def is_valid_amount(amount):
        return amount > 0


order = Order.from_cents(1550)
print(order.amount, Order.is_valid_amount(10))
# >>> 15.5 True
```

Использование `cls(...)` внутри `@classmethod` гарантирует, что при наследовании дочерний класс вернёт свой тип, а не родительский.

## Обычные методы и поведение объекта

Обычные методы задают **поведение**: в отличие от однократного `__init__`, их вызывают столько раз, сколько нужно, проверяя инварианты и меняя поля `self`.

Разделение на **состояние** (в `__init__`) и **поведение** (в методах) — основа чистого ООП: создание обязательных полей не должно быть разбросано по произвольным методам, иначе состояние объекта станет непредсказуемым.

## Частая архитектурная ошибка в `__init__` и подход Junior vs Senior

Перегружать `__init__` тяжёлой логикой (сетевыми запросами, подключением к БД, чтением файлов) — плохая практика: конструктор должен лишь быстро провалидировать аргументы и задать начальное состояние.

Если объекту нужна тяжёлая подготовка или I/O, выносите её в `@classmethod`-фабрику или отдельный метод `connect()` — иначе класс будет невозможно легко создавать в юнит-тестах.

> **Junior vs Senior**:
> - **Junior**: Открывает соединение с БД прямо в `__init__` и объявляет изменяемый `items = []` в теле класса, получая утечку состояния между экземплярами и хрупкие тесты.
> - **Senior**: Держит `__init__` быстрым и чистым, инициализирует все изменяемые поля через `self`, а парсинг конфигов и сетевые вызовы выносит в фабрики `@classmethod`.
