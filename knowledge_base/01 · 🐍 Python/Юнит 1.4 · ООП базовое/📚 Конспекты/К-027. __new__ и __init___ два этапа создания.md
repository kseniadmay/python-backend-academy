## Создание объекта – это не один шаг

Вызов `Dog('Rex')` не является одним неделимым действием. Python выполняет два последовательных этапа: сначала создаёт пустой объект в памяти, а затем заполняет его атрибутами.

За каждый этап отвечает отдельный магический метод: `__new__` и `__init__`.

---

## `__new__` – создание объекта в памяти

**`__new__`** — настоящий конструктор: он выделяет память и возвращает новый экземпляр через `super().__new__(cls)`:

```python
class MyObject:
    # __new__ выделяет память ДО __init__
    def __new__(cls, *args, **kwargs):
        instance = super().__new__(cls)
        return instance
```

Первым аргументом идёт класс `cls` (экземпляра ещё нет), и метод обязан вернуть объект — иначе `__init__` не запустится.

Чаще всего `__new__` переопределяют при наследовании от неизменяемых `int`/`str`/`tuple` (их нельзя менять в `__init__`) и в паттерне **Singleton**.

Пример паттерна Singleton, возвращающего всегда один и тот же экземпляр класса:

```python
class Singleton:
    _inst = None

    def __new__(cls):
        # Создаём экземпляр только один раз
        if cls._inst is None:
            cls._inst = super().__new__(cls)
        return cls._inst

a = Singleton()
b = Singleton()

# Обе переменные указывают на 1 объект
print(a is b)
# >>> True
```

## `__init__` – инициализация состояния

**`__init__`** — это инициализатор, получающий уже созданный `__new__` объект `self` и записывающий в него начальные атрибуты:

```python
class User:
    def __new__(cls, name):
        print('1. Память выделена')
        return super().__new__(cls)

    def __init__(self, name):
        # Записываем состояние в self
        print('2. Состояние задано')
        self.name = name

u = User('Alice')
# >>> 1. Память выделена
# >>> 2. Состояние задано

print(u.name)
# >>> Alice
```

Метод `__init__` всегда возвращает `None` (возврат любого другого значения вызовет `TypeError`). В 99% повседневного кода используется только `__init__`.

## Порядок вызовов и сравнение `__new__` vs `__init__`

Сравнение двух этапов создания экземпляра и их контрактов:

| Характеристика | `__new__` | `__init__` |
| :--- | :--- | :--- |
| Порядок и роль | 1-й шаг: выделение памяти | 2-й шаг: заполнение атрибутов |
| 1-й аргумент | Класс `cls` | Готовый экземпляр `self` |
| Возврат | Новый объект (иначе пропуск `__init__`) | Строго `None` (иначе `TypeError`) |
| Применение | Singleton, метаклассы, `str`/`int`/`tuple` | Любая обычная инициализация |

Критическое правило: если переопределённый `__new__` вернёт объект другого класса (или забудет `return`), интерпретатор вообще не вызовет `__init__`.

## Наследование от неизменяемых типов и ловушка Singleton

Главный практический сценарий `__new__` — создание подклассов от неизменяемых типов (`str`, `int`, `tuple`). В `__init__` менять значение строки уже поздно, поэтому трансформацию выполняют в `__new__`:

```python
class UpperStr(str):
    def __new__(cls, value):
        # Неизменяемая строка в uppercase
        upper = value.upper()
        return super().__new__(cls, upper)


tag = UpperStr('backend')
print(tag)
# >>> BACKEND
```

**Ловушка Singleton с `__init__`:** когда `__new__` возвращает уже существующий экземпляр `cls._inst`, Python **всё равно автоматически вызывает `__init__` повторно** при каждом `Singleton()`. Поэтому в Singleton инициализацию защищают флагом `self._initialized` либо используют обычный объект на уровне модуля.

> **Junior vs Senior**:
> - **Junior**: Пытается изменить значение подкласса `int`/`tuple` внутри `__init__` или пишет `Singleton` на `__new__`, не зная, что `__init__` будет перезатирать поля объекта при каждом повторном вызове.
> - **Senior**: Использует `__new__` только для иммутабельных подклассов и метапрограммирования, а для синглтона в Python предпочитает экземпляр на уровне модуля или `@lru_cache(maxsize=1)` на фабричной функции.
