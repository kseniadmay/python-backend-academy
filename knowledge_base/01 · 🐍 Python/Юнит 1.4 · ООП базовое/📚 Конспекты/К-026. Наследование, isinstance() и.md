## Базовое наследование

Наследование выражает отношение "является" (is-a): дочерний класс получает все атрибуты и методы родителя и может их переопределять или дополнять.

```python
class Animal:
    def __init__(self, name):
        self.name = name
    def speak(self):
        return f'{self.name} издаёт звук'
class Dog(Animal):
    def speak(self):
        return f'{self.name} лает'
class Cat(Animal):
    pass
print(Dog('Рекс').speak())  # 'Рекс лает'
print(Cat('Мурка').speak())
```

## isinstance() – проверка типа с учётом иерархии

`isinstance(obj, Class)` проверяет, является ли `obj` экземпляром `Class` **или любого его подкласса** – в отличие от `type(obj) == Class`, который проверяет точное совпадение типа.

```python
d = Dog('Рекс')
print(isinstance(d, Dog))  # True
# True – Dog это подкласс Animal
print(isinstance(d, Animal))
# False – точный тип именно Dog, не Animal
print(type(d) == Animal)

# True – можно передать кортеж классов,
print(isinstance(d, (Dog, Cat)))
```

---

## issubclass() – проверка отношения между классами

`issubclass(ChildClass, ParentClass)` проверяет отношение на уровне **классов**, а не экземпляров.

```python
print(issubclass(Dog, Animal))  # True
# False – обратное неверно
print(issubclass(Animal, Dog))
# True: класс считается подклассом себя
print(issubclass(Dog, Dog))
```

---

## Преимущества isinstance() перед прямым сравнением type()

`isinstance()` уважает полиморфизм – код, написанный для `Animal`, корректно работает с любым подклассом `Animal`, что и является смыслом наследования. Проверка `type(obj) == Animal` сломается на любом подклассе, даже если он полностью совместим по интерфейсу – это противоречит самой идее ОО-иерархий и считается анти-паттерном за пределами редких случаев, когда точный тип действительно принципиален.

---

## Наследование vs композиция: когда что выбирать
Наследование применимо, только когда есть истинное отношение **«является» (is-a)**, и дочерний класс расширяет поведение родителя. Если нужно просто переиспользовать логику — отдавайте предпочтение **композиции** («содержит в себе», has-a).

---

## Когда использовать isinstance() и issubclass()
`isinstance()` — стандартный способ проверить тип с учётом полиморфизма перед специализированной обработкой подкласса.
`issubclass()` применяется при валидации самих классов (в плагинах, фабриках и метапрограммировании).

## Абстрактные базовые классы (abc.ABC) и виртуальные подклассы в isinstance()

Функция `isinstance()` в Python поддерживает не только прямое наследование по дереву MRO, но и **виртуальные подклассы**:

- **Регистрация через `.register()`**: Любой класс можно зарегистрировать как виртуальный подкласс абстрактного базового класса (`MyABC.register(TargetClass)`). При этом `TargetClass` не наследуется от `MyABC`, но `isinstance(target_obj, MyABC)` и `issubclass(TargetClass, MyABC)` возвращают `True`.
- **Динамическая проверка через `__subclasshook__`**: Модуль `abc` позволяет абстрактному классу определить метод `__subclasshook__(cls, C)`, который анализирует структуру класса `C` (наличие нужных методов). Так работают классы стандартной библиотеки из `collections.abc` (например, `Iterable`, `Sequence`, `Mapping`). Любой объект с методом `__iter__` считается экземпляром `collections.abc.Iterable` без явного наследования!

```python
from abc import ABC, abstractmethod
import collections.abc

class SoundEmitter(ABC):
    @abstractmethod
    def make_sound(self) -> str:
        pass

class Radio:
    def make_sound(self) -> str:
        return 'Играет музыка'

# Явная регистрация виртуального подкласса
SoundEmitter.register(Radio)

r = Radio()
print(isinstance(r, SoundEmitter))  # True! Даже без class Radio(SoundEmitter)
print(issubclass(Radio, SoundEmitter))  # True!
```
