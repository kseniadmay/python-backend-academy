## Базовое наследование

Наследование выражает отношение "является" (is-a): дочерний класс получает все атрибуты и методы родителя и может их переопределять или дополнять.

```python
class Animal:
    def __init__(self, name):
        self.name = name
    def speak(self):
        return f'{self.name} издаёт звук'

# Наследуется и переопределяет speak
class Dog(Animal):
    def speak(self):
        return f'{self.name} лает'

# Наследует метод speak без изменений
class Cat(Animal):
    pass

print(Dog('Рекс').speak())
# >>> Рекс лает
print(Cat('Мурка').speak())
# >>> Мурка издаёт звук
```

## isinstance() – проверка типа с учётом иерархии

`isinstance(obj, Class)` проверяет, является ли `obj` экземпляром `Class` **или любого его подкласса** – в отличие от `type(obj) == Class`, который проверяет точное совпадение типа.

```python
class Animal:
    def __init__(self, name):
        self.name = name

class Dog(Animal):
    pass

class Cat(Animal):
    pass

d = Dog('Рекс')
print(isinstance(d, Dog))
# >>> True
# Dog — подкласс Animal
print(isinstance(d, Animal))
# >>> True
# Точный тип именно Dog, не Animal
print(type(d) == Animal)
# >>> False
print(isinstance(d, (Dog, Cat)))
# >>> True
```

## issubclass() – проверка отношения между классами

`issubclass(ChildClass, ParentClass)` проверяет отношение на уровне **классов**, а не экземпляров.

```python
class Animal:
    pass

class Dog(Animal):
    pass

print(issubclass(Dog, Animal))
# >>> True
# Родитель не является подклассом потомка
print(issubclass(Animal, Dog))
# >>> False
# Класс считается подклассом самого себя
print(issubclass(Dog, Dog))
# >>> True
```

## Преимущества isinstance() перед прямым сравнением type()

`isinstance()` уважает полиморфизм – код, написанный для `Animal`, корректно работает с любым подклассом `Animal`, что и является смыслом наследования.

Проверка `type(obj) == Animal` сломается на любом подклассе, даже если он полностью совместим по интерфейсу – это противоречит самой идее ОО-иерархий и считается антипаттерном за пределами редких случаев, когда точный тип действительно принципиален.

## Наследование vs композиция: когда что выбирать

Наследование применимо, только когда есть истинное отношение **«является» (is-a)**, и дочерний класс расширяет поведение родителя. Если нужно просто переиспользовать логику — отдавайте предпочтение **композиции** («содержит в себе», has-a).

---

## Когда использовать isinstance() и issubclass()

`isinstance()` — стандартный способ проверить тип с учётом полиморфизма перед специализированной обработкой подкласса.

`issubclass()` применяется при валидации самих классов (в плагинах, фабриках и метапрограммировании).

## Виртуальные подклассы и явная регистрация через register()

Функция `isinstance()` поддерживает регистрацию виртуальных подклассов без физического наследования:

```python
from abc import ABC, abstractmethod

class SoundEmitter(ABC):
    @abstractmethod
    def make_sound(self) -> str:
        pass

class Radio:
    def make_sound(self) -> str:
        return 'Играет музыка'

# Делаем Radio виртуальным подклассом
SoundEmitter.register(Radio)

r = Radio()
print(isinstance(r, SoundEmitter))
# >>> True
print(issubclass(Radio, SoundEmitter))
# >>> True
```

Виртуальный подкласс удовлетворяет проверкам `isinstance()` и `issubclass()`, не загрязняя дерево MRO родительскими классами.

## Структурная типизация в рантайме: метод `__subclasshook__`

Модуль `abc` позволяет абстрактному классу определить метод `__subclasshook__(cls, C)`, проверяющий наличие методов в классе `C`:

- Так устроена стандартная библиотека `collections.abc` (`Iterable`, `Sequence`, `Mapping`).
- Любой объект, реализующий метод `__iter__`, автоматически признаётся экземпляром `collections.abc.Iterable` без явного вызова `register()` или наследования.
