## Что такое инкапсуляция и зачем она нужна

**Инкапсуляция** – это принцип, при котором данные объекта и методы для работы с ними объединены в одну структуру, а доступ к внутренним деталям ограничен. Цель не в секретности, а в защите целостности объекта: пользователь класса не должен случайно сломать его внутреннюю логику, изменив важную переменную напрямую.

---

## Три уровня доступа через префиксы

В Python уровень доступа обозначается количеством подчёркиваний перед именем атрибута.

```python
class BankAccount:
    def __init__(self):
        self.owner = 'Alice'  # публичный
        self._balance = 1000  # защищённый
        self.__pin = 1234  # приватный
```

**Публичный атрибут** – без префикса. Это официальный интерфейс класса. Им можно пользоваться без ограничений.

**Защищённый атрибут** – один символ `_`. Это соглашение, а не техническое ограничение. Разработчик сигнализирует: «этот атрибут – внутренняя деталь реализации, я могу изменить его логику в любой момент». Доступ к нему технически возможен, но использование снаружи класса делает ваш код хрупким.

**Приватный атрибут** – два символа `__`. Python применяет к нему специальный механизм переименования и затрудняет прямой доступ. В отличие от `_`, здесь уже есть техническое воздействие на уровне интерпретатора.

---

## Name mangling: что происходит с `__pin`

Когда Python видит атрибут с двумя подчёркиваниями, он автоматически переименовывает его по формуле `_ИмяКласса__имя_атрибута`. Это называется **name mangling** (искажение имён).

```python
account = BankAccount()

print(account.__pin)  # AttributeError
print(account._BankAccount__pin)  # 1234 – атрибут существует, просто переименован
```

Атрибут не исчезает и не скрывается по-настоящему – он просто получает другое имя. Это означает, что настоящей приватности в Python нет. В Java доступ к приватному полю невозможен на уровне компилятора. В Python действует другой принцип: язык расставляет предупреждающие знаки, но не строит стен.

Основная причина существования name mangling – **защита от коллизий при наследовании**. Если создать подкласс и случайно объявить в нём атрибут с тем же именем, name mangling гарантирует, что приватный атрибут родителя не будет перезаписан.

---

## Почему обходить name mangling – плохая практика

Обращение к атрибуту через искажённое имя (`account._BankAccount__pin`) технически работает, но является грубым нарушением инкапсуляции. Вы обходите защитный механизм, заложенный автором класса, и создаёте зависимость от внутренней детали реализации, которая может измениться в любой момент.

## Как это применяется на практике

Для предоставления контролируемого доступа к защищённым данным используют публичные методы или `@property`. Это позволяет добавлять валидацию, логирование или ограничения, не открывая внутренние атрибуты напрямую:

```python
class BankAccount:
    def __init__(self):
        self._balance = 1000

    def deposit(self, amount):
        if amount > 0:
            self._balance += amount

    @property
    def balance(self):
        return self._balance
```

Пользователь читает баланс через `account.balance`, не зная и не завися от того, как именно он хранится внутри.

На собеседовании важно понимать разницу между `_` и `__`: первый – соглашение без технических последствий, второй – name mangling с конкретным механизмом переименования. И оба не создают настоящей приватности, как в Java или C++.
