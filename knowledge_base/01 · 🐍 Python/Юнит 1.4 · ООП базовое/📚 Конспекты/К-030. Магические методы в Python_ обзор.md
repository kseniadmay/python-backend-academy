## Что такое магические методы

**Магические методы** (dunder methods, от "double underscore") – методы вида `__method__`, которые Python вызывает автоматически в ответ на встроенные операции: создание объекта, сложение через `+`, вывод через `print()`, обращение по индексу, сравнение. Они превращают пользовательский класс в объект, который ведёт себя как встроенный тип – это и называется "поддержкой протокола".

---

## Основные группы методов

```python
class Money:
    def __init__(self, amount, curr='USD'):
        self.amount = amount
        self.currency = curr
    # Однозначное представление для отладки
    def __repr__(self):
        return (
            f"Money({self.amount}, "
            f"'{self.currency}')"
        )
    # Читаемый вывод суммы с валютой
    def __str__(self):
        amt, cur = self.amount, self.currency
        return f'{amt} {cur}'
```

---

## Категории по назначению

- **Создание и представление**: `__init__` (инициализация), `__new__` (создание объекта), `__repr__` / `__str__` (строковое представление).
- **Арифметика**: `__add__`, `__sub__`, `__mul__`, `__truediv__` и обратные версии (`__radd__`) для случая `other + self`.
- **Сравнение и контейнеры**: `__eq__`, `__lt__`, `__le__`, `__gt__`, `__len__`, `__getitem__`, `__setitem__`, `__contains__` (`in`), `__iter__` (`for`).
- **Специальные протоколы**: `__enter__` / `__exit__` (для контекстного менеджера `with`), `__call__` (вызов объекта как функции `obj()`), `__get__` / `__set__` (дескрипторы).

---

## __eq__ и __hash__ связаны

Если класс переопределяет `__eq__`, Python автоматически делает объект **нехэшируемым** (`__hash__` становится `None`), если `__hash__` не переопределён явно – потому что два "равных" объекта обязаны иметь одинаковый хэш, а старое поведение (хэш по `id`) этому гарантию больше не даёт. Если объект с кастомным `__eq__` нужно класть в `set` или использовать как ключ словаря – `__hash__` нужно определить самостоятельно, согласованно с `__eq__`.

---

## Когда использовать

Магические методы стоит переопределять, когда объект действительно ведёт себя как значение — сравнивается, складывается и красиво выводится (`Money`, `Vector`, `DateRange`). Не добавляйте `__add__` просто «потому что можно», если для класса нет естественного смысла операции сложения.

При этом `__repr__` полезно определять почти всегда: без него объекты выглядят в логах и отладчике как безликие адреса памяти.
