## Что такое магические методы

**Магические методы** (dunder methods, от "double underscore") – методы вида `__method__`, которые Python вызывает автоматически в ответ на встроенные операции: создание объекта, сложение через `+`, вывод через `print()`, обращение по индексу, сравнение. Они превращают пользовательский класс в объект, который ведёт себя как встроенный тип – это и называется "поддержкой протокола".

---

## Основные группы методов

```python
class Money:
    def __init__(self, amount, curr='USD'):
        self.amount = amount
        self.currency = curr
    def __repr__(self):
        return (
            f"Money({self.amount}, "
            f"'{self.currency}')"
        )
    def __str__(self):
        amt, cur = self.amount, self.currency
        return f'{amt} {cur}'
```

## Категории по назначению

**Создание и представление**: `__init__` (инициализация), `__new__` (создание объекта, реже переопределяется), `__repr__`/`__str__` (текстовое представление). **Арифметика**: `__add__`, `__sub__`, `__mul__`, `__truediv__` и их "обратные" версии `__radd__` и т.д. для случая `other + self`. **Сравнение**: `__eq__`, `__lt__`, `__le__`, `__gt__`, `__ge__`, `__ne__`. **Контейнерное поведение**: `__len__`, `__getitem__`, `__setitem__`, `__contains__` (для оператора `in`), `__iter__` (для `for`). **Контекстный менеджер**: `__enter__`/`__exit__` (для `with`). **Вызов как функция**: `__call__` – позволяет вызывать экземпляр как `obj()`. **Дескрипторы**: `__get__`/`__set__`/`__set_name__` (разобраны отдельно).

---

## __eq__ и __hash__ связаны

Если класс переопределяет `__eq__`, Python автоматически делает объект **нехэшируемым** (`__hash__` становится `None`), если `__hash__` не переопределён явно – потому что два "равных" объекта обязаны иметь одинаковый хэш, а старое поведение (хэш по `id`) этому гарантию больше не даёт. Если объект с кастомным `__eq__` нужно класть в `set` или использовать как ключ словаря – `__hash__` нужно определить самостоятельно, согласованно с `__eq__`.

---

## Когда использовать

Магические методы стоит переопределять, когда объект действительно должен вести себя как значение – сравниваться, складываться, печататься по-человечески (`Money`, `Vector`, `DateRange`). Не стоит переопределять их "потому что можно" – если у операции `+` нет естественного бизнес-смысла для класса, добавление `__add__` только запутает пользователей класса. `__repr__` – почти всегда полезно определить хотя бы его, ради читаемого вывода в отладчике и логах.
