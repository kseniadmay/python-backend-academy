1. Что возвращает вызов async-функции без await? >> Объект корутины — тело функции ещё не выполняется.
2. Что делает event loop? >> Управляет множеством корутин в одном потоке — запускает готовую задачу до ближайшего await, переключается на другую.
3. Чем asyncio.gather() отличается от последовательного await каждой корутины? >> gather() запускает их конкурентно — общее время примерно равно максимальной из задач, а не сумме.
4. Почему time.sleep() внутри async def — плохая идея? >> Он блокирует весь event loop целиком, а не только текущую корутину — все остальные задачи замирают.
5. Чем заменить time.sleep() в асинхронном коде? >> await asyncio.sleep().
6. Что такое Task в asyncio? >> Обёртка вокруг корутины, которую планирует и выполняет event loop; создаётся через asyncio.create_task().
7. Как выполнить блокирующий синхронный вызов, не заморозив event loop? >> Через asyncio.to_thread() или loop.run_in_executor().
8. Для каких задач asyncio даёт реальный выигрыш? >> Для I/O-bound — много времени ожидания сети, БД, файлов, а не вычислений.
9. Что делает asyncio.run()? >> Создаёт event loop и запускает переданную корутину как точку входа в асинхронную программу.
10. Можно ли вызвать await вне async-функции? >> Нет (за исключением интерактивных сред вроде Jupyter/REPL с поддержкой top-level await) — обычный код бросит SyntaxError.
11. В чём разница между asyncio.create_task() и просто await corofunc()? >> create_task() запускает корутину "в фоне" немедленно, не блокируя дальнейшее выполнение; await ждёт завершения сразу же.
12. Что произойдёт, если не сделать await для созданного Task? >> Сама задача всё равно начнёт выполняться на event loop (в отличие от простой корутины) — но если программа завершится раньше, чем Task закончится, он может быть прерван недоделанным, и в консоль выведется предупреждение "Task was destroyed but it is pending". Это ДРУГОЕ предупреждение, чем "coroutine was never awaited" — то относится к случаю, когда корутину вообще не передали ни в await, ни в create_task().
13. Освобождает ли GIL операция await asyncio.sleep()? >> Она отдаёт управление event loop'у, позволяя выполняться другим корутинам, пока не истечёт таймер.
14. Что делает asyncio.wait_for(coro, timeout=5)? >> Ждёт завершения корутины не дольше указанного времени, иначе бросает TimeoutError.
15. Какая библиотека даёт асинхронный HTTP-клиент, совместимый с asyncio? >> httpx.AsyncClient или aiohttp.
16. Из какого более старого механизма Python исторически выросли async/await? >> Из генераторов и yield (через send()) — ранние асинхронные библиотеки строились поверх генераторных корутин.
17. Что делает asyncio.sleep(0)? >> Не задерживает выполнение по времени, но передаёт управление event loop'у на один "тик" — даёт шанс выполниться другим ожидающим корутинам.
18. Может ли обычная (не async) функция быть вызвана изнутри корутины напрямую, без await? >> Да, если это быстрая, неблокирующая функция — await нужен только для awaitable объектов (корутин, задач, futures).
19. Что произойдёт при исключении внутри одной из корутин, переданных в asyncio.gather()? >> По умолчанию gather() немедленно пробросит это исключение наружу, не дожидаясь остальных (если не указан return_exceptions=True).
20. Что делает return_exceptions=True в asyncio.gather()? >> Вместо прерывания при первом исключении, собирает исключения как обычные результаты в списке — можно обработать каждое отдельно.
