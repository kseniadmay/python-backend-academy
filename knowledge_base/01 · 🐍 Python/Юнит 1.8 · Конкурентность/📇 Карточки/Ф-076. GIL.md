1. Какую ключевую задачу управления памятью упрощает GIL (Global Interpreter Lock) в CPython? >> Подсчёт ссылок ( `reference counting` ); без GIL потребовались бы блокировки на каждый объект
2. Как называется PEP о free-threaded Python? >> PEP 703
3. Освобождается ли GIL при сетевом запросе через `requests` ? >> Да; на время ожидания ответа сервера
4. Как GIL влияет на интеграцию с C-расширениями? >> Упрощает и делает безопаснее; C-код может освобождать GIL на время тяжёлых вычислений
5. В какой версии Python началась работа по удалению GIL? >> Python 3.13; доступен экспериментально через флаг сборки
6. Как многопоточность влияет на CPU-bound задачи? >> Не ускоряет; из-за накладных расходов на переключение может работать медленнее однопоточного кода
7. Пример библиотеки освобождающей GIL? >> `NumPy` ; тяжёлые операции над массивами выполняются без GIL
8. Сколько потоков могут одновременно выполнять байткод? >> Только один
9. Является ли `while n > 0: n -= 1` CPU-bound или I/O-bound? >> CPU-bound; чистые вычисления без ввода-вывода
10. На каком уровне реализован GIL? >> На уровне интерпретатора как мьютекс
11. Для каких задач многопоточность в Python эффективна? >> Для I/O-bound задач
12. Как часто Python переключает потоки? >> Каждые `5 мс` по умолчанию; настраивается через `sys.setswitchinterval(seconds)`
13. В какой реализации Python используется GIL? >> CPython; в PyPy и Jython реализация отличается
14. Почему потоки Python не работают параллельно на разных ядрах? >> GIL заставляет потоки захватывать блокировку по очереди
15. Что такое Free-threaded Python? >> Сборка CPython без GIL для истинного параллелизма потоков; в Python 3.13 доступна как экспериментальная опция
16. Что происходит с GIL при ожидании I/O? >> Освобождается; другой поток может захватить его и работать
17. Почему при GIL не нужны дополнительные блокировки для reference counting? >> GIL гарантирует что только один поток изменяет счётчики ссылок в каждый момент
18. Что такое GIL? >> Global Interpreter Lock – глобальная блокировка интерпретатора; ограничивает выполнение байткода одним потоком в каждый момент
