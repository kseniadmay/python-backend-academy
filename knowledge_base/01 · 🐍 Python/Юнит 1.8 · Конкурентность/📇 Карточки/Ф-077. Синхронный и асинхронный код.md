1. В чём разница между `asyncio.create_task()` и `asyncio.gather()` ? >> `create_task()` запускает задачу немедленно в фоне; `gather()` запускает несколько и ждёт все результаты
2. Зачем используется асинхронный контекстный менеджер `async with` при работе с клиентами (например, `aiohttp.ClientSession` )? >> Гарантирует закрытие сессии после завершения блока
3. В чём принципиальная разница между асинхронностью ( `asyncio` ) и многопоточностью ( `threading` )? >> Асинхронность использует один поток и кооперативное переключение; `threading` использует несколько потоков с вытесняющим переключением
4. Что произойдёт, если забыть оператор `await` перед вызовом асинхронной функции или `asyncio.gather()` ? >> Вернёт объект корутины не запустив задачи
5. Зачем ставить оператор `*` перед списком задач в `await asyncio.gather(*tasks)` ? >> Распаковка списка в позиционные аргументы
6. Что такое конкурентность? >> Управление несколькими задачами с переключением между ними; не обязательно одновременное выполнение
7. Если 3 запроса по 1 секунде в асинхронном коде – итог? >> Примерно 1 секунда
8. Как запустить асинхронную программу? >> `asyncio.run(main())` ; создаёт event loop, запускает корутину и закрывает loop по завершении
9. Что заменяет `requests` в асинхронном коде? >> `aiohttp`
10. Как запустить несколько корутин конкурентно? >> `asyncio.gather(*tasks)` или `asyncio.create_task()`
11. Сколько потоков в асинхронном выполнении? >> Один
12. Плохо ли использовать `requests.get` внутри `async def` ? >> Да; блокирует весь event loop на время запроса
13. Блокируется ли асинхронная программа при ожидании I/O? >> Нет
14. Какое ключевое слово определяет асинхронную функцию? >> `async def`
15. Что делает `await asyncio.gather(*tasks)` ? >> Запускает все задачи конкурентно и ожидает завершения всех
16. Как выполняется синхронный код? >> Последовательно; каждая операция ждёт завершения предыдущей
17. Если 3 запроса по 1 секунде в синхронном коде – итог? >> 3 секунды
18. Что такое event loop? >> Цикл событий; центральный механизм `asyncio` ; управляет очередью корутин и переключением между ними в точках `await`
19. Является ли асинхронность синонимом параллелизма? >> Нет; это конкурентность в одном потоке, а не параллельное выполнение на разных ядрах
20. Что происходит с управлением в асинхронном коде при ожидании I/O? >> Передаётся другой задаче; текущая задача приостанавливается
21. Что такое корутина в `asyncio` ? >> Функция определённая через `async def` ; может приостанавливаться в точках `await`
22. В каком случае асинхронность теряет преимущество? >> При CPU-bound задачах без I/O; весь поток занят вычислениями
23. Когда асинхронность переключается между задачами? >> Только в точках `await` ; не во время вычислений
24. Что происходит при HTTP-запросе в синхронном режиме? >> Программа блокируется и ждёт ответа; другие операции не выполняются
