## `asyncio.run()` – точка входа

Любая асинхронная программа запускается функцией **`asyncio.run()`**: она создаёт новый event loop, исполняет переданную корутину и корректно закрывает цикл после завершения.

Вызывать её следует один раз на старте приложения из синхронного контекста — обычно внутри `if __name__ == '__main__'`.

## `asyncio.gather()` – конкурентный запуск группы задач

**`asyncio.gather()`** принимает группу корутин и исполняет их конкурентно: пока одна ждёт в `await`, event loop сразу переключается на следующую:

```python
import asyncio

async def worker(name, delay):
    # Уступает управление Event Loop
    await asyncio.sleep(delay)
    return f'{name}: done'

async def main():
    # Конкурентный запуск всех 3 корутин
    results = await asyncio.gather(
        worker('Task-1', 0.03),
        worker('Task-2', 0.01),
        worker('Task-3', 0.02),
    )
    print(results)
    # >>> ['Task-1: done', 'Task-2: done',
    # >>> 'Task-3: done']

asyncio.run(main())
```

Короткие задачи завершаются внутри ожидания самой долгой, а список результатов `gather` возвращает строго в порядке передачи аргументов.

## Реальный сценарий: HTTP-запросы через `aiohttp`

Синхронный `requests` блокирует весь event loop на время сетевого ответа, поэтому для асинхронных HTTP-запросов применяют `aiohttp`:

```python
import asyncio
import aiohttp

async def fetch(session, url):
    # Неблокирующий HTTP-запрос
    async with session.get(url) as response:
        return await response.json()

async def main():
    urls = [
        (
            'https://jsonplaceholder.'
            'typicode.com/posts/1'
        ),
        (
            'https://jsonplaceholder.'
            'typicode.com/posts/2'
        ),
        (
            'https://jsonplaceholder.'
            'typicode.com/posts/3'
        ),
    ]
    async with (
        aiohttp.ClientSession() as session
    ):
        tasks = [
            fetch(session, url)
            for url in urls
        ]

        # Выполняем все запросы одновременно
        await asyncio.gather(*tasks)

asyncio.run(main())
```

Объект `aiohttp.ClientSession` держит общий пул соединений — создавайте одну сессию на всё приложение вместо новой под каждый запрос.

На строках `async with session.get` и `await response.json()` цикл событий переключается на другие запросы.

## `asyncio.create_task()` – немедленный запуск в фоне

Когда задачи нужно запускать динамически в фоне без немедленного ожидания на месте, корутину оборачивают в `Task` через `asyncio.create_task()`:

```python
import asyncio

async def worker(name, delay):
    await asyncio.sleep(delay)
    return f'{name}: done'

async def main():
    # Старт задачи в фоне немедленно
    task = asyncio.create_task(
        worker('background', 0.02)
    )
    await asyncio.sleep(0.01)

    # Дожидаемся результата задачи
    res = await task
    print(res)
    # >>> background: done

asyncio.run(main())
```

При прямом `await coro()` корутина останавливает текущий код до завершения, а `create_task()` сразу ставит задачу в очередь планировщика.

## Ограничения, ошибки и схема выбора инструмента

`asyncio` ускоряет только **I/O-bound** операции: тяжёлые вычисления и синхронные вызовы (`time.sleep`, `requests.get`) намертво замораживают event loop (для легаси-кода используйте `asyncio.to_thread()`).

Сводка выбора инструмента по характеру нагрузки:

| Сценарий нагрузки | Инструмент | Почему |
| :--- | :--- | :--- |
| Последовательный шаг I/O | `await` напрямую | Простой линейный поток выполнения |
| Фиксированный список I/O-задач | `asyncio.gather()` | Запуск пачкой, сохранение порядка |
| Фоновые / динамические задачи | `asyncio.create_task()` | Старт в фоне с ручным `await task` |
| Вычисления на CPU (CPU-bound) | `multiprocessing` | Настоящий параллелизм без GIL |

> **Junior vs Senior**:
> - **Junior**: вызывает `await fetch(url)` последовательно внутри цикла `for`, теряя конкурентность, и запускает `create_task()` без сохранения ссылки на задачу.
> - **Senior**: объединяет независимый I/O через `asyncio.gather()` или фоновые `create_task()` с удержанием ссылок и никогда не вызывает блокирующие `time.sleep` и `requests` в потоке event loop.
