## `asyncio.run()` – точка входа

Любая асинхронная программа запускается через **`asyncio.run()`**. Эта функция создаёт новый event loop, запускает переданную корутину, дожидается её завершения и закрывает loop. Вызывать её нужно один раз – из синхронного контекста, обычно в `if __name__ == '__main__'`.

---

## `asyncio.gather()` – конкурентный запуск группы задач

**`asyncio.gather()`** принимает несколько корутин и запускает их конкурентно. Event loop переключается между ними в точках `await`, не теряя времени на ожидание:

```python
import asyncio

async def worker(name, delay):
    print(f'[{name}] started')
    await asyncio.sleep(delay)
    print(f'[{name}] done in {delay}s')
    return f'{name}: done'

async def main():
    results = await asyncio.gather(
        worker('Task-1', 3),
        worker('Task-2', 1),
        worker('Task-3', 2),
    )
    print(results)  # ['Task-1: done', 'Task-2: done', 'Task-3: done']

asyncio.run(main())
```

Задачи на 1 и 2 секунды завершаются «внутри» ожидания самой долгой. `gather` возвращает результаты в том порядке, в котором были переданы корутины – независимо от порядка их завершения.

## Реальный сценарий: HTTP-запросы через `aiohttp`

Синхронная библиотека `requests` блокирует event loop при каждом запросе. Для асинхронной работы используют `aiohttp`:

```python
import asyncio
import aiohttp

async def fetch(session, url):
    async with session.get(url) as response:
        data = await response.json()
        print(f'Got response from {url}')
        return data

async def main():
    urls = [
        'https://jsonplaceholder.typicode.com/posts/1',
        'https://jsonplaceholder.typicode.com/posts/2',
        'https://jsonplaceholder.typicode.com/posts/3',
    ]
    async with aiohttp.ClientSession() as session:
        tasks = [fetch(session, url) for url in urls]
        await asyncio.gather(*tasks)

asyncio.run(main())
```

`aiohttp.ClientSession` – это пул соединений. Создавать новую сессию под каждый запрос не нужно – это дорого. Одна сессия на всё время работы программы – правильный подход.

`async with session.get(url)` инициирует запрос. `await response.json()` – точка приостановки: пока сервер отвечает и данные идут по сети, event loop переключается на следующий запрос. JSON собирается по мере готовности.

## `asyncio.create_task()` – немедленный запуск в фоне

`asyncio.gather` удобен, когда известен весь список задач заранее. **`asyncio.create_task()`** позволяет поставить корутину в очередь выполнения немедленно, не дожидаясь явного `await`:

```python
async def main():
    task = asyncio.create_task(worker('background', 2))
    await asyncio.sleep(1)
    await task  # дождаться завершения
```

`create_task` оборачивает корутину в объект `Task` и ставит её в event loop немедленно. Это отличие от простого `await`: при `await coroutine()` вы приостанавливаетесь до завершения именно этой корутины. При `create_task` корутина начинает выполняться параллельно с текущим кодом.

## Ограничения и типичные ошибки

`asyncio` работает только для **I/O-bound задач**. Для тяжёлых вычислений он бесполезен: CPU будет занят, event loop не сможет переключиться, и вся конкурентность рухнет.

Никогда не вызывайте блокирующие операции внутри async-функций: `time.sleep()` вместо `asyncio.sleep()`, `requests.get()` вместо `aiohttp`, любые синхронные файловые операции без специальных оберток. Каждый такой вызов замораживает весь event loop и всю конкурентность вместе с ним.

Если нужно вызвать блокирующую функцию в async-контексте – используйте `asyncio.run_in_executor()`, который запускает её в отдельном потоке, не блокируя event loop.

---

## Схема выбора инструмента

I/O-bound с небольшим числом задач – `await` напрямую.

I/O-bound с заранее известным списком задач – `asyncio.gather()`.

I/O-bound с динамически добавляемыми задачами или фоновыми процессами – `asyncio.create_task()`.

CPU-bound – `multiprocessing` вне зависимости от контекста.
