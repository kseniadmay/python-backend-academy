## Проблема: CPU простаивает во время I/O

С точки зрения процессора, ожидание сетевого ответа длится вечность. Синхронный код усугубляет простой: следующий запрос не стартует, пока не завершится предыдущий:

```python
import requests

def fetch_all(urls):
    results = []
    for url in urls:
        # Поток заблокирован до ответа
        r = requests.get(url)
        results.append(r.json())
    return results
```

Три запроса по одной секунде выполнятся за три секунды подряд, пока процессор просто ждёт.

## Асинхронный подход: переключение вместо блокировки

Асинхронность позволяет не простаивать на ожидании: пока первый запрос ждёт ответа сервера, стартуют второй и третий.

Обычный `requests` блокирует поток целиком, поэтому в асинхронных сервисах применяют **`aiohttp`**:

```python
import asyncio
import aiohttp

async def fetch(session, url):
    async with session.get(url) as response:
        return await response.json()

async def fetch_all(urls):
    async with (
        aiohttp.ClientSession() as session
    ):
        tasks = [
            fetch(session, url)
            for url in urls
        ]

        # Запускаем запросы конкурентно
        return await asyncio.gather(*tasks)
```

Через `asyncio.gather` три односекундных запроса завершатся примерно за одну секунду — общее время задаёт самый долгий ответ, а не сумма всех.

## Как это работает: event loop и `await`

`asyncio` работает в одном потоке под управлением цикла событий (**event loop**), который распределяет время между корутинами.

Встречая `await`, корутина приостанавливается и уступает управление другим задачам, а при готовности ответа от ОС возвращается на место остановки.

Если внутри `async def` вообще нет `await`, функция выполнится целиком, не отдавая управление другим задачам.

---

## Конкурентность – это не параллелизм

**Параллелизм** — одновременное выполнение нескольких потоков или процессов буквально в одну микросекунду на разных ядрах CPU. **Конкурентность** — эффективное чередование множества задач внутри одного потока.

`asyncio` обеспечивает конкурентность без параллелизма: один event loop обслуживает тысячи соединений во время I/O-ожидания без расходов на создание потоков.

## Выбор инструмента и практические сценарии

Сводка выбора между `asyncio`, `threading` и `multiprocessing`:

| Инструмент | Оптимальный сценарий | Ограничение |
| :--- | :--- | :--- |
| **`asyncio`** | Тысячи I/O-операций: API, боты, скрейперы | Требует async-драйверы и неблокирующий код |
| **`threading`** | Интеграция старых блокирующих библиотек | Не даёт прироста CPU-коду из-за GIL |
| **`multiprocessing`** | Тяжёлая математика, ML, обработка медиа | Высокий расход RAM на копии процессов |

В веб-скрейперах, API-агрегаторах и чат-ботах асинхронный подход удерживает задержки почти постоянными вне зависимости от роста числа конкурентных запросов.
