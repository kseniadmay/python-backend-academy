## Проблема: CPU простаивает во время I/O

С точки зрения процессора, выполняющего миллиарды операций в секунду, ожидание ответа от сетевого сервера длится вечность. В это время CPU не делает ничего полезного. Синхронный код усугубляет проблему: следующая строка не выполнится, пока не завершится предыдущая.

```python
import requests

def fetch_all(urls):
    results = []
    for url in urls:
        r = requests.get(url)  # поток заблокирован до получения ответа
        results.append(r.json())
    return results
```

Три запроса по одной секунде каждый – итого три секунды. Время суммируется. Чем больше запросов – тем медленнее. При этом между запросами CPU просто ждёт.

## Асинхронный подход: переключение вместо блокировки

**Асинхронность** позволяет программе не блокироваться во время ожидания, а переключаться на другую задачу. Пока первый запрос ждёт ответа от сервера, начинается второй. Когда второй ждёт – начинается третий.

Стандартная библиотека `requests` не умеет работать асинхронно – она всегда блокирует поток. Для асинхронных HTTP-запросов используют **`aiohttp`**.

```python
import asyncio
import aiohttp

async def fetch(session, url):
    async with session.get(url) as response:
        return await response.json()

async def fetch_all(urls):
    async with aiohttp.ClientSession() as session:
        tasks = [fetch(session, url) for url in urls]
        return await asyncio.gather(*tasks)
```

`asyncio.gather` запускает все задачи «одновременно» и ждёт завершения последней. Три запроса по одной секунде завершатся примерно за одну секунду – время определяется самым долгим запросом, а не их суммой.

## Как это работает: event loop и `await`

`asyncio` работает в одном потоке. Внутри него есть **event loop** – цикл событий, который управляет переключением между задачами.

Когда корутина встречает `await` – она приостанавливается и передаёт управление event loop. Тот проверяет, какие другие задачи готовы продолжить выполнение, и передаёт управление им. Когда ожидаемая операция завершается – первая корутина возобновляется.

`async def` объявляет функцию как корутину. Вызов `await` означает: «приостановись здесь и дай другим задачам поработать». Без `await` корутина выполняется синхронно внутри event loop.

## Конкурентность – это не параллелизм

Это важное различие, которое часто путают. **Параллелизм** – это физическое одновременное выполнение на нескольких ядрах: несколько потоков или процессов работают буквально в одну микросекунду. **Конкурентность** – это грамотное управление множеством задач в одном потоке: задачи не выполняются одновременно, но быстро чередуются.

`asyncio` – это конкурентность без параллелизма. Один event loop, один поток, тысячи одновременных соединений. Это работает именно потому, что во время I/O-ожидания CPU свободен – переключение между задачами дешевле создания отдельных потоков.

---

## Когда asyncio, а когда threading или multiprocessing

`asyncio` оптимален для **I/O-bound задач с большим числом одновременных операций**: HTTP-запросы, работа с базой данных через async-драйверы, WebSocket-соединения. Один асинхронный поток способен обслуживать тысячи соединений – это его главное преимущество перед `threading`.

`threading` имеет смысл, когда нужно интегрировать синхронный блокирующий код в асинхронную среду или работать с библиотеками без async-поддержки.

`multiprocessing` остаётся единственным вариантом для **CPU-bound задач**: `asyncio` не обходит GIL и не ускоряет вычисления – он только устраняет простои при ожидании.

---

## Практические сценарии

`asyncio` критически важен в высоконагруженных системах: чат-боты с тысячами одновременных пользователей, веб-скрейперы, собирающие данные с сотен источников, API-агрегаторы, делающие параллельные запросы к внешним сервисам. В таких системах синхронный код создаёт линейно растущие задержки, а асинхронный держит их почти постоянными вне зависимости от числа параллельных задач.
