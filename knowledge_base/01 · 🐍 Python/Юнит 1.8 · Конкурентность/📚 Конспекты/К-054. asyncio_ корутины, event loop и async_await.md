## От генераторов к async/await: как устроены корутины

Исторически асинхронность в Python выросла из генераторов: конструкция `yield` и метод `.send()` позволяли приостанавливать функцию и передавать в неё данные извне. В стандарте PEP 492 появились нативные корутины с синтаксисом **`async def`** и **`await`**.

Вызов async-функции без `await` не начинает выполнение её тела: интерпретатор лишь конструирует объект корутины. Если забыть передать его в `await` или `asyncio.create_task()`, то при сборке мусора CPython выведет предупреждение `RuntimeWarning: coroutine was never awaited`.

---

## async def: функция, которая возвращает объект, а не результат

Обычная функция при вызове немедленно начинает выполнение. Функция с **`async def`** ведёт себя иначе: вызов **не выполняет** её тело сразу – вместо этого создаётся объект-корутина, «замороженная» задача с инструкциями, но не запущенная.

```python
import inspect

async def greet():
    return 'hello'

# Вызов async-функции возвращает объект
# корутины, а не строку 'hello'
coro = greet()
print(
    'Объект корутины:',
    inspect.iscoroutine(coro),
)
# >>> Объект корутины: True
coro.close()
```

Чтобы корутина реально выполнилась, её нужно передать в event loop – через `await` или `asyncio.run()`.

## await: точка добровольной передачи управления

**`await`** – не просто «подожди». Это инструкция корутине: «здесь я завишу от внешней операции, и нет смысла удерживать управление».

При встрече с `await` происходит три вещи: текущая корутина приостанавливается (все локальные переменные сохраняются), управление возвращается в event loop, и event loop запускает другие готовые задачи, пока ожидается результат.

```python
import asyncio

async def fetch():
    # приостановиться, отдать управление
    await asyncio.sleep(0.01)
    return 'done'
```

`await` можно использовать только внутри `async def` – попытка использовать его в обычной функции даёт `SyntaxError`.

## Event loop – диспетчер корутин

**Event loop** – центральный механизм `asyncio`, работающий в одном потоке и управляющий всеми корутинами и задачами (Task): решает, какую запустить, какую приостановить, какую возобновить.

Алгоритм работы планировщика:
1. Event loop выбирает готовую к выполнению задачу из очереди `_ready` и запускает её;
2. Когда корутина достигает `await`, она приостанавливается и регистрирует дескриптор сокета в ОС (через `epoll`/`kqueue`/`IOCP`);
3. Event loop немедленно переключается на следующую готовую задачу;
4. Когда операция завершается, ОС будит event loop, и задача возвращается в очередь на возобновление.

## Task – единица планирования event loop'а

`asyncio.gather` (и другие способы запуска конкурентно) оборачивает каждую корутину в объект **`Task`** – именно задачи, а не корутины напрямую, регистрируются в очереди event loop'а.

`asyncio.create_task(coro)` планирует немедленный запуск корутины в фоне, не блокируя текущую строку. Если для созданного `Task` не был вызван `await` до завершения программы, интерпретатор при закрытии loop выведет предупреждение: `Task was destroyed but it is pending`.

```python
import asyncio

async def background_logger():
    await asyncio.sleep(0.01)
    return 'log_saved'

async def main():
    # задача регистрируется в event loop
    # немедленно
    task = asyncio.create_task(
        background_logger()
    )
    result = await task
    print('Фоновая задача завершена:', result)
    # >>> Фоновая задача завершена: log_saved

asyncio.run(main())
```

## Антипаттерн блокировок: Event Loop Starvation и режим отладки

Если корутина выполняет синхронную блокирующую операцию (`time.sleep()`, вызов `requests.get()`, криптографический хэш большого файла), выполнение не возвращается в event loop. Наступает **голодание цикла событий (Event Loop Starvation)**: все остальные параллельные клиентские запросы сервиса (FastAPI / aiohttp) зависают в очереди.

Для обнаружения таких «скрытых» блокировок в Python предусмотрен режим отладки `PYTHONASYNCIODEBUG=1` (или `loop.set_debug(True)`), который протоколирует предупреждения, если обработчик удерживает управление дольше порога `slow_callback_duration` (по умолчанию 100 мс):

```python
import asyncio

async def worker(
    name: str,
    delay: float,
) -> str:
    # ПРАВИЛЬНО: неблокирующий await
    # asyncio.sleep вместо блокирующего
    # time.sleep
    await asyncio.sleep(delay)
    return f'{name}: ok'

async def main():
    res = await worker('async_task', 0.01)
    print(
        'Кооперативная корутина выполнена '
        'без блокировок:',
        res,
    )
    # >>> Кооперативная корутина выполнена без блокировок: async_task: ok

asyncio.run(main())
```

## asyncio.gather – конкурентный запуск группы корутин

`asyncio.gather(*coros)` запускает переданные корутины конкурентно: общее время ожидания равно времени самой медленной операции, а не их сумме.

По умолчанию при ошибке в одной корутине `gather` сразу пробрасывает исключение наружу. Флаг `return_exceptions=True` позволяет собрать все результаты и ошибки в единый список:

```python
import asyncio

async def fetch_success():
    await asyncio.sleep(0.01)
    return 'data_ok'

async def fetch_fail():
    await asyncio.sleep(0.01)
    raise ValueError('Service Unavailable')

async def main():
    results = await asyncio.gather(
        fetch_success(),
        fetch_fail(),
        # Ошибки возвращаются в списке
        # (без падения)
        return_exceptions=True,
    )
    print(
        'Собрано результатов:',
        len(results),
        '| Тип ошибки:',
        type(results[1]).__name__,
    )
    # >>> Собрано результатов: 2 | Тип ошибки: ValueError

asyncio.run(main())
```

## asyncio.run – точка входа

**`asyncio.run(main())`** – стандартный способ запустить асинхронный код из синхронного контекста: создаёт новый event loop, запускает переданную корутину, ждёт её завершения и корректно закрывает loop.

Вызывать `asyncio.run()` следует ровно один раз на всё приложение как верхнеуровневую точку входа. Попытка вызвать `asyncio.run()` внутри уже запущенного цикла событий приведёт к ошибке `RuntimeError: This event loop is already running`.

## Передача управления на один тик: трюк с asyncio.sleep(0)

Вызов `await asyncio.sleep(0)` не приостанавливает выполнение по времени, но немедленно возвращает управление в event loop на один квант («тик»).

Это даёт планировщику возможность запустить другие ожидающие задачи из очереди. Трюк применяется в циклах пакетной обработки данных, чтобы длительные вычисления не вызывали голодание (`starvation`) сетевых обработчиков:

```python
import asyncio

async def cooperative_computation(items):
    total = 0
    for idx, x in enumerate(items):
        total += x
        if idx % 100 == 0:
            # Уступаем управление другим
            # корутинам на 1 тик
            await asyncio.sleep(0)
    return total

print(
    'Сумма 1000 элементов с уступкой '
    'управления:',
    asyncio.run(
        cooperative_computation(range(1000)),
    ),
)
# >>> Сумма 1000 элементов с уступкой управления: 499500
```

## Интеграция синхронного кода: asyncio.to_thread

Если проект использует синхронную библиотеку без асинхронного аналога или выполняет дисковый I/O, блокирующий вызов нельзя выполнять прямо в корутине.

Начиная с Python 3.9, стандартный инструмент для изоляции блокирующего кода — **`asyncio.to_thread()`**:

```python
import asyncio
import time

def blocking_io_task(name: str) -> str:
    # Имитация блокирующего чтения файла или
    # легаси-библиотеки
    time.sleep(0.02)
    return f'{name}: ready'

async def main():
    # Вызов выполняется в отдельном системном
    # потоке ThreadPoolExecutor
    res = await asyncio.to_thread(
        blocking_io_task,
        'legacy_report',
    )
    print(
        'Синхронный вызов выполнен '
        'безопасно:',
        res,
    )
    # >>> Синхронный вызов выполнен безопасно: legacy_report: ready

asyncio.run(main())
```

## Контроль таймаутов: asyncio.wait_for и обработка TimeoutError

В бэкенд-разработке любой внешний сетевой вызов обязан иметь верхнюю границу времени ожидания (Deadline), чтобы зависшие соединения не исчерпали пул задач сервера.

Для этого используется **`asyncio.wait_for(coro, timeout=секунды)`**:

```python
import asyncio

async def slow_request(delay: float) -> str:
    await asyncio.sleep(delay)
    return 'ok'

async def main():
    # Прерываем долгий запрос по таймауту
    try:
        await asyncio.wait_for(
            slow_request(0.5),
            timeout=0.05,
        )
    except asyncio.TimeoutError:
        print('Таймаут 0.05с сработал!')
        # >>> Таймаут 0.05с сработал!

asyncio.run(main())
```
