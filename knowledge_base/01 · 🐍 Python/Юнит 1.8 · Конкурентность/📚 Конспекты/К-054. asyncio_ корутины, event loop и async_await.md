## Корутины `async def` и `inspect.iscoroutine`

Исторически корутины выросли из генераторов (`yield`/`.send()`), а в PEP 492 получили синтаксис `async def` и `await`.

Вызов `async def` не выполняет тело сразу, а создаёт замороженный объект-корутину. (Если забыть `await` или `create_task()`, при сборке мусора возникнет `RuntimeWarning`.)

Пример проверки возвращаемого объекта корутины через `inspect`:

```python
import inspect

async def greet():
    return 'hello'

# Вызов возвращает объект корутины
coro = greet()
print(
    'Объект корутины:',
    inspect.iscoroutine(coro),
)
# >>> Объект корутины: True

coro.close()
```

## `await` и точка входа `asyncio.run()`

Инструкция **`await`** (разрешённая только внутри `async def`) замораживает текущую корутину и передаёт управление циклу событий до готовности результата.

Для запуска верхнеуровневой корутины вызывают **`asyncio.run(main())`** один раз (вызов внутри работающего цикла даст `RuntimeError`):

```python
import asyncio

async def fetch():
    await asyncio.sleep(0.01)
    return 'done'

async def main():
    res = await fetch()
    print(res)
    # >>> done

asyncio.run(main())
```

## Event loop – диспетчер корутин

**Event loop** работает в одном потоке и управляет очередями готовых и ожидающих задач по четырём шагам:

1. Забирает готовую задачу из очереди `_ready` и запускает её.
2. На строке `await` приостанавливает корутину и регистрирует сокет/таймер в ОС (`epoll` / `kqueue` / `IOCP`).
3. Немедленно переключается на следующую готовую задачу.
4. Когда ОС сообщает о готовности I/O, будит цикл и возвращает задачу в очередь.

## `Task` – единица планирования event loop'а

В очереди цикла событий регистрируются не сырые корутины, а обёртки **`Task`**. Если не вызвать `await` на созданном `Task` до закрытия программы, появится предупреждение `Task was destroyed but it is pending`.

Функция **`asyncio.create_task(coro)`** планирует фоновый запуск корутины немедленно:

```python
import asyncio

async def background_logger():
    await asyncio.sleep(0.01)
    return 'log_saved'

async def main():
    # Регистрация в event loop сразу
    task = asyncio.create_task(
        background_logger()
    )
    result = await task
    print('Фоновая задача:', result)
    # >>> Фоновая задача: log_saved

asyncio.run(main())
```

## Event Loop Starvation и уступка тика `asyncio.sleep(0)`

Если корутина вызывает блокирующую операцию (`time.sleep()`, `requests.get()`, тяжёлый расчёт), возникает **Event Loop Starvation** — все остальные запросы замирают.

Найти скрытые блокировки помогает режим отладки `PYTHONASYNCIODEBUG=1` (`loop.set_debug(True)`), логирующий колбэки дольше `slow_callback_duration` (100 мс).

В длинных вычислительных циклах отдать управление другим корутинам на один тик помогает `await asyncio.sleep(0)`:

```python
import asyncio

async def cooperative_sum(items):
    total = 0
    for idx, x in enumerate(items):
        total += x
        if idx % 100 == 0:
            # Уступаем другим задачам на 1 тик
            await asyncio.sleep(0)
    return total

coro = cooperative_sum(range(1000))
ans = asyncio.run(coro)
print('Сумма с уступкой тика:', ans)
# >>> Сумма с уступкой тика: 499500
```

## `asyncio.gather` и обработка ошибок `return_exceptions=True`

`asyncio.gather(*coros)` запускает корутины конкурентно и по умолчанию сразу пробрасывает первую ошибку наружу.

Флаг `return_exceptions=True` позволяет вернуть исключения прямо в списке результатов:

```python
import asyncio

async def fetch_success():
    await asyncio.sleep(0.01)
    return 'data_ok'

async def fetch_fail():
    await asyncio.sleep(0.01)
    raise ValueError('Service Unavailable')

async def main():
    results = await asyncio.gather(
        fetch_success(),
        fetch_fail(),
        return_exceptions=True,
    )
    err = type(results[1]).__name__
    print('Всего:', len(results))
    print('Ошибка:', err)
    # >>> Всего: 2
    # >>> Ошибка: ValueError

asyncio.run(main())
```

## Изоляция блокировок (`to_thread`) и дедлайны (`wait_for`)

Чтобы синхронный дисковый I/O или легаси-библиотека не блокировали цикл, в Python 3.9+ её выносят в поток через **`asyncio.to_thread()`**:

```python
import asyncio
import time

def blocking_io_task(name: str) -> str:
    time.sleep(0.02)
    return f'{name}: ready'

async def main():
    res = await asyncio.to_thread(
        blocking_io_task,
        'legacy_report',
    )
    print('В отдельном потоке:', res)
    # >>> В отдельном потоке: legacy_report: ready

asyncio.run(main())
```

Любой внешний сетевой вызов защищают ограничением времени ожидания (**Deadline**) через `asyncio.wait_for(coro, timeout=...)`:

```python
import asyncio

async def slow_request(delay: float) -> str:
    await asyncio.sleep(delay)
    return 'ok'

async def main():
    try:
        await asyncio.wait_for(
            slow_request(0.5),
            timeout=0.05,
        )
    except asyncio.TimeoutError:
        print('Таймаут 0.05с сработал!')
        # >>> Таймаут 0.05с сработал!

asyncio.run(main())
```
