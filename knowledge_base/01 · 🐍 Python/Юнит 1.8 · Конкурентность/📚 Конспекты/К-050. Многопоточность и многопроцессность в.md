## Поток vs процесс: в чём разница

**Процесс** – это изолированная единица выполнения со своим адресным пространством в памяти. Каждый процесс живёт независимо: у него своя копия интерпретатора, своя память, свои ресурсы.

**Поток** (thread) – это единица выполнения внутри процесса. Все потоки одного процесса разделяют общую память. Это делает их лёгкими: создание потока дешевле создания процесса, а обмен данными между потоками не требует сериализации – они просто читают одни и те же объекты.

## GIL – главное ограничение CPython

В стандартном интерпретаторе Python (CPython) существует **GIL** – Global Interpreter Lock, глобальная блокировка интерпретатора. GIL гарантирует, что в каждый момент времени только один поток выполняет Python-байткод, даже если процессор многоядерный.

Это означает, что многопоточность в Python не даёт настоящего параллелизма для CPU-нагрузки. Потоки не выполняются одновременно – они быстро чередуются, создавая иллюзию параллельности.

Почему GIL существует: он защищает внутренние структуры CPython (подсчёт ссылок, управление памятью) от гонок данных. Без GIL потребовалась бы тонкая блокировка на уровне каждого объекта, что сильно усложнило бы интерпретатор.

Важно: GIL – это деталь реализации CPython. В PyPy, Jython и других реализациях Python ситуация может быть другой. В Python 3.13 ведётся работа по удалению GIL (экспериментальная сборка без GIL уже доступна).

## Когда threading всё же полезен

GIL снимается во время операций ввода-вывода: чтение файла, сетевой запрос, ожидание базы данных. Пока один поток ждёт ответа от сервера, GIL освобождается, и другой поток может работать.

Поэтому `threading` эффективен для **I/O-bound задач** – там, где программа большую часть времени ждёт, а не считает.

```python
import threading

def fetch_data():
    pass

t = threading.Thread(target=fetch_data)
t.start()
t.join()  # ожидаем завершения потока
```

Для I/O-bound задач в современном Python чаще используют **`asyncio`** – он эффективнее threading при большом количестве одновременных соединений, потому что не создаёт отдельные потоки под каждую задачу.

## Multiprocessing – настоящий параллелизм

Чтобы задействовать несколько ядер процессора, используют модуль **`multiprocessing`**. Каждый процесс получает собственный интерпретатор со своим GIL и независимой памятью. Это даёт настоящий параллелизм на уровне CPU.

```python
import multiprocessing

def heavy_computation():
    pass

p = multiprocessing.Process(target=heavy_computation)
p.start()
p.join()
```

За это приходится платить. Создание процесса – тяжёлая операция: Python запускает новый интерпретатор и копирует адресное пространство. Обмен данными между процессами требует сериализации через очереди (`multiprocessing.Queue`), каналы (`Pipe`) или разделяемую память (`shared memory`).

## Как выбрать инструмент

Выбор определяется типом нагрузки, а не предпочтениями.

**I/O-bound** – задача тратит время на ожидание: сетевые запросы, работа с файлами, базы данных. Используйте `threading` или `asyncio`. GIL не мешает, потому что он снимается во время ожидания.

**CPU-bound** – задача нагружает процессор: математические вычисления, обработка изображений, парсинг больших объёмов данных. Используйте `multiprocessing`. Только так можно задействовать несколько ядер и обойти GIL.

В реальных системах подходы комбинируют: например, `multiprocessing` для параллельных вычислений и `asyncio` внутри каждого процесса для обработки множества соединений.

## `concurrent.futures` – удобная обёртка

Для большинства практических задач удобнее использовать высокоуровневый интерфейс из стандартной библиотеки:

```python
from concurrent.futures import ThreadPoolExecutor, ProcessPoolExecutor

with ThreadPoolExecutor(max_workers=4) as executor:
    results = list(executor.map(fetch_data, urls))

with ProcessPoolExecutor(max_workers=4) as executor:
    results = list(executor.map(heavy_computation, data_chunks))
```

`concurrent.futures` скрывает управление потоками и процессами, автоматически управляет пулом и возвращает результаты через `Future`-объекты. На собеседовании это хороший признак зрелости: знать не только `threading.Thread`, но и удобные абстракции над ним.
