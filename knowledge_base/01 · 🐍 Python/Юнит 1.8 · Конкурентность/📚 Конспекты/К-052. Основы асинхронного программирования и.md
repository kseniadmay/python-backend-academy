## Кооперативная модель: `async def` и передача управления `await`

В асинхронной модели задачи добровольно уступают процессор в точках ожидания.

Функция `async def` возвращает корутину, а **`await`** приостанавливает её и отдаёт управление диспетчеру до готовности операции:

```python
import asyncio

async def fetch(name: str) -> str:
    # Приостановка и передача управления циклу
    await asyncio.sleep(0.01)
    return f'{name}: done'
```

При достижении `await` все локальные переменные корутины сохраняются, и выполнение переходит к другим готовым задачам. Использовать `await` внутри обычной функции нельзя (`SyntaxError`).

## Event Loop: диспетчер корутин

**Event loop** (цикл событий) работает в одном потоке и управляет очередью корутин: выбирает готовую задачу, запускает до ближайшего `await` и переводит в список ожидания.

Как только ОС сигнализирует, что сетевой сокет ответил или таймер сработал, цикл возвращает корутину в очередь готовых ровно с той строки, где она остановилась.

## Критическая ошибка: блокирующий вызов в async-коде

Обычная блокирующая операция (`time.sleep()`, синхронный HTTP-запрос, тяжёлый расчёт без `await`) замораживает весь event loop:

```python
async def bad():
    # Весь event loop стоит 1 секунду!
    time.sleep(1)

async def good():
    # Другие задачи работают во время ожидания
    await asyncio.sleep(0.01)
```

Главное правило асинхронного сервиса: внутри корутин используйте только неблокирующие async-совместимые библиотеки и операции.

## `asyncio.gather`: конкурентный запуск корутин

**`asyncio.gather`** запускает несколько корутин конкурентно и возвращает результаты в порядке передачи аргументов:

```python
import asyncio

async def task(name, delay):
    await asyncio.sleep(delay)
    return name

async def main():
    results = await asyncio.gather(
        task('A', 0.02),
        task('B', 0.01),
        task('C', 0.03),
    )
    print(results)
    # >>> ['A', 'B', 'C']

asyncio.run(main())
```

Задачи завершаются в разном порядке (`B`, затем `A`, затем `C`), но общее время выполнения равно лишь длительности самой долгой задачи вместо их суммы.

## `asyncio.run`: точка входа

Стандартный способ запустить верхнеуровневую корутину из синхронного кода (появился в Python 3.7 вместо ручного `get_event_loop()`):

```python
import asyncio

async def main():
    await asyncio.sleep(0.01)
    print('Цикл выполнен')
    # >>> Цикл выполнен

if __name__ == '__main__':
    asyncio.run(main())
```

`asyncio.run(main())` сам создаёт новый event loop, запускает `main()`, ждёт результата и чисто закрывает цикл.

## Таймауты, отмена задач (`CancelledError`) и подход Junior vs Senior

Любой внешний сетевой вызов без ограничения времени может зависнуть навсегда, забив память открытыми задачами. В `asyncio` запросы защищают таймаутом через **`asyncio.timeout()`** (Python 3.11+) или **`asyncio.wait_for(coro, timeout=2.0)`** — при превышении лимита задача отменяется и выбрасывается `TimeoutError`.

Когда задачу отменяют методом `task.cancel()`, внутри неё в точке `await` возбуждается исключение **`asyncio.CancelledError`**. С Python 3.8 оно наследуется от `BaseException` (а не от `Exception`), чтобы случайный `except Exception:` не сломал остановку задачи.

```python
import asyncio

async def slow_api():
    await asyncio.sleep(5)
    return 'ok'

async def main():
    try:
        # Ограничиваем ожидание 0.01 сек
        await asyncio.wait_for(
            slow_api(),
            timeout=0.01,
        )
    except TimeoutError:
        print('Таймаут запроса!')
        # >>> Таймаут запроса!

asyncio.run(main())
```

> **Junior vs Senior**:
> - **Junior**: Запускает `await client.get(url)` без таймаутов, перехватывает `except BaseException:` (проглатывая `CancelledError` и зависая при выключении сервера) или забывает сохранить ссылку на `create_task()`.
> - **Senior**: Оборачивает внешние вызовы в `asyncio.timeout()` / `wait_for()`, при перехвате `CancelledError` освобождает ресурсы и делает повторный `raise`, а группы задач контролирует через `asyncio.TaskGroup`.
