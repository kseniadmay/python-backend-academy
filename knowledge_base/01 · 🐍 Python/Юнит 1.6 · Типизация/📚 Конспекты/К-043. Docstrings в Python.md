## Что такое docstring и как он работает

Docstring – это строковый литерал в тройных кавычках `"""`, который стоит первым в теле модуля, класса или функции. В отличие от комментария с `#`, Python не игнорирует docstring при выполнении – он компилируется и сохраняется в атрибуте `__doc__` объекта.

```python
def process_payment():
    """Обрабатывает входящий платёж."""
    pass

print(process_payment.__doc__)

help(process_payment)  # то же самое, но с форматированием
```

Это делает код самодокументированным: описание функции доступно программно прямо во время выполнения. На этом же механизме работают генераторы документации – Sphinx, mkdocs и другие: они сканируют проект и собирают `__doc__` со всех объектов в единый сайт.

Согласно PEP 257, тройные двойные кавычки `"""` – стандарт для docstrings. Одинарные `'''` тоже работают, но так не принято.

## Три стиля оформления

Содержимое `__doc__` – это просто строка, Python не диктует её формат. Но сообщество договорилось о трёх стандартах. На собеседованиях могут спросить, какой стиль ты используешь и почему – важно понимать разницу.

**Google Style** – самый распространённый в коммерческой веб-разработке. Читается легко даже в сыром виде, без рендеринга. Секции обозначаются словами с отступами.

```python
def process_payment(order_id: int, amount: float, currency: str = 'RUB') -> dict:
    """Обрабатывает платёж для заказа.

    Args:
        order_id: Уникальный идентификатор заказа.
        amount: Сумма платежа.
        currency: Код валюты (по умолчанию 'RUB').

    Returns:
        Словарь со статусом и ID транзакции.
    """
    pass
```

**NumPy Style** – стандарт для data science и научных библиотек. Более многословный и формализованный, секции разделяются линией из дефисов. Если пишешь ML-код – увидишь его повсюду.

```python
def calculate_discount(price: float, discount_percent: float) -> float:
    """
    Вычисляет цену со скидкой.

    Parameters
    ----------
    price : float
        Исходная цена товара.
    discount_percent : float
        Размер скидки в процентах (0-100).

    Returns
    -------
    float
        Итоговая цена после применения скидки.
    """
    pass
```

**Sphinx Style** – классика для крупных библиотек и корпоративных проектов. Использует синтаксис reStructuredText с префиксами `:param:` и `:return:`. Выглядит более тяжеловесно, но именно этот формат лежит в основе документации Django и многих системных библиотек.

```python
def find_user(user_id: int, include_deleted: bool = False):
    """Находит пользователя по идентификатору.

    :param user_id: ID пользователя в базе данных.
    :param include_deleted: Включать ли удалённых пользователей.
    :return: Объект пользователя или None.
    """
    pass
```

Практическое правило: для веб-разработки и большинства коммерческих проектов – Google Style. Для data science и ML – NumPy Style.

## Документирование модулей и классов

Docstring модуля – это первое, что видит разработчик, открывая файл. Он стоит в самом начале, до всех импортов.

```python
"""
Модуль для работы с платежами.

Предоставляет интеграцию со Stripe и YooKassa.
Поддерживает разовые платежи, подписки и возвраты.

Example:
    from payments import PaymentService
    service = PaymentService(provider='stripe')
    result = service.charge(order_id=42, amount=1500.0)
"""

import stripe  # импорты идут после docstring

class PaymentService:
    """Сервис обработки платежей.

    Управляет жизненным циклом транзакции от инициации до завершения.
    """

    def charge(self, order_id: int, amount: float) -> bool:
        """Списывает средства с клиента."""
        pass
```

Docstring класса описывает его ответственность в целом, не пересказывая каждый метод. Docstring метода – только то, что делает конкретный метод.

## Doctest: документация, которую можно запустить

Самая частая проблема с документацией – она устаревает. Код меняется, docstring остаётся старым. Модуль `doctest` решает это: примеры в docstring можно запускать как тесты.

```python
def add(a: int, b: int) -> int:
    """
    Складывает два числа.

    >>> add(2, 2)
    4
    >>> add(-1, 1)
    0
    """
    return a + b
```

```bash
python -m doctest mymodule.py
pytest --doctest-modules
```

Если реализация изменится и примеры перестанут соответствовать реальному поведению – тесты упадут. Это не замена юнит-тестам, но хороший способ держать примеры в актуальном состоянии.

## Инструменты

**pydocstyle** – линтер, проверяет соответствие docstrings стандарту PEP 257. Установи его в проект и настрой в CI – он быстро выработает привычку писать docstrings правильно.

**Sphinx** – стандарт индустрии для генерации документации. Мощный, но требует настройки. Используется в Django, Python и большинстве крупных библиотек.

**mkdocs** – современная альтернатива. Использует Markdown вместо reStructuredText, проще для старта.

**pdoc** – минималистичный вариант, не требует конфигурации, генерирует документацию на лету прямо из `__doc__`.

---

## Главное правило

Выбор конкретного стиля менее важен, чем единообразие. Смешение Google Style и Sphinx Style в одном проекте – это хаос: ни линтеры не смогут работать корректно, ни разработчик не поймёт, какому стандарту следовать дальше. Выбери один стиль на старте проекта, зафикси его в `pydocstyle` и не отступай.
