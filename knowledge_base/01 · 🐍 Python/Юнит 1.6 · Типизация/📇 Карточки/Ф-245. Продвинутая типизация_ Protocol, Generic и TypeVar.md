1. Чем Protocol отличается от обычного наследования типов? >> Protocol — структурная типизация: класс подходит, если имеет нужные методы, без явного наследования от протокола.
2. Что делает декоратор @runtime_checkable для Protocol? >> Разрешает isinstance()-проверку протокола в рантайме, а не только статически через mypy.
3. Что делает TypeVar? >> Создаёт переменную типа — заполнитель, конкретизируемый при использовании Generic-класса или функции.
4. Что означает TypeVar('T', bound=SomeClass)? >> T может быть любым типом, но только подтипом SomeClass.
5. Чем Optional[X] отличается от Union[X, None]? >> Ничем, Optional[X] — это просто сокращение для Union[X, None].
6. Что делает @overload из typing? >> Описывает несколько допустимых сигнатур одной функции для статического анализатора; реальную логику выполняет финальная реализация без декоратора.
7. Обязан ли класс явно наследоваться от Protocol, чтобы ему соответствовать? >> Нет, в этом и суть структурной типизации — достаточно иметь нужные методы/атрибуты.
8. Проверяет ли Protocol совпадение по умолчанию во время выполнения программы (runtime)? >> Нет, только статически через mypy, если не добавлен @runtime_checkable.
9. Чем ABC отличается от Protocol с точки зрения проверки в рантайме? >> ABC бросает TypeError при создании экземпляра без реализации всех абстрактных методов; Protocol по умолчанию рантайм вообще не проверяет.
10. Что делает синтаксис class Stack[T]: в Python 3.12+? >> Современный короткий синтаксис для generic-класса, эквивалентный TypeVar('T') + Generic[T] в более старых версиях.
11. Может ли один класс реализовывать несколько Generic-параметров одновременно? >> Да: class Mapping(Generic[K, V]) — с несколькими типовыми переменными.
12. Что произойдёт при попытке создать экземпляр класса, который наследует Protocol напрямую? >> Обычно это не имеет смысла — Protocol предназначен для типизации параметров, а не для прямого наследования в бизнес-логике (хотя технически возможно).
13. Что делает TypeVar без параметра bound? >> Означает "любой тип", просто связывает вход и выход функции/класса одним и тем же конкретным типом при каждом использовании.
14. Может ли Generic-класс иметь методы без использования параметра типа T? >> Да, не все методы обязаны использовать T.
15. Проверяет ли mypy соответствие Generic-класса на этапе выполнения программы? >> Нет, только статически, во время анализа кода — в рантайме параметры типа обычно стираются (type erasure), как и во многих других языках.
