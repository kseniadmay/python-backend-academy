1. Что такое `mypyc` и для чего он используется в Python? >> Инструмент компиляции аннотированного Python в C-расширения для ускорения выполнения
2. Что такое Gradual Typing? >> Сочетание динамической и статической проверки типов в одном проекте; можно аннотировать постепенно
3. Что означает `-> None` в сигнатуре? >> Функция ничего не возвращает
4. В чём разница между `mypy` и `pyright` ? >> `mypy` – классический анализатор от создателей Python; `pyright` – от Microsoft, быстрее, используется в Pylance для VS Code
5. Является ли Python строго типизированным языком? >> Нет; типизация добровольная и постепенная
6. Что означает «статический» в статических анализаторах? >> Анализ кода без его запуска
7. Что означает `Optional[str]` ? >> `str | None` ; аргумент может быть строкой или `None`
8. Что такое `Protocol` из `typing` ? >> Механизм структурной типизации (duck typing + type hints); класс считается совместимым если реализует нужные методы, без явного наследования
9. Как аннотации влияют на IDE? >> Улучшают автодополнение, подсветку ошибок, рефакторинг и навигацию по коду
10. Как называется подход к добавлению типов выборочно? >> Постепенная типизация (gradual typing)
11. Что даёт сигнатура функции с аннотациями? >> Описывает ожидаемые типы аргументов и тип возвращаемого значения без чтения тела функции
12. Что считается наиболее актуальной формой документации в Python? >> Аннотации типов; они находятся в коде и проверяются инструментами на соответствие реальности
13. Два примера статических анализаторов типов? >> `mypy` и `pyright`
14. На каком этапе анализаторы находят ошибки типов? >> До запуска программы; статический анализ без выполнения кода
15. Что произойдёт в `mypy` если передать `None` вместо `str` ? >> Ошибка о несовместимости типов до запуска программы
16. К чему приводит отсутствие аннотаций в большом проекте? >> К накоплению трудноуловимых багов и усложнению поддержки кода
17. Почему аннотации важны при командной разработке? >> Новый разработчик сразу видит какие данные ожидает функция и что она возвращает
18. Нужно ли аннотировать весь проект сразу? >> Нет; можно начать с публичных API и критически важных функций
19. Влияют ли аннотации на выполнение кода? >> Нет; игнорируются интерпретатором во время выполнения
