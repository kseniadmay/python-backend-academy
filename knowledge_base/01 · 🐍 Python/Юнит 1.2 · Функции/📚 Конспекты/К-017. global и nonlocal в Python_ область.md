## Как Python решает, где искать переменную

При обращении к переменной Python ищет её по правилу **LEGB** – строго по порядку, останавливаясь на первом совпадении. Сначала он смотрит в **Local** – внутри текущей функции. Если не нашёл – идёт в **Enclosing**, то есть во внешние функции при наличии вложенности. Затем в **Global** – на уровень модуля. И наконец в **Built-in** – встроенные имена Python вроде `len` или `range`.

---

## Почему нельзя просто изменить внешнюю переменную

```python
count = 0

def increment():
    count += 1  # UnboundLocalError!
```

Здесь возникает `UnboundLocalError`, и причина не очевидна. Python анализирует тело функции **до выполнения**. Видит `count += 1` – это присваивание, значит `count` помечается как локальная переменная. Когда доходит до выполнения `count + 1`, локальная переменная ещё не определена – отсюда ошибка.

Это не баг, а защита от случайного изменения внешнего состояния. Важный момент: **читать** внешнюю переменную из функции можно без каких-либо ключевых слов. Нельзя только изменять.

## `global` – доступ к переменной уровня модуля

```python
count = 0

def increment():
    global count
    count += 1

increment()
print(count)  # 1
```

`global count` – это не объявление переменной, а инструкция интерпретатору: не создавай локальную копию, работай с именем в глобальном пространстве имён. После этого `count += 1` меняет именно глобальный объект.

## `nonlocal` – доступ к переменной во внешней функции

`global` ищет только на уровне модуля. Если переменная находится во внешней функции – он не поможет. Для этого существует `nonlocal`.

```python
def outer():
    x = 10

    def inner():
        nonlocal x
        x += 1

    inner()
    print(x)  # 11

outer()
```

`nonlocal` поднимается вверх по цепочке вложенных функций и находит первую, в которой определена переменная. Принципиальное ограничение: глобальную область `nonlocal` не трогает. Если переменная не найдена ни в одной внешней функции – будет `SyntaxError`.

---

## Где `nonlocal` реально используется

Главный практический сценарий – **замыкания** и **декораторы**.

```python
def make_counter():
    count = 0

    def counter():
        nonlocal count
        count += 1
        return count

    return counter

c = make_counter()
print(c())  # 1
print(c())  # 2
```

`count` живёт в памяти `make_counter` после её завершения, но `counter` продолжает к ней обращаться. Это и есть **замыкание** (closure) – функция, которая помнит своё окружение.

---

## `global` vs `nonlocal` – сравнение

`global` ищет переменную на уровне модуля и, если не находит, бросает `NameError`. `nonlocal` ищет только среди внешних функций – глобальную область он принципиально игнорирует, и при отсутствии переменной выдаёт `SyntaxError`. Типичные сценарии тоже разные: `global` применяют для счётчиков и флагов уровня модуля, `nonlocal` – в замыканиях и декораторах.

---

## Когда применять, а когда – нет

Функция, которая меняет внешнее состояние неявно, усложняет тестирование и отладку: непонятно, где и когда данные изменились. В большинстве случаев лучше проектировать функции так, чтобы они принимали аргументы и возвращали новые значения – это делает поведение предсказуемым.

`nonlocal` оправдан в декораторах и замыканиях, где сохранение состояния между вызовами является частью задачи. `global` в production-коде встречается редко и почти всегда сигнализирует об архитектурной проблеме.
