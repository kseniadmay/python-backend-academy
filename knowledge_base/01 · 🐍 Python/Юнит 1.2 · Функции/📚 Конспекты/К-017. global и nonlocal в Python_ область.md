## Как Python решает, где искать переменную (LEGB)

При обращении к имени Python ищет его по правилу **LEGB** строго сверху вниз до первого совпадения:

| Порядок | Уровень | Область поиска |
| :--- | :--- | :--- |
| **1. L** | **Local** | Внутри текущей функции |
| **2. E** | **Enclosing** | Во внешних вложенных функциях |
| **3. G** | **Global** | На уровне модуля (файла) |
| **4. B** | **Built-in** | Встроенные имена (`len`, `range`) |

## Модификация внешних скоупов и UnboundLocalError

Читать внешнюю переменную можно просто так, а попытка изменить её без объявления скоупа вызывает ошибку рантайма:

```python
count = 0

def increment():
    # UnboundLocalError при вызове!
    count += 1

try:
    increment()
except UnboundLocalError as err:
    print(type(err).__name__)
# >>> UnboundLocalError
```

Python сканирует тело функции до запуска: увидев `count += 1`, он заранее считает `count` локальной переменной, поэтому на этапе чтения до присваивания возникает `UnboundLocalError`.

## `global` – доступ к переменной уровня модуля

Директива `global` указывает интерпретатору работать с переменной уровня модуля вместо создания локальной копии:

```python
count = 0

def increment():
    global count
    count += 1

increment()
print(count)
# >>> 1
```

После `global count` оператор `+= 1` изменяет объект прямо в глобальном пространстве имён модуля.

## `nonlocal` – доступ к переменной во внешней функции

Ключевое слово `global` смотрит только на уровень модуля; для изменения переменной внешней функции внутри вложенной используют `nonlocal`:

```python
def outer():
    x = 10

    # nonlocal меняет x во внешней outer()
    def inner():
        nonlocal x
        x += 1

    inner()
    print(x)
    # >>> 11

outer()
```

`nonlocal` ищет имя в ближайшей охватывающей функции (глобальную область не трогает) и выбрасывает `SyntaxError`, если переменная не найдена ни в одной из них.

## Где `nonlocal` реально используется

Главный практический сценарий `nonlocal` — замыкания и декораторы, которым нужно обновлять приватное состояние между вызовами:

```python
def make_counter():
    # Живёт в замыкании counter
    count = 0

    def counter():
        nonlocal count
        count += 1
        return count

    return counter

c = make_counter()
print(c())
# >>> 1

print(c())
# >>> 2
```

Переменная `count` сохраняется в ячейке замыкания после завершения `make_counter`, а вызовы `c()` безопасно её обновляют.

## `global` vs `nonlocal`: сравнение и правила применения

Ключевые отличия модификаторов области видимости:

| Критерий | `global` | `nonlocal` |
| :--- | :--- | :--- |
| Область поиска | Уровень модуля (`Global`) | Охватывающие функции (`Enclosing`) |
| Если имени нет | `NameError` (при чтении) | `SyntaxError` при компиляции |
| Типичный сценарий | Глобальные флаги модуля (редко) | Замыкания и декораторы |

Проектируйте функции чистыми (вход через аргументы и возврат результата) для предсказуемости.

`nonlocal` уместен для счётчиков в замыканиях, а `global` в production-коде обычно указывает на проблему архитектуры.
