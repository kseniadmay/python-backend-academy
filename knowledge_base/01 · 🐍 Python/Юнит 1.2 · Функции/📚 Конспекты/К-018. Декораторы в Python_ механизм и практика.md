## Определение и синтаксис `@`

**Декоратор** — это функция высшего порядка, которая принимает другую функцию, добавляет ей новое поведение и возвращает обёрнутую функцию под тем же именем.

Синтаксический сахар `@` является просто сокращением для ручной перепривязки имени:

```python
# Синтаксический сахар Python:
@decorator
def func():
    pass

# Эквивалентная ручная обёртка:
def func():
    pass

func = decorator(func)
```

Никакой скрытой магии нет: `@decorator` передаёт объявленную ниже функцию в `decorator` и переприсваивает имя результату.

## Анатомия декоратора

Рассмотрим классический декоратор со счётчиком вызовов и сохранением метаданных:

```python
from functools import wraps

def call_counter(func):
    calls = 0

    # Сохраняем __name__ и __doc__ оригинала
    @wraps(func)
    def wrapper(*args, **kwargs):
        nonlocal calls
        calls += 1
        name = func.__name__
        print(f'{name} вызов #{calls}')
        return func(*args, **kwargs)

    return wrapper

@call_counter
def compute_sum(n):
    return sum(range(n))

res = compute_sum(10)
# >>> compute_sum вызов #1

print(f'Результат: {res}')
# >>> Результат: 45
```

Как устроена обёртка внутри:

- **`*args, **kwargs` + `return`:** позволяют принимать любые аргументы и прозрачно возвращать результат `func` (иначе вызов начнёт возвращать `None`).
- **`@wraps(func)`:** копирует метаданные `__name__` и `__doc__` в `wrapper`, иначе `compute_sum.__name__` вернёт `'wrapper'` и сломает отладку.

## Декоратор с аргументами – три уровня вложенности

Если декоратору нужны параметры настройки, поверх обычной конструкции добавляется внешняя фабрика:

```python
from functools import wraps

# Фабрика декоратора с параметром n
def repeat(n):
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            for _ in range(n):
                result = func(*args, **kwargs)
            return result

        return wrapper
    return decorator

@repeat(3)
def greet():
    print('Hello!')

greet()
# >>> Hello!
# >>> Hello!
# >>> Hello!
```

Запись `@repeat(3)` сначала вызывает фабрику, которая возвращает `decorator`, затем тот получает `greet` и возвращает `wrapper`. Поэтому здесь три уровня вложенности, а не два.

## Где декораторы используются в реальном коде

В backend-разработке декораторы отделяют бизнес-логику функции от инфраструктурных задач (DRY и разделение ответственности):

- **Логирование:** автоматическая запись аргументов, времени вызова и результата функции.
- **Проверка прав доступа:** проверка аутентификации (вроде `@login_required`) до входа в обработчик.
- **Кеширование:** сохранение результатов чистых функций через `@lru_cache` или `@cache`.
- **Retry-логика:** автоматический повтор запроса при временных сетевых сбоях.
- **Профилирование:** замер времени выполнения без изменения кода самой функции.

## Стек из нескольких декораторов и подход Junior vs Senior

На одну функцию можно навесить сразу несколько декораторов. Они **накладываются снизу вверх** (от ближайшего к `def`), а при вызове функции их обёртки `wrapper` **исполняются сверху вниз** (как слои матрёшки):

```python
# Эквивалентно: bold(italic(say_hi))
@bold
@italic
def say_hi():
    return 'Python'
```

Если декоратор замеряет время работы (`@timer`), а второй кеширует результат (`@lru_cache`), их порядок меняет смысл: `@timer` над `@lru_cache` замерит скорость чтения из кеша, а `@lru_cache` над `@timer` запустит таймер только при промахе кеша.

> **Junior vs Senior**:
> - **Junior**: Забывает `@wraps(func)` и `return func(*args, **kwargs)`, из-за чего декорированная функция теряет имя/докстринг в Swagger и возвращает `None`.
> - **Senior**: Всегда ставит `@wraps(func)`, принимает универсальные `*args, **kwargs`, осознанно выстраивает порядок стека декораторов и не прячет в декораторы неочевидные побочные эффекты.
