## Что такое замыкание

Когда функция завершает выполнение, её локальные переменные уничтожаются – стек вызовов очищается. Но если внутри функции была определена другая функция, которая ссылается на переменную из внешней, Python не уничтожает эту переменную. Он понимает, что она ещё понадобится, и сохраняет её живой.

**Замыкание** – это внутренняя функция, которая помнит переменные из охватывающей (enclosing) области видимости даже после того, как внешняя функция завершила выполнение.

---

## Как это выглядит на практике

```python
def make_multiplier(n):
    def multiplier(x):
        return x * n  # n захвачена из внешней функции

    return multiplier

times3 = make_multiplier(3)
print(times3(5))  # 15
```

Здесь важно не перепутать два разных этапа: создание замыкания и последующий вызов внутренней функции.

Сначала выполняется строка `times3 = make_multiplier(3)`. В этот момент Python вызывает `make_multiplier`, создаёт переменную `n = 3`, затем создаёт внутреннюю функцию `multiplier` и замечает, что она использует переменную из внешней области видимости. Поэтому значение `n` сохраняется в специальном объекте замыкания. После строки `return multiplier` внешняя функция `make_multiplier` завершается.

Но значение `n = 3` не исчезает, потому что внутренняя функция успела захватить его в своё замыкание.

И только после этого выполняется строка `print(times3(5))`. Здесь `times3` уже является ссылкой на ранее созданную функцию `multiplier`. Несмотря на то что `make_multiplier` давно завершилась, `multiplier` продолжает помнить значение `n = 3` и использует его при каждом вызове.

Это не магия и не скрытый механизм – в Python это можно буквально проверить. У каждой функции-замыкания есть атрибут **`__closure__`**, который хранит захваченные переменные:

```python
print(times3.__closure__[0].cell_contents)  # 3
```

Важный нюанс: замыкание хранит не копию значения, а **ссылку на ячейку памяти** (cell object). Это ключевой момент, из которого вытекает одна из самых распространённых ловушек.

## Ловушка: замыкание в цикле

```python
funcs = [lambda: i for i in range(3)]
print([f() for f in funcs])  # [2, 2, 2] – а не [0, 1, 2]
```

Этот результат почти всегда удивляет новичков. Интуитивно кажется, что каждая функция должна запомнить своё значение: `0`, `1` и `2`. Но замыкания в Python работают иначе.

Важно понимать, что во время выполнения цикла Python не создаёт отдельную переменную `i` для каждой итерации. Внутри цикла существует одна общая переменная `i`, значение которой постоянно меняется:

```python
i = 0
i = 1
i = 2
```

На каждой итерации создаётся новая функция `lambda: i`. Но сама лямбда в этот момент не выполняется. Она только создаётся и сохраняет ссылку на переменную `i`, а не текущее значение этой переменной.

После завершения цикла переменная `i` содержит последнее присвоенное значение – `2`. И только после этого происходит вызов функций `[f() for f in funcs]`. В этот момент каждая лямбда обращается к одной и той же переменной `i`. А так как цикл уже завершился, её текущее значение равно `2`.

Поэтому результат получается таким `[2, 2, 2]`.

Ключевой момент здесь в том, что замыкание не фотографирует значение переменной в момент создания функции. Оно хранит ссылку на переменную и читает её текущее состояние в момент вызова.

---

## Решение: фиксация значения через аргумент по умолчанию

```python
funcs = [lambda i=i: i for i in range(3)]
print([f() for f in funcs])  # [0, 1, 2]
```

Здесь происходит принципиально другой механизм.

Во время каждой итерации Python вычисляет аргумент по умолчанию `i=i`. Аргументы по умолчанию вычисляются сразу **в момент создания функции**, а не позже при вызове.

Поэтому механизм работы теперь выглядит так:

```text
i = 0  → lambda i=0: i
i = 1  → lambda i=1: i
i = 2  → lambda i=2: i
```

То есть текущее значение `i` немедленно копируется в локальный аргумент функции. Теперь каждая функция получает собственную локальную переменную `i`, которая уже не зависит от внешнего цикла.

Поэтому после завершения цикла вызов `[f() for f in funcs]` даёт `[0, 1, 2]`, потому что каждая функция хранит своё отдельное зафиксированное значение.

Это приём называется **binding at definition time** – связывание в момент определения.

## Где замыкания используются в реальном коде

**Декораторы** целиком построены на замыканиях. Когда декоратор оборачивает функцию, внутренняя функция-обёртка захватывает оригинальную функцию из внешней области видимости и сохраняет к ней доступ.

**Фабричные функции** – как `make_multiplier` выше – позволяют генерировать специализированные функции с предустановленным состоянием без создания классов.

**Счётчики и накопители** без классов – замыкание с `nonlocal` позволяет хранить изменяемое состояние между вызовами, что разобрали в теме про `nonlocal`.

Замыкания легче классов по накладным расходам. Если нужно сохранить состояние и поведение, но класс избыточен – замыкание часто более уместный выбор.

---

## Главное, что нужно понимать

Замыкание захватывает переменную, а не значение. Пока это не усвоено – поведение в цикле будет казаться багом. Когда усвоено – замыкания становятся предсказуемым и мощным инструментом. Разница между ссылкой и значением в контексте замыканий – классический вопрос на собеседованиях уровня middle.
