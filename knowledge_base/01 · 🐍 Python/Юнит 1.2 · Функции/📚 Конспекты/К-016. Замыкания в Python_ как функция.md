## Что такое замыкание

Обычно локальные переменные уничтожаются после возврата из функции. Но если вложенная функция ссылается на переменную из охватывающей (`enclosing`) области, Python продлевает ей жизнь.

**Замыкание** — внутренняя функция, которая помнит переменные внешней области после завершения внешней функции:

```python
def make_multiplier(n):
    def multiplier(x):
        # n захвачена из внешней функции
        return x * n

    return multiplier

times3 = make_multiplier(3)
print(times3(5))
# >>> 15
```

После вызова `make_multiplier(3)` внешняя функция завершается, но внутренняя `multiplier` сохраняет живую ссылку на `n`.

---

## Инспекция рантайма: кортеж `__closure__` и объект cell

В CPython захваченные переменные хранятся в атрибуте функции **`__closure__`** в виде кортежа ячеек памяти (`cell object`):

```text
times3 (PyFunctionObject)
   │
   └── __closure__ (tuple)
          │
          └── [0]: cell object
                      │
                      └── PyLongObject (3)
```

Значение внутри ячейки можно прочитать в рантайме через атрибут `cell_contents`:

```python
def make_multiplier(n):
    return lambda x: x * n

times3 = make_multiplier(3)

# Чтение значения из ячейки памяти cell
print(times3.__closure__[0].cell_contents)
# >>> 3
```

Замыкание хранит именно ссылку на разделяемую ячейку `cell`, а не копию значения.

## Ловушка: замыкание в цикле и позднее связывание

Поскольку ячейка разделяется между всеми функциями цикла, возникает ловушка позднего связывания (`late binding`):

```python
funcs = [lambda: i for i in range(3)]

# Все функции видят итоговое i = 2
print([f() for f in funcs])
# >>> [2, 2, 2]
```

Внутри цикла существует одна общая переменная `i`, а не снимок её значения на каждой итерации. Последовательность изменений в одной общей ячейке:

```text
1-я итерация: i = 0
2-я итерация: i = 1
3-я итерация: i = 2 (остаётся в ячейке)
```

В момент вызова `f()` все три лямбды обращаются к одной ячейке памяти, где к концу цикла уже лежит `2`.

---

## Решение: фиксация значения через аргумент по умолчанию

Чтобы зафиксировать значение на каждой итерации, его передают аргументом по умолчанию `lambda i=i: i`:

```python
funcs = [lambda i=i: i for i in range(3)]
print([f() for f in funcs])
# >>> [0, 1, 2]
```

Аргументы по умолчанию вычисляются сразу **в момент создания функции**, поэтому каждая лямбда получает свою копию числа:

```text
i = 0  → lambda i=0: i
i = 1  → lambda i=1: i
i = 2  → lambda i=2: i
```

Такой приём называют **binding at definition time**: локальная переменная каждой функции сохраняет собственное зафиксированное значение независимо от цикла.

## Где замыкания используются в реальном коде

Замыкание захватывает переменную, а не её значение — понимание этой разницы делает инструмент предсказуемым в повседневных задачах:

- **Декораторы:** внутренняя функция-обёртка захватывает исходную функцию из внешней области видимости.
- **Фабричные функции:** как `make_multiplier`, создают специализированные функции с заданной конфигурацией без классов.
- **Счётчики и накопители:** в связке с `nonlocal` хранят изменяемое состояние между вызовами с меньшим оверхедом, чем у классов.

> **Junior vs Senior**:
> - **Junior**: путает захваченную ячейку `__closure__` с копированием значения, из-за чего функции из цикла возвращают одно последнее значение или падают с `UnboundLocalError`.
> - **Senior**: понимает механику `cell`-объектов и позднего связывания, применяет замыкания в декораторах и фабриках, а при росте состояния переходит на классы или `functools.partial`.
