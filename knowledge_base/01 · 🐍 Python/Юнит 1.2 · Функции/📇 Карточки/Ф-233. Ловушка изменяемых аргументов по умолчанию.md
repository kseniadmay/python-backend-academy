1. Когда вычисляется значение по умолчанию для аргумента функции? >> Один раз, в момент определения функции, а не при каждом вызове.
2. Почему `def f(cart=[])` опасно? >> Все вызовы без явного аргумента будут делить один и тот же список между собой.
3. Как правильно задать изменяемое значение по умолчанию? >> cart=None, затем внутри функции: if cart is None: cart = [].
4. Касается ли эта проблема только списков? >> Нет, любых изменяемых объектов — dict, set, экземпляров собственных классов.
5. Затрагивает ли эта проблема аргументы по умолчанию типа int или str? >> Нет, они неизменяемы — их нельзя случайно мутировать, поэтому разделяемое состояние безопасно.
6. Что произойдёт, если внутри функции переприсвоить cart = [] вместо if cart is None? >> Это создаст новый локальный список при каждом вызове, но лишит функцию возможности принимать существующий список как аргумент осмысленно — нужна именно проверка is None.
7. Является ли это поведение багом интерпретатора Python? >> Нет, это следствие модели: def выполняется один раз, значения по умолчанию вычисляются и живут вместе с объектом функции.
8. Проявляется ли эта ловушка при вызове функции с явно переданным аргументом каждый раз? >> Нет, проблема возникает только когда аргумент опускается и используется общее значение по умолчанию.
9. Проявляется ли эта ловушка, если функция никогда не мутирует переданный по умолчанию объект, а только читает его? >> Нет, проблема возникает только при мутации (append, изменение элемента) — просто чтение общего пустого объекта безопасно.
10. Что вернёт func.__defaults__ для функции def f(a, b=[]):? >> Кортеж со значениями по умолчанию — ([],) — можно увидеть тот самый общий объект напрямую.
11. Есть ли аналогичная ловушка для значений по умолчанию у методов класса? >> Да, полностью идентичная — self не влияет на момент вычисления значения по умолчанию.
