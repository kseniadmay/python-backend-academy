1. В чём ловушка с переприсваиванием изменяемого аргумента внутри функции ( `lst = [1, 2, 3]` )? >> `def f(lst): lst = [1,2,3]` не изменит внешний список; переприсваивание разрывает связь с оригиналом; для изменения нужны методы мутации: `.append()` , `.extend()` и т.д.
2. На какой объект в памяти указывает аргумент `lst` внутри функции `append_item(my_list)`: `def append_item(lst):; lst.append(99)` ? >> На тот же объект списка, что и `my_list` снаружи
3. Что выведет `print(my_list)` после выполнения функции: `def append_item(lst): lst.append(99); my_list = [1, 2, 3]; append_item(my_list); print(my_list)` ? >> `[1, 2, 3, 99]`
4. Почему значение `a` остаётся равным `5` после вызова функции: `def change(x): x = 100; a = 5; change(a); print(a)` ? >> `int` неизменяем; `x = 100` создало новую локальную переменную, не затронув оригинал
5. Что произойдёт при выполнении `x = 100` внутри функции, если `x` был передан как аргумент: `def modify(x):; x = 100; a = 5; modify(a); print(a)` ? >> На новый объект `100` в памяти; связь с `a` разорвана
6. Что происходит при переприсваивании аргумента внутри функции ( `x = 100` )? >> Локальная переменная начинает указывать на новый объект; оригинал не затрагивается
7. Может ли функция изменить значение переданного неизменяемого объекта ( `int` , `str` , `tuple` ) во внешнем коде? >> Нет; любое «изменение»создаёт новый объект и новую локальную ссылку
8. Какая операция изменяет оригинал без разрыва ссылки? >> Методы мутации: `.append()` , `.extend()` , `.update()` и др.
9. Создаётся ли новая переменная при вызове `.append()` на `mutable` -объекте? >> Нет; метод работает напрямую с исходным объектом по существующей ссылке
10. Что именно копируется при передаче аргумента в функцию? >> Копируется ссылка на объект, но не сам объект; функция получает доступ к тому же адресу в памяти
11. От чего зависит, изменит ли функция оригинальный объект? >> От изменяемости ( `mutability` ) объекта: `mutable` – изменится, `immutable` – нет
12. Как изменения `mutable` -объекта внутри функции отражаются снаружи? >> Изменения видны снаружи, так как функция работает с тем же объектом в памяти
13. Почему Python не является ни `pass by value` , ни `pass by reference` ? >> Передаётся копия ссылки на объект; поведение зависит от изменяемости объекта, а не от механизма передачи
14. Как называется механизм передачи аргументов в Python? >> Передача по присваиванию ( `pass by assignment` ); также называется передачей ссылки на объект
15. В какой момент переменная внутри функции ссылается на тот же объект, что и снаружи? >> В момент вызова, до любого переприсваивания внутри функции
