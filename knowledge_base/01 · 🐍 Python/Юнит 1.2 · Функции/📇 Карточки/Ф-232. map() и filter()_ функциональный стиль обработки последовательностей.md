1. Что возвращает map(func, iterable)? >> Ленивый итератор с результатами применения func к каждому элементу.
2. Что делает filter(func, iterable)? >> Оставляет только элементы, для которых func вернула истинное значение.
3. Что делает filter(None, iterable)? >> Оставляет только "истинные" (truthy) элементы, отбрасывая falsy (0, '', None, [] и т.д.).
4. Чем map/filter отличаются от списковых включений по результату? >> Результат идентичен, разница только в стиле и читаемости — list comprehension обычно читается легче при комбинировании нескольких трансформаций.
5. Ленивы ли map() и filter()? >> Да, как и генераторы — вычисляют значения по требованию, не сразу.
6. Можно ли передать в map() обычную именованную функцию вместо lambda? >> Да: map(str.upper, words) — часто компактнее эквивалентного списка включения.
7. Что произойдёт при передаче в map() нескольких итерируемых объектов разной длины? >> map() остановится на самой короткой, как и zip().
8. Как получить список (а не ленивый итератор) из результата map()? >> Обернуть в list(): list(map(func, iterable)).
9. Эквивалентен ли filter(lambda x: x > 0, nums) списковому включению [x for x in nums if x > 0]? >> Да, по результату полностью эквивалентен.
10. Что делает functools.reduce() в отличие от map()/filter()? >> Сворачивает последовательность в одно значение через последовательное применение функции к парам элементов, а не преобразует/фильтрует поэлементно.
11. Можно ли передать в map() метод класса (bound method) как функцию? >> Да, любой вызываемый объект (callable) подходит для map()/filter().
12. Что произойдёт при попытке повторно пройтись циклом for по уже израсходованному объекту map()? >> Ничего не выведет — как и генератор, map-объект можно пройти только один раз.
13. Как получить индекс элемента вместе со значением при использовании map()? >> Обычно комбинируют с enumerate(): map(func, enumerate(items)) — map получит пары (индекс, значение).
