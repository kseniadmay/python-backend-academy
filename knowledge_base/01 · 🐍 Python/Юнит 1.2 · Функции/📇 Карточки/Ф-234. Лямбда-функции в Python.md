1. Из скольких выражений может состоять тело lambda? >> Ровно из одного — не набор инструкций, без if/else в виде оператора, без циклов.
2. Какой самый частый сценарий использования lambda? >> Аргумент key= для sorted(), max(), min(), или callback для filter()/map().
3. Почему PEP 8 не рекомендует `f = lambda: ...` с присваиванием переменной? >> У обычной функции def есть осмысленное имя в трейсбеке, у лямбды __name__ всегда '<lambda>' — усложняет отладку без выигрыша.
4. В чём ловушка лямбды внутри цикла? >> Лямбда захватывает переменную, а не её значение на момент создания — та же проблема, что и с замыканиями.
5. Может ли lambda не принимать аргументов вообще? >> Да: f = lambda: 42.
6. Может ли lambda содержать значения по умолчанию для параметров? >> Да: lambda x, y=10: x + y.
7. Может ли lambda вызвать саму себя рекурсивно? >> Технически возможно через трюк с параметром по умолчанию, но крайне не рекомендуется — для рекурсии нужна именованная функция.
8. Что вернёт (lambda x: x**2)(5)? >> 25 — лямбду можно вызвать сразу же после определения.
9. Может ли lambda содержать *args и **kwargs? >> Да: f = lambda *args, **kwargs: sum(args).
10. Что вернёт (lambda x, y: x + y).__name__? >> '<lambda>' — у лямбды всегда одно и то же служебное имя, независимо от переменной, которой она присвоена.
11. Можно ли использовать lambda как значение по умолчанию для аргумента функции? >> Да: def f(callback=lambda: None): — распространённый паттерн "опциональный callback".
