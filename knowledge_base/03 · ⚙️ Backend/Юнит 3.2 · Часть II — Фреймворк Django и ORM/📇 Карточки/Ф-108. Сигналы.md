1. Что произойдет, если в обработчике сигнала Django (receiver) возникнет необработанное исключение? >> По умолчанию прервёт выполнение кода инициировавшего отправку сигнала
2. Как объявить, отправить и перехватить кастомный сигнал в Django? >> Инициализировать объект класса `Signal()` : `order_completed = Signal()`
3. Почему в крупных Django-проектах сигналы (Signals) часто считают антипаттерном (проблема неявных зависимостей)? >> Связь между компонентами, не видимая при обычном чтении кода вызывающей стороны
4. Как в Django с помощью сигнала post_save автоматически создавать профиль пользователя? >> Создаёт запись в таблице профилей, связывая её с новым пользователем
5. Какую архитектурную модель реализуют сигналы в Django? >> Pub/sub (издатель-подписчик)
6. Для чего импортируется `from django.dispatch import receiver` ? >> Для доступа к декоратору подписки на сигналы
7. Может ли одна функция обрабатывать несколько сигналов? >> Да – передать список сигналов в `@receiver`
8. Тип данных `created` в сигнале `post_save` ? >> `bool`
9. Почему сигналы считаются потенциально опасными для отладки? >> Они создают неявные зависимости, затрудняя отслеживание потока выполнения
10. Является ли `order_completed = Signal()` функцией или объектом? >> Объектом класса `Signal`
11. Какой обязательный аргумент передаётся в `.send()` ? >> `sender`
12. Зачем в `send_welcome_email` используется `.delay()` ? >> Для асинхронного выполнения отправки письма в фоновой задаче (Celery)
13. В какой момент срабатывает `pre_save` ? >> Непосредственно перед сохранением экземпляра в БД
14. Где внутри `AppConfig` происходит импорт модуля с сигналами? >> Внутри метода `ready(self)`
15. Может ли один сигнал иметь несколько обработчиков? >> Да, неограниченное количество
16. Почему использование сервисов прозрачнее сигналов? >> Вызов сервиса прописан в коде явно, что облегчает понимание логики
17. Что рекомендуется использовать вместо сигналов для сложной бизнес-логики? >> Явные вызовы сервисных функций
18. Какое условие позволяет выполнять код только при первом создании объекта? >> `if created:`
19. В каком файле рекомендуется подключать обработчики сигналов? >> `apps.py`
20. В какой момент срабатывает `post_save` ? >> Сразу после сохранения экземпляра модели в БД
21. Из какого модуля импортируются `post_save` и `pre_save` ? >> `django.db.models.signals`
22. Наследником какого класса должна быть конфигурация приложения в `apps.py` ? >> `AppConfig`
23. Какое значение принимает `created` если запись обновлена, а не создана? >> `False`
24. Как сигнал передаёт данные подписчикам? >> Через именованные аргументы в методе `.send()`
25. Влияют ли сигналы на производительность при массовом сохранении объектов? >> Да – для каждого объекта вызываются все подписанные обработчики
26. Каким методом инициируется отправка сигнала? >> `.send()`
27. Что такое `sender=Order` в `order_completed.send(sender=Order, ...)` ? >> Указание класса выступающего источником события
28. Для чего используются сигналы в контексте взаимодействия компонентов? >> Для реакции одних компонентов на события в других без прямой зависимости
29. Какой аргумент обработчика `user_logged_in` позволяет получить IP-адрес? >> `request` – через `request.META.get('REMOTE_ADDR')`
30. В каком модуле находится класс `Signal` для кастомных сигналов? >> `django.dispatch`
31. Для чего в обработчике `post_save` используется `**kwargs` ? >> Для приёма дополнительных аргументов которые могут быть переданы сигналом в будущем
32. Что передаётся в аргументе `instance` обработчика `post_save` ? >> Конкретный экземпляр модели который был сохранён
33. Какой декоратор используется для подписки функции на сигнал? >> `@receiver`
34. Какому паттерну проектирования соответствуют сигналы Django? >> Паттерн Наблюдатель (Observer)
35. Как называется аргумент обработчика содержащий класс отправивший событие? >> `sender`
36. Верно ли что сигналы Django работают только с моделями БД? >> Нет – можно создавать кастомные сигналы для любых событий
37. Какой сигнал использовать для модификации данных перед записью в БД? >> `pre_save`
38. Какую роль играет аргумент `sender` в `@receiver` ? >> Указывает от какого компонента принимать сигналы; если отправитель не совпадает – обработчик не вызывается
39. Из какого модуля импортируется `user_logged_in` ? >> `django.contrib.auth.signals`
40. Какой сигнал срабатывает после удаления записи? >> `post_delete`
