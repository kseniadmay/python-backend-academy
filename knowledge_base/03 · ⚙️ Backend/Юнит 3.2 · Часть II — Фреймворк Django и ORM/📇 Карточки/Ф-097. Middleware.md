1. В каком формате и порядке объявляются Middleware в settings.py Django? >> Строками с полным путём через точку: `'myapp.middleware.LogRequestMiddleware'`
2. За что отвечает `SecurityMiddleware` ? >> Редирект на HTTPS и добавление защитных HTTP-заголовков: `X-Content-Type-Options` , `Referrer-Policy` и др.
3. В каком файле регистрируются собственные middleware? >> `settings.py`
4. Какое стандартное middleware добавляет объект пользователя в `request.user` ? >> `AuthenticationMiddleware`
5. Какой объект middleware должен анализировать для логирования входящих URL? >> Объект `request`
6. Как middleware упрощает работу View с часто используемыми данными? >> Добавляет эти данные в объект `request` ещё до вызова View
7. Зачем `AuthenticationMiddleware` требует `SessionMiddleware` выше в списке? >> Для извлечения данных сессии, необходимых для идентификации пользователя
8. Какое middleware первым получит входящий HTTP-запрос? >> Первое в списке `MIDDLEWARE` (сверху)
9. Как создать объект логгера для текущего модуля? >> `logging.getLogger(__name__)`
10. В какой момент middleware обрабатывает ответ? >> После того как ответ сформирован во View
11. Что представляет собой аргумент `get_response` в `__init__` ? >> Вызываемый объект, передающий запрос следующему middleware или View и возвращающий `HttpResponse`
12. В какой момент middleware обрабатывает запрос? >> До попадания во View
13. Где в списке `MIDDLEWARE` обычно располагается `SecurityMiddleware` ? >> В самом начале (сверху)
14. Какая стандартная библиотека Python используется для логирования внутри middleware? >> `logging`
15. Для чего middleware используется в контексте безопасности? >> Проверка IP, ограничение доступа, фильтрация запросов, проверка заголовков, логирование
16. В каком порядке запрос проходит через список `MIDDLEWARE` ? >> Сверху вниз
17. Если middleware изменит `request` , увидят ли это следующие middleware? >> Да – изменения сохраняются при передаче по цепочке
18. Что возвращает `self.get_response(request)` внутри middleware? >> Объект ответа `HttpResponse`
19. Какое middleware не позволит отправить POST-форму без специального токена? >> `CsrfViewMiddleware`
20. Если `AuthenticationMiddleware` не находит пользователя, что записывается в `request.user` ? >> `AnonymousUser`
21. За что отвечает `SessionMiddleware` ? >> За поддержку и обработку сессий
22. Что произойдёт если допустить опечатку в пути к классу middleware? >> Django выдаст `ImportError` при запуске
23. Какую структуру использует Django для работы с несколькими middleware? >> Цепочку (chain)
24. В каком методе реализуется основная логика кастомного middleware? >> `__call__`
25. Какое middleware первым получит объект `Response` из View? >> Последнее в списке `MIDDLEWARE` (снизу)
26. Где лучше реализовать автоматическое добавление HTTP-заголовков ко всем ответам? >> В собственном middleware
27. Как называется переменная в `settings.py` содержащая список middleware? >> `MIDDLEWARE`
28. Когда порядок middleware в `settings.py` критичен? >> Когда одно middleware зависит от данных подготовленных другим – например, сессии для аутентификации
29. Как передаётся управление следующему middleware в `__call__` ? >> Через вызов `self.get_response(request)`
30. В каком порядке ответ проходит через middleware обратно к пользователю? >> Снизу вверх
31. Для чего ещё используется `__init__` кроме сохранения `get_response` ? >> Для однократной инициализации при запуске: загрузка конфигурации, создание подключений, подготовка ресурсов
32. Какой метод кастомного middleware инициализирует его при запуске сервера? >> `__init__`
33. Что чаще всего логируют в middleware для аналитики? >> Путь ( `request.path` ), метод, IP-адрес отправителя и время обработки
34. Если в `MIDDLEWARE` указан `myapp.middleware.RequestTimingMiddleware` , где лежит файл? >> В папке `myapp`
35. Как в Django называется промежуточный слой обрабатывающий запрос до View и ответ после неё? >> Middleware
36. Как в middleware получить HTTP-метод запроса? >> `request.method` – возвращает `'GET'` , `'POST'` и т.д.
37. Может ли middleware полностью прервать запрос не передавая его во View? >> Да – если оно сразу вернёт объект `Response`
38. Правда ли что middleware работает по принципу матрёшки (onion architecture)? >> Да – каждое middleware оборачивает следующее
39. Где сохраняется ссылка на `get_response` в middleware? >> В атрибуте `self.get_response`
40. Какую задачу выполняет `CsrfViewMiddleware` ? >> Проверяет CSRF-токены и защищает от атак, при которых сторонний сайт выполняет действия от имени пользователя
