1. Какие параметры передаются бэкендом на Token Endpoint при обмене authorization_code на токены в OAuth 2.0? >> `code` , `client_id` , `client_secret` , `grant_type=authorization_code` , `redirect_uri`
2. Перечислите пошагово сценарий работы OAuth 2.0 Authorization Code Flow. >> Редирект пользователя на Authorization Server → пользователь логинится и подтверждает → AS возвращает `code` → backend обменивает `code` на токены → backend запрашивает данные с `access_token`
3. Может ли OAuth 2.0 без OIDC сообщить имя пользователя? >> Нет; нужен дополнительный запрос к Resource Server с `access_token` или использование OIDC
4. Что такое Authorization Code? >> Одноразовый временный код, который сервер возвращает клиенту после подтверждения пользователем; обменивается на токены на сервере
5. Для чего предназначен OAuth 2.0? >> Для авторизации – предоставления ограниченного доступа к ресурсам от имени пользователя; не для аутентификации
6. Какой HTTP-метод используется при редиректе пользователя на Authorization Server? >> `GET` с параметрами `client_id` , `redirect_uri` , `scope` , `response_type=code`
7. Чем OAuth отличается от сессий и JWT? >> OAuth – делегированная авторизация через третью сторону; сессии/JWT – прямая аутентификация в рамках одного приложения
8. Зачем `client_secret` при обмене кода? >> Аутентифицирует само приложение на сервере авторизации; подтверждает что запрос от доверенного клиента
9. Почему Authorization Code Flow безопаснее прямой передачи токена? >> Токен передаётся через защищённый server-to-server канал; code в URL браузера – короткоживущий и одноразовый
10. Четыре участника OAuth 2.0? >> Resource Owner (пользователь); Client (приложение); Authorization Server (Google, GitHub); Resource Server (API с данными)
11. Чем отличаются `id_token` и `access_token` ? >> `id_token` – кто этот пользователь (аутентификация); `access_token` – право вызова API (авторизация)
12. Что происходит при запросе новых `scope` ? >> Пользователю снова показывается экран подтверждения; нельзя расширить права без согласия
13. Где должен храниться `client_secret` ? >> Только на сервере (backend); никогда в браузере или мобильном приложении
14. Что такое OIDC (OpenID Connect)? >> Надстройка над OAuth 2.0 для аутентификации; добавляет `id_token` с данными о пользователе
15. Является ли OAuth 2.0 протоколом аутентификации? >> Нет; это протокол авторизации; для аутентификации используется OIDC (OpenID Connect)
16. В каком формате `id_token` в OIDC? >> JWT; содержит claims о пользователе: имя, email, sub (уникальный ID)
17. Для чего параметр `scope` в OAuth 2.0? >> Ограничивает запрашиваемые права доступа; принцип минимальных привилегий
