1. Что такое HMAC и чем он отличается от обычного хэширования (например, SHA-256)? >> Hash-based Message Authentication Code; для подписи сообщений и токенов; не чистый SHA-256, а SHA-256 + секретный ключ; защищает от подделки
2. Что означает `rounds=12` в bcrypt? >> $2^{12}$ итераций; ~250 мс на одно хэширование; баланс между безопасностью и UX
3. Что такое соль (salt)? >> Случайная строка, добавляемая к паролю перед хэшированием; уникальна для каждого пользователя; делает хэши уникальными и защищает от rainbow tables
4. Почему один и тот же пароль даёт разный bcrypt-хэш при каждом вызове? >> Каждый раз генерируется новая случайная соль
5. Почему SHA-256 подходит для контрольных сумм, но не для паролей? >> Контрольные суммы требуют скорости; пароли требуют медлительности против перебора
6. Что такое rainbow tables? >> Заранее вычисленные таблицы соответствий популярных паролей и их хэшей; делают brute force мгновенным для слабых паролей
7. Функции Django для работы с паролями? >> `make_password()` – создание хэша; `check_password()` – проверка; высокоуровневые абстракции без ручного сравнения
8. Какой алгоритм Django использует по умолчанию? >> PBKDF2; настраивается через `PASSWORD_HASHERS`
9. Для чего `hashlib` в Python? >> Хэширование данных общего назначения: API-ключи, контрольные суммы, идентификаторы, HMAC; не для паролей
10. Какой метод bcrypt работает при проверке пароля? >> `bcrypt.checkpw()` извлекает соль и параметры из хэша и пересчитывает; сравнивать строки вручную не нужно
11. Почему пароли нельзя хранить в зашифрованном виде? >> Шифрование обратимо; при утечке ключа шифрования злоумышленник получит все пароли открытым текстом
12. Что такое Argon2? >> Победитель Password Hashing Competition 2015; современная рекомендуемая альтернатива bcrypt для новых проектов
13. Правильные алгоритмы для хэширования паролей? >> Bcrypt и Argon2; не SHA-256, не MD5 – они слишком быстрые
14. Почему пароли нельзя хранить через SHA-256 или MD5? >> Слишком быстрые: миллиарды попыток в секунду; уязвимы для brute force и rainbow tables
15. Особенность bcrypt по хранению соли? >> Соль автоматически встраивается в строку хэша; хранить отдельно не нужно; для проверки достаточно одного значения из БД
16. Как хранить API-ключи в БД? >> Хэш через `hashlib.sha256(key.encode()).hexdigest()` ; оригинальный ключ не хранится; при запросе хэшируем и сравниваем
17. Что такое медленное хэширование? >> Алгоритмы с настраиваемым cost factor; намеренно медленные (~250 мс); brute force становится вычислительно дорогим
