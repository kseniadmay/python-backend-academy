1. В чём разница между Аутентификацией (AuthN) и Авторизацией (AuthZ) и какими HTTP-кодами выражаются их ошибки? >> Аутентификация проверяет **кто вы** (ошибка `401 Unauthorized`); Авторизация проверяет **что вам разрешено делать** (ошибка `403 Forbidden`, когда личность известна, но прав недостаточно)
2. В чём основная идея модели RBAC (Role-Based Access Control)? >> Права доступа (Permissions: `order:cancel`, `user:ban`) назначаются не пользователям напрямую, а **ролям** (`viewer`, `moderator`, `admin`), а пользователям присваиваются одна или несколько ролей
3. Чем модель ABAC (Attribute-Based Access Control) отличается от RBAC? >> В RBAC доступ зависит только от статической роли субъекта; в ABAC решение принимается по атрибутам субъекта, самого ресурса и окружения (например: «Редактировать статью может только её автор (`article.author_id == user.id`) в рабочее время»)
4. Как в FastAPI идиоматично реализовать проверку роли (`require_role('admin')`) для группы эндпоинтов? >> Через параметризованную фабрику зависимостей `Depends(require_role('admin'))`, которая получает `current_user` и выбрасывает `HTTPException(status_code=403)`, если нужной роли нет
5. В чём разница между методами `has_perm(request, view)` и `has_object_permission(request, view, obj)` в классах `BasePermission` (DRF)? >> `has_perm` проверяет общий доступ к эндпоинту до обращения к конкретной записи БД; `has_object_permission` проверяет права на конкретный экземпляр модели `obj` (вызывается в `get_object()`)
6. В какой известной ловушке DRF метод `has_object_permission` НЕ вызывается автоматически? >> При списочных запросах (`list`) и при создании объекта (`create`): для списка фильтрацию доступных записей нужно делать в `get_queryset()`
7. Что такое уязвимость IDOR / BOLA (Insecure Direct Object Reference / Broken Object Level Authorization)? >> Самая частая уязвимость API (№1 в OWASP API Top 10): сервер проверяет, что пользователь вошёл в систему, но не проверяет при `GET /orders/105`, что заказ `105` принадлежит именно этому пользователю
8. Почему иногда при попытке чужого пользователя открыть приватный ресурс `/documents/999` возвращают `404 Not Found` вместо `403 Forbidden`? >> Чтобы не раскрывать сам факт существования документа с ID `999` в базе данных (защита от перебора идентификаторов — Enumeration Attack)
9. Что означает принцип наименьших привилегий (Principle of Least Privilege) при проектировании ролей и API-ключей? >> Любому пользователю, сервису или токену по умолчанию выдаётся минимально необходимый набор прав (`scopes`), требуемый только для его прямой задачи
10. Стоит ли зашивать полный список прав и ролей внутрь долгоживущего JWT-токена без проверки на сервере? >> Если администратор заблокирует пользователя или отберёт роль `admin`, старый JWT продолжит давать права до истечения своего `exp`; поэтому `access_token` делают короткоживущим (5–15 минут), а критичные операции сверяют с БД/кэшем
