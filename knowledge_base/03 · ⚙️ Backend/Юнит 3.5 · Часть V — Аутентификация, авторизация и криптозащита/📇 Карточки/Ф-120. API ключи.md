1. Почему передача API-ключа в заголовке (X-API-Key) безопаснее, чем в query-параметрах URL? >> Заголовки не входят в URL, используемый как ключ кэша; ключ не попадает в CDN, прокси или браузерный кэш
2. Зачем `is_active` вместо удаления записи? >> Сохраняет историю использования и логи; позволяет быстро деактивировать скомпрометированный ключ
3. Как проверить API ключ при запросе? >> Хэшировать полученную строку; найти запись в БД с совпадающим хэшем и `is_active = 1`
4. Что делать если пользователь потерял API ключ? >> Сгенерировать новый; старый восстановить невозможно
5. Что такое scopes для API ключей? >> Ограничение набора разрешённых действий; принцип минимальных привилегий; ключ имеет доступ только к нужным ресурсам
6. Зачем использовать разные API ключи для dev/staging/prod? >> Действия при разработке и тестировании не имеют доступа к боевым данным
7. Как генерировать криптографически безопасный API ключ в Python? >> `secrets.token_urlsafe(32)` ; генерирует 32 байта энтропии в Base64 URL-safe формате
8. Почему передача API ключа через query parameter опасна? >> Ключ попадает в логи веб-серверов, прокси, историю браузера и кэш – высокий риск утечки
9. К какому типу взаимодействия относятся API ключи? >> Service-to-service; также используются для доступа внешних разработчиков к API
10. Почему `random.choices()` нельзя использовать для API ключей? >> `random` не является криптографически стойким; предсказуем для атакующего
11. Зачем использовать стандартные префиксы (Stripe `sk-` , GitHub `ghp_` )? >> Позволяют secret scanners автоматически находить случайно закоммиченные ключи в публичных репозиториях
12. Что такое IP Whitelist для API ключей? >> Ограничение: запросы принимаются только с заранее определённых IP-адресов; защищает от использования украденного ключа
13. Что такое API ключ? >> Уникальная случайная строка с высокой энтропией; используется для аутентификации сервиса или клиента при каждом запросе
14. Зачем логировать использование каждого API ключа? >> Для отслеживания подозрительной активности, анализа нагрузки и расследования инцидентов
15. Как хранить API ключи в БД? >> Только хэш ( `sha256` ), никогда открытый ключ; аналогично паролям; ключ показывается пользователю только один раз при создании
16. Три способа передачи API ключа? >> Заголовок `Authorization: Bearer <key>` или `X-API-Key: <key>` (рекомендуется); query parameter (не рекомендуется); тело POST-запроса
17. Зачем хранить prefix ключа отдельно от хэша? >> Для идентификации ключа в интерфейсе и логах; восстановить оригинал из хэша невозможно
18. Что такое ротация ключей? >> Периодическая плановая замена ключей на новые; минимизирует ущерб при незамеченной утечке
