1. Как хранятся и пробрасываются секреты в Kubernetes? >> Объект `Secret` (тип `generic` ); `kubectl create secret generic app-secrets --from-literal=KEY=VALUE`
2. Какими способами передаются переменные окружения и секреты в контейнер Docker? >> `docker run -e SECRET_KEY=abc123` ; в Docker Compose через секцию `environment` ; ссылка на хост через `${VARIABLE_NAME}`
3. Что произойдёт в Pydantic Settings при отсутствии обязательного поля? >> Ошибка валидации при инициализации `Settings()` ; приложение падает явно
4. Разница `os.environ['KEY']` vs `os.environ.get('KEY')` ? >> `os.environ['KEY']` бросает `KeyError` при отсутствии – для обязательных переменных; `os.environ.get('KEY')` возвращает `None` – для опциональных
5. Как Python читает `.env` -файл? >> Только через библиотеку `python-dotenv` ; `load_dotenv()` загружает переменные в `os.environ` ; стандартный Python не читает `.env` автоматически
6. Специализированные решения для управления секретами? >> HashiCorp Vault (с аудитом доступа); AWS Secrets Manager; GCP Secret Manager
7. Что делать первым делом если секрет попал в Git? >> Немедленно отозвать или сменить скомпрометированный секрет; смена приоритетнее удаления из истории
8. Что такое `.env.example` ? >> Шаблон с именами нужных переменных без реальных значений; коммитится в репозиторий; помогает разработчикам настроить окружение
9. Главное правило работы с секретами? >> Никогда не хранить в исходном коде и репозитории; читать из переменных окружения
10. Что такое Pydantic Settings? >> Библиотека `pydantic-settings` ; класс наследует `BaseSettings` ; автоматически читает переменные из `os.environ` с валидацией типов
11. Почему нельзя хранить секреты в коде даже в приватном репозитории? >> Нарушение принципов безопасности; смена пароля требует пересборки кода; доступ к репозиторию = доступ к секретам
12. Что добавить в `.gitignore` для защиты секретов? >> `.env` , `.env.*` (кроме `.env.example` ), `*.key` , `secrets/`
13. Почему удаление секрета из истории Git недостаточно? >> Секрет мог быть уже перехвачен сканерами GitHub/GitLab или склонирован другими пользователями до удаления
14. Что такое секреты в разработке? >> Ключи API, пароли БД, приватные ключи, `SECRET_KEY` ; данные, которые нельзя раскрывать
15. Что делать если реальный ключ попал в `.env.example` ? >> Немедленно сменить ключ; удаление из истории Git не гарантирует безопасность
16. Инструменты для удаления секрета из истории Git? >> `git filter-branch` или `BFG Repo-Cleaner` ; но сначала – смена секрета
