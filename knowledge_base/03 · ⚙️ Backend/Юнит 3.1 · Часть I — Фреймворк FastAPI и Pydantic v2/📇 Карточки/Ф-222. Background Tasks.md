1. Как FastAPI выполняет синхронную функцию, переданную в BackgroundTasks? >> В отдельном потоке (threadpool), чтобы не блокировать event loop
2. В каком процессе выполняются задачи `BackgroundTasks` ? >> В том же процессе что и само приложение FastAPI
3. В чём разница масштабирования `BackgroundTasks` и Celery? >> `BackgroundTasks` масштабируется внутри процесса приложения; Celery – через отдельные воркеры
4. Является ли `BackgroundTasks` встроенным механизмом? >> Да – built-in, не требует внешних зависимостей
5. В чём разница настройки `BackgroundTasks` и Celery? >> `BackgroundTasks` работает без настройки; Celery требует брокер и воркеры
6. Можно ли использовать `BackgroundTasks` с `Depends` ? >> Да – объект можно внедрять в зависимости для переиспользуемой логики
7. Что передаётся первым аргументом в `add_task` ? >> Функция для выполнения в фоне
8. Есть ли в `BackgroundTasks` автоматический повтор при ошибке? >> Нет – механизм retry отсутствует
9. Для каких задач предпочтительнее `BackgroundTasks` ? >> Простые и быстрые операции без требований к отказоустойчивости
10. Какой метод регистрирует задачу в `BackgroundTasks` ? >> `add_task`
11. Что инжектируется в функцию-зависимость `get_notifier` ? >> Экземпляр `BackgroundTasks`
12. Является ли `BackgroundTasks` заменой Celery? >> Нет – упрощённая альтернатива только для лёгких задач
13. Что произойдет, если в функции BackgroundTasks в FastAPI возникнет необработанное исключение? >> Выведется в логи процесса; на уже отправленный ответ не повлияет
14. Что возвращает эндпоинт сразу после постановки задач в фон? >> HTTP-ответ – например объект созданного заказа
15. Что произойдёт с задачей `BackgroundTasks` если приложение упадёт до её завершения? >> Задача безвозвратно потеряется – не сохраняется в постоянном хранилище
16. Требуется ли Redis или Celery для `BackgroundTasks` ? >> Нет – задачи хранятся в памяти текущего процесса
17. Есть ли встроенный мониторинг задач в `BackgroundTasks` ? >> Нет – `BackgroundTasks` не предоставляет дашборда или отслеживания статусов (для мониторинга очередей используют Celery + Flower или метрики Prometheus)
18. Что такое `BackgroundTasks` в FastAPI? >> Встроенный инструмент для выполнения задач сразу после отправки HTTP-ответа клиенту
19. Как тяжёлая задача в `BackgroundTasks` влияет на FastAPI? >> Потребляет ресурсы того же процесса – снижает пропускную способность
20. Поддерживает ли `BackgroundTasks` задачи по расписанию? >> Нет – для этого нужен Celery Beat или аналог
21. Какие типы функций можно использовать в `BackgroundTasks` ? >> Синхронные ( `def` ) и асинхронные ( `async def` )
22. В какой именно момент выполняется фоновая задача, добавленная через BackgroundTasks в FastAPI? >> Строго после того, как ответ успешно отправлен клиенту
23. Как `BackgroundTasks` попадает в функцию эндпоинта? >> FastAPI автоматически внедряет его через DI при указании типа параметра
24. Как импортировать `BackgroundTasks` ? >> `from fastapi import BackgroundTasks`
25. Если нужно масштабировать фоновое выполнение независимо от веб-сервера, что выбрать? >> Celery
26. Как передать аргументы в фоновую функцию? >> Перечислить следом за функцией в `add_task` : `background_tasks.add_task(func, arg1, kwarg=val)`
27. Можно ли вызвать `add_task` несколько раз в одном эндпоинте? >> Да – планируется несколько задач последовательно
28. Когда Celery предпочтительнее `BackgroundTasks` ? >> Тяжёлые и длительные задачи с требованиями к мониторингу и гарантированному повтору
29. Ключевое преимущество `BackgroundTasks` перед обычным вызовом функции? >> Клиент получает ответ немедленно, не ожидая завершения фоновой функции
