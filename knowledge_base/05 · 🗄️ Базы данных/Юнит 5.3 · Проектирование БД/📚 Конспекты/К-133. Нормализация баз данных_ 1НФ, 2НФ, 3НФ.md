## Зачем нужна нормализация: три аномалии плоской таблицы

> **Принцип единого факта**: нормализация — это декомпозиция широкой таблицы на связанные сущности так, чтобы **каждый бизнес-факт хранился в базе ровно в одном месте**.

Хранение клиентов, городов и списков товаров в одной плоской таблице порождает три разрушительные аномалии:

- **Аномалия обновления**: при смене телефона клиента приходится обновлять 100 строк его заказов (с риском рассинхрона).
- **Аномалия вставки**: невозможно завести в базу новый склад или товар, пока на него нет хотя бы одного заказа.
- **Аномалия удаления**: удаление единственного заказа клиента случайно стирает и карточку самого клиента.

```text
└─────────────────────┬─────────────────────┘

                      ▼ Шаг 2: 2НФ

                      ▼ Шаг 3: 3НФ
┌───────────────────────────────────────────┐
│ Нет транзитивных связей неключевых полей  │
└───────────────────────────────────────────┘
```

## Сводная матрица 1НФ, 2НФ и 3НФ (формула Кодда)

Классическое правило Эдгара Кодда: *каждый неключевой атрибут должен зависеть от ключа (1НФ), всего ключа (2НФ) и ничего, кроме ключа (3НФ)*:

| Форма | Требование к схеме | Типичное нарушение | Способ устранения |
| :--- | :--- | :--- | :--- |
| **1НФ** | Все ячейки атомарны, нет списков через запятую и колонок `phone1`, `phone2` | В поле `items` лежит `'Мышь, Кабель'` | Вынести элементы в строки дочерней таблицы `order_items` |
| **2НФ** | 1НФ + каждый неключевой столбец зависит от **всего составного PK** целиком | В `order_items(order_id, prod_id)` хранится `prod_title` | Вынести `prod_title` в справочник `products(id, title)` |
| **3НФ** | 2НФ + **нет транзитивных зависимостей** между неключевыми полями | В `users(id, city, city_zip)` индекс зависит от города | Вынести города в таблицу `cities(id, name, zip)` |

## Первая нормальная форма (1НФ): атомарность ячеек

В 1НФ запрещено хранить массивы, JSON-списки или строки через запятую в одной ячейке, по которым требуется фильтрация или `JOIN`:

```python
import sqlite3

with sqlite3.connect(':memory:') as conn:
    conn.executescript('''
        CREATE TABLE order_items (ord_id INT, item TEXT);
        INSERT INTO order_items VALUES (1, 'Мышь'), (1, 'Коврик');
    ''')
    rows = conn.execute(
        'SELECT item FROM order_items WHERE ord_id = 1'
    ).fetchall()
    print('Позиции заказа в 1НФ:', rows)
```

## Вторая нормальная форма (2НФ): зависимость от всего ключа

Если первичный ключ составной `(order_id, product_id)`, то название и цена каталога товара зависят только от половинки ключа (`product_id`) и обязаны жить в таблице `products`:

```python
import sqlite3

with sqlite3.connect(':memory:') as conn:
    conn.executescript('''
        CREATE TABLE products (id INT PRIMARY KEY, name TEXT);
        CREATE TABLE items (ord_id INT, prod_id INT, qty INT,
            PRIMARY KEY (ord_id, prod_id));
        INSERT INTO products VALUES (10, 'SSD 1TB');
        INSERT INTO items VALUES (1, 10, 2);
    ''')
    sql = 'SELECT p.name, i.qty FROM items i JOIN products p ON i.prod_id = p.id'
    print('Схема во 2НФ:', conn.execute(sql).fetchall())
```

## Третья нормальная форма (3НФ): без транзитивных связей

Если в таблице `employees(id, dept_id, dept_phone)` телефон зависит от отдела (`id -> dept_id -> dept_phone`), возникает транзитивная зависимость — реквизиты отдела выносятся в `departments`:

```python
import sqlite3

with sqlite3.connect(':memory:') as conn:
    conn.executescript('''
        CREATE TABLE depts (id INT PRIMARY KEY, phone TEXT);
        CREATE TABLE emp (id INT PRIMARY KEY, name TEXT, d_id INT);
        INSERT INTO depts VALUES (1, '+7-495-001');
        INSERT INTO emp VALUES (10, 'Alice', 1);
    ''')
    sql = 'SELECT e.name, d.phone FROM emp e JOIN depts d ON e.d_id = d.id'
    print('Схема в 3НФ:', conn.execute(sql).fetchall())
```

## Полная сборка нормализованной схемы 3НФ через `JOIN`

В 3НФ изменение названия города или цены товара выполняется в **одной строке справочника**, а полная картина собирается на лету через `JOIN`:

```python
import sqlite3

with sqlite3.connect(':memory:') as conn:
    conn.executescript('''
        CREATE TABLE cities (id INT PRIMARY KEY, name TEXT);
        CREATE TABLE users (id INT PRIMARY KEY, u TEXT, c_id INT);
        INSERT INTO cities VALUES (1, 'Москва');
        INSERT INTO users VALUES (1, 'Bob', 1);
        UPDATE cities SET name = 'Санкт-Петербург' WHERE id = 1;
    ''')
    sql = 'SELECT u.u, c.name FROM users u JOIN cities c ON u.c_id = c.id'
    print(conn.execute(sql).fetchall())
```
