## Когда 3НФ становится узким местом на чтении (`Read-Heavy`)

> **Осознанный инженерный компромисс**: денормализация — это намеренное добавление дублирующих полей или агрегатов в уже нормализованную схему 3НФ, чтобы избавиться от тяжёлых `JOIN` и `GROUP BY` на горячих запросах чтения.

```text
Сравнение пути чтения в 3НФ и после денормализации:
┌────────────────────────────────────────────────┐
│ 1. Строгая 3НФ (каждый раз при открытии ленты):│
│    SELECT o.id, COUNT(i.id), SUM(i.price)      │
│    FROM orders o JOIN items i ON o.id = i.o_id │
│    GROUP BY o.id;  --> Дорогой JOIN + Агрегация│
├────────────────────────────────────────────────┤
│ 2. Денормализованная шапка заказа:             │
│    SELECT id, items_cnt, total_sum             │
│    FROM orders WHERE id = 42;                  │
│    --> Мгновенный Index Lookup за 0.1 мс!      │
└────────────────────────────────────────────────┘
```

## Четыре продакшен-паттерна денормализации

Где в реальных высоконагруженных системах отступают от 3НФ:

| Паттерн | Пример в схеме БД | Выигрыш на чтении | Как синхронизировать |
| :--- | :--- | :--- | :--- |
| **1. Кэш-счётчики (Counter Cache)** | `likes_count` в `posts`, `total_sum` в `orders` | Мгновенный вывод ленты без `COUNT(*)` | Триггер БД или инкремент в транзакции |
| **2. Исторический слепок (Snapshot)** | `price_at_purchase` прямо в `order_items` | Смена цены в каталоге не искажает старые чеки | Записывается один раз при покупке |
| **3. `MATERIALIZED VIEW`** | Физическая витрина отчётов по дням на диске | Тяжёлый отчёт считается раз в 15 минут | `REFRESH MATERIALIZED VIEW CONCURRENTLY` |
| **4. Копия атрибута родителя** | `author_name` внутри таблицы `comments` | Вывод 100 комментариев без `JOIN users` | Фоновое обновление при смене имени |

## Паттерн 1: хранение предрасчитанной суммы в шапке заказа

Чтение готового поля `total_cents` из строки заказа выполняется за один точечный поиск по первичному ключу без сканирования таблицы позиций:

```python
import sqlite3

with sqlite3.connect(':memory:') as conn:
    conn.execute(
        'CREATE TABLE orders (id INT PRIMARY KEY, total INT)'
    )
    conn.execute('INSERT INTO orders VALUES (42, 3500)')
    row = conn.execute(
        'SELECT id, total FROM orders WHERE id = 42'
    ).fetchone()
    print('Мгновенное чтение:', row)
```

## Паттерн 2: исторический слепок цены на момент покупки

Если хранить цену только в справочнике `products`, то завтрашнее подорожание товара задним числом изменит суммы всех прошлогодних чеков!

Поэтому в `order_items` обязательно дублируют `unit_price` на секунду оформления заказа:

```python
import sqlite3

with sqlite3.connect(':memory:') as conn:
    conn.executescript('''
        CREATE TABLE products (id INT, price INT);
        CREATE TABLE items (prod_id INT, buy_price INT);
        INSERT INTO products VALUES (1, 100);
        INSERT INTO items VALUES (1, 100);
        UPDATE products SET price = 250 WHERE id = 1;
    ''')
    sql = 'SELECT p.price, i.buy_price FROM products p JOIN items i ON p.id = i.prod_id'
    print('Текущая vs В чеке:', conn.execute(sql).fetchone())
```

## Цена денормализации: синхронизация в одной транзакции

Плата за быстрое чтение — усложнение записи: при добавлении новой позиции необходимо атомарно обновить и `order_items`, и `orders.total` внутри одной транзакции `with conn:`:

```python
import sqlite3

with sqlite3.connect(':memory:') as conn:
    conn.executescript('''
        CREATE TABLE orders (id INT PRIMARY KEY, total INT);
        CREATE TABLE items (ord_id INT, price INT);
        INSERT INTO orders VALUES (1, 0);
    ''')
    with conn:
        conn.execute('INSERT INTO items VALUES (1, 450)')
        conn.execute('UPDATE orders SET total = total + 450 WHERE id = 1')
    print('Заказ:', conn.execute('SELECT * FROM orders').fetchone())
```

## Автоматический пересчёт витрины через триггер СУБД

Чтобы прикладной код никогда не забывал обновить денормализованный счётчик, обновление вешают на триггер `AFTER INSERT` внутри самой базы данных:

```python
import sqlite3

with sqlite3.connect(':memory:') as conn:
    conn.executescript('''
        CREATE TABLE posts (id INT PRIMARY KEY, likes INT);
        CREATE TABLE pl (pid INT);
        INSERT INTO posts VALUES (1, 0);
        CREATE TRIGGER trg AFTER INSERT ON pl BEGIN
            UPDATE posts SET likes = likes + 1 WHERE id = NEW.pid;
        END;
        INSERT INTO pl VALUES (1);
    ''')
    print('Лайки:', conn.execute('SELECT likes FROM posts').fetchone())
```
