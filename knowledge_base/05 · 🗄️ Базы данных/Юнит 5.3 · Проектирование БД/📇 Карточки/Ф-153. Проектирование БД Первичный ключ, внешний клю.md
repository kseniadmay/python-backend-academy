1. Какое поведение при удалении родительской записи действует по умолчанию? >> `RESTRICT` – запрещает удаление, если на запись ссылаются дочерние
2. Что автоматически создаёт `PRIMARY KEY` ? >> Уникальный индекс; ускоряет поиск строк по первичному ключу
3. Что такое первичный ключ (PRIMARY KEY)? >> Столбец или набор столбцов, уникально идентифицирующий каждую строку таблицы; обязательно `UNIQUE` и `NOT NULL`
4. Что такое суррогатный ключ? >> Искусственно сгенерированный идентификатор (автоинкремент, UUID), не связанный с бизнес-данными
5. Что такое натуральный ключ? >> Ключ, основанный на реальных бизнес-данных: `email` , ИНН, ISBN
6. Что делает `ON DELETE SET NULL` ? >> При удалении родительской записи устанавливает `NULL` в соответствующих столбцах дочерних записей; столбец должен допускать `NULL`
7. Когда стоит использовать `ON DELETE CASCADE` ? >> Когда дочерние записи не имеют смысла без родительской: например, позиции заказа ( `order_items` ) при удалении заказа
8. Может ли столбец составного первичного ключа содержать `NULL` ? >> Нет; все столбцы составного первичного ключа обязательно `NOT NULL`
9. Что делает `ON UPDATE CASCADE` ? >> При изменении первичного ключа родителя автоматически обновляет значения внешнего ключа во всех дочерних записях
10. Как задать составной первичный ключ в SQL? >> `PRIMARY KEY (order_id, product_id)` в конце определения таблицы
11. Почему суррогатный ключ предпочтительнее натурального? >> Не меняется при изменении бизнес-данных; стабильнее как основа для внешних ключей
12. Когда стоит использовать `ON DELETE SET NULL` ? >> Когда дочерняя запись сохраняет смысл без связи с родителем: например, `author_id` статьи при удалении автора
13. Что делает `ON DELETE SET DEFAULT` ? >> При удалении родительской записи присваивает дочерним записям значение по умолчанию ( `DEFAULT` )
14. Является ли автоинкрементный `id` натуральным ключом? >> Нет; это суррогатный ключ – он не несёт бизнес-смысла
15. Может ли первичный ключ содержать `NULL` ? >> Нет; `PRIMARY KEY` автоматически накладывает ограничения `UNIQUE` и `NOT NULL`
16. Что такое внешний ключ (FOREIGN KEY)? >> Столбец, ссылающийся на первичный ключ другой таблицы; обеспечивает ссылочную целостность
17. Для чего в PostgreSQL используется `SERIAL` ? >> Создаёт автоинкрементный целочисленный суррогатный ключ; эквивалент `INTEGER` + `DEFAULT nextval(sequence)` ; в современном PostgreSQL предпочтителен `GENERATED ALWAYS AS IDENTITY`
18. Что такое составной первичный ключ? >> Первичный ключ, состоящий из двух и более столбцов; все столбцы обязательно `NOT NULL`
19. Что такое ссылочная целостность? >> Состояние БД, при котором все значения внешних ключей указывают на существующие строки родительской таблицы
20. Сколько первичных ключей может быть в одной таблице? >> Только один; но он может быть составным (включать несколько столбцов)
21. Что произойдёт при вставке `user_id = 5` , если в `users` нет записи с `id = 5` ? >> БД выдаст ошибку нарушения ограничения внешнего ключа ( `foreign key violation` )
22. Обязательно ли внешний ключ должен ссылаться именно на `PRIMARY KEY` ? >> По стандарту SQL – на уникальный идентификатор ( `PRIMARY KEY` или `UNIQUE` ); на практике чаще всего `PRIMARY KEY`
23. В чём риск использования `email` как первичного ключа? >> Пользователь может сменить email; потребуется обновление всех внешних ключей во всех дочерних таблицах
24. Что делает `ON DELETE CASCADE` ? >> При удалении родительской записи автоматически удаляет все связанные дочерние записи
25. Как называется таблица, на которую ссылается внешний ключ? >> Родительская (referenced table)
26. Как называется таблица, в которой определён внешний ключ? >> Дочерняя (referencing table)
