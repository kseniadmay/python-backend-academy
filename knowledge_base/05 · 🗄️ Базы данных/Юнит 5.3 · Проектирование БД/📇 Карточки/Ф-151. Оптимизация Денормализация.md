1. Какое «золотое правило» применения денормализации? >> Сначала нормализовать → измерить производительность → выявить узкое место → только тогда денормализовать конкретное проблемное место
2. Для чего используются JSON-поля как приём денормализации? >> Хранение связанных сущностей (например, товаров заказа) в одной строке; позволяет получить все данные одним запросом без `JOIN`
3. Что такое аномалия обновления в денормализованной схеме? >> Необходимость обновлять одни и те же данные в нескольких местах одновременно; например, `email` продублирован в 1000 заказов – при смене нужно обновить все
4. Каков минус JSON-полей в реляционной БД? >> Сложнее поддерживать строгость структуры; поиск по вложенным элементам труднее; нельзя использовать FK-ограничения
5. Каков главный минус дублирования столбцов? >> Аномалии обновления: при изменении данных в исходной таблице нужно обновить все дублирующие записи; риск рассинхронизации
6. Верно ли, что денормализацию следует применять ко всей БД сразу? >> Нет; денормализуют только конкретные проблемные места, подтверждённые профилированием
7. Что такое предвычисленный агрегат? >> Заранее рассчитанный результат агрегатной функции, хранящийся в таблице; например, `orders_count` у пользователя вместо `COUNT` при каждом запросе
8. Как влияет денормализация агрегатов на скорость `INSERT` ? >> Снижает её: при каждой вставке нужно обновлять дополнительные агрегатные поля
9. В чём разница между OLAP и OLTP? >> OLTP – частые небольшие транзакции чтения/записи (бизнес-операции); OLAP – аналитика и отчёты по большим объёмам данных, преимущественно чтение
10. Для какого типа систем денормализация более характерна? >> OLAP (аналитические системы); OLTP (транзакционные) требуют строгой консистентности и чаще остаются нормализованными
11. Какие данные являются хорошими кандидатами для денормализации? >> Данные, не изменяющиеся после создания (история заказов, архивные логи); для них нет риска аномалий обновления
12. В чём суть приёма «дублирование столбцов»? >> Хранение данных из связанной таблицы напрямую в основной; например, `user_name` в таблице `orders` вместо `JOIN` с `users`
13. Какую роль играют триггеры в денормализованной схеме? >> Автоматически поддерживают актуальность дублированных или агрегированных данных при изменении исходных
14. Какие три основных приёма денормализации существуют? >> Дублирование столбцов (копирование данных из связанной таблицы); предвычисленные агрегаты (хранение `COUNT` / `SUM` ); JSON-поля (вложенные сущности в одной строке)
15. Как поддерживать актуальность предвычисленных агрегатов? >> Через триггеры БД (автоматически при `INSERT` / `UPDATE` / `DELETE` ) или логику на стороне приложения
