1. Когда снимается блокировка, установленная через `FOR UPDATE` или `UPDATE` ? >> Только после `COMMIT` или `ROLLBACK` всей транзакции
2. Верно ли, что короткие транзакции полностью исключают дедлоки? >> Нет; они снижают вероятность, но не исключают полностью
3. Что должно делать приложение при получении `ERROR: deadlock detected` ? >> Перехватить ошибку и повторить всю транзакцию ( `retry` )
4. Алгоритм разрешения дедлока в PostgreSQL? >> Обнаружение цикла → выбор жертвы → откат жертвы → ошибка приложению → приложение делает retry
5. Что такое `lock_timeout` ? >> Параметр, ограничивающий время ожидания блокировки; при истечении транзакция прерывается с ошибкой вместо бесконечного ожидания
6. Что PostgreSQL делает при обнаружении дедлока? >> Выбирает одну транзакцию-«жертву» и принудительно откатывает её с ошибкой `ERROR: deadlock detected`
7. Почему `SELECT FOR UPDATE ORDER BY id` предотвращает дедлоки? >> Гарантирует детерминированный порядок захвата блокировок; вторая транзакция ждёт первую на самом первом ресурсе, не создавая цикла
8. Что произойдёт, если в транзакции сначала обновить `id=10` , потом `id=5` ? >> Нарушится единый порядок блокировок; если другая транзакция делает наоборот – возникнет дедлок
9. Что делает `SELECT ... FOR UPDATE` ? >> Захватывает строки блокировкой до `COMMIT` / `ROLLBACK` ; другие транзакции не могут изменить эти строки до снятия блокировки
10. Что такое дедлок (deadlock)? >> Ситуация, когда две или более транзакции бесконечно ждут друг друга, удерживая ресурсы, нужные другим
11. Как установить `lock_timeout` на 5 секунд? >> `SET lock_timeout = '5s';`
12. Почему лучше блокировать минимальное количество строк? >> Меньше вероятность пересечения с другими транзакциями; ниже риск дедлока и выше общая производительность
13. Как PostgreSQL обнаруживает дедлок? >> Периодически проверяет граф блокировок на наличие циклов ожидания ( `wait cycles` )
14. Как правильно заблокировать строки `id=1` и `id=2` для обновления? >> `SELECT * FROM accounts WHERE id IN (1, 2) ORDER BY id FOR UPDATE;`
15. Самый эффективный способ предотвращения дедлоков? >> Всегда обращаться к ресурсам в одном и том же порядке; если все транзакции блокируют строки по возрастанию ID – цикл не образуется
16. Является ли дедлок фатальной ошибкой для БД? >> Нет; это штатная ситуация, разрешаемая откатом одной транзакции; другая продолжает работу
17. Почему не рекомендуется блокировать всю таблицу? >> Блокировка таблицы останавливает все конкурирующие операции и резко снижает производительность системы
18. Может ли дедлок возникнуть при трёх транзакциях? >> Да; если A ждёт B, B ждёт C, C ждёт A – образуется цикл
