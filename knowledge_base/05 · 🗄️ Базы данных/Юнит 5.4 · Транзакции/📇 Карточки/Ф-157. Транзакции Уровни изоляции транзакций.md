1. Что гарантирует `REPEATABLE READ` ? >> Устраняет Dirty Read и Non-repeatable Read; снимок данных фиксируется на начало транзакции; Phantom Read теоретически возможен по стандарту
2. Что гарантирует `SERIALIZABLE` ? >> Устраняет все аномалии; транзакции выполняются так, как будто строго последовательно; самый медленный уровень
3. Что такое Non-repeatable Read? >> Повторное чтение одной строки в рамках одной транзакции возвращает разные значения; другая транзакция изменила и зафиксировала строку между чтениями
4. Как изменить уровень изоляции для текущей транзакции в PostgreSQL? >> `SET TRANSACTION ISOLATION LEVEL REPEATABLE READ;` выполнить после `BEGIN` до первого запроса
5. Какой уровень изоляции используется по умолчанию в PostgreSQL? >> `READ COMMITTED`
6. Какие четыре уровня изоляции определены стандартом SQL? >> `READ UNCOMMITTED` → `READ COMMITTED` → `REPEATABLE READ` → `SERIALIZABLE`
7. Что такое SSI? >> Serializable Snapshot Isolation – механизм PostgreSQL для реализации `SERIALIZABLE` через снимки с проверкой конфликтов; эффективнее традиционных блокировок
8. Что допускает `READ UNCOMMITTED` ? >> Все аномалии включая Dirty Read; транзакция видит незафиксированные изменения других; на практике почти не используется
9. Какой уровень изоляции используется по умолчанию в MySQL? >> `REPEATABLE READ`
10. На каком уровне гарантированно устраняется Phantom Read во всех СУБД? >> `SERIALIZABLE`
11. Что гарантирует `READ COMMITTED` ? >> Устраняет Dirty Read; транзакция видит только зафиксированные изменения; Non-repeatable Read и Phantom Read возможны
12. На каком уровне впервые устраняется Dirty Read? >> `READ COMMITTED`
13. Что такое Phantom Read? >> Повторный запрос с тем же условием возвращает разное количество строк; другая транзакция вставила или удалила строки, подходящие под условие
14. В чём отличие Non-repeatable Read от Phantom Read? >> Non-repeatable Read – изменились данные в существующей строке; Phantom Read – изменилось количество строк, подходящих под условие
15. Сводная таблица аномалий по уровням изоляции? >> `READ UNCOMMITTED` : Dirty✓ NR✓ Phantom✓; `READ COMMITTED` : Dirty✗ NR✓ Phantom✓; `REPEATABLE READ` : Dirty✗ NR✗ Phantom✓*; `SERIALIZABLE` : Dirty✗ NR✗ Phantom✗ (*в PostgreSQL устранён)
16. Что такое Dirty Read? >> Транзакция читает незафиксированные изменения другой транзакции; если та откатится – прочитанные данные окажутся несуществующими
17. На каком уровне впервые устраняется Non-repeatable Read? >> `REPEATABLE READ`
18. Что происходит при конфликте двух транзакций на уровне `SERIALIZABLE` ? >> Одна из транзакций завершается с ошибкой; приложение обязано повторить транзакцию
19. Что определяют уровни изоляции транзакций? >> Какие аномалии параллельного выполнения допустимы; чем выше уровень – тем строже изоляция и ниже производительность
20. Устраняет ли PostgreSQL Phantom Read на уровне `REPEATABLE READ` ? >> Да; реализация через MVCC в PostgreSQL исключает Phantom Read на этом уровне – отличие от стандарта SQL
