1. Когда следует использовать `UNION ALL`? >> Когда дубликаты допустимы или гарантированно не возникнут – для оптимизации производительности
2. Как в `UNION ALL` различить источник данных для каждой строки? >> Добавить дополнительный столбец с константой: `SELECT name, 'customer' AS type FROM customers UNION ALL SELECT name, 'supplier' AS type FROM suppliers`
3. Для чего используются `UNION` и `UNION ALL` в SQL? >> Для объединения результирующих наборов нескольких `SELECT` -запросов в один
4. Какой оператор работает быстрее: `UNION` или `UNION ALL`? >> `UNION ALL` – не тратит ресурсы на поиск и удаление дубликатов
5. Если одно и то же лицо есть и в таблице клиентов, и в таблице поставщиков, сколько раз оно появится в результате `UNION`? >> Один раз – `UNION` удалит дубликат
6. В чём различие между операторами `UNION` и `UNION ALL` при объединении результирующих выборок в SQL? >> `UNION` автоматически удаляет дублирующиеся строки, а `UNION ALL` объединяет выборки без дедупликации, сохраняя все строки
7. Что произойдёт, если типы данных в объединяемых `SELECT` несовместимы? >> Ошибка выполнения запроса
8. Как `UNION ALL` обрабатывает дублирующиеся строки? >> Сохраняет все строки включая дубликаты – дедупликация не выполняется
9. Почему `UNION` медленнее `UNION ALL`? >> `UNION` выполняет дедупликацию: сравнивает все строки результата, что требует дополнительных ресурсов
10. Как `UNION` обрабатывает дублирующиеся строки? >> Удаляет все повторяющиеся строки, оставляя только уникальные
11. Сколько строк вернёт операция `UNION` для двух таблиц по 10 строк, содержащих 2 одинаковые строки? >> 18 строк – 2 дубликата удаляются
12. Когда следует использовать `UNION`? >> Когда дубликаты в итоговом результате недопустимы
13. Сколько строк вернёт операция `UNION ALL` для двух таблиц по 10 строк, содержащих 2 одинаковые строки? >> 20 строк – все строки сохраняются
14. Какие два требования предъявляются к объединяемым `SELECT`-запросам при использовании `UNION`, `INTERSECT` и `EXCEPT`? >> Одинаковое количество столбцов в каждом запросе и совместимые типы данных соответствующих столбцов в одинаковом порядке
15. Если в объединяемых таблицах гарантированно нет дубликатов, какой оператор эффективнее? >> `UNION ALL` – даёт тот же результат без лишних затрат на дедупликацию
16. Какой теоретико-множественный оператор SQL возвращает только строки, присутствующие в ОБОИХ запросах? >> `INTERSECT` (пересечение); по умолчанию автоматически удаляет дубликаты аналогично UNION.
17. Какой оператор SQL возвращает строки из первого запроса, которых НЕТ во втором запросе? >> `EXCEPT` (в PostgreSQL/SQLite) или `MINUS` (в Oracle); реализует теоретико-множественную разность $A ∖ B$.
