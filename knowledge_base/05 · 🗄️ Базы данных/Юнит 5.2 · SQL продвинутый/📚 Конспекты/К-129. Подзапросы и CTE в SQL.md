## Классификация подзапросов по форме и связности

> **Некоррелированный против коррелированного**: некоррелированный подзапрос вычисляется **один раз** перед основным запросом, а коррелированный ссылается на внешнюю строку и перезапускается на каждой строке как вложенный цикл.

```text
Три формы подзапросов по размерности результата:
┌────────────────────────────────────────────────┐
│ 1. Скалярный (1 строка × 1 столбец):           │
│    WHERE salary > (SELECT AVG(salary) FROM emp)│
├────────────────────────────────────────────────┤
│ 2. Списочный (N строк × 1 столбец):            │
│    WHERE dept_id IN (SELECT id FROM active_dep)│
├────────────────────────────────────────────────┤
│ 3. Табличный (N строк × M столбцов):           │
│    FROM (SELECT dept, SUM(s) FROM emp          │
│          GROUP BY dept) AS sub                 │
└────────────────────────────────────────────────┘
```

## Скалярный подзапрос для сравнения со средним

Некоррелированный скалярный подзапрос в `WHERE` сначала вычисляет единственное число (например, средний чек), после чего внешний запрос фильтрует таблицу по этому порогу:

```python
import sqlite3

with sqlite3.connect(':memory:') as conn:
    conn.execute('CREATE TABLE emp (name TEXT, sal INT)')
    conn.executemany(
        'INSERT INTO emp VALUES (?, ?)',
        [('Ann', 100), ('Bob', 200), ('Cid', 300)],
    )
    sql = '''
    SELECT name, sal FROM emp
    WHERE sal > (SELECT AVG(sal) FROM emp)
    '''
    print('Выше среднего:', conn.execute(sql).fetchall())
```

## Смертельная ловушка `NOT IN` при наличии `NULL`

Почему запрос `WHERE id NOT IN (SELECT manager_id FROM users)` возвращает **0 строк**, если среди `manager_id` встретился хотя бы один `NULL`?

Выражение `id NOT IN (1, NULL)` раскрывается в `id != 1 AND id != NULL`, что даёт `TRUE AND UNKNOWN` $\implies$ `UNKNOWN`, обнуляя всю выборку:

| Конструкция | Поведение при `NULL` в подзапросе | Short-Circuit выход | Рекомендация |
| :--- | :--- | :--- | :--- |
| `WHERE id IN (...)` | Безопасно (игнорирует `NULL`) | Зависит от плана | Для небольших списков |
| `WHERE id NOT IN (...)` | 💥 Возвращает **0 строк**, если есть `NULL` | ❌ Сканирует всё | ❌ Избегать на nullable-полях |
| `WHERE NOT EXISTS (...)` | ✅ Безопасно (проверяет факт строки) | ✅ Да (`LIMIT 1`) | ✅ Стандарт в продакшене |

## Защита от `NULL` через `WHERE NOT EXISTS`

Предикат `NOT EXISTS` проверяет существование строки в подзапросе на уровне булевой логики, поэтому `NULL` в соседних строках никогда не ломает фильтрацию:

```python
import sqlite3

with sqlite3.connect(':memory:') as conn:
    conn.execute('CREATE TABLE u (id INT, mgr INT)')
    conn.executemany(
        'INSERT INTO u VALUES (?, ?)',
        [(1, None), (2, 1), (3, 1)],
    )
    sql = (
        'SELECT a.id FROM u a WHERE NOT EXISTS '
        '(SELECT 1 FROM u b WHERE b.mgr = a.id)'
    )
    print('Листья:', conn.execute(sql).fetchall())
```

## Именованные табличные выражения `CTE` (`WITH`)

Конструкция **`WITH имя AS (...)`** (Common Table Expression) разбивает громоздкий вложенный запрос на линейные именованные шаги сверху вниз:

```python
import sqlite3

with sqlite3.connect(':memory:') as conn:
    conn.execute('CREATE TABLE s (d TEXT, v INT)')
    conn.executemany(
        'INSERT INTO s VALUES (?, ?)',
        [('IT', 400), ('IT', 200), ('HR', 100)],
    )
    sql = (
        'WITH t AS (SELECT d, SUM(v) AS sv FROM s GROUP BY d) '
        'SELECT d, sv FROM t WHERE sv >= 500'
    )
    print(conn.execute(sql).fetchall())
```

## Обход деревьев произвольной глубины через `WITH RECURSIVE`

Добавление ключевого слова **`RECURSIVE`** к `WITH` позволяет обходить иерархии (категории каталога, оргструктуру, ветки комментариев) за один SQL-запрос из якоря и рекурсивного шага через `UNION ALL`:

```python
import sqlite3

with sqlite3.connect(':memory:') as conn:
    conn.execute('CREATE TABLE c (id INT, p INT, n TEXT)')
    conn.executescript(
        "INSERT INTO c VALUES (1, NULL, 'Root'), (2, 1, 'SQL');"
    )
    sql = (
        'WITH RECURSIVE t AS (SELECT id, n FROM c WHERE p IS NULL '
        'UNION ALL SELECT c.id, c.n FROM c JOIN t ON c.p=t.id) '
        'SELECT n FROM t'
    )
    print(conn.execute(sql).fetchall())
```
