1. Что такое `PostGIS` ? >> Расширение PostgreSQL для работы с географическими данными и пространственными запросами
2. В каких сценариях при проектировании проекта разработчики отдают предпочтение СУБД MySQL перед PostgreSQL? >> Legacy-проекты на MySQL; простые CRUD-приложения; LAMP-стек
3. Как PostgreSQL хранит логические значения? >> Нативный тип `BOOLEAN` со значениями `TRUE` / `FALSE`
4. Что даёт нативный тип `UUID` в PostgreSQL? >> Компактное хранение (16 байт), встроенная валидация, удобные функции `gen_random_uuid()`
5. В каких операциях MySQL традиционно быстрее PostgreSQL? >> Простые операции чтения ( `SELECT` ) на несложных запросах
6. Как MySQL хранит логические значения? >> `TINYINT(1)` ; нативного `BOOLEAN` нет; `0` – false, `1` – true
7. Какой движок MySQL не поддерживает транзакции? >> `MyISAM` ; транзакции поддерживает только `InnoDB`
8. Как создать автоинкрементный PK в MySQL? >> `id INT AUTO_INCREMENT PRIMARY KEY`
9. Что такое механизм MVCC (Multi-Version Concurrency Control) в PostgreSQL? >> Многоверсионное управление конкурентным доступом: при изменении строки создаётся её новая версия, благодаря чему читающие транзакции никогда не блокируют пишущие, а пишущие — читающие.
10. В чём преимущество MVCC PostgreSQL перед MySQL? >> Более последовательная реализация; лучше подходит для высокой конкурентной записи
11. С какой версии MySQL поддерживает JSON? >> MySQL 5.7; PostgreSQL поддерживает `JSON` и `JSONB` уже давно
12. Как MySQL ведёт себя при `GROUP BY` без всех неагрегируемых столбцов? >> Выполняет запрос, выбирая произвольное значение для пропущенных столбцов; PostgreSQL выдаёт ошибку
13. Уровень изоляции транзакций по умолчанию в PostgreSQL? >> `READ COMMITTED`
14. Какая СУБД строже следует стандарту SQL? >> PostgreSQL; MySQL допускает нестандартное поведение (например, `GROUP BY` без всех неагрегируемых столбцов)
15. Почему PostgreSQL называют объектно-реляционной СУБД? >> Поддерживает сложные типы данных (массивы, `JSONB` , `hstore` ), пользовательские типы, наследование таблиц
16. Уровень изоляции транзакций по умолчанию в MySQL (InnoDB)? >> `REPEATABLE READ`
17. В чём преимущество `JSONB` над `JSON` в PostgreSQL? >> Бинарный формат: быстрее при чтении, поддерживает `GIN` -индексы, удаляет дубли ключей
18. Каким образом СУБД MySQL эффективно хранит 128-битные идентификаторы UUID при отсутствии нативного типа? >> `VARCHAR(36)` или `BINARY(16)` ; нативного типа UUID нет
19. В каких инженерных сценариях рекомендуется выбрать СУБД PostgreSQL вместо MySQL? >> Новые проекты; сложные запросы и аналитика; нужны `JSONB` , массивы, `UUID` , `PostGIS` , полнотекстовый поиск с русским языком
20. Для каких задач PostgreSQL подходит лучше MySQL? >> Сложные аналитические запросы, высокая конкурентная запись, специфические типы данных ( `JSONB` , `UUID` , массивы, полнотекстовый поиск)
21. Как PostgreSQL реализует полнотекстовый поиск на русском языке? >> Через встроенные словари и `tsvector` / `tsquery` ; поддерживает морфологию; MySQL `FULLTEXT` такого не поддерживает
22. Как создать автоинкрементный PK в PostgreSQL? >> `SERIAL PRIMARY KEY` или `INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY` ; второй вариант предпочтительнее с PostgreSQL 10+
