1. Как откатить последнюю миграцию в Alembic? >> `alembic downgrade -1` ; на один шаг назад
2. Как создать файлы миграций в Django? >> `python manage.py makemigrations` ; Django сравнивает текущие модели с последней миграцией и генерирует diff
3. Как откатить Django до конкретной миграции? >> `python manage.py migrate <app> 0003` ; откатывает до состояния после миграции `0003`
4. Как инициализировать Alembic в проекте? >> `alembic init alembic` ; создаёт директорию с конфигурацией и папкой версий
5. Что такое миграции БД? >> Механизм версионирования схемы базы данных; позволяют изменять структуру таблиц, откатывать изменения и синхронизировать схему между разработчиками и средами
6. Какие два инструмента миграций используются в Python? >> Django Migrations (встроен в Django) и Alembic (для SQLAlchemy)
7. Как откатить до конкретной ревизии в Alembic? >> `alembic downgrade abc123` ; где `abc123` – идентификатор ревизии
8. Как просмотреть статус всех миграций в Django? >> `python manage.py showmigrations` ; показывает применённые `[X]` и не применённые `[ ]`
9. Что такое ревизия в Alembic? >> Уникальный идентификатор версии схемы БД; каждый файл миграции имеет свой `revision` и `down_revision`
10. Что такое `upgrade()` и `downgrade()` в Alembic? >> `upgrade()` – применяет изменения; `downgrade()` – отменяет их; оба должны быть реализованы для каждой миграции
11. Почему при добавлении поля в большую таблицу рекомендуется `null=True` ? >> Избегает длительной блокировки таблицы при добавлении колонки с `NOT NULL` без default; сначала добавляют с `null=True` , заполняют, затем добавляют ограничение
12. Почему миграции нужно коммитить в Git? >> Миграции – часть кода проекта; без них другие разработчики и серверы не смогут воспроизвести состояние схемы
13. Как применить все миграции в Alembic? >> `alembic upgrade head` ; `head` – состояние, когда все миграции применены
14. Главное правило работы с миграциями? >> Никогда не редактировать уже применённые миграции; создавать новые
15. Как создать миграцию в Alembic автоматически? >> `alembic revision --autogenerate -m "описание"` ; сравнивает метаданные SQLAlchemy с текущим состоянием БД
16. Что такое `dependencies` в файле миграции Django? >> Список миграций, от которых зависит текущая; определяет порядок применения
17. Как разрешить конфликт миграций в Django (два разработчика создали миграции одновременно)? >> `python manage.py makemigrations --merge`
18. Как проверить корректность миграции перед production? >> `python manage.py sqlmigrate <app> <номер>` в Django; `alembic upgrade head --sql` в Alembic – показывают SQL без выполнения
19. Как применить миграции в Django? >> `python manage.py migrate` ; применяет все ожидающие миграции для всех приложений
20. Что делают `op.add_column()` и `op.drop_column()` ? >> `add_column` – добавляет колонку в таблицу; `drop_column` – удаляет; используются внутри `upgrade()` / `downgrade()`
21. Как разрешаются конфликты в Alembic? >> Вручную; в отличие от Django нет автоматической команды merge
22. Когда запускать миграции при деплое? >> До развёртывания нового кода (pre-deploy); иначе новый код может обращаться к несуществующим полям
23. Как просмотреть SQL конкретной миграции Django? >> `python manage.py sqlmigrate <app> <номер>` ; полезно перед запуском на production
