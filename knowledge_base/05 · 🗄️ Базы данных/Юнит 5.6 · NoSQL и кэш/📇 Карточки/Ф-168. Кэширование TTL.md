1. Какой TTL рекомендуется для часто меняющегося списка продуктов? >> 300 секунд (5 минут)
2. Можно ли установить TTL для существующего ключа без перезаписи значения? >> Да: `r.expire('key', seconds)` или `r.expireat('key', timestamp)`
3. Для данных, почти не меняющихся, какой порядок TTL подходит? >> Сутки (86400 секунд) и более
4. Что означает `-1` при `r.ttl('key')` ? >> Ключ существует, но TTL не установлен (постоянный)
5. Если `base_ttl=3600` и Jitter `±300` , в каком диапазоне будут истекать ключи? >> От 3300 до 3900 секунд
6. Что происходит с ключом после истечения TTL? >> Redis автоматически удаляет его
7. Если `r.ttl('key')` вернул `-2` , существует ли ключ? >> Нет (`-2` означает, что ключа не существует или он уже истёк; `-1` означает ключ без TTL)
8. Какой TTL рекомендуется для статического контента? >> 86400 секунд (1 день)
9. Какой TTL рекомендуется для профиля пользователя ( `user_profile` )? >> 3600 секунд (1 час) – данные меняются редко
10. `r.set('key', 'value', px=60000)` – каков TTL в минутах? >> 1 минута
11. Может ли Redis удалить постоянный ключ (без TTL) при нехватке памяти? >> Да, в зависимости от политики вытеснения ( `maxmemory-policy` ); TTL и eviction – независимые механизмы
12. Какой TTL рекомендуется для сессии пользователя ( `user_session` )? >> 604800 секунд (7 дней)
13. Какой аргумент `r.set` устанавливает TTL в миллисекундах? >> `px` : `r.set('key', 'value', px=60000)`
14. Для чего в ключе `products:category:{category_id}` используется двоеточие? >> Для логического разделения пространств имён – традиция в Redis
15. Как изменяется нагрузка на БД при использовании Jitter? >> Становится равномерной (размазанной) во времени
16. Что такое Jitter (рассеивание TTL)? >> Добавление случайного отклонения к базовому TTL чтобы разнести истечения ключей во времени
17. Какой TTL рекомендуется для leaderboard в режиме real-time? >> 10 секунд
18. `r.pttl` vs `r.ttl` – в чём разница? >> `r.ttl` возвращает секунды, `r.pttl` – миллисекунды
19. Какую проблему предотвращает Jitter? >> Cache Stampede – массовое одновременное истечение ключей и пиковую нагрузку на БД
20. Если `jitter=60` , каков максимальный разброс TTL? >> 120 секунд (от `-60` до `+60` )
21. Что произойдёт, если все ключи имеют одинаковый жёсткий TTL? >> Все cache miss произойдут одновременно – резкая пиковая нагрузка на БД
22. Для чего используется аргумент `exat` в `r.set` ? >> Для установки конкретного Unix timestamp истечения ключа
23. В каких единицах возвращает результат `r.ttl()` ? >> В секундах
24. Как установить истечение ключа по конкретному Unix timestamp? >> `r.expireat('key', timestamp)`
25. Зачем в `set_with_jitter` используется `max(ttl, 1)` ? >> Чтобы не установить нулевой или отрицательный TTL при большом отрицательном значении Jitter
26. Какую функцию из модуля `random` используют для вычисления отклонения? >> `random.randint(-jitter, jitter)`
27. Какая команда возвращает оставшееся время жизни ключа в миллисекундах? >> `r.pttl('key')`
28. Какой TTL рекомендуется для результатов поиска? >> 600 секунд (10 минут) – компромисс между актуальностью и нагрузкой
29. Какой аргумент `r.set` устанавливает TTL в секундах? >> `ex` : `r.set('key', 'value', ex=3600)`
30. Что означает TTL в контексте Redis? >> Time To Live – время жизни ключа; по истечении Redis автоматически удаляет его
31. Что означает `1700000000` в `r.expireat('key', 1700000000)` ? >> Unix timestamp – конкретный момент времени
32. Зачем `QuerySet` преобразуется в `list(products)` перед кэшированием? >> Чтобы сохранить конкретные данные, а не ленивый объект запроса, который нельзя сериализовать
33. `cache.set(key, value, timeout=CACHE_TTL['product_list'])` – каков TTL? >> 300 секунд
34. Почему для курсов валют устанавливается короткий TTL (60 секунд)? >> Это высокодинамичные данные, требующие частого обновления
35. `r.set('key', 'value', ex=3600)` – каков TTL? >> 3600 секунд (1 час)
36. Какой шаблон ключа используется для категории товаров? >> `f'products:category:{category_id}'`
37. Если `base_ttl=60` , а `random.randint` вернул `10` , каков итоговый TTL? >> 70 секунд
38. Если `base_ttl=3600` , а `random.randint` вернул `-60` , каков итоговый TTL? >> 3540 секунд
39. Как удалить TTL и сделать ключ постоянным? >> `r.persist('key')` ; если ключ уже постоянный – ничего не изменится
40. Что означает `-2` при `r.ttl('key')` ? >> Ключ не существует
41. Какая команда устанавливает TTL для уже существующего ключа? >> `r.expire('key', seconds)`
