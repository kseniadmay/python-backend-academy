## Зачем каждому ключу кэша нужен `TTL` (Time-To-Live)?

> **Срок годности на пакете молока в холодильнике**: **TTL (Time-To-Live)** — это встроенный таймер самоуничтожения ключа в Redis: когда время выходит, ключ автоматически исчезает и освобождает оперативную память.

Оперативная память (`RAM`) на сервере стоит дорого и строго ограничена. Если складывать в Redis сессии пользователей, одноразовые SMS-коды и кэш без срока годности, память переполнится, и Redis начнёт падать с `OOM (Out Of Memory)` — либо отдавать безнадёжно устаревшие данные.

```text
Коды возврата команды TTL key в Redis (частый вопрос на собеседовании!):
  ├── TTL > 0  (например, 3590)  --> Ключ существует, до автоудаления осталось 3590 секунд
  ├── TTL == -1                  --> Ключ существует, но у него НЕТ срока жизни (живёт вечно!)
  └── TTL == -2                  --> Ключа НЕ существует (уже протух и удалён или не создавался)
```

## Команды управления временем жизни TTL в Redis

| Команда Redis / redis-py | Действие | Применение |
| :--- | :--- | :--- |
| **`r.set(key, val, ex=3600)`** | Атомарная запись с TTL в **секундах** | Основной способ записи в кэш |
| **`r.set(key, val, px=500)`** | Атомарный TTL в **миллисекундах** | Распределенные блокировки, троттлинг |
| **`r.set(key, val, exat=ts)`** | Удаление в конкретный **Unix timestamp** | Фиксированное истечение по расписанию |
| **`r.expire(key, 60)`** | Установка TTL на существующий ключ | Продление сессии или счетчика `INCR` |
| **`r.ttl(key)` / `r.pttl(key)`** | Остаток жизни в секундах (`-1` = вечный, `-2` = нет) | Диагностика кэша и `Retry-After` |
| **`r.persist(key)`** | Снятие таймера (ключ становится вечным) | Отмена инвалидации |

## Ловушки сброса TTL: неатомарный SET и флаг keepttl

1. **Неатомарная установка TTL**: раздельный вызов `r.set('k', 'v')` и `r.expire('k', 60)` при сетевом сбое оставляет ключ в памяти навсегда. Всегда используйте параметр `ex=...` внутри `r.set()`.
2. **Сброс таймера при перезаписи**: повторный вызов `r.set('k', 'new_val')` без аргумента `ex` или флага `keepttl=True` сбрасывает ранее установленный таймер TTL, делая ключ бессмертным.

## Проблема Cache Avalanche и сглаживание через TTL Jitter

При одновременном истечении TTL у тысяч ключей запросы клиентов пробивают кэш и обрушиваются на базу данных (**Cache Avalanche**).

**Инженерное решение — TTL Jitter (случайный разброс времени)**:

```python
import random

# Базовый интервал 3600 сек со случайным
# разбросом в диапазоне +-5 минут
ttl_with_jitter = (
    3600 + random.randint(-300, 300)
)
print(
    'TTL с Jitter (сек):',
    ttl_with_jitter > 3000,
)
# >>> TTL с Jitter (сек): True
```

Ключи вытесняются плавно в течение нескольких минут, устраняя пиковые ударные волны на СУБД.

> **Junior vs Senior**:
> - **Junior**: Задает всем ключам одинаковый константный TTL при прогреве кэша, провоцируя лавину `Cache Avalanche`.
> - **Senior**: Задает TTL с рандомизацией (`ex=3600 + random.randint(0, 300)`), проверяет коды возврата `r.ttl()` и сохраняет существующий таймер через `keepttl=True`.

## Практикум в Python 3.13: жизненный цикл TTL (`>0`, `-1`, `-2`), `PERSIST` и `TTL Jitter`

```python
import random
import redis

r = redis.Redis()

# Атомарная установка ключа с TTL и
# проверка кодов возврата r.ttl():
r.set("promo:code", "SALE25", ex=120)
# Без ex -> живёт вечно (TTL = -1)
r.set("config:site_name", "Python Academy")

print(
    'TTL ключа с таймером (promo:code)      '
    ':',
    r.ttl('promo:code'),
    'сек (> 0)',
)
# >>> TTL ключа с таймером (promo:code)      : 120 сек (> 0)
print(
    'TTL вечного ключа    '
    '(config:site_name):',
    r.ttl('config:site_name'),
    '(-1 = нет TTL)',
)
# >>> TTL вечного ключа    (config:site_name): -1 (-1 = нет TTL)
print(
    'TTL несуществующего  (ghost:key)       '
    ':',
    r.ttl('ghost:key'),
    '(-2 = нет ключа)',
)
# >>> TTL несуществующего  (ghost:key)       : -2 (-2 = нет ключа)

# Снимаем таймер командой PERSIST -> ключ
# становится вечным (-1):
r.persist("promo:code")
print(
    'TTL promo:code после r.persist()       '
    ':',
    r.ttl('promo:code'),
)
# >>> TTL promo:code после r.persist()       : -1

# Генерация TTL с Jitter против лавины кэша
# (Cache Avalanche):
random.seed(42)
ttls = [
    3600 + random.randint(-300, 300)
    for _ in range(5)
]
print(
    'Примеры TTL с Jitter вокруг 3600 с     '
    ':',
    ttls,
)
# >>> [3681, 3514, 3875, 3420, 3655]

```
