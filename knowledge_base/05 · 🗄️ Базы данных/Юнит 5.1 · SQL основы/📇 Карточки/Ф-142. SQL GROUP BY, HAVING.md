1. Можно ли в `HAVING` использовать агрегат по столбцу, не указанному в `SELECT` ? >> Да: `HAVING COUNT(*) > 1` работает независимо от того, есть ли `COUNT(*)` в `SELECT`
2. Может ли `HAVING` использоваться без `GROUP BY` ? >> Да; вся таблица рассматривается как одна группа: `HAVING COUNT(*) > 100` проверяет общее количество строк
3. Что вернёт `HAVING COUNT(*) = 1` ? >> Только те группы, которые состоят ровно из одной строки
4. В каком из операторов разрешено использование агрегатных функций? >> Только в `HAVING` ; `WHERE` работает с отдельными строками до агрегации
5. Что делает `HAVING` в SQL-запросе? >> Фильтрует уже сформированные группы по условию, как правило с агрегатными функциями
6. При одновременном использовании `WHERE` , `GROUP BY` и `HAVING` – что выполняется первым? >> Фильтрация строк через `WHERE`
7. Какое действие SQL выполняет сразу после `WHERE` ? >> Группировку строк через `GROUP BY`
8. В чём разница между `COUNT(*)` и `COUNT(column)` ? >> `COUNT(*)` считает все строки в группе включая `NULL` ; `COUNT(column)` считает только строки, где значение в столбце не `NULL` – классическая ловушка
9. Что произойдёт, если написать `WHERE AVG(salary) > 70000` вместо `HAVING` ? >> Ошибка: агрегатные функции недопустимы в `WHERE`
10. Почему `ORDER BY` ставится в конце запроса с группировкой? >> Сортировка выполняется на последнем этапе – после вычисления агрегатов и фильтрации групп
11. Что проверяет `HAVING AVG(salary) > 70000` ? >> Превышает ли средняя зарплата внутри конкретной группы значение 70000
12. Для чего используется `DESC` после `ORDER BY` ? >> Для сортировки по убыванию – от большего к меньшему
13. Для чего используется `AS` в `COUNT(*) AS cnt` ? >> Для создания псевдонима результирующего столбца; `cnt` – имя, по которому можно ссылаться на него в `ORDER BY`
14. В каком блоке проверять условия, не связанные с агрегатами (имя, дата)? >> В `WHERE` – до группировки
15. Какая функция находит максимум в группе? >> `MAX(column)`
16. Какая функция находит минимум в группе? >> `MIN(column)`
17. Как сгруппировать по двум столбцам: `department` и `position` ? >> `GROUP BY department, position`
18. С какими функциями чаще всего используется `GROUP BY` ? >> С агрегатными: `COUNT` , `SUM` , `AVG` , `MIN` , `MAX`
19. Как `GROUP BY` обрабатывает строки с одинаковыми значениями? >> Объединяет их в одну группу; агрегатные функции вычисляются внутри каждой группы отдельно
20. Какая функция вычисляет среднее значение по группе? >> `AVG(column)`
21. Обязательно ли использовать агрегатные функции вместе с `GROUP BY` ? >> Нет; без агрегатных функций `GROUP BY` просто возвращает уникальные комбинации значений столбцов
22. `WHERE` ограничивает строки до `GROUP BY` или после? >> До – сначала отфильтровываются строки, затем из оставшихся формируются группы
23. Для предварительной фильтрации сотрудников по возрасту до группировки – какой оператор использовать? >> `WHERE age > 25` – `WHERE` применяется до `GROUP BY`
24. Каково основное назначение `GROUP BY` в SQL? >> Группировка строк с одинаковыми значениями в указанных столбцах для последующего применения агрегатных функций
25. Если в таблице 10 сотрудников в 2 отделах, сколько строк вернёт `GROUP BY department` ? >> 2 строки – по одной на каждый отдел
26. При одновременном использовании `WHERE` , `GROUP BY` и `HAVING` – что выполняется последним? >> Сортировка через `ORDER BY` (если присутствует); из этих трёх – последним выполняется `HAVING`
27. Где в синтаксисе запроса стоит `HAVING` относительно `GROUP BY` ? >> Сразу после `GROUP BY` : `GROUP BY ... HAVING ...`
28. Условие `HAVING COUNT(*) > 5` – что оно фильтрует? >> Оставляет только группы, в которых более 5 строк
29. Что произойдёт, если в `SELECT` указать столбец, не входящий в `GROUP BY` и не обёрнутый в агрегатную функцию? >> В PostgreSQL и большинстве СУБД – ошибка; MySQL без `ONLY_FULL_GROUP_BY` вернёт произвольное значение из группы (непредсказуемое поведение)
30. Что фильтрует `WHERE` в запросе `WHERE salary > 50000 GROUP BY department` ? >> Сотрудников с зарплатой ≤ 50000; они не войдут ни в одну группу
31. В чём принципиальное отличие `WHERE` от `HAVING` ? >> `WHERE` фильтрует отдельные строки до группировки; `HAVING` – группы после группировки
32. Почему в `WHERE` нельзя использовать агрегатные функции? >> `WHERE` выполняется до `GROUP BY` , когда группы ещё не сформированы; агрегат вычислить невозможно
33. К чему применяется `WHERE salary > 50000` в запросе с группировкой? >> К каждой отдельной строке до попадания в группу
34. Какой результат вернёт `SELECT department FROM employees GROUP BY department` ? >> Список уникальных названий отделов без повторений
35. Влияет ли порядок столбцов в `GROUP BY` на состав формируемых групп? >> Нет; `GROUP BY a, b` и `GROUP BY b, a` формируют одинаковые группы; порядок имеет значение только в `ROLLUP` / `CUBE` / `GROUPING SETS`
36. `HAVING` ограничивает строки или группы? >> Группы – он применяется после того, как группы уже сформированы и агрегаты вычислены
37. Как расшифровывается `AVG` в SQL? >> Average – среднее значение
38. Запрос для подсчёта сотрудников в каждом отделе? >> `SELECT department, COUNT(*) FROM employees GROUP BY department`
39. Где в синтаксисе запроса стоит `GROUP BY` относительно `WHERE` ? >> После `WHERE` : `WHERE ... GROUP BY ...`
40. Каков результат `COUNT(*)` в запросе с `GROUP BY department` ? >> Количество строк (сотрудников) в каждом конкретном отделе
41. Как отсортировать результаты по убыванию средней зарплаты? >> `ORDER BY AVG(salary) DESC` или по алиасу: `ORDER BY avg_salary DESC`
42. Запрос для нахождения средней зарплаты по отделам? >> `SELECT department, AVG(salary) FROM employees GROUP BY department`
43. В каком логическом порядке выполняются этапы запроса с `GROUP BY` ? >> `FROM` → `WHERE` → `GROUP BY` → `HAVING` → `SELECT` → `ORDER BY`
