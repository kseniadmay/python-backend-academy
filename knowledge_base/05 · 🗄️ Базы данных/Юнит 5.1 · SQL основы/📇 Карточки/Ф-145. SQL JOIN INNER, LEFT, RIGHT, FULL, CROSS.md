1. Какой тип `JOIN` создаёт комбинаторный взрыв данных при больших таблицах? >> `CROSS JOIN`
2. Что является «левой» таблицей в `FROM TableA LEFT JOIN TableB` ? >> `TableA`
3. Для чего используются псевдонимы таблиц в `JOIN` -запросах? >> Для сокращения кода и явного указания принадлежности столбца при одинаковых именах в разных таблицах
4. В каком `JOIN` результат всегда содержит все данные из обеих таблиц? >> `FULL JOIN`
5. Поддерживается ли `FULL JOIN` в MySQL? >> Нет; в MySQL его эмулируют через `UNION` двух запросов: `LEFT JOIN UNION RIGHT JOIN`
6. Если нужно гарантированно включить всех сотрудников (левая таблица), какой `JOIN` выбрать? >> `LEFT JOIN`
7. Что возвращает `LEFT JOIN` относительно левой таблицы? >> Все строки из левой таблицы независимо от наличия совпадений в правой; в столбцах правой таблицы при отсутствии совпадения – `NULL`
8. Влияет ли количество строк в правой таблице на результат `LEFT JOIN` ? >> Да: если одной строке слева соответствуют несколько строк справа, результирующих строк будет больше, чем строк в левой таблице
9. В таблице A 5 строк, в таблице B 3 строки. Сколько строк вернёт `A CROSS JOIN B` ? >> 15 строк
10. Что такое `CROSS JOIN` в терминах теории множеств? >> Декартово произведение: каждая строка левой таблицы соединяется с каждой строкой правой
11. Как рассчитать количество строк в результате `CROSS JOIN` таблиц с n и m строками? >> n × m строк
12. Соответствует ли `INNER JOIN` математическому пересечению множеств? >> Не совсем: пересечение множеств – это оператор `INTERSECT` ; `INNER JOIN` работает со строками двух таблиц по условию, а не с идентичными строками
13. Может ли `CROSS JOIN` вернуть пустой результат? >> Да, если хотя бы одна из таблиц пустая
14. Как называется оператор, возвращающий все строки из обеих таблиц с `NULL` для несовпадений? >> `FULL JOIN` (он же `FULL OUTER JOIN` )
15. В каком месте запроса указывается условие `ON` ? >> Сразу после присоединяемой таблицы: `JOIN table ON condition`
16. Сколько столбцов будет в результате `JOIN` двух таблиц? >> Сумма столбцов, указанных в `SELECT` из обеих таблиц
17. Как называется тип объединения, возвращающий только строки с совпадениями в обеих таблицах? >> `INNER JOIN`
18. Какую основную функцию выполняет оператор `JOIN` в SQL? >> Объединяет строки из двух и более таблиц на основе заданного условия
19. Почему `RIGHT JOIN` используется редко? >> Обычно его заменяют `LEFT JOIN` со сменой порядка таблиц – результат идентичен, а код читается привычнее
20. Что произойдёт с сотрудником без отдела при `INNER JOIN` таблиц сотрудников и отделов? >> Он не попадёт в результат – `INNER JOIN` исключает строки без совпадений
21. Верно ли, что `FULL JOIN` – это объединение результатов `LEFT JOIN` и `RIGHT JOIN` ? >> Да, концептуально: `FULL JOIN` = `LEFT JOIN` + строки `RIGHT JOIN` , которых нет в `LEFT JOIN` ; технически реализуется как `LEFT JOIN UNION RIGHT JOIN`
22. Когда `CROSS JOIN` оправдан, несмотря на редкость использования? >> Для генерации всех возможных комбинаций параметров: цветов и размеров, дней и сотрудников, позиций меню
23. Когда результат `FULL JOIN` содержит `NULL` в колонке имени сотрудника? >> Когда в таблице отделов есть отдел, к которому не привязан ни один сотрудник
24. Что является «правой» таблицей в `FROM TableA RIGHT JOIN TableB` ? >> `TableB`
25. Как получить результат `RIGHT JOIN` через `LEFT JOIN` ? >> Поменять таблицы местами: `A RIGHT JOIN B` эквивалентен `B LEFT JOIN A`
26. В каком JOIN условие `ON` не указывается? >> `CROSS JOIN`
27. Почему `INNER JOIN` считается самым строгим типом объединения? >> Он отсеивает любые данные, не имеющие точного соответствия по условию `ON`
28. Считается ли `FULL JOIN` распространённым в повседневных запросах? >> Нет, используется реже `INNER` и `LEFT JOIN` ; часто нужен для поиска несоответствий между таблицами
29. Для чего используется условие `e.department_id = d.id` в `JOIN` ? >> Для сопоставления внешнего ключа одной таблицы с первичным ключом другой
30. Как с помощью `LEFT JOIN` найти «брошенные» записи без связей? >> `LEFT JOIN` + фильтр `WHERE right_table.id IS NULL` – строки без совпадений будут иметь `NULL` в полях правой таблицы
31. Какое ключевое слово задаёт условие объединения таблиц? >> `ON`
32. Можно ли заменить `INNER JOIN` на `LEFT JOIN` без изменения логики? >> Нет: `LEFT JOIN` может вернуть строки с `NULL` , которых не было бы при `INNER JOIN`
33. Будет ли результат `LEFT JOIN` содержать меньше строк, чем левая таблица? >> Нет, строк будет не меньше; если одной строке слева соответствует несколько строк справа – строк станет больше
34. Важен ли порядок таблиц в `INNER JOIN` для итогового состава строк? >> Нет, состав строк будет одинаковым; порядок может влиять на производительность (план запроса оптимизатора)
35. Что означает `e` в `FROM employees e INNER JOIN departments d` ? >> Псевдоним (alias) таблицы `employees` ; сокращает код и устраняет неоднозначность имён столбцов
36. При каком `JOIN` получить список всех отделов, даже без сотрудников? >> `LEFT JOIN` , если отделы – левая таблица; `RIGHT JOIN` , если отделы справа
37. Требует ли `CROSS JOIN` наличия условия `ON` ? >> Нет, `ON` не используется – соединение происходит без условия
38. Что такое `RIGHT JOIN` ? >> Возвращает все строки из правой таблицы и только совпадающие из левой
39. Какая информация теряется при `INNER JOIN` сотрудников и отделов? >> Сотрудники без отдела и отделы без сотрудников
40. Что подставляется в столбцы правой таблицы при `LEFT JOIN` , если совпадения нет? >> `NULL`
