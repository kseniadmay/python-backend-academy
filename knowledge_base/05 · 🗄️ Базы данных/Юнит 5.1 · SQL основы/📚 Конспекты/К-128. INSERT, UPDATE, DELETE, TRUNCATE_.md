## Правило безопасности DML: проверка `WHERE` перед изменением

> **Защита от потери таблицы**: команда `UPDATE` или `DELETE` без клаузы `WHERE` мгновенно перезапишет или удалит **100% строк таблицы**. Перед запуском в продакшене всегда проверяйте условие через `SELECT`.

```text
Безопасный конвейер изменения данных в продакшене:
┌────────────────────────────────────────────────┐
│ 1. BEGIN;                                      │
│    (Открываем защитную транзакцию)             │
│ 2. SELECT id, status FROM orders WHERE id = 42;│
│    (Убеждаемся глазами, что выбрана 1 строка)  │
│ 3. UPDATE orders SET status = 'shipped'        │
│    WHERE id = 42 RETURNING id, status;         │
│ 4. COMMIT; (или ROLLBACK при малейшей ошибке)  │
└────────────────────────────────────────────────┘
```

## Пакетная вставка строк (`Batch INSERT` / `executemany`)

Вставка 1 000 записей по одной в цикле тратит время на 1 000 сетевых походов и синхронизаций диска.

Пакетный `INSERT INTO ... VALUES (...), (...)` или метод `executemany()` вставляет весь пакет за одну транзакцию в десятки раз быстрее:

```python
import sqlite3

with sqlite3.connect(':memory:') as conn:
    conn.execute('CREATE TABLE tags (id INT, name TEXT)')
    batch = [(1, 'python'), (2, 'sql'), (3, 'async')]
    conn.executemany(
        'INSERT INTO tags VALUES (?, ?)', batch
    )
    cnt = conn.execute('SELECT COUNT(*) FROM tags').fetchone()[0]
    print('Вставлено строк:', cnt)
```

## Идемпотентный `UPSERT` (`ON CONFLICT DO UPDATE`)

Чтобы атомарно вставить новую запись или обновить существующую при совпадении уникального ключа (`UNIQUE` / `PRIMARY KEY`), используется конструкция `ON CONFLICT (...) DO UPDATE`:

```python
import sqlite3

with sqlite3.connect(':memory:') as conn:
    conn.execute(
        'CREATE TABLE cart (sku TEXT PRIMARY KEY, qty INT)'
    )
    sql = '''
    INSERT INTO cart VALUES (?, ?)
    ON CONFLICT(sku) DO UPDATE SET qty = cart.qty + excluded.qty
    '''
    conn.execute(sql, ('KB-01', 2))
    conn.execute(sql, ('KB-01', 3))
    print('Корзина:', conn.execute('SELECT * FROM cart').fetchall())
```

## Возврат изменённых строк за один поход через `RETURNING`

Клауза **`RETURNING`** в PostgreSQL и SQLite (3.35+) позволяет в одном запросе `INSERT`, `UPDATE` или `DELETE` сразу получить сгенерированный `id` или обновлённые поля без дополнительного `SELECT`:

```python
import sqlite3

with sqlite3.connect(':memory:') as conn:
    conn.execute(
        'CREATE TABLE tasks (id INTEGER PRIMARY KEY, st TEXT)'
    )
    row = conn.execute(
        "INSERT INTO tasks (st) VALUES ('new') RETURNING id, st"
    ).fetchone()
    print('Создана запись:', row)
```

## Архитектурное сравнение `DELETE`, `TRUNCATE` и `DROP`

Разница между построчным удалением, быстрым сбросом хранилища и сносом таблицы:

| Характеристика | `DELETE FROM tbl` | `TRUNCATE TABLE tbl` | `DROP TABLE tbl` |
| :--- | :--- | :--- | :--- |
| **Класс команды** | DML (работа со строками) | DDL (сброс файла данных) | DDL (удаление объекта) |
| **Поддержка `WHERE`** | ✅ Да (выборочное удаление) | ❌ Нет (очищает всю таблицу) | ❌ Нет (сносит саму таблицу) |
| **Скорость на $10^7$ строк** | 🐢 Медленно ($O(n)$ записей в WAL) | ⚡ Мгновенно ($O(1)$) | ⚡ Мгновенно ($O(1)$) |
| **Возврат места ОС** | ❌ Нет (оставляет *dead tuples* до `VACUUM`) | ✅ Да, сразу освобождает диск | ✅ Да |
| **Триггеры `ON DELETE`** | ✅ Срабатывают на каждую строку | ❌ Не срабатывают | ❌ Не срабатывают |
| **Откат через `ROLLBACK`** | ✅ Да | ✅ В PostgreSQL да | ✅ В PostgreSQL да |

## Точечное удаление и контроль затронутых строк (`rowcount`)

При выполнении `UPDATE` или `DELETE` курсор DB-API 2.0 возвращает точное число изменённых записей в атрибуте `cursor.rowcount`:

```python
import sqlite3

with sqlite3.connect(':memory:') as conn:
    conn.execute('CREATE TABLE logs (id INT, old INT)')
    conn.executemany(
        'INSERT INTO logs VALUES (?, ?)',
        [(1, 1), (2, 1), (3, 0)],
    )
    cur = conn.execute('DELETE FROM logs WHERE old = 1')
    print('Удалено устаревших строк:', cur.rowcount)
```
