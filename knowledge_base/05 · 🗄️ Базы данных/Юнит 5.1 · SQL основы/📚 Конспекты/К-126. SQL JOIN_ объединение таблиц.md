## Реляционное объединение таблиц через `JOIN`

> **Принцип соединения**: оператор `JOIN` сопоставляет строки двух таблиц по ключу связи `ON` (обычно `users.id = orders.user_id`), а тип `JOIN` определяет судьбу строк, которым не нашлось пары.

```text
Таблица users:       Таблица orders:
┌────┬───────┐       ┌────┬─────────┬────────┐
│ id │ name  │       │ id │ user_id │ amount │
├────┼───────┤       ├────┼─────────┼────────┤
│ 1  │ Alice │ <───> │ 10 │    1    │  500   │
│ 2  │ Bob   │       │ 11 │   99    │  300   │
└────┴───────┘       └────┴─────────┴────────┘

Результаты разных видов JOIN:
• INNER JOIN : только Alice (id=1 есть в обеих)
• LEFT JOIN  : Alice + Bob (у Боба amount=NULL)
• RIGHT JOIN : Alice + заказ #11 (name=NULL)
• FULL JOIN  : Alice + Bob + заказ #11
```

## Сравнительная шпаргалка по видам `JOIN`

Сводная матрица всех типов соединения таблиц в стандарте SQL:

| Тип объединения | Что попадает в результат | Если пары нет | Типичный сценарий |
| :--- | :--- | :--- | :--- |
| **`INNER JOIN`** | Только строки, где ключ совпал в обеих таблицах | Строка отбрасывается | Заказы с именем реального клиента |
| **`LEFT JOIN`** | Все строки левой таблицы + совпадения из правой | Справа будет `NULL` | Все клиенты, даже без покупок |
| **`LEFT JOIN + IS NULL`** | Строки левой таблицы **без пары** справа (*Anti-Join*) | Справа `NULL` | Найти клиентов без единого заказа |
| **`RIGHT JOIN`** | Все строки правой таблицы + совпадения из левой | Слева будет `NULL` | Аналог `LEFT JOIN` с обратным порядком |
| **`FULL OUTER JOIN`** | Все строки обеих таблиц (и пары, и одиночки) | `NULL` со стороны пропуска | Сверка выписок банка и базы заказов |
| **`CROSS JOIN`** | Декартово произведение: каждая строка с каждой ($N \times M$) | Условие `ON` не нужно | Сетка всех цветов и размеров товара |
| **`SELF JOIN`** | Таблица соединяется сама с собой через два алиаса | `NULL` у корня дерева | Связь «Сотрудник → Руководитель» |

## `INNER JOIN`: пересечение только совпадающих строк

Оператор `INNER JOIN` (или просто `JOIN`) отбрасывает любые строки, у которых нет пары во второй таблице:

```python
import sqlite3

with sqlite3.connect(':memory:') as conn:
    conn.executescript('''
        CREATE TABLE u (id INT, name TEXT);
        CREATE TABLE o (uid INT, total INT);
        INSERT INTO u VALUES (1, 'Alice'), (2, 'Bob');
        INSERT INTO o VALUES (1, 500);
    ''')
    sql = 'SELECT u.name, o.total FROM u JOIN o ON u.id = o.uid'
    print('INNER JOIN:', conn.execute(sql).fetchall())
```

## `LEFT JOIN` и паттерн `Anti-Join` (`WHERE id IS NULL`)

`LEFT JOIN` сохраняет 100% строк левой таблицы, подставляя `NULL` в правые столбцы при отсутствии совпадений, что позволяет легко найти «сирот» через `WHERE o.uid IS NULL`:

```python
import sqlite3

with sqlite3.connect(':memory:') as conn:
    conn.executescript('''
        CREATE TABLE u (id INT, name TEXT);
        CREATE TABLE o (uid INT, total INT);
        INSERT INTO u VALUES (1, 'Alice'), (2, 'Bob');
        INSERT INTO o VALUES (1, 500);
    ''')
    sql = 'SELECT u.name FROM u LEFT JOIN o ON u.id=o.uid WHERE o.uid IS NULL'
    print('Без заказов:', conn.execute(sql).fetchall())
```

## Ловушка фильтра в `WHERE` при `LEFT JOIN`

Если после `LEFT JOIN` добавить условие на правую таблицу в секцию `WHERE o.status = 'paid'`, то для клиентов без заказов проверка `NULL = 'paid'` вернёт `UNKNOWN`.

В результате `WHERE` выбросит всех клиентов без заказов, нечаянно превратив `LEFT JOIN` в обычный `INNER JOIN`:

```python
import sqlite3

with sqlite3.connect(':memory:') as conn:
    conn.executescript('''
        CREATE TABLE u (id INT, name TEXT);
        CREATE TABLE o (uid INT, st TEXT);
        INSERT INTO u VALUES (1, 'Alice'), (2, 'Bob');
        INSERT INTO o VALUES (1, 'paid');
    ''')
    sql = "SELECT u.name, o.st FROM u LEFT JOIN o ON u.id=o.uid WHERE o.st='paid'"
    print('Bob пропал:', conn.execute(sql).fetchall())
```

## Безопасный фильтр правой таблицы внутри `ON`

Чтобы сохранить все строки левой таблицы при `LEFT JOIN`, дополнительное условие для правой таблицы нужно указывать прямо внутри предиката **`ON`**:

```python
import sqlite3

with sqlite3.connect(':memory:') as conn:
    conn.executescript('''
        CREATE TABLE u (id INT, name TEXT);
        CREATE TABLE o (uid INT, st TEXT);
        INSERT INTO u VALUES (1, 'Alice'), (2, 'Bob');
        INSERT INTO o VALUES (1, 'paid');
    ''')
    sql = "SELECT u.name, o.st FROM u LEFT JOIN o ON u.id=o.uid AND o.st='paid'"
    print('Bob сохранён:', conn.execute(sql).fetchall())
```

## Иерархия внутри одной таблицы через `SELF JOIN`

Когда сущность ссылается на саму себя (`manager_id` указывает на `id` в той же таблице сотрудников), таблица соединяется сама с собой под двумя разными алиасами (`e` и `m`):

```python
import sqlite3

with sqlite3.connect(':memory:') as conn:
    conn.execute('CREATE TABLE e (id INT, n TEXT, m INT)')
    conn.executemany(
        'INSERT INTO e VALUES (?, ?, ?)',
        [(1, 'CTO', None), (2, 'Dev', 1)],
    )
    sql = 'SELECT a.n, b.n FROM e a LEFT JOIN e b ON a.m = b.id'
    print('Пары:', conn.execute(sql).fetchall())
```
