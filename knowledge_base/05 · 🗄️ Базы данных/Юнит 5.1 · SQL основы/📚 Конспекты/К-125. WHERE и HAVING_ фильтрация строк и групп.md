## Разделение ответственности между `WHERE` и `HAVING`

> **Два рубежа фильтрации**: `WHERE` проверяет каждую физическую строку поодиночке до группировки, а `HAVING` проверяет уже сформированную группу строк после `GROUP BY`.

```text
Конвейер фильтрации в SQL:
┌─────────────────────────────────────────┐
│ Сырая таблица (employees)               │
└───────────────────┬─────────────────────┘
                    ▼
[1. WHERE salary >= 1000]
    (Отсекает отдельные СТРОКИ по индексам)
                    │
                    ▼
[2. GROUP BY dept]
    (Схлопывает оставшиеся строки в отделы)
                    │
                    ▼
[3. HAVING COUNT(*) >= 2]
    (Отсекает целые ГРУППЫ по агрегатам)
                    │
                    ▼
┌─────────────────────────────────────────┐
│ Итоговый отчёт по крупным отделам       │
└─────────────────────────────────────────┘
```

## Сравнительная таблица `WHERE` против `HAVING`

Ключевые отличия двух операторов фильтрации на техническом интервью:

| Критерий | Оператор `WHERE` | Оператор `HAVING` |
| :--- | :--- | :--- |
| **Момент выполнения** | **До** `GROUP BY` и расчёта агрегатов | **После** `GROUP BY` и расчёта агрегатов |
| **Объект фильтрации** | Отдельные сырые строки таблицы | Сформированные группы строк |
| **Агрегаты (`COUNT`, `SUM`, `AVG`)** | ❌ Запрещены (вызовут ошибку синтаксиса) | ✅ Разрешены и являются главной целью |
| **Работа с B-Tree индексами** | ✅ Да, сокращает чтение с диска | ❌ Нет, фильтрует готовые группы в памяти |

## Построчная фильтрация в `WHERE` до группировки

Условия по обычным столбцам всегда выносятся в `WHERE`, чтобы отбросить лишние строки ещё до ресурсоёмкой сортировки и группировки в памяти:

```python
import sqlite3

with sqlite3.connect(':memory:') as conn:
    conn.execute('CREATE TABLE s (d TEXT, a INT)')
    conn.executemany(
        'INSERT INTO s VALUES (?, ?)',
        [('IT', 500), ('IT', 10), ('HR', 400)],
    )
    sql = (
        'SELECT d, SUM(a) FROM s '
        'WHERE a >= 100 GROUP BY d'
    )
    print(conn.execute(sql).fetchall())
```

## Фильтрация агрегированных корзин через `HAVING`

Когда условие зависит от результата агрегатной функции (`COUNT(*) >= 2` или `SUM(amount) > 500`), его невозможно вычислить для одной строки — такой фильтр ставится в `HAVING`:

```python
import sqlite3

with sqlite3.connect(':memory:') as conn:
    conn.execute('CREATE TABLE st (d TEXT, n TEXT)')
    conn.executemany(
        'INSERT INTO st VALUES (?, ?)',
        [('IT', 'Ann'), ('IT', 'Bob'), ('HR', 'Cid')],
    )
    sql = (
        'SELECT d, COUNT(*) FROM st '
        'GROUP BY d HAVING COUNT(*) >= 2'
    )
    print('Отделы:', conn.execute(sql).fetchall())
```

## Совместная работа `WHERE` и `HAVING` в одном запросе

В аналитических запросах `WHERE` и `HAVING` работают в паре: `WHERE` оставляет только оплаченные заказы, а `HAVING` отбирает клиентов с крупной суммой покупок:

```python
import sqlite3

with sqlite3.connect(':memory:') as conn:
    conn.execute('CREATE TABLE o (u TEXT, st TEXT, s INT)')
    conn.executemany(
        'INSERT INTO o VALUES (?, ?, ?)',
        [('A', 'ok', 200), ('A', 'ok', 150)],
    )
    sql = (
        "SELECT u, SUM(s) FROM o WHERE st = 'ok' "
        'GROUP BY u HAVING SUM(s) >= 300'
    )
    print('VIP:', conn.execute(sql).fetchall())
```

## Условная агрегация через `FILTER (WHERE ...)`

В PostgreSQL и SQLite (3.30+) клауза **`FILTER (WHERE ...)`** внутри агрегатной функции позволяет посчитать несколько срезов за один проход таблицы:

```python
import sqlite3

with sqlite3.connect(':memory:') as conn:
    conn.execute('CREATE TABLE t (d TEXT, ok INT)')
    conn.executemany(
        'INSERT INTO t VALUES (?, ?)',
        [('IT', 1), ('IT', 0), ('IT', 1)],
    )
    sql = (
        'SELECT d, COUNT(*) FILTER (WHERE ok=1) '
        'FROM t GROUP BY d'
    )
    print(conn.execute(sql).fetchall())
```
