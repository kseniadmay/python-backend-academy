## Два признака задачи на DP и дерево `fib(5)`

> **Шпаргалка против повторного счёта**: посчитав $1+1+1+1+1 = 5$, при добавлении ещё одной единицы вы сразу назовёте $6$, не складывая всё заново.

**Динамическое программирование (DP)** применимо, когда у задачи одновременно есть два свойства:

1. **Перекрывающиеся подзадачи**: наивная рекурсия многократно пересчитывает одни и те же ветки (`fib(3)` и `fib(2)`), разгоняя сложность до $O(2^n)$.
2. **Оптимальная подструктура**: ответ большой задачи собирается из решений меньших подзадач по формуле перехода:

```text
Дерево fib(5) — повторы веток кэшируются:

             fib(5)
            /      \
       fib(4)      [fib(3)] <-- из кэша O(1)!
       /    \
   fib(3)   [fib(2)]        <-- из кэша O(1)!
   /    \
fib(2) fib(1)
```

## Подходы Top-Down и Bottom-Up в DP

Один и тот же алгоритм DP можно записать либо рекурсией с кэшем, либо итеративным циклом по массиву состояний:

| Критерий | Top-Down (Мемоизация) | Bottom-Up (Табуляция) | Bottom-Up с $O(1)$ памяти |
| :--- | :--- | :--- | :--- |
| **Механика** | Рекурсия сверху + кэш в словаре или `@lru_cache` | Цикл `for` от базы вверх с таблицей `dp[i]` | Хранение только 2–3 последних значений |
| **Время** | **$O(n)$** | **$O(n)$** | **$O(n)$** |
| **Память** | $O(n)$ кэш + стек | $O(n)$ без риска `RecursionError` | **$O(1)$** |
| **Удобство** | Пишется мгновенно декоратором | Быстрее на больших $n$ | Оптимум для продакшена |

## Мемоизация в Python через `@lru_cache`

Декоратор `@functools.lru_cache(maxsize=None)` сохраняет уже вычисленные значения функции, сжимая экспоненциальное дерево `fib(n)` $O(2^n)$ до линейного $O(n)$:

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def fib_memo(n: int) -> int:
    if n <= 1:
        return n
    return fib_memo(n - 1) + fib_memo(n - 2)

print('fib_memo(35):', fib_memo(35))
# >>> fib_memo(35): 9227465
```

## Табуляция и сжатие памяти до O(1)

В задаче **«Лестница» (*Climbing Stairs*)** за шаг можно подняться на $1$ или $2$ ступеньки, поэтому число способов прийти на ступеньку $i$ равно `dp[i] = dp[i-1] + dp[i-2]`.

Поскольку на каждом шаге нужны только две предыдущие ступеньки, весь массив `dp` заменяют парой переменных за $O(1)$ памяти:

```python
def climb_stairs_o1(n: int) -> int:
    if n <= 2:
        return n
    prev2, prev1 = 1, 2
    for _ in range(3, n + 1):
        prev2, prev1 = prev1, prev2 + prev1
    return prev1

ways = climb_stairs_o1(5)
print('Способов (n=5):', ways)
# >>> Способов (n=5): 8
```

## Размен монет (`Coin Change`) и ошибка жадного подхода

Для номиналов `coins = [1, 3, 4]` и суммы `6` жадный выбор возьмёт самую крупную монету `4` и доберёт единицами (`4 + 1 + 1` = 3 монеты), хотя оптимум равен 2 монетам (`3 + 3`).

Табличный перебор `dp[x] = min(dp[x - c] + 1)` проверяет все номиналы и гарантированно находит минимум:

```python
def coin_change_min(
    coins: list[int],
    amount: int,
) -> int:
    inf = amount + 1
    dp = [0] + [inf] * amount
    for x in range(1, amount + 1):
        for c in coins:
            if x >= c:
                cand = dp[x - c] + 1
                if cand < dp[x]:
                    dp[x] = cand
    ans = dp[amount]
    return ans if ans != inf else -1

res = coin_change_min([1, 3, 4], 6)
print('Мин. монет для 6:', res)
# >>> Мин. монет для 6: 2
```

> **Junior vs Senior**:
> - **Junior**: Пытается разменять произвольные монеты жадным алгоритмом или запускает рекурсию без кэша с зависанием $O(k^n)$.
> - **Senior**: Сначала формулирует состояние `dp[x]` и формулу перехода, проверяет решение через `@lru_cache`, а для нагруженного кода переводит его в табуляцию (со сжатием памяти при возможности).
