Бинарный поиск применим, когда массив отсортирован или функция проверки монотонна (сначала `False`, затем начиная с точки перехода везде `True`).

Отбрасывая 50% пространства на каждом шаге, алгоритм находит ответ среди $10^9$ элементов всего за $\lceil \log_2(10^9) \rceil = 30$ сравнений:

```text
Поиск target = 23 в [2, 5, 8, 16, 23, 38, 56]:

Шаг 1: L=0, R=6 -> mid=3 (16<23) -> L=4
Шаг 2: L=4, R=6 -> mid=5 (38>23) -> R=4
Шаг 3: L=4, R=4 -> mid=4 (23==23) -> idx 4
```

## Итеративный бинарный поиск без классических багов

Чтобы алгоритм никогда не зацикливался и не пропускал крайние элементы, соблюдайте три правила:

1. **Условие `while left <= right`**: знак `<=` проверяет последнюю точку `left == right`.
2. **Сдвиг `left = mid + 1` и `right = mid - 1`**: индекс `mid` уже проверен, иначе `left = mid` зациклится при схлопывании окна.
3. **Середина `left + (right - left) // 2`**: в 32-битных языках защищает `(left + right)` от переполнения `int`:

```python
def binary_search(
    nums: list[int],
    target: int,
) -> int:
    left, right = 0, len(nums) - 1
    while left <= right:
        mid = left + (right - left) // 2
        if nums[mid] == target:
            return mid
        if nums[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1

idx = binary_search([2, 5, 8, 16, 23, 38], 23)
print('Индекс 23:', idx)
# >>> Индекс 23: 4
```

## Границы дубликатов: `bisect_left` и `bisect_right`

Если в отсортированном списке есть повторяющиеся элементы, найти первое и последнее вхождение помогает встроенный модуль **`bisect`**:

- **`bisect_left(a, x)`** (`Lower Bound`) — первый индекс `i`, где `a[i] >= x`.
- **`bisect_right(a, x)`** (`Upper Bound`) — первый индекс `i`, где `a[i] > x` (позиция сразу после всех `x`).
- Число вхождений `x` равно `bisect_right(a, x) - bisect_left(a, x)` за $O(\log n)$:

```python
from bisect import bisect_left, bisect_right

def find_first_and_last(
    nums: list[int],
    target: int,
) -> tuple[int, int]:
    left = bisect_left(nums, target)
    if left == len(nums):
        return -1, -1
    if nums[left] != target:
        return -1, -1
    right = bisect_right(nums, target) - 1
    return left, right

res = find_first_and_last(
    [10, 20, 20, 20, 30], 20
)
print('Диапазон 20:', res)
# >>> Диапазон 20: (1, 3)
```

## Сравнительная таблица вариантов поиска

Выбор стратегии зависит от отсортированности данных, числа запросов и ограничений памяти:

| Алгоритм / Функция | Время | Память | Когда применять |
| :--- | :--- | :--- | :--- |
| Линейный поиск (`x in list`) | $O(n)$ | $O(1)$ | Неотсортированные данные или 1 запрос |
| Итеративный / `bisect` | **$O(\log n)$** | **$O(1)$** | Отсортированный массив, границы диапазона |
| Рекурсивный бинарный поиск | $O(\log n)$ | $O(\log n)$ | Хуже по памяти из-за стека вызовов |
| Бинарный поиск по ответу | **$O(n \log R)$** | **$O(1)$** | Задачи «минимизировать максимум / скорость» |

## Бинарный поиск по ответу (*Binary Search on Answer*)

Даже если входной массив не отсортирован, бинарный поиск работает по **пространству возможных ответов**, когда предикат монотонен: если скорость `v` успевает обработать все задачи, то `v + 1` тоже успеет.

Найдём минимальную скорость сервера, чтобы обработать все пакеты не дольше чем за `max_hours`:

```python
def min_server_rate(
    batches: list[int],
    max_hours: int,
) -> int:
    low, high = 1, max(batches)
    while low < high:
        mid = (low + high) // 2
        hours = sum(
            (b + mid - 1) // mid
            for b in batches
        )
        if hours <= max_hours:
            high = mid
        else:
            low = mid + 1
    return low

rate = min_server_rate([3, 6, 7, 11], 8)
print('Мин. скорость:', rate)
# >>> Мин. скорость: 4
```

> **Junior vs Senior**:
> - **Junior**: Сортирует массив за $O(n \log n)$ ради одного поиска (хотя цикл `for` быстрее за $O(n)$) либо делает рекурсию со срезами `nums[:mid]`, тратя $O(n)$ на копирование.
> - **Senior**: Использует итеративные границы `left, right` за $O(1)$ памяти, применяет `bisect` для дубликатов и находит монотонные предикаты в задачах оптимизации.
