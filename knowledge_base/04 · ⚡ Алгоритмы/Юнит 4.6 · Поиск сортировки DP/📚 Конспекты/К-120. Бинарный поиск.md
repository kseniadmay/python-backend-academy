# 🔍 К-120. Бинарный поиск (Binary Search): границы, модуль `bisect` и поиск по ответу

> **Ментальная модель — «Поиск слова в бумажном словаре»**:
> Открывая словарь в середине, вы видите слово на букву «М», а ищете слово на «С». Вы мгновенно понимаете, что вся первая половина словаря (буквы А–Л) вам точно не нужна, и одним движением отбрасываете **50% страниц**!
> Благодаря делению области поиска пополам на каждом шаге бинарный поиск в массиве из **$1\,000\,000\,000$ (миллиарда)** элементов находит ответ максимум за **$\lceil \log_2(10^9) \rceil = 30$ сравнений** вместо миллиарда!

## 1. Главный инвариант и пошаговая механика

**Обязательное условие (Precondition)**: массив обязан быть **отсортирован** (или проверяемая функция должна быть **монотонной** — сначала везде `False`, затем начиная с некоторой точки везде `True`).

```text
Поиск target = 23 в отсортированном массиве:

Шаг 1: left=0, right=6 -> mid = (0+6)//2 = 3 (значение 16 < 23) ==> отбрасываем левую половину: left = mid + 1 = 4
       [ 2,   5,   8,  16,  23,  38,  56 ]
         ^              ^              ^
        left           mid           right

Шаг 2: left=4, right=6 -> mid = (4+6)//2 = 5 (значение 38 > 23) ==> отбрасываем правую половину: right = mid - 1 = 4
       [ 2,   5,   8,  16,  23,  38,  56 ]
                             ^    ^    ^
                           left  mid right

Шаг 3: left=4, right=4 -> mid = 4 (значение 23 == target) ==> НАЙДЕНО за 3 шага!
```

### Три классические детали реализации без багов:
1. **Условие цикла `while left <= right`**: знак `<=` обязателен, чтобы проверить последний оставшийся элемент, когда окно схлопнулось в одну точку (`left == right`).
2. **Сдвиг границ `left = mid + 1` и `right = mid - 1`**: элемент `nums[mid]` уже проверен! Если написать `left = mid`, то при `left == right` цикл станет бесконечным.
3. **Формула середины `mid = left + (right - left) // 2`**: в Python `int` имеет произвольную точность и не переполняется, но в языках с 32-битным `int` (C++, Java, Go) сумма `(left + right)` при больших индексах вызывает целочисленное переполнение (`Integer Overflow`).

## 2. Левая и правая границы (`bisect_left` и `bisect_right`)

Что делать, если в отсортированном массиве есть **дубликаты** (`[10, 20, 20, 20, 30]`), и нужно найти самое первое или самое последнее вхождение числа `20`?
Для этого используется модуль **`bisect`**:
- **`bisect.bisect_left(a, x)`** (`Lower Bound`) — первый индекс `i`, где `a[i] >= x` (самая левая позиция для вставки `x` без нарушения сортировки).
- **`bisect.bisect_right(a, x)`** (`Upper Bound`) — первый индекс `i`, где `a[i] > x` (позиция сразу *после* всех дубликатов `x`).
- Количество вхождений `x` в отсортированном массиве вычисляется за **$O(\log n)$**: `bisect_right(a, x) - bisect_left(a, x)`.

| Алгоритм / Функция | Временная сложность | Пространственная сложность | Когда использовать |
| :--- | :--- | :--- | :--- |
| Линейный поиск (`x in list`, `list.index(x)`) | $O(n)$ | $O(1)$ | Неотсортированный массив или однократный поиск |
| Итеративный бинарный поиск / `bisect` | **$O(\log n)$** | **$O(1)$** | Отсортированный массив, поиск границ диапазона |
| Рекурсивный бинарный поиск | $O(\log n)$ | $O(\log n)$ (стек вызовов) | Уступает итеративному по памяти |
| Бинарный поиск по ответу (*Binary Search on Answer*) | **$O(n \log(\text{Range}))$** | **$O(1)$** | Задачи «минимизировать максимум» (скорость загрузки, распил досок) |

## 3. Паттерн «Бинарный поиск по ответу» (Binary Search on Answer)

Даже если входной массив не отсортирован, бинарный поиск применим к **пространству возможных ответов**, если выполняется монотонность: *«если мы успеваем обработать задачи со скоростью $v$, то со скоростью $v + 1$ тем более успеем»*.

> **Junior vs Senior**:
> - **Junior**: Сортирует массив за $O(n \log n)$ ради **одного** бинарного поиска за $O(\log n)$ (хотя обычный линейный проход `for` нашёл бы элемент быстрее — за $O(n)$!), либо пишет рекурсивный бинарный поиск со срезами `binary_search(nums[:mid])`, где сам срез копирует половину массива за $O(n)$, убивая логарифмическую сложность!
> - **Senior**: Использует итеративный бинарный поиск с индексами `left, right` за $O(1)$ памяти, применяет `bisect_left` / `bisect_right` для поиска диапазонов дубликатов и распознаёт монотонную функцию проверки `can_finish(speed)` для бинарного поиска по ответу.

```python
import bisect

# 1. Классический бинарный поиск за O(log n) времени и O(1) памяти
def binary_search(nums: list[int], target: int) -> int:
    left, right = 0, len(nums) - 1
    while left <= right:
        mid = left + (right - left) // 2
        if nums[mid] == target:
            return mid
        if nums[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1

# 2. Поиск первого и последнего вхождения дубликата через bisect за O(log n)
def find_first_and_last(nums: list[int], target: int) -> tuple[int, int]:
    left_idx = bisect.bisect_left(nums, target)
    if left_idx == len(nums) or nums[left_idx] != target:
        return -1, -1
    right_idx = bisect.bisect_right(nums, target) - 1
    return left_idx, right_idx

# 3. Бинарный поиск по ответу: минимальная мощность сервера (задач/час), чтобы закрыть пул за h часов
def min_server_rate(batches: list[int], max_hours: int) -> int:
    low, high = 1, max(batches)
    while low < high:
        mid_rate = (low + high) // 2
        # Сколько часов потребуется при скорости mid_rate (округление вверх: (b + r - 1) // r)
        hours_needed = sum((b + mid_rate - 1) // mid_rate for b in batches)
        if hours_needed <= max_hours:
            high = mid_rate      # скорость достаточна, пробуем найти ещё меньшую слева
        else:
            low = mid_rate + 1   # слишком медленно, увеличиваем минимальную границу
    return low

print("Индекс 23 в [2, 5, 8, 16, 23, 38, 56]:", binary_search([2, 5, 8, 16, 23, 38, 56], 23))
print("Диапазон числа 20 в [10, 20, 20, 20, 30]:", find_first_and_last([10, 20, 20, 20, 30], 20))
print("Мин. скорость сервера для пакетов [3, 6, 7, 11] за 8 часов:", min_server_rate([3, 6, 7, 11], 8))
```
