## Ключевая концепция: русская матрёшка и стек вызовов

> **Базовый случай и раскрутка стека**: вы открываете матрёшки одну за другой, пока не дойдёте до самой маленькой цельной фигурки (`1`), и затем собираете итоговый ответ в обратном порядке.

- Каждый рекурсивный шаг сводит задачу к меньшей подзадаче того же типа (**рекурсивный случай**).
- Когда подзадача становится тривиальной (**базовый случай / Base Case**), рекурсия останавливается и стек вызовов раскручивается назад.

---

## Два обязательных компонента любой рекурсии

Любая корректная рекурсивная функция обязана содержать:
1. **Базовый случай (Base Case / Условие выхода)** — простейший вход, для которого ответ известен сразу без новых рекурсивных вызовов (например, `n <= 1` или `node is None`). Без базового случая рекурсия бесконечна!
2. **Рекурсивный шаг (Recursive Step)** — сведение задачи к **строго меньшей** подзадаче того же типа, приближающей аргументы к базовому случаю (`n - 1`, `n // 2`, `node.left`).

```text
Жизненный цикл стека вызовов (Call Stack) при вычислении factorial(3):

Фаза 1: Погружение (Push кадров в стек)          Фаза 2: Возврат и вычисление (Pop кадров)
+-----------------------------------+            +-----------------------------------+
| Кадр 3: factorial(1) -> Base Case!|  ======>   | Возвращает 1                      |
| Кадр 2: factorial(2) ждёт f(1)    |            | Вычисляет 2 * 1 = 2               |
| Кадр 1: factorial(3) ждёт f(2)    |            | Вычисляет 3 * 2 = 6 (ИТОГ)        |
+-----------------------------------+            +-----------------------------------+
```

## Стек вызовов Call Stack и отсутствие TCO в Python

Каждый рекурсивный вызов создает в памяти стековый кадр (`Stack Frame`). Пространственная сложность рекурсии определяется максимальной глубиной вызовов $O(\text{depth})$.

- По умолчанию лимит глубины в CPython составляет `1000` вызовов (`sys.getrecursionlimit()`). Превышение вызывает `RecursionError`.
- **Оптимизация хвостовой рекурсии (TCO)** в CPython отсутствует ради сохранения читаемых стектрейсов (`Traceback`). Глубокие линейные алгоритмы реализуются через итерации.

| Тип рекурсии | Память стека | Время | Пример |
| :--- | :--- | :--- | :--- |
| **Линейная** | $O(n)$ | $O(n)$ | Обход связного списка |
| **Логарифмическая** | $O(\log n)$ | $O(\log n)$ | Бинарный поиск, деление пополам |
| **Ветвящаяся по дереву** | $O(h)$ | $O(n)$ | Обход бинарного дерева |
| **Древовидная без кэша** | $O(n)$ | $O(2^n)$ | Наивный расчёт Фибоначчи |

## Итеративная трансформация: явный стек против рекурсивного переполнения

> **Junior vs Senior**:
> - **Junior**: Применяет рекурсию для линейной обработки десятков тысяч элементов или принудительно увеличивает лимит `sys.setrecursionlimit()`, рискуя вызвать падение процесса (`Stack Overflow`).
> - **Senior**: Применяет рекурсию для логарифмических и древовидных структур (JSON, AST), а для глубоких линейных графов переходит к итеративному алгоритму с явным стеком `stack = [root]`.

```python
from typing import Any

def sum_nested_numbers(data: Any) -> int:
    """Суммирует все числа на любой глубине
    вложенности словарей и списков.
    """
    # Базовый случай рекурсии — нашли число
    if isinstance(data, int):
        return data
    if isinstance(data, list):
        return sum(
            sum_nested_numbers(item)
            for item in data
        )
    if isinstance(data, dict):
        return sum(
            sum_nested_numbers(val)
            for val in data.values()
        )
    return 0

# Цикл тратит O(1) памяти вместо стека
def factorial_iterative(n: int) -> int:
    result = 1
    for i in range(2, n + 1):
        result *= i
    return result

payload = {
    "a": 10,
    "b": [20, {"c": 30, "d": [40, 50]}],
    "meta": "ok",
}
print(
    'Сумма чисел во вложенном JSON:',
    sum_nested_numbers(payload),
)
# >>> Сумма чисел во вложенном JSON: 150
print(
    'Итеративный факториал 6! за O(1) '
    'памяти:',
    factorial_iterative(6),
)
# >>> Итеративный факториал 6! за O(1) памяти: 720
```
