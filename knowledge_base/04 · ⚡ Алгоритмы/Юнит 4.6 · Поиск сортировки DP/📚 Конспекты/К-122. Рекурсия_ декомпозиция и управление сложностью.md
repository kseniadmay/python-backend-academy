## Базовый случай и рекурсивный шаг

> **Русская матрёшка**: вы открываете фигурки одну за другой до самой маленькой цельной фигурки, а затем собираете итог на обратном пути.

Любая корректная рекурсивная функция обязана включать два элемента:

1. **Базовый случай (Base Case)** — условие немедленного выхода (`n <= 1`, `node is None`), без которого рекурсия станет бесконечной.
2. **Рекурсивный шаг (Recursive Step)** — сведение задачи к строго меньшей подзадаче (`n - 1`, `n // 2`), приближающей вход к базе:

```text
Call Stack для factorial(3):

1. Погружение (Push кадров):
   Кадр 1: factorial(3) ждёт f(2)
   Кадр 2: factorial(2) ждёт f(1)
   Кадр 3: factorial(1) -> 1 (Base Case!)

2. Возврат (Pop и умножение):
   Кадр 2: 2 * 1 = 2
   Кадр 1: 3 * 2 = 6 (Итог)
```

## Стек вызовов и отсутствие TCO в CPython

Каждый вложенный вызов выделяет в памяти новый кадровый фрейм (**Stack Frame**), поэтому расход памяти равен максимальной глубине рекурсии $O(\text{depth})$.

- По умолчанию лимит глубины в CPython равен `1000` (`sys.getrecursionlimit()`) — превышение бросает `RecursionError`.
- **Оптимизации хвостовой рекурсии (TCO)** в CPython намеренно нет, чтобы сохранять полные читаемые стектрейсы при ошибках.

## Типы рекурсии и расход памяти стека

Форма дерева вызовов определяет как время выполнения, так и глубину расхода памяти на стеке:

| Тип рекурсии | Память стека | Время | Пример |
| :--- | :--- | :--- | :--- |
| **Линейная** | $O(n)$ | $O(n)$ | Обход связного списка |
| **Логарифмическая** | $O(\log n)$ | $O(\log n)$ | Бинарный поиск |
| **По дереву** | $O(h)$ | $O(n)$ | Обход бинарного дерева |
| **Древовидная без кэша** | $O(n)$ | $O(2^n)$ | Наивный Фибоначчи |

## Рекурсивный обход вложенных структур (JSON)

Рекурсия естественна для иерархических данных с неизвестной заранее вложенностью (деревья, AST, вложенный JSON):

```python
from typing import Any

def sum_nested(data: Any) -> int:
    # Базовый случай: целое число (не bool)
    if (
        isinstance(data, int)
        and not isinstance(data, bool)
    ):
        return data
    if isinstance(data, list):
        return sum(
            sum_nested(x) for x in data
        )
    if isinstance(data, dict):
        return sum(
            sum_nested(v)
            for v in data.values()
        )
    return 0

payload = {
    'a': 10,
    'b': [20, {'c': 30, 'd': [40, 50]}],
    'meta': 'ok',
}
print('Сумма в JSON:', sum_nested(payload))
# >>> Сумма в JSON: 150
```

## Итеративная трансформация против `RecursionError`

Линейные задачи на больших объёмах данных (десятки тысяч элементов) переводят в цикл `for`/`while` за $O(1)$ памяти (либо используют явный стек `stack = [root]` для глубоких графов):

```python
def factorial_iterative(n: int) -> int:
    result = 1
    for i in range(2, n + 1):
        result *= i
    return result

res = factorial_iterative(6)
print('6! за O(1) памяти:', res)
# >>> 6! за O(1) памяти: 720
```

> **Junior vs Senior**:
> - **Junior**: Запускает линейную рекурсию по $10\,000$ элементам или поднимает `sys.setrecursionlimit()`, рискуя уронить процесс с переполнением стека ОС.
> - **Senior**: Использует рекурсию для логарифмических и древовидных структур (JSON, AST), а глубокие линейные и графовые обходы переписывает итеративно со стеком в куче.
