## Квадратичные O(n²) против O(n log n) сортировок

> **Перестановка соседей против «разделяй и властвуй»**: простые сортировки сравнивают пары за $O(n^2)$, а промышленные дробят массив пополам за $O(n \log n)$.

- **Квадратичные сортировки (`Bubble`, `Selection`, `Insertion`)** просты и хороши на 10–30 элементах, но на 100 000 записях делают миллиарды шагов.
- **Эффективные сортировки (`Merge Sort`, `Quick Sort`)** рекурсивно делят массив на $\log_2 n$ ярусов, тратя по $O(n)$ на каждом уровне.
- **Timsort (встроен в `list.sort()` и `sorted()`)** соединяет оба подхода: находит уже упорядоченные участки (`runs`), досортирует мелкие вставками и сливает как `Merge Sort`.

## Панорама алгоритмов сортировки и стабильность

**Стабильность (Stability)** означает, что элементы с равными ключами сохраняют свой исходный порядок — это необходимо при многоуровневой сортировке (сначала по имени, затем по баллу).

Сравнение классических алгоритмов по времени, памяти и стабильности:

| Алгоритм | Лучший | Средний | Худший | Память | Стабильна? | Суть метода |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Bubble Sort** | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | Да | Обмен соседей; максимум всплывает вправо |
| **Selection Sort** | $O(n^2)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | Нет | Поиск минимума и перестановка в `i` |
| **Insertion Sort** | **$O(n)$** | $O(n^2)$ | $O(n^2)$ | $O(1)$ | **Да** | Вставка элемента в отсортированную часть |
| **Merge Sort** | $O(n \log n)$ | **$O(n \log n)$** | **$O(n \log n)$** | $O(n)$ | **Да** | Деление пополам и слияние двух списков |
| **Quick Sort** | $O(n \log n)$ | **$O(n \log n)$** | $O(n^2)$ | $O(\log n)$ | Нет | Деление вокруг `pivot` на `< pivot` и `> pivot` |
| **Timsort** | **$O(n)$** | **$O(n \log n)$** | **$O(n \log n)$** | $O(n)$ | **Да** | Гибрид **Insertion Sort** + **Merge Sort** |

## Механика сортировки слиянием (`Merge Sort`)

Алгоритм состоит из двух фаз: сначала массив рекурсивно делится пополам до одиночных элементов (глубина $\log_2 n$), а затем пары списков сливаются вверх двумя указателями за $O(n)$ на каждом уровне:

```text
Merge Sort (деление вниз, слияние вверх):

          [ 38, 27, 43, 3 ]
           /             \
     [38, 27]          [43, 3]
      /    \            /    \
   [38]    [27]      [43]    [3]
      \    /            \    /
     [27, 38]          [3, 43]
           \             /
          [ 3, 27, 38, 43 ]
```

## Реализация `Merge Sort` на Python

Слияние двух уже отсортированных списков выполняется двумя индексами `i` и `j`; условие `<=` при сравнении левого и правого элементов сохраняет стабильность сортировки:

```python
def merge_sorted(
    left: list[int],
    right: list[int],
) -> list[int]:
    merged: list[int] = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            merged.append(left[i])
            i += 1
        else:
            merged.append(right[j])
            j += 1
    merged.extend(left[i:])
    merged.extend(right[j:])
    return merged

def merge_sort(arr: list[int]) -> list[int]:
    if len(arr) <= 1:
        return arr
    mid = len(arr) // 2
    return merge_sorted(
        merge_sort(arr[:mid]),
        merge_sort(arr[mid:]),
    )

print(merge_sort([38, 27, 43, 3, 9, 82, 10]))
# >>> [3, 9, 10, 27, 38, 43, 82]
```

## `Timsort` в Python, `key=` и `list.sort` vs `sorted`

Метод `lst.sort()` сортирует список на месте и возвращает `None`, а функция `sorted()` создаёт новый отсортированный список.

При передаче `key=func` Python вычисляет ключ ровно 1 раз на элемент ($O(n)$ вызовов, паттерн *Schwartzian Transform*), а не на каждом из $O(n \log n)$ сравнений:

```python
candidates = [
    {'name': 'Борис', 'score': 90},
    {'name': 'Анна', 'score': 95},
    {'name': 'Алексей', 'score': 90},
]

# Сортируем по убыванию балла и имени
ranked = sorted(
    candidates,
    key=lambda c: (-c['score'], c['name']),
)
res = [
    f"{c['name']} ({c['score']})"
    for c in ranked
]
print('Рейтинг:', res)
# >>> Рейтинг: ['Анна (95)', 'Алексей (90)', 'Борис (90)']
```

> - **Junior**: Присваивает `res = my_list.sort()`, получая `None`, или замедляет сортировку через `cmp_to_key` для простых сравнений по двум полям.
> - **Senior**: Чётко различает мутирующий `list.sort()` и чистый `sorted()`, а многокритериальную сортировку задаёт кортежем в `key=` (`(-score, name)`).
