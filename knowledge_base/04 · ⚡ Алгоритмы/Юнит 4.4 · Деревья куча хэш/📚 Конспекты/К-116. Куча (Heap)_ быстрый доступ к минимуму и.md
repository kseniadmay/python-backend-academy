## Инвариант бинарной кучи (Heap)

> **Турнирная пирамида чемпиона**: в отличие от BST, элементы слева направо в куче не упорядочены — важно лишь, чтобы каждый родитель был не хуже своих детей.

- **Min-Heap** гарантирует, что на вершине пирамиды (`heap[0]`) всегда лежит абсолютный минимум.
- Бинарная куча уложена настолько плотно, что не нуждается в объектах узлов и указателях — она целиком хранится в обычном списке `list`.

## Отображение кучи на плоский массив `list`

Куча представляет собой почти полное бинарное дерево (*Complete Binary Tree*) без пустых дырок, поэтому оно идеально укладывается в массив по простым индексным формулам:

| Элемент относительно узла `i` | Формула индекса | Пример для корня (`i = 0`) |
| :--- | :--- | :--- |
| **Корень (минимум в Min-Heap)** | `arr[0]` | `arr[0]` |
| **Левый потомок** | `2 * i + 1` | `arr[1]` |
| **Правый потомок** | `2 * i + 2` | `arr[2]` |
| **Родитель узла** | `(i - 1) // 2` | — |

```text
1. Дерево Min-Heap (родитель <= детей):
         [ 1 ] (i=0)
        /     \
    [ 3 ]     [ 5 ] (i=2)
    /   \     /
  [ 7 ] [ 9 ][ 8 ]

2. Массив в памяти:
   Индекс:   0   1   2   3   4   5
   Значение:[1,  3,  5,  7,  9,  8]
             │   ▲   ▲
             └───┴───┘
```

## Сложность операций в бинарной куче

При добавлении и удалении из корня пирамида восстанавливает свой инвариант всплытием (*sift up*) или просеиванием вниз (*sift down*) по высоте дерева $\log n$:

| Операция | Сложность | Что происходит внутри массива |
| :--- | :--- | :--- |
| **Просмотр минимума (`heap[0]`)** | **$O(1)$** | Прямое чтение нулевого индекса |
| **Вставка (`heappush`)** | **$O(\log n)$** | Запись в конец и всплытие к родителю |
| **Извлечение минимума (`heappop`)** | **$O(\log n)$** | Перенос хвоста в корень и просеивание вниз |
| **Построение кучи (`heapify`)** | **$O(n)$** | Построение снизу вверх за линейное время |

## Модуль `heapq` и эмуляция Max-Heap

В стандартной библиотеке модуль `heapq` реализует **Min-Heap** поверх обычного списка `list`:

| Функция `heapq` | Сложность | Описание |
| :--- | :--- | :--- |
| `heapq.heapify(lst)` | **$O(n)$** | Превращает `lst` в кучу `in-place` |
| `heapq.heappush(h, x)` | **$O(\log n)$** | Вставляет `x` с сохранением кучи |
| `heapq.heappop(h)` | **$O(\log n)$** | Извлекает минимум (`h[0]`) |
| `heapq.heappushpop(h, x)` | **$O(\log n)$** | Вставляет `x` и сразу снимает минимум |
| `heapq.nlargest(k, it)` | **$O(n \log k)$** | Возвращает $k$ наибольших элементов |

Для эмуляции **Max-Heap** числа умножают на `-1` при вставке (`heappush(h, -val)`) и возвращают знак обратно при извлечении (`-heappop(h)`):

```python
import heapq

nums = [15, 3, 9, 1, 22, 7]
heapq.heapify(nums)
print(f'Min={nums[0]} | куча={nums}')
# >>> Min=1 | куча=[1, 3, 7, 15, 22, 9]

max_h: list[int] = []
for val in [40, 100, 25, 85]:
    # Инвертируем знак для эмуляции Max-Heap
    heapq.heappush(max_h, -val)

mx = -heapq.heappop(max_h)
print('Max из Max-Heap:', mx)
# >>> Max из Max-Heap: 100
```

## Паттерн Top-K элементов: пирамида лидеров

Чтобы найти $K$ **наибольших** элементов из огромного потока данных без полной сортировки $O(n \log n)$, в памяти держат **Min-Heap** строго размера $K$.

В корне `min_heap[0]` всегда сидит *самый слабый* из текущих лидеров — это мгновенный порог отсечения за $O(1)$: если новый элемент больше корня, заменяем корень через `heapreplace`:

```python
import heapq

def top_k_largest(
    stream: list[int], k: int
) -> list[int]:
    # Храним k лидеров в min-куче
    min_heap = stream[:k]
    heapq.heapify(min_heap)
    for x in stream[k:]:
        if x > min_heap[0]:
            heapq.heapreplace(min_heap, x)
    return sorted(min_heap, reverse=True)

data = [12, 5, 787, 1, 23, 90, 45, 600]
print(top_k_largest(data, 3))
# >>> [787, 600, 90]
```
