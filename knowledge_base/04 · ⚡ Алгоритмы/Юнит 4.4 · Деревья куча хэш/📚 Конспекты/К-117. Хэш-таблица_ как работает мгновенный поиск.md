# ⚡ К-117. Хэш-таблица (Hash Table): устройство `dict` и `set`, коллизии и амортизация

> **Ментальная модель — «Гардероб с номерками по формуле»**:
> В обычном списке, чтобы найти куртку Ивана, гардеробщику нужно осмотреть все $n$ крючков подряд за $O(n)$.
> В **хэш-таблице (Hash Table)** имя `"Иван"` пропускается через математическую **хэш-функцию (Hash Function)** `hash("Иван")`, которая мгновенно выдаёт число. Остаток от деления этого числа на количество крючков (`hash % size`) указывает точный номер крючка за **$O(1)$**!

---

## 1. Цепочка преобразования ключа в индекс ячейки

Когда вы выполняете `d[key] = value` или проверяете `key in s`, внутри происходит 4 шага:
1. Вызывается `h = hash(key)` (`key.__hash__()`) $\to$ возвращается 64-битное целое число.
2. Вычисляется индекс слота в массиве: `index = h & (table_size - 1)` (битовая маска для размера $2^k$, эквивалентная `h % table_size`).
3. Проверяется слот `index`. Если там лежит ключ, выполняется проверка равенства `existing_key == key` (`__eq__`).
4. Возвращается или записывается значение за **$O(1)$ в среднем**.

```text
Путь ключа в хэш-таблице:

Ключ "user_42" ---> hash("user_42") ---> индекс = hash % 8 (напр., 3) ---> Бакет [3]: ("user_42", 950)
```

---

## 2. Коллизии (Hash Collisions) и два метода их разрешения

Поскольку число возможных ключей бесконечно, а размер массива конечен, два разных ключа (`k1 != k2`) могут попасть в один и тот же индекс бакета. Это называется **коллизией (Collision)**.

### Метод 1: Метод цепочек (Separate Chaining)
Каждая ячейка массива хранит указатель на связный список (или динамический массив) всех пар `(key, value)`, попавших в этот индекс. При поиске мы за $O(1)$ находим бакет и линейно просматриваем короткую цепочку внутри него.

### Метод 2: Открытая адресация (Open Addressing / Probing) — используется в CPython `dict` и `set`!
Никаких внешних связных списков нет: **все элементы хранятся непосредственно в самом массиве таблицы**. Если ячейка `index` уже занята другим ключом, алгоритм по детерминированной формуле (**зондирование / Probing**) ищет следующую свободную ячейку в этом же массиве.
- При удалении ключа (`del d[k]`) ячейку нельзя просто очистить в `EMPTY`, иначе оборвётся цепочка поиска для следующих элементов — вместо этого туда ставится специальная метка **«надгробие» (`DUMMY` / `Tombstone`)**.

```text
Компaктная хэш-таблица CPython 3.6+ (Compact Open-Addressed Dict — сохраняет порядок вставки!):

1. Разреженная таблица индексов (dk_indices, хранит только номера строк в entries, 1..8 байт на слот):
   Слот хэша:  [ 0: EMPTY | 1: 0 | 2: EMPTY | 3: 2 | 4: 1 | 5: EMPTY | 6: EMPTY | 7: EMPTY ]

2. Плотный массив записей (dk_entries, заполняется строго по порядку вставки 0, 1, 2...):
   Индекс 0:  [ hash=101 | key="alice" | value=10 ]
   Индекс 1:  [ hash=252 | key="bob"   | value=20 ]
   Индекс 2:  [ hash=83  | key="carol" | value=30 ]
```

## 3. Коэффициент заполнения (Load Factor) и контракт Хэшируемости

- **Load Factor ($\alpha = \frac{n}{\text{buckets}}$)**: отношение числа элементов к размеру массива. В CPython `dict`, как только таблица заполняется на **$\frac{2}{3}$ ($\approx 0.66$)**, происходит реаллокация (размер увеличивается минимум вдвое) и перехэширование всех элементов за $O(n)$, чтобы вероятность коллизий оставалась минимальной, а поиск работал за **амортизированное $O(1)$**.
- **Какие объекты могут быть ключами `dict` и элементами `set` (Hashable)?**
  Только объекты, у которых хэш **никогда не меняется за время жизни** и соблюдается закон: `a == b ==> hash(a) == hash(b)`.
  - **Хэшируемые (неизменяемые)**: `int`, `str`, `float`, `bool`, `None`, `frozenset`, и `tuple` (только если все элементы внутри кортежа тоже хэшируемые!).
  - **Нехэшируемые (изменяемые)**: `list`, `dict`, `set` (`__hash__ = None` $\to$ `TypeError: unhashable type`).

> **Junior vs Senior**:
> - **Junior**: Считает, что `dict` в Python разрешает коллизии методом цепочек (списками), или переопределяет в своём классе только `__eq__`, удивляясь, почему экземпляры класса перестали добавляться в `set` (`TypeError: unhashable type`).
> - **Senior**: Знает, что CPython `dict` использует **открытую адресацию с псевдослучайным зондированием** и компактное разделение на `dk_indices` + `dk_entries` (благодаря чему с Python 3.7+ словари гарантированно сохраняют порядок вставки и экономят до 30% памяти). При переопределении `__eq__` в неизменяемом классе всегда реализует согласованный `__hash__` (или использует `@dataclass(frozen=True)`).

```python
# Классическая задача Two Sum за O(n) с помощью хэш-таблицы + демонстрация учебной хэш-таблицы
def two_sum_hash(nums: list[int], target: int) -> tuple[int, int] | None:
    """Находит индексы двух чисел с суммой target за 1 проход O(n)."""
    seen: dict[int, int] = {}  # {число: его_индекс}
    for i, x in enumerate(nums):
        complement = target - x
        if complement in seen:
            return seen[complement], i
        seen[x] = i
    return None

class SimpleHashTable:
    """Учебная хэш-таблица с разрешением коллизий методом цепочек."""
    def __init__(self, capacity: int = 8) -> None:
        self.capacity = capacity
        self.buckets: list[list[tuple[str, int]]] = [[] for _ in range(capacity)]

    def _idx(self, key: str) -> int:
        return hash(key) % self.capacity

    def put(self, key: str, val: int) -> None:
        bucket = self.buckets[self._idx(key)]
        for i, (k, _) in enumerate(bucket):
            if k == key:
                bucket[i] = (key, val)
                return
        bucket.append((key, val))

    def get(self, key: str) -> int | None:
        for k, v in self.buckets[self._idx(key)]:
            if k == key:
                return v
        return None

print("Two Sum O(n) для [2, 11, 7, 15], target=9 -> индексы:", two_sum_hash([2, 11, 7, 15], 9))
ht = SimpleHashTable(capacity=4)
ht.put("alpha", 100)
ht.put("beta", 200)
print("Из учебной хэш-таблицы: alpha =", ht.get("alpha"), "| beta =", ht.get("beta"))
```
