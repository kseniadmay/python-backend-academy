1. Метод открытой адресации (Open Addressing)? >> При коллизии ищется следующий свободный бакет по заданной стратегии зондирования
2. Что значит hashable? >> Объект имеет `__hash__` и его хэш-значение не меняется за время жизни объекта; также требуется корректный `__eq__`
3. Средняя сложность хэш-таблицы для поиска, вставки, удаления? >> $O(1)$ в среднем; $O(n)$ в худшем случае при множестве коллизий
4. Какой метод разрешения коллизий использует Python `dict` ? >> Открытую адресацию с псевдослучайным зондированием – не метод цепочек
5. Почему изменяемые объекты нельзя использовать как ключи? >> Изменение объекта изменит его хэш; элемент окажется в неверном бакете и станет недостижимым
6. Какая ошибка при `d[[1, 2]]` ? >> `TypeError: unhashable type: 'list'`
7. Что такое бакет? >> Ячейка массива хэш-таблицы
8. Load factor для 6 элементов в таблице размером 8? >> 0.75
9. Что делает хэш-функция? >> Преобразует ключ в целое число (хэш)
10. Сложность рехэширования? >> $O(n)$
11. Что такое рехэширование? >> Создание новой таблицы большего размера и перераспределение всех элементов
12. Почему средняя сложность $O(1)$ несмотря на дорогое рехэширование? >> Рехэширование происходит логарифмически редко; амортизированная сложность $O(1)$
13. Два типа данных Python на основе хэш-таблиц? >> `dict` и `set`
14. Что такое load factor? >> Количество элементов / размер таблицы
15. Три стратегии открытой адресации? >> Линейное зондирование, квадратичное зондирование и двойное хэширование
16. Можно ли использовать `tuple` как ключ? >> Да, если все элементы кортежа сами хэшируемы; `(1, [2, 3])` – нельзя
17. Требование к ключу хэш-таблицы? >> Объект должен быть хэшируемым (hashable)
18. Метод цепочек (Chaining)? >> Каждый бакет содержит связный список пар (ключ, значение); коллизии добавляются в список
19. Какова последовательность преобразования ключа в индекс ячейки хэш-таблицы? >> Ключ → хэш-функция → `hash % размер_таблицы` → индекс → ячейка массива (бакет)
20. Как хэш превращается в индекс? >> `hash % размер_таблицы`
21. При каком load factor Python `dict` расширяется? >> Примерно при $> 2/3$ (~0.67)
22. Почему `list` нельзя использовать как ключ? >> `list` изменяемый и нехэшируемый – `__hash__` не определён
23. Можно ли использовать `str` как ключ? >> Да – строки неизменяемы и хэшируемы
24. Что такое коллизия? >> Два разных ключа получают одинаковый индекс
25. Как коллизии влияют на производительность? >> Замедляют поиск вплоть до $O(n)$ в худшем случае
26. Какой метод разрешения коллизий хэш-таблицы используется внутри CPython для dict и set? >> Открытая адресация (Open Addressing) с псевдослучайным зондированием по формуле `j = (5*j + 1 + perturb) & mask`.
27. Что такое dummy (или DKIX_DUMMY) маркер при удалении элемента из хэш-таблицы CPython? >> Специальный маркер «ранее удалённого слота»; он сообщает поиску, что цепочку коллизий нельзя прерывать, но слот свободен для новой записи.
28. Как устроена компактная раскладка словаря dict в CPython начиная с версии 3.6? >> Разделена на две таблицы: разреженный массив индексов `dk_indices` (хранит 1-байтовые смещения) и плотный массив записей `dk_entries` (хранит `hash`, `key`, `value` в порядке вставки).
29. Почему словарь dict в Python 3.7+ гарантирует сохранение порядка вставки (insertion order)? >> Благодаря плотному массиву `dk_entries`, куда новые пары `(key, value)` просто аппендятся в конец по мере добавления.
