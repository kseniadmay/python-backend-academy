# 🔗 К-113. Связные списки (Linked Lists): узлы, указатели и классические алгоритмы

> **Ментальная модель — «Квест с записками-подсказками (Охота за сокровищами)»**:
> - В массиве (`list`) все сундуки стоят в ряд под номерами: вы можете сразу подойти к сундуку №50 за $O(1)$.
> - В **связном списке (Linked List)** сундуки (узлы / **Nodes**) спрятаны в произвольных точках города (кучи памяти). У вас в руках есть только координаты первого сундука (`head`). Открыв его, вы находите сокровище (`val`) и записку с адресом следующего сундука (`next`). Чтобы попасть к 50-му сундуку, нужно последовательно пройти все 49 предыдущих за $O(n)$! Зато добавить новый сундук между двумя известными можно мгновенно за $O(1)$ — просто переписав адрес в одной записке.

---

## 1. Односвязный и двусвязный списки в памяти

- **Односвязный список (Singly Linked List)**: каждый узел `ListNode` хранит значение `val` и ссылку `next` на следующий узел. Последний узел («хвост») указывает на `None`.
- **Двусвязный список (Doubly Linked List)**: каждый узел хранит три поля: `val`, `next` (вперёд) и `prev` (назад). Это позволяет удалять известный узел `node` за **$O(1)$** без поиска предыдущего элемента (`node.prev.next = node.next`) и используется внутри `collections.deque` и **LRU Cache**.

```text
Односвязный список (узлы разбросаны в произвольных ячейках кучи):

head -> [0x1040: val=10 | next=0x28A0] ---> [0x28A0: val=20 | next=0x09F0] ---> [0x09F0: val=30 | next=None]

Двусвязный список:

None <-- [prev | val=10 | next] <===> [prev | val=20 | next] <===> [prev | val=30 | next] --> None
```

### Сравнение со статическим/динамическим массивом (`list`)

| Операция | Массив (`list`) | Односвязный список (`head`) | Двусвязный список (`head` + `tail`) |
| :--- | :--- | :--- | :--- |
| Доступ по индексу `i` | **$O(1)$** | $O(n)$ (обход от `head`) | $O(n)$ |
| Вставка / удаление в начале (`head`) | $O(n)$ (сдвиг памяти) | **$O(1)$** | **$O(1)$** |
| Вставка / удаление в конце (`tail`) | **$O(1)$** аморт. | $O(n)$ (или $O(1)$ при хранении `tail` только для вставки) | **$O(1)$** (и вставка, и удаление) |
| Удаление известного узла `node` в середине | $O(n)$ | $O(n)$ (нужно найти `prev`) | **$O(1)$** (через `node.prev`) |
| Локальность кэша CPU (Cache Locality) | **Высокая** (непрерывный блок) | **Низкая** (узлы разбросаны в RAM, промахи кэша L1/L2) | **Низкая** + расход памяти на 2 указателя |

## 2. Три фундаментальных паттерна работы со связными списками

### Паттерн 1: Фиктивный узел-страж (`Dummy Node` / `Sentinel Node`)
При удалении или слиянии списков голова `head` сама может измениться или удалиться. Чтобы не писать десятки проверок `if head is None`, создаётся временный узел `dummy = ListNode(0, head)`, а в конце возвращается `dummy.next`.

### Паттерн 2: Разворот списка на месте (`In-place Reversal`) за $O(n)$ времени и $O(1)$ памяти
Используются три указателя (`prev = None`, `curr = head`, `nxt = curr.next`). На каждом шаге стрелка `curr.next` перенаправляется назад на `prev`:

```text
До шага:     prev      curr ---> nxt ---> ...
После шага:  prev <--- curr      nxt ---> ...  (затем prev = curr, curr = nxt)
```

### Паттерн 3: Быстрый и медленный указатели («Черепаха и Заяц» / Floyd's Tortoise and Hare)
Указатель `slow` делает **1 шаг** (`slow = slow.next`), а `fast` делает **2 шага** (`fast = fast.next.next`):
- **Поиск середины списка**: когда `fast` добежит до конца (`None`), `slow` окажется ровно посередине!
- **Обнаружение цикла (Floyd's Cycle Detection)**: если в списке есть петля, `fast` гарантированно догонит `slow` внутри цикла (`slow is fast`) за $O(n)$ времени и **$O(1)$ памяти** (без создания `set` посещённых узлов!).

```python
from __future__ import annotations

class ListNode:
    def __init__(self, val: int = 0, next: ListNode | None = None) -> None:
        self.val = val
        self.next = next

def to_list(head: ListNode | None) -> list[int]:
    res: list[int] = []
    while head is not None:
        res.append(head.val)
        head = head.next
    return res

# 1. Разворот односвязного списка in-place за O(n) времени и O(1) памяти
def reverse_list(head: ListNode | None) -> ListNode | None:
    prev: ListNode | None = None
    curr = head
    while curr is not None:
        nxt = curr.next       # 1. Сохраняем ссылку на хвост, чтобы не потерять его
        curr.next = prev      # 2. Разворачиваем стрелку назад
        prev = curr           # 3. Сдвигаем prev вперёд
        curr = nxt            # 4. Сдвигаем curr вперёд
    return prev

# 2. Поиск середины списка алгоритмом «Черепахи и Зайца» за 1 проход
def find_middle(head: ListNode) -> int:
    slow: ListNode = head
    fast: ListNode | None = head
    while fast is not None and fast.next is not None:
        slow = slow.next  # type: ignore[assignment]
        fast = fast.next.next
    return slow.val

# 3. Проверка наличия цикла по алгоритму Флойда за O(1) памяти
def has_cycle(head: ListNode | None) -> bool:
    slow = fast = head
    while fast is not None and fast.next is not None:
        slow = slow.next          # type: ignore[union-attr]
        fast = fast.next.next
        if slow is fast:
            return True
    return False

n1 = ListNode(10, ListNode(20, ListNode(30, ListNode(40, ListNode(50)))))
print("Середина списка [10, 20, 30, 40, 50]:", find_middle(n1))
rev_head = reverse_list(n1)
print("После разворота in-place:", to_list(rev_head))

# Создадим список с циклом: 1 -> 2 -> 3 -> (обратно в 2)
c1, c2, c3 = ListNode(1), ListNode(2), ListNode(3)
c1.next, c2.next, c3.next = c2, c3, c2
print("Цикл обнаружен алгоритмом Флойда:", has_cycle(c1))
```

> **Junior vs Senior**:
> - **Junior**: При развороте связного списка пишет `curr.next = prev` *до* сохранения `nxt = curr.next`, мгновенно теряя ссылку на оставшуюся часть списка в памяти, либо проверяет цикл через `visited = set()`, тратя $O(n)$ памяти.
> - **Senior**: Всегда сохраняет `nxt = curr.next` первой строкой в цикле разворота, использует `dummy`-узел для защиты от граничных условий на `head` и применяет алгоритм Флойда (`slow`/`fast`) для детекции циклов за $O(1)$ памяти.
