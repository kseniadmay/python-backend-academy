# ⏱️ К-110. Big O: временная и пространственная сложность (Time & Space Complexity)

> **Ментальная модель — «Масштабирование доставки по городу»**: Представьте курьерскую службу при росте числа заказов $n$ с $10$ до $1\,000\,000$:
> - **$O(1)$ (Постоянная / Constant Time)** — вы берёте заказ с верхней полки по известному номеру ячейки. Неважно, сколько всего полок на складе ($10$ или $10^6$), время одно и то же.
> - **$O(\log n)$ (Логарифмическая / Logarithmic Time)** — игра «Угадай число от $1$ до $1\,000\,000$»: каждым вопросом вы отсекаете половину вариантов и находите ответ максимум за $\approx 20$ шагов ($\log_2 10^6 \approx 19.93$).
> - **$O(n)$ (Линейная / Linear Time)** — курьер обходит все $n$ квартир по очереди. В $10$ раз больше квартир $\implies$ в $10$ раз больше времени.
> - **$O(n^2)$ (Квадратичная / Quadratic Time)** — каждый из $n$ гостей на вечеринке жмёт руку каждому из $n$ гостей: при $n = 1\,000$ это уже $\approx 1\,000\,000$ рукопожатий!

## 1. Зачем нужна нотация Big-O (Asymptotic Analysis)?

Измерять скорость алгоритма в секундах ненадёжно: один и тот же код на суперкомпьютере и на микроконтроллере покажет разное время.
**Асимптотическая сложность (Big-O Notation)** измеряет не секунды, а **скорость роста числа элементарных операций** (или объёма памяти) при стремлении размера входных данных $n \to \infty$.

### Три золотых правила упрощения Big-O
1. **Оцениваем худший сценарий (Worst-Case Scenario)**: если линейный поиск может найти элемент на первом шаге ($O(1)$ — *Best Case*) или в самом конце ($O(n)$ — *Worst Case*), в Big-O фиксируется верхняя граница $O(n)$.
2. **Отбрасываем константы (Drop Constants)**: $O(2n)$ и $O(500n)$ записываются просто как $O(n)$, так как нас интересует характер кривой роста.
3. **Оставляем только старшее слагаемое (Drop Non-Dominant Terms)**: в выражении $O(n^2 + 100n + 50)$ при $n = 10^5$ вклад $n^2 = 10^{10}$ полностью подавляет $100n = 10^7$, поэтому итог — $O(n^2)$.

```text
Рост числа операций при увеличении входа n:

Операции ^      O(2^n)   O(n^2)
         |        |       /
         |        |      /      O(n log n)
         |        |     /        /
         |        |    /        /     O(n)
         |        |   /        /     /
         |        |  /        /    /      O(log n)
         |        | /        /   /      .---------
         |        |/        /  /   .---'
         |--------+--------/--/.------------------- O(1)
         +---------------------------------------------> Размер данных (n)
```

## 2. Иерархия классов сложности (от быстрых к медленным)

| Сложность | Название (RU / EN) | Число операций при $n = 1\,000$ | Типичный пример в Python |
| :--- | :--- | :--- | :--- |
| **$O(1)$** | Константная (*Constant*) | $1$ | Доступ по индексу `arr[i]`, поиск в `dict` / `set`, `list.append()` |
| **$O(\log n)$** | Логарифмическая (*Logarithmic*) | $\approx 10$ | Бинарный поиск (`bisect`), поиск в сбалансированном BST |
| **$O(n)$** | Линейная (*Linear*) | $1\,000$ | Одиночный цикл `for x in arr`, `x in list`, `min(arr)`, `sum(arr)` |
| **$O(n \log n)$** | Линейно-логарифмическая (*Linearithmic*) | $\approx 10\,000$ | Сортировка `arr.sort()` / `sorted(arr)` (алгоритм **Timsort**), Merge Sort |
| **$O(n^2)$** | Квадратичная (*Quadratic*) | $1\,000\,000$ | Двойной вложенный цикл по массиву, сортировка пузырьком (Bubble Sort) |
| **$O(2^n)$** | Экспоненциальная (*Exponential*) | $\approx 10^{301}$ (зависание) | Наивный рекурсивный Фибоначчи без кэша, генерация всех подмножеств |
| **$O(n!)$** | Факториальная (*Factorial*) | $\infty$ | Полный перебор всех перестановок (`itertools.permutations`) в задаче коммивояжёра |

## 3. Сложение vs Умножение сложностей

- **Последовательные блоки $\implies$ Сложение $O(A + B) = O(\max(A, B))$**:
  Если сначала выполняется цикл на $n$ шагов, а *после него* — цикл на $m$ шагов, итоговая сложность равна $O(n + m)$. Если оба цикла идут до $n$, то $O(n + n) = O(2n) = O(n)$.
- **Вложенные блоки $\implies$ Умножение $O(A \cdot B)$**:
  Если внутри каждого из $n$ шагов внешнего цикла выполняется $m$ шагов внутреннего цикла (или операция `x in list` за $O(m)$!), сложности перемножаются: $O(n \cdot m)$, а при $n = m$ получаем $O(n^2)$.

```python
def analyze_loops(n: int) -> tuple[int, int]:
    # 1. Последовательные циклы: O(n) + O(n) = O(n)
    seq_ops = 0
    for _ in range(n):
        seq_ops += 1
    for _ in range(n):
        seq_ops += 1

    # 2. Вложенные циклы: O(n) * O(n) = O(n^2)
    nested_ops = 0
    for _ in range(n):
        for _ in range(n):
            nested_ops += 1

    return seq_ops, nested_ops

seq_100, nested_100 = analyze_loops(100)
print(f"При n=100: последовательные = {seq_100} оп. O(n), вложенные = {nested_100} оп. O(n^2)")
```

## 4. Временная vs Пространственная сложность (Time vs Space Complexity)

- **Временная сложность (Time Complexity)** — сколько *шагов процессора* требует алгоритм при росте $n$.
- **Пространственная сложность (Space Complexity / Auxiliary Space)** — сколько *дополнительной оперативной памяти* выделяет алгоритм (помимо самих входных данных), включая новые структуры данных и **глубину стека вызовов (Call Stack)** при рекурсии!

> **Junior vs Senior**:
> - **Junior**: Пишет проверку пересечения двух списков через ` [x for x in list_a if x in list_b] `, думая, что один цикл `for` в списковом включении означает $O(n)$. На деле оператор `x in list_b` внутри цикла делает линейное сканирование $O(m)$ на каждом шаге, превращая код в скрытый $O(n \cdot m) \approx O(n^2)$, который зависает на $100\,000$ элементов.
> - **Senior**: Использует компромисс **«память в обмен на время» (Space-Time Tradeoff)** — предварительно конвертирует `set_b = set(list_b)` за $O(m)$ времени и $O(m)$ памяти, после чего проверка `x in set_b` работает за $O(1)$, снижая общую временную сложность с $O(n^2)$ до линейной $O(n + m)$.

```python
# Демонстрация Space-Time Tradeoff: поиск дубликатов за O(n^2) vs O(n)
def has_duplicate_quadratic(nums: list[int]) -> tuple[bool, int]:
    """O(n^2) по времени, O(1) по дополнительной памяти."""
    comparisons = 0
    n = len(nums)
    for i in range(n):
        for j in range(i + 1, n):
            comparisons += 1
            if nums[i] == nums[j]:
                return True, comparisons
    return False, comparisons

def has_duplicate_linear(nums: list[int]) -> tuple[bool, int]:
    """O(n) по времени, O(n) по дополнительной памяти (хэш-таблица set)."""
    lookups = 0
    seen: set[int] = set()
    for x in nums:
        lookups += 1
        if x in seen:
            return True, lookups
        seen.add(x)
    return False, lookups

sample = list(range(200)) + [199]  # дубликат в самом конце
res_q, ops_q = has_duplicate_quadratic(sample)
res_l, ops_l = has_duplicate_linear(sample)
print(f"O(n^2): найден={res_q}, сравнений={ops_q}")
print(f"O(n)  : найден={res_l}, обращений к set={ops_l} (ускорение в {ops_q // ops_l} раз!)")
```

## 5. Шпаргалка по сложности операций базовых коллекций CPython

| Операция | `list` (динамический массив) | `collections.deque` (двусвязный список блоков) | `dict` / `set` (хэш-таблица) |
| :--- | :--- | :--- | :--- |
| Доступ по индексу / ключу | **$O(1)$** (`arr[i]`) | $O(n)$ (в середине), **$O(1)$** по краям | **$O(1)$** в среднем (`d[k]`) |
| Поиск элемента (`x in col`) | $O(n)$ (линейный скан) | $O(n)$ (линейный скан) | **$O(1)$** в среднем ($O(n)$ при коллизиях) |
| Добавление в конец (`append`) | **$O(1)$** амортизированно | **$O(1)$** | **$O(1)$** амортизированно |
| Вставка / удаление в начале | **$O(n)$** (`insert(0, x)`, `pop(0)`) | **$O(1)$** (`appendleft`, `popleft`) | — |
| Удаление по значению / ключу | $O(n)$ (`remove(x)`) | $O(n)$ (`remove(x)`) | **$O(1)$** в среднем (`del d[k]`) |
