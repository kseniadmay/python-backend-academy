# ⏱️ Big O: временная и пространственная сложность (Time & Space Complexity)

> **Ментальная модель — «Масштабирование доставки по городу»**:
> Представьте курьерскую службу при росте числа заказов $n$ с $10$ до $1\,000\,000$:
> - **$O(1)$ (Постоянная / Constant Time)** — вы берёте заказ с верхней полки по известному номеру ячейки. Неважно, сколько полок на складе ($10$ или $10^6$), время одно и то же.
> - **$O(\log n)$ (Логарифмическая / Logarithmic Time)** — игра «Угадай число от $1$ до $1\,000\,000$»: каждым вопросом отсекается половина вариантов ($\log_2 10^6 \approx 20$ шагов).
> - **$O(n)$ (Линейная / Linear Time)** — курьер обходит все $n$ квартир по очереди: в 10 раз больше квартир $\implies$ в 10 раз больше времени.
> - **$O(n^2)$ (Квадратичная / Quadratic Time)** — каждый из $n$ гостей жмёт руку каждому из $n$ гостей: при $n = 1\,000$ это уже $\approx 1\,000\,000$ рукопожатий!

## Зачем нужна нотация Big-O (Asymptotic Analysis)?

Измерять скорость алгоритма в секундах ненадёжно: один и тот же код на мощном сервере и на слабом ноутбуке покажет разное время.
**Асимптотическая сложность (Big-O Notation)** измеряет не секунды, а **скорость роста числа элементарных операций** (или объёма памяти) при стремлении размера входных данных $n \to \infty$.

### Три золотых правила упрощения Big-O
1. **Оцениваем худший сценарий (Worst-Case)**: если поиск может найти элемент за 1 шаг ($O(1)$) или в конце ($O(n)$), в Big-O фиксируется верхняя граница $O(n)$.
2. **Отбрасываем константы (Drop Constants)**: $O(2n)$ и $O(500n)$ записываются как $O(n)$, важна лишь кривая роста.
3. **Оставляем старшее слагаемое (Drop Non-Dominant)**: в $O(n^2 + 100n)$ при $n = 10^5$ слагаемое $n^2 = 10^{10}$ доминирует, итог — $O(n^2)$.

```text
Рост операций от размера входа n:

Операции
   ^
   │  O(2^n)    O(n^2)
   │    │        /     O(n log n)
   │    │       /       /    O(n)
   │    │      /       /    /
   │    │     /       /    /   O(log n)
   │    │    /       /    /     ...
   │────┼───/───────/────/─────── O(1)
   └────┴───────────────────────► n
```

## Иерархия классов сложности (от быстрых к медленным)

| Сложность | Название (RU / EN) | Операций при $n = 1\,000$ | Типичный пример в Python |
| :--- | :--- | :--- | :--- |
| **$O(1)$** | Константная (*Constant*) | $1$ | Доступ `arr[i]`, поиск в `dict`/`set`, `list.append()` |
| **$O(\log n)$** | Логарифмическая (*Logarithmic*) | $\approx 10$ | Бинарный поиск (`bisect`), поиск в сбалансированном BST |
| **$O(n)$** | Линейная (*Linear*) | $1\,000$ | Одиночный цикл `for x in arr`, `x in list`, `sum(arr)` |
| **$O(n \log n)$** | Линейно-логарифмическая | $\approx 10\,000$ | Сортировка `arr.sort()` (Timsort), Merge Sort |
| **$O(n^2)$** | Квадратичная (*Quadratic*) | $1\,000\,000$ | Двойной вложенный цикл, пузырьковая сортировка |
| **$O(2^n)$** | Экспоненциальная (*Exponential*) | $\approx 10^{301}$ (зависание) | Рекурсивный Фибоначчи без кэша, все подмножества |
| **$O(n!)$** | Факториальная (*Factorial*) | $\infty$ | Перебор всех перестановок (`itertools.permutations`) |

## Сложение vs Умножение сложностей

- **Последовательные блоки $\implies$ Сложение $O(A + B) = O(\max(A, B))$**:
  Если сначала выполняется цикл на $n$ шагов, а затем — цикл на $m$ шагов, итоговая сложность $O(n + m)$. При одинаковых $n$: $O(n + n) = O(2n) = O(n)$.
- **Вложенные блоки $\implies$ Умножение $O(A \cdot B)$**:
  Если внутри каждого из $n$ шагов внешнего цикла выполняется $m$ шагов внутреннего (или операция `x in list` за $O(m)$!), сложности перемножаются: $O(n \cdot m)$, а при $n = m$ получаем $O(n^2)$.

```python
def analyze_loops(n: int) -> tuple[int, int]:
    # 1. Последовательно: O(n) + O(n) = O(n)
    seq_ops = 0
    for _ in range(n):
        seq_ops += 1
    for _ in range(n):
        seq_ops += 1

    # 2. Вложенные циклы: O(n) * O(n) = O(n^2)
    nested_ops = 0
    for _ in range(n):
        for _ in range(n):
            nested_ops += 1

    return seq_ops, nested_ops

seq_100, nested_100 = analyze_loops(100)
print(f"n=100: O(n)={seq_100} оп, "
      f"O(n^2)={nested_100} оп")
```

## Временная vs Пространственная сложность: Space-Time Tradeoff

- **Временная сложность (Time Complexity)** — сколько элементарных шагов процессора требует алгоритм при росте $n$.
- **Пространственная сложность (Space Complexity)** — сколько дополнительной памяти выделяет алгоритм (помимо входных данных), включая вспомогательные структуры и глубину стека вызовов (Call Stack) при рекурсии.

## Практика Space-Time Tradeoff: поиск дубликатов $O(n^2)$ vs $O(n)$

Сравним наглядно квадратичный подход без выделения памяти и линейный подход через хэш-таблицу `set`:

```python
def has_duplicate_quadratic(
    nums: list[int]
) -> tuple[bool, int]:
    """O(n^2) по времени, O(1) по памяти."""
    comps = 0
    n = len(nums)
    for i in range(n):
        for j in range(i + 1, n):
            comps += 1
            if nums[i] == nums[j]:
                return True, comps
    return False, comps

def has_duplicate_linear(
    nums: list[int]
) -> tuple[bool, int]:
    """O(n) времени, O(n) памяти (set)."""
    lookups = 0
    seen: set[int] = set()
    for x in nums:
        lookups += 1
        if x in seen:
            return True, lookups
        seen.add(x)
    return False, lookups

sample = list(range(100)) + [99]
res_q, ops_q = has_duplicate_quadratic(sample)
res_l, ops_l = has_duplicate_linear(sample)
print(f"O(n^2): {res_q}, ops={ops_q}")
print(f"O(n)  : {res_l}, ops={ops_l}")
```
