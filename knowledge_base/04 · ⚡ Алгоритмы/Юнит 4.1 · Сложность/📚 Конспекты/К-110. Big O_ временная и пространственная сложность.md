## Ментальная модель: масштабирование нагрузки

Представьте курьерскую службу доставки при росте числа заказов $n$ от $10$ до $1\,000\,000$.

Скорость выполнения операций ведёт себя совершенно по-разному в зависимости от выбранного алгоритма и структуры данных. Асимптотическая оценка показывает, как именно сервис справляется с лавинообразным ростом нагрузки.

---

## Константное время: O(1)

Выдача заказа со склада по известному номеру ячейки или ключу в хэш-таблице (`dict`/`set`).

Сколько бы полок ни стояло на складе ($10$ или $10^6$), операция занимает одно фиксированное время: $O(1)$ (Constant Time).

---

## Логарифмическое время: O(log n)

Поиск заказа в отсортированном реестре методом деления пополам (бинарный поиск).

Каждый шаг отсекает ровно половину оставшихся вариантов: для базы в $1\,000\,000$ заказов алгоритм находит нужный максимум за $20$ шагов ($\log_2 10^6 \approx 20$).

---

## Линейное время: O(n)

Курьер последовательно объезжает адреса по маршрутному листу один за другим.

Время выполнения растёт строго пропорционально объёму данных: в $10$ раз больше адресов $\implies$ в $10$ раз больше времени ($O(n)$ Linear Time).

---

## Квадратичное время: O(n²)

Попарная сверка каждого заказа с каждым другим (например, поиск конфликтующих адресов вложенным циклом).

При росте базы в $10$ раз время вырастает в $100$ раз ($n^2$). Для $1\,000$ заказов это $1\,000\,000$ операций, а для миллиона — сервис гарантированно зависнет.

---

## Асимптотический анализ и нотация Big-O

Измерять скорость алгоритма в секундах ненадёжно: один и тот же код на мощном сервере и на ноутбуке покажет разное физическое время.

**Асимптотическая сложность (Big-O)** оценивает не секунды, а **скорость роста числа операций** (или объёма памяти) при стремлении размера данных $n \to \infty$.

**Три правила упрощения Big-O:**
1. **Худший сценарий (Worst-Case)**: если поиск находит элемент за 1 шаг ($O(1)$) или в конце ($O(n)$), фиксируется верхняя граница $O(n)$.
2. **Отбрасывание констант (Drop Constants)**: $O(2n)$ и $O(500n)$ сводятся к $O(n)$, важна форма кривой роста.
3. **Старшее слагаемое (Drop Non-Dominant)**: в $O(n^2 + 100n)$ при больших $n$ слагаемое $n^2$ доминирует, итог — $O(n^2)$.

```text
Рост операций от размера входа n:

Операции
   ^
   │  O(2^n)    O(n^2)
   │    │        /     O(n log n)
   │    │       /       /    O(n)
   │    │      /       /    /
   │    │     /       /    /   O(log n)
   │    │    /       /    /     ...
   │────┼───/───────/────/─────── O(1)
   └────┴───────────────────────► n
```

| :--- | :--- | :--- | :--- |
| **$O(1)$** | Константная (*Constant*) | $1$ | Доступ `arr[i]`, поиск в `dict`/`set`, `list.append()` |

## Сложение vs Умножение сложностей

- **Последовательные блоки $\implies$ Сложение $O(A + B) = O(\max(A, B))$**:
  Если сначала выполняется цикл на $n$ шагов, а затем — цикл на $m$ шагов, сложность равна $O(n + m)$. При $n = m$: $O(n + n) = O(2n) = O(n)$.
- **Вложенные блоки $\implies$ Умножение $O(A \cdot B)$**:
  Если внутри каждого из $n$ шагов внешнего цикла выполняется $m$ шагов внутреннего (или операция `x in list` за $O(m)$), сложности перемножаются: $O(n \cdot m)$, а при $n = m$ получаем $O(n^2)$.

```python
def analyze_loops(n: int) -> tuple[int, int]:
    # 1. Последовательно: O(n) + O(n) = O(n)
    seq_ops = 0
    for _ in range(n):
        seq_ops += 1
    for _ in range(n):
        seq_ops += 1
    # 2. Вложенные циклы: O(n) * O(n) = O(n^2)
    nested_ops = 0
    for _ in range(n):
        for _ in range(n):
            nested_ops += 1
    return seq_ops, nested_ops
```

## Временная vs Пространственная сложность

- **Временная сложность (Time Complexity)** — число элементарных шагов процессора при росте размера входных данных $n$.
- **Пространственная сложность (Space Complexity / Auxiliary Space)** — объём дополнительной оперативной памяти для вспомогательных структур и фреймов стека вызовов (Call Stack) при рекурсии.

---

## Практика Space-Time Tradeoff: поиск дубликатов

Сравним квадратичный подход без выделения дополнительной памяти и линейный подход через хэш-таблицу `set`:

```python
def has_duplicate_quadratic(
    nums: list[int]
) -> tuple[bool, int]:
    """O(n^2) по времени, O(1) по памяти."""
    comps = 0
    n = len(nums)
    for i in range(n):
        for j in range(i + 1, n):
            comps += 1
            if nums[i] == nums[j]:
                return True, comps
    return False, comps
```
