1. Сложность `arr.pop()` с конца? >> $O(1)$
2. Сложность `sorted(arr)`? >> $O(n \log n)$ по времени (алгоритм Timsort — адаптивный гибрид Merge Sort и Insertion Sort); $O(n)$ памяти. Пример и пояснение: `sorted([3, 1, 2])` создаёт и возвращает **новый** отсортированный список `[1, 2, 3]`, не меняя исходный (в отличие от `arr.sort()`, который сортирует список на месте за $O(1)$ по доп. памяти).
3. Сложность `s1 - s2` (разность множеств)? >> $O(\text{len}(s1))$ по длине первого множества. Для разности алгоритм обходит все элементы `s1` и за $O(1)$ проверяет отсутствие в `s2`. Разъяснение: $O(\min(n, m))$ применяется для пересечения `s1 & s2`.
4. Каким типом структуры является `dict` в Python? >> Хэш-таблица; ключи хэшируются для определения индекса в памяти
5. Сложность `arr.copy()`? >> $O(n)$; поверхностная копия, копирует ссылки на все $n$ элементов
6. Сложность `len(arr)`? >> $O(1)$; длина хранится как атрибут `ob_size` объекта
7. К какому типу относится `list` в Python? >> Динамический массив указателей (`PyObject*`) с геометрическим овер-аллокатором памяти
8. `x in list` vs `x in set` — в чём разница? >> `list` — $O(n)$ линейный перебор; `set` — $O(1)$ хэш-поиск в среднем
9. Сложность `list(d.keys())`? >> $O(n)$; создание нового списка со ссылками на все ключи
10. Сложность `arr.append()`? >> $O(1)$ амортизированная; геометрическое перевыделение буфера компенсирует редкие расширения
11. Сложность `arr.remove(x)`? >> $O(n)$; линейный поиск элемента плюс сдвиг последующих элементов влево
12. Разница `s.remove(x)` и `s.discard(x)`? >> `remove` выбрасывает `KeyError`, если элемента нет; `discard` молча игнорирует отсутствие
13. Сложность `s1 & s2` (пересечение множеств)? >> $O(\min(n, m))$ — алгоритм итерируется по меньшему из двух множеств с проверкой наличия во втором за $O(1)$
14. Сложность `s1 | s2` (объединение множеств)? >> $O(n + m)$ — копирует все уникальные элементы обоих множеств в новую хэш-таблицу
15. Для чего лучше использовать `set`, а не `list`? >> Хранение уникальных элементов, быстрый поиск (`x in s` за $O(1)$), операции над множествами
16. Почему `arr.insert(0, x)` — $O(n)$? >> Требует физического сдвига всех последующих элементов массива вправо на одну позицию
17. Сложность `x in s`? >> $O(1)$ в среднем; хэш-поиск
18. Сложность `del d['key']`? >> $O(1)$ в среднем; удаление записи из хэш-таблицы
19. Является ли `dict` в Python 3.7+ упорядоченным? >> Да; гарантирует порядок вставки (Insertion Order), но индексация по целочисленному смещению не поддерживается
20. Что делает хэш-функция? >> Вычисляет целочисленный хэш-код ключа для определения индекса ячейки (bucket) в памяти
21. Что такое `set` в Python? >> Хэш-таблица без значений (только уникальные ключи); реализация аналогична `dict`
22. Сложность добавления/обновления ключа в `dict`? >> $O(1)$ амортизированная
23. Сложность доступа по индексу `arr[i]`? >> $O(1)$; непрерывный массив ссылок позволяет мгновенно вычислить адрес по формуле `base + i * 8`
24. Почему `key in dict` быстрее `key in list`? >> `dict` использует хэш-функцию ($O(1)$ в среднем), а `list` — последовательный перебор ($O(n)$)
25. Какие базовые коллекции Python не поддерживают доступ по индексу? >> `dict` и `set`; они не поддерживают адресацию по индексу
26. Сложность `x in arr`? >> $O(n)$; последовательный перебор элементов
27. Сложность `arr.pop(0)`? >> $O(n)$; удаление первого элемента требует сдвига всех оставшихся элементов влево
28. Сложность `len(d)`? >> $O(1)$; длина хранится в заголовке словаря
29. Сложность `arr.index(x)` и `arr.count(x)`? >> $O(n)$; линейный проход по массиву
30. Сложность `d['key']` и `d.get('key')`? >> $O(1)$ амортизированная
31. Сложность `arr.reverse()`? >> $O(n)$ по времени, $O(1)$ по памяти (in-place разворот)
32. Сложность `s.add(x)`? >> $O(1)$ амортизированная
33. Когда операции со словарём деградируют до $O(n)$? >> При большом количестве коллизий хэшей
34. Поиск дубликатов: `set` vs вложенные циклы? >> `set`: $O(n)$ время, $O(n)$ память; вложенные циклы: $O(n^2)$ время, $O(1)$ память
