## Статический массив и динамический `list`

> **Ряд кресел против раздвижного зала**: статический массив занимает фиксированный блок памяти из $N$ ячеек, а `list` в Python выделяет память с запасом и автоматически расширяется при переполнении.

- **Статический массив (Static Array)** — подряд идущие ячейки памяти фиксированной длины $N$; адрес любого элемента вычисляется сразу за $O(1)$.
- **Динамический массив (`list`)** — хранит буфер с запасом (`capacity > length`): пока места хватает, вставка в конец стоит $O(1)$, а при заполнении выделяется буфер большего размера с копированием элементов за $O(n)$.
- **Есть ли статические массивы в Python?** В самом языке их нет (`array.array` тоже динамический); массивы строго фиксированного размера предоставляет **NumPy** (`numpy.ndarray`).

## Адресная арифметика O(1) и локальность кэша

Массив хранит элементы в непрерывном блоке памяти, поэтому процессор мгновенно вычисляет адрес нужного индекса:

$$\text{Address}(i) = \text{Base\_Address} + i \times \text{Element\_Size}$$

Благодаря этому чтение `arr[0]` и `arr[999_999]` выполняется за строго одинаковое время **$O(1)$**.

Ещё быстрее работает **кэш-локальность (Cache-Friendly)**: процессор считывает RAM кэш-линиями по 64 байта, поэтому соседние элементы (`arr[1]`, `arr[2]`...) сразу попадают в сверхбыстрый кэш L1–L3 (**Cache Hit**):

```text
Массив указателей PyObject* (шаг 8 байт):

Индекс  Адрес     Буфер в памяти
 [0]   0x1000 ──► [ ptr_0 ]
 [1]   0x1008 ──► [ ptr_1 ]
 [2]   0x1010 ──► [ ptr_2 ]
 [3]   0x1018 ──► [ запас (пусто) ]
 [4]   0x1020 ──► [ запас (пусто) ]

ob_size   = 3  (число элементов)
allocated = 5  (вместимость буфера)
```

## Анатомия `PyListObject` в CPython

Внутри интерпретатора CPython объект `list` опирается на структуру `PyListObject` с тремя ключевыми полями:

1. `ob_item` (`PyObject **`) — указатель на непрерывный массив ссылок (по 8 байт) на объекты в куче.
2. `ob_size` (`length`) — текущее число реально хранящихся элементов (`len(lst)`).
3. `allocated` (`capacity`) — сколько ячеек под указатели выделено в буфере с запасом (**Over-allocation**).

Благодаря хранению указателей, сам массив адресов всегда имеет фиксированный размер шага, даже если внутри списка лежат объекты разных типов.

## Алгоритм `list.append(x)` и амортизация O(1)

При добавлении элемента в конец списка возможны два сценария:

- **Есть свободное место (`length < capacity`)**: ссылка записывается в `ob_item[length]` за **$O(1)$**.
- **Буфер заполнен (`length == capacity`)**: выделяется новый блок (в CPython с запасом $\approx 1.125$), все $n$ указателей копируются в него за $O(n)$, а старый буфер освобождается.

Так как переаллокации случаются экспоненциально реже по мере роста, средняя стоимость одного вызова остаётся **$O(1)$** (проверим это через `sys.getsizeof`):

```python
import sys

lst: list[int] = []
prev_bytes = sys.getsizeof(lst)
resizes: list[tuple[int, int]] = []

for i in range(1, 25):
    lst.append(i)
    cur_bytes = sys.getsizeof(lst)
    if cur_bytes != prev_bytes:
        resizes.append((len(lst), cur_bytes))
        prev_bytes = cur_bytes

print('Реаллокации list (len -> байты):')
# >>> Реаллокации list (len -> байты):

for n, sz in resizes[:4]:
    print(f'  n={n:2d} -> {sz} байт')
# >>>   n= 1 -> 88 байт
# >>>   n= 5 -> 120 байт
# >>>   n= 9 -> 184 байт
# >>>   n=17 -> 248 байт
```

## Сложность вставки и удаления в начале списка

В непрерывном массиве не может быть пустых «дырок» между элементами, поэтому `insert(0, x)` и `pop(0)` сдвигают все $n$ указателей за $O(n)$.

Сравнение стоимости основных операций со списком `list` по позициям:

| Операция в `list` | В конец (`i = n-1`) | В середину (`n // 2`) | В начало (`i = 0`) |
| :--- | :--- | :--- | :--- |
| Чтение/запись `lst[i]` | **$O(1)$** | **$O(1)$** | **$O(1)$** |
| Вставка (`append` / `insert`) | **$O(1)$ аморт.** | **$O(n)$** | **$O(n)$** |
| Удаление (`pop()` / `pop(i)`) | **$O(1)$** | **$O(n)$** | **$O(n)$** |
| Срез `lst[a:b]` | **$O(b - a)$** | **$O(b - a)$** | **$O(b - a)$** |

## Строки `str` и ловушка квадратичной конкатенации

Строки (`str`) в Python — неизменяемые массивы символов.

Выражение `s = s + ch` в цикле на каждой итерации выделяет новую строку и копирует все прежние символы, давая сложность $O(n^2)$, поэтому части собирают через `list` + `''.join()` за $O(n)$:

```python
def build_csv_row(items: list[int]) -> str:
    parts: list[str] = []
    for item in items:
        parts.append(str(item * 10))

    # Единая линейная сборка за O(n)
    return ','.join(parts)

print('CSV:', build_csv_row([1, 2, 3, 4, 5]))
# >>> CSV: 10,20,30,40,50
```

## Паттерн Swap-and-Pop: удаление за O(1)

Если порядок элементов в списке не важен, произвольный элемент по индексу можно удалить без сдвига массива за $O(1)$:

1. Перезаписываем удаляемую ячейку последним элементом списка.
2. Удаляем дубликат с конца через `arr.pop()` за $O(1)$:

```python
def fast_unordered_remove(
    arr: list[str], index: int
) -> str:
    removed = arr[index]

    # Переносим последний элемент на место
    arr[index] = arr[-1]
    arr.pop()
    return removed

servers = ['srv-1', 'srv-2', 'srv-3', 'srv-4']
deleted = fast_unordered_remove(servers, 1)

print(f'Удалён: {deleted}')
# >>> Удалён: srv-2

print(f'Осталось: {servers}')
# >>> Осталось: ['srv-1', 'srv-4', 'srv-3']
```

> **Junior vs Senior**:
> - **Junior**: удаляет и вставляет элементы в начало `list` внутри цикла (`pop(0)` за $O(n^2)$) и клеит строки через `+=` в цикле.
> - **Senior**: понимает устройство `PyListObject` и амортизацию `append`, выносит очереди на `collections.deque`, использует Swap-and-Pop для удаления без порядка за $O(1)$ и учитывает локальность CPU-кэша.
