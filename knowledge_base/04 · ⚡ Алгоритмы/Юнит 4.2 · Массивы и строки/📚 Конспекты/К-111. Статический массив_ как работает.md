# 🧱 Статический и динамический массив: устройство в памяти и амортизация

> **Ментальная модель — «Ряд кресел в кинотеатре vs Раздвижной стол»**:
> - **Статический массив (Static Array)** — ряд из $N$ пронумерованных кресел, забетонированных в полу вплотную друг к другу. Зная адрес первого кресла, вы за $O(1)$ вычисляете адрес любого кресла. Но добавить $(N+1)$-е место в этот же ряд нельзя, если соседнее пространство уже занято.
> - **Динамический массив (`list` в Python)** — ряд с запасом свободных мест (`capacity > length`). Пока есть запас, новые зрители садятся за $O(1)$. Когда запас исчерпан, выделяется новый ряд в $\approx 1.125\text{–}2$ раза больше, все пересаживаются за $O(n)$, и снова появляется свободный запас!

## Статический массив и формула адресной арифметики $O(1)$

**Массив (Array)** хранит элементы в **непрерывном блоке оперативной памяти (Contiguous Memory Block)**.
Благодаря непрерывности процессор вычисляет адрес элемента мгновенно:

$$\text{Address}(i) = \text{Base\_Address} + i \times \text{Element\_Size}$$

Чтение `arr[0]` и `arr[999_999]` занимают строго одинаковое время **$O(1)$ (Random Access)**. Кроме того, соседние элементы попадают в одну **кэш-линию процессора (CPU Cache Line, 64 байта)**, что даёт превосходную пространственную локальность (**Cache Locality**).

```text
Массив указателей PyObject* (шаг 8 байт):

Индекс  Адрес     Буфер в памяти
 [0]   0x1000 ──► [ ptr_0 ]
 [1]   0x1008 ──► [ ptr_1 ]
 [2]   0x1010 ──► [ ptr_2 ]
 [3]   0x1018 ──► [ запас (пусто) ]
 [4]   0x1020 ──► [ запас (пусто) ]

ob_size   = 3  (число элементов)
allocated = 5  (вместимость буфера)
```

## Анатомия PyListObject в CPython: три ключевых поля

Внутри интерпретатора CPython объект `list` (структура `PyListObject`) содержит три ключевых поля:
1. `ob_item` (`PyObject **`) — указатель на непрерывный массив ссылок (указателей по 8 байт) на Python-объекты в куче.
2. `ob_size` (`length`) — текущее число реально хранящихся элементов (`len(lst)`).
3. `allocated` (`capacity`) — сколько всего ячеек под указатели выделено с запасом (**Over-allocation**).

Благодаря косвенной адресации через `PyObject*`, сам список в Python всегда остаётся непрерывным массивом адресов фиксированного размера (8 байт на элемент), независимо от типов лежащих в нём объектов.

## Алгоритм list.append(x) и амортизированная стоимость $O(1)$

- **Обычный шаг (`length < capacity`)**: запись ссылки в ячейку `ob_item[length]` и увеличение `length += 1`. Сложность: **$O(1)$**.
- **Реаллокация при переполнении (`length == capacity`)**:
  1. Выделяется новый буфер большего размера (коэффициент роста в CPython $\approx 1.125$).
  2. Все $n$ указателей копируются в новый буфер за **$O(n)$**.
  3. Старый буфер освобождается.
- **Почему `append` в среднем стоит $O(1)$ (Amortized $O(1)$)?**
  Дорогое копирование случается экспоненциально реже. В сумме за $n$ вызовов тратится $\approx 2n$ операций, то есть амортизированная стоимость одного шага равна константе **$O(1)$**.

```python
import sys

lst: list[int] = []
prev_bytes = sys.getsizeof(lst)
resizes: list[tuple[int, int]] = []

for i in range(1, 25):
    lst.append(i)
    cur_bytes = sys.getsizeof(lst)
    if cur_bytes != prev_bytes:
        resizes.append((len(lst), cur_bytes))
        prev_bytes = cur_bytes

print("Реаллокации list (len -> байты):")
for length, size_b in resizes[:4]:
    print(f"  len={length:2d} -> "
          f"{size_b} байт")
```

## Почему вставка и удаление в начале списка стоят $O(n)$?

В массиве **не может быть «дырок»** между элементами:
- При `lst.insert(0, x)` приходится сдвинуть все $n$ элементов вправо (`arr[i+1] = arr[i]`).
- При `lst.pop(0)` приходится сдвинуть все $n-1$ элементов влево (`arr[i-1] = arr[i]`).

| Операция в `list` | В конец (`i = n-1`) | В середину (`n // 2`) | В начало (`i = 0`) |
| :--- | :--- | :--- | :--- |
| Чтение/запись `lst[i]` | **$O(1)$** | **$O(1)$** | **$O(1)$** |
| Вставка (`append` / `insert`) | **$O(1)$ аморт.** | **$O(n)$** | **$O(n)$** |
| Удаление (`pop()` / `pop(i)`) | **$O(1)$** | **$O(n)$** | **$O(n)$** |
| Срез `lst[a:b]` | **$O(b - a)$** | **$O(b - a)$** | **$O(b - a)$** |

## Строки (str) и ловушка квадратичной конкатенации

Строки (`str`) в Python — **неизменяемые (Immutable)** массивы символов.
Выражение `s = s + ch` внутри цикла на каждой итерации выделяет **новую строку** и копирует все символы: $1 + 2 + \dots + n = O(n^2)$!

```python
def build_csv_row(items: list[int]) -> str:
    """Сборка через list + join за O(n)."""
    parts: list[str] = []
    for item in items:
        parts.append(str(item * 10))
    return ",".join(parts)

print("CSV:",
      build_csv_row([1, 2, 3, 4, 5]))
```

## Паттерн Swap-and-Pop: удаление из массива за $O(1)$

Если строгий порядок элементов в списке **не имеет значения**, удаление произвольного элемента по индексу можно ускорить с $O(n)$ до $O(1)$:
1. Переносим последний элемент на место удаляемого за $O(1)$.
2. Вызываем `arr.pop()`, отрезая хвост за $O(1)$ без сдвига всего массива!

```python
def fast_unordered_remove(
    arr: list[str], index: int
) -> str:
    """Swap-and-Pop: удаление за O(1)."""
    removed = arr[index]
    # перезаписываем удаляемый последним
    arr[index] = arr[-1]
    # удаляем последний за O(1)
    arr.pop()
    return removed

servers = ["srv-1", "srv-2", "srv-3", "srv-4"]
deleted = fast_unordered_remove(servers, 1)
print(f"Удалён: {deleted}")
print(f"Осталось: {servers}")
```
