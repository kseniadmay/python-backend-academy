Анатомия памяти PyListObject: массив указателей ob_item

В Python список list — это не связанный список (linked list), а динамический массив указателей на объекты. В исходном коде CPython (файл listobject.h) структура определена как PyListObject:

+--------------------+ | PyListObject | +--------------------+ | ob_refcnt: 1 | | ob_type: &PyList_T | | ob_size: 4 | --> логическая длина списка (len) | allocated: 8 | --> физически выделенная ёмкость (capacity) | ob_item: [ * ]------> [ &obj0, &obj1, &obj2, &obj3, NULL, ... ] +--------------------+ | | | | v v v v [10] [20] [30] [40] (отдельные PyObject в куче)

Ключевой вывод для Backend: операция взятия по индексу lst[i] выполняется строго за O(1) (мгновенное смещение по формуле ob_item + i * sizeof(void*)). Однако срезы lst[1:3] выделяют новый массив и копируют указатели, поэтому их сложность равна O(k), где k — длина среза.

⚠️ Junior-подход
Использует nums[start:stop] внутри цикла обработки миллионов записей, создавая гигабайты временных списков и перегружая GC.
✓ Senior-инженерия
Использует итераторы, генераторы или itertools.islice для потоковой обработки срезов без копирования памяти.

Вопрос карточки
Какова алгоритмическая сложность по времени и памяти операции среза списка lst[a:b] в Python?
Кликните или нажмите Пробел для ответа ➔
Эталонный ответ
Сложность составляет O(k) по времени и O(k) по памяти, где k = b - a — длина результирующего среза.

CPython аллоцирует новый объект PyListObject и копирует k указателей на элементы из исходного списка.
⚡ Блиц-проверка понимания

Что произойдёт, если изменить мутабельный объект внутри поверхностной копии среза? 

a = [[1, 2], [3, 4]]
b = a[:]
b[0].append(99)
print(a[0])
