# Запрет технических кодов и номеров в UI (Clean Human UI Invariant)

- **Никогда не использовать технические номера карточек, конспектов и т.д. в интерфейсе пользователя**:
  - СТРОГО ЗАПРЕЩЕНО выводить в пользовательском интерфейсе служебные технические коды и идентификаторы (`К-001`, `Ф-001`, `К-конспекты`, `Ф-карточки`, `Ф-xxx`, `К-*`, `Ф-*`, технические коды юнитов вида `Юнит 1.1`, `Юнит X.Y`, `1.1`, UUID, raw slug, машинные коды заметок).
  - Пользователю показываются исключительно понятные человеческие названия тем («Базовый синтаксис»), смысловые заголовки и естественные номера («Карточка 1 из 10», «Урок 1: Базовый синтаксис», «Урок 1 из 9»).
  - Вся внутренняя техническая номенклатура базы знаний (`К-*`, `Ф-*`, ID юнитов `X.Y`) остаётся строго под капотом (в data-атрибутах, стейте и коде движка).

# Педагогические правила Кодди (Coddy Pedagogical Invariants)

- **Квантование теории на микро-шаги (Bite-Sized Chunks)**:
  - Никаких «стен текста» и бесконечных простыней. Теория разбивается на короткие микро-шаги (сессия чтения 1.5–2.5 мин).
  - Один микро-шаг = один атомарный концепт/метод с семантическим заголовком `## ` и разделителем `---`.
- **Mobile-First верстка кода (Screen Fit & No Horizontal Overflow)**:
  - **Запрет горизонтального скролла на мобилке**: код обязан идеально и комфортно читаться на экранах мобильных телефонов (эталонный viewport iPhone `390px`, portrait).
  - **Лимит длины строки в блоках кода**: **строго не более 42–48 символов** (оптимально 35–42 символа).
  - **Запрет длинных хвостовых комментариев**: СТРОГО ЗАПРЕЩЕНО вешать длинные поясняющие комментарии в конец строки кода (`code()  # комментарий...`). Поясняющий комментарий выносится **на отдельную строку НАД кодом**, либо оформляется лаконичным маркером вывода (`# => 42`, `# True`).
  - **Перенос длинных конструкций**: вызовы функций, словари, списки и регулярные выражения форматируются многострочно с отступами.
  - **Разреженность**: логические блоки кода разделяются пустыми строками по 2–4 строки.
- **Пошаговая когнитивная прогрессия («операция за операцией»)**:
  - Пошаговое объяснение, жизненные ментальные модели, обязательный контраст подходов: наивный vs идиоматичный, быстрые vs медленные операции ($O(1)$ vs $O(N)$).
- **Интерактивность и мгновенный отклик (Runnable & Verifiable)**:
  - 100% сниппетов кода синтаксически валидны, запускаемы в Brython через `▶ Запустить код` и выводят результат через `print(...)`.
- **Фокус на реальном собеседовании (Junior+ Backend Mastery)**:
  - Подсвечивать нюансы первого скрининга: безопасность (ReDoS, уязвимость десериализации pickle), память CPython, `.pyc`, иммутабельность путей `pathlib`, логирование исключений с traceback через `logger.exception()`.
