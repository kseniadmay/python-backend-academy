# Приоритеты проекта (Core Design Hierarchy)

- **Главная цель платформы — ФУНКЦИОНАЛЬНЫЙ МИНИМАЛИЗМ + КРАСОТА (Functional Minimalism & Aesthetic Supremacy)**:
  - Любое архитектурное, компоновочное и визуальное решение оценивается через строгий синтез эстетического совершенства и функционального минимализма:
    1. **Эстетическое превосходство (Aesthetic Supremacy)**: воздушность, гармония, безупречные пропорции, чистая типографика Onest, благородная палитра «Вечерний Обсидиан» с мягкими световыми сферами и матовым стеклом. Интерфейс должен вызывать эстетический восторг и желание учиться, не перегружая восприятие.
    2. **Функциональный минимализм (Functional Minimalism / «Меньше, но лучше»)**: бескомпромиссная борьба с визуальным шумом, избыточными рамками и дублирующими плашками. Каждый видимый элемент несёт ясную ценность. Глубокие аналитические инструменты, схемы и тренажёры аккуратно подчиняются визуальной чистоте: прячутся под элегантные аккордеоны, модальные окна или специализированные экраны, сохраняя абсолютную лёгкость и состояние потока (Flow State) на первом экране.

# Coddy Pedagogical UI & Single-Action Home Screen Invariants

- **Принцип Home = Journey (Главный экран как путь)**: В образовательных приложениях в философии Coddy/Duolingo каноническим главным экраном (`#/`) обязана являться интерактивная карта/тропа обучения (3D Serpentine Path), а не аналитический дашборд.
- **Инвариант единственного доминирующего действия (Single Dominant CTA / Закон Хика)**:
  - На первом экране обучающегося запрещено размещать конкурирующие кнопки перехода.
  - Разрешена строго **одна** доминирующая светящаяся кнопка продолжения («ПРОДОЛЖИТЬ ➔» / «НАЧАТЬ (2 МИН) ➔»), привязанная к текущей активной ноде или карточке фокуса.
- **Запрет демотивирующей глобальной аналитики на главной**:
  - Категорически запрещено выводить глобальные счётчики незавершённости («Осталось N тем») и пустые индикаторы («0%») на первом экране.
  - Разрешён только локальный прогресс текущей главы (например, «Глава 1: Python Core · 2/9») и положительное подкрепление (Стрик 🔥, XP ⚡).
- **Синхронизация тайминга микро-шагов**: Длительность микро-шага во всех элементах UI (сайдбар, карточка фокуса, тултипы) обязана быть строго консистентной (единый стандарт: «2 минуты»).
- **Изоляция детальной аналитики**: Матрицы компетенций, эшелоны собеседований, тепловые карты и аккордеоны тем обязаны располагаться на специализированных экранах обзора (`#/map`, `#/stats`) и не засорять главный экран погружения в поток (Flow State).

# Visual Design Prototypes & Two-Tier Workflow Invariant

- **Двухуровневый рабочий процесс (Two-Tier Implementation Workflow)**:
  1. `Этап 1 (Прототип-песочница)`: При создании, исследовании или аудите вариантов дизайна UI/UX агент создаёт в директории `design_mockups/` отдельную независимую тестовую HTML-страницу для каждого предложенного варианта (например, `variant_a_top_centered.html`), запускает их в Chrome и предоставляет прямые кликабельные ссылки `file:///...` для живого тестирования.
  2. `Этап 2 (Сквозная интеграция)`: После утверждения концепта прототип **не остаётся изолированным артефактом**, а **обязательно и немедленно интегрируется в канонический файл приложения (`academy.html`)** с синхронизацией в эталонный скрипт сборки (`scripts/assemble_academy.py`).

# Zero-Error Headless Chrome Pre-Flight Invariant (Mandatory)

- Перед завершением любой UI-задачи обязательно запускать инструментальную проверку в реальном Headless Chrome:
  1. `pageerror === 0` (0 рантайм исключений).
  2. `console.error === 0` (0 ошибок в консоли).
  3. Отсутствие утечек `undefined`, `null`, `NaN` в видимом DOM.
  4. Прогон `python verify_all.py --quick` -> строго 100% PASS.
