# 📋 Журнал решений Дескриптора (Descriptor Decision Log)
**Компонент:** Интерактивная тропа обучения (3D Serpentine Path / `viewPathSerpentine`)  
**Файлы реализации:** `academy.html`, `Эталоны/Эталоны.html`, `Эталоны.html`  
**Дата фиксации:** 19 октября 2026 г.

---

## 1. Контекст и цели аудита

При первичном визуальном осмотре тропы Академии казалось, что в первых темах пропущены базовые коллекции (`list`, `dict`, `set`, `tuple`). 
Однако **детальное погружение в базу знаний (`RemNote_Python_Mastery_FIXED`, `PY_MASTERY`) показало, что теория упакована образцово**:
- Внутри **Юнита 1.1 («Базовый синтаксис»)** находится **13 микро-конспектов (`К-001` – `К-013`)**, полностью покрывающих срезы, списки, словари, множества, `collections` (`namedtuple`, `deque`, `Counter`), моржовый оператор `:=`, работу с файлами `open()`, `zip()` и `id()`.
- Внутри **Юнита 1.2** — 8 конспектов по функциям, замыканиям и декораторам.
- Внутри **Юнита 1.3** — генераторы, `yield` и протокол итератора.
- Всего в модуле Python — 68 конспектов, а на платформе — 45 юнитов в 7 модулях.

**Коренная проблема заключалась в критическом разрыве между глубиной контента внутри ячеек и тем, как тропа презентовала его снаружи.**

---

## 2. Принятые решения и их обоснование

### Решение 1. Снятие хардкода скрытия названий тем (`showUnderLabel`)
* **Что было:** В коде `academy.html` было жестко зашито: `const showUnderLabel = (i >= activeUnitIndex && i <= activeUnitIndex + 2);`. Из-за этого подписи отображались только для 3 узлов, а остальные 42 превращались в безымянные серые болванки.
* **Что сделано:** Теперь подписи отображаются для **всех юнитов текущей активной главы**, для всех пройденных юнитов и для 3 ближайших юнитов вперед. Для заблокированных юнитов добавлен маркер `🔒`.
* **Почему:** Студент должен видеть целостную карту пути и понимать, к каким темам он движется (Syllabus Clarity).

### Решение 2. Семантический маппинг иконок вместо циклического рандома
* **Что было:** Иконки узлов циклились по модулю 4: `TRAIL_CHAPTER_ICONS[(i - startIdx) % 4]`. Темы получали случайные иконки (генераторы получали звезду, ООП — книгу, а следующая тема — терминал).
* **Что сделано:** Реализована функция `getSemanticTrailIcon(u, i, isChapterLast)`, где каждый юнит привязан к осмысленной пиктограмме:
  - Базовый синтаксис / CLI / скрипты ➔ `terminal`
  - Функции / REST API / код ➔ `code`
  - ООП / Архитектурные слои / ORM ➔ `layers`
  - Алгоритмы / Сложность / Asyncio / Redis ➔ `zap`
  - Базы данных / SQL / Таблицы ➔ `database`
  - Web / HTTP / Сеть ➔ `globe`
  - Безопасность / Типизация / SOLID ➔ `shield`
  - Инфраструктура / Git / Графы ➔ `branch`
  - DevOps / Docker / Облака ➔ `cloud`
  - Инструменты / Linux / Память ➔ `wrench`
  - Финальные узлы глав ➔ `trophy`
* **Почему:** Иконки обязаны передавать сущность изучаемого материала, а не быть визуальным шумом.

### Решение 3. Радиальный микро-прогресс конспектов (Radial Progress Ring)
* **Что было:** Узел имел только два состояния — «НАЧАТЬ» (желтый) или «СДАНО» (зеленый). Так как закрытие 13 конспектов занимает несколько дней, узел казался «застывшим».
* **Что сделано:** Рассчитывается процент освоенных навыков юнита. Если юнит начат, вокруг активного гексагона рендерится светящееся кольцо прогресса SVG (`.hex-progress-ring`), а бейдж сверху показывает: `ПРОДОЛЖИТЬ · X/Y`.
* **Почему:** Обеспечивает петлю немедленного подкрепления (Instant Feedback Loop), студент видит динамику внутри текущего юнита.

### Решение 4. Устранение демотивирующих «0%» и «0/45» по канону `AGENTS.md`
* **Что было:** В мобильном статус-баре выводилось `📘 0/45`, а в главном баннере — `⚡ Готовность к тех-скринингу: 0%` и `Начни · 9`.
* **Что сделано:**
  - В мобильном баре: `📘 Гл. 1: 0/9` (локальный фокус главы вместо пугающего 0/45).
  - В баннере: при `e1PctTop === 0` выводится позитивный статус `⚡ Старт тех-скрининга · Фундамент` вместо «0%».
  - В счетчике юнитов: `Начало · 9 юнитов` вместо абстрактного `Начни · 9`.
* **Почему:** Прямое требование канона `AGENTS.md` (строка 15: *«Категорически запрещено выводить глобальные счётчики незавершённости и пустые индикаторы на первом экране»*).

### Решение 5. Устранение дублирования виджетов SRS в сайдбаре
* **Что было:** В правом рельсе десктопа подряд шли два виджета: «Очередь SRS (12 карточек)» и «Повторение карточек (Повторить →)».
* **Что сделано:** Удален дублирующий блок `.coddy-rail-card--row`.
* **Почему:** Избавление от информационного шума и экономия полезной высоты экрана.

### Решение 6. Умная кнопка прыжка к активному уроку (`#path-jump-btn`)
* **Что было:** Желтая кнопка со стрелкой вниз `↓` висела на экране непрерывно, даже когда активный урок находился прямо по центру экрана, загораживая контент.
* **Что сделано:**
  - Подключен scroll-listener: кнопка плавно скрывается (`.is-hidden`), когда активный узел в зоне видимости.
  - Если пользователь проскроллил ниже активного узла, стрелка динамически разворачивается вверх (`.path-jump-btn--up svg`).
* **Почему:** Кнопка действия должна появляться только тогда, когда в ней есть функциональная необходимость.

### Решение 7. Мобильный Bottom Sheet для поповера узла (`.path-popover`)
* **Что было:** Поповер позиционировался абсолютными координатами над SVG. На мобильных экранах он обрезался краями вьюпорта или улетал под нижний таббар.
* **Что сделано:** На экранах `<= 640px` поповер открывается как мобильная нижняя шторка (`position: fixed; bottom: 0; width: 100%; border-radius: 24px 24px 0 0;`) с плавной анимацией выдвижения снизу (`popoverSlideUp`) и увеличенным тач-таргетом закрытия.
* **Почему:** Нативная мобильная эргономика и удобство управления одной рукой.

### Решение 8. Обогащение состава ячейки и тактильный отклик (Haptics)
* **Что было:** В поповере отображались только 3 навыка, скрывая объем теории (конспектов).
* **Что сделано:**
  - В поповер добавлен мета-блок: `📚 X тем-конспектов · 🎯 Y навыков`.
  - При тапе на узел тропы и кнопку прыжка добавлен нативный тактильный микро-отклик: `navigator.vibrate(10)`.
* **Почему:** Демонстрирует фундаментальность ячейки и создает ощущение премиального нативного мобильного приложения.

### Решение 9. Адаптивность сегментов прогресса и ликвидация обрезки текста («Начало · 9 юн»)
* **Что было:** В правом блоке липкого баннера главы текст счетчика на мобильных устройствах срезался границей экрана: `Начало · 9 юн` из-за жесткой фиксированной ширины полосок `.path-seg-bar { width: 22px; }`.
* **Что сделано:**
  - Полоски сегментов сделаны резиновыми: `flex: 1 1 0; min-width: 6px; max-width: 22px; height: 8px;`.
  - В счетчик добавлен адаптивный переключатель: на экранах `<= 480px` выводится лаконичный формат `0 / 9` (или `X / Y`), а на десктопе сохраняется развернутый текст `Начало · 9 юнитов` / `X из Y сдано`.
* **Почему:** Обеспечивает абсолютную чистоту типографики без клиппинга на любых мобильных разрешениях (от 320px до 430px).

### Решение 10. Повышение z-index мобильного Bottom Sheet и Backdrop-оверлей
* **Что было:** У плавающего мобильного таббара платформы был зашит высокий приоритет `z-index: 100000 !important;`. При открытии мобильного поповера (`z-index: 1050;`) остров таббара оказывался поверх шторки, перекрывая кнопку действия.
* **Что сделано:**
  - Установлен `z-index: 100002 !important;` для `.path-popover` на экранах `<= 640px`.
  - Добавлен темный полупрозрачный блюр-оверлей `.path-popover-backdrop` (`z-index: 100001;`) с плавной анимацией появления и закрытием шторки по тапу мимо.
* **Почему:** Гарантирует правильную z-стекинг иерархию модальных окон в мобильном интерфейсе.

### Решение 11. Ликвидация «0/45» и динамический «Радар скрининга» в десктопном рельсе
* **Что было:** В шапке десктопного рельса сохранялся нарушающий инвариант глобальный счетчик `📘 0/45` и пустые «0%», а в виджете «Радар скрининга» красовались захардкоженные фейковые значения (85%, 40%, 0%).
* **Что сделано:**
  - В плашке рельса счетчик локализован по текущей главе: `📘 Гл. N: X/Y`.
  - При `0%` готовности к скринингу вместо демотивирующих нулей выводится статус `СТАРТ · базовый тех-скрининг`.
  - В «Радаре скрининга» проценты тем («Сложность O(n) & срезы», «Хеш-таблицы & dict/set», «SQL JOIN & индексы») рассчитываются динамически в реальном времени через `getSkillMP()`, а при нулевом прогрессе честно выводится «Не начато».
* **Почему:** Строгое соблюдение канона `AGENTS.md` (строка 15) и честный фидбек для студента.

### Решение 12. Динамический таргет в CTA поповера ячейки тропы
* **Что было:** Кнопка поповера всегда вела строго на `u.skills[0]`. При возвращении к частично пройденному юниту студент отбрасывался в уже изученный первый навык.
* **Что сделано:** Кнопка «ПРОДОЛЖИТЬ» динамически ищет первый навык юнита с `getSkillMP(s.id) < 80`.
* **Почему:** Студент мгновенно попадает именно в ту тему, на которой остановился, сохраняя состояние потока (Flow State).

### Решение 13. Стилизация подписей узлов тропы (`hex-node-underlabel--*`)
* **Что было:** В CSS отсутствовали стили для модификаторов `--active`, `--completed`, `--locked`, из-за чего активный урок имел блеклую серую подпись.
* **Что сделано:** Для `.hex-node-underlabel--active` задан яркий контрастный цвет `#f8fafc` (белый), жирность 800 и тень; для пройденных — мягкий светлый `#e2e8f0`, для заблокированных — приглушенный `#64748b`.
* **Почему:** Создает четкую визуальную иерархию между текущим, сданным и заблокированным контентом.

### Решение 14. Замена сирены на щит `🛡️` и устранение утечки слушателей скролла
* **Что было:** В бейдже эшелона использовалась тревожная сирена `🚨`, а при каждом рендере маршрута регистрировался новый слушатель скролла на `window`.
* **Что сделано:**
  - Сирена заменена на благородный щит `🛡️` фундамента скрининга.
  - Слушатель скролла для `#path-jump-btn` защищен флагом `window._pathJumpScrollBound`.
* **Почему:** Спокойная академическая эстетика и защита от утечек памяти.

## 3. Памятка для следующего Дескриптора (Инварианты)

> [!WARNING]
> **Чего НЕЛЬЗЯ делать при следующих доработках тропы:**
> 1. **Не возвращайте глобальный счетчик «N из 45» на первый экран** — на главной и тропе должен жить только фокус текущей главы.
> 2. **Не скрывайте названия тем в текущей главе** — студент не должен учиться «вслепую».
> 3. **Не ломайте синхронизацию эталонов** — после любого изменения `academy.html` обязательно запускайте `python scripts/sync_etalons.py`. Файлы `academy.html` и `Эталоны/Эталоны.html` обязаны быть побайтово идентичны.
> 4. **Не делайте коммиты без предварительного подтверждения пользователя** — строго соблюдайте инвариант `AGENTS.md` (строка 52).
> 5. **Формулируйте коммиты строго в прошедшем времени** (краткие причастия / совершенный вид: *«сделаны»*, *«обновлены»*, *«внедрен»*, *«устранены»*, *«ликвидировано»*). Запрещены отглагольные существительные и инфинитивы.
